- 초기 S0·shape9 모델은 합성 경로 유형인 직진·굴곡·회전을 학습했다. 이 라벨은 공식 fishing_code 네 조업형태와 대응하지 않는다.

## 5. 실제 모델과 평가 설계

합성 S0·shape9의 라벨은 직진·굴곡·회전이다. 실제 평가에서는 실제 fishing_code 네 클래스에 맞춰 새 모델을 적합했다. 따라서 “합성 모델 weight를 그대로 실제에 옮겨 실패했다”가 아니다. 확인한 것은 형상 기반 실제 라벨 분류기의 내부 성능이다.

Train 7,372척에서 선박·월별 고정 hash로 최대 월 4개, 총 129,142개 시간대 행의 형상을 계산했다. 선박당 최대 24개 행이다. 115,300개는 유효, 13,842개는 길이 0으로 사용할 수 없었고, 유효 기하가 전혀 없는 선박은 90척이었다. 레코드별 무시간 shape9 특징을 계산하고, 선박별 특징 평균·표준편차·25·75분위수 36개와 mask 36개를 만든 72입력 후보를 비교했다. R0는 shape9 평균 9개와 mask 9개, 총 18입력이다. 절대 좌표·ID·월·행수·시간대·점별 시간·속도는 모델 입력에 없었다.

선박 단위 split으로 같은 선박이 학습과 평가에 섞이지 않게 했다. final을 먼저 잠그고 개발 seed 3201·3202·3203을 사용했다. 네 고정 후보는 평균9 MLP, 분포36 MLP, 분포36 선형, 분포36 ExtraTrees다. train·validation·calibration 역할을 분리했고 개발 적격 기준에는 Macro F1 최소 +0.03, accuracy·NLL·Brier 비열등 조건이 있었다. ExtraTrees만 통과해 동결했다. 개발 30 fit 후 final에서 baseline과 후보를 두 초기화씩 비교해 총 34회 적합했다. final 1,473척 중 특징 부족 20척은 유보하고 roster와 coverage에 남겼다. 최종 결과를 보고 재튜닝하지 않았다.

## 7. 낮은 성능의 원인과 한계

### 확인된 현상

1. 정확도는 다수 클래스 상수 예측과 거의 같다. Scorable에서 연안복합만 예측해도 49.69%를 맞힌다. 후보의 49.90%는 근소한 차이다.
2. 희소 클래스 성능이 낮다. 통발은 0/204, 채낚기연승낚시는 5/29다. Train 선박 중 채낚기는 158척(2.14%)뿐이다.
3. MLP·선형은 class weight 없이 NLL+L2를 최소화했고 ExtraTrees도 class_weight=None이었다. Macro F1을 직접 최적화한 것은 아니다. 다수 클래스 편향을 설명할 수 있지만 단독 원인으로 증명되지는 않았다.
4. 동결 ExtraTrees의 final에서는 통발을 0/204척 맞혔다. 개발 validation에서는 ExtraTrees가 split별 2/125, 2/125, 3/124척을 맞혔으므로 모든 분할·모델에서 통발 정답이 0이었다고 일반화하면 틀린다. 개발과 final 모두 통발 구분 능력이 매우 낮았다는 것이 확인된 결과다.

### 검증할 가설

| 가설 | 근거 | 미확인 |
| --- | --- | --- |
| 클래스 불균형이 소수 클래스 recall에 기여했을 수 있다. | 개발 fit support는 [86, 580, 1,395, 2,016]으로 최다/최소 약 23.4배이며 class weight가 없었다. | class weight·balanced sampling을 한 요소만 바꿔 기여도를 분리하지 않았다. |
| 형상 중심 입력이 실제 조업종류를 충분히 분리하지 못할 수 있다. | 점별 시간·속도·실제 거리·장비 상태가 없고 절대 위치·월·시간대도 입력하지 않았다. | 클래스별 특징 중첩과 추가 정보의 개선량을 측정하지 않았다. |
| 표본 선택·선박 집계가 항적 다양성을 놓쳤을 수 있다. | 약 389만 Train 행 중 129,142행만 기하 계산했고 월별 최대 4행을 사용했다. | 표본 수를 늘린 결과나 다른 hash 표본과 비교하지 않았다. |
| 시간대 항적과 선박 속성 라벨의 행동 정합성이 약할 수 있다. | fishing_code는 선박 조업형태이고 시간대별 조업·이동·정박 행동의 별도 정답은 없다. | 각 창에 비조업 이동이 얼마나 섞이는지 확인하지 않았다. |

| 희소 클래스 final 표본이 작아 class 지표 변동이 클 수 있다. | 채낚기 final support는 29척이다. | 더 큰 독립 자료의 성능은 없다. |

따라서 “불균형 탓”, “400 epoch 부족”, “좌표계 오류”, “label noise” 가운데 하나를 확인된 원인으로 쓰지 않는다.

### 원인이라고 단정하면 안 되는 것

- 합성 weight를 실제자료에 전이하지 않고 실제 라벨로 새로 학습했다.
- 월 메타데이터 오류와 구조 오염행은 학습 전 수정·격리했다. 수정 전 오류를 저장 final의 직접 원인으로 쓰지 않는다.
- 지표·혼동행렬·split 계보·저장 모델 재적재의 독립 검산은 일치했다. 이는 계산 재현성이지 모든 자료 의미 오류를 배제한 증명은 아니다.
- 온도 보정 전후 argmax가 1,453척 중 바뀐 선박은 0척이라 통발 실패의 원인이 아니다.
- 18개 gradient 개발 적합은 모두 400 epoch에서 best checkpoint였고 마지막 validation NLL은 조금 줄었다. 큰 train/validation NLL gap은 없었으나 400 이후는 미측정이다. 미수렴이나 epoch 부족으로 단정할 수 없다.
- Test 6월 파싱 미완료와 사고 ID 미연결은 공식 평가 한계이지, 2026 Train 내부 holdout 저성능의 원인은 아니다.

| 공식 Test·사고 탐지 | 공식 점수와 확정 사고 매핑 없음. 기존 모델 주기 F: 자료의 Test 6월 파싱은 부분 검사. 첨부 조사에서는 별도 공식 Test 전체 판독 완료를 보고. |

후속 작업은 final을 다시 튜닝에 쓰지 않고 새 개발 계약부터 고정해야 한다. 우선 class weight/균형 표본의 영향, 월당 4행보다 큰 표본의 효과, 평균9·분포36·형상 크기·시간대 정보의 분리 기여, 시간대별 라벨과 조업/이동/정박 정합성, 2025/2026 파일과 공식 Test A/B의 역할, 사고 ID와 시간 정답을 연결할 공식 근거를 확인한다. 결과는 accuracy·Macro F1·클래스별 recall·coverage·NLL·Brier를 함께 보고한다.

### 재평가로 보완한 평가 조건과 모델 설명

프로젝트의 목표는 선박의 조업형태 분류와 평소 항적에서 벗어나는 정도의 이상점수 산출이다. 지금 실제자료에서 완료한 학습·평가는 앞의 분류에 해당한다. 이상점수 0~1은 사고 확률과 다르며, 사고 기록이 없다는 이유만으로 정상 정답을 붙일 수 없다. 시간별 이상점수는 해당 시각까지의 자료로 계산해야 한다. 선박 분류를 위해 허용된 기간 전체를 요약하는 절차를 실시간 이상 탐지에 그대로 사용하면 미래 정보가 섞인다.

실제 shape9의 아홉 특징은 부분선 직진성, 절대 방향변화 평균, 회전방향 집중도, 부호 있는 방향변화 표준편차, 절대 방향변화 최대, 부분선 퍼짐비, 부분선 chord 이탈비, 전체 점구름 퍼짐비, 점구름 반경 4차 모멘트 비다. 각 구성 선의 굴곡·형상 통계이며 실제 시간순 움직임·조업 행동을 직접 관측한 값은 아니다. 원자료의 좌표 반복이나 관측 방식에 따라 통계가 바뀔 수 있으므로 형상과 수집 특성을 별도로 점검해야 한다. 자세한 식과 특징명은 [실제 성능 진단 4절](real_accuracy_diagnosis_and_evaluation_history_20261029.md)에 있다.

전처리 중앙값·표준화 통계는 각 train에서만 적합했다. MLP는 hidden 16, L2=.01, 최대 400 epoch, full-batch gradient descent 학습률 .03, patience 35를 사용했다. 선형 후보는 hidden 없이 같은 학습 조건을 썼다. ExtraTrees는 256개 트리, min_samples_leaf=2, max_features=1.0, class_weight=None이었다. validation NLL로 checkpoint를 선택하고 별도 calibration에서 초기화별 온도를 정했다. init42·137의 보정 확률을 평균했다.

| 개발 후보 | 3분할 평균 Macro F1 | R0 대비 | 개발 판정 |
| --- | ---: | ---: | --- |
| R0 평균9 MLP | 0.16607 | 기준 | baseline |
| R1 분포36 MLP | 0.17405 | +0.00797 | 최소 +0.03 미달 |
| R2 분포36 선형 | 0.19373 | +0.02765 | 최소 +0.03 미달 |
| R2 분포36 ExtraTrees | 0.33575 | +0.16968 | 유일한 적격 후보 |

개발 후보는 평균 Macro F1 차이 ≥+.03, accuracy 차이 ≥−.01, NLL 차이 ≤+.02, Brier 차이 ≤+.01, 세 split 중 둘 이상 F1 개선, 동일한 유효 분모 조건을 모두 만족해야 했다. final에서도 같은 네 지표 조건과 bootstrap 95% 개선 하한 >0을 요구했다. 1월을 제거한 추가 강건성 진단에서는 F1 하락이 .03 이내여야 했다. 실제 공통 scorable 1,432척에서 하락은 .01948로 기준 안이었으나, 유보는 20척에서 41척으로 증가해 coverage는 98.642%에서 97.217%로 낮아졌다. 이는 1월 관측이 없는 상황의 민감도이며 새로운 연도 일반화 평가가 아니다.

final은 라벨층화 hash seed20261028로 전체 7,372척에서 1,473척을 잠갔다. 개발 각 split의 roster는 train 4,127척, validation 884척, calibration 888척이었다. 최종 적합은 사전에 고정한 seed3201의 역할을 사용했다. 그 train의 scorable은 4,077척이며 클래스 support [86,580,1395,2016]은 전체 Train 비율이 아닌 이 분모다. 세 개발 split은 동일 모집단을 공유한다. 개발 30 fit은 네 후보와 degree_control 민감도 설정의 5조건×3분할×2초기화이며, degree_control은 후보 선택 대상이 아니었다.

원자료 라벨 행 수, 선박 수, 기하 표본 수, final 평가 수는 서로 다른 분모다. WKT를 읽을 수 있어도 길이 0이거나 특징이 정의되지 않을 수 있다. 모델의 13,842개 길이0 표본을 모두 CSV 손상이나 WKT 파싱 오류라고 부르면 안 된다. 이 표본들은 모델의 유효 형상 조건을 만족하지 못한 경우다.

첨부 자료의 사고 조사에서는 42개 사고 기록과 59개 후보 ID가 64개의 사고-후보 쌍을 이뤘다. 사고가 속한 시간대가 관측된 것은 49/64쌍, 전후 13시간대가 모두 관측된 것은 17/64쌍이다. 형상 조건과 테스트 이력을 모두 갖춰 실제 연도 간 비교한 것은 51쌍(고유 ID 47개)이었고, 같은 ID의 최선 모양이 다른 후보 ID 대조군보다 가까운 경우는 36/51쌍이었다. 후보 선정·검색 행 수의 영향을 받는 탐색 비교라 이를 정확도 70.6%나 사고 판별 성능으로 보고하지 않는다.

첨부 문서의 전수 조사·공식 공지 확인·후보 분석은 그 문서에서 보고한 작업이다. 이번 통합·재평가 작업에서 공식 CSV 전체를 다시 읽거나 해당 분석 코드를 실행한 것은 아니다. 기존 모델 평가 경로의 Test6 부분 파싱과 첨부 조사 경로의 Test 4,212,389행 전체 WKT 판독 완료는 조사 대상·시점·검사 방법이 다른 기록이다. 두 자료의 파일 크기도 다르므로 전체 파일별 SHA-256 대조 없이 검사 상태를 서로 덮어쓰지 않는다.

### 첨부 자료에 기록된 최신 설계와 제출 준비

첨부 문서 13절·28절은 후속 모델설계 2판의 후보로 선박별 분류 TabICLv2, 불규칙 이력 비교 ATENet, 이상 탐지 비교 ALoRa-T 창 끝 어댑터를 기록했다. 기존 MLP·트리는 비교 기준으로 남긴다. 이 내용은 첨부 자료의 계획 인계이며 이번 문서에서 논문·구현을 새로 검증하거나 실제 모델 학습·개선을 확인한 결과가 아니다. 세 모델 융합을 확정한 것도 아니다. 긴 창은 Train 512시간 완전 창이 98,414개여도 출처는 126개 ID뿐이므로, 창 개수를 독립 표본이나 많은 선박의 일반화 근거로 쓰지 않는다.

첨부 문서가 정리한 Test A 출력은 선박 ID별 예측 라벨과 선택 라벨의 확률이다. Test B는 선박별 행 안에 시각·이상점수 쌍을 나열하고 대표 최고점 시각을 기록하는 구조다. 대표 최고점 시각은 실제 사고 정답이나 당시 경보 시각과 구별해야 한다. 이상점수를 만들 수 없는 구간을 임의의 정상 점수 0으로 채우지 않는다.

첨부 문서에 따르면 결과 파일 외에 재현 코드·분석 보고서·발표자료, 실행 환경과 버전 README, 학습·추론 Notebook과 데모영상, 생성형 AI 사용 범위와 참가자의 검토 기록 등이 제출 준비 항목으로 안내됐다. 실제 A/B 대상, 허용 관측 기간, 정량 채점 산식, 누락값·동률 규칙과 최종 파일 형식은 여전히 확인 과제다. 이는 첨부 문서의 공지 조사 요약이며 현재 계정 화면을 새로 확인한 결과는 아니다. 참가신청 날짜를 결과 제출 마감으로 자동 해석하지 않는다.

### 2026-10-29 재평가 기록

통발 오분류 설명에서 빠졌던 채낚기 예측 4척을 보완했다. 개발 후보의 수치와 선택 이유, final 성공 조건, 1월 제외 coverage 변화, 전처리·학습 설정, 분모별 라벨 통계, 첨부 조사의 최신 후보·제출 설명을 추가했다. 교차 연도 위험을 현재 내부평가 저성능 원인과 구분하고, 기존 모델 작업과 첨부 조사·이번 재평가의 확인 범위를 명시했다. 원자료 재학습·모델 추론·공식 제출은 이 재평가의 수행 내용이 아니다.
