# 2026-10-26 모델 제작 동행 실습: 실행 전 고정 기준

사용자 요청 범위는 ① 목표·검증 기준 설정 ② 작은 기준 모델 실행 ③ 항적 한 건의 전체 추적 ④ 실패 사례 분석까지다. 이후 특징·모델·임계값 개선은 이번에 실행하지 않는다. 본 문서는 이번 실행 결과를 산출하기 전에 작성했다. 기존 seed 42 결과는 이미 알려져 있으므로 신규 사전등록 연구나 미열람 평가라고 주장하지 않는다.

## 목표와 자료 범위

- 기술 목표: 합성 원자료 → 부분선별 기하 특징 8개 → 전처리 입력 16개 → 생성 경로 3클래스 예측 → 생성 정답 대조를 실행하고 재현한다.
- 학습 목표: 입력과 정답의 분리, 부분선 보존, train 전용 전처리, logit·확률·이상점수의 차이, 오분류 관찰과 원인 가설의 차이를 설명한다. 학습자의 이해는 산출물 생성만으로 완료 처리하지 않는다.
- 자료: 기존 S0 생성기 seed=42, 합성 선박 84그룹 / 1,008경로. straight/sweep/turn은 생성 경로 유형이며 fishing_code나 정상·사고 라벨이 아니다.
- 실제자료 상태: data/raw에는 .gitkeep뿐, data/reference에는 참고 CSV 1개·10행이 확인되었다. 정확한 CRS·라벨 단위·정식 Train/Test·공식 평가 조건이 미확정이므로 실제자료 학습을 수행하지 않는다.
- 기존 fishing_demo 구현을 재사용한다. NotebookLM 생성 보고서의 대체 특징·hidden=32 예제는 실행하지 않는다.

## 검증 기준

기술 통과는 임의 정확도 목표가 아니라 계약 준수와 추적 가능성으로 판단한다. 낮은 성능도 유효한 분석 결과다.

1. 모든 split 사이 선박 ID 중복이 0이며, 적합·선택·보정의 자료 경계가 지켜진다.
2. 특징 순서·단위가 기존 계약과 같고, label/vessel_id/split/scenario/sim_times/quality는 모델 특징에서 제외된다.
3. 부분선을 잇지 않고 계산한다. 실제 속력·가속도를 계산하지 않는다.
4. 예측값은 유한하며 확률합은 허용오차 1e-10 안에서 1이다. 유보 수와 평가 라벨 수를 분리한다.
5. 저장·재로딩 추론과 기존 예측을 대조한다. 정답을 제거해도 확률·이상점수가 바뀌지 않는다.
6. 추적의 수동 NumPy 순전파·기하 계산은 공개 API/저장 결과와 허용오차 1e-10으로 대조한다. 이는 수치 검산 오차이며 실제 센서 정밀도가 아니다.
7. accuracy·macro F1·NLL·Brier·혼동행렬·클래스별 support를 보고하고 혼동행렬 분모를 검산한다.
8. 실행 명령·환경·소스/산출물 해시·검증 결과를 보존한다.

## 추적과 실패 사례 선택 규칙

- 대표 항적: 선택 MLP의 test 오분류 중 sample_id 사전순 첫 사례. 오분류가 없으면 첫 test 정분류라고 명시한다.
- 대조 항적: 대표 항적과 같은 생성 정답을 가진 test 정분류 중 sample_id 사전순 첫 사례.
- 추가 사례: stress 오분류 중 같은 규칙으로 첫 사례.
- 추적: 합성 raw_record·부분선·각 특징·train 통계·대치/표준화·mask·16차원 입력·은닉값·logit·보정 전후 확률·예측·정답·NLL·별도 거리점수를 연결한다.
- 전체 혼동쌍과 확신도 0.8 이상 오분류도 집계한다. 0.8은 분석 표시 기준이며 운영 경보 임계값이 아니다.
- test/stress는 서로 다른 선박이고 stress에 네 변화가 함께 적용된다. 차이를 개별 조건의 순수효과·과적합·실제 사고 성능으로 해석하지 않는다.
- 분석은 원자료/계약/특징/전처리/모델/표시 계층별 관찰·가설·미확인을 구분한다. 후속 개선 실험은 제안만 남긴다.
