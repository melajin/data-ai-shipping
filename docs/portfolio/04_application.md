# 적용: 제출 재현과 실제 시점의 판단을 구분한다

현재 Test A의 CLI는 고정된 제출 대상 ID 집합과 337열 특징 순서를 확인하고 선박별 유형과 선택 클래스 점수를 출력한다. 임의의 새 선박에 대한 일반 서비스는 아니다. 새 대상에 적용하려면 입력 명부와 관측 기간, 특징 계약, 참조 문맥과 평가 집단을 다시 정하고 검증해야 한다. 저장소에 포함되지 않은 두 가중치의 복원 방법은 [Test A 안내](../../test_a/deliverables/README.md)에 있다. ([입력 검사](../../test_a/deliverables/round63_submission_20261106/src/round63/pipeline.py))

Test B 패키지는 고정된 시간별 기하 요약과 참조자료로 후보와 근거를 재현한다. 관측 이력이 짧으면 일부 성분을 계산할 수 없고, 이상점수는 사고 확률이 아니다. 사후 제출 분석에서는 제공 기간 전체에서 최고점을 선택하며, 2025년 입력에 2026년 기준자료를 사용한 결과를 당시의 실시간 예측으로 설명하지 않는다. ([패키지 안내](../../test_b/deliverables/testb_system_20261106/README.md), [실행 요약](../../test_b/deliverables/testb_system_20261106/results/reproduction_001/summary.json))

실시간 적용을 검토하려면 관측 구간 종료, 실제 수신 가능 시각, 판단 시각과 참조자료의 당시 가용성을 확인해야 한다. 별도 [시간순 입력 검사](../../fishing_demo/causal_replay.py)는 중복·시간 역전·가용성 위반 등을 구분한다. [설정](../../configs/testb_realtime.json)의 점수 생성과 외부 전달은 비활성화돼 있으며, 계약 검사 통과만으로 경보 품질을 주장하지 않는다. 확정 사고·정상 정답, 오경보 분모, 탐지 지연과 결측 처리를 갖춘 현장 평가가 추가로 필요하다.

원본의 [AI 활용과 검토](../../test_a/deliverables/round63_submission_20261106/docs/AI_활용과_검토.md)는 참가자가 과제 범위와 평가 조건을 정하고, 잠정 사고 연결과 확정 정답을 구분하며, 사후에 유리한 산식을 선택하지 않도록 검토했다고 기록한다. 같은 문서는 코드 작성·실험 지원에 Codex, 코드 검토에 Claude를 활용했다고 명시한다. 이 기록을 넘어 특정 코드나 팀 의사결정을 개인의 단독 기여로 귀속하지 않는다. 원본 제공 데이터의 외부 재배포 조건을 확인하기 전에는 공개 배포 가능하다고 가정하지 않는다.
