# S0 반복 개선 실험 — 2026-10-26 실행 전 계약

사용자가 “모델 설정, 분석, 틀린 이유 찾기, 모델 재설정 반복해서 유의미한 결과 나올 때까지 시도”하도록 범위를 확장했다. 앞선 단일 실행 결과는 보존하고 이 별도 실험에서 개선을 검증한다. 실제자료 학습·외부 항적 수집·실선 운용은 이번에도 수행하지 않는다.

## 질문과 유의미한 결과의 기준

질문은 기존 소형 MLP가 합성 경로의 크기·단절·잡음 변화에 덜 의존하도록 바꾸면 **보통 조건 성능을 유지하면서 조건 변화 성능이 반복해서 좋아지는가**다. 기존 seed42 test/stress는 원인 가설을 세운 이력으로만 사용하고 새 후보 선택에 재사용하지 않는다. 완벽한 분류를 종료 조건으로 삼지 않는다.

| 구분 | 사전 고정 조건 |
| --- | --- |
| 주 기준선 | 원래 8특징 + tanh16 MLP, L2=0, full-batch GD |
| 개발 생성 seed | 1101, 1102, 1103, 1104, 1105 |
| 모델 초기화 seed | 42, 137; 모든 후보에서 같은 두 값 |
| 최종 생성 seed | 9101부터 9110까지 10개; 후보 잠금 전에 데이터 생성 자체를 하지 않음 |
| 각 생성 seed의 자료 | 기존 생성기·그룹 수 유지: train 432, validation/calibration/normal/shift 각각 144 |
| 개발 평가 역할 | 생성기 split 이름 test/stress는 각각 development_normal/development_shift로 사용. 최종 평가라고 부르지 않음 |
| 그룹 식별 | 생성 seed마다 ID 문자열이 재사용되므로 실험 키는 (generator_seed, vessel_id/sample_id) |
| 학습 절차 | train에서만 전처리·분류 적합, validation NLL로 epoch, calibration으로 양의 온도 |
| MLP 조건 | hidden=16, L2=0, 최대400epoch, lr=.03, patience35 |
| tree 후보 조건 | ExtraTrees 256 trees, min_samples_leaf=2, max_features=1.0, class_weight 없음, n_jobs=1, random_state=초기화 seed |
| 평가 | accuracy·macro F1·NLL·Brier·혼동·클래스별 support·유효/유보 수. 모든 후보의 분모 동일 |

개발 seed별로 두 초기화 결과를 평균한 뒤 후보−기준선 Macro F1 차이를 비교한다. 적격은 ① normal 평균 차이≥−.01 ② shift 평균 차이≥+.05 ③ 5개 seed 중 4개 이상 shift 차이>0 ④ 유효/유보 분모 동일이다. 이는 이번 합성 실험의 설계 기준이며 공식 대회 점수식이 아니다.

최종에서도 같은 기준의 ①②④를 적용하고 일관성은 10개 중 8개 이상으로 고정한다. seed 단위 paired bootstrap 2,000회(고정seed=20261026)의 shift 개선 평균 95% 구간 하한이 0보다 큰지도 요구한다. normal 평균 기준을 통과했다는 사실을 통계적으로 입증된 비열등성이라고 부르지 않는다. 같은 생성기 편향·실제자료 일반화·사고 탐지 능력은 검증하지 않는다.

tree 후보까지 진행하면 `classes_=[0,1,2]`를 확인하고 `z=log(clip(p, np.finfo(float).tiny, 1))`에 기존 양의 온도 보정을 적용한다. 이는 트리의 원래 학습 logit이 아니라 **로그 확률에 대한 온도 보정**이다. T는 calibration에서만 결정하며 tree에는 epoch 선택이 없다. 직접 생성한 로컬 pickle만 저장·재로딩하고 외부 pickle 입력 CLI는 제공하지 않는다. pickle 해시는 동일성 증거이며 출처 신뢰성을 보장하지 않는다. 버전·특징 순서·클래스 순서·전처리·온도와 저장 전후 원래/보정 확률 일치를 기록한다. 직접 트리 배열을 해석하는 새 추론기는 만들지 않는다. 이 선택은 [scikit-learn의 모델 저장 지침](https://scikit-learn.org/stable/model_persistence.html)을 참고한 Astra 검토에 따른 것이다.

## 반복 순서와 고정 예산

1. 원래 MLP 기준선을 개발 seed×초기화 조건에서 실행한다.
2. **1차 재설정:** 총길이 로그 열만 제거한 shape7 MLP. 길이 의존성을 절제한다.
3. 1차에서 적격 후보가 없으면 **2차 재설정:** shape9 MLP와 shape15 MLP. 전체 관측점 구름의 무차원 특징 및 부분선 안 호 길이 재표본화 회전 특징을 비교한다.
4. 2차에서도 없으면 **3차 재설정:** shape9 ExtraTrees와 shape15 ExtraTrees. 확정된 입력에서 다른 비선형 분류 구조를 비교한다.
5. 각 단계는 사전에 나열한 순서로 가장 단순한 적격 후보를 선택한다. 새 후보 최대5개, 분석→재설정 최대3차. 개발 적격 후보가 생기면 더 복잡한 단계는 수행하지 않는다.
6. 특징·모델·학습/epoch 선택/보정의 **절차**와 실행 소스 해시를 잠근다. 이후 처음으로 final seed 자료를 생성한다.
7. 최종은 주 기준선과 잠근 후보만 각각 새 train/validation/calibration으로 적합하고 test/stress를 1회 평가한다. 개발의 하나의 가중치가 아니라 동결된 제작 절차를 검증하는 설계다.
8. 최종 기준을 충족하면 “이 합성 조건에서 유의미한 개선 확인”으로 종료한다. 개발 예산 내 적격이 없거나 최종 실패이면 개선 미확인으로 기록한다. 통과할 때까지 최종 seed를 갈아 끼우거나 같은 최종 결과를 보고 재설정하지 않는다.

## 새 특징 계약

기존 S0 8특징·16입력 계약과 저장 파일은 바꾸지 않는다. 새 실험은 별도 `fishing_iteration_model_v1` 형식을 사용한다.

- original8: 기존 8개 특징 그대로.
- shape7: original8에서 log1p_total_length_m만 제거. 다른 7개와 기존 부분선 직선성 산술평균을 변경하지 않는다.
- shape9: shape7 + 전체 관측점 구름의 중심화 공분산 고유값 비율 제곱근 + 평균 반지름4제곱/평균 반지름2제곱의 제곱. 점 사이 연결선을 추가하지 않는다.
- shape15: shape9 + 부분선별 정규화 호 길이 8점/16점 재표본화에서 회전각 절대합·회전각 합의 절대값·누적회전 범위 각각의 부분선 최대값(6개). 부분선끼리 보간하지 않는다. 계산 불가는 NaN이며 전처리에서 train 대치와 mask를 붙인다.
- 원래 length/straightness 계산은 부분선을 보존한다. 새 특징에 실제 시각·속력·가속도·label·ID·scenario·quality를 넣지 않는다.

## 원인 분석과 증거

길이 민감도와 부분선 분할 민감도는 같은 train 항적을 각각 한 조건만 바꾸는 짝 검산으로 관찰한다. 척도 변경 시 shape7·global 특징의 불변성, 점을 그대로 두고 경계만 나눌 때 global 특징의 불변성을 검사한다. 이는 수학적 특징 민감도의 확인이며 실제 사고·실제 센서 효과를 뜻하지 않는다.

각 반복은 가설·변경점·개발 결과·유지/폐기 이유를 기록한다. 최종 실패는 숨기지 않고 남긴다. 학습자가 설명해야 할 핵심은 “변경 전 가설이 무엇이었고, 어떤 비교가 그 가설을 지지하거나 약화했는가”다. 사용자는 코딩 입문 수준으로 확인됐으며, 기술적 성공과 사용자 이해는 따로 관리한다.

최종 추적 모델의 기본 예시는 생성 seed=9101·초기화 seed=42로 미리 정한다. 개선 사례는 그 실행의 shift에서 기준선은 틀리고 선택 모델은 맞힌 항적을 sample_id로 정렬한 첫 사례, 남은 실패는 선택 모델이 틀린 첫 shift 사례로 정한다. 해당 사례가 없으면 없다고 기록한다. 가장 높은 성능의 seed나 가장 보기 좋은 항적으로 교체하지 않는다. 입력 수는 선택 특징 수의 2배이며 기존 S0의 16개 입력과 새 모델 입력을 혼동하지 않는다.

역할 요청: 설계 판단 astra_decision/GPT-6 Astra/high, 특징 구현·원인 분석 sol_complex/GPT-6.1 Sol/max, 독립 검토 sol_review/GPT-6.1 Sol/high. 파일별 단일 담당을 유지하고 부모가 공통 실행과 통합을 담당한다.
