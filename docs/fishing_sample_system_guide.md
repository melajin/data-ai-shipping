> **범위 주의**  여기서 `straight`, `sweep`, `turn`은 생성기가 만든 경로 모양의 이름이다. 공식 조업 코드, 어업행동, 사고 여부가 아니다. 보고된 점수는 동일한 합성 생성 규칙 아래의 실험 결과이며 실제 선박이나 조업 자료의 정확도가 아니다. 실제 하드웨어를 연결하거나 실측하는 과정도 없다.

## 1. 이 실습에서 설명할 수 있어야 하는 것

작은 시스템 전체를 따라가며 다음 역량을 연습한다.

1. 합성 좌표가 어떤 가정과 수식으로 만들어졌는지 말하고, 그 가정이 모델에 주는 편향을 찾는다.
2. 부분선 경계를 보존하면서 길이·방향 변화·공간 분포를 계산하고 각 특징의 단위와 결측 의미를 설명한다.
3. 학습 자료에서만 대치·표준화·모델을 적합하고, 선박 그룹 단위로 학습·선택·보정·최종평가를 분리한다.
4. softmax 분류기의 손실과 역전파를 손으로 한 표본 계산해 보고, 실제 코드의 기울기 식과 대응시킨다.
5. test와 고정 stress 결과, 오차, 신뢰구간, 이상점수를 서로 다른 질문에 답하는 값으로 해석한다.
6. 한 번 본 test 결과에 맞춰 설계를 계속 고치면 그 test가 더 이상 독립평가가 아니라는 이유를 설명한다.

현재 장치는 합성 지역좌표만 사용하므로 전압·핀·센서 범위 같은 하드웨어 연결 조건은 없다. 실제 좌표계·시간·라벨 계약을 확인하기 전에는 실제 자료나 장치에 적용한다고 간주하지 않는다.

## 2. 시스템 흐름

```text
seed와 생성 가정
  → 합성 records(JSON)와 선박별 split
  → 계약·좌표·시간·분할 검증
  → 각 record의 부분선별 8개 기하 특징
  → train에서 결측 대치·평균/표준편차·결측 표시자 적합
  → 5개 분류 후보를 train으로 학습하고 validation NLL로 선택
  → calibration에서 선택된 모델의 온도 T만 보정
  → train에서 클래스별 기하 거리 기준을 적합하고 validation에서 임계값 결정
  → test와 stress 결과 산출 및 JSON 모델/예측/보고서 저장
  → 저장된 모델을 다시 읽어 예측 동일성을 확인하고 오프라인 HTML로 표시
```

이 흐름은 물리 현상부터 장치까지의 연결을 구현한 것이 아니다. 실제 위치와 시간의 관측을 입력으로 삼지도 않는다. 이 단계의 구현물은 합성자료, NumPy 모델, JSON 아티팩트, 오프라인 대시보드다.

각 split의 역할은 서로 대체할 수 없다.

| split | 이 실행에서 쓰는 일 | 이 자료로 해도 되는 선택 |
|---|---|---|
| `train` | 특징 대치·표준화 통계, 분류 가중치, 클래스별 공분산 적합 | 파라미터 학습 |
| `validation` | epoch 체크포인트, 후보 모델, 거리 점수 임계값 선택 | 정해 둔 후보 안에서 모델 선택 |
| `calibration` | 선택된 모델의 scalar temperature 선택 | 클래스 확률의 과신/과소신 조정 |
| `test` | 최종 일반 합성 조건 평가와 vessel bootstrap | 결과 보고만. 재선택 금지 |
| `stress` | 미리 고정한 합성 조건 변화에서의 평가 | 결과 보고만. 실제 분포 변화의 대체물 아님 |

서로 다른 역할의 자료를 한데 섞어 통계를 계산하면 검증이 낙관적으로 보일 수 있다. 특히 결측 대치나 표준화도 입력 전처리의 일부이므로 test까지 합쳐 평균·중앙값을 계산하지 않는다.

## 3. 합성 자료의 생성과 라벨

### 3.1 레코드와 그룹

기본 실행은 `seed=42`, 선박 그룹 36/12/12/12/12(train/validation/calibration/test/stress), 그룹별 클래스당 4개 레코드를 만든다. 각 선박 그룹에는 세 클래스가 모두 있고, 각 클래스마다 변형 표본 네 개가 있다. 따라서 기본 생성물은 84개 그룹, 1008개 record다.

- train: 36 × 3 × 4 = 432 records
- validation, calibration, test, stress: 각각 12 × 3 × 4 = 144 records
- 레코드 총수: 432 + 4 × 144 = 1008

한 그룹 안의 샘플들은 회전, 이동, 크기, 잡음, 누락 같은 그룹별 생성 조건을 공유한다. 같은 vessel ID가 두 split에 나타나지 않게 분리한다. 레코드 행만 무작위로 나눠 같은 그룹의 가까운 변형이 train과 test에 함께 들어가면, 모델이 새로운 선박에서도 통하는 기하 규칙보다 그 선박의 조건을 기억했는지 구별하기 어렵기 때문이다.

레코드의 주요 필드는 `sample_id`, `vessel_id`, `split`, `label`, `parts`, `sim_times`, `scenario`, `quality`다. `parts`는 부분선별 XY 미터 좌표 배열의 배열이다. 누락 관측 또는 명시적 단절을 하나의 직선으로 잇지 않는다. `sim_times`는 생성 중 붙인 시뮬레이션 초이며 실제 관측 시각이 아니다. 분류 특징은 `parts`에서만 계산하고 label·vessel_id·split·scenario·sim_times·quality는 모델 입력에서 제외한다.

### 3.2 경로 생성 규칙

각 경로에는 55~85개의 점이 생성된다. 길이 척도는 800~1600 m에서 뽑은 값에 선박 그룹의 배율을 곱한다. 그룹마다 회전각, 원점, 잡음 크기, 누락률, 부분선 단절률을 먼저 뽑고 세 라벨을 생성한다. 생성기에서 쓰는 방향각 `h(u)`로 한 단계의 이동 방향을 만들고, 이를 누적해 경로를 만든다.

$$
 u_i = \frac{i}{n-1},\qquad
 \Delta r_i = \frac{L}{n-1}(\cos h(u_i),\;\sin h(u_i)),\qquad
 r_i = \sum_{j < i}\Delta r_j
$$

그 뒤 회전행렬 `R(φ)`와 원점 `o`를 적용하고 좌표별 잡음을 더한다.

$$
 r'_i = R(\phi)r_i + o + \epsilon_i,\qquad
 R(\phi)=\begin{bmatrix}\cos\phi&-\sin\phi\\\sin\phi&\cos\phi\end{bmatrix}
$$

라벨별 방향각은 다음 가족에서 생성된다. 여기서 `s`는 ±1, `u`는 0~1 사이 진행률이다.

- `straight`: `h(u)=s·a·(u−0.5)+b·sin(2πu)`. `a`는 0~1 rad, 작은 파동 계수 `b`는 0~0.18 범위다.
- `sweep`: `h(u)=s·A·sin(2πc·u+ψ)`. 진폭 `A`는 0.25~1.3 rad, 주기 계수 `c`는 0.7~1.6, 위상 `ψ`는 −0.5~0.5 범위다. 이름은 굴곡 유형을 뜻하며 왕복 조업이나 그물 운용을 뜻하지 않는다.
- `turn`: `h(u)=s·a·(u−0.5)+b·sin(2πu)`. 주된 `a`는 0.75~3.6 rad, 보조 파동 계수 `b`는 0~0.12 범위다.

직진과 회전의 각도 범위가 0.75~1 rad에서 겹치고 모든 경로에 잡음·부분 관측이 있으므로 라벨 경계가 완벽히 분리되지 않는다. 이는 합성 분류 문제를 만들기 위한 가정이지 실제 운항을 재현하는 물리 모델은 아니다. 선박 운동 방정식, 해류, 풍향·파랑, 조업 상태 기계(FSM), 센서 오차 모델은 없다.

### 3.3 누락과 stress

base 그룹의 점 누락 확률은 그룹별 0.01~0.06, 단절 확률은 0.005~0.025다. 누락점이나 단절이 생기면 별도 부분선으로 보존한다. stress는 생성 시점에 정한 조건 변화로 경로 종류 라벨은 유지하면서 길이 배율 2.6, 잡음 배율 5, 점 누락 확률 0.24, 부분선 단절 확률 0.07을 사용한다. 이 stress는 생성기 안에서 미리 지정한 교란이지 현실에서 일어날 변화의 목록이나 사고 라벨이 아니다.

기본 실행에서 `test`와 `stress`는 서로 겹치지 않는 별도 12개 선박 그룹이며, stress 그룹에 네 조건(척도·잡음·점 누락·부분선 단절)을 동시에 바꾼다. 따라서 두 split의 점수 차이는 조건 효과와 그룹 표본 차이가 섞인 관찰이다. 이 설계만으로 특정 조건 하나의 순수 효과를 추정하거나 과적합의 원인을 입증할 수 없다.

### 3.4 데이터 경계에서 하는 검증

`data.py`의 `validate_record`와 `validate_dataset`은 좌표가 유한한 수인지, 부분선과 시뮬레이션 시각 배열이 맞는지, 시간 값이 부분선 사이에서도 증가하는지, 품질 카운트가 점 배열과 맞는지, ID와 split 그룹이 겹치지 않는지 확인한다. 잘못된 계약은 조용히 고쳐 쓰지 않고 `ValueError`로 거절한다. 길이가 0인 경로는 데이터 경계에서 없애지 않는다. 특징 단계가 그런 입력을 명시적으로 유보할 수 있도록 남겨 둔다.

## 4. 여덟 가지 기하 특징

각 record는 부분선 `j`를 서로 독립적으로 처리한다. 부분선의 점을 `p_{j,0}, …, p_{j,m_j−1}`라 하면 벡터와 총 경로 길이는 다음과 같다.

$$
 v_{j,i}=p_{j,i+1}-p_{j,i},\quad
 \ell_{j,i}=\|v_{j,i}\|_2,\quad
 L_j=\sum_i\ell_{j,i},\quad
 D_j=\|p_{j,m_j-1}-p_{j,0}\|_2
$$

`fishing_demo/features.py:extract_features`는 다음 순서의 8개 특징을 계산한다. `FEATURE_NAMES`의 순서가 모델 입력 순서이므로 이름이나 순서를 바꾸면 저장된 모델과의 호환성도 바뀐다.

| 순서 | 코드 이름 | 수식과 의미 | 단위 / 결측 조건 |
|---|---|---|---|
| 1 | `log1p_total_length_m` | `ln(1 + Σ_j L_j / 1 m)`. 여러 부분선의 길이 합에 로그를 적용한다. | 길이 단위를 1 m로 나눈 무차원 로그. 입력 크기 범위를 누른다. |
| 2 | `mean_part_straightness` | `mean_j(D_j/L_j)` (양의 길이인 부분선에 대해). 부분선별 직선성의 산술평균이다. | 무차원, 0~1. 부분선 길이로 가중하지 않는다. |
| 3 | `mean_abs_turn_rad` | 연속한 두 비영(非零) 세그먼트의 회전각 `θ=atan2(v_i×v_{i+1}, v_i·v_{i+1})`에 대해 `mean(|θ|)`. | rad. 유효 각도 쌍이 없으면 결측. |
| 4 | `turn_direction_concentration` | `|Σ θ| / Σ|θ|`. 좌우 회전이 상쇄되지 않고 한쪽으로 쌓이는 정도를 요약한다. | 무차원, 보통 0~1. 각도가 없으면 결측, 각도는 있으나 총 회전량이 0이면 0. |
| 5 | `std_turn_rad` | 위 signed `θ`들의 모집단 표준편차 (`ddof=0`). | rad. 유효 각도 쌍이 없으면 결측. |
| 6 | `max_abs_turn_rad` | `max(|θ|)`. 가장 큰 국소 방향 변화를 나타낸다. | rad. 유효 각도 쌍이 없으면 결측. |
| 7 | `mean_part_spread_ratio` | 각 부분선 점의 공분산 `C_j=(1/m_j)Σ_i(p_i−p̄)(p_i−p̄)^T`에서 고유값 `λmin≤λmax`를 얻어 `sqrt(λmin/λmax)`를 부분선별 평균한다. | 무차원. 점구름이 가늘고 길면 0에 가깝고 원형에 가까우면 커진다. |
| 8 | `mean_part_chord_deviation_ratio` | 각 부분선에서 시작점~끝점 chord에 대한 최대 수직거리 `H_j=max_i |(p_i−p_0)×(p_end−p_0)|/D_j`; `H_j/L_j`를 유효 부분선끼리 평균한다. | 무차원. 닫힌 부분선처럼 `D_j=0`이면 해당 부분선 값은 결측 처리 후 평균에서 제외한다. |

**두 가지 자주 하는 계산 실수**

첫째, `mean_part_straightness`는 `ΣD_j/ΣL_j`가 아니다. 예를 들어 길이 10 m, 직선성 0.9인 부분선과 길이 90 m, 직선성 0.2인 부분선이 있으면 코드 특징은 `(0.9+0.2)/2=0.55`다. 전체 길이로 가중한 비는 `(0.9·10+0.2·90)/100=0.27`이다. 서로 다른 뜻을 가진 두 값을 섞으면 구현과 설명이 어긋난다.

둘째, 서로 단절된 부분선의 끝과 시작을 이어 새 벡터를 만들지 않는다. 그 사이 경로가 관측됐다는 증거가 없기 때문이다. `sim_times`가 있어도 이 실습은 실제 속도나 가속도를 계산하지 않는다. 실제 시간 간격·위치 좌표계·선박 단위가 확인되지 않았고, 현재 시간은 시뮬레이션용이다.

회전각은 각 이웃 벡터 쌍의 `atan2(cross,dot)`로 −π~π 범위에서 계산한다. 따라서 표본 간 실제 방향 변화가 π보다 크면 짧은 방향 회전과 반대 방향 회전을 구별할 수 없다. 고빈도 회전이나 감긴 항적에서 각도 누적량을 실제 회전으로 해석하려면 샘플링 조건을 먼저 검토해야 한다.

### 4.1 손계산 예제: ㄱ자 부분선

점이 `(0,0) → (3,0) → (3,4)` m인 부분선 하나를 보자. 두 벡터는 `(3,0)`, `(0,4)`이고 각 세그먼트 길이는 3 m와 4 m다.

- 총 길이 `L=7 m`, 변위 `D=sqrt(3²+4²)=5 m`, 부분선 직선성 `5/7≈0.7143`.
- 첫 번째 특징 `ln(1+7)=ln(8)≈2.0794`.
- 외적은 `3·4−0·0=12`, 내적은 `0`이므로 국소 회전각 `atan2(12,0)=π/2≈1.5708 rad`.
- 각도 하나만 있으므로 평균 절대 회전과 최대 절대 회전은 모두 `π/2`, 표준편차는 0, 방향 집중도는 `|π/2|/|π/2|=1`이다.
- 끝점 chord 길이는 5 m다. 중간점의 chord 수직거리는 `|3·4−0·0|/5=2.4 m`이므로 chord 편차 비는 `2.4/7≈0.3429`다.
- 세 점의 중심 공분산은 대략 `[[2,1.3333],[1.3333,3.5556]]`, 고유값은 약 1.2342와 4.3214다. 따라서 spread ratio는 `sqrt(1.2342/4.3214)≈0.5343`이다.

이 예제는 계산식의 뜻을 확인하기 위한 것이다. 단 하나의 각도와 세 점으로 실선 유형을 판정할 수 있다는 뜻은 아니다.

## 5. 결측 대치와 크기 조정

일부 특징은 모든 record에 정의되지 않는다. 예를 들어 길이가 0인 전체 입력은 유효 분류 표본이 될 수 없고, 방향각이 만들어지지 않는 짧은 부분선에서는 각도 특징이 결측이다. `feature_matrix`는 이 `None` 값을 `NaN`으로 바꾸고, `extract_features`는 최소 하나의 양의 길이 부분선이 없으면 `valid=false`와 이유를 반환한다. pipeline은 valid이며 허용된 정수 label이 있는 행만 학습·평가에 포함한다. label을 정수 class index로 바꾸기 전에 유효 범위를 먼저 거르는 것도 잘못된 값이 인덱스가 되는 일을 막는다.

`Preprocessor.fit(X_train)`은 각 특징 열마다 다음을 train에서만 계산한다.

1. 결측이 아닌 학습 관측값의 중앙값 `m_d`를 계산한다. 결측 셀을 `m_d`로 채운다.
2. 채운 학습 열의 평균 `μ_d`와 모집단 표준편차 `σ_d` (`ddof=0`)를 계산한다.
3. `σ_d=0`이면 1로 바꾼다. 학습에서 열 전체가 결측이면 `m_d=μ_d=0`, `σ_d=1`로 둔다.
4. 임의 split `x`에 대해 `z_d=(filled(x_d)−μ_d)/σ_d`를 만들고, 원래 결측 여부 `M_d=1[x_d is missing]`를 별도 열로 붙인다.

따라서 8개 기하 특징은 16개 열(표준화한 8개 값 + 결측 마스크 8개)이 된다. 결측을 단순히 0으로 바꾸면 실제 값이 0인 경우와 관측하지 못한 경우를 구분하지 못할 수 있다. 중앙값과 마스크가 그 차이를 보존한다. `transform`은 학습 때 저장한 숫자를 재사용하고 새 split의 통계를 다시 맞추지 않는다.

## 6. 분류 모델과 손실의 수식 전개

### 6.1 선형 softmax 분류기

전처리된 한 record를 열벡터 `x∈R^d`, 클래스 수를 `C=3`, 클래스별 점수를 logit `z∈R^C`라 하자. 선형 후보는

$$
 z = W^T x+b,\quad W\in\mathbb{R}^{d\times C},\;b\in\mathbb{R}^{C}
$$

로 점수를 계산한다. `softmax`는 각 행의 최댓값을 먼저 빼서 수치적으로 안정화한 뒤 확률을 만든다.

$$
 p_k = \frac{\exp(z_k-z_{max})}{\sum_{c=1}^{C}\exp(z_c-z_{max})},\qquad
 \sum_k p_k=1
$$

정답 클래스가 `y`인 한 행의 교차엔트로피는 `ℓ=−ln(p_y)`다. 전체 `n`개의 유효 학습 행에 대한 평균 negative log-likelihood(NLL)는

$$
 L_{NLL}=-\frac{1}{n}\sum_{i=1}^{n}\log p_{i,y_i}
 =\frac{1}{n}\sum_i\left(\log\sum_k e^{z_{ik}}-z_{i,y_i}\right)
$$

이다. 마지막 등식은 `−log softmax`에 로그 정규화 항을 전개한 것이다. 점수 `z_k`에 대한 미분은 정답 여부를 나타내는 one-hot `q_{ik}`를 쓰면

$$
 \frac{\partial L_{NLL}}{\partial z_{ik}}=\frac{p_{ik}-q_{ik}}{n}
$$

이 된다. 정답 클래스에서 확률을 낮게 예측할수록 그 logit을 올리는 방향의 gradient가 나온다. 선형 모델의 gradient는 체인룰로

$$
 \nabla_W L_{NLL}=X^T(P-Q)/n,\qquad
 \nabla_b L_{NLL}=\sum_i(P_i-Q_i)/n
$$

가 된다.

### 6.2 L2 항과 손계산 gradient

현재 학습 목표는 NLL에 가중치만 벌점으로 더한다. `λ`가 L2 계수일 때

$$
 J(W,b)=L_{NLL}+\frac{\lambda}{2}\sum_{j,k}W_{jk}^2
$$

이고 따라서 `∇W J=∇W L_NLL+λW`, `∇b J=∇b L_NLL`이다. 편향 `b`는 벌점 대상이 아니다. `/2`가 있기 때문에 제곱합을 미분하면 계수 `λ`가 남는다.

손으로 한 표본을 계산해 보자. 설명을 간단하게 하려고 특징 하나 `x=1`, 3개 클래스, 현재 파라미터에서 나온 예측 확률 `p=(0.5,0.3,0.2)`, 정답 class 0으로 둔다. `q=(1,0,0)`이므로 logit gradient는

$$
 (p-q)=(-0.5,\;0.3,\;0.2),\qquad
 \ell=-\ln(0.5)\approx0.6931
$$

이다. `W=(0.2,−0.1,0.3)`, `λ=0.1`이라고 하면 정규화 비용은 `(0.1/2)(0.2²+(-0.1)²+0.3²)=0.007`이고, 전체 목적식은 약 `0.7001`이다. 데이터 gradient와 벌점 gradient를 더한 `∇W J`는 `(-0.5,0.3,0.2)+0.1·(0.2,-0.1,0.3)=(-0.48,0.29,0.23)`이다. 편향 gradient는 벌점 없이 `(-0.5,0.3,0.2)`다. 이 작은 예제의 `x=1`은 실제 모델의 16개 입력 열 중 하나만 남긴 계산 연습이다.

### 6.3 16개 tanh hidden unit 모델

비선형 후보는 hidden unit 16개를 사용한다.

$$
 H=\tanh(XW_1+b_1),\quad Z=HW_2+b_2,\quad P=softmax(Z)
$$

`D=(P−Q)/n`라 두면 출력층과 hidden 층의 gradient가 다음처럼 이어진다.

$$
 \nabla_{W_2}J=H^TD+\lambda W_2,\quad
 \nabla_{b_2}J=\sum_iD_i
$$
$$
 D_1=(DW_2^T)\odot(1-H^2),\quad
 \nabla_{W_1}J=X^TD_1+\lambda W_1,\quad
 \nabla_{b_1}J=\sum_iD_{1,i}
$$

`1−H²`는 `tanh`의 미분이다. `⊙`는 원소별 곱이다. 구현은 NumPy의 행렬곱으로 모든 batch를 한 번에 계산하는 full-batch gradient descent를 사용한다. 매 epoch 뒤 `θ ← θ−0.03·∇J`로 갱신한다. 은닉층이 없는 경우에는 앞의 선형식으로 같은 과정을 계산한다.

현재 모델에는 dropout, 재구성(reconstruction) 보조 손실, 시간 모델, sequence attention이 없다. 재구성 모델은 지금 구현된 기능으로 설명하면 안 된다. 필요성과 데이터 계약이 확인되면 이후 확장 후보로 별도 설계할 수 있다.

### 6.4 후보와 epoch 선택

사전에 고정한 후보는 다음 5개다. pipeline은 각 후보의 가중치를 train에 맞추고 매 epoch validation NLL을 기록한다. 후보 간 선택 기준도 validation의 **온도 보정 전 NLL**이다. NLL이 같으면 후보 목록의 앞쪽, 즉 단순한 모델이 먼저 선택된다.

| 후보 | 구조 | L2 `λ` | 이번 실행 validation NLL (보정 전) | best epoch |
|---|---|---:|---:|---:|
| `linear_l2_001` | 선형 | 0.01 | 0.527081 | 400 |
| `linear_l2_01` | 선형 | 0.1 | 0.596607 | 400 |
| `mlp16_l2_0` | tanh 16 | 0 | **0.467992** | 400 |
| `mlp16_l2_001` | tanh 16 | 0.01 | 0.478080 | 400 |
| `mlp16_l2_01` | tanh 16 | 0.1 | 0.601108 | 400 |

선택된 `mlp16_l2_0`는 이번 비교에서 L2 계수가 0인 모델이다. 이것은 정규화가 항상 성능을 높이지 않는다는 실험 예다. 반대로 다른 자료나 다른 seed에서 정규화가 도움이 되지 않는다고 결론 내릴 근거도 아니다. 후보군의 성능과 데이터 표본이 제한되어 있다.

구현은 validation NLL이 더 낮아지는 epoch를 보관하고 35회 연속 개선이 없으면 멈춘 뒤 최선 checkpoint로 되돌린다. 그러나 이번 기본 실행은 **다섯 후보가 모두 epoch 400까지 도달했다.** 실제 조기 종료가 발생하지 않았다. 따라서 이번 결과로 조기 종료가 과적합을 막았다고 주장할 수 없다. 구현에 조기 종료가 있다는 것과 이번 실행에서 조기 종료가 작동해 효과를 냈다는 것은 서로 다른 말이다.

## 7. 과적합을 줄이고 새 조건에 더 잘 맞추는 절차

과적합은 학습 표본에 맞춘 규칙이 새 표본에서는 유지되지 않는 현상이다. 이 프로젝트에서는 “정확도를 올리는 비법”보다 어떤 변화가 새로운 그룹에서 재현되는지 확인하는 절차가 핵심이다.

### 7.1 먼저 비교할 증거

- `history`의 train NLL과 validation NLL을 함께 본다. train NLL만 계속 내려가는데 validation NLL이 오르기 시작하면 학습 자료에 더 맞추면서 선택 자료에는 덜 맞을 수 있다.
- 같은 epoch와 같은 후보에서 train/validation 차이를 본다. 이번 선택 모델의 온도 보정 전 best epoch 400에서 train NLL은 0.435238, validation NLL은 0.467992로 차이는 약 0.032754다. 두 곡선은 epoch 400까지 감소했지만, 상한에 도달했으므로 이후의 곡선 형태나 seed 변화에서 같은 추세가 이어질지는 모른다.
- 다섯 후보의 validation NLL을 함께 본다. train 성능이 더 좋은 모델만 선택하지 않는다.
- confusion matrix에서 어떤 합성 유형 쌍이 섞이는지 본다. test에서는 `sweep` 정답 48개 중 15개가 `straight`로 예측됐다. 원인은 특징 겹침, 생성기 경계, 표본 변동 등일 수 있어 행렬만으로 원인을 확정할 수 없다.
- test와 stress의 차이를 통해 모델이 사전 고정한 부가 조건 변화(척도·잡음·누락·단절)에 민감한지 본다. 여기서 차이가 크면 그 조건이 특징·자료·측정 품질 중 어디에 영향을 주는지 추적한다.

### 7.2 이번 구현에서 이미 사용하는 통제

1. **선박별 그룹 분리:** 같은 vessel의 관련 표본이 fit과 최종평가에 흩어지지 않는다.
2. **train 전용 통계:** 중앙값·평균·표준편차·모델 가중치·거리 공분산은 train으로만 적합한다.
3. **작은 사전 후보군:** 선형과 16-unit MLP, 세 수준의 L2 조합만 비교한다. 후보를 test 성적을 본 뒤 추가하지 않는다.
4. **validation 선택:** 후보와 epoch를 test 결과로 고르지 않는다.
5. **별도 calibration:** 선택을 끝낸 뒤 temperature를 calibration으로 정한다.
6. **독립적인 최종 보고:** test/stress는 후보 선택에 참여하지 않는다. 보고서를 본 뒤 설계를 변경한다면 그 test를 반복해서 “최종 독립검증”이라 부르지 말고, 새로 모은 미사용 그룹 또는 새 고정 평가 집합이 필요하다.

### 7.3 개선을 시도할 때의 순서

실제 오차를 먼저 특정하고, 그 오차를 구별할 수 있는 변경 한 가지를 제안한 뒤, validation에서 확인한다. 여러 변경을 한꺼번에 하면 무엇이 개선 또는 악화의 원인이었는지 알기 어렵다.

1. **계약·원자료 오류부터 확인:** 좌표계 혼합, 단위 오류, 중복점, 시간 정렬, 부분선 경계, label mapping 오류가 있으면 모델 복잡도를 늘려도 올바른 문제를 풀지 못한다.
2. **오류 유형을 나눈다:** 혼동행렬·record별 예측·특징값·quality를 함께 보고 특정 클래스 또는 품질 조건에 오류가 모이는지 찾는다. 실제 원자료를 쓰게 되면 라벨 근거와 검토 이력도 확인한다.
3. **가장 단순한 설명을 먼저 바꾼다:** 특정 길이 척도에만 취약하면 길이 의존 특징과 그룹 크기 변동을 확인한다. 누락에 취약하면 부분선 분할과 관측 누락을 확인한다. 회전 특징이 불안정하면 샘플링 간격과 각도 wrap 문제부터 본다.
4. **train 다양성을 늘린다:** 정확한 라벨과 검증 가능한 출처를 가진 새로운 선박·기간·해역·관측 조건을 추가한다. 같은 선박의 거의 같은 궤적을 많이 복제하는 일은 독립적인 정보량을 같은 비율로 늘리지 않는다.
5. **그룹 조건을 실제 배포 질문에 맞춘다:** “새 선박”을 평가할 때는 선박 기준, “미래 기간”을 평가할 때는 시간 순서, “새 해역”을 평가할 때는 해역을 기준으로 holdout한다. 여러 조건을 동시에 일반화한다고 말하려면 그 교차 조건을 대표할 자료와 별도 평가가 있어야 한다.
6. **validation과 test 경계를 유지한다:** 모델·특징·임계값은 validation에서 선택하고, 새 설계가 확정된 뒤에만 잠긴 test를 한 번 평가한다. test를 보고 다시 고친 경우에는 다음 비교의 신뢰할 평가 자료를 새로 정한다.

L2를 무조건 키우거나 줄이지 않는다. 이번 run에서는 λ=0인 MLP가 λ=0.01 또는 0.1보다 validation NLL이 낮았고, 모든 후보가 400 epoch까지 계속 개선됐다. 다른 seed와 새 그룹에서 같은 차이가 유지되는지 확인하기 전에는 그 이상으로 일반화할 수 없다. 정확도 상승도 보장할 수 없다. 좋은 변경은 예상한 오차를 validation에서 줄이고, 그 이유가 새로 모은 독립 그룹에서 유지되는지까지 확인된 변경이다.

### 7.4 Validation 선택 과적합과 다음 개발 단계

test를 잠가 두면 test 누출은 막을 수 있지만, validation을 반복해서 들여다보며 특징·후보·학습 설정을 계속 바꾸는 선택 과적합까지 막아 주지는 않는다. 후보가 많아지거나 반복 실험 횟수가 늘면, 작은 validation 그룹에 우연히 잘 맞는 변경을 고를 수 있다. 현재 S0는 **seed 42 한 번과 사전 고정 5개 후보**의 제한된 비교로 유지한다. 이 실행 결과를 보고 기존 test/stress에 맞춰 특징·후보·임계값을 다시 조정하지 않는다.

후속 개발에서 후보 탐색을 넓히기 전에는 다음 평가 계획을 먼저 고정한다.

1. 개발용 그룹 안에서 `GroupKFold` 등 선박 그룹 교차검증으로 후보를 비교하거나, 모델 선택에 아직 쓰지 않은 별도 개발 그룹을 확보한다. record 행이 아니라 연결된 선박 그룹이 fold 경계를 상속하게 한다.
2. 비교할 후보 수(예산), 평가 지표, 생성 seed 목록과 모델 초기화 seed 목록을 실행 전에 정한다. 지정한 seed 결과를 모두 요약하고 최고 seed의 결과만 골라 보고하지 않는다.
3. 모델과 특징을 동결한 뒤 별도 calibration 그룹으로 온도를 보정하고, 그 다음까지 쓰지 않은 test 그룹에서 한 번 최종평가한다. 결과를 보고 다시 수정하면 다음 평가에는 새 미사용 test 그룹이 필요하다.

현재 기본 `demo` API는 하나의 `seed`를 합성 데이터 생성과 분류기 초기화에 함께 전달한다. 각 후보 분류기도 같은 초기화 seed를 받는다. 후속 실험에서는 `generator_seed`와 `model_init_seed`를 별도 입력·보고 필드로 나누고, 미리 선언한 seed 목록을 전부 기록하는 편이 원인 추적과 재현에 낫다. 이 분리는 향후 설계이며 현재 API가 이미 분리되어 있다는 뜻은 아니다.

### 7.5 조건별 paired 스트레스 실험 설계

현재 최종 `test`와 `stress`는 서로 다른 선박 그룹이다. 따라서 이 결과는 교란 요인 분석이나 모델 민감도 실험으로 재사용하지 않는다. 향후 원인을 조사할 개발 전용 paired 실험은 동일한 잠재 원경로와 같은 난수 흐름에서 다음 한 요인만 바꿔 만든다.

- 기준 경로 대 길이 척도만 변경
- 기준 경로 대 좌표 잡음만 변경
- 기준 경로 대 점 누락률만 변경
- 기준 경로 대 부분선 단절률만 변경

각 파생 record와 그룹은 원본 split 배정을 상속한다. 다만 원인 조사 paired 변형은 train/validation 등 개발용 그룹에서만 만들고, calibration/test 그룹에는 개발용 변형을 추가하지 않는다. 같은 원본 경로를 여러 split으로 복제하지 않는다. 같은 경로 seed, 방향·원점·척도, 표본별 난수 draw를 짝지은 뒤 해당 요인만 적용하고, 기준-변경 쌍의 특징 변화·유보 여부·예측 변화와 vessel 단위 지표 차이를 비교한다. 점 누락과 단절은 결정론적 난수값을 공유한 뒤 임계값만 바꿔 재현할 수 있다. 교란 강도와 비교 지표도 보기 전에 고정한다.

점 누락은 모델에 주어진 정보 자체를 줄일 수 있다. 따라서 paired 점수 저하만으로 “모델이 누락에 과민하다”고 단정할 수 없다. 향후 합성 paired fixture를 만들 때 생성기가 아는 삭제 전 완전 경로를 보존하고, 완전 경로와 관측점만 남은 경로에서 계산한 특징의 차이로 입력 정보 손실을 살핀다. 이어 같은 원본 경로 쌍에서 모델 예측 변화와 오류 변화를 기록해, 정보 손실에 대한 전체 반응을 관찰한다. 이 비교는 기여를 완벽히 분해하는 증명이 아니며, 필요하면 관측 가능한 특징 범위에서 통제한 모델 민감도 점검을 추가한다. 실제 자료는 관측하지 못한 경로의 정답 모양을 보통 알 수 없으므로, 결측 원인을 알 수 없는 상태에서 정보 손실과 모델 민감도의 순수 기여를 정확히 나눌 수 있다고 주장하지 않는다.

이 원인 조사와 후보 개발에는 개발용 그룹만 쓴다. 이미 본 현재 최종 `test`와 `stress`를 요인별 개발 자료로 재활용하거나, 그 결과가 좋아질 때까지 조정하지 않는다. 설계를 확정한 뒤에는 새 미사용 그룹을 확보해 모델 동결 → 별도 calibration → 미사용 test 순서로 평가한다.

## 8. 확률 보정, 평가 지표, 신뢰구간

### 8.1 temperature 보정

클래스 logit `z`를 양의 scalar `T`로 나눠 `p=softmax(z/T)`를 계산한다. `T<1`은 확률을 더 뾰족하게, `T>1`은 더 고르게 만든다. 양수로 모든 logit을 나누므로 argmax 클래스는 변하지 않는다. 이 단계는 주로 확률값의 NLL/Brier를 조정하며 분류 정확도를 고치는 방법은 아니다.

`fit_temperature`는 calibration 자료만 사용해 0.1~10의 로그 간격 81개 후보(`T=1` 포함)를 평가하고 calibration NLL이 가장 낮은 온도를 고른다. 기본 run의 온도는 `T=0.9440608763`이다. 손으로 이해할 예로 logits `(2,1,0)`일 때 `T=1`이면 첫 클래스 확률은 `e²/(e²+e+1)≈0.6652`, 정답이 첫 클래스일 때 NLL은 `−ln(0.6652)≈0.4076`이다. `T=2`에서는 첫 확률이 약 `0.5065`, NLL은 약 `0.6802`가 된다. calibration에서 실제 입력의 NLL을 계산해 grid 중 선택한다. 이 작은 예는 후보 온도를 비교하는 원리이지 실제 선정 온도를 유도하는 계산이 아니다.

이번 run에서 test NLL은 보정 전 0.442877에서 보정 후 0.438500으로 조금 낮아졌고 정확도는 그대로 0.8125였다. stress NLL은 보정 전 0.871707에서 보정 후 0.880226으로 높아졌다. calibration에 맞춘 온도가 모든 split의 점수를 반드시 개선하는 것은 아니다.

### 8.2 분류 지표

정답 행을 `i`, 예측한 클래스 확률을 `p_i`, 정답 one-hot을 `q_i`라 하자.

- Accuracy: `정답 클래스 예측 수 / 유효 라벨 표본 수`.
- 클래스별 `precision=TP/(TP+FP)`, `recall=TP/(TP+FN)`, `F1=2·precision·recall/(precision+recall)`이다. macro F1은 세 클래스 F1의 단순 평균이다. 표본 수가 많은 클래스에 더 큰 비중을 주지 않는다. 이번 실행은 train의 클래스별 support가 144이고 validation/calibration/test/stress는 각각 48이라 모두 균형이지만, 실제 자료에서 불균형이 생기면 accuracy와 macro F1이 다른 인상을 줄 수 있다.
- NLL: `−mean_i ln(p_{i,y_i})`. 정답 확률이 낮고 확신이 큰 오답에 큰 벌점을 준다.
- 다중분류 Brier: `mean_i Σ_k(p_{ik}−q_{ik})²`. 구현은 클래스 수로 다시 나누지 않는다. 확률의 예측 오차를 본다.
- 혼동행렬: 행이 실제 합성 라벨, 열이 예측 라벨이다. support는 실제 클래스별 유효 표본 수다.

정확도와 확률 품질은 다른 질문이다. 정확도는 argmax 결과를 비교하고 NLL/Brier는 확률의 품질을 살핀다. 결과 하나만 떼어 모델 전체를 설명하지 않는다.

### 8.3 Vessel bootstrap 신뢰구간

각 최종 split은 선박 12개 그룹을 가지므로 record를 독립이라고 가정해 행 단위로 뽑는 대신, 선박 ID를 복원추출한다. 매 반복에서 12개 선박을 복원추출하고 해당 선박의 모든 레코드를 함께 포함해 accuracy와 macro F1을 다시 계산한다. 200회 반복 결과의 2.5, 97.5 백분위수를 95% percentile 구간으로 적는다.

이번 test accuracy 구간은 0.7639~0.8752, macro F1은 0.7549~0.8747이다. stress accuracy는 0.5417~0.6875, macro F1은 0.5353~0.6866이다. 손으로 재현할 때는 “선박 12개를 복원추출 → 선택된 선박들의 전체 표본으로 지표 계산 → 200회 반복 → 값 정렬 후 2.5%, 97.5% 분위수”를 수행한다. 실제 코드는 결정적 seed를 써서 반복을 재현한다.

이 구간은 이 생성기·이 seed·이 실행 결과에 조건부로 계산한 표본 변동 요약이다. 생성기의 편향, 새로운 해역/시기, 다른 모델 초기화 seed의 불확실성은 포함하지 않는다. 따라서 “실제 성능이 이 구간에 든다”거나 “95% 확률로 일반화 성능이 이 범위다”라는 의미가 아니다.

## 9. 분류 확률과 별개의 이상 점수

`AnomalyModel`은 train에서 표준화 특징과 결측 마스크를 포함한 각 클래스의 평균과 공분산을 맞춘다. 클래스 `k`의 표본평균을 `μ_k`, 표본 공분산을 `S_k`, 특징 차원을 `d`라 하면

$$
 S_k=\frac{1}{\max(n_k-1,1)}\sum_{i:y_i=k}(z_i-\mu_k)(z_i-\mu_k)^T,
 \quad v_k=\operatorname{tr}(S_k)/d
$$

공분산을 역행렬로 계산할 수 있게 고정 shrinkage `α=0.2`와 ridge를 적용한다.

$$
 r_k=\max(10^{-6},v_k·10^{-6}),\quad
 \tilde S_k=(1-\alpha)S_k+(\alpha v_k+r_k)I
$$

표본 `z`의 클래스별 squared Mahalanobis 거리는

$$
 d_k^2(z)=(z-\mu_k)^T\tilde S_k^{-1}(z-\mu_k),\qquad
 s(z)=\min_k d_k^2(z)
$$

이다. 가장 가까운 합성 클래스 분포에서 얼마나 멀리 있는지 나타내며 값이 클수록 세 클래스 모두에서 멀다. 거리 크기는 “사고 확률”, “사고 감지”, “새 조업 확률”이 아니다. 클래스별 분포가 실제 현상을 대표한다는 근거가 없기 때문이다.

pipeline은 validation 점수의 95 백분위수를 임계값으로 고정하고 `score > threshold`인지를 표시한다. 이것은 사용자 화면을 위한 규칙이며 보장된 오탐률이나 conformal prediction 보장은 아니다. 손계산 예로 공분산이 `I`, 평균이 `(0,0)`, 입력이 `(3,4)`이면 squared Mahalanobis 거리는 `3²+4²=25`다. 실제 코드는 16차원 특징에서 세 클래스 거리를 모두 계산해 그중 최솟값을 쓴다.

기본 실행의 validation 95 백분위 임계값은 17.6126이다. test 표본 중 threshold 초과 비율은 0.0139, stress는 0.3819였다. 별도의 민감도 점검에서 test record 60개의 가장 긴 부분선 중간점에 `(1500,−1500)` m를 더했을 때 점수 증가 중앙값은 5234.10이고 60개 모두에서 증가했다. 이 실험은 큰 좌표 교란에 대한 점수 반응을 보여 줄 뿐 사고 탐지율이나 실제 오염 감지 성능이 아니다.

| split | groups / records | accuracy | macro F1 | NLL | Brier |

| train | 36 / 432 | 0.8264 | 0.8271 | 0.4302 | 0.2422 |

report의 다수 클래스 baseline은 train에서 정한 최대 빈도 클래스만 항상 예측한다. 이번 세 클래스 균형 예에서는 test와 stress accuracy가 0.3333, macro F1 0.1667이었다. 모델 수치가 이 간단 기준보다 높더라도 이는 **합성 세 경로 유형**에 대한 상대 비교이며 실제 조업 분류 성능을 뜻하지 않는다.

선택 모델 test 혼동행렬은 행이 정답 `[straight,sweep,turn]`, 열도 같은 순서다.

$$
 \begin{bmatrix}
 40&3&5\\
 15&32&1\\
 1&2&45
 \end{bmatrix}
$$

가장 눈에 띄는 오류는 sweep 48개 중 15개가 straight로 분류된 것이다. 스트레스 행렬은 `[[29,13,6],[12,27,9],[10,5,33]]`였다. stress의 정확도는 test보다 약 19.44%p 낮고 NLL은 약 두 배다. 그러나 비교 대상은 서로 다른 12개 그룹이고 stress에는 네 조건 변화가 함께 적용됐다. 그러므로 19.44%p 차이는 이 실행의 관찰값이며 교란의 순수 효과나 과적합의 증거가 아니다. 생성 조건, 그룹 구성, 누락으로 정보가 사라진 영향, 모델 반응을 분리하려면 앞 절의 개발용 paired 실험이 필요하다. 이 비교만으로 원인이 어떤 한 특징인지, 현실의 조건 변화에서도 같은지 확정할 수 없다.

이는 동시에 다음 두 판단을 허용한다.

- **허용:** 이번 seed에서 선택한 모델이 사전 분리된 test 선박 12개에서 보고된 합성 경로 유형을 어느 정도 구분했고, 사전 지정한 stress에서는 성능이 내려갔다.
- **허용되지 않음:** 실제 어업행동을 정확히 81.25% 분류한다, 사고를 찾아낸다, 새 해역에도 같은 점수를 낸다, stress 점수가 실제 분포 이탈률을 나타낸다.

## 11. 대시보드에서 시스템을 관찰하는 방법

`fishing_demo/visualization.py:write_dashboard`는 JSON 보고서와 예측을 내장한 자체 포함 HTML을 만든다. 외부 라이브러리나 네트워크를 요구하지 않는다. JSON을 안전하게 내장하고 화면의 사용자 값은 HTML 코드로 해석하지 않도록 DOM 텍스트로 그린다. 브라우저에서 `outputs/sample_system/dashboard.html`을 열어 다음 순서로 본다.

1. **상단 요약:** 선택된 모델, test accuracy/macro F1, stress−test 변화와 synthetic 표기를 확인한다.
2. **부분선 경로 탐색:** split과 synthetic class를 고르고 record를 선택한다. XY 축이 동일 축척인지, 각 부분선 시작·끝이 표시되는지, 단절 경계가 연결되지 않았는지 본다. 좌표는 실제 지도 위 위치가 아니다.
3. **예측 근거:** 합성 정답, 예측, 보정된 클래스 확률을 본다. 잘못 분류된 샘플에서 특징과 geometry를 같이 확인하되, 표시된 확률을 실제 조업 가능성으로 바꾸어 읽지 않는다.
4. **거리와 특징:** 이상 점수와 validation 임계값을 비교하고 입력 특징 표를 살핀다. 결측은 0이 아니라 미확인으로 표시된다. 임계 초과는 사고 판정이 아니다.
5. **혼동행렬과 NLL 곡선:** 선택 split의 행/열을 읽고 validation과 train 곡선 간격 및 기울기를 본다. epoch 400 표시는 이번 run에서 조기 종료되지 않았음을 함께 확인한다.
6. **후보·split 표와 감사 정보:** 다섯 후보의 validation NLL, split별 표본 수·점수, 설정 seed, 데이터 해시, split 그룹과 test 재선택 여부, 제한사항을 확인한다.

대시보드는 설명을 돕는 관찰창이다. 지도, 실제 관측, 하드웨어 계측 장치가 아니다. 시각화에 나온 한 표본의 모양으로 정확도 전체를 판단하지 말고 보고서의 그룹별 지표와 오차 분포를 함께 본다.

## 13. 직접 실행하기

기본 시스템 실행에는 NumPy만 필요하다. 테스트는 Python 표준 라이브러리의 `unittest`를 사용한다. 아직 설치하지 않았다면 NumPy를 설치한 뒤 저장소 루트에서 실행하고, 출력은 `outputs/sample_system/`으로 둔다.

```powershell
# 기본 런타임 의존성
python -m pip install numpy

# 전체 기본 흐름: generate → train → evaluate → JSON 및 HTML 저장
python tools/run_sample_system.py demo --out outputs/sample_system --seed 42 --epochs 400

# 생성과 학습을 따로 살펴보고 싶을 때
python tools/run_sample_system.py generate --out outputs/sample_system --seed 42
python tools/run_sample_system.py train --data outputs/sample_system/sample_dataset.json --out outputs/sample_system --seed 42 --epochs 400

# 저장한 모델의 추론 경로
python tools/run_sample_system.py predict --data outputs/sample_system/sample_dataset.json --model outputs/sample_system/model.json --out outputs/sample_prediction

# 표준 라이브러리 unittest로 테스트 스위트 실행
python -m unittest discover -s tests -v
```

`--epochs`는 모델 구현에서 최대 400으로 제한한다. 재현할 때 seed와 입력 파일을 함께 기록한다. `train`은 `fishing_sample_v1` JSON 계약을 요구하고 `predict`는 이 합성 모델 스키마와 local XY meter 계약을 요구한다. 일반 CSV를 실제자료처럼 넣어 실행하는 인터페이스가 아니다. 실습 후 `report.json`의 `audit`, split별 `metrics`, `candidates`, `anomaly`와 `predictions.json`의 개별 오답을 대시보드와 대조한다.

## 14. 실제자료가 도착한 뒤 열어야 할 관문

이 단계에서 만든 모델이 실제자료에 자동 적용되는 것은 아니다. 실제 수신 후에는 우선 원자료 구조와 사용 권한을 확인하고 입력 계약부터 세운다.

1. **좌표와 단위:** 위경도인지 투영 좌표인지, 어떤 좌표 기준계인지, 거리 단위가 무엇인지, 좌표 오차와 해상도는 어떤지 확인한다. 위경도를 미터라고 간주해 그대로 넣지 않는다.
2. **시간:** 시간대, 단위, 중복·누락·정렬, 위치 간 간격을 확인한다. 실측 시간이 검증되기 전에는 속도·가속도 특징을 추가하지 않는다.
3. **부분선과 품질:** 항적 단절·장비 누락·정박·품질 저하를 어떻게 표시할지 합의한다. 관측이 없던 구간을 직선으로 연결하지 않는다.
4. **라벨의 뜻과 근거:** 현재 `straight/sweep/turn`을 실제 fishing_code로 대응시키지 않는다. 실제 분류 대상 정의, 모호·복합 활동, 라벨 출처와 검토 방법을 정한 후 별도 mapping을 만든다. 사고 label이 없다면 사고 모델을 학습했다고 말할 수 없다.
5. **그룹 holdout:** 선박 ID와 trip ID 등 연결된 자료가 train/test 양쪽으로 새지 않게 분리한다. 실제 사용 질문이 미래 운항 또는 새 해역이면 기간·해역을 별도로 holdout할 충분한 그룹이 있는지 확인한다.
6. **비교 가능한 평가:** 실제 표본 기준선과 유효/유보율, 클래스별 support, confusion, NLL/Brier, 그룹 bootstrap 등을 정하고 test는 고정한다. 분포 변화 및 실패 시 시스템 동작도 따로 검증한다.
7. **전처리·모델 변경 승인:** 기존 `predict`는 synthetic/local XY 모델만 허용한다. 실제 스키마, feature 단위, 모델 버전, 검증 보고를 정한 뒤 별도 adapter와 실제자료 평가 단계로 확장한다.

실제자료는 표본이 도착했다고 곧바로 학습시키지 않는다. label과 좌표/time 계약, 그룹 식별, 평가 설계를 먼저 확인하고 이전 합성 단계에서 구현·관찰·검증한 내용을 실제 원자료에서 다시 검증한다.

## 15. 학습 질문

먼저 답을 보지 않고 짧게 설명한 뒤 아래 정답 기준과 비교한다.

1. 같은 선박의 레코드를 record 단위 무작위 분할하면 어떤 누출 위험이 있나?
2. 두 부분선의 `mean_part_straightness`가 0.55라고 해서 `ΣD/ΣL`도 0.55라고 할 수 있나?
3. angle feature가 결측일 때 왜 중앙값만 넣지 않고 결측 mask도 붙이나?
4. 이번 실행의 MLP 후보 중 λ=0 모델이 선택됐다. 이 결과만으로 L2를 제거하는 것이 항상 더 낫다고 말할 수 있나?
5. test 이상 점수가 임계값을 넘으면 사고로 해석할 수 있나?
6. test 결과를 본 뒤 특징을 추가하고 같은 test 점수를 다시 최종 성능이라고 보고해도 되나?
7. 이 데이터의 `sim_times`로 실제 선박 속력과 가속도를 계산할 수 있나?
8. temperature를 0.944로 조정했는데 왜 test 정확도가 그대로일 수 있나?

### 답안 기준

1. 같은 선박의 그룹 특징·생성 조건을 공유하는 가까운 표본이 양쪽에 들어가 성능을 낙관적으로 보이게 할 수 있다. 이 구현은 vessel 단위로 split하고 겹침을 감사한다.
2. 아니다. 부분선별 직선성의 평균은 각 부분선에 동일 가중치를 주고 `ΣD/ΣL`은 길이로 가중한다. 예제의 값은 각각 0.55와 0.27이다.
3. 0은 실제 측정된 값일 수 있지만 결측은 관측이 없었다는 다른 상태다. mask가 이 정보를 모델 입력에 남긴다.
4. 아니다. 이번 제한된 합성 후보·seed의 validation 결과다. 다른 표본·조건·seed에서 L2의 효과가 달라질 수 있다.
5. 아니다. 점수는 세 합성 클래스의 공분산 분포에서의 거리이며 사고 label로 학습·검증되지 않았다.
6. 아니다. 그 test는 이제 변경 선택에 영향을 준 자료다. 새로운 미사용 고정 평가 자료가 필요하다.
7. 아니다. 초는 시뮬레이션 시간을 뜻하고 실제 timestamp가 아니다. 위치 좌표도 실제 관측이 아니다.
8. 양수 temperature는 logits 순서를 바꾸지 않아 argmax가 유지된다. 확률의 NLL/Brier만 변할 수 있다.

## 16. 팀 설명용 2분 해설

> “이번 S0는 실제 어업 라벨이 없는 상태에서 전체 데이터-모델 흐름을 연습하려고 만든 합성 실험입니다. 84개 가상 선박 그룹의 좌표를 생성하고, 각 경로는 straight·sweep·turn 중 하나지만 이 이름은 생성 경로 유형일 뿐 공식 조업 코드가 아닙니다. 하나의 경로가 누락이나 단절로 여러 부분선이 되면 사이를 연결하지 않습니다.
>
> 각 record에서 총 길이, 부분선 직선성 평균, 국소 회전 통계, 점 분포의 spread와 chord 편차 등 여덟 기하 특징을 계산합니다. 결측은 train 중앙값으로 채우고 원래 결측이었다는 mask도 입력에 붙입니다. 이 통계와 모델은 train에서만 맞춥니다. 후보와 epoch는 validation NLL, 확률 온도는 별도 calibration NLL로 고르며 test와 사전 고정 stress는 마지막 결과 확인에만 씁니다. 같은 선박이 split을 넘지 않았는지도 검사합니다.
>
> seed 42의 선택 모델은 16 hidden-unit tanh 분류기이고 test accuracy 0.8125, stress accuracy 0.6181을 기록했습니다. stress 조건에서 성능이 내려간 것은 이 생성기가 정한 큰 잡음·누락·단절 변화에 지금 특징이 민감하다는 관찰입니다. 선박 단위 bootstrap 구간도 보고하지만 생성기 편향과 실제 해역을 포함하지 않습니다. 그러므로 이 점수는 실제 조업 분류 정확도나 사고 감지 결과가 아닙니다. 다음 단계는 실제 자료의 좌표·시간·라벨·선박 그룹 계약을 확인하고 독립 holdout에서 다시 검증하는 일입니다.”

팀 리뷰에서 질문이 나오면 이 순서로 근거를 짚는다: `sample_system_contract.md`의 경계 → `data.py` 생성 가정 → `features.py` 수식 → `models.py` 학습 목적식 → `pipeline.py` split 감사 → `report.json` 지표 → `dashboard.html` 개별 표본 관찰. 성능 숫자와 평가 범위를 한 문장 안에서 분명히 연결한다.
