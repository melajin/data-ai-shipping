## 0. 공통 규칙 (모든 작업에 적용)

### 절대 금지
- **final holdout 1,473척을 학습 입력·예측·성능 평가·하이퍼파라미터 선택에 쓰지 않는다.** 캐시 로드 후 final 행은 곧바로 분리하고, 분리 이전에 전체 행렬에 대해 어떤 통계(결측 대체값, 클립 범위, 분위수 기준 등)도 계산하지 않는다.
- 1차 코드(`real_model_cycle_20261028.py`, `run_evaluation_cycle_20261028.py`, `real_geometry_20261028.py`)와 기존 2차 산출물(`outputs/cycle2_20261029/` 아래 기존 파일)은 **수정하거나 덮어쓰지 않는다.** 새 산출물은 `outputs/cycle2_followup/`에 둔다.
- 원자료 재추출은 하지 않는다. 기존 특징 캐시(npz)를 쓴다.

### 고정 조건
- 모델: ExtraTrees 256트리. 작업 4에서 지정한 한 요인 외에는 기존 하이퍼파라미터를 그대로 쓴다.
- 분할: 1차 분할 함수, seed 3201/3202/3203.
- 초기화: 42·137, 확률 평균 후 채점(기존 방식).
- 라벨: `label_vocabulary.json`을 읽고 해시 검증. 한글 클래스명을 소스에 직접 쓰지 않는다.
- 클래스 순서와 동점 규칙: 코드 상단에 상수로 명시한다. 동점은 dtype과 무관하게 생길 수 있으므로(트리 평균 확률은 분모가 작은 유리수), 동점 발생 건수를 셀·분할마다 기록한다.

### 저장 규칙
- 확률은 **float64**로 저장한다. 판정 label(argmax 결과)도 함께 저장한다.
- 저장 직후 파일을 다시 읽어 확률·판정·혼동행렬·지표가 저장 전 값과 일치하는지 검사한다. 불일치가 있으면 예외로 중단한다.
- 모든 입력 파일과 출력 JSON의 SHA-256을 리포트에 기록한다.

### NLL 정책
- 두 가지를 모두 보고한다: (a) 현행 `tiny` 바닥값, (b) `1e-15` 바닥값.
- 정답 확률이 정확히 0인 건수와, 그 건들의 NLL 기여(전체 분모 기준)를 분리해서 보고한다.
- 바닥값을 결과가 좋아지도록 사후 선택하지 않는다.

### 실행 환경
- 머신 메모리 여유가 적다. **전경 단일 프로세스**로 실행하고 병렬 워커를 늘리지 않는다.
- 10분을 넘길 작업은 셀 단위로 체크포인트를 남겨 재개 가능하게 만든다.

### 보고 형식
작업마다 `docs/cycle2_followup_<작업번호>_<날짜>.md`를 만든다. 각 문서에는 다음 세 칸을 구분해 적는다.
- **확인된 사실**: 측정값과 그 계산 범위
- **해석**: 측정하지 않은 설명은 여기에만 둔다
- **미수행·한계**: 하지 않은 것, 독립 반복이 아닌 것

분할 3개는 독립 반복이 아니다. 신뢰구간이나 유의성 검정으로 쓰지 않는다. 분할별 값, 평균, 범위, 양수 분할 수만 보고한다.

## 작업 4. 정답 확률 0 처리 — 한 요인 대조

**목적:** NLL 악화가 전반적 과신 때문인지, 순수 잎이 만드는 0확률 때문인지 가른다. **온도 보정보다 먼저 한다.** 온도 보정 `softmax(log(p)/T)`는 p=0을 회복하지 못하기 때문이다. log 0 = −∞이고, tiny 바닥값을 써도 T=2에서 한 건당 약 354 nats가 남는다.

### 대상 셀
`all/balanced/dist36`, `all/balanced/dist36_scale32` 두 개만.

### 보정용 자료 분리
- 각 분할의 train 선박을 클래스별로 층화해 **80% 적합 / 20% 보정**으로 나눈다. 선박 ID 해시로 결정적으로 나눈다.
- 적합 자료가 줄었으므로 **같은 80%로 적합한 무처리 기준 모델**을 반드시 함께 만든다. 처리 효과는 이 기준과 비교한다. 기존 100% 적합 셀과 직접 비교하지 않는다.

### 비교할 처리 (각각 독립, 섞지 않음)
- **A. min_samples_leaf:** 후보 {1, 2, 5, 10}. 보정 자료의 NLL(1e-15 바닥값)로 하나를 고른 뒤 validation에서 평가한다.
- **B. 균등분포 혼합:** p' = (1−ε)·p + ε/K, K=4. ε 후보 {0, 1e-4, 1e-3, 1e-2, 3e-2}. 보정 자료의 NLL로 고른 뒤 validation에서 평가한다.

### 보고 항목 (셀 × 처리 × 분할)
- 정답 확률 0 건수와 그 NLL 기여
- NLL(두 바닥값 정책), Brier
- Macro F1, 정확도, 통발 recall/precision, 클래스별 recall
- 선택된 하이퍼파라미터 값(분할마다 다르면 그대로 적는다)

### 판정 (실행 전 고정)
- 0확률 건수가 0이 되고 NLL이 기준보다 낮아지면 "0확률 처리로 NLL 악화의 해당 부분이 설명된다"로 기록한다.
- A가 Macro F1이나 통발 recall을 분할 2/3 이상에서 낮추면 그 손실을 따로 명시한다. A는 판정도 바꾸지만, B는 ε가 작으면 argmax를 거의 바꾸지 않는다.

산출물: `docs/cycle2_followup_4_zero_prob.md`, `outputs/cycle2_followup/zero_prob.json`

## 작업 5. 온도 보정

**전제:** 작업 4에서 0확률 문제를 처리한 설정을 쓴다. 처리 방식은 작업 4 결과에 따라 B를 기본으로 한다. 작업 4가 끝나지 않았으면 시작하지 않는다.

- 작업 4와 같은 80/20 분리를 쓴다. 20% 보정 자료에서 양의 단일 온도 T를 적합하고 validation에서 평가한다.
- 기존 프로젝트의 보정 함수(1차 `real_model_cycle_20261028.py`)를 **불러 쓰되 수정하지 않는다.** 그 함수의 clipping 정책을 리포트에 적는다.
- 양의 단일 온도는 argmax를 바꾸지 않는다. F1·recall이 바뀌면 버그로 보고 정지한다.
- 보고: NLL(두 정책), Brier, 선택된 T(분할별).
- **이 결과로 1차 관문 통과·실패를 판정하지 않는다.** 1차 관문은 final에서 mean9_mlp16과 비교하는 조건이고, 이 작업은 개발 validation이다. 기준 모델 mean9_mlp16은 0확률을 내지 않는 MLP라는 점도 리포트에 적는다.

산출물: `docs/cycle2_followup_5_calibration.md`

## 작업 6. 통발 전용 이진 모델 확인

**목적:** 검토서의 통발 OVR AUC 0.58~0.62와 AP 0.19~0.21(통발 비율 약 0.142)은 4클래스 모델의 통발 점수다. 전용 이진 모델로도 분리가 약한지 확인한다.

- 특징: dist36, dist36_scale32 두 가지. 관측 행: 전량.
- 모델: ExtraTrees 256(이진, class_weight="balanced"), 그리고 비교용 로지스틱 회귀(표준화는 train에서만 적합).
- 분할별로 ROC-AUC, AP, 통발 비율을 보고한다. 기존 4클래스 모델의 통발 점수 AUC/AP와 같은 표에 놓는다.
- **임계값 선택이나 결정 규칙 조정은 하지 않는다.**

### 판정 (실행 전 고정)
- 이진 모델 AUC가 분할 3/3에서 0.65 미만이면 "현재 특징에서 통발 순위 분리가 약하다"로 기록하고, 결정 규칙 조정 실험은 보류한다.
- 0.65 이상이면 결정 규칙 진단을 다음 후보로 올린다. 이 경우에도 실행하지 않고 보고만 한다.
- AUC가 낮아도 "특징에 정보가 없다"는 증명으로 쓰지 않는다.

산출물: `docs/cycle2_followup_6_trap_binary.md`

## 작업 7. train/validation 집계 2×2 대조

**목적:** 관측 행 확대 효과가 학습 쪽 특징 개선인지, 평가 입력 정밀도 개선인지 가른다.

- 고정: ExtraTrees 256, balanced, dist36, 작업 3의 float64 저장 규칙.
- 조건 4개: train 집계 {s4, all} × validation 집계 {s4, all}. (s4,s4)와 (all,all)은 작업 3 결과를 재사용한다.
- 평가: **양쪽 집계 모두에서 평가 가능한 선박의 공통 집합**과, 원래 평가 집합을 둘 다 보고한다. coverage를 함께 적는다.
- 보고: Macro F1, 정확도, 통발 recall, 연안복합 예측 비중(분할별).
- 해석 주의: (all train, s4 validation) 조건은 특징의 잡음 수준이 train과 validation에서 다르다. 이 조건이 나쁘게 나오면 분포 차이 때문일 수 있다고 적는다.

산출물: `docs/cycle2_followup_7_agg_2x2.md`
