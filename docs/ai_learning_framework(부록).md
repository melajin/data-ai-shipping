# AI 이론을 폭넓게 배우고 실제 모델을 해석하는 학습 틀

이 문서는 본인의 AI 학습을 시작하고 확장하기 위한 **학습자용 지도**다. 개별 제품의 사용법이나 특정 버전의 성능을 중심에 두지 않고, AI의 주요 이론 분야를 연결해 이해한 뒤 회사별 실제 모델을 공개 근거로 해석하는 것을 목표로 한다.

이 학습 틀에 맞춘 [18장 교재](ai_textbook/모델%20해석%20목차.md)를 함께 읽는다. 교재는 개념 설명, 수식과 계산 예제, 연습·힌트·별도 해설, 공개 모델 사례와 출처를 제공한다. 교재 작성 상태와 학습자의 이해·실습 수행 상태는 구분한다.

## 학습 범위와 현재 조건

학습의 중심 질문은 세 가지다. 어떤 문제를 풀기 위한 이론인가, 어떤 가정과 메커니즘으로 동작하는가, 실제 모델이나 시스템에서 그 개념을 어디까지 확인할 수 있는가.

탐색·논리·계획, 통계학습, 확률모형, 신경망, 생성, 강화학습·제어, 인과, 전문 분야, 대안적 접근, 시스템과 평가를 모두 학습 대상에 포함한다. 아래 목록은 확장 가능한 지도이며 모든 세부 연구 주제를 열거한 완결 목록은 아니다. **선택은 실습 주제·심화 수준·진행 순서에 적용한다. 이론 분야 자체를 제외하는 선택 과정으로 축소하지 않는다.**

| 항목 | 현재 상태 | 개인화 전에 확인할 내용 |
| --- | --- | --- |
| 문서 용도와 학습자 | 본인의 학습을 위한 학습자용 문서로 확인됨 | 학습 활동에서 본인이 설명·판단·구현할 핵심 과정 |
| 목표 | 폭넓은 이론 이해와 실제 모델 해석 | 분야별로 원하는 설명·설계·검증 깊이 |
| 현재 수준 | 미확인 | AI 경험, 선형대수·미적분·확률통계, Python·알고리즘 이해 |
| 시간 | 미확인 | 주당 학습 시간, 지속 가능한 학습량 |
| 장비와 환경 | 현재 작업공간의 Windows·PowerShell 확인; 학습 실습 환경·가용 자원 미확인 | 학습용 Python·개발 도구, CPU/GPU·메모리, API·계산 자원 |
| 물리 장치 실습 조건 | 미확인 | 장비 보유 여부, 부품의 허용 조건, 측정·전원 환경 |

이 조건을 확인하기 전에는 기간, GPU 규모, API 예산, 장치 연결을 확정하지 않는다. 우선 G0 진단과 M01의 문제 정의부터 시작하고, 필요한 수학·프로그래밍 개념을 함께 준비한다.

문서는 네 층으로 확장한다. **학습 지도 → 개념 문서 → 비교·연결 문서 → 갱신되는 모델 사례**의 순서다. 같은 개념의 정의와 원리는 개념 문서에 두고, 회사별 공개 사실과 시점은 모델 사례에 기록한다.

## 9축으로 보는 전체 지도

9축은 학습 내용을 보는 관점이다. 18모듈은 실제 학습을 진행하기 위한 묶음이다. 하나의 모듈이나 개념은 여러 축에 연결될 수 있으며, 축은 상호배타적 분류나 일렬로 끝내는 단계가 아니다.

| 축 | 중심 질문 | 대표 내용 | 대표 연결 모듈 |
| --- | --- | --- | --- |
| ① 기초 수학·CS | 원리와 계산을 설명하는 언어는 무엇인가? | 선형대수, 미분, 확률·정보, 알고리즘, 수치 계산 | M02·M03·M04 |
| ② 문제·데이터·실험 | 무엇을 풀며 어떤 관측으로 확인하는가? | 목표, 표집, 누수, 기준선, 실험 설계, 개입 | M01·M03·M06·M15·M18 |

| ⑨ 실제 모델 해석 | 공개된 모델 사례를 어떤 이론과 연결할 수 있는가? | 공식 자료, 공개 구조·학습 설명, 평가 조건, 미확인 내부 정보 | 모든 모듈에 붙이는 사례층 |

예를 들어 Transformer의 구조와 표현은 ④에, 그 모델을 학습하고 디코딩하는 과정은 ⑤에, 언어·멀티모달 과제는 ⑥에 연결한다. 인과는 전문 분야인 동시에 문제·실험 설계인 ②와 평가 해석인 ⑧에도 연결한다.

③은 **학습 신호**, **지식 재사용 방식**, **데이터 접근·분산 조건**의 하위 묶음으로 기록한다. 예를 들어 자기지도 사전학습을 한 모델을 전이·미세조정하며 연합 환경에서 학습할 수 있으므로, 이들을 같은 수준의 배타적 유형으로 취급하지 않는다.

## 먼저 구분할 개념

- **목표·손실·대리 지표:** 실제로 달성하려는 목표, 학습에서 최적화하는 함수, 평가에 쓰는 측정치를 구분한다. 셋이 일치한다고 가정하지 않는다.
- **학습 방식·구조·분야:** 자기지도는 학습 신호, Transformer는 구조, 언어는 분야에 관한 표현이다. 이들을 하나의 분류 목록으로 비교하지 않는다.
- **확률적 추론·모델 실행·추론 능력:** 사후확률이나 잠재변수를 계산하는 추론, 학습된 모델을 실행하는 inference, 문제 해결 능력으로서의 reasoning을 문맥에 따라 구분한다.
- **미세조정·문맥 내 학습·RAG:** 매개변수를 갱신하는 방식, 입력 문맥을 이용하는 방식, 외부 정보를 검색해 제공하는 시스템 구성을 구분한다. 실제 결합 방식은 사례마다 확인한다.
- **생성·판별 관점과 출력 과제:** 확률모형의 생성·판별 관점과 텍스트·이미지 등을 생성하는 과제는 구분해 정의한다. 출력만 보고 모델 내부의 확률모형이나 학습 방식을 확정하지 않는다.
- **형식 준수·정확도·확률 보정:** 유효한 구조의 출력을 만드는 것, 판단이 맞는 것, 반환 확률과 실제 발생 빈도가 일치하는 것은 별도 평가 대상이다.
- **공개 사실·해석·미확인:** 공식 문서의 주장, 근거를 연결한 자신의 해석, 공개되지 않은 사항을 명시적으로 나눈다. 관찰한 행동으로 비공개 내부구조를 단정하지 않는다.

## 18개 학습 모듈

모든 모듈에서 핵심 문제, 정의, 가정, 대표 원리, 한계와 대안을 개관한다. 심화 증명과 구현 규모는 개인화 조건에 맞춘다. 표의 선수 모듈은 **그 모듈 전체의 완강**이 아니라 이번 주제에 필요한 개념의 준비를 뜻한다. ⑨ 사례층은 모든 행에 공통이므로 연결축에서 생략한다.

## 선수학습과 진행 순서

기본 흐름은 **문제와 관측 정의 → 필요한 수학·계산 → 여러 모델 관점 비교 → 학습·생성·의사결정 연결 → 모든 분야 개관 → 최소 시스템 구성**이다. M18 평가는 처음부터 누적하고, ⑨ 실제 모델 사례도 각 개념을 배울 때 붙인다.

1. **G0와 M01:** 현재 수준·환경을 진단하고 작은 문제의 입력, 출력, 목표, 관측 조건을 적는다.
2. **M02~M04와 G1:** 해당 문제에 필요한 수학·확률·계산을 보충하면서 작은 기준선과 평가 분리를 준비한다.
3. **M05~M08과 G2:** 기호·고전 통계·확률·신경 접근을 모두 개관하고, 작은 문제에서 두 접근을 비교한다.
4. **M09~M11·M15·M16과 G3:** 학습 신호·재사용, 생성, 정책·제어, 인과, 통합·대안 접근의 관계를 설명한다.
5. **M12~M14와 G4:** 언어, 비전, 음성, 멀티모달, 시계열, 추천, 그래프를 모두 개관한다. 제어·인과·통합 분야는 앞 단계에서 이어 온다.
6. **M17과 누적된 M18 및 G5:** 작은 전체 흐름을 연결하고 평가·로그·오류 처리·자원 조건을 검증한다.

막히면 번호 전체를 되돌아가기보다 필요한 개념으로 돌아간다. 예를 들어 역전파의 연쇄법칙은 M02, 확산의 조건부확률은 M03·M07, 정책 평가의 교란 문제는 M15로 연결한다.

심화 순서는 개념 의존성에 맞춰 조정한다. 신경망 이전에도 기호 탐색과 고전 모델을 배울 수 있고, 평가·데이터 누수는 고급 모델을 배운 뒤로 미루지 않는다. M16의 선수 개념은 주제마다 달라 모든 선수 모듈을 한꺼번에 요구하지 않는다.

각 학습 기록의 수행 상태는 **미확인 / 안내받아 수행 / 독립 수행 / 조건 변경 대응**으로 남긴다. 읽은 페이지 수나 실행 성공만으로 단계를 완료 처리하지 않는다.

## 단계별 완료 관문

기술 목표는 구현물·계산·실험이 무엇을 해야 하는지에 관한 것이다. 학습 목표는 본인이 무엇을 설명·설계·검증할 수 있어야 하는지에 관한 것이다. 두 상태를 별도로 기록하고, 다음 단계에 필요한 동작과 이해를 확인한다.

| 관문·범위 | 기술 목표와 확인할 산출물 | 학습 목표와 설명 질문 | 관찰·검증 및 조건 변경 |
| --- | --- | --- | --- |
| **G0 준비** | 현재 수준·시간·장비·환경 진단표와 학습 범위 기록 | 어떤 선수 개념이 준비됐으며 어떤 도움이 필요한가? | 짧은 설명·손계산·환경 확인으로 수준을 진단한다. 미확인 항목을 임의로 채우지 않는다. |
| **G1 M01~M04** | 작은 입력→기준선→출력→평가 흐름, 입력·출력 명세, 데이터 분리와 평가 기록 | 목표·손실·지표는 어떻게 다르며 누수는 어디에서 생기는가? | 분리한 평가 결과를 관찰하고 표집·분할·입력 조건을 바꿨을 때 해석한다. |
| **G2 M05~M08** | 작은 문제에 대한 두 접근의 비교, 핵심 연산 일부의 직접 계산·구현 | 표현·가정·귀납편향·계산 비용 때문에 어떤 차이가 생기는가? | 같은 비교 조건과 실패 사례를 기록한다. 오류를 데이터·모델·계산 단계로 좁힌다. |
| **G3 M09~M11·M15·M16** | 개념 연결도, 학습 신호·생성·정책·인과 중 선택한 작은 실험 또는 사고 실험 | 신호·목적·샘플링·보상·식별 가정은 어떤 역할을 하는가? | 가정과 통제 조건을 먼저 적고, 조건 하나를 바꾼 결과나 반례를 설명한다. 모든 이론군의 개관은 유지한다. |
| **G4 M12~M14 및 관련 분야** | 모든 분야의 개관 비교표, 필요한 분야의 작은 실습 | 분야의 데이터·과제·지표·오류 구조가 방법을 어떻게 바꾸는가? | 분야에 맞는 지표와 오류 사례를 남긴다. 다른 분야로 옮길 때 바뀌는 조건을 설명한다. |
| **G5 M17~M18** | 최소 시스템, 계층별 로그·오류 진단 기록, 비용·지연·자원 관측 | 구성요소의 연결 조건과 실패 원인을 어떻게 설명하고 수정하는가? | 작은 전체 흐름부터 확인한 뒤 정확도·신뢰성·성능·예외 처리를 확장한다. 자원·입력·오류 조건을 바꿔 확인한다. |

일반 기록에는 **조건 → 예상 결과 → 관찰·측정값 → 해석 → 다음 확인**을 남긴다. 결과가 맞는지에 더해 설계 이유, 측정 해석, 고장 진단, 조건 변경 대응을 확인한다. 증명·반례·손계산·사고 실험이 적합한 개념에 코드를 강제하지 않는다.

소프트웨어 실습에서는 입력 형식, 단위·범위, 출력 스키마, 호출·처리 주기, 지연, 자원, 오류 상태 등 실제 연결에 필요한 조건을 명시한다. 기술 결과는 **코드 테스트 / 시뮬레이션 / 실제 장치 실험**으로 구분한다. 이 문서에는 아직 해당 실습의 수행 결과가 없다.

물리 사례를 사용하는 경우에는 **현상 → 센서 → 회로 → 펌웨어 → 통신 → 응용 소프트웨어**의 흐름을 설명한다. 연결 전에 실제 부품의 허용 전압·핀, 단위·측정 범위, 샘플링 주기, 통신 형식·지연, 전원과 오류 상태를 확인한다. 데이터시트 확인값, 설계 가정, 실측값을 구분하고, 실패 시 하드웨어·펌웨어·통신·응용 계층별로 원인을 좁힌다.

AI 지원은 도구 설정과 반복 작업을 돕되, 해당 단계에서 본인이 선택할 모델·가정·실험 조건과 직접 구현할 핵심 연산은 남긴다. 이번 단계의 범위를 넘어 전체 시스템을 자동 완성하지 않는다.

## 개념과 모델 사례 문서 템플릿

아래 항목은 개념·사례 문서를 작성하고 확장할 때의 공통 구조다. 실제 본문과 사례는 [교재 길잡이](ai_textbook/모델%20해석%20목차.md)에서 찾는다.

### 개념 문서

1. **개념명·식별자·관련 축·모듈:** 대표 용어와 동의어를 적고 유사 개념과 구분한다.
2. **학습 목표·선수 질문:** 설명·설계·검증 중 무엇을 할 수 있어야 하는지와 필요한 사전 개념을 적는다.
3. **문제·정의:** 풀려는 문제, 입력·출력, 용어의 정확한 의미를 적는다.
4. **직관·원리·수식·가정:** 기호와 단위를 정의하고 성립 조건을 함께 설명한다.
5. **한계·대안:** 실패 조건, 적용 범위, 다른 접근과의 차이를 적는다.
6. **학습 활동:** 본인의 핵심 판단을 남기는 계산·증명·구현·비교·사고 실험을 정한다.
7. **검증 기록:** 조건, 예상, 관찰·측정, 해석을 기록하고 테스트·시뮬레이션·실측을 구분한다.
8. **이해 확인:** 설명, 설계 이유, 오류 진단, 조건 변형 질문과 수행 상태를 남긴다.
9. **연결·사례:** 선수·후속·대안 개념과 실제 모델 사례의 연결 근거를 적는다.
10. **출처·갱신:** 원출처, 확인 위치·일자, 자료 버전, 미해결 충돌을 기록한다.

### 비교·연결 문서

같은 문제를 다루는 접근들의 목적, 가정, 표현, 데이터 조건, 계산 과정, 비용, 평가 조건, 실패 양상을 같은 기준으로 비교한다. 용어가 비슷하다는 이유로 동치로 묶거나, 서로 다른 문제의 수치를 단순히 순위화하지 않는다.

### 회사별 모델 사례

1. **회사·모델·버전·시점:** 자료 공개일과 실제 확인일을 구분한다.
2. **학습 개념·과제·입출력:** 관련 모듈과 문제, 인터페이스, 시스템 경계를 적는다.
3. **공개된 구조·학습 자료:** 공개된 설명의 범위만 기록하고 세부 미공개 사항을 표시한다.
4. **이론 연결:** 어떤 공개 사실이 어떤 개념과 연결되는지 근거를 붙인다. 해석은 해석으로 표시한다.
5. **평가·특화:** 지표, 비교 대상, 데이터·도구·계산 조건을 적고 회사 주장과 독립 검증을 구분한다.
6. **운영 조건:** 비용·지연·자원·사용 제약은 조건과 시점을 붙여 기록한다.
7. **비공개·미확인:** 관찰한 행동만으로 학습 방식이나 내부구조를 확정하지 않는다.
8. **학습 질문·원출처:** 설명·반례·조건 변경 질문과 공식 문서·논문·평가 자료를 남긴다.

“특화됐다”는 표현은 특정 과제와 평가 조건에 한정한다. 회사 전체나 모델 계열 전체의 영구적 우열로 확대하지 않는다.

작은 연결 예로 TypeSafe의 Jev 공식 문서는 Choice·Score·Noul이라는 구조화된 판단 인터페이스를 설명한다. 이를 M01의 과제·출력 명세, M17의 시스템 연결, M18의 평가 구분에 연결할 수 있다. 이것은 문서에 공개된 인터페이스를 연결한 것이며 내부구조나 타사 대비 우월성을 확인한 것은 아니다. [TypeSafe 공식 소개](https://docs.typesafe.ai/introduction)

같은 문서의 Choice·Score `confidence`는 각각 반환한 선택지별·점수별 확률에서 계산한 요약값이다. 배포 데이터 분포의 요약이나 정답 확률 보장의 의미로 쓰지 않는다. 출력 형식 준수, 판단 정확도, 확률 보정은 각각 확인한다. [TypeSafe Confidence 설명](https://docs.typesafe.ai/confidence)

## 남은 자료 공백과 확인 사항

교재 초판은 아래 이론군의 원리·가정·한계와 대표 활동을 제공한다. 다만 각 분야의 모든 논문·증명·구현을 망라하는 것은 아니다. 다음 항목은 개인별 심화 과정에서 자료를 확장하고 재검토할 기준이다. 이미 확보한 근거와 장별 연결은 [출처 색인](ai_textbook/92_sources.md)과 각 장에서 확인한다.

- **기초와 학습 이론:** 수준에 맞는 수학·알고리즘 보충, 수치 안정성, PAC/VC·표본복잡도와 일반화 이론의 직접 근거·활동.
- **구조와 생성의 심화:** Attention/Transformer, SSM·MoE·희소구조, 생성 모델별 목적·가정·샘플링, 최신 연결의 원논문과 비교 자료.
- **학습 방식과 통합·대안:** 메타·지속·능동·연합 학습, 신경기호·합성·진화·퍼지·스파이킹의 체계적 자료와 성립 조건.
- **의사결정과 전문 분야:** 제어 안정성·MPC, 오프라인·모방 학습, 인과 식별, 비전·음성·멀티모달·시계열·추천·그래프별 지표와 대표 원리.
- **언어·기반모델과 시스템:** PEFT, 선호·보상 학습, 추론 시 계산, RAG·에이전트, 양자화·증류·운영의 이론과 검증 자료.
- **신뢰성과 책임:** 보정·분포 변화·강건성, 보안·개인정보·공정성, 인간 감독에 관한 구체적인 조건과 평가 절차.
- **회사별 사례:** [공개 사례집](ai_textbook/91_model_cases.md)에서 확인한 모델의 설계·용도를 이론과 연결한다. 다른 회사·새 버전은 공식 자료와 비교 가능한 평가 근거를 추가한 뒤 해석한다.
- **개인화·자료 접근:** 학습 수준·시간·장비·환경, 강좌 하위 링크·판본·문제 접근성. 이 조건에 따라 실습 깊이와 진행 순서를 조정한다.

## 세 모델의 역할과 전달 절차

아래는 2026-10-09 기준의 현재 운영 설정이다. 역할 분담은 제작 작업을 배정하고 검토 책임을 정하기 위한 것이며, 학습자가 해야 할 핵심 판단을 대신 완료하는 절차가 아니다.

| 담당 역할 | 모델·effort | 책임 |
| --- | --- | --- |
| astra_decision | GPT-6 Astra high | 종합 판단, 설계 결정, 결정 근거와 후속 관문 설정 |
| sol_review | GPT-6.1 Sol high | 독립 검토와 간단한 조건 설정 |
| sol_complex | GPT-6.1 Sol max | 복잡한 다단계 구현·분석 |
| sol_module | GPT-6.1 Sol xhigh | 확정된 인터페이스를 따르는 모듈 구현 |
| luna_worker | GPT-6 Luna xhigh | 명확한 문서 작업·자료 정리·지정된 범위의 구현. Luna 작업은 모두 xhigh |

기존 제작계획에서 Sol medium이었던 작업은 xhigh로, 복잡 구현의 Sol high는 max로 두 단계 올렸다. 검토와 간단한 조건 설정은 Sol high 예외를 적용하고, 종합 판단·결정·근거 설정은 Astra high에 둔다. 역할별 프로필은 .codex/agents에 저장되어 있다. 설정 파일을 저장한 사실만으로 실행 중인 부모 세션 모델이 바뀌거나 실제 하위 세션에 프로필이 적용됐다고 간주하지 않는다. 티켓을 시작할 때 실제 세션의 모델·effort를 확인한다.

이 문서가 최초 작성될 때는 Astra ultra, Sol ultra, Luna xhigh 운영표를 사용했다. 그 시기 교재 검증 기록에 남은 ultra 등 과거 실행 설정은 해당 실행 이력으로 그대로 둔다. 아래의 역할표는 현재 운영표다.

1. **Astra의 결정:** 학습 범위·모듈 관계·진행 관문을 정하고, 여러 작업의 결론과 근거를 종합한다.
2. **Luna의 정리:** 출처 식별자, 기관·저자, 공개일·확인일, 자료 유형·버전, 핵심 주장과 확인 위치를 적는다.
3. **Sol의 검토와 구현:** sol_review는 조건과 자료 연결을 검토하고, sol_complex와 sol_module은 승인된 티켓의 복잡 구현 또는 정해진 모듈을 담당한다. 동의어는 묶되 유사 개념을 동치로 만들지 않는다.
4. **충돌 처리:** 주장 A/B, 원출처, 대상·가정·지표·시점의 차이를 기록한다. 조건 차이로 양립하면 설명하고, 직접 모순이면 원문·1차 자료를 대조한다. 근거가 부족하면 미해결로 둔다.
5. **Sol → Astra:** 연결 결과와 누락된 선수 개념·중복·남은 충돌을 전달한다. Astra는 큰 틀과 학습 목표의 일관성을 감독한다.
6. **학습 기록 갱신:** 본인의 설명·활동·검증 결과와 수행 상태를 문서에 남긴다. 제품 사례는 원리 문서와 연결한 채 공개 자료의 시점에 맞춰 갱신한다.

## 이 학습 틀의 완료 기준

학습 틀은 범위, 9축과 18모듈 관계, 선수 개념, 기술·학습 목표와 관문, 문서 템플릿, 출처·공백, 역할 운영을 제시하면 완료로 본다. **이 문서는 그 설계 범위를 제시한 상태**다.

학습 과정의 완료는 별도다. 본인이 핵심 개념을 설명하고, 설계 이유를 제시하며, 검증 결과·실패 원인을 해석하고, 조건 변경에 대응한 기록으로 확인한다. 현재 개인화 조건·개별 학습 수행·실습 결과는 미확인이다. [교재](ai_textbook/모델%20해석%20목차.md)의 문제와 관문으로 진도를 확인하고, 필요에 따라 심화 증명·실험과 새 공개 사례를 보강한다.
