## 스캐너 검토 지적과 확인할 후속 조치

1. 임의 바이트 prefix가 UTF-8 문자 중간에서 잘릴 수 있다. 정상 원본 인코딩 오류와 표본 끝의 잘림을 구분해야 한다. worker에 전달했고 수정 여부를 테스트로 확인한다.
2. 최저 hash 4개를 유지하는 동안 임시 후보로 진입한 행의 WKT 검사 수는 최종 보유 4행의 수와 다를 수 있다. 검사한 후보와 최종 특징 표본의 분모를 구분해야 한다.
3. parse error 또는 검사 중 원본 변경이 있는 파일에서는 전체 계약 통과를 선언하거나 모델을 실행하면 안 된다. 파일 완료 상태·해시 완독·원본 불변 확인이 학습 전제다.
4. 캐시된 해시를 읽은 바이트와 이번 실행에서 새로 해시한 바이트는 다르다. 각각의 필드 이름·값이 일치해야 한다.
