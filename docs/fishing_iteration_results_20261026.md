# 모델을 바꾸고 다시 검증한 결과 — 2026-10-26

**합성 실험에서 반복되는 개선을 확인했다.** 기존 소형 MLP에서 입력 특징 구성을 바꾼 `shape9_mlp`가 별도로 잠가 둔 최종자료 10묶음 모두에서 조건 변화 성능을 높였다. 실제자료 성능이나 사고 탐지 성능은 아직 검증하지 않았다.

이 문서는 코딩부터 차근차근 배우는 사용자를 위한 실행 해설이다. 앞선 [항적 한 건 이해하기](fishing_guided_baseline_20261026.md)는 기존 모델의 16개 입력을 설명하고, 이번 문서는 개선 모델의 **18개 입력**을 설명한다. 학습한 모델·예측·실패 사례·검증 기록은 모두 파일로 남겼다.

## 1. 어떤 순서로 반복했나

[실행 전 계약](iterative_model_protocol_20261026.md)에 목표·개발자료·최종자료·후보·성공 기준을 먼저 적었다. 개발 과정에서는 최종자료를 생성하지 않았다.

| 순서 | 변경 | 개발 보통 조건 Macro F1 차이 | 개발 조건 변화 Macro F1 차이 | 판단 |
| --- | --- | ---: | ---: | --- |
| 기준 | 기존 8특징 + tanh16 MLP | 기준 | 기준 | 비교 대상으로 고정 |
| 1차 | 전체 길이 특징만 제거: 7특징 | +0.0000 | −0.0665 | 채택하지 않음 |
| 2차 A | 7특징에 전체 점들의 퍼짐 특징 2개 추가: 9특징 | +0.0383 | +0.0795 | 기준 통과, 채택 |
| 2차 B | 9특징에 부분선 재표본화 회전 특징 6개 추가: 15특징 | +0.0425 | +0.0043 | 조건 변화 개선 기준 미달 |

개발자료는 생성 seed 1101~1105의 5묶음이며, 매번 가중치 시작 seed 42·137을 사용했다. 각 자료 묶음 안에서 두 시작 조건의 결과를 평균했다. 같은 자료·평가 행을 유지해 특징 변경을 비교했다.

단순히 특징을 늘리는 것으로 해결되지 않았다. 길이만 제거한 1차는 조건 변화 성능이 오히려 낮아졌고, 더 복잡한 15특징도 목표를 충족하지 못했다. 9특징 모델은 5묶음 모두 조건 변화 성능이 높아져 이 모델의 제작 절차를 잠갔다. 3차 트리 비교로 넘어갈 필요가 없어 실행하지 않았다.

## 2. 잠근 뒤 처음 만든 최종자료의 결과

생성 seed 9101~9110의 새 자료 10묶음을 사용했다. 모델 설정을 고정한 뒤 각 묶음의 train으로 학습하고 validation으로 epoch, calibration으로 확률 온도를 정하는 **제작 절차 전체**를 검증했다. 각 묶음에서 기존 모델과 개선 모델을 같은 두 시작 seed로 비교했다.

| 최종 조건 | 기존 평균 Macro F1 | 개선 평균 Macro F1 | 차이 |
| --- | ---: | ---: | ---: |
| 보통 조건 | 0.8452 | 0.8799 | +0.0347 |
| 조건 변화 | 0.5566 | 0.6634 | +0.1068 |

Macro F1은 세 클래스의 성능을 고르게 반영하는 분류 점수다. 정확도와 같은 계산은 아니다. 정확도 평균은 보통 조건 **84.48% → 87.95%**, 조건 변화 **56.56% → 67.71%**였다.

- 조건 변화 Macro F1은 **10묶음 모두에서 개선**됐다.
- 개선 평균의 seed 단위 paired bootstrap 95% 구간은 **+0.0916~+0.1195**였다. 개별 행이나 두 초기화를 독립 표본으로 세지 않고 데이터 생성 seed 10개를 재추출했다.
- 사전 기준인 보통 조건 평균 하락 0.01 이내, 조건 변화 평균 개선 0.05 이상, 10묶음 중 8묶음 이상 개선, 구간 하한 0 초과, 동일 평가 분모를 모두 충족했다.
- normal/shift 각 묶음의 평가 항적은 144개이고 유보는 0개다. 같은 144건을 두 초기화 모델이 평가한 것이므로 288개의 독립 항적이라고 부르지 않는다.
- 결과는 고정 합성 생성기와 이번 교란 조건에 한정된다. 조건 변화 정확도가 67.71%라는 점에서 오류가 여전히 많이 남는다. 실제 조업 코드·실제 해역·사고 탐지의 성능은 아니다.

## 3. 모델의 무엇을 바꿨나 — 코딩 입문용 설명

모델이 읽는 입력은 경로 자체가 아니라 경로를 요약한 숫자다. 최초 모델은 8개 숫자와 8개 누락 표시, 총 16개 입력을 읽었다.

이번에는 기존 8개 중 전체 길이 로그를 제거하고 다음 두 숫자를 추가했다.

1. **전체 점 구름의 퍼짐 비율:** 관측된 모든 좌표가 길게 늘어선 정도와 옆으로 퍼진 정도를 요약한다.
2. **중심에서의 거리 분포:** 점들이 중심 가까이 모이는지, 바깥으로 퍼져 있는지 요약한다.

이 두 값은 관측점 집합을 사용한다. 떨어진 부분선 사이에 이동 선분을 추가하지 않는다. 좌표별 실제 시각이나 속력도 사용하지 않는다.

```text
기존: 특징 8개 + 누락 표시 8개 = 입력 16개 → 은닉 노드 16개 → 확률 3개
개선: 특징 9개 + 누락 표시 9개 = 입력 18개 → 은닉 노드 16개 → 확률 3개
```

은닉 노드 수·학습률·학습 횟수 한도는 유지했다. 입력 수에 맞게 첫 가중치 표의 크기가 16×16에서 18×16으로 바뀌었다. 새 모델은 기존 모델 파일의 숫자 일부를 고친 것이 아니라, 새 입력 정의로 train에서 다시 학습한 모델이다.

## 4. 틀린 이유는 어디까지 확인했나

같은 개발 train 항적 60개에서 조건을 하나씩 바꿔 특징을 계산했다. 이 단계에서는 모델을 학습하지 않았다.

| 한 번에 바꾼 조건 | 관찰 |
| --- | --- |
| 좌표를 중심 기준 2.6배 확대 | 전체 길이 로그의 평균 변화 약 +0.9547. 나머지 기존 형상 특징의 최대 차이는 약 7.21×10⁻¹⁰ |
| 좌표는 그대로 두고 부분선만 최대 3점씩으로 재분할 | 평균 부분선 직선성이 0.9771에서 0.9988로 바뀜. 새 전체 점 구름 특징 2개는 변화 0 |

이 검산은 기존 부분선 요약이 경계를 잘게 나누는 데 민감하고, 전체 점 구름 특징이 그 경계 변화에 불변임을 보여 준다. 실제 센서 실험이나 사고 실험은 아니다.

그러나 “길이가 변하니까 길이 특징을 빼면 좋아진다”는 첫 가설은 성능 비교에서 지지되지 않았다. 전체 모양 정보를 보충한 구성에서 성능이 좋아졌다는 것이 이번 실험의 결과다. 특정 항적 하나의 오분류 원인을 하나로 확정한 것은 아니다.

## 5. 실제로 고쳐진 한 항적과 남은 실패

예시 모델은 성능이 가장 좋은 실행을 골라 쓰지 않고, 미리 정한 **데이터 생성 seed=9101, 가중치 시작 seed=42**를 사용한다. 서로 다른 생성 seed에서 sample_id 문자열이 재사용되므로 아래 ID는 반드시 이 두 seed와 함께 읽는다.

### 고쳐진 사례

`S0-stress-000-straight-01`의 생성 정답은 straight다.

| 유형 | 기존 확률 | 개선 확률 |
| --- | ---: | ---: |
| straight | 41.77% | 87.67% |
| sweep | 6.86% | 0.79% |
| turn | 51.36% | 11.54% |

기존 모델은 turn으로 틀렸고, 개선 모델은 straight로 맞혔다. “기준선은 틀리고 개선 모델은 맞힌 shift 사례 중 ID 순 첫 사례”라는 사전 규칙으로 골랐다. raw 좌표·9개 특징·train 통계·18개 입력·은닉값·확률·생성 정답을 [iteration_trace.json](../outputs/iterative_models_20261026/iteration_trace.json)에 연결했다.

### 여전히 틀리는 사례

같은 자료의 `S0-stress-000-straight-02`도 생성 정답은 straight다. 개선 모델은 straight 21.86%, sweep 23.11%, turn 55.03%를 주며 turn으로 틀렸다.

생성기의 straight와 turn은 일부 각도 범위가 겹친다. 잡음·누락·특징 요약도 판단에 영향을 줄 수 있다. 그 중 어느 것이 이 실패를 얼마만큼 설명하는지는 이번 사례만으로 확정할 수 없다. 이 정답을 임의로 바꾸거나 어려운 항적을 평가에서 빼지 않았다.

## 6. 지금 직접 실행할 수 있는 것

학습을 다시 하지 않고 개선 모델의 예측을 확인하려면 프로젝트 폴더 터미널에서 실행한다.

```powershell
python tools/predict_iteration_sample.py --out outputs/iterative_models_20261026
```

출력에서 다음 항목을 차례로 본다.

1. `features_9`: 좌표를 요약한 아홉 숫자.
2. `model_inputs_18`: train 기준으로 바꾼 아홉 숫자와 누락 표시 아홉 개.
3. `probabilities`: 세 유형에 부여한 확률.
4. `prediction`과 `generator_answer`: 예측과 생성 정답의 비교.
5. `training_performed: false`: 저장한 모델을 사용했으며 이번 명령에서 다시 학습하지 않았다는 뜻.

남은 실패를 직접 확인하려면 다음처럼 sample_id만 바꾼다.

```powershell
python tools/predict_iteration_sample.py --out outputs/iterative_models_20261026 --sample-id S0-stress-000-straight-02
```

[짧은 예측 코드](../tools/predict_iteration_sample.py)는 자료·모델 읽기 → 특징 계산 → 저장 전처리 → 예측 → 정답 비교의 다섯 구간으로 나눴다. [실제 개선 모델](../outputs/iterative_models_20261026/models/shape9_mlp_d9101_i42.json)은 9101 자료·42 초기화로 학습한 한 실행의 가중치다. 위 평균 성능은 이 파일 하나의 점수가 아니라 동일 제작 절차를 여러 자료·초기화에서 반복한 결과다.
