# 03 첨부 자료와 분석 방향

[전체 정리로 돌아가기](../../2026%20데이터%20분석대회%20데이터%20분석%20정리.md)

## 10월 19일 제안서에 맞춘 설계 방향

사용자가 추가한 [「MLP 기반 어선 조업형태 분류 및 이상항적 분석」 제안서](../../data/reference/competition_20261019/additional/IT%EC%A2%85%ED%95%A9%EC%84%A4%EA%B3%84%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8_%EC%A0%9C%EC%95%88%EC%84%9C_C215192%20%EC%B5%9C%EC%8A%B9%EB%B9%88.pdf)는 표지의 제출일이 2026-10-19인 10쪽 문서다. 실제 제출 여부는 확인하지 않았다. 이 문서를 프로젝트의 **현재 서술된 설계 방향**으로 통합하되, 데이터 정의는 첨부 공지와 실제 CSV 점검 결과를 우선한다. 제안서에 적힌 계획은 구현 완료나 후속 단계 실행 승인과 구분한다.

| 설계 항목 | 추가 제안서의 내용 | 기존 문서에 반영한 상태 |
| --- | --- | --- |
| 입력·특징 | WKT 파싱, 부분선 보존, 형상과 관측 상태 구분. 형상 계산용 연속 중복은 축약하되 원본과 반복 기록 보존 | 기존 전처리 원칙과 일치. 가공 조건·이력을 남기는 후속 계획으로 유지(pp.3–5) |
| 분류 모델 | MLP 중심으로 TabM·RealMLP 비교. 같은 숫자 특징·선박 분할에서 작은 LightGBM 단독과 혼합도 비교 | MLP 중심 방향은 문서상 선택. 두 후보 중 최종 모델과 혼합비는 실험 후 결정(pp.5–7) |

| 이상 기준 | 학습자료의 중앙값·분포 등과 새 항적의 편차 비교. 확인된 사고 관련 구간 분리 | 우선 비교 기준을 만드는 계획. 사고 미표시를 정상으로 바꾸지 않음. 특정 탐지기는 미선정(p.7) |
| 검증·효율 | 선박 분리, 내부 Macro-F1·클래스별 정밀도/재현율, 사건·시간 순서 평가, 처리시간·메모리·확률 품질·실패 확인 | 구체화한 내부 평가안. 공식 점수식·실측 성능과 구분(pp.7–8) |
| 확장 | 연속 시간대가 있으면 작은 Transformer 인코더, 선택적 복원 디코더. TabPack·확률 보정 검토 | 기본 모델 평가 이후의 조건부 후보. 디코더 복원오차가 사고라는 뜻은 아님(pp.8–9) |
| 추진·출력 | 데이터 점검 → 평가 준비 → 기본 비교 → 검증·보완 → 결과 정리. 예측 파일·재현 코드·분석 결과 | 완료 증거가 필요한 계획. 달력 일정·예측 산출물·실제자료 평가 완료를 새로 주장하지 않음(p.10) |

추가 제안서가 **구체화한 것**은 필수 실험과 확장의 구분, 단독·혼합의 동일 조건 비교, 경보가 실제 가능한 시각을 쓰는 평가다. 새 데이터나 성능 결과가 추가된 것은 아니다. [구체적인 평가 계획](02_분석해석과_다음단계.md)에서 이어 읽는다.

## 자료를 읽는 기준

첨부 문서는 **과제 설명, 작성자의 제안, 아직 검증하지 않은 확장 아이디어**가 섞여 있다. 공지 사본의 규칙, CSV에서 직접 계산한 결과, 문서 작성자의 제안을 구분해 읽는다. 논문 최신성·벤치마크·공식 구현은 이번에 외부 검색으로 재확인하지 않았다. 아래 모델 이름은 첨부 자료에 나온 후보이며 최종 추천이나 실측 순위가 아니다.

파일명에 적힌 중요도와 `여기서 중요한 문서 알려준다.txt`의 순서는 작성자의 읽기 선호다. 사실 판정이나 이번 작업의 실행 지시로 사용하지 않는다. `Claude outputs (사용X)` 자료는 목록만 보존하고 분석 근거에서 제외했다. 모든 원본은 [파일 목록](04_파일목록과_검증기록.md)에서 연다.

## 제안 자료가 제시하는 공통 흐름

원자료 식별 → CSV·WKT 검사 → **형상과 관측 상태를 구분한 특징** → 조업 분류와 별도 이상점수 → 근거·한계가 보이는 출력 → 독립 평가라는 방향이다. 이 중 이번에 직접 실행한 것은 원자료 식별·구조 검사·기본 집계까지다.

핵심 가설은 **같은 형상이라도 반복 좌표가 늘면 모델 판단이 불필요하게 바뀌는지 확인하자**는 것이다. 샘플의 인접 반복 158회는 이를 검토할 이유가 되지만, 반복이 분류를 방해한다거나 개선 실험이 성공했다는 증거는 아니다. 같은 경로의 원본·변형본은 같은 그룹으로 관리해 누수를 막아야 한다. 근거: `15` pp.3–6,8; `14` pp.1–4,9.

## 모델 후보의 역할

| 후보 | 문서가 제안한 역할 | 판단 전에 필요한 것 |
| --- | --- | --- |
| TabM | 현재 제안서의 MLP 분류 비교 후보 | 정식 자료·선박 분할에서 단독 성능, 반복 민감도, 실행 비용 |
| RealMLP | TabM과 같은 특징·분할로 비교할 MLP 후보 | TabM과 동일한 평가·탐색 조건. CPU 비용·안정성 확인 |
| 작은 LightGBM | 분류 기준선 및 조건부 혼합 비교 | 단독 결과를 먼저 확인. 혼합이 실제 개선되는지 독립 검증 |
| 학습 분포·강건 편차 기준 | 추가 제안서에서 먼저 구성할 이상점수 비교 기준 | 평상시 기준의 정의, 사고 혼입·미확인 정상 문제, 점수 방향·임계값 |
| Isolation Forest·DTE | 이전 ZIP의 선택적 탐지기 후보. 추가 제안서에서는 구체 모델 미선정 | 사고 정답·시간대별 검증·오경보 기준과 실제 구현 비용 |
| 경로 이미지·작은 CNN | 형상 이미지가 숫자 특징에 정보를 더하는지 비교 | 렌더링 규격·좌표·단절 처리 및 동일 선박 분할 |
| Transformer·디코더 복원 | 좌표열 또는 여러 시간대 특징열을 이용하는 후속안 | 연속 시간 자료, 시간 순서·가용성, 결측 마스크, 자원·과적합 통제 |

TabM 내부의 예측 멤버와 서로 다른 알고리즘을 섞는 혼합은 구분한다. 이전 ZIP의 1·2순위는 **비교를 시작할 순서**이며 측정된 성능 순위가 아니다. 추가 제안서는 TabM·RealMLP를 비교할 두 후보로 적고 특정 승자를 확정하지 않는다. 최종 모델·혼합비·정확도·CPU 시간은 이번 자료에서 결정할 수 없다. 근거: `04` pp.1,3–9,11; `09` §§1–3; `10`·`11` pp.2–5; `12` §§1–2.

GIST를 참고한 이미지 아이디어는 원 연구와 현재 WKT 입력이 다르다. 원 연구를 재현했다거나 원 논문 성능이 현 과제에서도 나온다고 쓰지 않는다. TabPack·Muon·확률 보정·지식 증류도 기본 모델이 확정된 뒤 검토할 서로 다른 개선 후보다. 근거: `04` p.6; `12` §§1,3–4; `13` §§1–7.

## 추가 제안서에서 확인이 필요한 표현

| 제안서 표현·위치 | 확인 수준과 통합 방법 |
| --- | --- |
| V-Pass 30초 위치 저장·10분 이내 발신, 4시간 기대 패킷 480개 중 269개 수신(p.3) | PDF가 소개한 외부 규격·실험 사례. 이를 뒷받침하는 원 출처를 이번 문서 판독만으로 확인하지 못했다. 현재 샘플의 실제 점 간격·누락률·부분선 분리 원인으로 적용하지 않음 |
| CSV는 5칼럼(p.3) | 의미 있는 열의 설명으로는 일치. 실제 파일의 물리 12열 중 빈 7열도 계속 기록 |
| `fishing_code`는 해당 선박의 어업 정보(p.3) | 제안서의 라벨 해석. 공식 부여 단위·시간별 변화·선박 내 불변 여부는 미확인 |
| 시간·계절이 조업의 힌트가 될 수 있음(p.4) | 검토할 가설. 현재 한 날짜·한 시간대 샘플로 효과를 입증할 수 없고 미래 날짜·지역·수집 방식의 대리변수 과적합도 검토해야 함 |
| 09–10시 항적, 10:05 경보 가능, 11:30 사고 → 85분 선행(p.8·그림4) | 가정된 시각의 산술 예시. 실제 사고나 탐지 성능이 아니며 모델의 지연도 측정된 값이 아님 |
| 새 선박 항적으로 분류와 사고 가능성 평가(p.10) | 신규 선박 조건은 분류 Test A에 대응. Test B의 선박 중복·과거 이력 사용 조건을 같은 문장으로 확정하지 않음 |
| TabPack 후속 연구 설명(p.9) | 첨부 문서의 연구 소개. 연구의 최신성·벤치마크·구현 가능성은 독립 검증 전 |

이 통합에서는 외부 법령·장치 규격이나 논문 상태를 새 사실로 확정하지 않아 웹 검증을 추가하지 않았다. 문서의 배경 인용과 현재 CSV의 입력 계약을 분리하는 데 사용했다. 장치 연결·구동 조건도 새로 제안하지 않는다.

## 평가기준을 분석 기록에 반영하기

첨부 `공지-평가기준.png`에서 **창의성 20·우수성 50·효과성 30**을 직접 확인했다. 이는 심사 항목의 배점이며 분류·이상 탐지의 공식 수치 계산식은 아니다.

- 창의성: 형상과 관측 상태 분리 가설을 분명히 적고, 기존 아이디어와 차이를 실험으로 확인한다. 지금은 가설만 정리됐다.
- 우수성: 입력 계약·누수 방지·재현 가능한 비교·실패 분석을 남긴다. 현재는 CSV 구조 검사 근거가 생겼다.
- 효과성: 사용자가 출력·한계·오경보를 이해하고 대응할 수 있는지 검증한다. 사고 감소나 현장 효과는 측정하지 않았다.

문서의 모델 수나 그림 수가 많다는 사실만으로 세 항목을 달성했다고 평가하지 않는다. 실제 후속 실험의 우선순위는 학습자 목표·정식 자료·시간·환경을 확인해 정한다.
