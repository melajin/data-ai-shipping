## 역할과 실행 증거

프로젝트 AGENTS.md의 독립 위임 규칙에 따라 자료 조사와 단계 판단을 나눴다. 공통 계약과 Obsidian 문서 통합은 주 담당자가 맡았다. 저장 설정이 부모 세션의 실행 모델을 변경했다고 해석하지 않는다.

| 담당 | 요청한 실행 모델·effort | 파일 소유권·증거 |
| --- | --- | --- |
| `source_evidence` / `luna_worker` | GPT-6 Luna / xhigh | [문서 근거 조사](../../outputs/competition_20261019/source_evidence.md) 단독 작성 |
| `scope_decision` / `astra_decision` | GPT-6 Astra / high | [범위·관문 판단](../../outputs/competition_20261019/scope_decision.md) 단독 작성 |
| `independent_review` / `sol_review` | GPT-6.1 Sol / high | [독립 검토 기록](../../outputs/competition_20261019/independent_review.md) 단독 작성 |

위 표는 생성 호출에 지정한 모델·effort와 결과 파일을 기록한 것이다. 서비스의 내부 라우팅 계측은 별도로 제공되지 않았다.

## 독립 검토 반영과 최종 확인

Sol 독립 검토에서 CSV 전체와 ZIP·추출본을 다시 대조해 행별 집계·분모·해시가 일치함을 확인했다. 지적된 문헌 조사 범위 표기를 실제 수행 수준으로 맞추고, 기존 검사기의 종료 코드 1을 명시했다. 장치 실측과 혼동하지 않도록 01 노트의 파일명을 ‘직접집계’로 통일하고 URL로 인코딩된 이전 파일명 링크도 교정했다.

최종 자동 점검은 진입 노트와 상세 노트 4개의 로컬 링크 및 원본 해시를 확인한다. 결과는 [최종 검증 JSON](../../outputs/competition_20261019/verification.json)에 보존했다. Obsidian 앱에서의 실제 화면 렌더링은 검사하지 않았으며, 표준 Markdown·상대경로 링크와 기존 보관함 경로를 사용했다.

### 추가 제안서 통합 검토

추가 PDF 통합에서는 문서 근거 조사를 `proposal_evidence`(luna_worker / GPT-6 Luna xhigh), 적용 조건 판단을 `proposal_decision`(astra_decision / GPT-6 Astra high), 독립 검토를 `proposal_review`(sol_review / GPT-6.1 Sol high)에 각각 단독 파일 소유권으로 배정했다. 공통 문서는 주 담당자가 통합했다. 표기한 모델·effort는 생성 호출 요청값이며 부모 세션 설정의 변경을 뜻하지 않는다.

추가된 계획은 현재 구현 상태·샘플 집계·F1 관문을 바꾸지 않는다. [추가 통합 검토](../../outputs/competition_20261019/proposal_integration_review.md)와 [추가 통합 검증](../../outputs/competition_20261019/proposal_integration_verification.json)에 반영 결과와 전체 링크·해시 확인을 기록했다.
