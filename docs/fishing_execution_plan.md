# 어선 항적 분석 실행 계획

## 2026년 11월 6일 Round021 — 내부 F1과 구체적 판단 절차로 보고 방향 전환

사용자는 공식 채점 세부식 미확정을 이유로 수치 보고를 미루기보다, 적용 가정을 밝힌 내부 F1을 계산하고 **어떻게 사고와 시각을 판단하는지**를 보고서 중심으로 정하도록 요청했다. [Round021 판단 근거 보고서](../testB/final/round_021_internal_f1_judgement_20261106/ROUND021_판단근거와_내부F1.md)에 전체 7,372척의 실제 집계와 사례를 작성했다. F1 자체의 계산식은 고정되어 있으며 공식 사건 매칭·시간오차 처리의 미확정과 구분한다.

기존 대표 비교 규칙 peak_score≥0.75를 결과에 맞춰 조정하지 않고 사용했다. 선정 183척 중 잠정 연결 7척으로 **선박 선정 내부 F1=0.05283**, 동일 선박 사건과 정수시간 ±6h 일대일 매칭한 **시각 포함 사건 내부 F1=0.00000**이다. 시각 포함 주 F1은 100사건 기준 `2TP/(K+100)`이며 선박 선정은 82척 기준 `2TP/(K+82)`다. 나머지 7,290척을 평가상 음성으로 두는 가정을 표시하고 실제 미사고 정답으로 승격하지 않았다. 전부 선정 및 기존 반경95분위는 참고 비교이며 가장 좋은 규칙을 사후 채택하지 않았다.

보고서는 **자료 신뢰성 확인 → 자동 검토 후보 선정 → 전후 관측 사실·대안 설명 검토 → 후보시각 근거 또는 판단 유보 기록**으로 구성했다. 한 시간의 부분선 길이만 큰 사례, 관측 공백 뒤 기록이 재개된 사례, 전체 관측이 두 번뿐인 사례 등을 실제 자료로 제시했다. 최고점·상태명·큰 반경을 곧바로 사고 근거로 쓰지 않고, 미선정을 정상 확인으로 설명하지 않는다. 수동 판단·시각 수정을 완료했다고 주장하거나 그런 성능을 내부 F1에 섞지 않았다.

정책별 22,116행, 사건별 300행, 사례 실제 관측 125행을 저장했고 합성 검사 및 저장 결과 독립 검산을 완료했다. 새 학습·임계값 탐색·2025/Test A 자료 접근·지역 사전확률 적합은 없었다. 상속한 기준선에 LSO 구현이 없다는 제한도 보고했다. 이 수치는 2026 내부 진단이며 공식 Test B 점수는 아니다.

## 평가 범위 보정 — 전체 선단과 조건부 시각 지표 구분

사용자가 "왜 자꾸 100척만 보는거야"라고 지적했다. 100은 제공된 연결 사건 수이며, Round018·020의 실제 시각 평가 대상은 사고가 잠정 연결된 82척이었다. 전체 7,372척의 자료를 읽었어도 대상 82척만 예측한 실험을 전체 선단 사고 판정으로 설명할 수 없다. 초기 h 개선 목표를 반복하면서 전체 선박에서 사고 후보를 고르고 시각을 제시하는 과제와의 통합이 빠졌다.

후속 작업의 기본 예측 대상은 **2026 전체 7,372척**이다. 모든 선박의 점수·후보 시각·사고 후보 선정 결과와 선정 수를 먼저 산출하고, 제공된 82척의 시각 적중은 별도 조건부 진단으로 유지한다. 나머지 7,290척은 미연결 비교군이며 확정 정상으로 만들지 않는다. 전체 대상의 선정률·미연결군 선택률과 연결군의 사고 여부 및 시각 회수 결과를 함께 보고하되, 정답이 불완전한 상태에서 이를 공식 F1·확정 오경보율이라고 부르지 않는다.

[Round019](../testB/final/round_019_vessel_discrimination_20261106/ROUND019_보고서.md)는 전체 7,372척의 점수화를 완료했다. 최고점의 관측 수 매칭 내 AUC는 0.5756, 부분선 중심점 반경은 0.6073으로 잠정 연결과의 연관을 분석했다. 그러나 시각 포함 시나리오에는 기존 h=0.0366을 고정했고, Round020 역시 82척의 시각 선택만 평가했다. 따라서 두 보고서를 나란히 놓는 것으로 전체 선단의 선별·시각 추정을 함께 실측한 결과가 되지는 않는다. 후속 설계에서는 이 분리된 결과의 통합을 과제로 명시하고, 기존 결과를 본 뒤 최적 임계값을 골라 독립 검증인 것처럼 보고하지 않는다. 2025 자료 접근 및 새 선박 재식별·ID 연결 금지는 유지한다.

## 2026년 11월 6일 Round020 완료 — 판정 기준 완화 후에도 기각

사용자가 주최 측 답변을 반영하여 이어서 실행하도록 요청했다. 기존 Round019 선박 판별 작업은 보존하고, 사고시각 선택 변경만 [Round020](../testB/final/round_020_missing_hour_time_20261106/ROUND020_report.md)으로 분리했다. 저장된 Round018 선박 제외 모델 82개를 재학습 없이 사용하고, 선박별 최초~최종 관측 사이 모든 정수시간에서 ±6h 모델 근거 합이 가장 큰 중심시각을 한 번 평가했다.

평가 전에 사용자가 "판정을 조금 러프하게", "판정 기준"이라고 지시하여 이번 개발 선별 기준을 완화했다. **5척 이상 적중하고 새 후보 우연 기대보다 높으면 개선 후보, 4척이고 기대보다 높으면 보류, 3척 이하 또는 기대 이하이면 기각**이다. p값은 기록만 하며 통과 조건에서 제외한다. 개선 후보는 통계적 유의성·독립 검증·운용 채택이 아니다. ±6h·분모·정답·사전 고정·누수 및 무결성 조건은 유지했다.

결과는 **3/82(3.6585%), 중앙 오차 573.5시간, 기각**이다. 전체 후보 균등선택의 기대는 **0.4695%**, 단측 p=0.0068920이며 기준선 최악 적중 겹침 p=1.0은 참고 기록이다. 중앙 오차와 우연모델 p값이 달라졌어도 기준선 대비 적중 수 증가가 0척이므로 h 개선으로 보고하지 않는다.

후보는 99,677개 관측시간에서 293,384개 전체 정수시간으로 늘었지만 실제 선택된 미관측 시각은 **0척**이었다. 81척의 선택 시각이 변경됐고 전체 82척에서 사고창 안의 후보는 기존에도 존재했다. 공백 후보 추가만으로 적중 문제가 해결된 것은 아니다.

합성 테스트 12개, 독립 코드·저장 결과 검산, 기존 최고점 재현(로짓 최대차 0.0), 동결 파일 전후 해시 확인을 완료했다. 실제 예측·평가는 한 번이며 RAM gate 768+640MiB를 충족했고 최대 프로세스 RAM은 181.75MiB였다. 2025 자료·새 ID 연결·추가 학습·Round019 결과 결합은 수행하지 않았다. 2026 잠정 연결의 조건부 시각 지표이며 공식 Test B F1이 아니다. 결과 후 새 규칙을 자동으로 추가 평가하지 않았다.

## 2026년 11월 6일 추가 주최 측 답변 반영 — 제출 시각과 평가자료

출처는 사용자가 이 대화에 전달한 주최 측 답변 전문이다. 아래 날짜는 프로젝트 반영일이며 원문의 발신일·발신자·메일 헤더는 제공되지 않았다. 별도로 원문 메일이나 웹을 조회한 기록은 아니다.

> 1. 항적 기록이 없는 시간대에도 시각과 이상항적 점수를 기재할 수 있으며, 해당 시간을 사고시각으로 제출하는 데 별도 제한은 없습니다.
>
> 2. 최고 이상점수가 같은 시각이 여러 개인 경우, 참가자가 판단하여 사고시각 하나를 선택해 제출해 주시기 바랍니다. Test B는 제출한 사고시각과 실제 사고시각 간 6시간까지의 시간오차를 고려한 F1으로 평가합니다.
>
> 3. Test B에는 사고 선박과 미사고 선박이 함께 포함되어 있습니다.
>
> 4. 제공된 「26년 1~6월 어선 사고현황」은 2026년 학습용 항적데이터의 분석을 위한 참고 자료이며, 2025년 Test B에 대응하는 사고정보가 아닙니다.

이 답변에 따른 설계·해석 기준은 다음과 같다.

- **사고시각 후보는 관측된 항적 시간으로 제한되지 않는다.** 관측이 없는 시간에도 추정 점수와 사고시각을 제출할 수 있다. 해당 점수는 추정값으로 구분하고, 관측 공백 자체를 사고 또는 정상 정답으로 간주하지 않는다. 허용된 제출 기간·시각 정밀도 등 원문에 없는 조건은 추가로 확정하지 않는다.
- **최고점 동점 해소는 참가자 선택이다.** 기존 source_ordinal 우선 규칙은 재현을 위한 내부 선택이지 공식 의무가 아니다. 새 규칙을 시험한다면 동점 해소도 결과 확인 전에 고정한다. 답변은 동점 처리의 재량을 설명한 것으로, 동점이 아닌 점수에 대한 임의 제출 규칙까지 새로 확정한 것은 아니다.
- **공식 Test B 평가는 6시간까지의 시각 오차를 고려한 F1이다.** 사고·미사고 선박이 섞여 있으므로 사고로 판단할 선박과 그 시각을 함께 다뤄야 한다. 사고 연결 선박만 대상으로 하는 h는 조건부 내부 진단이며, 미사고 선박의 잘못된 사고 제출을 반영한 공식 F1을 대체하지 않는다. 공란·미제출 처리, 다중사고 매칭 등 세부 산식은 이 답변만으로 확정하지 않는다.
- **2026 사고현황은 2026 학습자료 분석용 참고자료다.** 이를 2025 Test B의 사고 정답으로 대입하거나 연도 간 선박 재식별·ID 연결의 근거로 사용하지 않는다. 2026 개발 성능에서 2025 공식 성능을 산출하지 않는다. 이 답변은 기존의 2025 테스트 자료 접근 금지를 해제하는 지시가 아니다.

[Round018](../testB/final/round_018_pointwise_loov_20261106/ROUND018_report.md)은 **2026 참고자료의 잠정 연결에 대한 개발 실험**이다. 3/82(3.6585%), 중앙 오차 760시간, 관측시간 균등 우연 기대 2.2689%, 기각이라는 기존 결과를 유지한다. 이 결과는 2025 Test B 공식 평가 결과가 아니다. 당시 관측시간만 후보로 삼은 것은 실험 설계의 제한이었으며 공식 제출 제한이 아니었다. 82척 모두 기존 관측 후보 중 사고 ±6h에 들어오는 시간이 있었으므로 후보 부재만으로 실패를 설명할 수도 없다.

후속 실험을 진행할 경우, 관측 공백을 포함하는 후보 시간의 범위·간격·추정 방법·동점 해소·사고/미사고 판정과 평가 분모를 먼저 문서로 고정한다. 후보 공간이 달라지면 우연 기대도 그 공간으로 새로 정의하며 기존 2.2689%를 그대로 적용하지 않는다. 2026 자료에서 사고 미기재 선박을 곧바로 확정 미사고 정답으로 승격하지 않는다. 이번 반영은 문서 해석 보완이며 새 라운드 학습·평가·2025 자료 접근·제출을 실행하지 않는다.

## 2026년 11월 6일 Test B 실행 패키지와 평가 요소별 보고서 완료

사용자가 시스템 구성부터 보고서 작성까지 완료하도록 요청하여 [Test B 실행 패키지](../deliverables/testb_system_20261106/README.md), [11쪽 결과 보고서](../deliverables/testb_system_20261106/reports/어선_이상항적_시스템_결과보고서.pdf), [편집 원문](핵심%20예상%20질문%207가지.md), [압축 묶음](../deliverables/testb_system_20261106.zip)을 완성했다. 공지의 창의성 20·우수성 50·효과성 30에 설계 차별점·재현 검증·활용 절차를 대응시켰으며 예상 심사 점수는 만들지 않았다.

기존 고정 점수함수와 저장 참조를 독립 실행 파일로 복사하고, 2025 Test B 기하 요약 입력 46,705행/100척을 실제 재계산했다. 종합점수·세 구성점수의 최대 절대차 0.0, 결측 위치·상태·후보 시각·원행번호 불일치 0이다. 실행 33.38초, 최대 프로세스 RAM 299.34MiB이며 직전 가용 RAM 3,401.29MiB를 확인했다. 원 WKT 파싱·새 기준자료 적합·새 모델 학습은 이번에 수행하지 않았다. 입력은 해시로 고정된 재현용 요약이며 임의의 새 자료에 대한 운영 서비스라고 주장하지 않는다.

점수 경계 테스트 4개, 동봉된 별도 입력 계약 테스트 26개를 통과했다. 실제 최고점·중앙순위·최소이력 사례 그림을 만들고 100척 후보의 수치 근거를 CSV로 제공했다. 후보 39척의 과거 관측이 24행 미만이라는 제한을 공개했다. PDF 11쪽을 렌더링해 검수했으며 중간 사례의 축 눈금 겹침을 수정했다. 독립 검토는 함수 대응·전수 비교·해시·후보 통계를 확인했다.

사후 재현의 기술적 완성과 사고 성능은 구분한다. 기존 개발 100사건/82RFID의 ±6h 적중 3/100은 별도 잠정 연결 자료이며, 신규 공식 F1·성능 개선·실시간 경보를 입증하지 않는다. 2026 참조를 사용한 2025 사후 결과는 당시 정보만 사용한 실시간 재현이 아니다. 관제 화면·외부 수집·공식 제출은 추가하지 않았다. 보고서에 기존 실패 실험과 정답·시간대·가용 시각 한계를 포함했다.

## 2026년 10월 26일 기준 모델 실행·단일 항적 추적·실패 분석

사용자가 목표·검증 기준 설정, 작은 기준 모델 실행, 항적 한 건의 원자료→특징→입력→예측→정답 추적, 실패 사례 분석까지 진행하도록 요청했다. “코딩부터 차근차근 설명이 필요”하다는 학습 수준을 반영했다. [실행 전 고정 기준](guided_baseline_protocol_20261026.md)에 범위·모델·검증·사례 선택 규칙을 고정하고, 기존 S0 합성 구현을 재사용한 [제작 동행 실습](fishing_guided_baseline_20261026.md)을 작성했다.

실행 산출물은 `outputs/guided_baseline_20261026/`에 분리했다. 고정 선형 기준선(hidden=0, L2=.01)의 test 정확도는 114/144=79.17%, 기존 5후보 절차에서 선택된 tanh16 MLP는 117/144=81.25%다. 대표 오분류 `S0-test-000-straight-02`의 합성 원자료·8개 특징·16차원 입력·은닉값·logit·확률·생성 정답을 연결했고, 전체 혼동과 stress 사례를 분석했다. 이미 알려진 seed42 결과의 **재현 평가**이며 기존 합성 자료·모델·예측 파일 해시와 일치한다. 새 blind test, 실제자료 성능 또는 개선 입증이 아니다.

이 작업은 사용자 요청의 1~4단계에 한정한다. 실제자료 학습·외부 수집·추가 후보 탐색·test를 본 후 모델 변경은 수행하지 않았다. 실제 F1 입력·평가 계약과 학습자의 이해 확인은 미완료 상태를 유지한다. 최종 수치 검산·독립 검토는 해당 출력 폴더의 `verification.json`, `audit_review.json`에서 확인한다.

## 1. 목표와 진행 원칙

어선 항적에서 조업 형태와 평상시와 다른 정도를 추정하고, 사람이 입력·근거·한계를 확인할 수 있게 전달하는 시스템을 단계적으로 만든다. 기술적으로 실행되는 상태와 학습자가 그 판단을 설명하고 바꿔 검증할 수 있는 상태를 따로 완료 처리한다.

전체 후보 흐름은 원자료 → 입력 검사 → 경로 특징 → 조업 분류와 이상 점수 → 결과 표시다. 환경자료와 합성 경로는 같은 핵심 흐름이 확인된 뒤 선택적으로 붙이는 확장 입력이다. 자료 설명과 실제 파일의 일치가 확인될 때까지 컬럼·좌표·시간·라벨에 의존하는 조건은 초안으로 표시한다. 이번 문서는 계획이며, F0 또는 F1의 실제 데이터 적합성이 완료되었다고 선언하지 않는다.

학습 길잡이 docs/ai_textbook/95_fishing_guide.md는 학습자용 교재라고 명시되어 있다. 구체적인 학습자 수준·선수지식·목표 역량·장비·실습 시간과 환경은 아직 미확인이다. 이 정보를 확인한 뒤 활동과 평가를 맞춘다. 정보가 정해지기 전에는 하드웨어 연결, 전압·핀·전원, 차시 수와 학습자 수준을 꾸며 넣지 않는다. 현재 제안은 소프트웨어 데이터 흐름의 준비 단계이며 센서·회로·펌웨어·통신은 요구가 확인된 경우에만 추가한다.

## 2. 근거와 데이터 상태

| 구분 | 확인된 내용 | 취급 |
| --- | --- | --- |
| 기존 목적 초안 | 공식 설명을 바탕으로 날짜·선박·시간대 항적, Train의 조업 라벨, Test A/B 목적을 정리해 둠 | 출처 설명의 요약이다. 실제 파일의 스키마·품질 검증과 구분 |
| 초기 명세 | 공식 페이지 설명 확인일을 2026-10-05로 기록. 샘플 CSV와 큰 ZIP 목록이 표시되었다고 기록 | 문서상 출처 확인. 다운로드·압축 내용·실제 행은 미확인 |
| 학습 길잡이 | 2026-10-07 기준 원자료 구조 점검 결과가 없다고 기록. 좌표별 시각·CRS 등은 미확인 | 학습자용 초안의 범위 설명 |
| 현재 data/raw | 빈 .gitkeep 한 개 | 이 작업공간의 직접 확인 결과. 검사할 원자료 없음 |
| outputs/data_inventory.json | scanned_files=[], csv_files_inspected=0, metadata_only_files=0, no_supported_data_found=true, truncated=false | 저장된 구조 점검 결과. 실제 데이터 평가가 아니며 검사한 경로·범위에 한정 |
| tools/inspect_data.py | 읽기 전용 구조 검사기 v1.1. 기본 탐색은 비재귀; CSV는 최대 2 MiB와 최대 100개 레코드 표본; 최대 100개 파일 | 제한된 2D WKT 구조만 검사. CRS·거리·실제자료 적합성은 검증하지 않음 |

검사기는 기본 UTF-8-SIG와 쉼표 구분 CSV를 사용한다. .zip 파일은 압축을 풀지 않고 메타데이터만 다룬다. 심볼릭 링크와 Windows 재분석 지점은 제외한다. 표본에서는 알려진 컬럼과 빈 필드, 날짜 형식, 시간대 값 범위를 검사하고, geom은 제한된 2D MULTILINESTRING 구조·유한 XY·부분선별 최소 점 수를 검사한다. 이는 실제 좌표계나 경로의 지리적 타당성을 확인하지 않는다. 100개 레코드를 넘거나 2 MiB보다 큰 CSV의 나머지 내용은 검사되지 않으며, 기본 탐색은 하위 폴더를 방문하지 않는다. 기존 inventory에서 잘림은 보고되지 않았지만, 그것은 당시 실행의 파일 탐색 결과일 뿐 모든 보관 위치를 조사했다는 의미가 아니다.

새로 등장하는 데이터 조건은 모두 초안 또는 가정으로 기록한다. 데이터시트·공식 설명에서 확인한 값, 설계 가정, 실제 검사·측정 결과를 혼용하지 않는다. 원자료가 도착하면 파일명·버전·크기·해시·검사 경로·검사한 행 수·한도·미검사 범위를 함께 기록한다. 보고서·오류 메시지·콘솔 출력에 원자료 필드값이나 WKT 본문을 그대로 내보내지 않고, 오류 유형과 안전한 행/필드 위치만 남기는 기준도 검사한다.

## 3. 잠정 데이터 계약

아래 계약은 기존 문서의 설명을 구현 가능한 질문으로 바꾼 초안이다. 실제 파일과 공식 세부 설명을 대조하기 전에는 확정 입력 규격으로 사용하지 않는다.

| 항목 | 잠정 계약 | 확인 전 제한 |
| --- | --- | --- |
| 관측 단위 | 한 레코드가 선박·날짜·시간대 항적이라는 설명을 출발점으로 둔다 | 실제 파일이 이 단위를 따르는지 확인 전 가정 |
| 식별·시간대 | part_dt는 날짜, rfid_id는 선박 식별자, rfid_time은 0~23 시간대라는 설명 | 시간대의 표준시·현지시각, 시작·종료 경계, 관측 시각은 미확인 |
| 경로 | geom은 경도·위도 순서의 WKT MultiLineString이라는 설명 | CRS 미확인 시 좌표 범위 검사를 기본 수행하지 않는다. lon/lat 범위 검사는 명시적으로 lon/lat이라고 가정한 선택 검사에서만 실행 |
| 라벨 | Train의 fishing_code를 조업 분류 정답 후보로 둔다 | 전체 코드·클래스 의미·라벨 단위·불확실성은 미확인 |
| 부분선·빈 경로 | MultiLineString 부분선 경계를 보존한다. 허용 WKT subset의 EMPTY 문법은 파싱 가능한 상태로 받되 분석 불가로 분리 집계한다 | 서로 다른 부분선을 이어 이동거리로 만들지 않음. EMPTY를 유효 특징이나 조업·이상 라벨로 만들지 않음 |
| 점별 시간 | 좌표별 시각이 확인되지 않은 현재 설명에서는 점별 시간 미상으로 둔다 | 좌표 순서만으로 속력·가속도·체류시간을 계산하지 않음 |
| 이상·사고 | 이상 점수와 사고 여부를 다른 결과로 둔다 | High 변동 수준은 사고 라벨이 아니며, 사고 정보 미표시는 정상 라벨이 아님 |
| 학습 분할에서 적합 | 모델, 스케일·변환, 정상 기준은 선박·시간·가용성 조건을 적용한 학습 분할에서만 적합한다 | 검증·보정·최종 평가 분할을 fit에 섞지 않음 |
| 검증 분할에서 선택 | 하이퍼파라미터와 운영 임계값은 사전에 정한 검증 분할에서 선택한다 | 최종 평가 결과를 보고 선택을 바꾸지 않음 |
| 별도 보정 분할 | 점수·확률 보정이 필요하면 별도 보정 분할에서 수행한다 | 보정 자료를 최종 평가 자료와 분리 |
| 최종 평가 분할 | 모든 최종 선택·적합·보정에서 제외하고 마지막 평가에만 사용한다 | 선박 분리와 시간 가용성 제약을 모든 분할에 적용 |
| 시간 가용성 | 관측시각(event/observation time)과 시스템이 그 자료를 알 수 있었던 가용시각(available time)을 나눈다 | 조기 탐지에는 판단 시점까지 실제 이용 가능했던 정보만 넣음 |
| 출처 | 원본·가공본·합성본·예측을 식별하고 원래 값과 예측값을 덮어쓰지 않는다 | 실제/합성 표본을 출처 없이 섞지 않음 |

계약의 확정은 파일·설명·검사 근거가 서로 맞는 항목에 한해서만 한다. 확인되지 않은 항목은 null/unknown 또는 명시적 오류로 남기며, 임의 보정으로 통과시키지 않는다. 공개된 과제 제출 예시는 내부 메시지 계약과 다른 층이므로, 실제 제출 규격을 확보한 뒤 별도 변환 규격으로 정의한다.

## 4. 전체 시스템 구조와 계층별 책임

| --- | --- | --- | --- |
| 원자료 | 제공기관 파일을 원본 그대로 식별·보존 | 파일 식별 정보, 출처, 미확인 메타데이터 | 자료 부재 상태를 기록. 취득 실행은 후속 |

| 환경 옵션 | 위치와 시간에 맞춘 관측자료를 부가 조건으로 전달 | 관측값, 출처, 관측시각, 가용시각, 결측·대표성 한계 | 외부 수집·결합 미실행. 이용 조건과 공간·시간 해상도 승인 후 |

오류는 원자료 접근·형식, 시간/좌표 계약, 기하 파싱, 특징 계산, 모델 입력·판정, 표시·전달의 경계에서 분류한다. 결과에는 입력 출처, 스키마·검사 버전, 모델 버전, 처리 상태와 정보 부족 이유를 전달하는 것이 잠정안이다. **[Astra 검토 대상]** 오류 코드와 데이터 계약 버전의 최종 통합 규칙은 독립적인 설계 결정으로 검토한다.

## 5. F0→F1 준비 작업과 선행조건 DAG

이번 실행 순서는 입력 계약 보완 → 검사기 강화 → 명시적 적합성 기하 검산 → 후속 관문 결정이다. 현재 data/raw에 원자료가 없으므로 실제 항적을 넣는 특징 파이프라인은 만들지 않는다. 기하 계산은 합성 fixture에 한하며, 좌표 평면과 미터 단위 가정을 명시한다.

    기존 목적·명세·학습 길잡이와 저장소 상태 확인 ─┐
    학습 환경의 미확인 질문 정리 ────────────────┼→ 계약 초안 보완
    원자료/실제 inventory 상태 직접 확인 ────────┘       │
                                                         ├→ 검사기 요구와 제한 연결
                                                         │   ├→ 원자료 필드값 출력 방지
                                                         │   ├→ 허용 WKT subset 파싱
                                                         │   ├→ EMPTY 파싱 및 분석불가 별도 집계
                                                         │   └→ CRS 미확인 범위검사 생략
                                                         └→ 합성 기하 계약 검산
                                                              ├→ 부분선별 길이
                                                              ├→ 각 부분선 변위
                                                              └→ 각 부분선 직선성
                                                                      │
                                                                      └→ F1 준비 검토

실제 원자료 제공은 별도 차단 관문이다. 원자료가 식별·버전 고정되고 계약과 맞는지 확인되기 전에는 실제 특징, 조업/이상 라벨, 학습·평가를 만들지 않는다. 자료 도착 시 검사기 출력과 한계를 확인한 후, 실제 자료를 처리할 다음 티켓을 따로 승인한다.

검사기 v1.1에는 원본값 비노출과 제한된 WKT 부분집합 검사가 구현되어 있다. 이 기능 설명은 실제 원자료를 검증했다는 뜻이 아니다. 아래는 현재 구현의 범위와 한도다.

- 보고서·표준 출력·오류에 CSV 필드의 원문 값이나 전체 geom 문자열을 노출하지 않는다. 오류 유형과 안전한 행/필드 위치만 보고하고, 예시 marker 문자열이 출력에 재등장하지 않는지 확인한다.
- 허용하는 WKT 문법 부분집합과 거부하는 구문을 명시한다. 이는 전체 WKT 호환 선언이 아니다.
- 2D MULTILINESTRING의 유한 XY 좌표쌍과 부분선별 최소 2점을 구조 파싱한다. `MULTILINESTRING EMPTY` 문법은 인식하지만 분석 불가(`geom_empty`)로 집계하고 표본 문제로 처리한다. Z/M/ZM 및 EWKT는 지원하지 않는다. 전체 OGC WKT 검증기는 아니다.
- CRS가 확인되지 않은 기본 설정에서는 좌표 범위 검사를 생략한다. 선택 검사에서 lon/lat이라고 명시적으로 가정한 경우에만 경도·위도 범위를 검사하며, 가정 상태를 결과에 남긴다.
- 허용 헤더만 보고서에 기록하고 알 수 없는 헤더는 개수만 센다. 후보키 `(part_dt, rfid_id, rfid_time)` 충돌은 표본 집계이며 전체 고유성 보장이나 중복 제거가 아니다. 표본 경계의 lookahead 파싱 오류는 이미 읽은 행을 보존하고 안전한 오류 코드와 행 위치를 남긴다.
- 이 검사기는 부분선·점 개수를 집계한다. 조업·이상 점수는 산출하지 않으며, 좌표 원문을 출력하거나 부분선을 연결하거나 거리·속력을 계산하지 않는다. 실제 검사 데이터는 여전히 없다.

후속 의존관계는 다음과 같다.

    대표 원자료 + 시간/CRS/축/점 순서 계약 확인 → 라벨 없이 F2 기하 입력·계산 점검 가능
    좌표별 시각이 없다고 계약 확인 → 기하만 허용, 실제 속력·가속도는 제외
    조업 라벨 의미 + 평가 분할 근거 확인 → F3 분류 기준선 및 별도 이상 기준 검토
    학습자료 분할 고정 → 학습자료에서만 변환·기준 적합 → 독립 평가
    관측시각·가용시각·공간 대표성 확인 → 환경 옵션 검토
    실제 특징 분포와 라벨 의미 확인 → 합성 유닛 하나의 의미 보존 검토
    결과 계약·사용자 목표 확인 → 표시 확장, 필요성이 입증될 때만 3D/시뮬레이터 검토

## 6. 명시적 적합성 검산

원자료가 없어 실제 적합률·결측 수·좌표 오류 수·실제 특징값은 계산할 수 없다. 아래는 합성 fixture의 평면 좌표를 미터로 해석한 기하 계약 검산이다. 실제 항적, 측정값, 조업 라벨, 이상 라벨 또는 속력 결과가 아니다.

| 검산 항목 | 계산 | 기대 결과 |
| --- | --- | --- |
| 부분선 A 길이 | A = [(0,0),(3,4),(6,4)]: sqrt(3²+4²)+3 = 5+3 | 8 m |
| 부분선 A 변위 | A의 첫 점에서 끝 점까지 sqrt(6²+4²)=sqrt(52) | 약 7.2111 m |
| 부분선 A 직선성 | 변위 ÷ 길이 = sqrt(52)÷8 | 약 0.9014 |
| 부분선 B 길이 | B = [(100,0),(100,12)]: 12 | 12 m |
| 부분선 B 변위 | B의 첫 점에서 끝 점까지 12 | 12 m |
| 부분선 B 직선성 | 변위 ÷ 길이 = 12÷12 | 1 |
| 두 부분선 길이 합 | 부분선 A 길이 + 부분선 B 길이 = 8+12 | 20 m |
| 단절 경계 | A의 끝과 B의 시작을 연결하는 선분을 추가하지 않음 | 사이 이동 길이는 미관측 |
| 금지연결 반례 | 교육용으로만 A 끝과 B 시작을 인위적으로 연결: sqrt((100−6)²+(0−4)²)=sqrt(8852), 이를 더한 잘못된 총 길이 20+sqrt(8852) | 약 94.0851 m 인위 구간, 잘못 연결한 합계 약 114.0851 m; 관측 feature가 아님 |
| 속력·조업/이상 라벨 | 점별 시각·라벨이 입력에 없음 | 출력하지 않음 |

직선성은 각 부분선 안에서만 정의한다. 전체 직선성이나 부분선 변위 합계는 만들지 않는다. 떨어진 부분선의 양 끝을 골라 하나의 전체 변위를 만드는 것은 계약 위반이다. 두 관측 부분선의 길이 합은 20 m로 보고하되, 단절 구간은 연결하지 않고 그 사이 이동길이는 미관측으로 남긴다. 금지연결 계산은 이 오류를 보이는 교육 반례이며 관측 feature가 아니다. 좌표, 단위와 부분선은 교육용 합성 가정이며, 실제자료의 CRS·좌표 축 순서를 확인했다는 뜻이 아니다.

데이터가 도착한 뒤 실제 적합성은 검사 범위와 나눠 보고한다. 검사한 파일/CSV 수, 표본 행 수, 미검사 바이트·행, 잘림 여부를 먼저 표시한다. 필수 필드 누락은 계약상 필수 컬럼 집합에서 헤더 컬럼 집합을 뺀 개수로 계산한다. 필드별 빈 비율은 빈 값 수 ÷ 검사 행 수이며, 분모가 0이면 미정으로 둔다. 날짜 달력성, 시간대 범위는 공식 정의와 파일 설명이 맞는 경우에 적용한다.

WKT parser의 결과는 구조화된 2D MULTILINESTRING, EMPTY(문법 인식·분석 불가), 지원하지 않는 문법, 잘못된 문법을 구별한다. 유한 XY와 부분선별 2점 이상을 검사하고 부분선·점 개수만 집계한다. 조업·이상 점수는 산출하지 않으며 좌표 원문을 출력하거나 부분선을 연결하거나 거리·속력을 계산하지 않는다. CRS가 확인되지 않았으면 좌표 범위 검사를 기본 수행하지 않는다. `--coordinate-assumption lonlat` 옵션은 lon/lat 가정을 명시해 범위만 검사하며 CRS 자체를 확인하지 않는다. 속력 계산을 위해서는 좌표별 시각이 제공되고 의미가 확인되어야 한다.

분할 역할은 평가 전에 고정한다. 모델·스케일/변환·정상 기준은 학습 분할에서만 적합하고, 하이퍼파라미터·운영 임계값은 지정 검증 분할에서 선택한다. 점수/확률 보정이 필요하면 별도 보정 분할에서 수행한다. 최종 평가 분할은 선택·적합·보정 전부에서 제외하며 마지막 평가에만 사용한다. 선박 분리와 시간 가용성 조건을 모든 분할에 적용하고 실제 실행은 하지 않았다. 환경정보가 후속 도입될 경우 관측시각과 가용시각을 별도 저장하고, 판단시각 t에서는 available_time ≤ t인 관측만 허용한다.

`tools/inspect_data.py`는 v1.1에서 제한된 2D WKT 구조를 검사한다. 2D MULTILINESTRING 유한 XY, 부분선별 최소 2점, EMPTY 문법 인식 후 분석 불가 집계, Z/M/ZM/EWKT 거부를 지원한다. 알 수 없는 헤더는 개수만 보고하며 후보키 충돌과 lookahead 파싱 오류 표본을 보존한다. CRS 기본 범위검사와 거리 계산은 하지 않으며 lon/lat 가정 옵션은 명시적 범위검사만 수행한다. 실제 원자료에서의 검증은 미수행이고, 버전별 실행 결과는 검증 기록을 참조한다.

## 7. 모델과 작업별 추론 설정

이 프로젝트는 새 세션의 기본 모델 설정으로 GPT-6 Astra high와 역할별 다섯 프로필을 설정 파일에 저장했다. 이 저장은 이미 실행 중인 부모 세션의 모델을 변경하지 않는다. 하위 작업도 프로필 파일이 있다는 이유만으로 해당 모델·effort로 실행되었다고 보지 않는다. 실제 하위 세션 생성 시 프로필이 적용되었는지와 세션이 보고하는 모델·effort를 확인해 티켓에 기록한다. subagent가 별도 모델/effort를 받지 않으면 부모 설정을 상속할 수 있으므로 실제 실행 설정을 확인한다. 자세한 상속·설정 우선순위는 [OpenAI 공식 subagent 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 참고한다.

| 역할 프로필 | 모델·effort | 맡는 일 |
| --- | --- | --- |
| astra_decision | GPT-6 Astra, high | 여러 작업의 종합 판단, 결정, 근거 설정 |
| sol_review | GPT-6.1 Sol, high | 독립 검토와 간단한 조건 설정 |
| sol_complex | GPT-6.1 Sol, max | 복잡한 구현과 검사기 보완 |

기존 제작계획에서 Sol medium이었던 작업은 Sol xhigh, Sol high였던 복잡 작업은 Sol max로 두 단계 높였다. 검토·간단 조건 설정은 Sol high로 배정하고, 종합 판단·결정·근거 설정은 Astra high가 맡는다. 모든 Luna 담당 작업은 Luna xhigh다. 현재 운영표는 이 확정 지침을 반영한다. 과거 교재 검증 산출물에 기록된 ultra 등 기존 실행 설정은 해당 시점의 이력으로 유지한다.

## 8. 파일 소유권과 통합 규칙

- 각 티켓은 한 명의 작성 소유자와 변경 허용 경로를 가진다. 이 문서는 docs/fishing_execution_plan.md만 소유한다. 본 계획 작성 범위에는 코드 수정이 없다.
- 다른 담당자는 배정받지 않은 문서·코드·출력 파일을 수정하지 않는다. 공유 계약이나 공용 검사기를 바꿔야 하면 먼저 제안 티켓을 작성해 통합 담당자가 승인한 뒤, 한 작성자만 그 파일을 수정한다.
- 평행 작업은 서로 다른 파일과 안정된 인터페이스를 사용한다. 같은 파일을 동시에 고치지 않는다. 공용 타입·컬럼 이름·오류 상태 변경은 문서 계약을 먼저 갱신하고 소비자 작업을 다시 확인한다.
- 통합 담당자는 티켓의 파일 소유권, 요구사항 추적, 변경 파일 목록, 검사 결과, 알려진 한계를 확인하고 계약 버전을 고정한다. 계약 불일치는 임의로 맞추지 않고 보류 상태와 선택 근거를 남긴다.
- 원자료는 원본으로 식별·보존한다. 보고서, 수작업 검산, 합성 예제는 실제 관측자료와 쉽게 구별되게 출처를 기록한다. 실제 장치나 평가를 하지 않았다면 했다고 표시하지 않는다.
- 자료·코드·계산 테스트, 시뮬레이션, 실제 데이터 평가, 실측은 서로 다른 증거로 기록한다. 산출물이 존재하는 것만으로 학습 목표 달성이나 모델 성능을 선언하지 않는다.
- 기존 어선 자료를 인용할 때 장 번호만 쓰지 않는다. 조류 프로젝트 문서와 장 번호가 중복되므로 docs/ai_textbook/chapters/19_fishing_data_geometry.md, 20_fishing_classification.md, 21_fishing_sequence_models.md, 22_fishing_anomaly.md, 23_fishing_environment.md, 24_fishing_virtual_units.md, 25_fishing_evaluation_system.md처럼 정확한 *_fishing_*.md 파일명으로 식별한다. 해설은 docs/ai_textbook/94_fishing_solutions.md, 학습 적용편은 docs/ai_textbook/95_fishing_guide.md로 부른다.

## 9. 기술 완료와 학습 성취

| 완료 축 | F0→F1 준비의 완료 조건 | 미완료로 남는 상태 |
| --- | --- | --- |
| 기술 준비 | 초안 데이터 계약·검사기 v1.1 기능과 한도, 원본값 비노출·WKT·경계 사례 검증 결과, 명시 fixture의 부분별 계산·총 길이 20 m·금지연결 반례와 자료 도착 후 적합성 절차가 검증 기록으로 확인됨 | 실제 원자료 스키마·품질 적합성은 미확인. 모델·실제 평가·외부 결합·가상 유닛·3D는 미구현 |
| 실제 F1 자료 관문 | 원자료 식별·설명 대조, 표본/전체 검사 범위 명시, 날짜·시간·geometry·부분선·라벨 조건을 근거와 함께 확인, 미검사 영역 설명 가능 | 원자료가 없으므로 현재 관문은 닫을 수 없음 |
| 학습 성취 | 학습자가 확인·가정·미확인을 구별하고, 왜 좌표별 시각이 없으면 속력을 계산할 수 없는지 설명하며, 손계산으로 부분선 단절을 보존하고 입력 실패 계층을 좁힘 | 문서를 읽거나 시스템이 실행된 사실만으로 성취 판정하지 않음 |
| 수업 적합성 | 학습자·선수지식·목표 역량·장비·시간·환경을 확인한 뒤 활동과 평가 기준을 맞춤 | 학습자용 자료라는 목적은 확인되었고, 구체적인 교육 운영 조건은 미확인 |

F1 전체 자료 적합성 기록에는 라벨 설명도 필요하지만, 그 조건을 기다려야 F2 기하 점검을 시작하는 것은 아니다. 대표 원자료의 시간·좌표·기하 입력 계약이 통과하면 라벨과 평가 분할이 미확정이어도 무라벨 경로 읽기·기하 계산을 검토할 수 있다. 좌표별 시각이 없다는 시간 계약을 확인한 경우 속력 없이 기하만 검증한다. 모델 기준선과 이상 점수 평가는 라벨 의미 및 평가 분할이 정리된 F3에서 시작한다.

## 10. 후속 작업 관문

| 관문 | 시작 조건 | 구현·검토 범위 | 다음으로 넘어갈 증거 |
| --- | --- | --- | --- |
| F0 준비 | 기존 목적·명세와 현재 파일 상태 | 요구·가정·환경 조건·계약·검사 한도 문서화 | 데이터 조건과 미확인이 구분됨 |
| F1 데이터 적합성 | 식별 가능한 원자료 제공 및 설명 근거 | 검사기 적용/확장, 스키마·시간·좌표·단절·라벨 대조, 명시 계산 | 파일/버전/범위가 재현되고 제한이 설명됨 |
| F2 무라벨 기하 확인 | 대표 원자료 및 핵심 시간·좌표·기하 입력 계약 통과 | 소량의 실제 경로 읽기→검사→기하 계산. 조업 라벨과 평가 분할은 선행조건이 아님 | 부분선 경계·계산을 설명하고, 점별 시각이 없으면 속력 없이 기하만 검증 |
| F3 분류·이상 기준선 | 조업 라벨 의미와 평가 분할 근거 | 최소 모델과 이상 점수 후보를 분리 정의 | 학습 기준 적합, 누수 검사, 독립 평가와 한계 기록 |
| 환경 옵션 | 외부자료 이용 허용·시공간 해상도·가용시각 확인 | 제한된 변수 하나 결합 검토 | 대표성·누수·결측이 평가되고 기여 근거 있음 |
| 합성 옵션 | 실제 특징 분포와 라벨 의미 확인 | 검증 유닛 한 조건과 재현 가능한 시드 | 라벨 의미 유지, 출처 분리, 실제 자료 평가 비교 |
| 표시 확장 | 핵심 결과 계약·오류·교육 요구 확인 | 2D 표시 후 필요한 상호작용 판단 | 출처·부분선·판단 유보가 읽히고 교육 목표에 기여 |
| 3D/시뮬레이터 | 2D·기하·시간·고도/깊이 의미 및 학습 요구 입증 | 필요한 최소 범위만 설계 | 정확한 관측량과 시각화 표현 구분, 별도 검증 |

각 확장 관문은 선택 사항이다. 교육 목표를 돕지 않거나 자료 근거가 없으면 추가 구현 결정을 보류한다. **[Astra 검토 대상]** 실제자료 확보 뒤의 모델 계열·공식 지표 세부화, 외부 자료 허용, 합성 라벨 정책, 3D 필요성은 새 증거를 반영해 판단 근거와 함께 승인한다. 분할별 학습·검증·보정·최종 평가 역할은 이미 승인된 규칙이다.

## 11. 다른 세션으로 복사할 시작 프롬프트

아래 문구를 작업 세션에 복사해 사용할 수 있다. 담당 세션은 지정된 티켓 파일만 수정하고, 미래 단계까지 자동 확장하지 않는다.

    docs/fishing_execution_plan.md와 배정 티켓의 근거를 읽고 지정 파일만 처리하라. F0→F1 기술준비는 Astra high가 승인 완료했으며 검증 결과는 docs/fishing_verification.md를 따른다. 실제 F1 자료 적합성은 원자료 부재로 열려 있다. 대표 원자료와 시간·좌표·기하 입력 계약이 통과하면 조업 라벨·평가 분할이 미확정이어도 무라벨 F2 기하 점검을 시작할 수 있다. 좌표별 시각이 없다고 계약이 확인되면 속력·가속도 없이 기하만 다룬다. 조업 라벨 의미와 평가 분할은 F3 분류·이상 기준선의 선행조건이다. 자료 조건은 초안·가정으로 표시하고 부분선 경계를 보존하며 사이를 연결하지 말라. 검사기는 점 개수를 집계하지만 조업·이상 점수를 내지 않고 좌표 원문을 출력하거나 부분선을 연결하거나 거리·속력을 계산하지 않는다. High 변동은 사고 라벨이 아니다. 학습 분할에서 모델·변환·정상 기준을 적합하고 검증 분할에서 하이퍼파라미터·운영 임계값을 선택하라. 필요 시 별도 보정 분할을 쓰고 최종 평가 자료는 모든 선택·적합·보정에서 제외하라. 선박 분리와 시간 가용성 조건을 전 분할에 적용하라. 역할 설정과 현재 부모 모델을 구분하고 실제 세션 모델·effort를 기록하라. 파일별 소유권을 지키고 완료 시 결과와 미확인 사항을 보고하라.

세션을 시작하기 전에 아래 티켓 양식에 정확한 파일 소유자와 경로를 채운다.

## 13. 문서와 설계 검토 표시

주요 근거는 docs/project_purpose(초안).md의 시스템 목적·원자료 미확보·환경 및 가상 경로 아이디어, docs/initial_spec(초안 조건 분석).md의 조사표·시간/좌표 한계·누수 방지·단계 기준, docs/ai_textbook/95_fishing_guide.md의 학습자 목표·기초부터 검증까지의 흐름이다. 이번 작업 지시는 모델·effort 확정, 현재 실행 범위와 금지된 미래 구현, 핵심 데이터 주의사항의 근거다. 역할별 프로필 적용 방식은 [OpenAI 공식 subagent 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)도 참고하되, 실제 역할·effort 배정은 사용자 확정 지시를 따른다.

자료가 도착하면 위 문서의 오래된 상태 설명을 자동으로 사실로 이어받지 말고 새 파일과 조사 결과를 우선한다. 새 조건은 출처, 확인 날짜, 해당 파일·행·필드 또는 문서 위치와 함께 기록한다. 독자적이고 영향이 큰 선택은 **[Astra 검토 대상]**으로 남기며, 검토 결과·근거·미해결 반대 근거가 기록되기 전까지 확정 설계로 서술하지 않는다.
