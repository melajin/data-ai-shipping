# 실제로 실행한 모델을 한 항적씩 이해하기 — 2026-10-26

이번에는 목표·검증 기준을 먼저 기록하고, 작은 선형 모델과 기존 소형 MLP를 실행한 뒤, 한 항적의 오분류와 전체 실패 사례를 분석했다. 코드·학습 가중치·예측·중간 계산을 함께 남겼다. **합성자료를 사용한 실제 코드 실행**이며 실제 어선자료 학습이나 사고 탐지 성능 평가가 아니다.

사용자는 “코딩부터 차근차근 설명이 필요”하다고 답했다. 이 문서는 실행 코드를 모두 먼저 이해하도록 요구하지 않는다. 아래 항적 한 건의 흐름부터 읽는다. 기술 검증 결과와 사용자의 이해 확인은 별개다.

## 1. 먼저 무엇을 만들었나

합성 생성기가 만든 경로를 `straight`, `sweep`, `turn` 세 생성 유형으로 분류하는 모델이다. 이 이름은 실제 조업 코드나 정상·사고 상태가 아니다. 화면에서 휘어 보인다는 이유로 생성 정답을 바꿀 수도 없다.

현재 원자료 폴더에는 실제 학습자료가 없고, 참고 CSV 10행만 별도 확인됐다. 좌표계·라벨의 부여 단위·정식 분할·공식 평가 조건이 미확정이어서 기존 S0 합성 학습 범위로 진행했다. 이 판단은 [실행 전 고정 기준](guided_baseline_protocol_20261026.md)에 남겼다.

모델은 두 가지다.

- **작은 기준선:** 숫자 16개에 가중치를 곱해 클래스별 점수 3개를 만드는 선형 softmax 모델. 설정은 실행 전에 hidden=0, L2=0.01로 고정했다.
- **소형 MLP:** 중간에 tanh 계산 노드 16개가 있는 모델. 기존 5개 후보 비교 절차를 그대로 재현했고 validation NLL로 `mlp16_l2_0`이 선택됐다. 새 후보를 탐색한 것은 아니다.

신경망의 가중치는 **학습자료를 보며 조정한 숫자 표**다. 그 숫자 표와 전처리 통계를 저장한 파일이 `model.json`이다. 파일을 다시 읽어서 같은 예측을 만드는 것도 검산했다.

## 2. 결과부터 확인하기

| 평가 조건 | 모델 | 맞힌 수 / 평가 수 | 정확도 | Macro F1 | NLL | Brier |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| test | train 클래스 비율 기준선 | 48 / 144 | 33.33% | 0.1667 | 1.0986 | 0.6667 |
| test | 고정 선형 모델 | 114 / 144 | 79.17% | 0.7902 | 0.4806 | 0.2830 |
| test | 선택 소형 MLP | 117 / 144 | 81.25% | 0.8104 | 0.4385 | 0.2564 |
| stress | 고정 선형 모델 | 84 / 144 | 58.33% | 0.5885 | 1.0139 | 0.5791 |
| stress | 선택 소형 MLP | 89 / 144 | 61.81% | 0.6180 | 0.8802 | 0.4998 |

- 정확도는 맞힌 비율이다. Macro F1은 클래스별 분류 균형을 보는 값으로 클수록 좋다. NLL·Brier는 확률 예측의 오차를 보며 작을수록 좋다.
- train 클래스 비율은 세 클래스 모두 1/3이다. 동률에서 인덱스가 먼저인 straight를 선택하므로 정확도는 1/3이다. NLL·Brier는 확률 1/3씩으로 계산했다.
- MLP는 이번 test에서 선형보다 3건 더 맞혔다. 이 차이가 다른 자료나 실행에서도 유지된다는 증거는 아니다. 비교의 통계적 우위를 검정하지 않았다.
- validation에서 MLP의 보정 전 정확도는 77.08%, 선형은 77.78%다. MLP 선택 이유는 사전에 정한 **NLL**이 더 낮았기 때문이다. 모든 지표에서 우월한 모델을 찾았다고 해석하면 안 된다.
- 다섯 후보의 최적 epoch는 모두 400이고 선택 MLP의 L2는 0이다. 이번 결과만으로 조기 종료나 L2가 성능을 개선했다고 주장할 수 없다. 확률 온도 보정은 양의 온도로 순위를 유지하므로 정확도 상승의 이유도 아니다.
- 이미 읽었던 seed 42 test/stress를 재현했다. 기존 자료·모델·예측 파일과 SHA-256이 동일하고 보고된 지표도 동일하다. 새 blind test나 개선 성과가 아니다.

train은 36개 합성 선박·432건, validation/calibration/test/stress는 각각 12개 선박·144건이다. 선박 중복은 0이며 전체 1,008건 중 유보는 0이었다. 여기서 “모두 유효”는 이 생성 자료의 결과이며 미래 입력도 모두 유효하다는 뜻이 아니다.

## 3. 항적 한 건: 좌표에서 예측까지

대표 사례는 `S0-test-000-straight-02`다. 결과가 그럴듯한 사례를 임의로 고르지 않고, 미리 정한 규칙인 **test 오분류를 sample_id로 정렬한 첫 사례**를 골랐다.

![실패 항적·정분류 대조·확률·혼동행렬](../outputs/guided_baseline_20261026/walkthrough.png)

### 3-1. 원자료는 무엇인가

관측 좌표는 62개이고 5개의 부분선으로 나뉜 합성 XY 미터 자료다. 이 사례는 누락점 0개지만 생성기의 단절 규칙 때문에 부분선이 5개다. 단절과 점 누락은 같은 상태가 아니다. 부분선 중 하나는 길이가 없어 양의 길이 부분선 집계에서 제외되고, 나머지 4개가 사용된다.

좌표 한 쌍은 `[x, y]`, 한 부분선은 좌표 쌍 여러 개, `parts`는 부분선 여러 개를 담은 목록이다. 떨어진 부분선 사이에 선을 추가하지 않는다. 실제 지도나 실제 항적 시간이 아니며 속력·가속도를 계산하지 않는다.

생성 정답 `label=0`은 결과 대조에 사용한다. 이를 입력 숫자에 넣고 정답을 외우게 하지 않는다.

### 3-2. 좌표 수십 개를 숫자 8개로 요약한다

특징은 모델이 읽도록 경로의 성질을 숫자로 요약한 것이다. 다음 표는 실제 이번 사례의 계산값이다. 계산값과 train 통계는 [trace.json](../outputs/guided_baseline_20261026/trace.json)에 보존했다. 전체 특징의 수식은 [26장](ai_textbook/chapters/26_fishing_sample_system_personal_study.md)의 6절에서 확인한다.

| 특징 이름 | 읽는 방법 | 원시 특징값 | 표준화 후 |
| --- | --- | ---: | ---: |
| log1p_total_length_m | 관측 부분선 길이 합을 로그로 줄인 값 | 6.432467 | -1.760354 |
| mean_part_straightness | 양의 길이 부분선별 직선성의 산술평균 | 0.990649 | 0.397818 |
| mean_abs_turn_rad | 유효한 이웃 이동 방향의 회전각 절대값 평균 | 0.037456 rad | -0.887310 |
| turn_direction_concentration | 회전이 한 방향으로 모이는 정도 | 0.460018 | 0.583789 |
| std_turn_rad | 회전각의 표준편차 | 0.042644 rad | -0.842375 |
| max_abs_turn_rad | 가장 큰 회전각 절대값 | 0.108896 rad | -0.876603 |
| mean_part_spread_ratio | 부분선별 공간 퍼짐 비율의 평균 | 0.038638 | -0.520604 |
| mean_part_chord_deviation_ratio | 부분선 양끝 직선에서 벗어난 정도의 길이 대비 비율 평균 | 0.034888 | -0.560154 |

부분선 직선성은 `양끝 거리 / 관측 선분 길이 합`이다. 여러 부분선은 각 비율을 먼저 계산한 뒤 평균한다. 전체 변위 합을 전체 길이 합으로 나눈 비율로 바꾸지 않는다.

### 3-3. 모델이 읽을 숫자 16개로 바꾼다

길이와 각도처럼 크기가 다른 숫자는 train에서 얻은 기준으로 바꾼다.

`표준화 값 = (결측 대치 후 값 - train 평균) / train 표준편차`

누락된 특징이 있다면 train 중앙값으로 채우고, “원래 누락이었다”는 표시도 남긴다. 이 사례는 여덟 특징이 모두 계산돼 표시 8개가 전부 0이다. 좌표 단절이 있다고 모든 특징이 결측인 것은 아니다.

```text
모델 입력 = [표준화한 특징 8개, 특징별 누락 표시 8개]

[-1.760354,  0.397818, -0.887310,  0.583789,
 -0.842375, -0.876603, -0.520604, -0.560154,
  0, 0, 0, 0, 0, 0, 0, 0]
```

이 숫자 목록을 벡터라고 부른다. Python에서는 NumPy 배열로 계산한다. `vessel_id`, `label`, `split`, `scenario`, `sim_times`, `quality`는 이 특징 벡터에 들어가지 않는다. `quality`는 원자료 상태 설명에만 쓴다.

### 3-4. 숫자 16개가 점수 3개가 된다

MLP는 먼저 입력과 가중치를 곱하고 편향을 더한 뒤 tanh를 적용해 은닉값 16개를 만든다. 다시 가중치를 곱하고 편향을 더해 클래스 점수 3개를 얻는다.

```text
입력(1×16) → W1(16×16)·b1(16) → tanh 은닉값(1×16)
           → W2(16×3)·b2(3) → logit(1×3)

이번 항적 logit: [0.584623, -2.105656, 1.142822]
클래스 순서:     [straight, sweep, turn]
```

logit은 아직 확률이 아니다. 세 점수에 양의 온도 T=0.944061을 적용해 softmax로 바꾸면 합이 1인 확률이 된다. 온도는 별도 calibration 자료로 정했다.

| 생성 유형 | 보정 후 모델 확률 |
| --- | ---: |
| straight | 34.91% |
| sweep | 2.02% |
| turn | 63.07% |

모델은 가장 높은 `turn`을 선택했다. 생성 정답은 `straight`이므로 **오분류**다. 63.07%는 모델이 낸 확률값이며 이 한 사례가 실제로 맞았다는 보증은 아니다. 보정 전후 확률과 은닉값 16개를 모두 trace.json에 남겼다. 수동 행렬 계산과 저장 예측이 허용오차 1e-10 안에서 같은지 검산한다.

같은 항적에 선형 기준선도 turn 확률 59.11%를 주며 틀렸다. 단순히 은닉층을 추가하면 이 사례가 해결된다는 증거는 없다. 정분류 대조 사례에서는 MLP가 생성 정답 straight에 84.01%를 줬다.

### 3-5. 틀렸는데 이상 플래그는 왜 안 켜졌나

이 항적의 별도 Mahalanobis 점수는 10.9661이고, validation에서 정한 임계값은 17.6126이다. 따라서 이상 플래그는 false다.

분류기는 “세 생성 유형 중 어느 것인가”를 묻고, 거리 모델은 “학습한 클래스 분포 모두에서 얼마나 떨어져 있는가”를 묻는다. 분포 근처에서도 잘못 분류할 수 있다. 이 사례가 그 차이를 보여 준다. 이상 플래그는 사고 유무 정답이 아니다.

## 4. 전체 실패 사례에서는 무엇을 알았나

### test: 144건 중 27건 오분류

아래는 선택 MLP의 혼동행렬이다. 행은 생성 정답, 열은 예측이다.

| 정답 ＼ 예측 | straight | sweep | turn | 정답별 수 |
| --- | ---: | ---: | ---: | ---: |
| straight | 40 | 3 | 5 | 48 |
| sweep | 15 | 32 | 1 | 48 |
| turn | 1 | 2 | 45 | 48 |

- 가장 많은 혼동은 `sweep → straight` 15건이다. sweep 48건의 31.25%이며, 전체 27건 오류의 55.56%다.
- 확률 최댓값이 0.8 이상인데 틀린 사례도 5건이다. 모델의 확신만으로 정답 여부를 판단할 수 없다. 0.8은 이번 오류 집계용 기준이다.
- 대표 오분류와 같은 정답의 정분류 대조 사례는 `S0-test-000-straight-00`이다. 서로 다른 항적의 특징 차이를 관찰할 수 있지만, 차이 하나가 원인임을 입증한 대조 실험은 아니다.

### stress: 144건 중 55건 오분류

첫 사례 `S0-stress-000-straight-01`은 생성 정답 straight를 sweep으로 예측했다. 확률은 straight 10.50%, sweep 52.80%, turn 36.70%다. 관측점은 53개, 누락점은 21개, 부분선은 21개이고 거리점수는 94.4297이다. 이상 플래그가 켜지지만 사고 정답은 없다.

stress에는 척도·잡음·점 누락·단절 네 조건 변화가 함께 들어가며 test와 선박도 다르다. 정확도가 81.25%에서 61.81%로 19.44%p 낮아졌다는 사실은 관찰했다. 어떤 변화가 얼마만큼 영향을 줬는지, 이것이 과적합인지까지 이번 비교로 확정할 수 없다.

### 원인을 어디까지 좁혔나

| 계층 | 이번에 관찰·검산한 것 | 남은 해석·가설 |
| --- | --- | --- |
| 원자료·정답 | 합성 생성 규칙·ID·label 출처와 계약 일치 | 생성 유형의 일부 범위가 겹쳐 분류가 어려울 수 있음. 이 사례의 오분류 원인을 확정한 것은 아님 |
| 기하 특징 | 부분선 보존, 길이·직선성 수동 검산, 특징 순서 일치 | 8개 요약만으로 클래스 구별 정보가 충분한지는 추가 가설 |
| 전처리 | train 통계 재계산 일치, 16차원 값 대조, 정답 제거 불변 | 다른 자료 조건에서 결측·표준화가 얼마나 안정적인지는 미검증 |
| 모델 | 수동 순전파·저장 추론 일치, confusion 독립 재계산 | 경계 부근의 클래스 중첩·표본·특징·모델 용량 중 원인 비중 미확정 |
| 전달·표시 | JSON의 클래스 순서·확률·정답을 연결하고 정적 진단 그림으로 확인 | dashboard HTML은 생성·기존 자동검증 근거가 있으나 이번 브라우저 시각 검토는 file URL 정책으로 차단됨 |

이번에는 분석까지 수행했다. 개선 가설을 실제 실험으로 확인하는 작업은 다음 단계다. 예를 들어 같은 기본 경로에서 누락 조건 하나만 바꾸는 짝 실험을 설계할 수 있지만, 이번 결과에 맞춰 모델을 재조정하지 않았다.

## 5. 직접 실행해 보기 — 학습을 다시 하지 않는 명령

프로젝트 폴더의 터미널에서 다음 한 줄을 실행하면 대표 항적의 숫자를 다시 출력한다.

```powershell
python tools/trace_one_sample.py --out outputs/guided_baseline_20261026 --sample-id S0-test-000-straight-02
```

이 명령은 파일을 읽고 이미 학습한 모델로 계산만 한다. 출력에서 `features_8`, `model_inputs_16`, `probabilities_3`, `predicted`, `generator_answer`, `correct`를 순서대로 찾는다.

[짧은 추적 코드](../tools/trace_one_sample.py)를 읽을 때는 다음 다섯 구간만 먼저 본다.

1. `load_dataset`, `load_model`: 경로 자료와 학습한 숫자 표를 읽는다.
2. `feature_matrix([record])`: 항적 한 건에서 특징 8개를 계산한다. `[record]`는 항적 한 건을 담은 목록이다.
3. `preprocessor.transform(raw)`: 저장된 train 통계로 특징을 바꾸고 누락 표시를 붙인다. `fit`으로 다시 학습하지 않는다.
4. `predict_logits`, `softmax`: 클래스 점수와 확률을 계산한다. `np.argmax`는 가장 큰 값의 위치를 고른다.
5. `record['label']`과 비교: 예측한 후에 생성 정답과 대조한다.

첫 학습 때는 가중치를 수정한다. 여기서 하는 추론은 **가중치를 고정한 채 새 입력을 계산**하는 일이다. 이 차이를 구분하는 것이 첫 학습 목표다.

전체 학습을 별도 새 폴더에서 재현하려면 다음 명령을 사용한다. 이미 내용이 있는 출력 폴더에는 덮어쓰지 않도록 막았다.

```powershell
python tools/run_guided_baseline.py --out outputs/guided_baseline_replay_02
python tools/analyze_guided_baseline.py --out outputs/guided_baseline_replay_02
```

## 7. 이 항적을 보고 직접 설명할 네 문장

아래는 정답을 외우는 시험이 아니라, 다음 단계 전에 이해를 확인할 질문이다. 현재 답변 상태는 미확인이다.

1. “62개 좌표가 있는데 모델 입력은 왜 16개인가?”
2. “생성 정답 straight는 언제 사용하며, 왜 입력에 넣지 않는가?”
3. “turn 확률 63.07%인데 왜 틀렸고, 이상 플래그는 왜 꺼져 있는가?”
4. “stress 성능이 낮다는 사실만으로 점 누락이 원인이라고 말할 수 없는 이유는?”

이번 기술 목표는 실행·재현·추적·실패분석까지다. 학습 목표의 달성 여부는 이 질문에 대한 설명과 실제 숫자를 바꿔 해석하는 활동으로 별도 확인한다.
