## 1. 한 장으로 이해하는 전체 그림

항적 분석은 원자료를 읽는 작업에서 끝나지 않는다. 파일을 해석하고, 좌표와 시간의 의미를 확인하고, 관측된 경로를 수치로 요약한 다음, 학습된 규칙으로 출력을 만든다. 각 단계의 입력 계약이 다음 단계의 계산 가능 범위를 결정한다.

현재 이미 구현된 흐름은 다음과 같은 **S0 합성 교육 실험**이다.

```text
명시적 합성 좌표·부분선·생성 정답
 → 레코드 검증과 유효성 판단
 → shape9 형상 특징 9개
 → train 통계로 대치·표준화 + 원래 결측 마스크 9개
 → 저장 MLP의 logits 3개
 → calibration에서 정한 온도로 softmax
 → 합성 유형 예측과 생성 정답 비교
```

합성 내부 입력은 `parts`라는 부분선별 좌표 배열을 가진 레코드다. 실제 CSV의 `geom` 문자열을 그대로 이 모델에 넣을 수 있는 것은 아니다. 실제자료에는 별도 CSV 해석, WKT 검사, 좌표·시간·라벨 계약 확인과 변환 절차가 필요하다. 해당 절차는 10장의 계획이며 이번 개정에서 실행하지 않았다.

| 단계 | 합성 실험의 입력과 출력 | 학습자가 설명할 핵심 |
| --- | --- | --- |
| 자료 생성·검증 | `local_xy_m` 좌표와 생성 정답 → 검증된 레코드 | 가정한 미터 좌표와 실제자료 CRS 확인은 다른 작업이다. |
| 특징 계산 | `parts` → 아홉 특징, 레코드 유효 여부 | 부분선 사이에 없는 선분을 만들지 않는다. |
| 전처리 | 아홉 특징 → 18차원 입력 | 대치한 숫자와 원래 결측 여부를 함께 전달한다. |
| 추론 | 18개 입력 → 세 logits → 세 확률 | 출력의 세 유형은 합성 생성기의 정의를 따른다. |
| 평가·진단 | 생성 정답·확률 → F1, NLL, 실패 사례 | 맞힌 비율과 확률의 품질을 따로 살핀다. |

실제자료의 분류 클래스 수는 라벨 설명과 분포를 확인한 뒤 정한다. 합성 모델의 세 출력 노드를 실제자료에 맞는 확정 구조라고 보지 않는다. 실제 속력·가속도·체류시간은 유효한 공간 단위와 점별 시각이 확보되어야 검토할 수 있다.

이 장의 확인 질문: “현재 모델이 받은 것은 실제 선박의 운동 상태인가, 명시적으로 생성한 경로 형상의 요약인가?” 입력의 출처를 설명할 수 있어야 출력의 의미도 설명할 수 있다.

## 2. 데이터가 만들어지는 방법과 실제자료를 읽는 순서

합성 실험에서는 생성기가 경로와 정답을 함께 만든다. `data_seed`는 생성 경로·관측점·교란 조건의 무작위성을 통제하고, `init_seed`는 가중치 초기화를 통제한다. 두 seed를 바꾼 결과를 같은 종류의 반복이라고 합치면 데이터 변화와 학습 시작점 변화의 영향을 구분하기 어렵다.

합성 레코드에는 `sample_id`, `vessel_id`, `split`, `label`, `parts`, `sim_times`, `scenario`, `quality`가 있다. `sim_times`는 가상 시각이며, `shape9` 특징값에는 사용하지 않는다. 합성 `vessel_id`와 실제 CSV의 `rfid_id`가 같은 의미와 지속성을 가진다고 자동 가정하지 않는다.

부분선은 한 항적 안에서 경계가 있는 좌표 묶음이다. `MultiLineString`은 여러 부분선을 표현할 수 있다. 경계가 신호 단절인지, 집계 방식인지, 원자료 제작 정책인지 실제자료에서 확인해야 한다. 관측되지 않은 경계를 이동 선분으로 연결하지 않는 원칙은 원인이 미확정인 동안에도 유지한다.

합성 실험의 분할은 다음 역할을 가진다.

| 분할 | 허용되는 역할 | 제외되는 역할 |
| --- | --- | --- |
| train | 전처리 통계·모델 가중치 적합 | 최종 평가 자료를 통계에 섞기 |
| validation | epoch·후보 등 사전에 정한 선택 | 가중치 학습용으로 무단 합치기 |
| calibration | 예측 점수의 온도 보정 | test·stress에서 온도 재조정 |
| test | 고정한 절차의 보통 조건 평가 | 결과를 보고 같은 자료에 맞춰 재선택 |
| stress | 정해 둔 조건 변화 평가 | 어려운 사례를 임의 제외해 성능 교체 |

기존 합성 검증기는 동일 `vessel_id`가 여러 분할에 나타나지 않도록 검사한다. 실제자료에서도 선박 ID의 지속성과 예측 대상 시점을 확인한 뒤 선박 분리·시간 가용성 조건을 적용해야 한다. 단순한 행 무작위 분할은 같은 선박과 중복 경로가 양쪽에 들어가 성능을 부풀릴 수 있다. 반대로 미래 시점 예측이 목적이면 선박 분리만으로 시간 누수까지 해결되지는 않는다.

월별 파일이라는 사실만으로 학습·검증·최종 평가 구성을 확정하지 않는다. 공식 분할과 제출 규칙을 먼저 대조하고, 없으면 목적에 맞는 분할 근거를 기록한다. 중복 후보도 같은 날짜·ID·시간대라는 이유만으로 삭제하지 않는다. 한 키에 여러 유효 항적이 있는지, 수정본인지, 반복 관측인지 확인해야 한다.

이 장의 확인 질문: “같은 항적을 두 초기화 모델로 평가한 두 행은 독립 항적 두 건인가?” 모델 실행 수, 고유 항적 수, 선박 그룹 수, 데이터 생성 seed 수를 구분한다.

## 3. 모델 입력: 항적을 아홉 숫자로 바꾸는 과정

`shape9`는 기존 `original8`에서 전체 길이 로그 한 개를 제외한 일곱 특징에, 전체 관측점 집합의 특징 두 개를 더한다. 실제 순서는 `iteration_features.py`와 저장 JSON의 `feature_names`에 일치한다. 거리·면적·고유값 두 개·점 수·부분선 수를 나열한 기존 보고서의 표는 이 구현의 `shape9` 명세가 아니다.

부분선 `j`의 내부 인접점 거리 합을 `L_j`, 그 부분선의 처음·끝 거리를 `D_j`라 하자. 양의 길이를 가진 부분선만 직선성 등의 평균 대상이 된다. 방향 변화각 `δ`는 같은 부분선의 연속된 영이 아닌 선분 사이에서 `atan2(cross,dot)`로 계산한다. 부분선 경계를 넘는 방향각은 만들지 않는다.

| 순서 | 코드의 특징 이름 | 계산과 해석 | 단위·결측 조건 |
| --- | --- | --- | --- |
| 1 | `mean_part_straightness` | 양의 길이 부분선별 `D_j/L_j`의 단순 평균. 길이 가중 평균이 아니다. | 무차원. 유효 부분선에서는 0~1 범위이며 부동소수점 오차를 고려한다. |
| 2 | `mean_abs_turn_rad` | 사용 가능한 부분선 내부 회전각들의 `mean(abs(δ))` | rad. 회전각이 하나도 없으면 결측 |
| 3 | `turn_direction_concentration` | `abs(sum(δ))/sum(abs(δ))`. 같은 방향 회전이 우세할수록 크다. | 무차원. 각도가 있지만 모두 0이면 0, 각도 자체가 없으면 결측 |
| 4 | `std_turn_rad` | 부호 있는 회전각 `δ`의 모집단 표준편차 | rad. 회전각이 없으면 결측 |
| 5 | `max_abs_turn_rad` | `max(abs(δ))` | rad. 회전각이 없으면 결측 |
| 6 | `mean_part_spread_ratio` | 부분선 점 공분산의 `sqrt(λ_min/λ_max)`를 구한 뒤 유효 부분선 평균 | 무차원. 선 모양은 0에 가깝고 두 방향으로 퍼질수록 커진다. |
| 7 | `mean_part_chord_deviation_ratio` | 부분선 처음·끝을 지나는 직선에서 점들의 최대 수직거리 / `L_j`를 구한 뒤 계산 가능한 부분선 평균 | 무차원. 닫힌 부분선처럼 `D_j=0`이면 그 부분선 값은 결측, 가능한 부분선이 없으면 최종 결측 |
| 8 | `cloud_spread_ratio` | 모든 관측점 집합의 공분산에서 `sqrt(λ_min/λ_max)` | 무차원. 점 집합의 퍼짐이 0이면 결측 |
| 9 | `cloud_radial_fourth_moment_ratio` | 점 집합 중심에서 제곱거리 `r²`를 구해 `mean(r⁴)/mean(r²)²` | 무차원. 중심 거리의 2차 모멘트가 0이면 결측 |

마지막 두 값은 좌표들을 점 집합으로 모아 계산한다. 점을 모으는 것과 이동 선분을 잇는 것은 다르다. 이 계산은 경계 사이 거리나 속력을 더하지 않는다. 같은 위치를 여러 번 관측한 점도 집합 통계에 반영되므로, 관측 밀도와 누락이 특징에 미치는 영향은 검토 대상이다.

직선성을 전체 처음·끝 거리로 계산하면 단절 항적에서 잘못된 범위가 생길 수 있다. 설명용 평면 좌표 `MULTILINESTRING ((0 0,1 0),(100 0,101 0))`은 관측 길이 합 2, 전체 처음·끝 거리 101이므로 잘못된 전체 비율은 50.5다. 현재 구현은 두 부분선 각각의 비율 1을 평균해 1을 얻는다. 관측되지 않은 99 길이를 더하거나 50.5를 임의로 1로 잘라 문제를 감추지 않는다.

`extract_features`는 양의 길이 부분선이 하나도 없으면 `valid=False`, 사유 `no_positive_length_parts`를 반환한다. 이는 일부 회전 특징만 결측인 유효 항적과 다른 상태다. `feature_matrix(...,'shape9')`는 무효 항적을 아홉 개 NaN 행으로 표시하지만 호출자가 기존 유효성 마스크를 유지해야 한다. 이 NaN 행을 대치할 수 있다는 이유로 유효한 분류 대상으로 바꾸면 안 된다.

점 수와 부분선 수는 품질 진단에 도움이 되지만 이 `shape9` 모델의 입력 특징은 아니다. 원래 길이 특징을 뺐다고 좌표계 검증이 불필요해지는 것도 아니다. 경도·위도의 도 단위를 평면 XY로 잘못 취급하면 각도·공분산 비율·형상도 왜곡될 수 있다.

전처리 입력을 `f∈R⁹`라 할 때, `Preprocessor.transform`은 먼저 `m_j=isnan(f_j)`를 계산한다. train에서 저장한 중앙값으로 NaN을 채우고, train 평균·표준편차로 표준화한 뒤 다음 순서로 붙인다.

`x = [scaled_feature_1, …, scaled_feature_9, mask_1, …, mask_9]`

따라서 입력은 `9+9=18`차원이다. 결측이 발생해도 마스크를 0으로 강제하는 구현이 아니다. 다만 특정 합성 자료에서 결측이 전혀 없으면 결과 마스크가 모두 0이 된다. “정책적으로 0 고정”과 “관측상 모두 0”은 구분해야 한다.

train에서 한 열이 모두 결측이면 중앙값·평균 0, scale 1을 사용한다. 일정한 열도 scale 1을 사용한다. `transform`은 통계를 다시 적합하지 않는다. 값이 무한대이거나 변환 중 overflow가 나면 예외를 낸다. 일반 전처리 객체가 모든 결측 패턴의 예측 유보를 보장하는 것은 아니므로, 레코드 유효성·미관측 결측·입력 분포 판단은 별도로 확인한다.

이 장의 확인 질문: “두 점만 있는 양의 길이 부분선은 전체 무효인가?” 직선성은 계산할 수 있지만 회전각이 없어 일부 특징이 결측일 수 있다. 전부 무효와 부분 결측을 구분한다.

## 4. shape9 MLP의 내부 구조

이 보고서의 구체적 예시 모델은 `outputs/iterative_models_20261026/models/shape9_mlp_d9101_i42.json`이다. 이 파일은 `source_type='synthetic'`, `coordinate_system='local_xy_m'`와 세 합성 클래스 이름을 기록한다. PyTorch의 `.pt` 파일을 가정할 필요가 없다.

현재 NumPy 구현은 행을 표본으로 놓는다. `X`의 크기가 `(N,18)`이면 순전파는 다음과 같다.

```text
H = tanh(X @ W1 + b1)       W1: (18,16), b1: (16,)
Z = H @ W2 + b2             W2: (16,3),  b2: (3,)
P = softmax(Z / temperature)
```

활성화 함수는 이 모델에서 **tanh**다. “tanh 또는 ReLU”라고 미정으로 설명하지 않는다. 가중치의 값과 부호가 특징들의 조합을 출력 점수에 연결하며, 편향은 입력이 0일 때의 기본 이동량을 제공한다. 은닉 노드를 특정 행동을 감지하는 전용 장치로 단정하려면 별도 분석이 필요하다.

파라미터 수는 `(18×16+16)+(16×3+3)=304+51=355`다. 현재 JSON의 `W1`은 `(18,16)`으로 저장된다. `(16,18)`을 필수 검사값으로 쓰면 구현과 충돌한다. 배열 방향은 사용하는 연산 규약과 함께 읽어야 한다.

softmax는 각 클래스 점수를 합이 1인 분포로 바꾼다. 현재 구현은 각 행의 최댓값을 먼저 빼고 양의 온도로 나누어 지수 계산을 한다. 공통 상수를 더해도 확률은 바뀌지 않는다. 이 안정화가 모든 극단 차이에서 0 확률 발생을 완전히 막는 것은 아니다.

예측 클래스는 가장 큰 확률의 위치다. 세 값의 합이 1이라는 성질만으로 현실 빈도와 일치하는 확률 보정이 성립하지는 않는다. 특히 이 모델의 출력은 실제 사고 확률이 아니다.

이 장의 확인 질문: “입력 차원이 늘었는데 기존 모델 파일을 그대로 사용할 수 있는가?” 특징 이름·순서와 전처리 통계·가중치 크기가 함께 맞아야 한다.

## 5. 모델은 어떻게 배우는가?

학습은 train의 입력과 생성 정답 사이 NLL을 줄이는 방향으로 가중치를 수정하는 과정이다. 현재 기본 `Classifier`는 NumPy의 full-batch 경사하강법을 사용한다. 한 epoch에서 전체 유효 train 표본의 gradient를 계산해 한 번 갱신한다. 미니배치 순서 변화가 이 구현의 핵심 무작위성인 것처럼 설명하지 않는다.

L2가 있으면 목적함수는 `mean NLL + λ/2 × sum(W²)`다. 가중치에는 벌점이 붙고 편향에는 붙지 않는다. `validation`의 보정 전 NLL이 가장 낮은 epoch를 저장하며, patience 동안 개선이 없으면 멈추고 최적 가중치를 복원한다. 학습 NLL과 L2가 포함된 목적함수는 별도 값이다.

직접 읽은 예시 JSON의 설정과 이력은 다음과 같다.

| 항목 | 저장값 |
| --- | --- |
| 데이터 생성 seed / 초기화 seed | 9101 / 42 |
| 은닉 노드 / L2 | 16 / **0.0** |
| 학습률 / epoch 한도 / patience | 0.03 / 400 / 35 |
| 기록된 epoch / 선택 epoch | 400 / 400 |
| train NLL, 1→400 epoch | 1.006129 → 0.299169 |
| validation NLL, 1→400 epoch | 1.010059 → 0.365201 |

이 실행은 400 epoch 한도에서 끝났고, validation으로 400번째 가중치를 선택했다. 학습 손실만 존재하는 상태가 아니다. 기존 감사 기록에서는 두 NLL이 모두 지속 감소했다고 보고했다. 다만 이것만으로 전역 최적점, 과소적합, 1200 epoch 이후 개선, 실제자료 일반화 중 어느 것도 확정할 수 없다.

결측 마스크가 train에서 계속 0이면 그 연결의 데이터 gradient는 `δ×0=0`이다. L2가 있으면 가중치는 벌점 때문에 줄어들 수 있으나, 이 예시 모델은 L2=0이다. 기존 단일 모델 감사에서는 해당 마스크 연결 가중치가 초기값과 동일함을 확인했다. 이는 마스크가 0인 학습 입력에 그 연결이 기여하지 않았다는 뜻이다. 실제 결측 입력을 안전하게 처리하는 규칙을 학습했다는 뜻은 아니다.

기존 감사의 인공 NaN 개입에서는 미학습 mask=1 경로가 예측을 바꿀 수 있음을 관찰했다. 이 결과는 코드 수준의 위험 가설을 뒷받침하지만 실제자료에서 결측 발생률이나 오분류율을 측정한 것은 아니다. 실제 결측 원인과 조합을 확인한 뒤 대응을 정해야 한다.

이 장의 확인 질문: “validation이 계속 좋아져도 stress NLL은 나빠질 수 있는가?” 자료 조건과 선택 지표가 다르므로 가능하다. 8장의 실제 저장 합성 비교에서 두 지표를 함께 읽는다.

## 6. 항적 한 건을 끝까지 추적

이 장의 첫 사례는 **설명용 가상 평면 좌표**다. 실제 선박 ID나 `fishing_code`를 부여하지 않는다. 한 부분선 `[(0,0),(3,0),(3,4)]`와 로컬 평면 좌표라는 가정을 둔다.

1. 관측 선분 길이는 3과 4이므로 부분선 길이는 7이다.

## 7. 평가 지표를 읽는 방법

정확도는 유효 정답 중 맞힌 비율이다. Macro F1은 각 클래스의 정밀도·재현율을 결합한 F1을 클래스별로 계산한 뒤 평균한다. 현재 구현에서는 해당 평가에 없는 클래스도 F1=0으로 평균에 들어간다. 실제자료에서는 공식 지표가 이 정의와 같은지도 확인해야 한다.

혼동행렬은 정답을 행, 예측을 열로 놓는다. 클래스별 정답 수인 support와 함께 읽으면 특정 클래스에서 실패가 몰리는지 볼 수 있다. 실제 클래스 정의가 미확정이면 합성 세 클래스 표를 그대로 평가 표준으로 옮기지 않는다.

NLL은 정답에 부여한 확률 `p_y`의 `-log(p_y)`를 평균한다. `p_y=0.1`이면 약 2.3026, `10⁻⁵`이면 약 11.5129다. 한 행의 큰 손실이 전체 평균에 얼마나 영향을 미치는지는 **손실 크기와 전체 분모**가 함께 결정한다. 큰 손실 한 개가 항상 수백 행의 평균을 압도하는 것은 아니다.

NLL은 정답 확률 분포를 평가하는 proper scoring rule의 한 예다. NLL만을 순수한 calibration 측정값으로 동일시하지 않는다. Brier score, 신뢰도 구간별 실제 빈도, 클래스별 오차와 함께 해석할 수 있다. 현재 다중클래스 Brier 구현은 `sum((p-one_hot(y))²)`의 표본 평균이며 클래스 수로 다시 나누지 않는다.

온도 보정은 logits를 양의 `T`로 나눈다. `T>1`이면 부드러워지고 `T<1`이면 뾰족해진다. 같은 양의 온도를 모든 클래스에 쓰면 argmax 순서는 유지된다. 현재 구현은 별도 calibration 자료의 NLL로 0.1~10의 81개 기하 간격 후보와 기준값을 비교한다.

예시 단일 모델의 저장 온도는 `0.707945784384138`이다. 기존 감사에 기록된 NLL은 아래와 같다. 이번 개정에서 다시 모델을 실행한 값은 아니다.

| 합성 분할 | 보정 전 NLL | 보정 후 NLL |
| --- | ---: | ---: |
| calibration | 0.357145 | 0.336594 |
| test | 0.292127 | 0.255712 |
| stress | 0.740719 | 0.830287 |

보통 조건 test에서는 개선됐지만 조건 변화에서는 악화했다. `T<1`이 학습 미완료를 증명하거나 모든 조건의 확률 품질을 보장하지 않는다. stress 결과를 보고 온도를 다시 맞추면 해당 stress는 독립 최종 평가의 역할을 잃는다.

이 장의 확인 질문: “F1은 올랐는데 NLL도 오를 수 있는가?” 클래스 선택의 성공과 정답 확률의 품질은 서로 다른 측면이다.

이 표에서 선형 모델은 기존 MLP보다 조건 변화 F1과 NLL이 좋았지만, 다중비교 보정 없는 사전 지정 보조 비교다. 가장 높은 숫자만 골라 통계적 우위를 확정하거나 이 결과로 모델을 다시 채택하지 않았다. L2 강화 MLP가 모든 확률 문제를 해결했다는 결론도 성립하지 않는다. 해당 설정들의 stress NLL은 기존 400 epoch 모델보다 높았다.

시간·속력 후보는 합성 시각을 사용한다. 해당 생성기의 단일 시간 간격, 크기·잡음·단절 조건에서 나온 결과로 실제 관측 시계열의 유용성을 부정하지 않는다. 보폭 대조군과 Δt 대조군을 함께 두면 어떤 정보가 추가됐는지 분석하는 데 도움이 되지만 인과 원인은 추가 통제 없이 확정하지 않는다.

각 후보·분할의 저장 예측은 `10 data seeds×2 initializations×144 rows=2,880`행이다. 두 초기화가 같은 원자료를 평가했으므로 2,880개의 독립 항적이나 독립 사건으로 간주하지 않는다. 실험의 비교 단위와 고유 항적 단위를 따로 기록한다.

이 장의 확인 질문: “선형 모델의 숫자가 가장 좋으니 실제자료에서도 바로 채택할 수 있는가?” 합성 생성기·후보 비교 범위와 실제자료 계약을 구분해 답한다.

## 9. 후사 진단: 숫자와 원인을 구분하기

ExtraTrees의 합성 최종 조건 변화 예측에는 정답 확률이 정확히 0으로 저장된 행이 4개 있다. 후사 JSON은 고유 항적 3개를 기록하고, 원래 보정 전 행별 확률은 저장되지 않았다는 한계를 명시한다. 따라서 트리의 원래 0 출력, 확률 clipping, 온도 변환, 지수 연산 underflow 중 무엇이 주원인인지 저장 보정 확률만으로 확정할 수 없다.

원문 보고서의 `ε=10⁻¹⁵`와 평균 NLL 9.52 설명은 교정이 필요하다. 그 **가정 그대로** 계산하면 0 한 행 손실은 약 34.5388, 네 행이 전체 2,880행 평균에 기여하는 값은 다음과 같다.

`4×(-log(10⁻¹⁵))/2880 ≈ 0.0479705`

이것만으로 전체 평균 9.52를 설명할 수 없다. 더구나 현재 `classification_metrics`와 후사 진단 코드는 실제로 `np.finfo(np.float64).tiny≈2.2250738585072014×10⁻³⁰⁸`을 하한으로 사용한다. 이 실제 규칙에서 한 0확률 행의 NLL은 약 708.3964이고, 네 행의 전체 평균 기여는 약 **0.9838839**다.

| 같은 ExtraTrees stress 자료의 범위 | 값 | 해석 |
| --- | ---: | --- |
| 전체 2,880 예측행의 보정 후 평균 NLL | **1.8180717** | 기존 공식 비교의 전체 분모 |
| 정답 확률 0인 4행의 평균 NLL 기여 | **0.9838839** | 실제 tiny 규칙에서 전체 평균 손실의 약 54.12% |
| 그 4행만 제외한 2,876행 평균 NLL | 약 **0.8353480** | 동일 저장 결과에서 계산한 후사 참고값. 공식 성능을 대체하지 않음 |

후사 JSON에 등장하는 `9.5265959` 같은 단일 사례 손실과 ExtraTrees 전체 평균을 혼동하지 않는다. 분모, 후보, 분할, 보정 여부, 수치 하한을 같이 표기해야 숫자의 의미가 보존된다. 확률 하한을 바꾸면 지표의 수치도 바뀌므로 알고리즘 자체의 우열과 평가 수치 규칙을 분리해 본다.

선형 모델과 MLP의 logits도 절댓값만으로 비교하지 않는다. `softmax(z)=softmax(z+c)`이므로 양수 확률에서 복원할 수 있는 것은 공통 이동량을 제외한 차이다. 중심화 logits의 차이를 살펴볼 수 있어도 “절대 logits가 작아서 우수하다”는 인과 결론은 나오지 않는다.

실패를 좁히는 순서는 원자료·계약·전처리·모델·표시 계층이다. 예컨대 확률 0이 보이면 저장 전·후 확률, 온도, 자료형과 연산을 확인한다. 모델을 바꾸거나 어려운 행을 삭제하는 것은 원인 확인의 대체 수단이 아니다.

이 장의 확인 질문: “극단 행을 뺀 값이 더 좋으면 어떤 이름으로 제시해야 하는가?” 전체 분모의 공식 평가와 구분한 후사 진단값이며 제외 기준과 남은 분모를 함께 적는다.

## 10. 현재 모델의 한계와 실제자료 처리 계획

이번 개정의 기술적 산출물은 최신 보고서다. 실제자료 처리의 다음 단계는 계획으로 남아 있다. 현 시점에는 12개 CSV가 확보됐다는 사실과 헤더 구조를 확인했으며, 전체 내용의 적합성 관문을 통과하지 않았다. 과거의 “실제 파일이 없다”는 설명도 현재 목록 상태에는 맞지 않는다.

먼저 원본을 보존하고, 읽은 범위와 확인 수준이 남는 작은 검사부터 진행한다. 파일 규모가 약 11.83 GB이므로 전체를 한 번에 메모리로 읽는 방식을 기본값으로 삼지 않는다. 결과는 별도 경로에 두고 각 파생 자료가 어느 원본·버전·검사 규칙에서 나왔는지 추적한다.

| 순서 | 예정 작업과 구현물 | 관찰·검증할 것 | 아직 확정하지 않는 것 |
| --- | --- | --- | --- |
| 1. 원본 식별 | 경로·크기·수정시각·파일 역할 목록, 필요 시 체크섬을 포함한 manifest | 대상 12개와 부속 파일 목록, 검사 일시·범위가 재현되는가 | 원본 수정·덮어쓰기, 파일명만으로 정식 평가 역할 판단 |
| 2. CSV 읽기 계약 | 제한된 표본을 청크로 읽어 인코딩·구분자·인용·컬럼 수 진단 | WKT 안 쉼표와 인용된 줄바꿈을 올바르게 처리하는가. 실패 위치·개수는 남기는가 | 오류 행을 조용히 건너뛰기, 물리 줄 수를 데이터 행 수로 확정 |
| 3. 빈 헤더 확인 | 4월·6월의 추가 열을 원래 열 위치와 함께 조사 | 빈 헤더 열이 본문에서도 전부 비어 있는가, 비어 있지 않은 값이 있는가 | 이름 없는 열을 본문 확인 전에 삭제 |
| 4. 전량 구조 검사 | 검증된 읽기 방식으로 청크별 행 수·열 수·결측·파싱 실패·값 분포 집계 | 표본 검사와 전량 검사를 별도 기록하고 총계가 맞는가 | 표본의 정상 상태를 전체 통과로 확대 |
| 5. 키·중복 점검 | 원본 파일·레코드 위치와 식별 필드를 보존한 중복 후보표 | 완전 동일 행, 동일 키·다른 geom, 월간·파일간 중복이 어떤 관계인가 | `(part_dt,rfid_id,rfid_time)`만으로 유일 키 확정 또는 일괄 제거 |
| 6. WKT·부분선 | 타입·파싱·비유한 좌표·빈 기하·짧은 부분선·반복점·점 수·부분선 수 집계 | 관측 경계가 유지되는가. 실패를 레코드와 연결할 수 있는가 | 경계 연결, 닫힌 경로·정지 후보를 임의 정상화 |
| 7. CRS 확인 | 제공 설명과 좌표 해석을 대조한 좌표 계약 | 좌표 순서·단위·원점·투영과 변환 범위가 근거로 확인되는가 | 좌표 범위만 보고 EPSG 확정, 도 단위 거리·각도 직접 계산 |

| 10. 분할·특징 범위 | 목적·공식 규칙·선박/시간 조건에 근거한 분할 계약 | 동일·유사 항적, 선박, 미래 정보가 부적절하게 섞이지 않는가 | 테스트를 보고 후보·임계값·전처리 선택 |
| 11. train 전용 변환 | 허용된 실제 특징과 train 통계·버전을 저장한 전처리 산출물 | 대치·표준화·특징 선택이 train에서만 적합되는가. 평가 미관측 결측은 어떻게 기록하는가 | 전체 데이터 fit, 합성 통계를 실제자료의 적합한 통계로 간주 |

체크섬 계산도 원본 전체 읽기와 시간이 필요하므로 검사 로그에 구분한다. 이번 개정에서는 새 전체 체크섬이나 전체 행 수를 산출하지 않았다. 청크의 크기는 사용 메모리와 레코드 크기를 보고 정하며 현재 특정 성능·소요시간을 약속하지 않는다.

CRS와 시간 계약이 확인되면, 먼저 소량의 실제 경로에서 부분선 보존과 허용된 기하 계산을 검증할 수 있다. 점별 시각이 없다고 확인된 경우에는 속력 없이 기하만 검증한다. 조업 분류의 학습·평가는 라벨 의미와 분할 계약이 추가로 필요하다. 실제자료용 파서가 합성 레코드 검증기의 `label∈{0,1,2}` 조건에 맞도록 원자료를 억지로 바꾸지 않는다.

사고현황 XLSX에 이름이 없다는 이유로 해당 선박·시간대를 정상이라고 표시하지 않는다. 미기재는 수집 범위·기간·식별자·사건 정의가 확인되지 않은 상태다. 조업 라벨, 기하학적 특이성, 사고 정답은 별도 의미다. 합성 stress의 큰 변동도 사고 정답이 아니다.

| 현 단계의 경계 | 필요한 증거 | 설명할 수 있어야 할 질문 |
| --- | --- | --- |
| 구조 확인 → 실제 기하 | 대표/전체 검사 범위, WKT·좌표·시간 계약, 단절 보존 | 왜 지금 계산한 길이·형상이 유효한가? |
| 기하 확인 → 분류 기준선 | 라벨 사전·부여 단위·분할·지표 계약 | 정답은 무엇이고 어떤 미래 자료로 평가하는가? |
| 분류 → 이상/사고 평가 | 정상 기준·사고 자료 범위·비용·운영 요구 | 특이한 모양과 사고를 어떻게 구분했는가? |

기술 완료와 학습 성취는 따로 확인한다. 검사기가 실행됐다는 기술 증거 외에, 학습자가 열 삭제·중복 보류·부분선 경계·CRS·분할의 이유를 설명하고 조건을 바꿨을 때 무엇이 달라지는지 판단할 수 있어야 한다. 학습자 수준·선수지식·시간·연산 자원은 여전히 미확인이다. 새 모델 계열·운영 임계값·외부자료·3D 확대 등의 결정은 근거가 확보된 뒤 해당 단계에서 다룬다.

## 11. 학습자를 위한 실습과 확인 질문

이번 문서는 읽기와 저장 결과 대조가 중심이다. 실제 CSV 전체 처리를 시작하기 전에 아래 항목을 코드·아티팩트에서 직접 찾아 설명한다. 새 학습이나 원본 수정은 이 보고서를 읽는 데 필요하지 않다.

| 점검 대상 | 찾아볼 실제 필드·연산 | 확인 목적 |
| --- | --- | --- |
| `iteration_features.py` | `_NAMES['shape9']`, `feature_names`, `feature_units` | 아홉 특징의 순서와 단위를 고정한다. |
| `features.py` | `extract_features`, `valid`, `reason`, `parts` | 부분선별 계산과 전체 무효·부분 결측의 차이를 확인한다. |
| `models.py` | `Preprocessor.fit/transform` | train 통계와 실제 NaN 마스크가 사용되는지 확인한다. |
| 예시 모델 JSON | `preprocessor`, `classifier.params`, `history`, `temperature` | 전처리·18×16 가중치·tanh 모델·400 epoch 선택·온도를 확인한다. |
| 비교 결과·후사 JSON | 후보명, 분할, 보정 여부, seed, 평가 분모 | 단일 실행·반복 평균·한 행 손실을 구분한다. |

이 프로젝트에서 해당 모델의 필수 저장물로 `scaler.pkl`, `model.pt`, `temperature.json`이 따로 있어야 한다고 가정하지 않는다. 예시 JSON 안에 전처리 통계·가중치·온도와 절차가 함께 있다. `feature_excludes`와 `training_procedure`를 읽으면 라벨·ID·분할·시각을 입력 특징에서 제외한 범위와 적합 역할을 확인할 수 있다.

다음 질문은 먼저 자신의 말로 답하고, 필요한 경우 괄호의 단서를 확인한다.

1. **shape9의 입력이 18개인 이유는?** (아홉 형상값과 원래 NaN 여부 아홉 개다. 점 수·부분선 수를 추가해 임의로 10특징을 만들지 않는다.)
2. **멀리 떨어진 두 직선 부분선의 직선성은 어떻게 계산하는가?** (각 부분선의 내부 길이·처음끝 거리 비율을 평균한다. 경계 사이 이동을 만들지 않는다.)
3. **양의 길이가 없는 항적과 회전각만 없는 항적은 같은가?** (전자는 레코드 무효, 후자는 유효하면서 일부 선택 특징 결측일 수 있다.)
4. **마스크가 모두 0이었던 학습에서 미래의 mask=1을 이해했다고 볼 수 있는가?** (실제 마스크는 생성되지만 그 입력 조건을 학습하지 않았을 수 있다.)
5. **355개 파라미터와 W1 크기는?** (`18×16+16+16×3+3=355`, 현재 NumPy 저장 방향은 `(18,16)`이다.)
6. **400 epoch에서 두 손실이 줄면 전역 수렴인가?** (저장 구간의 개선을 확인할 뿐 이후 최적점·새 조건 일반화는 추가 근거가 필요하다.)
7. **네 개 0확률 행의 평균 손실 기여는 왜 하한 규칙에 따라 달라지는가?** (`10⁻¹⁵` 가정이면 약 0.04797, 실제 float64 tiny 규칙이면 약 0.98388이다.)
8. **rfid_time이 있으면 실제 속력을 계산할 수 있는가?** (점별 시각과 좌표 단위·순서가 확인되어야 한다. 시간대 라벨만으로 충분하지 않다.)
9. **사고현황에 없으면 정상 정답인가?** (수집 범위와 사건 정의를 확인하기 전에는 미기재의 뜻을 확정할 수 없다.)
10. **전체 파일로 중앙값을 계산해도 되는가?** (평가 정보가 학습 변환에 들어간다. 적합은 train에서 하고 평가에는 저장 변환을 적용한다.)

기술 확인은 각 질문의 근거 위치를 찾고 계산을 대조하는 것이다. 학습 성취는 답안을 읽은 사실이 아니라, 다른 경로·단절·결측·분할 조건을 제시했을 때도 이유와 영향을 설명할 수 있는지로 확인한다.
