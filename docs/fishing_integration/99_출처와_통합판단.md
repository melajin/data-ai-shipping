# 출처와 통합 판단

이 노트는 어선 항적 과제 관련 PDF 세 편을 현재 프로젝트 문서와 함께 읽을 때 쓸 출처 경계와 기술적 정정 기준을 모은다. 핵심 기준은 관측된 형상과 추정한 운항 의미를 분리하고, 부분선을 보존하며, 사고시각이나 합성 이상점수를 실제 이상 라벨로 바꾸지 않는 것이다. PDF의 페이지 링크는 모두 실제 PDF 쪽수 `#page=N`을 가리킨다.

세 파일의 원본 위치, 크기, 해시는 [manifest.json](sources/manifest.json)에 기록되어 있다. P1은 표지에서 참가자 학습용 Claude 정리이며 주최측 공식 문서가 아니라고 밝힌다. P2와 P3도 각각 제안서 초안과 모델 설계안이며, 제안·가정·예시를 실험 결과로 제시하지 않는다. PDF가 인용한 공지 이미지, 참가신청서 HWP, 샘플 CSV는 이 프로젝트의 `data/raw`에 없다. 현재 그 폴더에는 `.gitkeep`만 있으므로 PDF에 적힌 10행 계산은 PDF 작성자의 분석 결과로 인용할 수 있지만 원 CSV로 재계산한 결과라고 쓰지 않는다.

P2는 실제 6쪽 중 마지막 쪽이 내부 인쇄 번호 `07/07`이고 `06/07` 표기는 없다. P3는 실제 26쪽 중 마지막 쪽이 `27/27`이며 `26/27` 표기는 없다. 인용은 혼동을 막기 위해 인쇄 쪽수가 아닌 실제 PDF 쪽수로 한다. 누락된 내부 번호에 해당하는 별도 내용은 확인된 자료에 없다.

## 자료별 페이지 안내

### P1 어선항적과제 이해가이드

1. [실제 1쪽](sources/어선항적과제_이해가이드.pdf#page=1)은 범위, 출처 종류, `공지·데이터·추론·제안` 표기 원칙을 설명한다. 이 문서 자체가 비공식 요약이라는 상태를 유지한다.
2. [실제 2쪽](sources/어선항적과제_이해가이드.pdf#page=2)은 조업형태 분류와 이상탐지의 과제 구분, Test A 신규 선박, Test B 사고시각 평가, 공식 지표·출력단위의 미확정을 요약한다. Test B에 정상과 사고 관련 항적이 있다는 설명은 정답 행별 정상/이상 라벨이 있다는 뜻이 아니다.
3. [실제 3쪽](sources/어선항적과제_이해가이드.pdf#page=3)은 행사 부문·일정·시상과 수요기관 추론을 다룬다. PDF는 당시 수요기관을 추론으로 표시했지만, [공식 AIDA 과제 상세 페이지](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004601/detail.do)는 2026-10-13 확인 시 과제명과 기관을 `해양경찰청`으로 표시한다. 기관 표기는 공식 확인됐지만, 특정 과제와 특정 기관상을 연결하는 주장은 여전히 확인되지 않았다.
4. [실제 4쪽](sources/어선항적과제_이해가이드.pdf#page=4)은 평가 형식, 신청서, 데이터 취급·개인정보·저작권 조건과 V-Pass 설명을 담는다. 규정은 HWP 요약으로 인용하고, 동의·서명이나 외부 데이터 이용 결정은 원문과 공식 제출 안내로 확인한다.
5. [실제 5쪽](sources/어선항적과제_이해가이드.pdf#page=5)은 특정 V-Pass 연구를 이 과제에 그대로 일반화하지 말라고 제한하면서 두 과제 파이프라인과 관측 계층을 제안한다. 신호 누락은 가능한 배경이지 이 데이터의 확인된 결측 원인은 아니다.
6. [실제 6쪽](sources/어선항적과제_이해가이드.pdf#page=6)은 컬럼, 10행 샘플, WKT MultiLineString을 설명한다. 샘플에 4개 라벨이 있다는 값은 전체 클래스 목록의 증거가 아니며, 공지의 “저인망”과 분류 그림의 4종 차이는 공식 목록 확인 항목이다.
7. [실제 7쪽](sources/어선항적과제_이해가이드.pdf#page=7)은 부분선 분리 원인을 가설로 들고 좌표 거리·정밀도·점별 시각 부재를 설명한다. EPSG:5179나 UTM 52N은 가능한 변환 예시이지 확인된 CRS가 아니다. 점 간 균등 간격으로 계산한 속력은 가정치다.
8. [실제 8쪽](sources/어선항적과제_이해가이드.pdf#page=8)은 샘플 10행의 거리·직선성·위치 표를 제시한다. 표의 누적거리는 부분선 사이 간격도 포함했다고 명시하므로 부분선 내부 길이와 같은 값으로 비교하지 않는다.
9. [실제 9쪽](sources/어선항적과제_이해가이드.pdf#page=9)은 10척 중 8척 정지, 좌표 흔들림, 중복 좌표, 예시 속력·조업행동 해석을 다룬다. “정지”, “포항”, “조업 행동”, 노트 값은 작은 한 시각대 샘플과 거리·시간 가정에 따른 추론이며 상태 라벨이나 실제 속력 측정이 아니다.
10. [실제 10쪽](sources/어선항적과제_이해가이드.pdf#page=10)은 조업형태 4종의 일반 설명과 기대 궤적, 신규 선박 일반화 문제를 다룬다. 업종별 항적 기대는 검증할 가설이다.
11. [실제 11쪽](sources/어선항적과제_이해가이드.pdf#page=11)은 선박 라벨과 시간 조각 입력의 차이, 제출 단위 불확실성, 위치·불균형 위험, 특징 목록과 처리 흐름을 제안한다. 같은 선박 라벨이 일정하다는 가정은 실제 Train에서 확인한다.
12. [실제 12쪽](sources/어선항적과제_이해가이드.pdf#page=12)은 기준 분류기·CNN 후보와 이상징후 후보·평가 난점을 설명한다. 사고가 적다는 이유로 이상점수를 실제 사고 분류 성능으로 부르지 않는다.
13. [실제 13쪽](sources/어선항적과제_이해가이드.pdf#page=13)은 규칙, 선박·업종 기준선, 학습형 탐지와 시간 평활 제안을 담는다. 통발 어선 B의 행동은 문서가 명시한 가상 시나리오다. 제출 표 예시와 “파일당 점수” 해석도 확정 스키마가 아니다.
14. [실제 14쪽](sources/어선항적과제_이해가이드.pdf#page=14)은 신청서·발표 설명 계획과 주최측 질문 목록을 정리한다. 출력 단위, 과제별 평가, 조기 탐지 창, Test B 이력, 클래스 목록, 외부 데이터 허용 등은 질문으로 남아 있다. 참가신청 기간은 [공식 AIDA 과제 페이지](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004601/detail.do)에서 별도로 확인되지만, 제출 횟수와 최종 결과물 마감은 구분해 확인해야 한다.
15. [실제 15쪽](sources/어선항적과제_이해가이드.pdf#page=15)은 2026-10-12 기준 일정, 용어와 문헌을 제공한다. D-25와 주차별 날짜는 당시 계획이므로 현재 일정으로 재사용하지 않는다. 공식 페이지의 참가신청 기간은 2026-09-15~2026-11-06이며, 이를 최종 결과물 마감으로 단정하지 않는다.
16. [실제 16쪽](sources/어선항적과제_이해가이드.pdf#page=16)은 CSV/WKT 파서와 특징 코드 초안을 싣는다. 예시 코드의 `np.vstack(parts)`는 부분선 경계를 잃고 인공 연결거리를 만든다. 본문 각주도 이 점을 경고하지만, 코드 결과를 그대로 채택하지 않는다. `Unnamed`로 시작하는 열을 모두 제거하는 부분도 의미 있는 열을 보존하는 최신 입력 처리 규칙과 맞지 않는다.

### P2 참가신청서 가이드와 제안서 통합본

1. [실제 1쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=1)은 제안 제목, 분류·이상점수의 후보, 문서 읽는 순서를 소개한다. 로지스틱·작은 LightGBM·강건 편차·IF는 계획 후보이며 경량 성능을 입증하지 않는다.
2. [실제 2쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=2)은 확인된 문제 설명, 미확정 평가·데이터 조건, 공식 신청 항목과 표현 원칙을 정리한다. 샘플 10행은 한 날짜·시간대의 10척이며 사고·점별 시각·연속 이력이 없다고 적는다.
3. [실제 3쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=3)은 신청서에 복사할 방법론·일정·예상 결과물의 초안이다. 부분선 보존, 신규 선박 검증, 사고시각과 이상 라벨 구분, 순간 속도·가속도·체류시간 미산출 조건은 통합 문안에 반영하기 좋다.
4. [실제 4쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=4)은 품질 확인, 분류 검증, 정상 후보, 시간순 평가, 경량화의 상세 근거다. 외부 자료와 개인/조업 기준은 데이터 이용 권한과 검증 향상이 확인될 때만 확장한다.
5. [실제 5쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=5)은 단계별 완료 조건과 필수·선택 결과를 분리한다. Q-learning은 핵심 분류·이상 기준보다 우수하다고 전제하지 않는 선택 실험이다.
6. [실제 6쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=6)은 제출 전 확인 항목, PDF가 의존한 S1-S5 출처, HWP의 개인정보 보유기간·데이터 폐기 등 규정 요약을 담는다. 공식 과제 페이지에는 HWP·샘플 CSV·수정 ZIP의 첨부 목록이 표시되지만, 실제 HWP가 프로젝트에 없어 규정 원문이나 서명·동의 내용을 이 PDF만으로 확정하지 않는다.

### P3 항적데이터 전처리와 모델설계 통합본

6. [실제 6쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=6)은 부분선 내부 길이와 길이가중 직선성 등 기본 특징 정의를 제안한다. 퇴화·2점 형상은 계산 불가와 0을 구분한다.
7. [실제 7쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=7)은 회전·방향·공간점유 특징과 표본화 예를 든다. 반복점은 체류시간이 아니며 표본화 간격은 정식 데이터 분포로 정한다.
8. [실제 8쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=8)은 전처리의 기대효과와 실패 사례, 한 요소씩 비교하는 실험 원칙을 제안한다. 외부 정보와 주변 선박은 허용 여부 확인이 선행한다.

## 현재 프로젝트의 합성 실험과 연결

S0는 사용자 요청으로 허용된 합성 교육 실험이며 PDF에 보고된 샘플 분석 및 후속 설계와 별도 관문이다. [샘플 시스템 계약](../sample_system_contract.md)은 합성 클래스가 `straight/sweep/turn` 생성 경로이며 공식 fishing_code가 아니라고 정의한다. [S0 검증 기록](../fishing_sample_verification.md)과 [학습 안내](../fishing_sample_system_guide.md)는 S0 점수·Mahalanobis 이상점수·stress를 실제 조업 분류나 사고 탐지 성능으로 부르지 않는다. 프로젝트 지침도 합성 `High` 변동을 사고 정답으로 취급하지 않도록 제한한다([AGENTS.md](../../AGENTS.md)). 이 세 PDF에는 `High` 사고 라벨 정의가 없으므로 그 생성 규칙이나 사고 의미를 덧붙이지 않는다. P3의 제안 모델(전역 IF/강건 편차)로 S0 Mahalanobis가 검증되었다고 쓰지 않는다.

## 확인된 출처와 미확인 경계

- P1-P3는 각각 포스터·공지 이미지·HWP·10행 CSV 또는 기술 문헌을 기초 자료로 열거한다. [공식 AIDA 과제 상세 페이지](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004601/detail.do)는 2026-10-13 확인 당시 과제명, 기관 표기, 참가신청 기간 `2026-09-15~2026-11-06`, HWP·샘플 CSV·수정 ZIP 첨부 목록을 표시했다. 이번에 전달받아 보관한 원자료는 PDF 세 편이며, 공지 이미지·HWP·샘플 CSV·수정 ZIP 원파일은 이번 검토 자료에 포함되지 않았다.
- 공식 페이지가 확인해 주는 것은 해당 페이지에 표시된 문제명·기관·참가신청 일정과 첨부 목록이다. 첨부 원파일 내용, 최종 결과물 제출 마감, 시간·좌표 계약, 전체 라벨 목록, 공식 평가 지표·출력 스키마, 특정 기관상 귀속은 미확인으로 남긴다.
- 기존 [실제자료 인벤토리·검증 기록](../fishing_verification.md)에 따르면 `data/raw`에는 `.gitkeep`만 있고 원자료 적합성 검사는 수행되지 않았다. PDF에 있는 샘플 수치와 S0 합성 수치는 서로 다른 출처·목적의 결과다.
- 이 검토에서 재현한 것은 PDF 물리 페이지 수, 페이지별 텍스트 내용, manifest SHA-256과 현재 로컬 원자료 폴더 상태다. 원 CSV의 WKT를 다시 파싱하거나 PDF의 성능·거리 수치를 독립 계산하지 않았다.

모델·effort 요청과 실제 실행 근거, 검증 상태는 [통합 검증 기록](통합_검증기록.md)에서 확인한다.
