# 항적 모델 평가와 실제자료 전환 계획

[통합 가이드](../../어선%20항적%20통합%20학습%20가이드.md) · [이전 모델과 현재 구현](03_모델과_현재구현.md) · [다음 제안서와 학습 활동](05_제안서와_학습활동.md)

모델 평가는 “어떤 표본에서 얼마나 맞았는가”에 더해 **무엇을 미리 알고 있었는가, 무엇을 독립된 사례로 셌는가**를 확인하는 일이다. 합성 코드의 정상 실행, 합성 경로 분류, 실제 어선 평가, 실제 장치 실험은 서로 다른 검증이다.

## 같은 선박이 양쪽에 있으면 생기는 문제

한 배의 1시 항적을 학습하고 같은 배의 2시 항적을 평가하면, 모델이 업종 일반 규칙 대신 위치·관측 정밀도·반복 패턴을 외울 수 있다. 신규 선박에 대한 질문에는 선박 단위 분리가 필요하다. ID를 입력에서 빼는 것과 데이터 분할에서 배를 분리하는 것은 둘 다 필요한 조건이다.

P3 11쪽은 그룹 분리와 클래스별 선박 수 확인을 제안한다. `StratifiedGroupKFold`도 그룹을 겹치지 않게 하면서 클래스 비율을 가능한 범위에서 유지하는 도구다. 데이터가 부족하면 원하는 균형을 보장하지 못한다. [공식 그룹 분할 문서](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.StratifiedGroupKFold.html)

PDF가 보고한 10행 샘플에서 통발과 채낚기연승낚시가 각각 한 척뿐이라면, 그 한 척을 학습에 넣을 때 해당 클래스의 신규 선박 평가는 없고 평가에 넣을 때 학습에 해당 클래스가 없다. fold 수를 줄이거나 같은 배의 행을 복제해도 독립 선박 부족이 해결되지 않는다.

## 다섯 분할의 책임

현재 프로젝트의 분할 규칙은 [S0 계약](../sample_system_contract.md)에 고정되어 있다.

| 분할 | 할 수 있는 일 | 섞으면 안 되는 일 |
| --- | --- | --- |
| train | 대체값·스케일·모델·공분산 적합 | test를 이용한 fit |
| validation | 후보·epoch·운영 임계값 선택 | 최종 독립 성능처럼 무조건 보고 |
| calibration | S0에서는 온도 보정만 적합 | 반복 모델 탐색이나 test 정답 사용 |
| test | 선택을 잠근 후 성능 산출 | 결과를 보고 후보를 다시 고르기 |
| stress | 사전 고정 조건 변화에서 결과 산출 | 관측 결과에 맞춰 조건을 바꿔 우수성을 주장 |

P3가 “별도 보정”에 임계값 선택까지 포함한 부분은 현재 프로젝트에서 **validation의 임계값 선택**과 **calibration의 확률 보정**으로 구분해 읽는다. 이름보다 실제로 어떤 자료를 어떤 선택에 사용했는지가 중요하다.

validation도 여러 번 보고 특징과 모델을 바꾸면 개발자가 그 자료에 적응한다. 후보 예산과 비교 목적을 미리 쓰고 개발 그룹 교차검증 또는 미사용 개발 그룹을 활용한다. 현재 test/stress를 보고 변경한 이후에는 그 결과를 완전히 손대지 않은 최종 평가처럼 계속 사용할 수 없다.

## 저장된 S0 결과 읽기

아래 값은 [report.json](../../outputs/sample_system/report.json)의 보정 후 `metrics`다. 이번 문서 통합에서 모델을 다시 학습한 수치가 아니다. 각 평가 분할은 12개 가상 그룹·144개 경로다.

| 지표 | Test | Stress | 해석 |
| --- | ---: | ---: | --- |
| 정확도 | 81.25% | 61.81% | 생성 경로 유형 정답을 맞힌 비율 |
| Macro F1 | 0.8104 | 0.6180 | 세 유형의 F1을 같은 가중치로 평균 |
| NLL | 0.4385 | 0.8802 | 정답에 부여한 확률의 손실, 작을수록 좋음 |
| Brier | 0.2564 | 0.4998 | 예측 확률과 one-hot의 제곱 차 합을 표본 평균 |
| 정확도 95% 구간 | 76.39~87.52% | 54.17~68.75% | 평가 분할 내 선박 bootstrap 200회 |
| 거리 임계값 초과율 | 1.39% | 38.19% | 분포 이탈 표시 비율, 사고 탐지율 아님 |

학습 클래스 비율을 출력하는 기준의 정확도는 33.33%, Macro F1은 0.1667이다. 클래스 비율이 같아 확률은 각각 1/3이고, 최대값 동률 처리에서는 한 클래스를 선택한다. 확률 기준과 최종 클래스 선택을 함께 해석해야 한다.

95% 구간은 해당 실행·생성기·평가 표본에 조건부인 불확실성 요약이다. 생성기 편향, 다른 학습 seed, 실제 해역의 변화까지 포함하는 보증 범위가 아니다.

## 혼동행렬로 오류를 설명하기

Test의 행은 실제 생성 유형이고 열은 예측 유형이다.

| 실제 / 예측 | straight | sweep | turn |
| --- | ---: | ---: | ---: |
| straight | 40 | 3 | 5 |
| sweep | 15 | 32 | 1 |
| turn | 1 | 2 | 45 |

정답은 대각선 합 $40+32+45=117$개여서 정확도는 $117/144=0.8125$다. sweep 48개 중 15개를 straight로 분류한 것이 눈에 띈다. 다음에 할 일은 잘못된 표본의 길이·굴곡·점 수·부분선 구조를 확인하여 어떤 가설을 비교할지 정하는 것이다. test에서 발견한 가설의 개선을 같은 test로 계속 입증하지 말고 개발 자료에서 비교한 뒤 새로운 평가를 준비한다.

## Stress 차이는 원인 실험과 다르다

현재 stress는 길이 배율 2.6, 잡음 배율 5, 점 누락 확률 0.24, 부분선 단절 확률 0.07을 함께 적용한다. test와 가상 선박 그룹도 다르다. 정확도가 19.44%p 낮아진 것은 관측된 비교 결과이지만, 어느 한 조건이 그 차이를 만들었다고 분해할 수 없다. 이 차이만으로 과적합을 확정할 수도 없다.

원인에 가까이 가려면 동일한 기본 경로와 난수 조건에서 한 요소만 바꾼 짝 실험을 설계한다. 예를 들어 길이는 유지하고 잡음만 바꾸는 실험을 반복하여 특징 변화와 오분류를 함께 기록한다. 그 다음 다른 seed·그룹에서도 방향이 유지되는지 확인한다.

저장된 60쌍 좌표 교란 실험은 한 중간점에 큰 좌표 변화를 가했을 때 거리 점수가 어떻게 반응하는지 확인한 검산이다. 사고 원인이 없는 합성 좌표 교란이므로 실제 사고 탐지 성공으로 계산하지 않는다.

## 이상 탐지에서 라벨을 정의하기

사고 발생시각은 사고 주변 모든 시간행에 정확한 이상/정상 정답을 주지 않는다. 사고 전 몇 시간에 약한 양성 라벨을 붙이는 방법은 가능하지만 창 길이·사고시각 오차·관측 커버리지에 따라 결과가 달라진다. 실제 이상구간 라벨과 구별하고 창 조건에 따른 민감도를 보고해야 한다. 근거는 [P3 16~18쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=16)이다.

사고가 기록되지 않았다는 이유만으로 모든 나머지 시간을 정상 정답으로 확정하지 않는다. “확인된 정상”, “비사고 기록 구간”, “판단 불가”를 구분한다. 합성의 High 변동이나 S0 stress도 사고 라벨로 바꾸지 않는다.

사고 3건에서 겹치는 시간창 300개를 만들었다면 독립 사고 수는 여전히 3건이다. 같은 사건의 창들이 학습과 평가에 나뉘지 않도록 관리하고, 행 수와 독립 선박·사건 수를 함께 보고한다.

## 지표는 분모까지 설명한다

P3 17쪽의 교육 예시는 정확한 이진 라벨이 있는 가상 1000행을 가정한다. TP=15, FP=30, FN=5, TN=950이다.

$$
\mathrm{Precision}=\frac{15}{45}=0.333,\quad
\mathrm{Recall}=\frac{15}{20}=0.75,\quad
F1=\frac{30}{30+30+5}\approx0.462
$$

정확도는 $(15+950)/1000=96.5\%$로 높지만 경보 45개 중 실제 이상은 15개다. 정확도 하나만으로 사고 관련 탐지 품질을 설명하기 어려운 이유다. 이 숫자는 실제 모델 성능이 아니다.

| 평가 값 | 분모·조건 | 잘못된 해석 |
| --- | --- | --- |
| 시간행 F1 | 정의된 행 단위 라벨 | 한 번 탐지한 사건의 모든 시간을 정답 처리 |
| 사건 사전 탐지율 | 관측 조건을 충족한 평가 가능 사건 | 관측 불가·미탐지 사건을 숨김 |
| 선행시간 | 사고시각 − 첫 유효 사전 경보 가용시각 | 데이터 수집 시작시각으로 앞당김 |
| 오경보 빈도 | 확인된 정상 관측시간과 경보 에피소드 | 정상 미확인 시간을 정상 정답으로 처리 |
| 비사고 기록 구간 경보 빈도 | 정상 여부 미확인인 관측 구간 | 확인된 오경보율로 바꿔 부름 |

정상으로 확인된 관측 200시간에서 경보 시작 5회라면 100시간당 2.5회다. 연속 경보를 한 에피소드로 묶는 규칙을 미리 정해야 한다. 관측시간은 실제 운항시간과 다르며 근거 없이 운항일당 비율로 바꾸지 않는다. AP와 PR 곡선의 사다리꼴 면적도 계산 정의가 다르므로 보고서에는 실제 사용한 함수·정의를 남긴다.

## 조기 탐지는 가용시각으로 계산한다

다음은 [P3 19쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=19)의 가정 예시다. 시간대가 `[h,h+1)`이고 데이터 전달과 계산 지연을 합쳐 5분이라고 가정한다.

| 정보 | 시각 | 판단 |
| --- | --- | --- |
| 사용한 항적 | 09:00~10:00 | 10:00 이전에는 전체가 완성되지 않음 |
| 경보 결과 가용 | 10:05 | 실제 경보 가능 시점 |
| 사고 | 10:20 | 선행시간 15분 |
| 다음 항적 결과 가용 | 11:05 | 10:00~11:00 전체 항적은 10:20 사고의 사전 탐지에 사용 불가 |

사고가 10:20에 발생했는데 10~11시 항적 전체를 써서 10:00부터 경보한 것처럼 계산하면 미래 정보 누수다. 실제 자료의 시간대·집계·전송·처리 지연이 확인되기 전에는 이 5분을 실제 시스템 수치로 쓰지 않는다.

사고시각이 시간 단위로만 알려졌다면 분 단위 선행시간을 정확히 안다고 보고할 수 없다. 가능한 범위나 시간대 단위 결과로 표시한다.

## 과거 이력과 미래 누수를 구별한다

현재 S0는 모든 분할에서 선박을 분리한다. P3 12쪽이 제안하는 “같은 선박의 과거로 그 선박의 미래 평가”는 별도의 실제 운영 시나리오다. 이 제안만으로 기존 전 분할 선박 분리 계약을 완화하지 않는다.

후속 F3에서 이력 사용이 허용된 시나리오를 결정한다면, 모델 적합 자료·설정 선택 자료·추론 때 유지하는 과거 상태를 구분한다. 현재 점수를 먼저 계산하고 이후에 기준을 갱신해야 한다. 현재 이상한 항적을 기준에 먼저 넣으면 자기 자신이 정상 기준을 바꿀 수 있다. 미래 보간, 중심 이동평균, 평가 전체 통계로 과거 정규화는 금지한다.

잠근 평가 후 전체 Train 재학습도 새로운 모델을 만드는 행위다. 이전 평가 점수는 이전 모델에 대한 근거이며 재학습 모델의 독립 평가 점수로 그대로 옮겨 적지 않는다.

## 실제자료 전환 관문

| 단계 | 기술 목표와 구현물 | 확인 방법 | 학습자가 설명할 질문 |
| --- | --- | --- | --- |
| S0 현재 | 합성 생성→학습→저장→재추론→표시 | 저장 근거와 재현 실행 | 왜 합성 성능이 실제 성능은 아닌가 |
| F1 실제자료 적합성 | 원본 식별·버전·해시·검사 범위와 데이터 계약 | 스키마·시간·좌표·부분선 대조, 라벨 설명·분포·충돌 및 미확인 항목 기록 | 무엇이 확인값이고 무엇이 가정인가 |
| F2 무라벨 기하 | 계약 통과 대표자료의 소량 기하 계산 | 단절·중복·빈 경로·단위 검산 | 왜 점별 시각 없이도 일부 기하는 가능한가 |
| F3 분류와 이상 기준선 | 확정 라벨·분할에 따른 최소 모델 | 독립 선박·시점·사건과 오류 분석 | 모델이 배우는 기준과 평가 질문이 일치하는가 |
| 후속 선택 확장 | 이력·환경·정책·3D 등 근거 있는 요소 | 추가 효과·비용·오류·시점 조건 비교 | 복잡성을 추가할 이유가 증명됐는가 |

F2에는 조업 라벨과 모델 평가 분할의 최종 확정이 필수 선행조건은 아니다. 대표 원자료의 핵심 시간·좌표·기하 계약이 먼저다. 반면 F3에는 라벨 의미와 평가 분할 근거가 필요하다. 이번 문서 통합은 관문 통과 기록을 새로 만드는 작업이 아니다.

## 후속 실험은 한 질문씩 만든다

| 질문 | 비교 예 | 채택 전에 확인할 것 |
| --- | --- | --- |
| 반복 압축이 도움이 되는가 | 같은 자료·분할·모델의 원본 vs 압축 | 짧은 움직임 손실, 품질 정보 보존 |
| 위치를 넣어도 일반화하는가 | 기하만 vs 절대 위치 추가 | 다른 해역·신규 선박 성능 |
| 비선형 모델이 필요한가 | 로지스틱 vs 작은 LightGBM | 희귀 클래스, 확률, CPU 비용 |
| 이상 기준이 다른 정보를 찾는가 | 강건 편차 vs 전역 IF | 정상 후보 오염, 점수 방향, 사건 반응 |
| 시간 평활이 유용한가 | 원시 점수 vs 과거만 쓰는 평활 | 경보 감소와 탐지 지연의 교환 |
| 개인 기준이 안전한가 | 전역 vs 허용된 과거 기준 | 초기 선박, 기준 오염, 현재 변화 숨김 |

이 후보들은 실행 계획을 위한 제안이다. 실제 비교는 해당 관문과 자료 조건을 충족한 뒤 수행한다. 임의 파일 크기 상한·CPU 시간 목표를 대회 규칙으로 쓰지 않으며, 같은 장비·스레드·배치 조건에서 특징 추출과 모델 추론을 나누어 측정한다.

강화학습은 상태·행동·보상·다음 상태와 비교 환경을 정의할 수 있을 때의 선택 실험이다. 현재 정적 CSV와 S0만으로 실제 항로 제어나 사고 예방 효과를 검증할 수 없다. 경보 replay 보상이 개선돼도 실제 사고가 줄었다는 결론으로 바꾸지 않는다.
