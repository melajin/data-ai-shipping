# 항적 데이터의 의미와 전처리 계산

[통합 가이드](../../어선%20항적%20통합%20학습%20가이드.md) · [이전 과제와 현재 상태](01_과제와_현재상태.md) · [다음 모델과 현재 구현](03_모델과_현재구현.md)

전처리는 모델에 넣기 편하도록 값을 바꾸는 작업에 앞서, **관측한 정보와 모르는 정보를 구별하는 작업**이다. 관측되지 않은 구간을 연결하거나 결측을 0으로 바꾸면 모델은 그 오류까지 사실처럼 학습한다.

## 한 행을 해석하는 계약

PDF의 설명을 바탕으로 아래 질문을 정리한다. 정식 파일과 데이터 사전을 직접 대조하기 전까지 실제 입력 계약은 잠정적이다. 근거는 [P1 6~7쪽](sources/어선항적과제_이해가이드.pdf#page=6), [P3 3~7쪽](sources/02_항적데이터_전처리와_모델설계_통합본.pdf#page=3)이다.

| 필드 | 설명에 따른 역할 | 실제자료에서 확인할 것 |
| --- | --- | --- |
| `part_dt` | 날짜 | 날짜 형식, 기준 시간대, 자정 경계 |
| `rfid_id` | 선박 식별자 | 문자열 유지, 익명화·중복·변경 여부 |
| `rfid_time` | 0~23 시간대 | 구간 시작/종료 의미, 집계 범위, 가용시각 |
| `geom` | WKT MultiLineString | 좌표계, XY 순서, 부분선과 좌표 순서의 의미 |
| `fishing_code` | Train의 조업 라벨 | 실제 코드 목록, 라벨이 붙는 단위, 변경·충돌 |

`rfid_id`는 분할과 연결에 쓰되 분류 입력에서 제외한다. 다만 ID를 빼는 것만으로 암기를 막을 수는 없다. 위치나 관측 정밀도가 특정 배를 대신 식별할 수 있기 때문에 선박 분리 검증이 필요하다.

원본 키·행 순서·파일 식별 정보를 보존한다. 빈 헤더처럼 보이는 열도 값이 모두 빈 것인지 확인한 뒤 처리한다. 사고 정보 등 추가 의미 컬럼을 알려진 5개 필드가 아니라는 이유로 삭제하지 않는다. PDF의 샘플 연도와 공지 예시 연도가 다르다는 이유로 날짜를 자동 수정하지 않는다.

## 좌표는 단위부터 확인한다

경도·위도는 각도 단위다. 좌표 차가 0.001이라고 해서 0.001m 이동한 것이 아니다. 실제자료에서는 CRS와 축 순서를 확인하고 지리 거리 계산이나 해당 해역에 적절한 미터 좌표계를 사용해야 한다. 좌표 숫자가 경도·위도 범위 안에 들어온다는 사실만으로 CRS가 확정되지는 않는다.

현재 S0는 `coordinate_system=local_xy_m`를 계약으로 고정한다. 다음 손계산은 실제 해역 좌표가 아닌 **교육용 평면 미터 예제**다.

## 부분선 사이를 연결하면 무엇이 잘못되는가

두 부분선이 있다고 하자.

```text
부분선 A: (0, 0) → (3, 4) → (6, 4)
부분선 B: (100, 100) → (100, 112)
단위: m
```

A의 길이는 $5+3=8$ m이고 B의 길이는 12 m다. 관측된 부분선 내부 길이의 합은 **20 m**다. A의 끝과 B의 시작 사이에는 관측된 연결이 없다.

두 배열을 평탄화해 인접점을 모두 이으면 다음 거리가 추가된다.

$$
\sqrt{(100-6)^2+(100-4)^2}=\sqrt{18052}\approx134.37\ \mathrm{m}
$$

잘못 연결한 전체 길이는 약 154.37 m가 된다. 이 추가 구간은 실제 이동거리로 사용하지 않는다. 연결 여부가 모르는 상태라는 정보를 보존해야 한다.

개념을 확인하는 최소 의사코드는 다음과 같다. 실제자료 로더나 완성된 전처리 파이프라인은 아니다.

```python
total_length = 0.0
for part in parts:
    # 거리와 각도는 이 part 내부에서만 계산한다.
    for start, end in zip(part[:-1], part[1:]):
        total_length += distance(start, end)
```

P1 8쪽은 일부 누적거리에 부분선 사이 간격을 포함한다고 명시하며, 16쪽 코드는 `np.vstack(parts)`로 경계를 없앤다. 이 계산을 현재 프로젝트의 관측 길이로 채택하지 않는다. P3 3쪽의 85.0m·132.5m는 선 내부 길이로 보고된 값이며, P1의 109m·149m와 계산 범위가 다르다. **이 수치는 두 PDF의 보고값 대조이고 이번에 원본 CSV로 재계산한 값은 아니다.**

## 길이와 변위와 직선성

부분선 $j$의 점을 $p_{j,0},\ldots,p_{j,n_j-1}$라 하면 다음과 같다.

$$
L_j=\sum_{i=1}^{n_j-1}\|p_{j,i}-p_{j,i-1}\|,\qquad
D_j=\|p_{j,n_j-1}-p_{j,0}\|
$$

길이 $L_j$는 관측한 경로를 따라 더한 값이고 변위의 크기 $D_j$는 그 부분선 양 끝의 직선거리다. $L_j>0$일 때 직선성은 $S_j=D_j/L_j$다. 평면 유클리드 거리에서는 0~1 범위이고, 경로가 돌아 나올수록 작은 값이 될 수 있다. 길이 0이면 $0/0$이므로 계산 불가로 둔다.

위 예제에서는 $S_A=\sqrt{52}/8\approx0.9014$, $S_B=1$이다. 현재 S0의 평균 부분선 직선성은 **유효 부분선의 단순 평균**이므로 약 0.9507이다.

P3 6쪽의 길이 가중 평균은 다음 식과 같다.

$$
\frac{\sum_j L_j S_j}{\sum_j L_j}=\frac{\sum_j D_j}{\sum_j L_j}
$$

이 식은 단순 평균과 다른 특징이며 예제에서는 약 0.9606이다. 수학적으로 정의 가능한 집계이지만, 현재 [S0 계약](../sample_system_contract.md)은 이 집계를 도입하지 않는다. PDF의 식으로 기존 코드 설명을 바꾸지 않는다. 실제자료에 다른 집계가 필요하면 그 의미·단절 수 민감도·검증 결과를 근거로 계약을 새로 정한다.

## 회전각은 시간당 회전율과 다르다

한 부분선 안의 연속한 유효 벡터 $u,v$에 대해 부호 있는 회전각을 다음처럼 계산한다.

$$
\theta=\operatorname{atan2}(u_xv_y-u_yv_x,\ u\cdot v)
$$

현재 코드는 라디안으로 계산한다. $\pi/2$ rad는 90도다. 영벡터는 방향이 없으므로 제외하며 부분선 끝과 다음 부분선 시작 사이의 각도는 만들지 않는다. 2점 부분선에는 벡터가 하나뿐이어서 회전각이 없다. 이를 “회전각 0”이라고 채우면 실제로 회전하지 않은 관측과 구분되지 않는다.

이 값은 좌표 순서에 따른 공간 굴곡이다. 점마다 시각이 없으면 90도를 얼마나 짧은 시간에 회전했는지 알 수 없다. 따라서 급선회 속도·각속도·가속도라는 이름으로 바꾸지 않는다.

## 반복 좌표는 형상과 품질을 나누어 읽는다

`A, A, A, B, C`라는 기록이 있으면 형상 계산용 경로는 `A, B, C`로 연속 반복을 압축할 수 있다. 원래 점 수 5와 중복 인접쌍 2개는 별도로 보존한다. 중복 비율은 같은 부분선 안에서 계산하여 $2/(5-1)=0.5$다.

전체 고유 좌표를 하나씩만 남기는 방법과는 다르다. `A, B, A`에서 뒤의 A는 재방문일 수 있으므로 전체 중복 제거로 없애지 않는다. 여러 부분선이 있다면 인접쌍의 분모도 각 부분선 내부의 $n_j-1$을 합산한다.

P3가 보고한 전체 표는 246개 점, 16개 부분선, 내부 인접쌍 230개, 연속 중복쌍 158개다. 따라서 비율은 $158/230\approx68.7\%$이고 연속 반복 압축 후 점 수는 $246-158=88$이다. 이 88개는 전체 고유 좌표 수를 뜻하지 않는다. 원본 CSV가 없는 현재 작업에서는 **PDF 보고값에 대한 산술 해설**로만 사용한다.

관측된 반복의 원인은 정지, 좌표 반올림, 통신 재전송, 가공 중 반복 등일 수 있다. 점별 시각과 수집 규칙 없이 반복 횟수를 정박 시간으로 환산하지 않는다. P1의 “8척 정지”라는 표현은 확정 관측으로 채택하지 않고, 작은 공간 범위 또는 정지·위치 흔들림 가능성으로 읽는다.

현재 S0는 영길이 벡터를 회전각 계산에서 제외하지만, 모든 특징에 대해 중복 압축이나 거리 재표본화를 수행하는 구현은 아니다. 퍼짐 비율은 원래 부분선의 점 분포에서 계산되어 표본 밀도의 영향을 받을 수 있다. PDF가 제안한 밀도 보정은 후속 비교 대상이다.

## 시간 정보가 없을 때 계산 가능한 것

| 값 | 현재 조건에서의 판단 |
| --- | --- |
| 관측된 부분선 길이 | 좌표계와 거리 계산법이 확인되면 가능 |
| 부분선 직선성·공간 굴곡 | 점 순서와 퇴화 조건을 명시하면 가능 |
| 점 수·반복 수·부분선 수 | 관측 구조의 품질 요약으로 가능 |
| 실제 순간 속력·가속도 | 점별 시각과 연결 조건 없이 불가 |
| 실제 체류시간·정박시간 | 기록 간격·관측 커버리지 없이 불가 |
| `L / 1시간` | 시간대 정의가 확인된 경우 관측 길이 대리지표로만 해석 |

시간대가 한 시간이라는 이유만으로 모든 점이 한 시간 전체를 고르게 관측했다고 가정할 수 없다. `60분/(점 수-1)`로 만든 시각은 실제 시각이 아니다. 또한 연속 시간대가 있다고 해서 마지막 점과 다음 행 첫 점 사이의 경로를 자동으로 연결하지 않는다. 시간순 특징 벡터 비교와 관측되지 않은 공간 연결은 다른 작업이다.

S0의 `sim_times`는 생성한 시간이다. 검증·예제 기록에는 있지만 현재 모델은 사용하지 않는다. 실제자료에서 점별 시각이 생기더라도 관측 순서·중복 시각·시간 간격·단절 처리를 따로 확정한 뒤 속력 계산을 추가한다.

## 결측과 영값과 거부와 유보

| 상태 | 예 | 처리 원칙 |
| --- | --- | --- |
| 유효한 0 | 방향 변화가 실제 0인 관측 | 0을 유지 |
| 정의 불가 | 0길이의 직선성, 각도가 없는 2점 선 | null/NaN과 사유·결측 표시 |
| 형식 오류 | 비유한 좌표, 잘못된 배열 구조 | 입력 거부와 안전한 오류 위치 |
| 분석 불가 | 빈 경로 또는 모든 부분선 길이 0 | 유보하고 예측을 정상값처럼 만들지 않음 |

현실에서는 0길이 기록 자체도 의미 있는 관측일 수 있다. S0가 분류를 유보하는 이유는 현재 특징과 학습 계약의 적용 범위 때문이다. 모든 실제 정지 사례를 자료 오류로 삭제하라는 뜻은 아니다.

관측 잡음을 줄이기 위해 고정 거리 이하를 모두 지우면 매우 짧은 유효 경로도 사라질 수 있다. P1의 5~20m 기준이나 P3의 거리 간격 예시는 확정 규칙이 아니다. 원본과 정제본을 분리하고, 짧은 항적에서 무엇을 잃는지 먼저 관찰한다.

## 현재 검사기가 확인하는 범위

[실제자료 검사기](../../tools/inspect_data.py)는 읽기 전용 구조 검사다. 기본은 UTF-8-SIG·쉼표 CSV, 비재귀 탐색, 파일당 2MiB, 표본 100레코드, 최대 100개 파일이다. 큰 파일·ZIP은 메타데이터만 확인하며 자동 압축 해제하지 않는다. 제한된 2D `MULTILINESTRING`만 지원하고 Z/M/ZM·EWKT는 지원하지 않는다.

`MULTILINESTRING EMPTY`는 문법상 인식하지만 분석 불가로 집계한다. 기본적으로 CRS를 가정하지 않으며, `--coordinate-assumption lonlat` 옵션을 주어도 범위 가정만 적용할 뿐 CRS를 확인한 것이 아니다. 표본 키 충돌 검사는 전체 자료의 고유성 검증이 아니다.

이 검사 결과와 학습 가능한 feature 테이블은 다르다. 실제자료용 거리 계산은 핵심 계약 확인 후 F2에서 구현·검증할 범위다. 이번 통합 작업은 그 파이프라인을 자동 생성하지 않는다.

## 손으로 확인할 활동

1. 위 두 부분선의 길이와 직선성을 직접 계산하고, 부분선 B의 시작 위치만 멀리 옮겼을 때 어떤 값이 유지되는지 설명한다.
2. `A,A,B,A`에서 연속 중복 제거와 전체 고유 좌표 추출의 결과를 각각 쓴다.
3. 2점 경로의 회전각을 0으로 채우면 어떤 정보가 사라지는지 설명한다.
4. 실제 CSV에서 속력을 추가하려면 필요한 정보와 오류 조건을 적는다.

심화는 [어선 기하 교재](../ai_textbook/chapters/19_fishing_data_geometry.md), 구현 대조는 [features.py](../../fishing_demo/features.py)를 사용한다.
