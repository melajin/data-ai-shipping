# 현재 상태를 반영한 제안서와 개인 학습 활동

[통합 가이드](../../어선%20항적%20통합%20학습%20가이드.md) · [이전 평가와 후속 실험](04_평가와_후속실험.md) · [출처와 통합 판단](99_출처와_통합판단.md)

제안서는 앞으로 검증할 방법을 설명하고, 실험 보고서는 이미 수행한 결과를 설명한다. 우리 프로젝트에서는 **합성 시스템의 구현 경험을 준비 역량으로 제시하되 실제 조업·사고 성과로 바꾸어 쓰지 않는다.** 아래 문안은 개인 학습과 제안서 편집을 위한 초안이며 신청·제출·서명은 수행하지 않았다.

## 제안서에 넣을 수 있는 통합 문안

아래 세 소제목은 [P2 3쪽](sources/01_참가신청서_가이드와_제안서_통합본.pdf#page=3)의 구조에 맞춰 현재 프로젝트의 상태를 반영했다. 최종 분량·형식·제출 단위는 실제 양식과 안내에 맞춘다.

### 데이터 활용 방안과 분석 방법론

시간대별 어선 항적에서 조업형태와 기준 패턴 대비 이상 정도를 분석하는 경량 시스템을 개발하고자 한다. 원자료 수령 후 파일 버전, 컬럼, 좌표계, 시간대와 가용시각, 부분선과 좌표 순서, 조업 라벨 및 사고정보 연결 조건을 확인한다. 원본 키와 부분선 경계를 보존하고 형상 특징과 관측 품질 정보를 구분한다. 점별 시각이 제공되지 않으면 실제 순간 속력·가속도·체류시간을 계산하지 않는다.

조업형태 분류는 선 내부 관측 길이, 직선성, 공간 굴곡과 범위 등 조건이 확인된 기하 특징을 사용한다. 최다 클래스 기준과 로지스틱 회귀를 마련하고 작은 LightGBM의 추가 효과를 비교할 계획이다. 선박 ID를 모델 입력에서 제외하고 신규 선박 조건에 맞춘 그룹 분리로 클래스별 성능과 확률을 평가한다.

이상항적은 전역 강건 편차와 Isolation Forest를 독립 기준으로 비교한다. 사고정보가 없다는 이유로 정상 정답을 확정하지 않으며, 사고시각 주변의 약한 라벨과 확인된 이상구간을 구분한다. 시간순 평가에서는 실제 가용시각을 기준으로 사전 탐지·사고 후 반응·관측시간당 경보 빈도를 따로 분석한다. 조업형태별·선박별 과거 기준과 시간 규칙은 추가 효과가 검증될 때 도입한다.

현재 준비 단계에서는 지역 평면 좌표의 합성 경로 생성, 8개 기하 특징, 선형·소형 MLP 분류, 확률 보정, 거리 점수, 저장·재추론 및 대시보드를 연결한 S0 교육 시스템을 구현했다. 이 결과는 생성 경로 유형에 대한 코드와 학습 흐름의 검증이며 실제 어선 성능을 입증하지 않는다. 실제자료 계약과 평가 조건을 확인한 뒤 최소 기준선부터 단계적으로 전환할 계획이다.

### 추진 일정

핵심 시간·좌표·기하 계약 확인 → 무라벨 기하 검증 → 라벨 의미·평가 분할 확인 후 분류·이상 기준선 구현 → 선박·시간·사건별 오류 분석 → 효과가 확인된 요소 추가 → 경량화와 제출 재현 점검 순으로 진행한다. 단계마다 산출물과 완료 조건을 기록하고 공식 마감 및 가용 작업 시간에 맞춰 일정을 확정한다. 핵심 과제의 조건이 갖춰지기 전에는 강화학습·외부자료·3D 등으로 범위를 확대하지 않는다.

### 예상 결과물

원자료 계약과 품질 보고서, 재현 가능한 전처리·특징 코드, 조업형태 및 예측 확률, 시간대별 연속 이상점수, 클래스·선박·사건·관측 품질별 오류 분석, 사고 전후 시각화, 모델 크기와 CPU 비용 기록, 실행 환경·분할·설정·버전을 포함한 재현 패키지를 제출 규격에 맞춰 작성할 계획이다.

## 제안서에서 바꿔 써야 하는 표현

| 피할 표현 | 현재 근거에 맞는 표현 |
| --- | --- |
| 어선 조업 정확도 81.25% 달성 | 합성 경로 세 유형의 Test 정확도 81.25%를 저장 실험에서 확인 |
| 사고 탐지율 95% | 합성 validation 거리 점수의 95백분위를 표시 임계값으로 사용 |
| 실제 샘플 10행을 우리 코드로 분석 완료 | 제공 PDF는 10행 분석을 보고하며 해당 원본 CSV는 현재 프로젝트에 없음 |
| LightGBM·IF 시스템 구현 완료 | 실제자료 기준선의 비교 후보로 계획 |
| 과적합을 해결 | 선박 분리·후보 제한·별도 보정 등 통제 절차를 구현하고 한계를 기록 |
| 실시간 사고 예방 시스템 완성 | 오프라인 합성 분석과 시각화를 구현했고 실제 가용시각·운용 효과는 후속 검증 |

실제 신청 정보, 팀원 동의, 서명은 해당 참가자가 작성할 사항이다. PDF가 요약한 규정 문구를 최신 공식 원문 확인 대신 사용하지 않는다. 여기서는 법적 해석이나 동의를 대신하지 않는다.

## 일정 정보의 확인 수준

2026-10-13에 읽은 [공식 과제 페이지](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004601/detail.do)는 과제명과 해양경찰청, **참가신청 일정 2026-09-15~2026-11-06**, 신청서·샘플·전체 ZIP의 파일 목록을 표시했다. 이 조회는 원본 파일의 다운로드·내용 검사와 다르다. 페이지에 참가신청이라고 표시된 날짜를 모든 결과물의 제출 마감으로 확대 해석하지 않는다.

P1의 작성일 기준 “D-25”는 그 문서의 과거 시점 표기다. 우리 학습자의 가용 시간·선수지식·장비 규모가 미확인이므로 고정된 25일 학습계획으로 옮기지 않는다. 실제 일정은 단계별 완료 조건과 본인의 자원을 확인해 정한다.

## 기존 결과를 먼저 읽는 실습

첫 실습은 재학습 없이 다음을 열어 보는 것이다.

1. [report.json](../../outputs/sample_system/report.json)에서 `selected_model`, `temperature`, `split_summary`, `metrics`를 찾는다.
2. [대시보드](../../outputs/sample_system/dashboard.html)를 브라우저로 연다.
3. test에서 정답·오답을 하나씩 골라 부분선, 확률, 기하 특징을 비교한다.
4. 학습 곡선과 혼동행렬에서 표본에 대한 관찰이 전체 결과와 어떻게 연결되는지 설명한다.
5. 설명할 수 없는 값은 수식을 다시 읽고 질문으로 남긴다.

화면의 XY는 지역 미터 좌표다. 실제 해역 지도나 실제 운항 속력으로 해석하지 않는다. 높은 거리 점수가 나왔다면 먼저 경로·부분선·특징·결측·학습 기준을 확인한다. 점수만 보고 사고 사례라는 이름을 붙이지 않는다.

## 별도 폴더에서 재현하기

프로젝트 루트에서 실행한다. Python 3.10 이상과 NumPy를 사용한다. 기존 저장 실험의 기록된 환경은 Python 3.13.3·NumPy 2.2.5이며 본인의 환경은 별도로 남긴다.

```powershell
Set-Location -LiteralPath 'D:\obsidian\claude\obsidian_export\DATA AI SHIPPING'
python -m pip install -r requirements-sample.txt
python tools/run_sample_system.py demo --out outputs/study_run_01
python tools/run_sample_system.py predict --data outputs/study_run_01/sample_dataset.json --model outputs/study_run_01/model.json --out outputs/study_predict_01
```

위 명령은 학습자가 실행할 절차이며 이번 문서 통합에서 실행한 새 실험은 아니다. `demo`는 같은 출력 경로의 생성물을 갱신하므로, 해당 폴더가 이미 있다면 `study_run_02`처럼 미사용 경로를 고른다. 기존 `outputs/sample_system`은 비교 기준으로 남겨 둔다.

코드를 변경한 실습에서는 영향받는 테스트를 실행하고 필요할 때 전체 검사를 한다.

```powershell
python -m unittest discover -s tests -v
```

저장된 이전 검증 기록은 91개 실행 중 89개 통과, 실패·오류 0, Windows symlink 권한 관련 건너뜀 2개다. 본인의 재실행 로그가 같은지 별도로 확인한다. 건너뜀은 성공으로 바꾸어 세지 않는다.

실제자료가 허용된 위치에 준비되고 후속 작업 범위가 정해진 뒤에는 읽기 전용 검사부터 시작한다.

```powershell
python tools/inspect_data.py data/raw --recursive --expect train --output outputs/real_inventory_01.json
```

이 명령도 CSV 전체 품질·CRS·실제 모델 성능을 자동 보증하지 않는다. [검사 한도](02_데이터와_전처리.md)를 보고 검사 범위와 미검사 범위를 함께 적는다. 이 안내를 원자료 수집이나 실제자료 학습이 이미 수행됐다는 기록으로 사용하지 않는다.

## 단계별 학습과 완료 조건

현재 자료는 본인 학습자용이다. 시작 전에 Python 함수·배열, 벡터 길이, 평균·표준편차, 확률·로그를 어느 정도 설명할 수 있는지 적는다. 하루 학습 시간과 사용 가능한 CPU·메모리도 기록한다. 수준이 정해지지 않았으므로 아래 단계에 고정 차시나 시간을 부여하지 않는다.

| 단계 | 기술 목표와 구현물 | 관찰할 현상과 검증 | 학습 목표와 설명 질문 |
| --- | --- | --- | --- |
| 1 과제 해석 | 두 과제의 입력·출력 표 | PDF와 프로젝트 계약 대조 | 분류·이상·사고의 차이를 설명 |
| 2 기하 | 작은 부분선 손계산표 | 길이 20m와 가상 연결의 차이 | 왜 부분선을 이어서는 안 되는가 |
| 3 특징과 결측 | 표본 하나의 8개 특징 읽기 | 회전각 없음과 0의 차이 | 왜 결측 마스크가 필요한가 |
| 4 학습 흐름 | 별도 폴더의 합성 실행물 | train·validation·calibration 역할 | 어디서 적합하고 어디서 선택하는가 |
| 5 평가 해석 | 혼동행렬·오류 사례 설명 | 117/144와 유형별 오류 계산 | 높은 정확도 외에 무엇이 필요한가 |
| 6 조건 변경 | 한 변수만 바꾸는 실험 계획 | 예상→결과→해석 비교 | 결과로부터 어떤 결론까지 가능한가 |

각 단계는 기술 결과와 이해를 따로 완료 처리한다. 실행 성공만으로 다음 단계의 학습을 통과했다고 쓰지 않는다. 질문은 먼저 스스로 답하고, 막힌 부분만 힌트·부분 예제로 확인한 뒤 필요한 경우 [심화 해설](../ai_textbook/chapters/26_fishing_sample_system_personal_study.md)을 읽는다.

## 실험 기록 틀

아래 항목을 새 개인 노트에 복사해 자신의 값으로 채운다. 빈 항목은 모르는 상태로 남기는 것이 임의 숫자를 넣는 것보다 낫다.

```text
자료와 코드 버전 및 파일:
조건과 가정, 단위:
변경할 한 요소:
고정할 요소와 분할:
예상 결과와 이유:
실제 계산값 또는 관찰값:
예상과 다른 점:
가능한 원인과 반례:
이 결과로 주장할 수 있는 것:
아직 주장할 수 없는 것:

```

## 오류가 났을 때 확인할 순서

| 계층 | 증상 예 | 먼저 볼 근거 |
| --- | --- | --- |
| 원자료 | 파일·인코딩·컬럼 불일치 | 파일 식별, 읽기 조건, 검사 범위 |
| 계약 | 시간 의미·좌표 순서·클래스 목록 불일치 | 원문 설명과 schema_version |
| 전처리 | 비정상 거리·결측 급증 | 부분선, 단위, 영벡터, feature 순서 |
| 모델 | 차원 오류·과신·이상 점수 상승 | 저장 전처리, 클래스 순서, train 기준 |
| 전달과 표시 | 값과 그래프 불일치 | 같은 표본 ID, 출력 JSON, 유보 상태 |

아직 장치가 없는 단계에서 하드웨어 원인으로 단정하지 않는다. 실제 장치를 도입하게 되면 센서·회로·펌웨어·통신을 별도 계층으로 추가하고 허용 조건을 확인한다.

## 팀이나 다른 사람에게 설명하는 순서

“우리는 시간대별 항적에서 조업형태와 기준 대비 이상 정도를 다룬다”로 시작한다. 다음으로 부분선·시간 정보의 한계, 현재 합성 시스템의 흐름, 저장 결과의 의미, 실제자료 전환 조건을 설명한다. 대시보드의 표본 하나를 근거로 연결하면 설명이 구체적이 된다.

마지막에는 스스로 답할 질문을 남긴다. **새 원자료가 들어왔을 때, 바로 모델부터 학습하지 않고 무엇을 확인할 것인가?** 그 답을 입력 계약·무라벨 기하·라벨과 평가 설계로 나누어 말할 수 있으면 다음 작업을 계획할 준비가 된 것이다.
