# 어선 항적 문서 통합 검증 기록

[통합 가이드](../../어선%20항적%20통합%20학습%20가이드.md) · [출처 대조](99_출처와_통합판단.md)

## 작업 범위와 결과

사용자가 제공한 PDF 세 편을 현재 프로젝트의 문서·코드·저장 실험에 연결하여 옵시디언용 상세 학습 자료로 통합했다. 홈, 주제별 노트 5개, 출처 대조, 이 검증 기록으로 구성했다. 기존 프로젝트 소개와 교재 목차에는 새 가이드 링크를 추가했다.

PDF 원본은 수정하지 않고 `sources`에 복사했으며 세 사본의 SHA-256이 Downloads 원본과 일치함을 확인했다. 파일별 경로·크기·해시는 [manifest.json](sources/manifest.json)에 있다. 원본 PDF의 16·6·26개 물리 페이지 텍스트를 조사하고 세 표지를 렌더링하여 시각 확인했다. 원본을 재조판하거나 PDF 전 페이지의 시각 품질을 인증한 작업은 아니다.

통합 판단에 사용한 기존 구현 파일과 report.json의 해시는 저장된 S0 검증 기록과 일치했다. 기존 테스트 결과 91개 실행·89개 통과·2개 건너뜀과 1008개 재추론 일치는 이전 실행 근거로만 인용했다. 이번 작업에서 모델 학습·소프트웨어 테스트·실제자료 평가·장치 실험을 새로 수행하지 않았다.

하위 에이전트 생성 호출에는 `agent_type`, `model`, `reasoning_effort`, `fork_turns=none`을 명시했다. 로컬 `.codex/agents`의 해당 프로필과 요청 설정도 대조했다. 도구는 각 작업의 생성과 완료를 반환했지만 별도의 런타임 모델 식별값을 제공하지 않았으므로 이는 **명시한 요청 설정 및 작업 실행 근거**이며 숨겨진 실행 모델에 대한 추가 인증이 아니다. 부모 세션의 실행 모델을 변경했다고 주장하지 않는다.

주요 검토 반영 사항은 다음과 같다.

- P1의 부분선 사이 연결 거리·균등 시각 속력·정지 단정을 현재 구현 원칙과 구별했다.
- PDF 보고 샘플과 현재 보유 실제 원자료·S0 합성 데이터를 분리했다.
- 특징 8개와 결측 마스크를 합친 16차원 입력, 대치 후 값과 표준화 후 값의 차이를 명확히 했다.
- `train_objective`는 저장 학습 기록이고 화면은 train·validation NLL을 그린다는 점을 수정했다.
- 온도 보정의 Test 개선과 Stress 악화를 모두 기록했다.
- 과제 1·2와 평가 자료 Test A·B의 명칭을 구별했다.
- F1의 라벨 조사와 F2의 무라벨 기하 허용 조건, F3의 라벨·분할 선행조건을 구분했다.
- 공식 페이지의 기관표기·참가신청 기간·파일 목록 직접 확인을 PDF의 간접 보고와 구분했다.

## 로컬 저장과 확인 한계

옵시디언 등록 설정에서 `D:\obsidian\claude` 보관함을 확인했다. 이 프로젝트와 새 문서는 그 아래 `obsidian_export\DATA AI SHIPPING`에 저장되어 있다. 외부 공유·신청서 제출·클라우드 동기화를 실행하지 않았다.

Markdown 파일을 다시 읽어 로컬 링크 대상, PDF 실제 페이지 범위, 코드 블록·수식 구분자, UTF-8 텍스트, PDF 사본 해시를 검사했다. 확인 결과는 [기계 판독 문서 검사](문서_검사결과.json)에 기록한다. 이 검사는 링크와 문서 구조에 대한 것이며 전체 수학 이론이나 학습자의 이해를 기계적으로 증명하지 않는다.

옵시디언 앱의 실제 읽기 화면과 Mermaid·수식 렌더링은 이번 세션에서 직접 확인하지 않았다. 읽기 모드에서 표·수식·PDF 링크를 확인하고, HTML 대시보드는 별도 브라우저로 연다. 코드와 기존 실험 결과는 변경하지 않았다.

작업 중 생성한 `tmp/pdfs/integration_20261013`의 추출 텍스트·표지 미리보기 삭제는 자동 승인 검토에서 정책상 차단되어 원위치에 남겼다. 최종 문서가 이 임시 파일에 의존하지는 않는다.
