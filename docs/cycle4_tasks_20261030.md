## 이번 사이클의 방향

1~3차는 "결과를 믿을 수 있는가"를 확인하는 작업이었다. 4차는 **신규 선박 macro F1을 올리는 실험만** 한다.

- 대회 규칙: Test A는 **원칙적으로 학습에 없는 신규 선박**이다.
- 학습은 2026년 1~6월, 테스트는 2025년 1~6월이다.
- 따라서 실제 시험과 가장 닮은 조건은 **"2025년 항적, 학습에서 본 적 없는 선박"**이다. 이번 사이클은 이 조건으로 검증한다.
- 겹치는 선박만 평가하면 F1이 0.98까지 나온다(ID 암기 효과, 사용자 실측). 이 숫자는 어떤 보고에도 성능으로 쓰지 않는다.

**기간: 4일.** 4일째에 그때까지의 최고 모델로 마무리하고 과제 2로 넘어간다.

## 1. 공통 규칙

### 절대 금지
- **final holdout 1,473척은 2025·2026년 항적 모두** 학습·예측·평가·선택에 쓰지 않는다. 2025년 자료를 붙일 때도 이 선박들은 먼저 제거하고, 분할마다 assert로 확인한다.
- 같은 선박의 2025년 기록과 2026년 기록이 **학습과 검증으로 갈라지면 안 된다.** 분할은 선박 ID 단위로 하고, 한 선박의 두 해 기록은 항상 같은 쪽에 둔다.
- 1~3차 코드와 산출물은 수정하거나 덮어쓰지 않는다. 새 산출물은 `outputs/cycle4/`, 문서는 `docs/cycle4_*`에 둔다.

### 고정 조건
- 모델: ExtraTrees(256, mlsf=2, max_features=1.0, class_weight="balanced", **n_jobs=1**).
- 분할: 1차 분할 함수, seed 3201/3202/3203.
- 초기화: 42·137, 확률 평균 후 채점.
- 집계: 2차 `all/balanced` 방식(선박별 관측 행 전량, 행 확률 → 선박 확률).
- 라벨: `label_vocabulary.json`을 읽고 해시 검증. 한글 클래스명을 소스에 직접 쓰지 않는다.

### 메모리 (3차 작업 1의 실패를 반복하지 않기 위해)
- 단일 프로세스로 실행한다.
- 초기화 42 적합 → 예측 → 확률만 저장 → `del model; gc.collect()` → 137 진행. **두 모델을 동시에 들고 있지 않는다.**
- 모델 객체는 저장하지 않는다. 예측확률은 float32로 저장해도 되며, 채점은 저장 전 float64 값으로 한다.
- `predict_proba`는 청크 단위로 한다.
- 실험·분할 단위로 체크포인트를 남기고, `--only <실험키>` 단일 실행 모드를 둔다.
- 첫 적합 1회에 대해 `sum(tree_.node_count)`, RSS 피크를 기록한다.

### 채택 규칙 (모든 실험에 동일)
- 주 지표: **V25 macro F1** (아래 작업 4-0 참조).
- 채택 조건: 비교 대상 대비 **3분할 평균 +0.02 이상, 그리고 3분할 모두 상승.**
- 조건을 못 넘으면 효과 없음으로 기록하고 버린다. 사후에 기준을 바꾸지 않는다.

### 보고 형식
- 작업마다 `docs/cycle4_<번호>_<이름>.md` 하나. **짧게 쓴다.** 결과표 + 확인된 사실 3줄 이내 + 미수행 사항.
- 결과표 열: 실험 / V25 macro F1(분할별·평균) / V26 macro F1 평균 / 정확도 / 업종별 재현율 / 채택 여부.
- 모든 표에 **찍기 기준선(전부 연안복합으로 예측)의 macro F1과 정확도**를 첫 행으로 넣는다.

## 작업 4-0. Test A와 같은 조건의 검증셋 만들기

**목적:** 2025년 신규 선박이라는 시험 조건을 검증에서 재현한다.

1. 테스트 CSV(2025년 1~6월)를 읽는다. 1차와 같은 파서·예외 처리 규칙을 쓴다.
2. 2025년 선박 중 학습(2026) 라벨이 있는 선박에 **같은 ID의 2026년 라벨을 붙인다.**
   - 라벨이 빈 선박, final holdout 선박은 제외한다.
   - 학습에 없는 선박(약 870척)은 라벨이 없으므로 제외한다. 이들은 Test A 후보다.
3. 2025년 자료로 dist36 특징 캐시를 만든다(1차와 같은 코드 경로).
4. 검증셋 두 개를 정의한다.
   - **V26:** 검증 선박의 2026년 항적 (기존과 같음)
   - **V25:** 같은 검증 선박의 2025년 항적 ← **이번 사이클 주 지표**
5. 확인해서 보고할 것:
   - 라벨을 빌려 붙인 선박 수, 업종별 분포(2026년 분포와 나란히)
   - 공식 제출샘플 sheet1(testA)의 rfid_id 중 학습에 있는 비율. **규칙대로 0에 가까운지** 확인한다.
   - 2025·2026 양쪽에 기록이 있는 선박의 비율

**정지 조건:**
- 제출샘플 testA ID가 학습에 상당수(10% 이상) 있으면 정지하고 보고한다. 시험 조건 가정이 흔들리기 때문이다.
- holdout 제외 assert가 하나라도 실패하면 정지한다.

## 작업 4-2. 특징 묶음을 하나씩 붙이기

작업 4-1에서 정한 기준 위에 **한 묶음씩만** 붙여서 각각 비교한다. 선박 단위 특징은 그 선박의 모든 행에 같은 값으로 붙인다(같은 선박 안의 정보만 쓰므로 선박 간 누수는 없다).

특징은 **선박·연도 단위**로 계산한다. 2025년 기록과 2026년 기록을 섞어서 계산하지 않는다.

"활동 행"은 행 길이 50m 초과인 행으로 정의한다. 이 기준은 사후에 바꾸지 않는다.

### A. 시간 (`featA`) — 채낚기(야간 조업) 겨냥
- 시간대(rfid_time)별 활동 행 비율 24개
- 야간(18~05시) 활동 비율
- 월별 활동 행 비율 6개(1~6월)
- 활동일당 평균 활동 시간대 수

### B. 재방문 (`featB`) — 통발(같은 자리 반복) 겨냥
- 격자: 0.01도(약 1km).
- 활동일 중 **이전 활동일에 갔던 격자를 다시 방문한 날의 비율**
- 상위 5개 격자에 들어간 좌표 비율
- 고유 방문 격자 수 ÷ 활동일 수
- 거의 정지한 좌표(인접점 이동 20m 미만)가 모인 격자 수

### C. 이동범위 (`featC`) — 전체
- 좌표 경도·위도 5~95% 분위수로 만든 범위 넓이(km²)
- 선박 좌표 중앙값에서의 최대 거리, 평균 거리, 회전반경(radius of gyration)
- 거친 해역 분포: 0.5도 격자별 좌표 비율. **학습 선박 50척 이상이 쓰는 격자만** 열로 만들고(격자 목록은 분할마다 학습 선박으로만 정한다) 나머지는 "기타" 한 열로 합친다.
- 선박 하나를 특정하는 값(모항 좌표, 첫 출항 좌표 등)은 넣지 않는다.

### D. 회전각 정제 (`featD`) — 통발·자망 겨냥
- 3차에서 max_abs_turn 상위 10% 기준값이 정확히 π였다. 거의 안 움직인 구간의 GPS 흔들림이 회전으로 잡힌 것으로 의심된다.
- 먼저 확인: 회전각 계산에 쓰인 인접 선분 중 길이 20m 미만 선분의 비율, max_abs_turn == π 인 조각 비율.
- 같은 구성 선 안에서 **20m 미만 선분을 제외하고** 회전각 계열 특징을 다시 계산한 dist36 변형(`dist36d`)을 만들어, dist36의 회전 계열 열을 교체한다.

### 실험 목록

| 실험 키 | 내용 |
|---|---|
| `+A` | 기준 + featA |
| `+B` | 기준 + featB |
| `+C` | 기준 + featC |
| `+D` | 기준의 dist36을 dist36d로 교체 |

각 실험의 특징 중요도 상위 20개를 함께 보고한다.

## 작업 4-3. 채택된 묶음 합치기, 필요하면 연안복합 처리

1. 4-2에서 채택된 묶음을 모두 합친 실험(`combo`)을 돌린다. 기준 대비 채택 규칙으로 판단한다.
2. `combo`에서도 연안복합 관련 혼동(통발→연안복합 등)이 혼동행렬에서 가장 크면, 아래 하나만 시험한다.
   - **2단계 분류:** 1단계는 "연안복합 vs 전업(자망·통발·채낚기)", 2단계는 전업 3업종 분류. 두 모델 모두 같은 학습 자료, 같은 분할. 최종 확률은 P(전업) × P(업종|전업), P(연안복합)은 1단계 값.
3. 채택된 최종 구성을 `final_config.json`에 고정한다(특징 목록, 학습 자료, 코드 SHA-256).

## 작업 4-4. 마무리 (0장 승인 시에만)

1. `final_config` 그대로 final holdout을 **한 번만** 평가한다. V25·V26 둘 다 보고한다. 이 결과로 구성을 바꾸지 않는다.
2. holdout을 포함한 전체 라벨 자료(2026 + 라벨을 빌린 2025)로 재학습한다.
3. 공식 Test A 대상 선박에 대해 예측해 제출 형식으로 저장한다.
   - 열: `rfid_id`, `예측 조업형태`, `예측조업형태 확률`(예측 업종의 확률)
   - 확률은 2차에서 정한 처리(균등분포 혼합 B 단독, ε≈0.01)를 적용한다.
   - 저장 후 다시 읽어 행 수·ID 중복·확률 범위(0~1)를 검사한다.
