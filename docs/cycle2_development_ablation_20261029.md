## 1. 결론 요약

- 이 고정 설계에서 **선박별 분포 특징에 사용하는 관측 행 확대**의 평균 Macro F1 차이가 가장 컸다(+0.04903, 최대 +0.07511). class weight(+0.01302)와 규모 특징(+0.01216)의 약 4배다. sample 대조 네 조건은 각각 세 분할 모두 양수였지만, 나머지 두 요인은 조건에 따라 분할별 부호가 섞였다.
- 세 요인을 모두 적용한 Macro F1 최고 셀은 0.41695로, 1차 재현 기준점 0.33540에서 +0.08155다. 개발 validation에서 선택한 값이며 실무 성능 확보의 근거로 충분하지 않다.
- 이 셀의 **분할 평균 정확도는 0.50040**이다. 합산 정확도는 0.50038로 다수 클래스 상수 예측(0.49544)보다 +0.00494다. 평가가능 선박-분할 2,630건에서 정답 13건 차이며, 독립 고유 선박 2,630척의 결과가 아니다.
- **통발 recall은 여전히 낮다.** 8개 셀 전체에서 분할 평균 recall 최대 0.06684다. 해당 셀의 통발 support는 분할별 125/125/124(합 374건)이며 선박이 분할 사이에 재등장할 수 있다. 1차 final의 0/204와는 평가집합이 달라 직접 전후 비교하지 않는다.
- 규모 특징 추가의 평균 차이는 none 조건에서 s4 +0.03599, all +0.00375였다. 전량 행의 분포 특징이 규모 특징과 겹치는 정보를 담는다는 설명은 미검증 가설이다. 균일 배율에 대한 shape9의 불변성은 행을 늘려도 유지되므로, 관측 행 확대가 절대 규모 정보를 복원한다는 뜻은 아니다. 작은 평균 차이를 효과 부재로 단정하지 않는다.
- 기준 셀에서 한 요인씩 켠 Macro F1 차이를 반올림 전에 더한 값의 다섯 자리 표시는 +0.14912이고, 세 요인을 함께 켠 차이는 +0.08155다. Macro F1 척도에서 가산적이지 않다는 기술 통계이며, 같은 다수 클래스 편향을 고친다는 메커니즘은 입증하지 않는다.

## 2. 사전등록한 설계

모델을 ExtraTrees(n_estimators=256, min_samples_leaf=2, max_features=1.0, seed 42·137 평균)로 **고정**했다. 1차 개발 관문을 통과한 유일한 후보라 모델 선택이 요인에 섞이지 않는다. split은 동결된 1차 함수를 같은 seed로 호출해 명부가 동일하다.

| 요인 | 수준 0 (1차 설정) | 수준 1 (2차 추가) |
| --- | --- | --- |
| sample | `s4` 선박·월당 4행 (129,142행) | `all` 라벨 유효 전량 (3,887,067행) |
| weight | `none` | `balanced` |
| features | `dist36` shape9 mean/std/q25/q75 | `dist36_scale32` + 규모 8종 |

선박별로 선택된 모든 월의 유효 행을 합쳐 shape9 각 열의 mean/std/q25/q75를 계산하므로, 학습 예제는 선박당 dist36 벡터 하나다. scale8도 같은 네 통계로 요약하여 32개를 추가한다. 전처리의 결측 지시자까지 포함하면 모델 입력은 각각 72차원·136차원이다. `balanced`는 유효 학습 선박의 클래스 수를 기준으로 적용된다.

2×2×2 = 8셀 × 3분할 × 2초기화 = 48 적합. 초기화 42·137의 확률을 먼저 평균해 분할당 지표 하나를 계산했다. 선택은 validation에서만 했고 final 선박이 train·validation·calibration 명부에 들어가지 않음을 assert로 확인했다. 전체 캐시에는 final 특징도 로드되지만 이번 모델의 학습·예측·평가에는 사용하지 않았다.

### 읽는 방법

- **관측 행 확대에서 가장 큰 평균 차이를 관찰했다.** 3.32% → 100%의 행을 분포 특징에 사용한 대조는 평균 +0.04903이고 네 조건 모두 세 분할에서 양수였다. 학습 선박 명부는 같으며, 특징 추정 변화·유효 선박 증가·validation 입력 변화의 기여는 분리되지 않았다.
- **class weight의 통발 recall 차이는 일관되게 양수였다.** 네 조건의 평균 차이는 +0.01871 ~ +0.04009이며 각 분할에서도 양수였다. 현재 모델·특징·분할에서 가중치 변경에 반응한 결과이며, 불균형이 통발 문제의 원인이라고 확정하지 않는다. Macro F1은 네 대조 중 하나만 세 분할 모두 양수였다.
- **규모 특징의 평균 차이는 조건에 따라 달랐다.** none 조건에서 s4 +0.03599, all +0.00375이고, balanced 조건에서는 +0.00589, +0.00302였다. shape9가 절대 규모를 비율로 정규화하고 scale8이 규모를 추가하는 설계와, 실제 분류에서 그 정보가 얼마나 쓰이는지는 별개다. 전량 행의 분위수가 규모 특징과 중복된다는 설명은 분포 중첩 등으로 확인하지 않았다.
- **정확도 차이와 Macro F1 차이를 구별한다.** 소수 클래스 recall과 다수 클래스 recall의 변화는 관찰되지만, 저장된 지표만으로 예측 재분배의 전체 경로를 확정하지 않는다. 셀별 확률·완전한 혼동행렬·예측 비율은 저장되지 않았다.

기준 셀에서 한 요인씩 켠 차이 +0.07511, +0.03803, +0.03599의 반올림 전 합은 0.1491216487…로, 다섯 자리 표시값은 +0.14912다(표시된 세 차이의 합은 +0.14913). 종전 +0.14914는 현재 저장 결과로 재현되지 않아 정정하며, 중간 산출 근거가 없어 발생 원인은 확정하지 않는다. 이는 네 고정 조건의 평균 차이를 더한 +0.07421과 다른 비교다. 함께 켠 차이 +0.08155와의 차이 및 교호작용은 Macro F1 척도의 비가산성을 나타내며 원인 메커니즘을 증명하지 않는다([계산 상세](cycle2_summary_audit_20261029.md#3-합산-효과와-교호작용)).

## 6. 확인된 것과 확인되지 않은 것

### 확인된 것

1. 세 요인의 네 조건 평균 Macro F1 차이는 모두 양수이며 관측 행 확대의 평균 차이가 가장 컸다. 가중치·규모 특징은 분할별 부호가 섞이는 조건이 있다.
2. class weight의 통발 recall 차이는 네 조건·각 분할에서 양수였다. 같은 분할을 공유하는 차이들을 독립 증거로 세지 않는다.
3. all은 기존 `s4` 선택 행을 포함하며 그 선택 재현을 확인했다. 학습 예제 단위는 선박으로 유지되지만 유효 학습 선박 수·분포 특징·평가 coverage도 바뀐다.
4. shape9는 절대 규모를 비율로 정규화하며, scale8은 규모 특징을 추가한다. 분류 정보의 중복·기여 메커니즘은 별도 검증이 필요하다.

### 확인되지 않은 것

- **왜 통발 recall이 낮은지는 여전히 모른다.** 세 요인을 다 적용한 셀은 0.05342이고 전체 셀 최대는 0.06684다. 형상 자체의 구분 정보 부족, 시간대 항적과 선박 속성 라벨의 정합성 부족, 관측 창 내 조업 행동의 희소성은 모두 미검증 가설이다.
- **규모 특징 추가의 평균 차이가 all에서 작은 이유**를 측정하지 않았다. 분포 중첩을 보지 않았고 분할별 변동도 크다.
- 비가산성이 "같은 편향을 고친다"는 메커니즘을 입증하지 않는다.
- validation Macro F1은 **선택 지표이며 held-out 점수가 아니다.** 8개 셀을 보고 고른 값이므로 낙관적으로 편향됐다.
- 2025 Test·공식 평가·사고 탐지는 이 문서의 범위가 아니다. 연도 간 분포 차이는 여전히 미측정 위험이다.
- NLL·Brier는 2차에서 계산하지 않았다. 1차 final 관문의 비열등 조건을 그대로 적용할 수 없다.

## 7. 다음 단계

final 1,473척은 **이번 모델의 학습·예측·평가에 사용하지 않았다.** 전체 특징 캐시를 로드했다는 사실과 구별한다. 1차에서 이미 평가했으므로 재평가를 독립된 새 holdout 검증이라고 부를 수 없다.

개발 지표상 Macro F1 최고 셀은 `all/balanced/dist36_scale32`(0.41695), 통발 recall 최고 셀은 `all/balanced/dist36`(0.06684)다. **2026-10-29 현재 재개봉 후보와 판정 기준은 미동결이며 final 재평가 금지를 유지한다.** 목표 지표·최소 개선폭·NLL/Brier 비열등 허용폭·보류 규칙·후보 및 코드 해시를 한 계약에 고정해야 한다.

개봉 전에 우선할 작업:

1. **통발 진단.** 개발 예측을 선박·seed·셀·정답·보류·확률과 함께 보존하고 통발 혼동행렬 행과 연안복합 예측 비율을 계산한다. 특징 분포 중첩과 고정 단순 모델의 AUC·PR-AUC·recall·precision도 분할별로 비교하되, 낮은 AUC를 특징 정보 부재의 상한 증명으로 해석하지 않는다.
2. **라벨-행동 정합성.** 시간대 창에 비조업 이동·정박이 얼마나 섞이는지 센다. 1차가 가설로만 남긴 항목이다.
3. **시간대·위치 정보의 기여 분리.** 2025 Test 일반화 위험이 있으므로 기여와 위험을 같이 측정한 뒤 판단한다.
4. NLL·Brier를 2차 지표에 추가해 1차 final 관문과 비교 가능하게 한다.

위 진단과 선박·월당 관측 행수의 포화 곡선은 후속 제안이며 이번 정정에서 실행하지 않았다. 포화 곡선은 선박 명부·선택 순서를 고정하고 train만 확대/validation만 확대/둘 다 확대를 구분하여 coverage와 함께 보고할 필요가 있다.

### 작업 중 발견하고 고친 결함 2건

1. **`record_ordinal` 기준 불일치.** 1차는 `enumerate(reader, 1)` 즉 1-based다. 2차 초안이 0-based여서 캐시 교차검증 중복이 0건으로 나왔고 quarantine 행 `(5, 127862)`도 다른 행을 건너뛰었다. 1-based로 맞춘 뒤 일치했다.
2. **클래스명 전사 오류로 한 클래스 전량 누락.** `채낚기연승낚시`를 소스에 직접 쓰면서 U+CC44를 U+C3E4로, U+C5F0을 U+C5AC로, U+B09A를 U+B099로 틀렸다. 라벨 해시가 어긋나 **채낚기 180,878행(158척)이 전부 unlabeled로 버려졌다.** 추출 1회차를 중단했다.
   고친 방식은 오타 수정이 아니라 하드코딩 제거다. 추출기는 검증된 라벨 해시 4개만 들고 hash→index로 분류하며, 라벨 문자열은 실행 중 원자료에서 읽어 해시 검증 후 `label_vocabulary.json`으로 내보낸다. 학습 스크립트는 그 파일을 읽고 로드 시점에 해시를 재검증한다. `_rank_key`가 라벨 문자열을 해시하므로 split 재현에 원문이 필요하다.

### 실행 환경 제약

머신 커밋 메모리가 30.8GB 중 28.7GB 사용(물리 여유 1.13GB) 상태여서 백그라운드 실행이 세 번 강제 종료됐다. 워커 메모리를 측정했더니 200,000행에서 58MB로 원인이 아니었고, 동시 실행 수가 문제였다. 전경 단일 프로세스로 파일 하나씩 돌렸고, 큰 파일 4개는 전경 호출 상한 10분을 넘겨 행 interleave 샤드(`record_ordinal % shards`)로 나눴다. 모든 샤드가 파일 전체를 스트리밍하므로 SHA-256 검증은 샤드마다 독립적으로 성립한다. 총 추출 시간 약 75분.
