- 문서 이력: 최초 초안은 2026-10-05 작성. 당시 공식 페이지 설명을 정리했으며 원데이터는 확인하지 않았다.
- 최초 작성일: 2026-10-05.
- 현재 개정일: 2026-10-09.
- 2026-10-05 당시 산출물: 요구사항, 데이터 확인표, 잠정 인터페이스, 단계별 검증 조건, 읽기 전용 구조 점검 도구의 초기 명세.
- 2026-10-05 당시 제외: 데이터 수집 실행, 모델 학습, 시뮬레이터 구현, 3D 뷰어 구현, 실제 장치 연결.
- 2026-10-09 현재 승인 범위: F0→F1 입력 계약 보완, 검사기 강화, 명시적 평면 미터 합성 경로의 계약 검산.
- 현재 후속 관문: 원자료 실제 적합성 확인, 실제 feature pipeline, 모델 학습·평가, 외부 수집, 가상 유닛, 시뮬레이터와 3D는 아직 승인 범위 밖이다.
- 현재 자료 상태: data/raw에는 빈 .gitkeep만 있고, 저장된 outputs/data_inventory.json은 CSV 0개를 보고한다. 원자료의 파일 내용은 확인하지 못했다.
- 검사기 상태: v1.0은 geom 접두부만 확인했다. 현재 v1.1은 제한된 2D MULTILINESTRING 구조·유한 XY·부분선별 최소 2점을 검사하고 EMPTY 문법을 분석 불가로 집계한다. Z/M/ZM/EWKT, 기본 CRS 범위검사, 거리 계산은 지원하지 않는다. 실제 원자료 검증은 미수행이며 구현 결과와 실행 검증은 docs/fishing_verification.md에서 구분해 기록한다.

## 1. 목적과 범위

어선 항적을 분석해 조업 상태를 분류하고 이상 정도를 표현하는 시스템의 초기 조건을 정한다.
목표는 동작하는 시스템과 그 판단 근거를 설명·설계·구현·검증할 수 있는 역량을 함께 다루는 것이다.
2026-10-05 초안에서는 분석 대상과 데이터 계약을 확정할 근거가 부족해 확인 절차를 먼저 정의했다. 2026-10-09 승인으로 입력 계약·검사기 보완과 평면 미터 합성 경로의 계산 검산까지 진행할 수 있다. 실제 항적을 처리하는 feature pipeline은 원자료 확인 전까지 만들지 않는다.

잠정 시스템 흐름은 `선박 활동 → 위치 관측 → 수집·저장 → 항적 구성 → 특징 계산 → 판단 모델 → 뷰어`이다.
위치 센서, 회로, 펌웨어, 통신 수단과 원자료가 AIS인지 여부는 확인되지 않았다.
수집 계층을 직접 개발해야 하는지도 미확인이다. 교육 목표와 장비 필요성이 확인되기 전에는 추가하지 않는다.

최초 작성 당시 확인된 요구는 기존 프로젝트 파일 없이 초기 명세부터 시작한다는 점이었다. 현재 범위는 위의 2026-10-09 개정 이력과 이번 실행 계획을 따른다.
공식 출처는 해양경찰청 주관 [어선 사고예방을 위한 항적데이터 분석](https://aida.kisti.re.kr/competition/main/problem/PROB_000000000004601/detail.do)이며, 아래는 2026-10-05 페이지 설명 확인 내용이다.

- 과제 1: 항적 기반 조업방식 분류. WKT MultiLineString에서 이동거리·방향 변화·선회·직선성·범위 등 공간 특징을 추출한다.
- 과제 2: 정상·사고 항적을 포함한 자료에서 선박별 또는 동일 조업형태의 평상시와 비교해 이상 정도를 산출한다.
- Train에는 조업 라벨이 있고 Test A에는 제거되어 있다. Test A의 선박은 원칙적으로 Train에 없는 신규 선박이다.
- 일부 사고 ID와 발생 시각이 별도 제공된다. Test B의 사고 정보는 숨겨지며 사고 전후 정확도와 조기 탐지를 평가한다. 정확한 지표식은 확인되지 않았다.
- 제공 목록에는 `샘플데이터.csv`(표시 8.5KB), `문제 데이터_수정_0928.zip`(표시 약 630928.8KB)이 있다. 다운로드·내용·크기는 실측하지 않았다.
- 9월 28일 수정 안내에는 1월 `rfid_time` 오류와 4월 중복 수정이 명시되어 있다. 이후 조사 시 사용 버전을 기록한다.

다음 내용은 이전 대화에서 전달된 프로젝트 방향이며, 공식 과제의 필수 구현 요구와 구별한다.

- 시간대별 경로가 있지만 좌표마다 대응하는 시각은 없다는 데이터 설명.
- 단일 판단 모델에서 조업 분류와 이상 점수를 함께 출력한다는 구상.
- 조업 목적, 활동 전환, 환경 반응, 변동 수준을 다루는 가상 유닛과 시뮬레이터 구상.
- 분석 결과와 3D 뷰어의 연계 구상.

단일 모델·시뮬레이터·3D 뷰어는 프로젝트 설계 선택이다. 공식 과제는 두 분석 과제를 제시한다.
공식 설명과 실제 파일의 일치, 전체 라벨 목록, 정확한 평가식과 제출 스키마는 추가 확인해야 한다.

## 3. 원데이터 조사표

공식 설명의 한 레코드는 선박·날짜·시간대 단위이며, 다음 컬럼은 설명 이미지에서 확인했다.
`part_dt`는 YYYYMMDD 날짜, `rfid_id`는 선박 ID, `rfid_time`은 0~23 시간대, `geom`은 WKT MULTILINESTRING, `fishing_code`는 Train의 조업형태 라벨이다.
자망·통발·저인망 등은 설명의 예시이며 전체 클래스 목록과 코드 대응은 미확인이다.
좌표는 경도(X), 위도(Y) 순서로 명시되지만 지리 CRS·측지 기준과 시간대는 미확인이다.
자료를 받으면 아래 표를 실제 컬럼명, 샘플, 근거 파일과 함께 채운다.
값을 추정하여 빈칸을 메우지 않고 `없음`, `미제공`, `미확인`을 구별한다.

| --- | --- | --- |
| 과제·출처 | 공식 문제, 제공 기관, 이용 조건, 제출 형식 | 공식 페이지·설명서 |
| 파일 구성 | 형식, 인코딩, 파일 수, 행 수, 중첩 구조 | 파일 목록·파싱 결과 |

| 표본화 | 주기, 누락, 축약·보간·평활 처리 여부 | 수집·가공 설명 |
| 조업 라벨 | 클래스 의미, 부여 단위, 출처, 불확실성 | 라벨 지침·분포 |

| 품질 | 결측, 중복, 좌표 점프, 잘림, 비정상 순서 | 집계와 표본 검토 |

조사 결과는 원본 보존, 조사에 사용한 파일 식별, 재현 가능한 집계 절차를 포함한다.
샘플로 확인한 구조는 잠정 계약으로 기록한다. 전체 행 수·품질·클래스 분포·분할 중복은 전체자료 집계로 별도 확인한다.
조사마다 검사 파일, 검사 범위, 읽은 레코드 수, 중단 한도와 미검사 범위를 표시한다.
라벨 없는 자료에서 항적 모양만 보고 조업 정답을 임의로 생성하지 않는다.

## 4. 시간·좌표·단위 계약의 확정 조건

계약 확정에는 설명서 근거와 실제 표본의 일치 확인이 모두 필요하다.

1. 시간대 구간은 시작·종료, 현지 시간대 또는 UTC, 날짜 경계와 포함 규칙을 명시한다.
2. 좌표별 시각이 없다면 각 점에 추정 시각을 넣어 실제 관측처럼 취급하지 않는다.
3. 좌표 순서가 불명확하면 경로 길이·방향 변화도 확정 특징으로 사용하지 않는다.
4. 좌표계와 축 순서를 확인한 뒤 거리 계산법과 필요 투영을 선택한다.
5. 위경도 차이를 미터 거리로 취급하지 않으며, 각도 단위와 거리 단위를 구별한다.
6. 위치 정밀도, 경로 축약, 결측 처리와 샘플 간격이 특징에 미치는 영향을 기록한다.
7. 유효하지 않은 좌표·시간은 오류 이유와 함께 격리하며 조용히 삭제·보정하지 않는다.
8. 실시간 처리·허용 지연·메시지 크기·전원·핀·전압은 현재 요구가 없으므로 확정하지 않는다.
9. MULTILINESTRING의 각 부분선은 분리해 처리한다. 부분선 사이를 임의로 연결해 거리·회전·직선성을 만들지 않는다.

시간대의 전체 길이가 알려져도 각 구간의 이동 시간이 알려지는 것은 아니다.
관측 경로가 해당 시간대 전체를 대표한다는 근거 없이는 `경로 길이 ÷ 시간대 길이`를 실제 평균속력이라 부르지 않는다.
보간이 필요하면 목적, 가정과 보간 표시를 남기고 원관측과 분리한다.

## 5. 계산 가능한 특징과 불가능한 특징

아래 가능 여부는 좌표계, 점 순서와 품질이 확인된다는 조건을 가진다.

| 특징 | 좌표별 시각 없이 가능한 범위 | 제한 |
| --- | --- | --- |
| 점 개수·결측·중복 비율 | 데이터 품질 집계 | 행동 특징과 구별 |
| 연결 경로 길이·시작/끝 변위 | 부분선별 관측 점을 이은 공간적 길이 | 실제 이동거리 전체를 보장하지 않음 |
| 경로 굴곡·방향 변화 | 기하학적 형태 비교 | 선박 자세·시간당 회전율과 다름 |
| 공간 범위·분산·재방문 형태 | 공간적 패턴 요약 | 체류 시간이나 방문 횟수는 별도 조건 필요 |
| 속력·가속도·회전율 | 계산 불가 | 대응하는 시각·시간 간격 필요 |
| 정지 시간·조업 지속시간 | 직접 계산 불가 | 연속 시간 관측과 상태 기준 필요 |
| 환경 변화에 대한 반응 | 직접 확정 불가 | 정렬된 환경 관측과 시간 관계 필요 |

기하학적 방향 변화도 좌표 축과 투영에 영향을 받으므로 계산 조건을 기록한다.
호 길이를 기준으로 점을 다시 배치하는 것은 공간 재표본화이며 시간 정보 복원이 아니다.
구간 사이 변화는 연결 순서, 동일 선박 여부와 공백을 확인한 경우에만 분석한다.

## 6. 가상 유닛의 정의와 검증 관문

가상 유닛은 합성 경로를 만들기 위한 설명 가능한 잠정 제어변수이다.
실제 선박의 내부 목적이나 상태를 관측했다고 주장하는 표현으로 사용하지 않는다.

| 유닛 | 잠정 의미 | 채택 조건 |
| --- | --- | --- |
| 조업 목적 | 생성하려는 활동 시나리오 | 실제 클래스 정의와의 대응 근거 |
| 활동 전환 | 시나리오 내 상태 변화 규칙 | 허용 전환, 관측 단위, 라벨 부여 규칙 |
| 환경 반응 | 환경 입력에 따른 경로 변화 가정 | 환경 정보의 의미·단위와 영향 가정 명시 |
| 변동 수준 | 생성 경로 변화의 상대적 크기 Low/Medium/High | 변화량 측정법·허용 범위·재현성 |

High 변동 수준을 이상 정답으로 사용하지 않는다. 변동의 크기와 이상 판단은 별개의 변수이다.
조업 분류의 핵심 특징을 깨는 변형을 한 뒤 원래 조업 라벨을 그대로 유지하지 않는다.
의미가 불명확한 합성 표본은 미라벨 또는 사용 보류로 처리한다.

- 관문 V1: 각 유닛이 바꾸는 변수, 유지해야 하는 조건, 난수 시드가 기록되는가?
- 관문 V2: 좌표·시간 계약과 생성 제약을 지키는가? 위반 표본을 탐지할 수 있는가?
- 관문 V3: 변형 후 라벨 의미가 유지되는가? 근거 없으면 학습 자료에서 제외하는가?
- 관문 V4: 실제 자료와 비교할 수 있는 특징 분포·한계가 정리되는가?
- 관문 V5: 해당 유닛이 목표 역량 또는 평가에 기여하는가? 기여 없으면 제거하는가?

환경 자료나 물리 모델 근거가 없으면 환경 반응은 가설적 시나리오로만 제시한다.
환경자료의 관측 시각과 공개·수신 가능 시각을 구분한다. 조기 탐지 입력에는 판단 당시 이용 가능했던 자료만 사용한다.
사후 재분석·보정 자료를 사용한 실험은 별도로 기록하며 실제 조기 탐지 조건의 평가와 구분한다.

## 7. 단일 모델·두 출력의 잠정 계약

잠정 구조는 하나의 입력 처리 흐름과 공유 표현에 조업 분류 출력 및 이상 점수 출력을 두는 것이다.
모델 계열, 신경망 사용 여부, 손실함수와 학습 방식은 아직 정하지 않는다.
분석 단위는 제공 라벨 단위와 시간 정보 확인 후 경로 또는 구간 등으로 확정한다.

- 조업 출력: 확정 클래스 목록에 대한 예측. 점수는 보정 검증 전 신뢰할 수 있는 확률로 단정하지 않는다.
- 이상 출력: 정의된 기준에서 벗어나는 정도. 점수 방향·범위·비교 가능 범위는 방식 선택 시 명시한다.
- 오류 출력: 입력 부적합, 정보 부족, 판단 불가를 정상/조업 외 클래스와 분리한다.
- 부가 정보: 입력 출처, 처리 버전, 모델 버전, 적용 가능한 조건을 보존한다.

라벨 가용성 관문은 다음과 같다.

1. 조업 정답이 없다면 지도학습 분류의 성능을 주장하지 않는다. 라벨 확보 또는 목표 변경이 선행한다.
2. 이상 정답이 있다면 정의·단위·판정 일관성을 검토한 뒤 지도학습 평가 가능성을 판단한다.
3. 이상 정답이 없으면 비지도 점수를 후보로 검토할 수 있으나 이상 탐지 정확도는 입증되지 않는다.
4. 조업 클래스 불확실성과 행동의 이상 여부를 같은 의미로 취급하지 않는다.
5. 두 출력을 함께 학습하려면 각각의 목표·정답·결측 라벨 처리와 출력 간 간섭을 검증한다.
6. 단일 모델 제약이 목표를 훼손하면 원인과 유지·변경안을 검토한 후 구조를 결정한다.
7. 사고 ID·시각은 모든 항적의 이상 정답을 뜻하지 않는다. 사건 전후 라벨을 만들려면 시간 창과 의미를 별도 정의한다.
8. 신규 선박에 과거 기준이 없을 때 동일 조업형태 기준의 사용 가능성 및 판단 유보 조건을 정한다.

## 8. 평가와 데이터 누수 방지

실제 자료 평가, 합성 자료 평가, 코드 테스트, 실제 장치 실험은 각각 별도 결과로 기록한다.
합성 자료 성능을 실제 선박 일반화 성능으로 보고하지 않는다.

- 분할 단위는 선박, 항차, 연속 구간의 중복 구조와 실제 사용 목적을 보고 정한다.
- 겹치는 경로 구간과 같은 원본의 증강본이 학습·평가 양쪽으로 넘어가지 않게 한다.
- 분할 역할은 평가 전에 고정한다. 모델, 스케일·변환, 정상 기준은 학습 분할에서만 적합한다.
- 하이퍼파라미터와 운영 임계값은 지정 검증 분할에서 선택한다. 점수·확률 보정이 필요하면 별도의 보정 분할을 사용한다.
- 최종 평가 분할은 모든 선택·적합·보정에서 제외하고 마지막 평가에만 사용한다. 선박 분리와 시점 가용성 조건을 모든 분할에 적용한다.
- 시간 일반화가 목적이면 시간 순서를 지키고, 새 선박 일반화가 목적이면 선박 분리를 검토한다.
- 공식 Test A 조건에 맞춰 선박이 겹치지 않는 검증을 우선 설계한다. 조기 탐지는 판단 시점 이후 항적·사고 정보를 입력에 사용하지 않는다.
- 정상 기준 추정에 평가 선박의 미래 항적을 섞지 않는다. 사고 미표시를 곧바로 정상 정답으로 취급하지 않는다.
- 선박 식별자·제공 파일명 등 정답을 우회적으로 드러내는 정보의 사용 여부를 검사한다.
- 합성 자료로 학습하더라도 실제 평가 자료의 특징이나 라벨을 생성 규칙 조정에 사용하지 않는다.
- 생성기 버전·시나리오·생성 실행·부모 표본 식별자를 보존하고, 같은 실행의 상관 표본이 분할을 넘는지 검사한다.
- 생성 상태값·규칙 ID·고정 패턴이 라벨을 직접 드러내는지 검사한다. 추적용 생성 메타데이터와 모델 입력을 구분한다.
- 시간대 전체 항적을 사용하는 경우 그 구간 종료와 처리 지연 이후를 판단 가능 시점으로 삼는다. 구간 안 사고보다 앞서 탐지했다고 주장하지 않는다.

공식 지표식이 확인되면 그것을 우선한다. 아래 지표는 후보이며 확정 요구사항이 아니다.
조업 분류는 클래스별 정밀도·재현율, macro F1, 혼동행렬, 클래스별 표본 수를 검토한다.
이상 정답이 있으면 PR-AUC 및 운영 임계값에서의 오탐·미탐을 검토한다.
사고 시각과 탐지 기록을 연결할 수 있으면 사건 단위 탐지율·선행 시간·오경보 빈도를 검토하되, 시간대 해상도가 주는 한계를 명시한다.
이상 정답이 없으면 점수 분포·안정성·사례 검토를 보고하며 정확도나 재현율을 산출하지 않는다.
성능 수치에는 평가 단위·자료 출처·표본 수를 붙이고, 상관된 점들을 독립 표본처럼 세지 않는다.
합성 자료의 효과는 동일한 실제 평가 조건에서 합성 자료 사용 전후를 비교한다.

## 9. 시뮬레이터·모델·뷰어의 잠정 전달 규격

시뮬레이터는 합성 출처와 생성 조건을 전달하고, 모델은 입력 검증 후 결과를 반환한다.
뷰어는 관측 경로·합성 경로·추정 결과의 출처와 정보 부족 상태를 구별해 표시한다.
시간이 없는 경로의 재생 속도는 시각화 설정이며 실제 선박 속도로 표시하지 않는다.
3D의 높이·깊이는 데이터 근거가 없는 한 물리적 관측량으로 해석하지 않는다.

아래는 메시지 역할을 설명하기 위한 예시이며 확정 스키마나 실제 데이터가 아니다.
좌표계 미확인 상태를 표현하려고 좌표 값을 비워 두었다. 이 예시는 모델 추론 입력으로 유효하지 않다.

```json
{
  "schema_status": "draft_example",
  "source_type": "synthetic_example",
  "trajectory_id": "example-001",
  "time": {"kind": "block_only", "start": null, "end": null, "timezone": null},
  "parts": [],
  "coordinate_contract": {"crs": null, "axis_order": null, "unit": null},
  "generation": {"scenario": "example_only", "variation_level": "High", "seed": 1},
  "labels": {"fishing_class": null, "anomaly": null},
  "prediction": {"fishing_class": null, "anomaly_score": null},
  "status": "insufficient_information"
}
```

확정 시 필수/선택 필드, 결측 규칙, 버전, 식별자, 점 순서, 단위, 오류 코드를 함께 정의한다.
부분선별 좌표 배열 또는 명시적인 부분선 식별·경계를 보존한다. 부분선 간 순서의 근거도 기록하며 평탄화로 단절을 없애지 않는다.
공식 제출 예시에는 파일명·예측 조업형태·예측 조업확률(0~1)·이상 항적점수(0~1)가 있다. 예시를 확정 CSV 스키마로 간주하지 않으며 내부 전달 규격과 제출 변환을 구별한다.
원래 라벨과 모델 예측은 덮어쓰지 않는다. 모델 점수의 범위·방향과 뷰어 표현도 함께 검증한다.

## 10. 단계별 기술 목표와 학습 목표

아래 표는 프로젝트의 장기적인 학습 순서를 설명한다. 2026-10-09 현재 제작 승인은 F0→F1의 입력 계약 보완, 검사기 강화, 평면 미터 합성 경로의 부분선별 길이·변위·직선성 검산까지다. 표의 실제 항적 처리·모델·가상 유닛·화면 구현은 원자료와 후속 관문을 통과하기 전의 작업으로 남는다.

| 단계 | 기술 목표·구현물 | 학습 목표·관찰할 현상 | 검증 방법 | 설명할 질문 |
| --- | --- | --- | --- | --- |
| 0. 초기 명세 | 요구·가정·확인표 작성 | 증거와 추정의 차이 | 단정한 미확인 사실이 없는지 검토 | 무엇을 아직 알 수 없는가? |
| 1. 자료·계약 확인 | 조사표와 입력 계약 | 시간·좌표·라벨의 의미 | 설명서와 표본 대조 | 왜 이 자료로 속력을 구할 수 있는가/없는가? |
| 2. 작은 전체 흐름 | 한 항적 읽기→검증→기하 특징→간단 표시 | 데이터가 결과로 바뀌는 흐름 | 작은 수작업 예시와 계산 대조 | 그림과 수치가 다르면 어느 계층을 볼 것인가? |
| 3. 판단 기준선 | 라벨 조건에 맞는 최소 모델과 평가 | 예측·정답·오류 해석 | 분할과 기준선 비교 | 높은 점수가 조업 이상을 뜻하는 근거는 무엇인가? |
| 4. 제한된 합성 실험 | 검증된 유닛 하나와 변형 기록 | 통제 실험·라벨 보존 | 합성 전후 및 실제 평가 비교 | 어떤 변형이 라벨을 무효로 만드는가? |
| 5. 확장 판단 | 필요한 신뢰성·예외 처리·뷰어 연계 | 고장 진단·조건 변경 대응 | 요구별 실패 사례와 재검증 | 복잡성을 늘릴 교육적·기술적 이유는 무엇인가? |

단계마다 이전 구현의 동작 확인과 학습자의 설명 확인을 별도로 기록한다.
학습자 지원에서는 핵심 판단을 직접 수행하게 하고, 도구 사용과 반복 변환은 적극 지원한다.
실험 기록은 조건, 예상 결과, 측정 또는 계산값, 해석을 포함한다.
실패는 원자료/수집, 시간·좌표 계약, 전처리·특징, 모델, 전달·뷰어 계층으로 좁혀 간다.
직접 장치를 다루게 되면 하드웨어·펌웨어·통신 계층을 별도로 추가하고 허용 조건을 먼저 확인한다.

## 11. 이번 단계 완료 기준과 다음 단계 시작 조건

2026-10-05 초기 명세의 작성 기준은 범위·가정·미확인 사항·검증 관문·평가 분리를 문서화하는 것이었다. 그 이력은 유지한다. 2026-10-09에 제작 승인이 입력 계약 보완, 검사기 강화, 평면 미터 합성 경로의 명시적 적합성 검산까지 추가되었다.

현재 F0→F1 준비의 문서 기준은 다음과 같다.

- 데이터 조건을 공식 설명, 설계 가정, 직접 확인한 저장소 상태로 구분한다.
- 검사기 v1.1의 실제 기능과 한도를 구분한다: 제한된 2D MULTILINESTRING 구조, 유한 XY, 부분선별 최소 2점, EMPTY 문법 인식 후 분석 불가 집계, Z/M/ZM/EWKT 미지원, 기본 CRS 범위검사·거리 계산 없음. 헤더는 알려진 항목만 보고하고 후보키 충돌은 표본 집계이며 전체 고유성 검증이 아니다. lookahead 파싱 오류에서는 표본 행을 보존한다.
- 명시 합성 fixture의 부분선별 길이·변위·직선성, 총 길이 20 m와 금지연결 반례를 기록한다. 부분선 사이를 잇지 않고 사이 이동길이는 미관측으로 둔다. 전체 직선성·부분선 변위 합계는 만들지 않는다.
- 분할 역할을 사전 고정하고 학습/검증/보정/최종 평가 자료의 사용 경계를 문서화한다. 이는 실제 분할이나 학습을 실행했다는 뜻이 아니다.
- 후속 작업·소유자·완료 근거를 docs/fishing_execution_plan.md 및 docs/fishing_verification.md에 연결한다.

문서 기준을 채운 것은 실제자료 적합성 완료나 학습 성취를 뜻하지 않는다. data/raw에 원자료가 없어 실제 스키마·좌표계·시간·라벨 적합성은 판정할 수 없다. 검사기와 합성 계산의 코드 검증 결과는 [검증 기록](fishing_verification.md)에서 실제 자료 검증과 구분해 참조한다.

실제 F1 전체 자료 적합성 관문은 원자료를 식별하고 공식 설명과 실제 헤더·표본을 대조하며 검사 범위·미검사 영역과 라벨 의미를 기록한 뒤 닫는다. 이 전체 관문을 닫기 전이라도, 식별 가능한 대표 원자료의 핵심 시간·좌표·기하 입력 계약이 확인되면 무라벨 F2 기하 점검은 별도로 시작할 수 있다. 이 제한된 F2는 조업 라벨과 평가 분할을 요구하지 않으며, 점별 시각이 없다는 시간 계약을 확인한 경우 속력·가속도 없이 기하만 검증한다. 조업 분류와 이상 기준선·평가는 라벨 의미 및 평가 분할 근거가 필요한 F3 범위다. 실제 모델 학습·평가, 외부 수집, 가상 유닛, 시뮬레이터, 3D 구현은 각 후속 관문과 별도 승인 전에는 진행하지 않는다. 각 단계에서 산출물의 동작과 학습자의 설명을 따로 확인한다.
