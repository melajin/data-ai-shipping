# 어선 제작 준비 단계 검증 기록

> 2026-10-12에 사용자 요청으로 S0 합성 데이터 학습·시각화를 추가했다. 최신 실행은 [S0 검증 기록](fishing_sample_verification.md)과 [학습·팀 설명서](fishing_sample_system_guide.md)를 따른다. 아래 내용은 2026-10-09 준비 단계의 이력이다.

기록일은 2026-10-09이다. Astra high가 F0→F1 기술준비 단계의 범위를 최종 승인했고 기술 검증이 완료됐다. 실제 원자료 적합성·모델 학습·실제 성능·장치 실험과 학습자의 성취를 확인한 기록은 아니다.

## 모델 배치와 실제 작업

| 담당 작업 | 지정하여 생성한 모델 | effort | 결과 |
| --- | --- | --- | --- |
| 범위·계약·결정·근거 | GPT-6 Astra | high | 현재 단계 범위와 세 설계 결정 |
| 독립 검토·간단한 읽기 조건 보완 | GPT-6.1 Sol | high | 입력·보고·범위 검토와 읽기 경계 수정 |
| WKT·헤더·표본 보고 구현 | GPT-6.1 Sol | max | 검사기 1.1 및 합성 회귀 테스트 |
| 확정된 합성 검산 모듈 | GPT-6.1 Sol | xhigh | 예제 JSON·검산 CLI·경계 테스트 |
| 제작 문서·정합성·목차 경로 | GPT-6 Luna | xhigh | 실행 계획, 프롬프트와 관련 문서 갱신 |

하위 에이전트는 생성 요청에 모델과 effort를 명시했다. 프로젝트의 [.codex 설정](../.codex/config.toml)은 이후 세션용 기본값이며 현재 부모 세션의 모델을 변경했다는 기록이 아니다. 역할별 설정은 [.codex/agents](../.codex/agents)에 있다. 실제 실행 요청과 최종 검사 결과는 [실행 보고서](../outputs/fishing_execution_report.json)에서 확인한다.

## 결정과 검토 근거

- Astra high는 원자료가 없는 상태에서 실제 특징 파이프라인·학습으로 확장하지 않고 검사기와 명시적 합성 검산을 이번 범위로 정했으며, 마지막 범위 검토에서 기술준비 완료를 승인했다. 실제 F1 자료 적합성은 계속 미확인이다.
- Sol high는 접두어만 맞는 잘못된 WKT와 알려진 컬럼명이 섞인 무헤더 입력의 값 노출, 표본 이후 CSV 오류로 앞선 집계가 사라지는 문제를 합성 사례로 재현했다. Sol max가 구조 검사·화이트리스트 출력·표본 보존으로 보완했다.
- Astra high는 EMPTY를 문법 인식 성공·분석 불가로 구분하고 문제 상태와 종료코드 1을 반환하는 계약을 승인했다. 지원하지 않는 표현과 잘못된 구문도 구분한다.
- Astra high는 전체 집계 직선성과 부분선 변위 합계가 불필요하다고 결정해 제외했다. 부분선별 길이·변위·직선성과 전체 길이 20 m, 금지연결 교육 반례만 남겼으며 반례는 관측값이 아니다.
- 분할 역할은 평가 전에 고정한다. 모델·스케일/변환·정상 기준은 학습 분할에서 적합하고, 하이퍼파라미터·운영 임계값은 지정 검증 분할에서 선택한다. 점수·확률 보정이 필요하면 별도 보정 분할에서 수행하며 최종 평가 자료는 모든 선택·적합·보정에서 제외한다. 모든 분할에 선박 분리와 시점 가용성 조건을 적용한다. 실제 분할·학습은 하지 않았다.

## 재실행

프로젝트 폴더에서 Python 3.10 이상으로 다음 명령을 실행한다. 최종 검증 환경의 Python 버전은 실행 보고서에 기록한다.

```powershell
python -B -X utf8 -m unittest discover -s tests -v
python -B -X utf8 tools/inspect_data.py data/raw --output outputs/data_inventory.json
python -B -X utf8 tools/check_synthetic_contract.py examples/fishing_contract_synthetic.json --output outputs/synthetic_contract_report.json
python -B -X utf8 docs/ai_textbook/validation/check_book.py
```

현재 원자료 폴더에는 `.gitkeep`만 있다. [조사 보고서](../outputs/data_inventory.json)의 CSV 검사 수 0은 미검사 상태이며 자료 적합성 통과가 아니다. 2 MiB보다 큰 파일과 ZIP은 메타데이터만 검사한다. CSV는 기본 최대 100개 레코드에 의미 검사를 수행하며 파일 읽기·CSV 파싱·의미 검사 범위를 구분한다.

## 결과와 한계

통합 실행 환경은 Python 3.13.3이었다. 실행 결과는 [통합 보고서](../outputs/fishing_execution_report.json), [테스트 결과](../outputs/fishing_test_results.json), [합성 수치 보고서](../outputs/synthetic_contract_report.json), [교재 구조 보고서](ai_textbook/validation/structure_report.json), [입력 조사 보고서](../outputs/data_inventory.json)에서 재현·확인할 수 있다.

| 검사 | 결과 | 범위와 제한 |
| --- | --- | --- |
| 자동 테스트 | 41개 실행, 40개 통과, 실패 0, 오류 0 | 심볼릭 링크 생성 테스트 1개는 현재 Windows 환경에서 링크 생성 제약으로 skip. 실패로 세지 않음 |
| 합성 기하 계약 | 12개 모두 통과: 부분선 기하 10개, 금지연결 반례 2개 | 평면 XY·미터 교육 fixture의 계산 일치만 확인 |
| 교재 구조 | 문서 43개, 장 32개, 오류 0, 경고 0 | 구조 검사 결과이며 내용의 과학적 정확성이나 학습 성취를 뜻하지 않음 |
| 설정 검사 | TOML 파일 6개 파싱, 역할 프로필 5개가 지정 모델·effort와 일치 | 이후 세션용 설정이며 현재 부모 세션을 재설정했다는 뜻이 아님 |

합성 fixture에서 부분선 A는 길이 8 m·변위 sqrt(52) m·직선성 약 0.9014, B는 길이와 변위가 각각 12 m·직선성 1이다. 길이 합은 20 m다. 부분선 사이 이동은 관측되지 않았다. 금지연결 교육 반례의 인위 구간은 94.0850679 m, 이를 더한 잘못된 길이는 114.0850679 m이며 실제 feature가 아니다. fixture에는 점별 시각과 조업·이상 라벨이 없어 속력·가속도나 사고 판정을 만들지 않는다.

검사기는 제한된 2D MULTILINESTRING 구조, 유한 XY와 부분선별 최소 2점을 검사하며 EMPTY는 문법 인식·분석 불가로 분류한다. 알려진 헤더만 보고하고 미지 헤더는 개수로 집계한다. 후보키 충돌은 검사 표본 안의 집계다. 좌표 원문을 출력하지 않고 부분선을 연결하거나 거리·속력을 계산하지 않으며, 조업·이상 점수도 산출하지 않는다. 기본 CRS 범위 검사는 없고 명시한 `--coordinate-assumption lonlat`은 CRS 확인이 아닌 가정 기반 범위 검사다.

현재 `data/raw`에는 `.gitkeep`만 있으며 저장 inventory의 CSV 검사 수는 0이다. 따라서 실제 스키마·좌표·시간·라벨 적합성 및 실제 데이터 성능은 미검증이다. 실제 모델 학습과 장치 측정도 수행하지 않았다. Astra는 기술준비 완료를 승인했지만, F1 자료 적합성·전체 시스템 구현·학습 성취 완료를 승인한 것은 아니다. 실행 계획의 T02 독립 검토, T05 문서 정합성, T06 통합 검토와 읽기 경계 보완은 완료되었다.
## 기술 완료와 학습 성취

기술 완료는 지정된 코드·설정·문서의 검사를 근거로 판정한다. 학습자의 F0/F1 성취는 아직 미확인이다. 다음 질문에 독립적으로 설명하고 조건을 바꾸어 계산한 기록이 필요하다.

1. 부분선 사이 거리를 더하면 왜 실제로 관측된 길이가 아닌가?
2. 좌표계 미확인 기본 입력과 평면 미터 합성 예제는 어떤 근거가 다른가?
3. EMPTY의 문법 인식과 분석 가능성은 어떻게 다른가?
4. 점별 시각이 없을 때 실제 속력을 구할 수 없는 이유는 무엇인가?
5. 코드 테스트, 합성 검산, 실제 데이터 평가가 각각 무엇을 입증하는가?

F2 무라벨 기하 점검은 식별 가능한 대표 원자료와 핵심 시간·좌표·기하 계약이 확인되면 시작할 수 있다. 조업 라벨 의미와 평가 분할은 F2의 선행조건이 아니며 F3 분류·이상 기준선의 조건이다. 점별 시각이 없다고 시간 계약을 확인한 경우 F2에서는 속력 없이 기하만 점검한다. 전체 작업 순서는 [실행 계획](fishing_execution_plan.md)을 따른다.
