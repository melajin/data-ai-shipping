# 공개 모델 사례로 이론 읽기

[교재 길잡이](모델%20해석%20목차.md) · [출처 색인](92_sources.md)

확인일: **2026-10-06**. 아래는 공개된 연구·문서에서 이론 연결이 뚜렷한 사례를 선별한 것이다. 해당 자료의 발표 당시 모델·설정에 관한 설명이며 최신 모델 순위나 회사 전체의 역량 비교가 아니다. 제품의 가격·현행 지원 기능·비공개 내부구조는 여기서 확정하지 않는다.

각 사례에서 **공개 사실**, **그 사실에 연결한 학습 해석**, **저자·회사의 평가 주장**, **미확인 사항**을 나눈다. 논문의 성능 표는 대상 자료·기준선·평가 절차의 조건에서 읽고, 이 교재에서 재현하거나 독립 검증한 수치로 표현하지 않는다.

이 표에서 “과제의 중심”은 공개된 목표를 뜻한다. 예를 들어 전사를 잘하도록 설계한 모델과 프롬프트 분할 모델은 같은 점수 하나로 우열을 매길 대상이 아니다. 특화 판단은 어떤 입력과 출력, 조건과 평가를 요구하는지부터 정한다.

## InstructGPT: 사전학습과 행동 적응을 나누기

**공개 사실.** 원논문은 GPT-3에서 출발해 시연 자료로 지도 미세조정하고, 응답의 선호 순위 자료를 이용해 인간 피드백 기반 강화학습으로 조정한 연구를 설명한다. 지시를 받는 텍스트 입력과 응답이 중심이다. [Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)

**이론 연결.** 09장의 “학습 신호·재사용” 축으로 보면 이미 학습한 표현을 재사용하고, 시연이라는 지도 신호와 선호·보상 신호를 다른 단계에서 이용한다. 11장의 정책 최적화와 12장의 SFT·RLHF를 연결할 수 있다. 더 큰 모델과 사용자에게 더 선호되는 행동은 같은 질문이 아니다.

**평가와 미확인.** 저자들은 자신들의 프롬프트 분포와 인간 평가 등에서 결과를 보고한다. 그 결과를 모든 요청의 사실성이나 회사의 현재 전체 모델에 대한 보장으로 확대하지 않는다. 현행 비공개 모델의 자료·구조·학습법은 이 논문만으로 확인할 수 없다.

확인 질문: 시연의 “좋은 답”과 선호 비교의 “더 좋은 답”은 같은 레이블인가? 인간 선호가 늘어도 사실 검증과 분포 밖 평가는 왜 남는가?

## CLIP: 자연어를 시각 개념의 조건으로 쓰기

**공개 사실.** CLIP 연구는 이미지–문장 쌍의 대응을 학습하고, 자연어로 지정한 시각 개념을 이용해 여러 과제의 zero-shot 평가를 수행한다. 새 데이터셋의 정답 레이블로 그 데이터셋 전용 모델을 다시 학습하지 않는 평가 조건을 구분한다. [Learning Transferable Visual Models From Natural Language Supervision](https://arxiv.org/abs/2103.00020)

**이론 연결.** 09장의 대조학습과 13장의 모달 정렬·공통 표현이다. 이미지와 후보 텍스트의 유사도로 선택을 만들 수 있다. 후보 문구·템플릿·집합을 바꾸면 과제 정의와 예측이 달라지므로 단순히 이미지에 고정된 클래스 확률이 존재한다고 읽지 않는다.

**평가와 미확인.** zero-shot은 어떠한 시각 자료도 배우지 않았다는 뜻이 아니다. 사전학습에 이용한 이미지–문장 자료와 후속 평가의 구분이다. 저자의 데이터·평가 결과가 임의 환경의 보정된 확률이나 모든 시각 과제의 성공을 보장하지 않는다.

확인 질문: 새로운 클래스 이름의 문구를 바꾸는 것이 왜 성능 조건인가? 대조 표현과 이미지 생성 모델은 무엇이 다른가?

## Whisper: 약지도와 시퀀스 전사의 연결

**공개 사실.** Whisper 논문은 대규모 약지도 음성 자료를 이용한 다국어 음성 인식·번역을 설명한다. 입력은 오디오, 주된 출력은 전사·번역 토큰열이다. [Robust Speech Recognition via Large-Scale Weak Supervision](https://arxiv.org/abs/2212.04356)

**이론 연결.** 09장의 신호 출처, 12장의 토큰 시퀀스, 13장의 시간·주파수 표현과 가변 길이 출력을 함께 읽는다. 약한 감독 신호는 양이 많더라도 완전한 정답이라는 뜻이 아니며 자료 잡음과 언어별 조건이 중요하다.

**평가와 미확인.** WER 등의 점수는 언어, 잡음, 전사·정규화 규칙에 따라 해석한다. 음성 인식 모델이라는 공개 사실을 음성 합성 기능으로 바꾸어 읽지 않는다. 현행 모든 장치·억양·희귀 언어의 정확도나 운영 지연은 별도 확인 대상이다.

확인 질문: 같은 전사를 대소문자·문장부호 기준을 달리 평가하면 왜 점수가 달라지는가? 학습 신호가 약할 때 잡음과 실제 언어 변화를 어떻게 나눌 것인가?

## SAM: 출력 단위가 분할 마스크인 경우

**공개 사실.** SAM은 이미지의 점·상자 등 프롬프트를 받아 분할하는 promptable segmentation 연구다. 논문은 모델과 SA-1B 자료 구축을 설명한다. [Segment Anything](https://arxiv.org/abs/2304.02643)

**이론 연결.** 01장의 출력 명세와 13장의 인식·검출·분할 구분이다. 한 이미지의 클래스 하나를 맞히는 것과 사용자가 지정한 대상의 픽셀 경계를 출력하는 것은 다른 문제다. 프롬프트가 과제 입력의 일부이므로 동일한 이미지라도 요청 조건이 바뀐다.

**평가와 미확인.** 경계·객체 크기·자료 도메인·프롬프트 방법과 IoU 등을 함께 확인한다. “어떤 대상도 의미를 알고 항상 정확히 분할한다”는 무조건적 해석은 원논문의 문제 정의를 넘는다. 의료·특수 센서·분포 밖 자료에 대한 실사용 성능은 이 교재에서 검증하지 않았다.

확인 질문: 상자 프롬프트가 조금 바뀌었을 때 어떤 출력 차이를 평가할 것인가? 전체 픽셀 정확도와 작은 객체의 IoU는 왜 다른가?

## GraphCast: 그래프와 반복 동역학 예측

**공개 사실.** 개발자의 공개 설명은 GNN 기반 날씨 예측을 다루며 두 시점의 날씨 상태를 입력해 6시간 뒤를 예측하고 그 결과를 반복 사용하는 흐름을 설명한다. [GraphCast: AI model for faster and more accurate global weather forecasting](https://deepmind.google/blog/graphcast-ai-model-for-faster-and-more-accurate-global-weather-forecasting/)

**이론 연결.** 14장의 그래프 관계와 시간 예측, 11장의 모델 rollout, 16장의 과학 AI를 연결한다. 여기서 그래프는 사회 관계만이 아니라 공간 물리량의 정보를 전달하는 표현이 될 수 있다. 한 단계 오차와 긴 예보의 누적 오차는 별도 질문이다.

**평가와 미확인.** 개발자의 속도·정확도 비교는 자신들이 공개한 평가 조건의 주장으로 귀속한다. 이 교재에서 운영 환경과 독립 재현을 시험한 결과는 아니다. 예측 모델의 성공을 임의 개입에 대한 인과효과나 물리 법칙의 완전한 보장으로 바꾸어 읽지 않는다.

확인 질문: 다음 상태를 다시 입력할 때 오차가 어떻게 누적될 수 있는가? 그래프 구조와 평가 지역·시점·변수 조건을 왜 함께 기록해야 하는가?

## TypeSafe Jev: 형식과 판단·실행을 분리하기

**공개 사실.** TypeSafe 공식 문서는 Jev에 상태와 형식이 정해진 질문을 제공해 구조화된 판단을 받는 인터페이스를 설명한다. Choice는 선택과 선택지 확률, Score는 기준에 따른 점수와 수준 확률, Noul은 0~1 값을 반환한다. Choice·Score에는 confidence가 있고 Noul에는 별도 confidence가 없다. [공식 Introduction](https://docs.typesafe.ai/introduction), [Primitives](https://docs.typesafe.ai/primitives)

**이론 연결.** 01장의 출력 명세, 17장의 스키마·후속 실행과 18장의 정확도·보정이다. 공급자의 “System One” 명칭은 제품 설명으로 기록하며 모든 AI를 나누는 표준 학습 분류로 사용하지 않는다.

공식 Choice confidence는 선택지가 $n>1$개이고 선택 확률의 최댓값이 $p_{\max}$일 때 $(p_{\max}-1/n)/(1-1/n)$이다. 공식 문서와 같은 교육용 분포 $(0.6,0.3,0.1)$을 가정하면 confidence는 0.4다. $(0.6,0.2,0.2)$도 0.4이므로 분포의 모든 차이를 담는 값은 아니다. [Confidence 공식 정의](https://docs.typesafe.ai/confidence)

**평가와 미확인.** 위 계산은 공식 예시 분포를 함수에 대입해 검산한 것이며 실제 호출 결과가 아니다. confidence 0.4를 정답률 40%로 읽지 않는다. 형식 준수·판단 정확도·확률 보정·분포 밖 실패를 따로 확인하고, 후속 실행의 허용 권한은 시스템 정책으로 별도 결정한다. 비공개 구조·학습 자료·발표일·타사 대비 우월성은 추정하지 않는다.

확인 질문: 언제 구조화된 출력이 도구 연결에 유용한가? 높은 confidence가 있어도 실제 쓰기 권한을 따로 확인해야 하는 이유는 무엇인가?

## 새 사례를 추가하는 기록 틀

회사·모델·버전, 원출처 공개일과 확인일, 과제·입출력·시스템 경계, 공개된 구조·학습 신호, 이론 연결 근거, 평가 조건·회사 주장과 독립 검증, 비용·지연의 조건·시점, 비공개·미확인, 학습 질문을 남긴다.

새 모델을 읽을 때 “어느 회사가 최고인가?”부터 묻기보다 **어떤 과제·신호·표현·계산·시스템 조건을 공개했고 무엇이 평가됐는가?**를 묻는다. 비교 가능한 조건이 없으면 순위 대신 확인 공백을 기록한다.
