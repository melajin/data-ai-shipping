# M17. 시스템과 인프라: 모델을 연결하고 운영하기

관련 축은 ⑦ 시스템 구성과 ⑧ 신뢰성이다. 모델의 매개변수와 입력·출력 사이에 데이터, 검색, 실행 도구, 권한, 상태, 비용, 오류 처리가 있다. 이 장은 작은 흐름을 먼저 설명·검증하고, 필요한 경우에만 분산·압축·자동화를 확장한다. 특정 API, GPU나 외부 서비스 가입은 필수 조건이 아니다.

## 1. 목표와 선수 질문

기술 목표는 입력 → 처리 → 출력 → 검사 흐름에 명세와 로그를 붙이는 것이다. 학습 목표는 오류가 모델·검색·권한·실행 중 어디에서 발생했는지 좁히고, 비용이나 데이터 조건이 바뀌었을 때 설계를 수정하는 것이다. 최소 산출물은 연결도, 단계별 입출력 표, 오류 상태표, 가상 비용·지연 계산이다. 코드 실행이 성공한 것과 학습자가 인터페이스와 실패 원인을 설명한 것은 별도 기록한다.

선수 질문: 동일한 모델이 다른 검색 자료를 받으면 어떤 부분이 달라지는가? 요청당 지연과 초당 처리량은 같은 지표인가? 모델이 도구 호출 문자열을 만들면 실제 실행 권한도 생기는가? 배열·복잡도·메모리는 M04, 신경망 학습은 M08, 언어모델 문맥과 디코딩은 M12, 평가는 M18과 연결한다.

## 2. 데이터·학습·서비스 파이프라인

데이터 파이프라인은 원천 수집 → 형식·단위 확인 → 정제 → 분할 → 변환 → 버전 기록의 흐름이다. 결측값 처리, 정규화 통계, 어휘나 특징 사전은 학습 집합에서 정한 뒤 검증·평가 집합에 적용한다. 전체 데이터에서 미리 정한 통계나 같은 사람의 중복 자료가 분할을 넘어가면 평가가 새 입력의 성능을 과장할 수 있다. 데이터 버전은 내용뿐 아니라 생성 시점, 대상, 허용 이용 범위, 처리 규칙을 포함한다.

학습 파이프라인은 데이터 버전·모델 설정·초기값 → 학습 → 검증 → 선택 → 최종 평가 → 저장의 흐름이다. 서비스 파이프라인은 요청 명세 → 입력 검사 → 검색 또는 모델 실행 → 결과 검사 → 응답 → 관측의 흐름이다. 저장한 매개변수만 같다고 서비스가 같은 것은 아니다. 토큰화·전처리·검색 인덱스·출력 규칙이 바뀌면 동작도 달라진다. 학습·검증·서비스에 쓰인 구성요소 버전을 함께 기록한다.

인터페이스는 “JSON을 쓴다”에서 끝나지 않는다. 문자열 인코딩, 필드 이름·자료형, 필수 여부, 단위·범위, 길이 제한, 처리 주기, 시간 제한, 오류 코드를 정한다. 날짜 문자열은 시간대와 형식을, 센서값은 °C 같은 단위와 샘플 시각을 붙여야 한다. 예를 들어 입력 필드 `temperature`가 30이라는 숫자만 담으면 섭씨·화씨·정규화 값인지 알 수 없다. 형식 검사를 통과했다고 의미가 옳은 것도 아니다.

## 3. 분산 계산은 무엇을 나누는가

데이터 병렬은 모델 사본마다 다른 미니배치를 처리하고 기울기를 모은다. 장치 $k$의 표본 수를 $n_k$, 그 장치의 평균 기울기를 $g_k$, 전체 장치 수를 $K$, 총 표본 수를 $N=\sum_{k=1}^K n_k$라고 하자. 전체 표본의 평균 기울기는

$$
g=\sum_{k=1}^K\frac{n_k}{N}g_k.
$$

표본 수가 다르면 각 장치 평균을 단순 평균하는 것은 같은 계산이 아니다. 두 장치가 2개·6개 표본에서 평균 기울기 1·3을 얻었다면 전체 평균은 $(2/8)1+(6/8)3=2.5$이며, 단순 평균 2와 다르다. 장치 수를 늘릴 때 전체 배치 크기·학습률·배치 통계가 바뀌면 단일 장치 학습과 결과가 달라질 수 있다.

모델 병렬은 모델의 부분을 장치에 나눈다. 텐서 병렬은 한 층의 행렬 연산 등을 분할해 통신하며, 파이프라인 병렬은 층들을 단계로 나누고 여러 작은 배치를 흐르게 한다. 단계 중 일부가 기다리는 빈 시간이 생길 수 있고 단계별 계산량이 불균형하면 가장 느린 단계가 전체 처리량을 제한한다. [GPipe, Huang 등, 2018/2019](https://arxiv.org/abs/1811.06965)는 작은 배치와 파이프라인 병렬을 결합한 원논문 사례다. 통신 시간, 동기화, 활성값 저장과 재계산의 비용까지 비교해야 장치 수 증가의 이득을 판단할 수 있다.

분산 학습, 분산 모델 실행, 연합학습은 같은 말이 아니다. 연합학습은 데이터가 여러 참여자에 남는 접근 조건까지 포함하며 M09와 연결한다. 매개변수나 기울기를 교환한다고 개인정보가 자동 보호되지 않는다. 동기 학습은 느린 참여자를 기다리고 비동기 학습은 오래된 매개변수에서 계산한 갱신을 받을 수 있다. 어느 방식을 택해도 통신 장애, 참여자 차이, 재현 조건을 명시해야 한다. 작은 문제에서는 먼저 한 환경의 기준선을 확인하고 실제 병목이 나타날 때 분산을 선택한다.

## 4. 정밀도·압축·양자화·증류

낮은 정밀도는 숫자를 표현하는 비트 수를 줄이는 것이고, 혼합 정밀도는 연산별로 정밀도를 다르게 쓰는 것이다. 가중치나 활성값을 낮은 정밀도로 저장하더라도 누적합·정규화·민감한 계산은 높은 정밀도가 필요할 수 있다. 값의 범위를 넘는 overflow, 작은 값이 사라지는 underflow, 반올림 누적을 검사한다. 비트 수만 비교해 정확도·속도를 확정할 수 없으며 실행 장치와 커널이 그 형식을 지원하는지도 확인한다.

양자화는 연속적인 실수값을 유한한 코드로 대응시킨다. 단순 균일 양자화에서 표현 구간의 최솟값을 $w_{min}$, 최댓값을 $w_{max}$, 코드 비트 수를 $b$, 간격을 $s=(w_{max}-w_{min})/(2^b-1)$로 둔다. 실수 가중치 $w$에 대해

$$
q=\operatorname{clip}\!\left(\operatorname{round}((w-w_{min})/s),0,2^b-1\right),
\qquad \widehat w=w_{min}+sq.
$$

$q$는 정수 코드, $\widehat w$는 복원값, round는 가장 가까운 정수 반올림, clip은 지정 구간으로 제한하는 함수다. 여기서는 중간값 동률을 피한 예제만 사용한다. 구간 안에서 가장 가까운 코드로 반올림한 오차는 $s/2$ 이하지만, 구간 밖 값을 제한한 오차에는 이 경계가 적용되지 않는다. 실제 정수 연산은 정수 영점과 스케일을 쓰는 아핀 형식, 채널별 범위, 누적 정밀도 등을 함께 설계한다. 근거는 [Jacob 등, 2017/2018, §2~3](https://arxiv.org/pdf/1712.05877)다.

학습 후 양자화는 저장된 모델에 범위와 코드를 적용하고 대표 입력으로 활성값 범위를 정할 수 있다. 양자화 인지 학습은 학습 중 양자화 오차를 모사해 매개변수를 적응시킨다. 범위 확인용 입력이 배포 입력과 다르거나 이상치가 크면 오차가 커진다. 가중치만 양자화했는지 활성값·캐시까지 바꾸었는지도 구분한다. 낮은 비트 형식의 저장 이득이 실제 지연 감소로 이어지는지는 별도 측정한다.

가지치기는 덜 필요한 가중치·채널·구조를 제거한다. 비구조적 0값이 많아져도 실행기가 희소 연산을 활용하지 못하면 빨라지지 않을 수 있다. 구조적 가지치기는 실행하기 쉬운 모양으로 줄일 수 있으나 표현 용량과 정확도를 재평가해야 한다. 저랭크 분해는 행렬을 더 작은 요인의 곱으로 근사한다. 전체 저장·계산 이득은 분해 차원과 추가 연산에 따라 달라진다. 압축 방법의 이름만으로 서비스 개선이 확정되지 않는다.

증류는 교사 모델의 출력이나 표현으로 학생 모델을 학습하는 방식이다. 교사·학생 로짓을 각각 $z^T,z^S$, 클래스 수를 $C$, 온도를 $T_0>0$라고 하자. 위첨자 T는 교사 식별자이며 온도 기호와 구분한다. $j$번째 클래스의 부드러운 확률은

$$
p_j^T=\frac{\exp(z_j^T/T_0)}{\sum_{c=1}^{C}\exp(z_c^T/T_0)},
\qquad
p_j^S=\frac{\exp(z_j^S/T_0)}{\sum_{c=1}^{C}\exp(z_c^S/T_0)}.
$$

$c$는 합의 클래스 인덱스, exp는 지수함수다. 학습 손실 한 예는 $L=\alpha L_{label}+(1-\alpha)T_0^2 KL(p^T\Vert p^S)$다. $L_{label}$은 정답 라벨 손실, $\alpha\in[0,1]$는 혼합 비율, $KL(p^T\Vert p^S)=\sum_j p_j^T\log(p_j^T/p_j^S)$는 교사와 학생 분포의 KL 발산이며 log는 자연로그다. 온도를 높이면 덜 선택된 클래스 사이의 관계도 학습 신호가 될 수 있다. [Hinton·Vinyals·Dean, 2015](https://arxiv.org/pdf/1503.02531)는 이 증류 원리를 제시한다. 학생의 용량·학습 데이터가 부족하거나 교사의 오류·편향이 있으면 지식 전달도 제한되며, 정확한 교사 복제를 보장하지 않는다.

## 5. 검색과 RAG: 매개변수 밖의 정보를 제공하기

검색 증강 생성(RAG)은 외부 자료를 검색해 모델의 생성에 제공하는 시스템 구성이다. 자료 준비 → 문서 분할 → 인덱스 → 질의 → 후보 검색 → 필요시 재순위 → 문맥 구성 → 생성 → 근거 확인의 흐름을 갖는다. 검색은 어휘 기반, 벡터 유사도, 둘의 결합 등을 쓸 수 있다. 임베딩이 비슷하다는 것과 질문의 정답 근거를 포함한다는 것은 다르다.

원래 RAG 논문은 매개변수 기억인 생성 모형과 비매개변수 기억인 검색 인덱스를 연결하고 함께 미세조정하는 설정을 다룬다. 근거는 [Lewis 등, 2020/2021](https://arxiv.org/abs/2005.11401)다. 오늘날 넓은 의미의 RAG는 고정 모델에 검색 결과만 제공할 수도 있으므로, RAG 자체가 항상 매개변수를 갱신하거나 항상 갱신하지 않는다고 일반화하면 안 된다. 문맥을 추가하는 것, 검색기 학습, 생성기 미세조정 중 무엇을 했는지 기록한다.

문서 조각에는 문서 식별자, 버전·작성일, 위치, 접근 권한, 원문 링크를 유지한다. 분할이 너무 작으면 조건과 예외가 잘리고, 너무 크면 관련 없는 텍스트와 비용이 늘 수 있다. 오래된 인덱스, 서로 충돌하는 문서, 질문과 관련 없는 근거는 생성기가 해결하지 못할 수 있다. 모델이 출처를 붙여도 그 출처가 실제로 해당 문장을 뒷받침하는지 확인한다. 접근 권한은 검색 전에 적용하고 캐시·로그에서도 유지해야 한다.

## 6. 도구·에이전트·메모리: 상태와 권한을 연결하기

도구 호출은 모델이 외부 함수에 전달할 이름과 인수를 제안하고 실행기가 이를 처리하는 인터페이스다. 자료형·범위·단위 검사는 실행기가 수행하며, 도구의 실제 허용 권한을 모델의 문장에 맡기지 않는다. “읽기”와 “쓰기”, 대상 자원, 호출 횟수, 시간 제한이 다르다. 검색 문서나 도구 응답에 포함된 문구는 자료이므로 그것이 실행기의 권한 설정을 바꿔서는 안 된다.

에이전트는 목표를 향해 관찰 → 선택 → 실행 → 상태 갱신을 반복하는 구성으로 이해할 수 있다. 모든 에이전트가 강화학습으로 훈련된 모델은 아니며, 긴 언어모델 대화 자체가 성공적인 행동 계획도 아니다. [ReAct, Yao 등, 2022/2023](https://arxiv.org/abs/2210.03629)는 추론 텍스트와 환경 행동을 번갈아 사용한 연구 사례다. 해당 연구의 과제 성공률을 모든 실제 도구 환경으로 확대하지 않는다. 실행 루프에는 완료 조건, 최대 단계, 비용 상한, 관찰할 실패 상태가 필요하다.

메모리는 현재 문맥, 검색 가능한 장기 기록, 구조화된 작업 상태 등으로 나눌 수 있다. 요약은 문맥 비용을 줄이지만 중요한 조건을 빠뜨릴 수 있다. 검색 가능한 기록은 누가 썼는지·언제 유효한지·지금 누가 볼 수 있는지 확인해야 한다. 작업 상태는 완료 단계·외부 실행 식별자·남은 인수처럼 검증 가능한 사실을 저장한다. “메모리에 들어갔다”는 것이 사실의 정당성이나 최신성을 보장하지 않는다.

상태 기계를 가령 준비 → 검증 → 실행 중 → 완료 또는 실패로 정하자. 외부 쓰기 작업이 시간 초과하면 실제로 실행되지 않은 것인지, 실행됐으나 응답을 못 받은 것인지 구분되지 않을 수 있다. 그대로 재시도하면 중복 생성이 가능하다. 동일 작업 식별자를 사용하는 멱등성 지원, 실행 결과 조회, 중복 검사를 통해 복구한다. 멱등성은 같은 요청을 반복해도 최종 효과가 한 번 실행한 것과 같도록 만드는 성질이다. 이를 지원하지 않는 도구에서는 결과 확인과 사람이 판단할 수 있는 보류 상태가 필요하다. 되돌리기 작업도 항상 원래 상태를 완전히 복원하는 것은 아니다.

## 7. 완료 계산 예제: 검색·생성·검사의 성공과 비용

가상 문서 질의 시스템은 입력 검사 10ms, 검색 40ms, 생성 150ms, 결과 검사 20ms를 순서대로 수행한다고 가정한다. ms는 밀리초다. 요청당 지연은 $10+40+150+20=220$ms다. 병렬·큐 대기·네트워크가 없는 설계 계산이며 실제 지연 실측이 아니다.

검색이 정답 근거를 찾을 확률을 $p_R=0.8$, 올바른 근거를 찾은 조건에서 생성이 맞을 확률을 $p_{G\mid R}=0.9$, 두 조건을 만족한 상태에서 출력 형식까지 맞을 확률을 $p_{F\mid RG}=0.95$로 정한다. $R,G,F$는 각각 해당 사건, $p$는 확률이다. 전체 성공은

$$
P(R\cap G\cap F)=p_R p_{G\mid R}p_{F\mid RG}
=0.8(0.9)(0.95)=0.684.
$$

$\cap$는 사건을 함께 만족한다는 뜻이다. 조건부확률의 연쇄식이므로 독립성 가정은 필요 없다. 검색에 실패해도 우연히 정답을 내는 경우를 성공에서 제외한 “근거를 확보한 올바른 형식의 정답”이라는 목표량이다. 단순 정답률을 측정하려면 다른 사건도 포함해야 한다.

검색만 0.95로 개선하고 나머지 조건부 성공률이 유지된다고 가정하면 성공은 $0.95(0.9)(0.95)=0.81225$다. 생성만 완벽해져도 원래 검색과 형식 조건에서는 $0.8(1)(0.95)=0.76$이다. 구성요소 평가가 개선 대상을 보여 준다. 다만 실제로 검색 개수를 늘리면 문맥·지연·생성 오류도 함께 바뀔 수 있으므로 “나머지 유지”는 확인해야 할 설계 가정이다.

양자화 계산도 따로 해 보자. $b=2,w_{min}=0,w_{max}=0.9$이면 코드 수는 4, 간격은 $s=0.9/3=0.3$이다. $w=0.52$는 $q=\operatorname{round}(1.7333)=2$, 복원값 0.6, 절대 오차 0.08이다. $w=1.2$는 코드 4를 최대 코드 3으로 제한해 복원값 0.9, 절대 오차 0.3이다. 두 번째는 포화 오차이므로 $s/2=0.15$ 경계를 벗어난다. 이는 가중치 하나의 검산이며 모델 정확도 측정은 아니다.

가중치 100만 개만 저장하면 32비트는 $10^6(32/8)=4\times10^6$바이트, 8비트는 $10^6$바이트다. 1MB를 100만 바이트로 정의하면 4MB 대 1MB다. 스케일·인덱스·활성값·캐시·실행기 메모리는 제외했다. 저장량 4배 감소를 전체 메모리나 실행 시간 4배 감소로 바꾸어 말하지 않는다.

마지막으로 가상 비용률을 입력 100만 토큰당 0.2비용단위, 출력 100만 토큰당 1비용단위로 정한다. 토큰은 사용한 토큰화 규칙의 단위다. 요청이 입력 1,000·출력 200토큰이면 비용은 $(1000/10^6)0.2+(200/10^6)1=0.0004$단위다. 1,000회는 0.4단위다. 이는 실제 서비스 가격이 아니다. 검색 저장·실행 도구·네트워크·재시도 비용은 추가로 잡는다. 입력이 3,000토큰으로 늘면 요청당 비용은 0.0008단위가 되어 2배다.

## 8. 배포·관측·오류 복구

모델 실행 성공, 형식 성공, 근거 성공, 사용자 목표 성공을 분리해 로그에 남긴다. 요청 식별자, 데이터·모델·검색 버전, 단계별 소요 시간, 토큰 수, 도구 상태, 오류 종류가 원인 분석에 유용하다. 로그 자체에도 접근 제한과 보존 정책이 필요하며 민감한 원문을 무조건 저장하지 않는다. 지연의 평균만 보면 긴 꼬리 요청을 숨길 수 있으므로 분위수와 실패율도 함께 확인한다. 처리량은 단위 시간당 완료 요청 수이고 지연은 한 요청의 완료 시간이다.

| 오류 계층 | 관찰 예 | 먼저 좁힐 확인 |
| --- | --- | --- |
| 데이터·전처리 | 단위 혼동, 누락 필드 | 원천·스키마·변환 버전 |
| 검색 | 관련 자료 없음, 권한 자료 노출 | 인덱스·질의·접근 필터 |
| 모델 | 근거와 다른 답, 형식 오류 | 문맥·디코딩·출력 검사 |
| 도구·실행 | 인수 오류, 시간 초과 | 입력 명세·권한·외부 실행 상태 |
| 상태·복구 | 같은 작업 두 번 실행 | 작업 식별자·멱등성·재시도 규칙 |
| 자원·운영 | 지연 급증, 메모리 부족 | 큐·배치·문맥 길이·동시 요청 |

제한된 재시도는 일시 오류에 도움이 될 수 있지만 잘못된 인수나 권한 거부를 반복 호출해 해결하지는 못한다. 검색 근거가 없을 때는 불확실성 표시·추가 입력 요청·응답 보류 같은 대안을 과제에 맞게 정한다. 새 버전은 동일한 평가 조건의 기준선과 비교하고 일부 요청부터 적용해 오류를 관찰할 수 있다. 되돌릴 수 있는 배포 상태와 자료 버전을 보존한다. 관측으로 문제를 발견한 뒤 어떤 조건에서 중지·복구할지도 미리 정한다.

## 9. 오개념과 방법 선택

“RAG면 근거가 있으니 항상 정확하다”는 검색·인용 검증을 누락한다. “정수 비트 수가 작으면 항상 빨라진다”는 실행기와 포화 오류를 누락한다. “에이전트가 계획했으니 실행됐다”는 외부 상태를 누락한다. “로그에 성공이라면 목표를 달성했다”는 목표 정의를 누락한다. 먼저 단일 요청과 읽기 도구의 작은 흐름을 확인하고, 병목·실패·수요가 증명하는 만큼 압축·분산·반복 행동을 확장한다.

## 10. 연습과 단계 힌트

### M17-Q1

**양자화의 범위.**

2비트 균일 양자화 구간이 0~1.2다. $w=0.73$과 $w=1.5$의 코드·복원값·절대 오차를 구하고, 반올림 오차 경계를 어느 경우에 적용할 수 있는지 설명하라. 힌트 1: 코드 최댓값은 3이다. 힌트 2: 구간 밖 값은 반올림 뒤 제한된다. 힌트 3: 비트 수와 활성값 범위는 서로 다른 조건이다.

### M17-Q2

**시스템 목표와 비용.**

근거 검색 확률 0.75, 올바른 검색 조건의 정답 확률 0.8, 두 조건 아래 형식 성공률 0.9인 가상 시스템의 근거 있는 정답 성공률을 구하라. 입력 2,000·출력 300토큰을 본문의 가상 비용률로 처리하는 비용을 계산하라. 검색을 0.9로 개선하는 대신 입력이 4,000토큰으로 늘 때 성공률과 비용을 다시 비교하라. 힌트 1: 조건부 사건의 연쇄식을 쓴다. 힌트 2: 토큰 수를 100만 단위로 바꾼다. 힌트 3: 정확도 개선과 비용 증가를 별도로 판단한다.

### M17-Q3

**쓰기 도구의 시간 초과.**

승인된 “학습 기록 생성” 요청을 보냈는데 응답이 시간 초과했다. 외부에 기록이 이미 생겼을 수도 있다. 준비·실행 중·확인 필요·완료·실패 상태와 작업 식별자를 이용해 중복을 줄이는 복구 절차를 설계하라. 멱등성을 지원하지 않고 실행 결과 조회도 할 수 없을 때 필요한 보류 상태를 설명하라. 힌트 1: 응답 실패와 작업 실패는 같지 않다. 힌트 2: 새 식별자로 무조건 재호출하면 두 기록이 될 수 있다. 힌트 3: 관측할 수 없는 상태를 완료나 실패로 임의 확정하지 않는다.

## 11. 다음 연결과 검증 범위

이번 장의 수치는 손계산과 수치 검산이다. 실제 분산 학습·압축 모델 실행·API 호출·하드웨어 실험을 수행한 결과가 아니다. 실제 실습을 선택할 때 기술 성공은 테스트 종류·입력·버전·조건으로 기록하고, 학습 성공은 연결 조건과 오류 원인을 독립적으로 설명했는지 기록한다. 하드웨어가 있다면 데이터시트 확인값, 설계 가정, 실측값을 분리하고 하드웨어·펌웨어·통신·응용 계층을 차례로 좁힌다.
