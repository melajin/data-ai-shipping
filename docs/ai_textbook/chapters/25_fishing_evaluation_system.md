## 학습 목표와 선수 질문

잘 계산한 모델을 적절한 질문으로 평가하고, 그 근거와 한계를 전달하는 장이다. 새 선박의 조업 분류와 이미 관측 중인 선박의 변화 탐지는 다른 검증 조건을 갖는다. 지표·경보 임계값·사고 탐지 시점·자료 가용성을 직접 계산하고, 오류가 어느 계층에서 생겼는지 설명한다. 선수 질문은 “같은 선박의 인접 항적을 학습·시험에 나누면 새 선박 성능인가?”, “확률 0.9는 90%의 실제 사고 가능성을 뜻하는가?”다.

이 장은 구현과 평가의 설계 설명이다. 실제 원자료 평가·모델 학습·시뮬레이터 구현·장치 실험은 수행하지 않았다. 아래의 클래스·사건·시간·성능 수치는 전부 교육용 가상 예다. 공식 평가식·정확한 제출 스키마는 확인 후 우선 적용하며 여기의 지표 후보를 대회 규정으로 단정하지 않는다. 확인일: 2026-10-07.

## 1. 과제·정답·표본·판단 시점의 계약

분류 목표는 시간대 항적의 조업 라벨 $y_i\in\{1,\ldots,C\}$를 예측하는 것이다. 이상 목표는 정한 기준에서 얼마나 벗어났는지 점수 $s_i$를 반환하는 것이다. 사고 정답이 충분히 정의되어 있지 않으면 $s_i$의 분포·안정성·사례를 조사할 수는 있지만 사고 탐지 정확도를 입증할 수는 없다.

사고 ID와 발생시각 $T_a$가 있더라도 모든 시간대에 대해 정답 $a_i$가 자동으로 결정되는 것은 아니다. 예를 들어 사건 전 $w$시간을 평가 대상으로 삼는 것은 **평가 창의 정의**이지 그 안의 모든 경로가 이상이라는 확인이 아니다. 사고 미표시 표본을 모두 정상으로 두면 숨긴 사고·미보고 사건을 잘못 음성으로 세게 될 수 있다.

계약에는 관측 단위, 라벨 의미, 특징·정답의 시간 창, 자료 도착시각, 선박·항차 그룹, 모델 출력 방향, 정보 부족 처리와 공식 제출 변환을 포함한다. 내부 결과와 대회 파일의 컬럼·범위는 별도 계약이다. [초기 명세의 확인 항목](../../initial_spec%28초안%20조건%20분석%29.md)

## 2. 행 분할이 아니라 사용 조건에 맞는 분할

### 2.1 새 선박 일반화

선박 집합 $V_{train},V_{val},V_{test}$를 정해

$$V_{train}\cap V_{val}=V_{train}\cap V_{test}
=V_{val}\cap V_{test}=\varnothing$$

가 되도록 나눈다. 같은 선박의 모든 해당 자료를 그룹으로 묶는 검증은 Test A의 신규 선박 조건에 맞는 후보다. 항적의 원본·증강본·합성 부모 표본이 다른 분할로 넘어가지 않게 한다. 선박 수가 적거나 클래스가 특정 선박에만 나타나면 모든 분할에 모든 클래스를 넣는 조건이 불가능할 수 있다. 그 제약을 보고하며 ID 겹침을 숨겨 해결하지 않는다.

### 2.2 과거에서 미래로

판단 시점 $\tau$까지 이용 가능한 정보만 사용해 이후 구간을 평가한다. 이미 관측 중인 같은 선박의 과거가 사용 가능한 경우, 그 조건에서 과거 기준을 구축하는 것은 가능하지만 이후 항적이나 평가 사건을 기준에 섞으면 안 된다. 새 선박 평가와 같은 선박 미래 평가는 나누어 보고한다.

겹치는 창 $[t-L,t]$를 만들었다면 경계 주변의 창은 원관측을 공유할 수 있다. 학습·평가 입력이나 정답 창이 공유되지 않도록 필요한 제외 구간을 정하고 이유를 기록한다. 단순히 날짜 경계를 두는 것만으로 모든 누수가 사라지는 것은 아니다. [scikit-learn의 그룹·시간 분할](https://scikit-learn.org/stable/modules/cross_validation.html)

### 2.3 무엇을 어디에서 적합하는가

학습 분할에서 표준화·결측 대치·특징 선택·모델·정상 기준·생성 규칙을 적합한다. 검증 분할에서 구조·하이퍼파라미터·경보 임계값·확률 보정을 고른다. 최종 시험자료는 선택을 끝낸 뒤 한 번의 최종 평가에 사용한다. 반복 비교 자체는 가능하지만 최종 시험을 선택 도구로 사용하면 그 성능은 독립 평가가 아니다.

모델 계열을 많이 비교할수록 검증자료에도 적응한다. 자료가 허용하면 바깥 그룹·시간 분할로 평가하고 그 안쪽에서 선택하는 nested 검증을 고려한다. 데이터 양이 적을 때는 복잡한 구조보다 분할의 신뢰성과 단순 기준선이 우선이다.

## 3. 조업 분류 지표를 유도하기

혼동행렬 $M_{ab}$를 실제 클래스 $a$, 예측 클래스 $b$의 표본 수라고 정한다. 클래스 $c$에 대해

$$TP_c=M_{cc},\quad FP_c=\sum_{a\ne c}M_{ac},\quad
FN_c=\sum_{b\ne c}M_{cb}.$$

$$P_c=\frac{TP_c}{TP_c+FP_c},\qquad
R_c=\frac{TP_c}{TP_c+FN_c},\qquad
F1_c=\frac{2P_cR_c}{P_c+R_c}
=\frac{2TP_c}{2TP_c+FP_c+FN_c}.$$

정밀도는 “이 조업이라고 예측한 것 중 맞은 비율”, 재현율은 “실제 이 조업 중 찾은 비율”이다. 조화평균은 둘 중 하나가 작으면 F1을 낮춘다. 분모가 0인 클래스의 처리, 평가에 포함할 클래스 집합과 표본 수를 명시한다.

$$\mathrm{Accuracy}=\frac{\sum_cM_{cc}}{\sum_{ab}M_{ab}},\qquad
\mathrm{MacroF1}=\frac1C\sum_cF1_c.$$

정확도는 모든 행을 동일하게 세고 macro F1은 클래스마다 동일하게 반영한다. weighted F1은 클래스 표본 수로 가중하므로 희귀 클래스 문제가 가려질 수 있다. [공식 지표 정의](https://scikit-learn.org/stable/modules/model_evaluation.html)

가상 3클래스의 혼동행렬을

$$M=\begin{pmatrix}3&1&0\\1&1&0\\0&1&2\end{pmatrix}$$

이라 하자. 클래스별 실제 수는 $(4,2,3)$, 예측 수는 $(4,3,2)$다. F1은 $6/(4+4)=0.75$, $2/(2+3)=0.4$, $4/(3+2)=0.8$이다. macro F1은 $(0.75+0.4+0.8)/3=0.65$, 정확도는 $6/9\approx0.666667$다. 이 가상 A·B·C를 실제 조업 코드 대응이라고 해석하지 않는다.

## 4. 이상점수의 순위와 경보 임계값

이 절은 이진 정답 $a_i\in\{0,1\}$가 정의된 가상 자료를 가정한다. $s_i\ge\theta$일 때 경보라고 하면 TP·FP·FN·TN으로 정밀도·재현율과 오경보율 $FP/(FP+TN)$을 구할 수 있다. 정답이 부족한 실제 자료에 이 가정을 자동 적용하지 않는다.

### 4.1 한 임계값과 순위 지표는 다르다

ROC-AUC는 점수 큰 쪽을 양성으로 볼 때 무작위 양성이 무작위 음성보다 높은 점수를 받을 확률의 표본 추정으로

$$\widehat{AUC}=
\frac{\sum_{i:a_i=1}\sum_{j:a_j=0}
\left[\mathbf1(s_i>s_j)+\tfrac12\mathbf1(s_i=s_j)\right]}{N_+N_-}$$

로 이해할 수 있다. 양성·음성이 모두 있어야 정의된다. 모든 경보 임계값에서의 순위를 요약하지만 실제 운영 임계값을 선택해 주지는 않는다.

정밀도–재현율 곡선은 사건이 드문 경우 경보 중 실제 사건 비율을 직접 보여 준다. average precision은 점수 임계값 단계 $k$별로

$$AP=\sum_k(R_k-R_{k-1})P_k$$

를 계산한다. 동점 점수는 같은 임계값 단계로 처리한다. 정밀도–재현율 곡선에 선형 사다리꼴 적분을 적용한 값과 AP는 같은 정의가 아니다. 둘을 모두 PR-AUC라는 이름으로 섞어 쓰지 않는다. [scikit-learn average precision의 정의](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)

가상 정답 $(1,0,1,0)$과 점수 $(0.9,0.8,0.4,0.1)$을 보자. $\theta=0.5$이면 TP=1, FP=1, FN=1, TN=1이라 정밀도·재현율·F1은 모두 0.5다. 양성 0.9는 두 음성보다 높고 양성 0.4는 0.1보다만 높으므로 ROC-AUC=$3/4$다. 양성 두 개가 순위 1·3에서 나타나므로 AP=$\frac12(1+2/3)=5/6$이다. 임계값 성능·ROC-AUC·AP는 서로 다른 숫자이며 각각 다른 질문에 답한다.

### 4.2 임계값을 결정하는 비용

검증자료의 비용 후보를

$$\widehat C(\theta)=\frac{c_{FN}FN(\theta)+c_{FP}FP(\theta)}N$$

로 정할 수 있다. $c_{FN},c_{FP}$는 교육용 또는 운영 설계의 오류 비용이고 실제 기관의 비용을 확인한 값과 구분한다. 미탐 비용을 높이면 낮은 임계값이 유리해질 수 있지만 경보 부담도 함께 증가한다. 공식 평가와 프로젝트 경보 실험의 기준을 별도로 둔다.

임계값을 현재 시험 사건이 가장 잘 보이도록 고르면 그 사건에 적응한 것이다. 정상 기준·점수 변환·임계값은 자료 분할과 시점 조건을 지켜 선택하고, 반복 경보를 사건 하나로 합치는 규칙도 평가 전에 정한다.

## 5. 사고 전후 평가와 실제 판단 가능 시각

시간대 레코드가 구간 $[b_i,e_i)$ 전체 경로를 포함하고 도착·처리 지연이 $\ell_i$라면

$$\tau_i\ge e_i+\ell_i$$

가 전체 경로를 이용한 판단의 가능한 시각이다. 시간대의 시작시각을 탐지시각으로 쓰면 아직 보지 못한 미래 경로를 알고 있던 셈이 된다. 실제 구간 경계·지연은 자료 확인 후 정하며, 이 식은 일반적인 정보 가용성 제약이다.

사건시각 $T_a$ 주변에 사전 정의한 평가 창에서 처음 경보한 가능한 시각을 $\tau_a^{alarm}$이라 하면 선행 시간은

$$L_a=T_a-\tau_a^{alarm}.$$

$L_a>0$이면 그 정의 아래 사건 전 경보, $L_a<0$이면 사건 후 탐지다. 평가 창에서 사전 경보와 사후 탐지를 허용하는 범위는 구분해 정한다. 예를 들어 10:00~11:00 항적이 11:05에 처리되고 사고가 10:40에 발생했다면 그 항적으로 만든 첫 경보의 선행 시간은 $10{:}40-11{:}05=-25$분이다. 10:00에 탐지했다고 보고하면 오류다. 사고시각이 한 시간 구간으로만 알려졌다면 단일 선행 시간 대신 가능한 범위·해상도의 한계를 보고한다.

사건 단위 탐지율은 사전 정의한 창에서 감지된 사건 수/평가 가능 사건 수다. 오경보 빈도는 확인된 비사건 관측 구간의 경보 사건 수/유효 선박 관측시간으로 정의할 수 있다. 숨긴 사고·미확인 정상 구간을 분모·오경보 정답에 쓰는 조건이 해결되지 않으면 경보 빈도까지만 보고하고 거짓경보율이라고 단정하지 않는다. 시간대별 재현율과 사건별 탐지율은 같은 단위가 아니다.

## 6. 점수·확률 보정과 판단 유보

분류 softmax가 반환한 0.9가 실제로 90% 맞는 빈도를 갖는지는 검증해야 한다. 이상점수를 0~1로 정규화한 값도 사고 확률이 자동으로 되지 않는다. 이 절의 확률 평가에서는 의미가 정의된 정답과 대응 확률이 있다는 조건을 둔다.

이진 Brier score는

$$BS=\frac1N\sum_i(p_i-a_i)^2$$

로 계산한다. 가상 $(a,p)=((1,0,1,0),(0.9,0.8,0.4,0.1))$의 제곱오차는 $(0.01,0.64,0.36,0.01)$이고 평균은 0.255다. NLL은

$$NLL=-\frac1N\sum_i[a_i\log p_i+(1-a_i)\log(1-p_i)]$$

이며 이 예는 약 0.684112다. 확률 0·1의 수치 처리를 기록하며, 잘못된 확신에는 큰 손실이 생긴다. 다중 클래스에서는 라벨 one-hot과 클래스별 확률의 제곱오차를 합하는 정의를 명시한다.

클래스 예측 확신도 $c_i=\max_cp_{ic}$를 구간 $B_m$으로 나눈 ECE 후보는

$$ECE=\sum_m\frac{|B_m|}{N}
\left|\frac1{|B_m|}\sum_{i\in B_m}\mathbf1(\widehat y_i=y_i)
-\frac1{|B_m|}\sum_{i\in B_m}c_i\right|.$$

구간 수·경계·표본 수에 민감하고 모든 클래스별 보정 오류를 드러내지는 않는다. Brier·NLL·보정 도표와 함께 본다. [확률 보정 공식 문서](https://scikit-learn.org/stable/modules/calibration.html)

temperature scaling은 학습된 logit $z$를 고정한 채 검증자료에서 $T>0$를 선택해 $p_c(T)=\operatorname{softmax}(z/T)_c$로 바꾼다. 양의 $T$는 클래스 argmax를 유지하지만 확신도를 바꾼다. 두 logit $(\log9,0)$은 $T=1$에서 $(0.9,0.1)$, $T=2$에서 $(0.75,0.25)$다. 실제 보정이 좋아지는지는 검증으로 판단하며 도메인 변화에서도 유지된다고 보장하지 않는다. [Guo 등, temperature scaling 원논문](https://arxiv.org/abs/1706.04599)

입력 부적합, 훈련 범위 밖 좌표·환경, 조업 클래스 불확실성과 이상 여부를 따로 표시한다. 예측 유보는 위험을 숨기는 정상 클래스가 아니며 유보 비율과 남은 표본의 오류를 같이 보고한다. 확률분포 엔트로피 $H(p)=-\sum_cp_c\log p_c$가 크다는 것은 조업 클래스가 불확실하다는 의미이지 사고가 발생했다는 정답이 아니다.

## 7. 설명을 수치와 경로에 연결하기

선형 모델에서는 표준화된 특징에 대한 logit 기여 $w_jx_j$를 보여 줄 수 있다. 특징의 단위·스케일이 다르면 계수 크기만 비교할 수 없고, 상관된 특징의 기여를 개별 인과 효과로 말할 수 없다. Gaussian 이상점수의 $x-\mu$는 어느 특징이 기준과 달랐는지 설명하며 공분산을 사용하면 상호 관련 변화까지 포함한다.

SHAP의 Shapley 값 정의는 특징 집합 $F$, 설명 대상 $j$에 대해

$$\phi_j=\sum_{S\subseteq F\setminus\{j\}}
\frac{|S|!(d-|S|-1)!}{d!}
\big[v(S\cup\{j\})-v(S)\big],\quad d=|F|.$$

특징을 가능한 여러 순서로 추가했을 때 모델 결과 변화의 평균을 구한다. $v(S)$를 만들 때 남은 특징을 어떤 배경자료·조건부 또는 주변 분포로 채우는지 명시해야 한다. 서로 관련된 길이·굴곡·점 수에 비현실적인 조합을 만들면 해석이 왜곡된다. 선택한 게임 아래의 모델 기여이지 실제 사고의 원인 증명은 아니다. [SHAP 원논문](https://arxiv.org/abs/1705.07874)

Permutation importance는 검증자료에서 한 특징을 섞은 뒤 성능이 얼마나 달라지는지 본다. 시간·선박 그룹을 무시해 섞으면 불가능한 표본을 만들 수 있으며 상관 특징이 대신 정보를 주어 중요도가 낮게 나올 수도 있다. 설명 대상의 모델 점수, 기준 경로, 특징 차이, 자료 품질과 불확실성을 함께 표시한다. 그림이 자연스럽다는 사실은 설명의 정확성을 검증하지 않는다.

## 8. 전체 시스템의 전달 계약

최소 흐름은 `항적 읽기 → 입력·좌표·시간 검증 → 공간 특징 → 모델 실행 → 결과·근거 표시`다. 외부자료는 [23장](23_fishing_environment.md)의 시점·공간 조건을 통과해 합류하고, 가상 유닛은 [24장](24_fishing_virtual_units.md)의 합성 출처를 유지한 채 같은 관측 입력 형식으로 연결한다. 실제 하드웨어·실시간 관제 연결은 현재 범위에 없다.

| 전달 정보 | 역할 | 주의할 점 |
| --- | --- | --- |
| source·원본 식별·버전 | 실제/합성 및 처리 출처 추적 | 생성 규칙·정답 메타데이터를 모델 입력과 분리 |
| 날짜·선박·시간대·부분선 | 표본과 경로 경계 보존 | 시각 없는 점에 실제 시각을 덧씌우지 않음 |
| CRS·단위·시간 계약 | 계산 조건 | 미확인 상태는 정상 숫자로 숨기지 않음 |
| 특징·결측·품질 | 모델의 입력과 오류 설명 | 학습과 추론의 순서·차원·스케일 일치 |
| 원래 라벨·예측 클래스·분포 | 정답과 추정 구별 | 예측으로 원래 라벨을 덮어쓰지 않음 |
| 이상점수·방향·기준·모델 버전 | 점수의 해석 | 정상 기준·변환·유효 비교 범위 기록 |
| 판단 가능 시각·상태·유보 사유 | 정보 가용성과 결과 한계 | 구간 시작을 자동 탐지시각으로 삼지 않음 |

3D 뷰어에서 높이·깊이에 실측 근거가 없다면 표현 설정이라고 명시한다. 경로 재생 속도도 점별 시간이 없으면 실제 선박 속도가 아니다. 사고를 확정하는 문구 대신 모델이 어떤 기준과 얼마나 달랐는지 보여 준다.

## 10. 재현성과 증거 종류

원본 버전·전처리·분할 목록·난수 시작값·학습 설정·정상 기준·임계값·자료 공개시점·모델 버전을 남긴다. 수치 검산, 구현 테스트, 합성 시뮬레이션, 실제 데이터 평가, 실제 장치 실험은 별도의 증거다. 합성 경로에 잘 맞는 결과를 실제 선박에 대한 성능으로 보고하지 않는다.

같은 선박의 수많은 시간대를 독립 표본처럼 세면 불확실성이 과소평가될 수 있다. 선박을 재표집하는 cluster bootstrap이나 시간 블록 재표집을 평가 질문에 맞게 고려한다. 선박마다 동일한 비중을 주는 평균과 모든 행을 동일하게 세는 평균은 다르므로 모집단·가중 정의를 먼저 정한다. 한 번의 분할 수치에는 표본 수·클래스·해역·기간·누락 조건을 함께 붙인다.

고장이 나면 원자료/정렬 → 좌표·시간 계약 → 특징 → 학습·정상 기준 → 모델 출력 → 전달·뷰어 순서로 범위를 좁힌다. 모델 성능 저하를 곧바로 선박 사고로 해석하지 않는다. [어선 적용편 검산 기록](../validation/README.md)은 선택한 교육용 계산과 문서 구조를 검사하며 실제 성능을 입증하지 않는다.

## 연습과 힌트

### M25-Q1

가상 정답 $(1,0,1,0)$과 점수 $(0.9,0.8,0.4,0.1)$에서 임계값 0.5의 정밀도·재현율·F1, ROC-AUC, AP를 구하라. 각각의 숫자가 왜 같을 필요가 없는지 설명하라.

힌트: 한 임계값의 혼동행렬, 양성–음성 4쌍의 순위, 양성 등장 순위 1·3을 따로 계산한다.

### M25-Q2

10:00~11:00 전체 항적은 11:05에 판단 가능하고 사고는 10:40에 일어났다. 이 항적으로 10:00 조기 탐지를 보고할 수 있는가? 선행 시간을 계산하고 점별 시각이 없을 때 무엇이 더 제한되는지 적어라.

힌트: 판단 시각은 관측 구간 시작과 같지 않다.

### M25-Q3

동일 가상 원본의 증강 경로가 학습·시험에 나뉘고, 모든 선박의 전체 기간 평균으로 특징을 표준화했다. 시험 macro F1이 높을 때 어떤 두 누수를 먼저 해결할 것인가? 해결 뒤 수치가 낮아진 것을 어떻게 해석할 것인가?

힌트: 부모 원본의 분할과 전처리 적합 범위를 확인한다. 독립 성능의 추정 조건이 바뀐다.

자신의 평가 설계를 남긴 뒤 [어선 적용편 해설](../94_fishing_solutions.md)을 읽는다.
