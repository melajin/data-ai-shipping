## 숫자를 담는 구조와 배열의 모양

프로그래밍에서 자료구조는 데이터를 저장하고 연산하는 형식이다. 딥러닝의 기본 구조는 다차원 배열(array) 또는 텐서(tensor)다. 스칼라·벡터·행렬도 각각 0·1·2차 텐서로 볼 수 있고, 3차 이상은 고차 텐서다. 텐서라는 단어가 항상 복잡한 물리학 개념을 뜻하는 것은 아니다. 이 문맥에서는 대부분 수치 배열을 의미한다.

배열의 **shape**는 각 축의 길이를 나타낸다. 예를 들어 이미지 배치는 `(batch, height, width, channels)` 또는 `(batch, channels, height, width)`로 표현될 수 있다. 두 배열 모두 “이미지 배치”라고 불릴 수 있지만, 축 순서가 다르면 연산 라이브러리가 기대하는 입력과 다를 수 있다. shape만 적지 말고 각 축이 무엇을 뜻하는지도 함께 기록한다.

자료형(dtype)은 각 요소를 어떤 표현으로 저장할지 정한다. `float32`는 보통 요소당 4바이트, `float16`은 요소당 2바이트를 사용한다. 낮은 정밀도 자료형은 메모리와 연산 비용을 줄일 수 있지만, 매우 작거나 큰 수를 표현할 때 오차와 범위 문제가 커질 수 있다. 저장장치, CPU, GPU, 라이브러리에 따라 지원 연산과 실행 속도가 달라질 수 있으므로 실제 장비 제약을 확인하지 않고 특정 연산이 문제없이 실행된다고 가정해서는 안 된다.

행렬 곱에서 축 의미를 지키는 것이 중요하다. 입력 배치 $\mathbf{X}\in\mathbb{R}^{m\times d}$는 사례가 $m$개이고 사례마다 특징이 $d$개 있음을 뜻한다. 가중치 $\mathbf{W}\in\mathbb{R}^{d\times k}$를 곱하면 점수 $\mathbf{Z}=\mathbf{X}\mathbf{W}\in\mathbb{R}^{m\times k}$가 된다. 각 사례마다 출력 점수 $k$개가 나온다. 열과 행 수가 맞아도 축을 잘못 해석하면 프로그램이 실행되면서 엉뚱한 값을 계산할 수 있다.

다음 짧은 Python 코드는 외부 패키지 없이 행렬과 벡터의 곱을 계산한다.

```python
A = [[1, 2], [0, 1], [3, -1]]
x = [2, 1]
y = []

for row in A:
    total = 0
    for j in range(len(x)):
        total = total + row[j] * x[j]
    y.append(total)

print(y)
```

`A`는 세 행을 담은 리스트이고, 각 `row`는 입력 성분 두 개에 대응하는 가중치다. `x`는 길이 2 입력 벡터다. 안쪽 `for` 반복문은 `range(len(x))`가 만든 인덱스를 차례로 받아 `j`번째 가중치와 입력을 곱해 `total`에 더한다. `len(x)`는 입력 성분 수를 반환하고, `range`는 그 수만큼의 인덱스를 만들며, 바깥 반복문은 각 행의 합을 출력 리스트 `y`에 추가한다. `append`는 계산된 출력을 리스트 끝에 붙인다. 예상 출력은 `[4, 1, 5]`다. 이 예는 노트북·인터프리터에서 실행할 수 있는 작은 소프트웨어 계산으로, GPU나 실제 장치에서 측정한 결과가 아니다.

브로드캐스팅(broadcasting)은 서로 다른 크기의 배열을 특정 규칙에 따라 연산하는 기능이다. 예를 들어 각 배치 행에 같은 편향 벡터를 더하려면 출력 특징 수만큼 원소가 있는 편향을 사용한다. 하지만 두 차원이 우연히 호환된다는 사실은 연산 의도가 맞다는 보증이 아니다. 연산 후 결과 shape와 샘플별 값 하나를 손으로 확인해야 한다.

## 연산량: 입력이 커지면 계산이 어떻게 늘어날까

시간복잡도 표기 $O(\cdot)$는 입력 크기에 따라 연산 수가 어느 정도로 증가하는지 큰 규모의 경향을 나타낸다. 한 목록을 한 번 훑는 작업은 $O(n)$, 모든 쌍을 비교하는 작업은 $O(n^2)$다. $m\times d$ 행렬과 $d\times k$ 행렬의 곱에는 대략 $mdk$번의 곱셈과 비슷한 규모의 덧셈이 필요하다. 정확한 실행 시간은 프로세서, 메모리 대역폭, 병렬화, 자료 크기, 라이브러리 구현에 따라 달라지므로 점근 표기만으로 초 단위 시간을 예측할 수 없다.

Transformer의 일반적인 self-attention에서 길이 $n$인 시퀀스의 각 위치는 다른 위치들과 관련 점수를 계산한다. attention 점수 행렬의 원소 수는 한 헤드 기준 대략 $n^2$에 비례하고, 점수 계산은 키·쿼리 차원을 $d_k$라 할 때 대략 $O(n^2d_k)$ 규모다. 시퀀스 길이를 두 배로 만들면 이 점수 행렬은 네 배가 될 수 있다. 실제 모델에는 선형층과 다른 비용도 있으므로 전체 실행 시간이 정확히 네 배라는 뜻은 아니다.

## 메모리 계산과 병목

배열에 담긴 원소가 $N$개이고 원소당 $b$바이트면 데이터 자체의 메모리는 $N\times b$바이트다. **worked example.** 한 배치가 32개 사례, 시퀀스 길이 512, 은닉 차원 768이며 활성화 배열 하나를 `float32`로 저장한다고 하자. 원소 수는 $32\times512\times768=12{,}582{,}912$개다. 메모리는 $12{,}582{,}912\times4=50{,}331{,}648$바이트, 약 50.3MB(십진 단위) 또는 48MiB(2진 단위)다.

이 계산은 한 배열의 크기만 보여준다. 학습 중에는 여러 층의 활성화, 기울기, 매개변수, 최적화기 상태, 중간 계산값을 보관할 수 있다. 따라서 실제 메모리는 한 배열의 값보다 훨씬 커질 수 있다. 반대로 추론·체크포인팅·메모리 절약 기법은 저장 방식을 바꿀 수 있다. 정확한 사용량은 모델 구조·배치·정밀도·라이브러리에 따라 측정해야 하며, 위 숫자는 단순한 메모리 산술이지 GPU 실측값이 아니다.

실행이 느리다고 항상 연산량만 원인은 아니다. 자주 발생하는 원인은 입력을 CPU와 GPU 사이에서 반복 복사하는 일, 작은 연산을 지나치게 잘게 나누는 일, 메모리 접근이 비효율적인 일, 배치 크기가 장비 메모리와 맞지 않는 일이다. 처음부터 빠르게 만들려 하기보다 작은 입력에서 모양과 계산 결과를 확인한 다음, 실제 병목을 프로파일링한다. 장비를 사용할 때는 메모리 용량, 자료형과 연산 지원, 저장공간·네트워크 조건을 확인하고, 고비용 실행 전에 작은 시험을 한다.

## 자동미분과 계산 그래프

자동미분(automatic differentiation)은 프로그램에서 계산한 값을 여러 기본 연산의 연결로 보고 연쇄법칙에 따라 미분을 계산한다. 입력과 매개변수에서 출력과 손실까지 어떤 연산이 순서대로 이어졌는지를 계산 그래프(computational graph)로 나타낼 수 있다. 정방향 계산은 값을 구하고, 역방향 계산은 결과 손실이 각 중간값과 매개변수에 얼마나 의존하는지 되짚는다.

**worked example.** $a=2$, $b=3$, $c=1$이고 $z=ab+c$, $L=(z-10)^2$라고 하자. 정방향에서 $ab=6$, $z=7$, $L=9$다. 역방향에서는 $dL/dz=2(z-10)=-6$, $dz/da=b=3$, $dz/db=a=2$, $dz/dc=1$이다. 따라서 $dL/da=-18$, $dL/db=-12$, $dL/dc=-6$이다. 각 매개변수의 변화가 최종 손실에 전달되는 정도를 계산했다.

딥러닝 프레임워크의 자동미분은 이 계산을 큰 그래프에도 적용한다. 다만 자동으로 미분해 주는 것은 정의된 계산 그래프다. 코드에서 그래프 밖으로 값을 꺼내 처리하거나, 미분이 없는 분기·비연속 함수를 쓰면 의도한 기울기와 다를 수 있다. 잘못된 목표함수, 누수, 불량한 데이터, 부정확한 평가를 자동미분이 고쳐 주지도 않는다. 기울기가 제대로 계산되었는지는 작은 예제의 손계산, 유한차분 같은 독립적 점검으로 확인할 수 있다.

**1. 컴퓨터 언어와 수학의 결합 (자료구조 + 연쇄법칙)**

- 수학 수식 단독으로는 정방향 결과만 구할 뿐 스스로 역산 경로를 기억하지 못함.
    
- 딥러닝 프레임워크는 수식을 실행하는 동시에, 각 연산의 연결 관계와 국소 미분(Local Gradient) 규칙을 메모리 상의 계산 그래프(Computational Graph, DAG)로 동적 기록함.
    
- 즉, "수학의 미분 공식 & 연쇄법칙"이라는 이론적 틀을 "컴퓨터의 그래프 자료구조 & 포인터 추적"으로 자동화한 것.
    

**2. 조건문(If-Else)이 아닌 연속적 경사하강법(Gradient Descent)**

- "경계를 못 넘으면 재시도(If True/False)"하는 조건부 반복 계산 방식이 아님. (조건문은 그래프를 불연속하게 만들어 미분 불가능하게 만듦)
    
- 모든 연산을 연속적인 함수로 이어 두고, 손실 함수(Loss)의 경사를 따라 모든 가중치($W$)를 동시에 조금씩 미끄러뜨리며 최적점으로 이동시킴.
    

**3. 가중치 자동 업데이트 피드백 루프 (Learning Loop)**

1. **정방향 연산 (Forward):** 입력데이터와 현재 가중치로 예측 및 손실($L$) 계산 후 그래프 생성
    
2. **역방향 연산 (Backward):** 저장된 그래프를 역추적해 각 가중치의 기울기($\frac{\partial L}{\partial W}$) 계산
    
3. **가중치 조정 (Step):** $W_{\text{new}} = W_{\text{old}} - \eta \cdot \frac{\partial L}{\partial W}$ 수식으로 가중치를 손실이 줄어드는 방향으로 변환
    
4. **반복 (Next Iteration):** 새로 조정된 가중치를 다시 정방향 계산 식에 입력하여 손실을 지속적으로 줄여나감



## 재현 가능한 계산 기록

재현성을 위해 난수 시드 하나만 기록하면 충분하다고 생각하기 쉽다. 시드는 난수 생성의 출발 상태를 정하지만, 데이터 파일 변경, 표본 분할, 병렬 연산 순서, CPU/GPU 커널, 라이브러리와 정밀도 차이까지 모두 고정하지 않는다. 실험 기록에는 적어도 다음 내용을 남긴다.

- 자료의 출처·버전·파일 식별자, 전처리 규칙과 학습 자료에서 계산한 변환값
- 학습·검증·시험 자료의 구분, 시간·그룹 분할 기준, 샘플 ID 또는 분할 파일
- 모델 구조·매개변수, 목표함수, 옵티마이저·학습률·배치 크기·학습 횟수
- 언어·라이브러리 버전, 실행 코드의 버전, 난수 시드, 장비 종류와 사용 정밀도
- 측정 지표, 임계값, 평가 절차와 결과, 실패·재시도·수동 선택 사항

실험을 반복해 같은 결과가 나오는 것과 새로운 조건에서도 안정적인 것은 다르다. 반복성은 같은 조건에서의 계산을 다시 확인하는 성질이고, 강건성은 조건이 바뀌어도 유용한 동작을 유지하는 성질이다. 자료 기간·기기·언어·집단이 바뀔 때 성능이 유지되는지 확인하는 일은 별도 실험이다. 코드를 실행했다는 사실만으로 실제 환경에서 검증했다고 말하지 않는다.

오류가 나면 계층을 나눠 확인한다. 먼저 자료 파일이 올바르게 읽히는지, shape와 dtype이 의도와 맞는지 본다. 다음으로 작은 입력에서 계산값과 손실이 손계산과 맞는지 확인한다. 이어서 기울기의 크기와 업데이트 후 손실을 점검한다. 메모리 부족이나 실행 장치 호환 문제는 모델 수학의 오류와 별도로 기록한다. 훈련 점수와 독립 시험 점수의 차이는 자료 분할·과적합·분포 이동을 따로 점검한다.

### 한 걸음 더: 수학 연산 수와 측정 시간을 구분하기

복잡도는 크기가 커질 때 연산량이 어떻게 증가하는지를 추상화한다. 실측 시간은 하드웨어와 시스템 소프트웨어, 병렬 스케줄링, 데이터 이동을 함께 반영한다. 그래서 비교를 할 때는 같은 입력 크기·자료형·장비·정밀도·실행 횟수·워밍업 조건을 사용하고, 반복 측정값과 분산을 남긴다. 단일 측정 시간을 모든 사용자 환경의 성능으로 일반화하지 않는다. 이번 교재의 예시는 배열 수와 바이트 수를 계산하는 교육용 산술이며 실제 장치 벤치마크가 아니다.

## 자주 생기는 오해

1. **“배열 shape가 맞으면 계산이 올바르다.”** 호환되는 shape로 잘못된 축 연산이 조용히 실행될 수 있다. 축의 의미와 샘플 결과를 확인한다.
2. **“float32 하나의 크기로 학습 메모리를 계산할 수 있다.”** 학습은 매개변수·기울기·활성화·최적화기 상태 등 여러 배열을 사용한다.
3. **“복잡도 O(n²)이면 두 배 큰 데이터에서 정확히 네 배 느리다.”** 그 항이 지배적일 때의 연산량 경향이다. 실제 시간은 시스템 조건에 달려 있다.
4. **“자동미분은 모델을 자동으로 학습시킨다.”** 자동미분은 기울기를 계산한다. 데이터·목표·최적화 업데이트·평가가 따로 필요하다.
5. **“시드가 같으면 언제나 같은 결과다.”** 시드는 재현에 필요한 요소 중 하나다. 코드·자료·환경·연산 순서도 영향을 준다.
6. **“코드 테스트에 성공하면 실제 장치에서도 검증된 것이다.”** 코드 실행, 시뮬레이션, 실제 장치 측정은 서로 다른 검증 단계다.

## 연습 문제

**M04-Q1.** $\mathbf{X}$의 shape가 `(64, 128)`, 가중치 $\mathbf{W}$가 `(128, 10)`, 모든 값이 `float32`라고 하자. $\mathbf{XW}$의 shape와 곱셈 수의 대략적인 규모를 구하라. $\mathbf{X}$, $\mathbf{W}$, 결과 하나를 각각 저장하는 데 필요한 메모리를 바이트와 대략 KiB로 계산하라.  
힌트: 결과 shape는 바깥 두 축에서 나오고, 행렬 곱은 세 차원의 곱만큼 곱셈을 한다. float32는 요소당 4바이트다.

**M04-Q2.** 길이 $n$인 시퀀스의 attention 점수 행렬이 $n^2$개 원소라고 단순화하자. 길이가 512에서 1024로 바뀌면 이 행렬 원소 수는 몇 배가 되는가? 실제 전체 실행 시간이 정확히 같은 배수로 증가한다고 단정할 수 없는 이유 두 가지를 쓰라.  
힌트: $(2n)^2/n^2$를 계산하고, 점수 행렬 외 연산과 하드웨어 실행도 생각한다.

**M04-Q3.** $z=ab+c$, $L=(z-10)^2$, $a=1,b=4,c=2$에 대해 정방향으로 $z,L$을 계산하고 $dL/da,dL/db,dL/dc$를 구하라. 이후 같은 프로그램의 결과를 다른 사람이 확인할 수 있도록 저장해야 할 자료·분할·환경 정보 다섯 가지를 적어라.  
힌트: 먼저 $dL/dz$를 구하고 각 중간 계산의 편미분을 곱한다. 기록 정보에는 시드 외의 재현 조건을 넣는다.
