# 네 안건의 혼합·비교 실험과 2026년 후속 연구 검토

**검토 기준일: 2026-10-16 | 실행 전제: Python·일반 Windows 노트북 CPU**

대상은 기존 「모델선정 4안건 통합보고서」의 네 안건이다. 샘플은 10행·10척이며, 정식 데이터로 모델을 학습·비교한 결과는 아직 없다. **[확인]은 자료·논문에서 확인한 내용, [판단]·[제안]은 이번 프로젝트에 대한 해석**이다. 아래 수치 예시는 실제 모델 성능이 아니다.

## 먼저 답하면

- **혼합과 개별 비교 모두 가능하다.** 먼저 역할이 같은 모델끼리 비교하고, 도움이 확인되는 조합만 남기는 순서가 적절하다.
- **TabM의 직접적인 2026년 후속 연구로 TabPack을 확인했다. ICML 2026 정식 논문이다.** 다만 현재 CPU 환경에 곧바로 더 적합하다고 확정할 수는 없다. [공식 학회 논문집](https://proceedings.mlr.press/v306/gorishniy26a.html)
- **RealMLP의 ‘2026년판 v2’에 해당하는 직접 후속 논문은 이번 조사에서 확인하지 못했다.** 관련 확률 보정 연구와 공식 구현 개선은 확인했으며, 각각 아래에 구분했다.
- **[판단] TabM·RealMLP를 기준 후보로 유지하면서, TabPack과 학습·보정 개선을 조건부 비교 대상으로 추가하는 것이 타당하다.** 논문 발표 연도만으로 기존 후보를 폐기할 근거는 부족하다.

## 1. 네 안건을 어떻게 섞을 수 있는가?

### 1-1. 기존 순위는 성능 순위가 아니라 검증을 시작하는 순서다

| 기존 안건 | 맡은 역할 | 다른 안건과 연결하는 방법 |
|---|---|---|
| **1순위: TabM + 작은 LightGBM** | 숫자 특징으로 조업형태 분류 | 2번·4번의 **같은 조업 클래스 확률**과 결합 가능 |
| **2순위: RealMLP + 작은 LightGBM** | 1번과 같은 분류 과제의 대안 | 1번과 개별 비교 후, 서로 다른 오류를 줄이는지 확인 |
| **3순위: DTE + 전역 이상 기준** | 평소와 다른 항적에 이상점수 부여 | 1번·2번·4번의 분류기와 **역할을 나누어 함께 사용** |
| **4순위: GIST 참고 이미지 조합** | 항적 이미지가 분류에 추가 정보를 주는지 확인 | 작은 CNN의 분류 확률과 숫자 특징 분류 확률을 결합 |

4번은 기존 보고서에서 제안한 **입력을 바꾼 수정안**이다. 현재 WKT 샘플에는 원 GIST의 속도·방향 변화 입력이 없어, 단순 항적 그림을 사용하는 모델을 ‘GIST 원 논문 재현’이라고 부르면 부정확하다.

### 1-2. 추천하는 세 가지 혼합 방식 [제안]

**A. 같은 문제를 푸는 모델들의 확률을 합친다 — 가장 먼저 시험**

- `TabM + LightGBM`, `RealMLP + LightGBM`을 우선 비교한다.
- 이후 필요하면 `TabM + RealMLP` 또는 `숫자 특징 모델 + 작은 CNN`을 추가한다.
- **쉬운 예시:** 조업이 두 종류뿐이라고 가정하자. TabM이 `(자망 0.8, 통발 0.2)`, RealMLP가 `(자망 0.6, 통발 0.4)`를 내면, 동일 비중 평균은 `(자망 0.7, 통발 0.3)`이다.

이를 **확률 평균 앙상블**이라고 한다. 클래스 이름·순서를 맞추고, 혼합 비중은 학습 영역 안의 검증 자료로 선택해야 한다. 평균했다고 확률이 자동으로 정확해지거나 과적합이 사라지지는 않는다.

**두 혼합안에 들어 있는 같은 LightGBM을 중복 집계하지 않는다.** 예를 들어 `TabM+LightGBM`과 `RealMLP+LightGBM`을 다시 평균하면, 의도와 다르게 트리의 비중이 커질 수 있다. 실제 실험에서는 개별 모델의 예측을 저장한 뒤 최종 비중을 명시한다.

**B. 분류와 이상탐지를 나란히 둔다 — 이번 과제에 자연스러운 연결**

```text
WKT 항적 → 공통 숫자 특징 ┬→ 조업형태 분류 → 조업 종류·분류 확률
                         └→ 전역 이상 기준 / DTE → 시간대별 이상점수
```

- 예: `TabM 또는 RealMLP + DTE + 전역 이상 기준`.
- **분류 확률 0.8과 이상점수 0.8은 다른 뜻이다.** 두 값을 그대로 평균하지 않는다.
- 분류기를 쓰더라도 전역 이상 경로는 유지한다. 이상 기동을 다른 조업으로 잘못 분류했을 때 이상징후가 가려지는지 확인하기 위해서다.

DTE와 전역 이상점수도 원래 단위가 다르다. 두 점수를 결합할 때는 **높을수록 이상이 되도록 방향을 맞추고, 학습 영역 안에서 고정한 참조 분포로 0–1 순위 점수로 변환**하는 안을 비교한다. 이렇게 만든 0.9도 사고 확률 90%를 뜻하지 않는다.

**C. 모델 내부 구조·전처리를 바꿔 결합한다 — 후순위 실험**

예를 들어 TabM에 RealMLP의 일부 전처리나 학습 설정을 적용할 수는 있다. 그러나 이는 **우리가 만든 새 수정안**이며, 기존 두 논문이 그 조합의 성능을 입증한 것은 아니다. 한 번에 한 요소만 바꾸어 도움이 있었는지 비교한다.

**[판단] 네 안건을 모두 넣는 것보다 A와 B부터 시험하는 편이 낫다.** TabM·RealMLP의 오류가 비슷하면 함께 넣어도 이득이 작고, 학습·추론 비용만 증가할 수 있다. 복잡한 추가 모델로 예측들을 다시 학습하는 **스태킹**은 충분한 선박 수와 누수 없는 검증 예측을 확보한 뒤 검토한다.

## 2. 각 안건을 공정하게 비교하는 실험안

### 2-1. 비교를 세 묶음으로 나눈다 [제안]

| 묶음 | 최소 비교 대상 | 확인할 질문 |
|---|---|---|
| **① 조업 분류** | 작은 LightGBM 단독 / TabM 단독 / RealMLP 단독 / 각 MLP와 트리의 혼합 | 신경망과 혼합이 단순 기준보다 실제로 나은가? |
| **② 이상탐지** | 전역 강건 기준(극단값에 덜 휘둘리는 기준) / DTE 단독 / 두 점수의 혼합 | 같은 오경보 수준에서 사고 전 이상징후를 더 잘 찾는가? |
| **③ 선택적 확장** | ①의 선정 모델에 이미지 추가 / TabM·RealMLP 상호 혼합 / 조건이 맞으면 TabPack | 추가 비용에 비례하는 이득이 있는가? |

①을 비교할 때 이상탐지 경로를 고정하고, ②를 비교할 때 분류기를 고정한다. ③에서는 **한 번에 하나만 추가**한다. 그래야 무엇이 좋아졌는지 설명할 수 있다.

### 2-2. 과적합을 막기 위해 먼저 고정할 조건

1. **선박 단위로 나눈다.** 같은 선박의 다른 시간대가 학습·최종 평가 양쪽에 들어가지 않도록 한다. Test A의 신규 선박 조건을 모사하기 위해서다.
2. **최종 평가 선박은 마지막까지 남겨 둔다.** 학습 영역 내부에서 특징·학습 중단 시점·혼합 비중·확률 보정을 고른다. 마지막 평가 결과를 보고 다시 설정을 고르면 새로운 독립 평가가 필요하다.
3. **공통 특징과 시간 예산을 맞춘다.** 거리·굴곡 등 원래 특징은 같게 하고, 각 모델이 요구하는 수치 변환은 학습 부분에서만 정한다. RealMLP의 자체 전처리 위에 표준화를 무조건 반복하지 않는다.
4. **검증 예측에도 누수를 막는다.** 혼합·스태킹용 예측을 만들 때 해당 선박의 정답을 기본 모델의 학습·학습 중단 시점 선택에 쓰지 않는다. 선박을 나누어 이런 예측을 모은 것을 선박 단위 OOF 예측이라고 한다. 학습 행을 그대로 맞춘 예측으로 혼합 모델을 훈련하지 않는다.
5. **같은 분할·여러 초기값에서 반복한다.** 예를 들어 3개 초기값으로 흔들림을 확인한다. 다만 3회 반복만으로 통계적으로 우월하다고 확정하지 않는다.
6. **모델 크기와 전체 CPU 비용을 기록한다.** WKT 처리·특징 또는 이미지 생성·모든 구성 모델의 추론 시간을 합친다. 저장 크기와 최대 메모리도 함께 비교한다.

**평가 지표 [제안]:** 분류는 클래스별 F1·재현율과 macro-F1을 본다. **Macro-F1은 조업 종류별 F1을 같은 비중으로 평균한 값**이다. 확률 품질은 log loss·Brier score로 별도 확인한다. 두 지표는 틀린 답에 큰 확신을 주는 경우 등을 벌점으로 평가하며, 낮을수록 좋다.

이상탐지는 사고 정보가 확보되면 고정된 오경보 수준에서 사건별 탐지율·사고 전 선행시간을 본다. 해당 시각 이후 자료를 특징·기준 갱신에 쓰지 않는다. 시간대별 항적이 확보된 시점을 확인하고, **사고 후 관측이 포함된 시간대 전체를 사고 전 경보로 계산하지 않는다.** 공식 정량 평가식이 확인되면 그 식을 우선한다.

**현재 샘플로 할 일:** WKT 파싱, 특징 생성, 모델 입력·출력 연결의 오류를 확인한다. 10척 중 일부 클래스는 한 척뿐이므로, 샘플을 나누어 얻은 F1로 모델 순위를 정하지 않는다. 이미지 변환이나 데이터 증강도 독립된 새 선박 정보를 만들어 주지는 않는다.

선박 ID는 분할·이력 연결에 사용하고 분류 입력에서 제외한다. 또한 점별 시각이 없는 현재 자료에서는 순간 속도·가속도를 만들어 입력하지 않는다.

## 3. 2026년 후속·개선 연구를 찾은 결과

### 3-1. ‘새 버전’과 ‘관련 개선’을 구분한 목록

| 연구 | 공개·학회 상태 | 기존 안건과의 관계 | 현재 활용 판단 |
|---|---|---|---|
| **TabPack** | 2026-07-06 공개, **ICML 2026 정식 논문** | TabM 저자들의 MLP 앙상블 후속 연구 | 자원이 맞으면 추가 비교 후보 |
| **Benchmarking Optimizers for MLPs in Tabular Deep Learning** | 2026-04-16 공개, 04-17 개정. **arXiv 기술보고서**로 확인 | TabM 등의 학습법 개선 근거 | Muon 적용 실험을 선택적으로 추가 |
| **Structured Matrix Scaling for Multi-Class Calibration** | 2025-11 최초 공개, 2026-03 개정, **AISTATS 2026 정식 논문** | RealMLP 공동저자가 참여한 확률 보정 연구. RealMLP v2는 아님 | 분류 확률을 보정하는 추가 후보 |
| **Distillation of Tabular Foundation Models into Efficient Predictors** | 2026-10-01 공개. **arXiv 사전공개 논문**으로 확인 | TabM을 작은 학생 모델로 활용하는 확장 연구 | GPU·재현성 조건을 확인한 뒤 후순위 검토 |

정식 학회 등재는 각각 [TabPack 논문집](https://proceedings.mlr.press/v306/gorishniy26a.html), [보정 연구 논문집](https://proceedings.mlr.press/v300/berta26a.html)에서 확인했다. 나머지 두 연구는 [최적화 보고서의 공개 이력](https://arxiv.org/abs/2604.15297), [증류 논문의 공개 이력](https://arxiv.org/abs/2610.01435)을 확인했으며, 이번 조사에서는 정식 학회 등재를 확인하지 못했다. **‘심사 완료 논문’으로 인용하면 안 된다.**

### 3-2. TabPack — 이번에 가장 직접적으로 검토할 후속 연구

**무엇을 바꿨나? [확인]**

- **TabM:** 여러 MLP가 주요 가중치를 공유하고, 멤버들의 주요 학습 설정은 같다.
- **TabPack:** 설정이 다른 여러 MLP와 학습 도구를 묶어 병렬로 학습하고, 학습 도중 조합할 멤버를 선택한다. 본문 구현은 멤버 간 가중치 공유를 사용하지 않는다.
- **쉽게 말하면:** 같은 설정의 여러 예측을 모으는 데서 나아가, 서로 다른 설정들을 한 번에 시험하며 조합한다. 핵심 개선은 좋은 설정을 찾기 위한 반복 작업을 줄이는 데 있다.

논문은 17개 표형 데이터의 성능·시간 등을 비교했다. 다만 학습 설정 다양화가 항상 정확도를 높였다는 뜻은 아니다. 저자들도 주요 실용적 효과를 설정 탐색(튜닝) 필요성 감소로 설명한다. **작은 검증 자료에 대한 과적합 위험과 추가 GPU 메모리 요구**도 명시했다. [논문 §3–5·부록 C](https://arxiv.org/html/2607.05380v1)

**우리 안건과 다른 점·필수 조건 [판단]**

- 입력은 기존처럼 항적에서 만든 **고정된 열의 숫자 특징과 조업 라벨**을 사용할 수 있다.
- 학습 중 여러 조합을 고르므로, 선박별로 분리된 충분한 검증 자료가 중요하다. 현재 10행으로는 적용 이득을 판단할 수 없다.
- 노트북 실험은 **M4 Pro의 내장 GPU와 48GB 통합 메모리**를 사용했다. Windows CPU 성능의 증거가 아니다. [논문 부록 D](https://arxiv.org/html/2607.05380v1)
- 공식 구현의 명시 지원 환경은 **Linux GPU와 Apple M 계열 macOS**다. Windows CPU는 명시된 지원 환경에 없어 별도 실행·비용 확인이 필요하다. 개선·수정 업데이트 예정 공지도 있어 구현 버전을 고정해야 한다. [공식 코드](https://github.com/yandex-research/tabpack)

**선택 판단:** GPU 등 실행 조건이 확보되면 **TabM과 비교할 가치가 큰 2026년 후보**다. 현재 CPU 전제에서는 TabM을 즉시 교체하기보다 조건부 후보로 추가한다. TabPack도 MLP 계열이므로 수업의 MLP 응용이라는 연결은 유지된다.

### 3-3. Muon — 모델을 바꾸지 않고 학습법을 개선하는 연구

**무엇을 바꿨나? [확인]**

최적화 알고리즘은 모델이 틀린 정도를 보고 가중치를 어떻게 수정할지 정하는 방법이다. 이 보고서는 **15개 최적화 방법을 17개 데이터에서 비교**했다. TabM에서 Muon은 AdamW 대비 **11승·5동률·1패**였다. 이는 논문의 정확도·AUC·회귀 지표를 사용하는 비교이며, 어선 F1의 개선 수치가 아니다. EMA라는 가중치 평균 방법도 검토했지만, 고급 MLP 변형에서 효과가 일관적이지는 않았다. [논문 §3·표 1](https://arxiv.org/pdf/2604.15297)

**우리에게 무엇이 다른가? [판단·제안]**

- `기존 TabM + AdamW`와 `같은 구조의 TabM + Muon`을 비교한다. 입력 특징이나 예측 문제는 바뀌지 않는다.
- 모델 구조를 키우지 않고 새 학습법을 검토할 수 있다. **학습 계산·상태 저장 비용은 늘 수 있으며 CPU에서 더 빠르다는 근거는 없다.**
- 학습률은 최적화 방법별로 다시 정해야 한다. 기존 값을 그대로 옮기면 공정한 비교가 아니다.

공식 예시는 **MLP 내부의 행렬 가중치에 Muon을 적용하고, 출력층·입력 임베딩 등은 다른 방식으로 처리**한다. 입력 임베딩은 숫자를 학습용 벡터로 바꾼 표현이다. 모든 가중치를 무조건 Muon에 넘기는 수정은 피한다. [공식 구현 지침](https://github.com/yandex-research/tabular-dl-optimizers#using-muon-and-ema-in-practice)

**선택 판단:** TabM을 버리는 대안이 아니라 **TabM을 유지하며 시험하는 학습 개선안**이다. RealMLP에도 적용 가능성을 연구할 수 있지만, 이 보고서가 RealMLP의 개선을 직접 실증한 것은 아니다. 학회 심사 완료가 필수 조건이면 주 근거보다 탐색 실험의 근거로 둔다.

### 3-4. 확률 보정 — RealMLP의 대체 모델이 아닌 추가 기능

**논문:** *Structured Matrix Scaling for Multi-Class Calibration*, Eugène Berta·David Holzmüller·Michael I. Jordan·Francis Bach, **AISTATS 2026**.

**무엇을 바꿨나? [확인]**

- 분류기가 내놓은 확률을 학습 후 다시 조정하는 **확률 보정** 연구다.
- 단순 온도 보정이 전체 확신의 강도를 조정한다면, 이 방법은 클래스 간 관계까지 유연하게 반영한다. 규제, 즉 조정을 과하게 하지 못하도록 제약하는 방법과 전처리로 과적합을 제어한다.
- **쉬운 예:** ‘자망 확률 90%’라고 표시한 항적들에서 실제 자망 비율이 훨씬 낮으면 과신한 것이다. 보정은 이러한 확률 표현을 조정한다.

표형 실험은 65개 다중 분류 데이터·7개 모델의 예측을 사용했다. RealMLP 자체를 대상으로 한 개선 실험은 아니므로 **‘RealMLP 2026 개선판’이라고 소개하면 부정확하다.** [공식 논문·§4.2](https://proceedings.mlr.press/v300/berta26a.html), [본문](https://arxiv.org/pdf/2511.03685)

**우리에게 필요한 조건 [제안]**

- TabM·RealMLP 또는 최종 혼합 모델의 **클래스별 확률과, 분리된 보정 자료의 정답**이 필요하다. 공식 `probmetrics` 구현을 검토할 수 있다.
- 보정 자료도 학습·최종 평가 선박과 분리하거나, 학습 영역 안에서 선박 단위 교차 검증으로 준비한다. 드문 조업 클래스의 선박 수가 부족하면 복잡한 보정은 보류한다.
- 무보정·단순 온도 보정·구조화 행렬 보정을 비교한다. 확률이 좋아지는지와 F1이 좋아지는지는 별개다. **행렬 보정은 최종 클래스 선택도 바꿀 수 있으므로 F1도 재확인**한다.

**선택 판단:** RealMLP를 교체할 이유가 아니라, 정식 데이터가 충분할 때 **분류 확률의 신뢰성을 높일 수 있는 보조 후보**다. 보정된 조업 확률도 사고 확률은 아니다.

### 3-5. 지식 증류 — 최근 확장이지만 현재는 후순위

**논문:** *Distillation of Tabular Foundation Models into Efficient Predictors*, Minho Jeong·Dooho Lee·Jinmo Lee·Jaemin Yoo, **2026-10-01 사전공개**.

**무엇을 바꿨나? [확인]**

성능이 강한 표형 사전학습 모델을 **교사**, TabM 등을 **학생**으로 삼는다. 실제 입력과 합성 입력에 대한 교사의 확률을 학생이 배우며, 완성된 학생은 교사를 부르지 않고 예측한다. 이런 학습을 **지식 증류**라고 한다. TabM 구조의 직접 후속판은 아니다.

논문은 TabICLv2·TabPFN v3 교사와 TabM·XGBoost 학생을 평가했다. TabArena 51개 데이터에서 같은 학생 구조의 조정·앙상블 기준보다 집계 성능이 개선됐다. 다만 교사 대비 예측 오차 손실이 남았고, 시간 측정은 H200 서버 환경이므로 노트북 CPU의 속도 개선으로 옮길 수 없다. [논문 §3–4·시간 측정 조건](https://arxiv.org/html/2610.01435v1)

**우리 적용에서 확인할 것 [판단·제안]**

- 교사 실행 비용·사용 조건과 학생 학습 비용까지 확인해야 한다. 학생만 작다고 전체 개발 비용이 작은 것은 아니다.
- 논문의 열 섞기 증강인 **CutMix**를 항적 특징에 그대로 적용하면 물리적으로 모순된 조합이 생길 수 있다. 예를 들어 한 연결 구간의 ‘직선 변위’가 ‘전체 이동거리’보다 커지는 가짜 특징을 만들지 않도록 제약이 필요하다. 이는 **우리 데이터에 대한 적용 위험 추론**이다.
- 교사·증강 모두 학습 영역 자료만 사용하고, 최종 평가 선박의 정답을 교사 입력이나 학생 학습에 넣지 않는다.
- 연결된 코드는 이번 확인에서 열리지 않아 재현성 검토를 마치지 못했다. 정식 학회 등재도 확인하지 못했다.

**선택 판단:** 수업의 Knowledge Distillation과도 연결되지만, **기본 모델 비교를 마친 뒤 자원이 확보될 때 검토할 확장안**이다. 이 연구는 TabM을 폐기하기보다 학생 모델로 계속 활용하는 사례다.

### 3-6. RealMLP에 대해서 확인한 것과 확인하지 못한 것

| 구분 | 확인 결과 | 해석 |

## 4. 지금 TabM·RealMLP를 계속 사용할 것인가?

### 4-1. 현재의 권고 [판단]

| 선택 | 지금의 판단 | 판단을 바꿀 조건 |
|---|---|---|
| **TabM 유지** | 기준 후보로 유지. 선택적으로 Muon 비교 | 신규 선박 성능·CPU 비용에서 RealMLP·트리·후속 모델이 안정적으로 우수할 때 교체 |
| **RealMLP 유지** | 다른 학습 방식의 비교 후보로 유지. 공식 구현 버전 고정 | 같은 예산에서 이득이 없거나 비용·불안정성이 크면 제외 |
| **TabPack 추가** | 가장 직접적인 2026년 후속 후보. 현재는 조건부 | 실행 환경·메모리·검증 선박 수가 충분하고 실제 개선이 확인될 때 채택 |
| **보정·증류 추가** | 각각 확률 품질·배포 효율을 위한 선택적 확장 | 필요한 자료·자원과 독립 평가에서의 이득이 확보될 때 채택 |

**새 논문이 기존 모델을 대체할 이유가 되려면 세 가지가 함께 맞아야 한다.**

1. **문제가 맞는가:** 일반 표형 분류의 개선이 신규 어선의 조업 분류에도 나타나는가? 이상탐지까지 해결했다는 뜻은 아니다.
2. **비교가 공정한가:** 같은 특징·선박 분할·시간 예산에서 개선되는가? 논문이 다른 지표로 보고한 숫자를 우리 F1로 읽지 않는다.
3. **실행 가능한가:** 전처리와 모든 구성 모델을 포함한 CPU 시간·메모리·저장 크기가 허용 범위인가?

**[제안] 정식 데이터 수령 전에는 모델 입력과 비교 절차를 준비한다.** 수령 후 `LightGBM → TabM·RealMLP 단독 → 필요한 혼합 → DTE → 조건부 최신 확장` 순으로 검증한다. 핵심 모델 하나의 채택이 끝나기 전에 모든 조합을 크게 탐색하지 않는다.

### 4-2. 기존 제안서에 반영할 짧은 문장

> 항적에서 추출한 숫자 특징을 바탕으로 TabM과 RealMLP 및 트리 기반 모델을 동일한 선박 분할에서 비교한다. 조업 분류와 이상탐지는 별도 경로로 검증하며, 혼합은 추가 이득이 확인될 때 적용한다. 2026년 후속 연구인 TabPack과 학습·확률 보정 개선은 실행 자원과 검증 자료가 확보될 경우 비교 대상으로 추가한다.

이는 **방법을 고정한 구현 완료 선언이 아니라, 검증을 통해 선택을 바꿀 수 있는 제안 단계의 계획**이다.
