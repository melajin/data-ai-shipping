## 추가로 요청하는 것 — Test B 실측과 연결되는 근거 2가지

Test B에서 사고 탐지 성능을 전 선단 7,372척으로 실측한 결과, 명확한 원인 하나를 찾았다. **사고 유형 자체가 지금 쓰는 기하 요약(1시간 단위 위치·길이·상태)에 드러나지 않는다.**

구체적으로:
- 개발 정답 167건 중 기관손상 58건·부유물감김 20건이 최다 — 엔진이 멎거나 그물에 걸려 해상에서 멈추는 유형이다.
- 이 유형의 사고창(±6h)에서 "해상정지" 상태가 나타나는 비율은 15.0%인데, 같은 선박·같은 창 길이에서 **그냥 평소에도 기대되는 비율이 26.0%**다. 사고 때 오히려 덜 나타난다.
- 공백 신호도 마찬가지다. 점수가 높은 후보 중 상당수가 "공백 후 재등장"인데, 이게 사고로 통신이 끊긴 건지 조업 마치고 쉬었다 다시 나간 건지 기하 데이터만으로는 구별이 안 된다.

세 가지 독립 측정이 같은 결론을 가리킨다 — **"해상정지"라는 라벨 하나로는 사고와 정상 조업(투망 대기, 조류 표류, 정박 후 재출항)을 가를 수 없다.** 이건 점수 계산 버그가 아니라 입력 자체의 한계로 보인다.

다음 작업은 점수 가중치를 조정하는 게 아니라 **조업형태별 정상 패턴을 반영하는 새 특징**이어야 한다는 게 B팀의 결론이다. 여기서 Test A가 필요하다. 아래 두 가지를 Test A 작업 과정에서 나온 걸로 채워 달라(README `§2.A` 아래에 "Test B에서 요청하는 추가 근거"라는 제목으로 이미 위치를 만들어 뒀다):

1. **조업형태별 "정상" 움직임이 기하적으로 얼마나 다른가.** 예: 형태별 평균 부분선 길이, 정박 비율, 상태(이동/정지/정박) 분포 비교. 숫자 몇 개면 된다.
2. **Test A의 조업형태 라벨을 Test B의 `s_zone`/`s_change` 계산에 넣는다면 어디에 넣고 뭐가 달라질 것 같은지.** 지금 Test B는 선박 자기 과거 이력과 전체 밀도만 쓰고 조업형태를 전혀 모른다. 구체적 결합 지점과 예상 효과를 1~2문단으로.

새로 실험하거나 숫자를 다시 뽑으라는 요청이 아니다. 이미 가진 Test A 결과·노트북에서 읽을 수 있는 내용이면 충분하다.
