# Test B — 어선 이상항적 분석

> 이 문서는 통합 README의 **Test B(목표 2) 담당 분량**입니다. 각 절의 번호와 제목은 대회 공지 「개발결과물 제출 안내」의 항목 순서를 그대로 따르므로, 팀원이 작성한 Test A(목표 1, 조업형태 분류) 원고를 같은 번호의 절 아래에 이어 붙이면 하나의 README가 됩니다.

## 시스템 개요

어선 항적 데이터를 다루는 이 프로젝트는 두 개의 질문을 순서대로 답합니다. 먼저 **이 배가 평소에 무엇을 하는 배인가**를 가리고(Test A, 조업형태 분류), 그 다음 **그 평소와 다른 움직임이 언제 나타났는가**를 찾습니다(Test B, 이상항적). 앞의 질문이 기준선을 세우고 뒤의 질문이 기준선에서의 이탈을 측정하는 구조입니다.

Test B 파트가 담당하는 구간은 다음 네 단계입니다.

1. **입력 확정** — 시간대별로 집계된 항적 기하 요약(중심점, 부분선 길이, bbox)과 선박 식별값을 받아 구조와 해시를 검사합니다.
2. **이상점수 계산** — 한 관측을 세 가지 축에서 평가합니다. 위치가 그 배의 과거 활동 범위에서 얼마나 떨어졌는지(`s_zone`), 항적의 기하 특성이 자기 이력과 얼마나 달라졌는지(`s_change`), 관측이 끊긴 시간과 그 사이 중심점이 벌어진 거리가 얼마나 큰지(`s_gap`). 세 점수의 평균이 종합 이상점수입니다.
3. **검토 후보 선정** — 선박별로 제공 기간 전체에서 가장 높은 점수를 받은 시각을 뽑아 100척의 후보 목록을 만듭니다.
4. **근거 제시** — 각 후보마다 세 구성점수, 그 시점까지 쌓인 과거 관측 수, 직전 시각의 점수, 동점 수를 함께 출력합니다.

세 점수를 끝까지 분리해 두는 것이 이 구성의 핵심입니다. 단일 점수만 내놓으면 "점수가 높다"가 위치 때문인지, 행동 변화 때문인지, 애초에 비교할 과거 자료가 없어서인지 구분할 수 없습니다. 네 번째 단계의 출력은 검토자가 그 세 경우를 즉시 갈라볼 수 있도록 설계했습니다. 실제로 후보 100척 중 39척은 과거 관측이 24행에 못 미쳐 `s_change`를 쓸 수 없으며, 이 사실이 점수와 나란히 표시됩니다.

**Test A와의 접점.** Test A의 조업형태 분류는 "이 배의 평상시"를 정의하는 쪽이고, Test B의 고정 기준자료(밀도 사전, 공백·거리 분포)는 그 평상시를 수치로 굳힌 형태입니다. 다만 이번 제출 패키지에서 두 파트는 하나의 실행 파이프라인으로 연결되어 있지 않습니다. Test B의 점수 함수는 조업형태 라벨을 입력으로 받지 않고, 선박 자신의 과거 이력과 전체 학습 밀도만 사용합니다. 조업형태별 기준선을 Test B에 주입하는 설계는 향후 과제로 남겨 두었습니다.

## 2. 데이터 및 모델

### 2.1 입력 데이터

| 항목 | 내용 |
| --- | --- |
| 적용 입력 | `inputs/observations.parquet` — 2025년 1월 1일 0시 ~ 6월 30일 23시, 100척, 46,705행 |
| 입력 단위 | 선박 1척의 1시간 구간 1건 |
| 주요 컬럼 | `rfid_id`(선박 식별값), `ts`(정수 시간키), `source_ordinal`(원본 행 순서), `cen_lon`·`cen_lat`(시간대 기하 중심점), `len_m`(부분선 길이), `bbox_m`(경계상자 크기) |
| 선박별 관측 수 | 최소 1행, 최대 3,413행 |
| 상태 분포 | 저속굴곡 28,284 / 정박정지 13,873 / 이동 2,313 / 해상정지 2,024 / 연안정지 211 |
| 비교용 저장 결과 | `inputs/stored_expected.parquet`, `inputs/stored_candidates.csv` — 재현 대조에만 사용하며 점수 계산에 들어가지 않음 |

`cen_lon`·`cen_lat`은 1시간 동안의 항적 전체를 하나의 기하 중심점으로 요약한 값입니다. 좌표별 시각이 원본에 없으므로 이 값에서 속력·침로를 복원하는 처리는 하지 않았고, 관측 사이의 경로를 보간하지도 않았습니다. 그림의 점들은 중심점의 산점도이며 선으로 잇지 않았습니다.

데이터는 대회 제공 자료이며 외부 데이터를 추가하지 않았습니다. `references/`의 참조분포는 2026년 학습 구간 항적에서 산출한 것으로, 공백·거리 참조는 각각 3,879,693건을 모집단으로 합니다(중위수 1시간 / 85.7m).

### 2.2 점수 구성

| 성분 | 계산 방식 | 가용 조건 |
| --- | --- | --- |
| `s_zone` | 과거 방문 격자까지의 거리와 학습 밀도의 희소도를 결합 | 첫 관측부터 계산 가능 |
| `s_change` | 과거 길이·형상 요약의 robust z와 상태 빈도 변화 | 과거 관측 24행 이상 축적 후 |
| `s_gap` | 직전 관측과의 시간 간격, 중심점 이동 거리를 각각 참조 CDF에 대입해 평균 | 직전 관측 존재 시 |

종합점수는 계산 가능한 성분들의 산술평균을 `[1e-6, 1]`로 절단한 값입니다. 46,705행 중 `s_change` 결측 1,974행, `s_gap` 결측 100행(각 선박의 첫 관측)이며 `s_zone`은 전 행에서 계산됩니다.

후보는 선박별 전체 기간 최고점으로 정하고, 동점이면 원본 `source_ordinal`이 작은 행을 택합니다. 이번 입력에서 동점이 발생한 선박은 없습니다. 직전 3·2·1시간의 참조 점수는 그 시각에 실제 관측이 있을 때만 채우며, 해당 선박 수는 각각 33·38·58척입니다. 가까운 다른 시각의 관측으로 빈칸을 대체하는 처리는 넣지 않았습니다.

### 2.4 성능 지표와 한계

사고 탐지 성능은 2026년 개발 자료에서 별도로 측정했습니다. 이 자료의 사건 100건·RFID 82개는 원본 사고표에 선박 식별 컬럼이 없어 시공간 조건으로 연결한 잠정 대응입니다. 지표는 사고시각 ±6시간 내 top-1 적중률이며, 대회 공식 F1과는 다른 내부 지표입니다.

| 방법 | 평가 가능 | ±6h 적중 | 중앙오차(h) |
| --- | --- | --- | --- |
| 고정 기준선 B0(전기간 최고점) | 100/100 | 3/100 | 1,053.5 |
| 최장 관측 공백 재개 시점 | 100/100 | 1/100 | 1,220.5 |
| 저속 조건 방향 분산 | 37/100 | 0/100 | 909.0 |
| 공백 대비 중심점 거리 비율 | 97/100 | 1/97 | 1,095.0 |
| 시간대 가중 | 100/100 | 4/100 | 998.5 |
| 동료 동시성 제외 | 100/100 | 4/100 | 827.0 |

**현재 수준은 사고 시각을 특정하는 데 이르지 못했습니다.** 최고 적중이 100건 중 4건이고 중앙오차가 800시간대이므로, 이 점수는 사고 판정값이 아니라 검토 우선순위 지표로 사용해야 합니다. 임계값을 설정해 자동 경보를 내는 기능은 넣지 않았습니다.

확인되지 않은 항목은 다음과 같습니다. 공식 채점식과 허용 시간창, 확정된 사고-선박 대응, 정상 운항 구간의 오경보율, 원본 자료의 시간대와 실제 수신 가능 시각입니다. 또한 2026년 참조분포로 2025년 항적을 계산한 결과이므로, 이 수치는 사후 재현이며 2025년 당시의 실시간 예측 성능과는 구분됩니다.

### 2.5 실시간 전환을 위한 입력 검증

`support/`에는 사후 점수 계산과 분리된 입력 계약 검증 모듈이 있습니다. "관측 구간 종료 ≤ 실제 자료 가용 시각 ≤ 판단 시각" 조건을 검사해, 미래 시각·역순 전송·상충 중복은 격리하고 시간대나 가용 시각이 확인되지 않은 행은 판단을 유보합니다. 동봉된 가공 예제 9행의 처리 결과는 수락 3·중복 1·격리 3·유보 2이며, 이 모듈은 점수와 경보를 생성하지 않습니다.

실제 운영으로 넘어가려면 실제 수신 시각 기록, 판단 시점에 참조자료가 존재했는지의 확인, 확정 정상·사고 라벨에 의한 임계값 보정, 탐지 지연·미탐·오경보율 측정이 필요합니다.

`run.ps1 -Output results/reproduction_new`도 2단계와 동일하게 동작합니다.

**입출력.** 입력은 `inputs/`와 `references/`이며 실행 중 수정되지 않습니다. 출력은 `--output`으로 지정한 새 폴더에 `scored_rows.parquet`(시간별 전체 점수), `candidates.csv`(선박별 근거 100행), `summary.json`(재현 대조 결과와 실행 기록), `execution_config.json`, `execution_provenance.json`으로 생성됩니다. 지정한 폴더가 이미 있으면 덮어쓰지 않고 종료합니다. 매 실행마다 입력·참조·소스 코드의 SHA-256을 `config.json`의 기록과 대조합니다.

보고서를 다시 만들려면 `python reports/build_report.py`를 실행합니다. 이 명령은 `reports/`와 `figures/`만 갱신합니다.

이번 제출본의 기준 실행 결과는 `results/reproduction_001/`에 보존되어 있으므로, 재실행 없이도 모든 수치를 확인할 수 있습니다.

## 7. AI 활용범위 및 주요 검토 과정

**활용 도구.** AI 코딩 에이전트 2종을 역할을 나눠 사용했습니다. Claude(Opus 5) — 코드 통합·검증·문서 작성. Codex(gpt-6-astra, reasoning effort high) — 데모영상 제작.

**주요 활용 내용.** 기존 실험 코드에서 점수 함수를 분리해 독립 실행 패키지로 재구성, 저장 결과와의 전수 대조 검증 코드 작성, 입력 계약 검증 모듈과 합성 테스트 작성, 분석 과정 노트북 작성과 실행 검증, 그림·보고서 생성, 데모영상 녹화.

**참가자 주요 기여 및 검증.** 과제 해석과 작업 범위를 결정했고, 성능 수치의 타당성에 반복적으로 문제를 제기해 지표 정의를 교정했습니다. 구체적으로는 ±6시간 국소화를 주 평가 관문으로 사전 고정할 것, 잠정 연결된 사고 자료를 확정 정답과 분리해 보관할 것, 결과를 본 뒤 유리한 산식을 고르는 방식을 금지할 것을 결정했습니다. 내부 지표가 recall 성격만 측정하고 있다는 점, 후보 선정 단위를 관측 행이 아니라 항차로 봐야 한다는 점도 참가자 검토에서 나온 교정입니다.

**검토한 대안 및 실패사례.** 사고시각 국소화를 개선하려고 아래 접근을 사전 기준을 정한 뒤 시험했고, 모두 채택하지 않았습니다.

| 접근 | 결과 | 제외 사유 |
| --- | --- | --- |
| 시간대 가중 | ±6h 4/100 | 기존 적중 3건을 전부 잃고 다른 4건을 맞혀 순증 1건. 전체 기간 통계를 사용하는 설계라 기준선 대비 개선으로 확정하지 못함 |
| 동료 동시성 제외 | ±6h 4/100 | 같은 사유. 셔플 p값이 낮았으나 개선 검정이 아님 |
| 관측 순서·전이 대리값 (Round009) | Tier0–1 top-1 2/60 | 사전 비교 4개 중 3개 실패 |
| `lin_raw` 백분위 점수 (Round010) | 사고창 대조 Δ=−0.1511, 순열 보정 p=0.0145 / top-1 0/48 | 평균 차이는 관찰됐으나 사고시각 순위로 이어지지 않음 |
| 위치 거리 CDF 순위 (Round011) | B0 2/60 → 자기+동료 1/60 | 사전 4개 관문 모두 실패 |

이 과정에서 사후 선택 편향을 피하기 위한 규칙을 함께 적용했습니다. 같은 100건을 반복 확인한 결과는 탐색 결과로만 기록하고, 그 자료에서 고른 산식을 동일 자료로 재평가하지 않았습니다. 정답을 본 뒤 여러 방법의 결과를 합집합으로 모으면 Tier0–1 6건이 적중하지만, 이는 예측기가 아니므로 성능으로 계산하지 않았습니다.

**최종 선택 이유.** 위 대안들이 사전 기준을 통과하지 못했으므로, 검증되지 않은 보정을 쌓는 대신 **기존 고정 기준선을 그대로 유지하고 재현성과 근거 제시를 완성하는 쪽**을 선택했습니다. 성능이 미달인 상태에서 점수 산식을 더 늘리면 사후 선택 편향만 커지고, 공식 채점식과 확정 정답이 확보되기 전에는 개선 여부를 판정할 수 없다고 판단했습니다. 대신 검토자가 점수의 근거와 자료 부족을 직접 확인할 수 있도록 구성점수·과거 이력·동점 정보를 모두 출력하는 구조에 비중을 두었습니다.
