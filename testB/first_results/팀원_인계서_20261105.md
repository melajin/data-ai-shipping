## 6 실제 점수 계산 방법

이번 계산은 기존 `run_008_testB_20261101.py`의 참조 생성 함수와 `score_vessel`을 호출했다. 새 `run.py`는 대상 명부·출력 경로를 연결하고 저장된 항구점의 조회 함수를 재구성하며, 원행 추적과 A 선택을 추가한다. 따라서 전체 실행기를 수정 없이 그대로 실행한 것은 아니다. 커스텀 숫자 변환 로더는 사용하지 않았다.

Train 참조가 2026년 전체 자료라는 점에서 이번 결과는 제공 자료를 사용하는 사후 분석이다. 실제 2025년 시점에 운용 가능한 실시간 시스템을 재현했다고 표현하지 않는다.

### 6.2 구역 성분

`s_zone`은 과거 미방문 구역까지의 거리와 Train 조업 밀도를 절반씩 합친다.

```text
거리 항 = min(과거 방문 셀 중심까지 최소거리 km / 20, 1)
밀도 항 = 1 - min(조회 밀도 / 3, 1)
s_zone = 0.5 × 거리 항 + 0.5 × 밀도 항
```

첫 행은 비교할 과거 방문 이력이 없어 거리 항을 0으로 둔다. 이미 방문한 셀이면 거리 항은 0이다. 밀도 조회는 0.01도 셀의 선박 수가 3척 이상이면 그 값을 쓰고, 아니면 0.05도 셀로 넘어간다. 참조가 없으면 밀도 항은 1이다. 실제 실행 코드의 밀도 항은 위 고정식이며 밀도 자체에 분위수 변환을 적용하지 않는다.

### 6.3 변화 성분

`s_change`는 이전 유효 행이 24개 이상일 때 계산한다. 24시간 연속 관측이라는 뜻이 아니라 **과거 24행**이다.

경로 길이와 직선성 대용값의 과거 중앙값에서 벗어난 정도를 robust z로 계산하고 `1 - exp(-abs(z)/2)`로 변환한다. 상태 변화는 `1 - 과거 동일 상태 비율`을 사용한다. 사용할 수 있는 항목의 평균이 변화 성분이다.

직선성 대용값은 `bbox_m / len_m`이다. 실제 경로의 시작점–끝점 변위를 사용한 직선성과 다르다. 캐시에 원 WKT와 점 순서가 없어 진짜 직선성을 복원하지 않았다.

상태는 정박정지·해상정지·연안정지·이동·저속굴곡으로 나눈다. 정지 기준은 길이 50m 이하와 경계상자 100m 이하이며, 정지 상태 구분에는 항구·자기 정박지 1km 및 2km 경계를 쓴다. 이동 기준은 길이 3,000m 초과와 직선성 대용값 0.6 이상이다. 나머지 비정지 행은 저속굴곡이다. 이러한 상태명은 실제 운항 상태의 확정 정답이 아니다.

Test 선박의 자기 정박지는 과거 야간 정지 셀에서 누적한다. 야간은 20~23시와 0~3시이며 현재 행을 처리한 뒤 이력을 갱신하므로 다음 행부터 반영된다.

### 6.4 공백 성분

`s_gap`은 이전 관측과 현재 관측의 시간 차이, 중심점 이동거리를 Train 분포의 누적순위로 바꾼다.

```text
CDF(v) = 정렬된 Train 참조에서 v 이하인 값의 수 / 참조 수
s_gap = 0.5 × CDF(관측 공백 시간) + 0.5 × CDF(중심점 이동거리)
```

첫 행은 이전 관측이 없어 결측이다. 같은 값도 CDF에 포함하는 `searchsorted(side="right")`를 사용한다. 점수는 공백 뒤 다시 관측된 **현재 행 시각**에 붙는다. 공백 시작시각이나 사고시각을 직접 추정하는 식이 아니다.

시간 차이는 시간대 수준이며 이동거리는 중심점 간 거리다. 좌표별 시각에 기반한 실제 속력·가속도로 해석하지 않는다.

### 6.5 최종 점수

```text
score = 결측이 아닌 s_zone, s_change, s_gap의 평균
유한한 score는 [0.000001, 1] 범위로 제한
```

바닥값은 0을 허용하지 않는 기존 출력 방식을 유지한 값이다. 정상 확률이나 사고 판정 임계값이 아니다. 결측 성분을 0으로 채우지 않으므로 성분 수에 따라 평균의 구성이 달라진다.

이번 전체 행에서 관찰한 성분 분포는 다음과 같다. 평균은 각 성분의 비결측 행만 사용했다.

| 성분 | 비결측 행 | 결측 행 | 평균 | 최솟값 | 최댓값 |
|---|---:|---:|---:|---:|---:|
| 구역 | 46,705 | 0 | 0.026355 | 0.000000 | 1.000000 |
| 변화 | 44,731 | 1,974 | 0.339507 | 0.015990 | 0.977461 |
| 공백 | 46,605 | 100 | 0.717596 | 0.456163 | 0.998914 |

현재 데이터에서는 공백 성분의 평균이 다른 성분보다 높다. 동일 가중 평균이 각 성분을 비슷한 수준으로 반영한다고 가정할 수 없다. 다만 이 분포만으로 공백 성분이 사고 탐지에 유효하다거나 불필요하다고 결론 내릴 수는 없다.

## 7 시각 후보와 제출 파일의 의미

### 7.1 A 선택

선박별 행은 `(ts, rfid_time, source_ordinal)` 순서로 정렬해 점수를 계산한다. 각 행의 변화·방문 이력에는 그 행보다 앞선 관측만 사용한다. 이후 **전체 제공 기간의 최댓값**을 찾아 A로 선택한다. A 선택 자체는 전체 기간을 본 사후 선택이므로 실시간 경보 성능과 다르다.

최고점이 같으면 원본 `source_ordinal`이 가장 작은 행을 선택한다. 이번 100척에는 최고점 동점이 없었다.

`B`는 A가 속한 이상 구간의 첫 임계 초과 시각이고, `C`는 해당 구간의 지속 조건 확인 결과다. 지속 조건을 통과하면 C=B다. A/B/C는 독립 모델 세 개의 투표가 아니다. 실제 B/C와 사고 판정 임계값은 이번 결과에 포함되지 않는다.

### 7.2 제출 형식

| 순서 | 열 이름 | 현재 채운 내용 |
|---:|---|---|
| 1 | `rfid_id` | 새 명부의 문자열 ID와 순서 |
| 2 | `사고시각` | 사고 판정 없이 A를 넣은 기준선 |
| 3 | `이상항적 점수` | A의 최종 점수, 소수점 6자리 반올림 |
| 4 | `시각1` | A보다 3시간 전. 실제 관측행이 있을 때만 입력 |
| 5 | `시각1 이상항적 점수` | 위 시간대의 점수 |
| 6 | `시각2` | A보다 2시간 전. 실제 관측행이 있을 때만 입력 |
| 7 | `시각2 이상항적 점수` | 위 시간대의 점수 |
| 8 | `시각3` | A보다 1시간 전. 실제 관측행이 있을 때만 입력 |
| 9 | `시각3 이상항적 점수` | 위 시간대의 점수 |

시각 문자열은 `YYYYMMDD H`다. 예를 들어 `20250611 7`처럼 한 자리 시간도 0을 붙이지 않는다. 원자료의 시간 기준을 유지했고 별도 시간대 변환은 적용하지 않았다. CSV는 UTF-8 BOM으로 저장했다.

**`사고시각` 열 이름은 제출 형식에서 가져왔으며 값의 확정성을 보증하지 않는다. 현재는 100척 모두에 A를 채웠다. 따라서 사고/미사고 판정에 따라 공란을 나누는 최종 결과는 아니다.** 미관측 보조 시각은 보간해서 채우지 않는다.

## 8 원행 추적과 데이터 열

`hourly_scores`는 20열이다.

| 열 | 의미와 사용상 주의 |
|---|---|
| `rfid_id` | 대상 선박 ID. 문자열로 읽어 명부와 결합 |
| `part_dt` | `YYYYMMDD` 날짜 |
| `rfid_time` | 0~23 시간대. 좌표별 시각이 아님 |
| `row_index` | 월별 원본 데이터 행 번호. 0부터 시작 |
| `source_month` | 원본 월 |
| `source_file` | 원본 파일 식별자 |
| `source_ordinal` | 앞 월의 전체 원행 수 합 + 현재 월 `row_index` |
| `key_valid`, `wkt_valid` | 기존 키·기하 검사 결과 |
| `n_coords` | 좌표 수 요약 |
| `len_m` | 부분선 내부 선분 길이의 합, m |
| `bbox_m` | 경계상자 대각선 길이 요약, m |
| `cen_lon`, `cen_lat` | 항적 중심 대리점의 경도·위도 |
| `ts` | 원본 `_ts_hours`가 만든 정수 시간 인덱스. Unix 초가 아님 |
| `state` | 규칙 기반 활동 상태 |
| `s_zone`, `s_change`, `s_gap` | 세 성분. 빈 값은 0이 아닌 결측 |
| `score` | 결측을 제외한 성분 평균과 바닥값 적용 결과 |

한 사례를 추적할 때는 `candidate_A.csv`의 RFID·`source_ordinal`을 `hourly_scores`와 연결한다. 해당 행의 `source_month`, `source_file`, `row_index`로 원본 위치를 찾는다. 월별 `row_index`만으로는 고유 행을 식별할 수 없다.

캐시에 원 WKT와 부분선 경계가 저장돼 있지 않으므로 정확한 원경로를 이 결과만으로 복원할 수 없다. 부분선을 임의 연결하거나 중심점 이동을 실제 경로 전체의 이동거리라고 표현하지 않는다. CRS/datum과 시간대 표준도 별도 확정되지 않았다.

이전 원본 CLI의 `--stage scores`·`--stage submit`을 그대로 실행하지 않는다. 그 CLI는 옛 명부와 기존 고정 출력 경로를 사용한다. 이번 `run.py`는 새 명부와 `first_results` 아래 출력으로 연결한다.

## 11 확인한 범위와 남은 한계

이번 실행 코드의 확인 항목은 대상 100행과 ID 순서, 시간대별 46,705행, 유한 점수의 `[0.000001, 1]` 범위다. 저장된 제출 CSV도 다시 읽어 100행·9열·명부 순서·A와 점수의 형식을 확인했다. 최종 생산 결과를 별도 독립 계산자가 다시 전부 계산해 검산한 것은 아니다. 이전 로더 감사 통과 수를 이번 점수 산출물의 독립 검산 결과로 옮겨 쓰지 않는다.

현재 성능 평가가 막히는 이유는 다음과 같다.

| 쟁점 | 현재 확인 수준 | 결과에 주는 제한 |
|---|---|---|
| 2025 Test B 사고 정답 | 확보되지 않음 | 놓침·오탐·시각 오차를 실제 정답 기준으로 측정할 수 없음 |
| 2026 사고–RFID 신원 | 후보만 있고 직접 확정 없음 | 후보를 선박 단위 확정 사고 라벨로 사용할 수 없음 |
| 정상 정답 | 확인 근거 없음 | 사고목록 부재·미연결을 정상으로 처리할 수 없음 |
| 사고자료의 개발 사용 조건 | 기록상 미확인 | 사고 기반 튜닝을 공식적으로 허용된 평가처럼 표현할 수 없음 |
| 임계값·B/C | 실제 기준 미확정 | 최종 사고 여부와 공란 처리를 결정하지 못함 |
| 공식 평가 수식과 시간 경계 | 실행 근거로 확정하지 않음 | 내부 ±6시간 진단을 도입해도 공식 점수와 구분해야 함 |
| 성분의 사고시각 포착력 | 미평가 | 구역·변화·공백 중 어느 시각 후보가 더 좋은지 결론 없음 |

고정 세 성분은 공간적 낯섦, 변화, 관측 공백을 측정한다. 사고가 이런 이상으로 나타난다는 가정은 아직 검증되지 않았다. 높은 점수의 원인이 단순 미방문 구역이나 자료 수신 공백일 수 있다.

같은 기간의 2026 사고와 항적을 쓰면 연도 문제는 줄일 수 있지만, 신원·정상 정답·분할 문제까지 자동으로 해결되는 것은 아니다. 2026에서 규칙을 만들고 2025에 적용할 때의 연도 간 분포 변화도 별도 한계다.

## 12 팀원이 이어갈 작업

다음 작업은 기존 기준선을 고정한 채 점수와 시각 선택이 사고와 어떤 관계가 있는지를 확인하는 것이다. 아래는 후속 작업안이며 이번 인계서 작성 중 실행하지 않았다.

| 우선순위 | 작업 | 재사용할 입력 | 남길 결과 | 판단할 질문 |
|---|---|---|---|---|
| 1 | 세 성분별 최고점 시각과 현재 A 비교 | 생성된 `hourly_scores` | 선박별 구역·변화·공백·평균의 후보 시각, 시간 차이, 결측·저정보 상태 | 현재 A가 어떤 성분에 의해 선택됐는가 |
| 2 | 2026 사고기간에서 평가 가능한 단위 확정 | 기존 사고 연결표와 2026 항적 | 확정 신원과 약한 연결을 분리한 평가 명세 | 선박 정답이 있는가, 없으면 무엇까지 측정할 수 있는가 |
| 3 | 신원 연결이 부족하면 시공간 셀 단위 약한 평가 설계 | 기존 후보 관계와 사고 시각·좌표 | 후보 조건·배경 구간·분할·분모가 고정된 약한 평가 자료 | 근접 사건 포착을 얼마나 설명하는가 |
| 4 | 동일 조건에서 시각 선택 규칙 비교 | 분할을 고정한 개발·검증 자료 | 성분별 후보와 공백 시작·끝 등의 시각 오차 비교 | ±6시간 내부 적중률이나 오차를 개선하는가 |
| 5 | 근거가 생긴 뒤 사고 판정·공란 규칙 결정 | 개발 자료, 독립 평가 자료 | 변경 전후 CSV와 비교표 | 어떤 배를 미사고 또는 자료 부족으로 남길 것인가 |

약한 평가에서는 사고 주변의 선박을 실제 당사자로 확정하지 않는다. 시공간 셀의 사건 포착률은 선박 단위 사고 recall·precision과 다르다. 사고 목록에 없는 셀도 자동으로 확정 정상 정답이 되지 않는다. 이런 자료로 계산한 수치는 약한 라벨 기반 내부 진단이라고 이름 붙인다.

평가에 사고시각을 쓸 경우, 사고 주변만 잘라 최대값을 선택한 결과를 전체기간 탐지 성능이라고 보고하지 않는다. 평가할 단위의 전체 관측기간에서 예측 시각을 먼저 고정하고 사건과 대조한다. 개발·검증에 같은 사건과 관련 선박이 반복해서 들어가지 않도록 연결 관계를 고려해 분리한다. 참조나 정규화도 평가 자료의 영향을 받지 않게 구성한다.

우선순위 1은 이미 생성된 점수만으로 가능하다. 결과를 보고 유리한 규칙을 선택했다면 해당 결과를 독립 성능 검증으로 다시 사용하지 않는다. 점수 분포에 맞춰 Test 분위수로 사고 임계값을 고르는 것은 현재 근거를 보완하지 못한다.

## 13 유지할 기준선과 작업 범위

현재 `first_results`의 CSV·Parquet·참조와 `results.json`은 첫 실제 결과 기준선이다. 후속 변경은 다른 폴더에 저장하고, 동일 100척·동일 관측기간·동일 입력으로 비교한다. 후보 시각이 달라진 배, 저정보 대상, 결측 성분, 참조 적합 범위를 함께 남긴다.

추가 로더 동등성 라운드, 실측 없는 메모리 최적화, 실제 자료에서 확인되지 않은 토큰의 방어 확장은 현재 우선작업에서 제외한다. 원본 로더가 실제로 실패하거나 결과 계산을 막는 문제가 확인됐을 때 해당 범위만 수정한다. 이미 확보한 선별 46,705행을 이유 없이 다시 추출하지 않는다.

이번 인계는 자료와 결과를 공유하기 위한 문서 작성이다. 외부 전송, 공식 제출, git push, 추가 모델 실험은 수행하지 않았다. 기술 결과 생성과 팀원의 이해도는 구분하며, 팀원의 설명·수정·판단 능력은 별도 활동에서 확인한다.

팀원이 결과를 설명할 때 확인할 질문은 다음과 같다.

1. 왜 이상점수 0.92를 사고확률 92%라고 말할 수 없는가?
2. 한 행뿐인 선박에서도 A가 생기는 이유는 무엇인가?
3. 변화 성분이 결측인 최고점과 세 성분이 모두 있는 최고점을 어떻게 비교해야 하는가?
4. 공백 뒤 관측 시각과 공백 시작·사고시각은 왜 다를 수 있는가?
5. 시공간 후보나 약한 라벨로 측정한 수치의 분모는 무엇인가?
