# Round 002 예정 검증 — 새 Test B 100척의 고정 규칙 추론

상태: Round 001 최종 감사와 인계 ACK 전까지 실행하지 않는다. 이 파일은 후속 계획이며 실행 결과가 아니다.

## 질문

새 제출샘플 Test B의 100척 모두 기존 원자료 기반 항적 캐시에 관측된다. 이전 100척 점수 캐시와는 교집합0이다. 기존 점수 계산의 참조자료·적합 범위를 확인하고 테스트 적합 없이 같은 고정 계산을 새100척의 전체 제공 기간에 적용할 수 있는가?

## 고정할 것

- 입력은 v2 제출샘플의 정확한 Test B ID100개와 그 순서다. ZIP member 및 사본의 SHA/명부는 Round 001 독립 직접 검산과 연결한다.
- CSV12쌍 전체 바이트 동일 W0 결과와 최종 독립 감사 범위를 계승한다. 다시13GB를 전수 해시하거나 캐시를 처음부터 무조건 재생성하지 않는다. 사용하려는 캐시의 원파일/파싱계보·필수열·시간·유효성은 필요한 범위에서 확인한다.
- 기존 점수식·참조 분포·지도와 하이퍼파라미터를 동결해 순수 추론을 준비한다. Test 기반 스케일러·KDE·군집·분위수·임계값을 새로 적합하지 않는다. 기존 scorer가 금지된 Test 적합을 포함하는지 실행 전에 코드로 확인한다.
- 동일 선박의 전체 제공 항적을 사용하는 사후 추론이며 실시간 경보/미래자료 미사용을 주장하지 않는다. 사고시각 근처로 관측기간을 자르지 않는다.
- score는 탐색적 이상 정도이며 확률·사고 정답이 아니다. A는 최고점 후보시각이며 사고 예측/사고 발생시각의 검증 결과로 표시하지 않는다. B/C·사고 여부·제출 파일은 근거 게이트가 충족되기 전 생성하지 않는다.
- 기존 legacy100척 결과를 새100척으로 이름만 바꾸거나 행순서로 이식하지 않는다. 소프트웨어·함수 계약과 대상별 점수는 구분한다.
- canonical·원자료·기존 캐시·선행 라운드는 읽기전용이다. 새 구현·실행·결과·검산은 testB/round_002/ 소유권별 폴더에만 쓴다. 고정 출력 경로의 canonical 스크립트를 실행하지 않는다.

## 작업 분해 권고

1. 새 Sol high 감독이 Round 001 인수 ACK 후 소유권을 받는다. 먼저 실제 버전 orchestration 가이드와 AGENTS.md의 메모리 규칙을 읽는다.
2. Luna xhigh 준비 담당: 새100척·기간·필수특징·소스계보·참조자료·코드 부작용·현재RAM/예상피크를 조사하고 실행 전 manifest를 만든다. 소규모 명부검산100척과 실제 새 점수 생성은 구분한다.
3. 감독: 기존 고정 scorer의 Test 적합 여부와 입력 호환·RAM 계획을 검토한다. 새2025대상 탐색 추론이 가능한지 결정하고 필요한 공통 점수/결측/동점/원행 추적·floor/자료부족 표시 규칙을 실행 전에 고정한다. 임계값은 학습하지 않는다. 구현상 새로운 임의 판정 기준을 추가하지 않는다.
4. Luna xhigh 실행 담당: 승인된 고정 scorer를 새100척 전체기간에 적용하고 시간대별 성분/점수·후보A·유효행/결측/관측범위·원본 추적을 저장한다. 데이터 부족과 정상/미사고를 구분한다. 실행 불가면 원인과 가능한 부분 결과를 남긴다.
5. 별도 Luna xhigh 검산자: 명부·점수/시각·입력 불변·샘플 원행·참조 적합범위·Test 비적합·실제 exit를 검산한다. 변경된 범위만 검산하며 결과를 최고점 합의나 사고 성능으로 바꾸지 않는다.

## RAM·세션

큰 로딩/추론 전 가용RAM과 예상 최대량·병행 작업을 확인한다. 부족하면 먼저 계약·코드검토·문서 등 독립 가능한 작업을 진행하고 재개 직전 RAM을 다시 확인한다. parquet 열 투영·청크·순차 처리를 우선한다. 사용자 프로세스를 임의 종료하거나 메모리 watch/polling을 만들지 않는다.

완료된 실제 worker는 handle별로 묶어 최신 dispatch 완료와 같은 handle의 활성 후속 유무를 확인한 뒤 worker-release한다. released/실제 창 닫힘과 retained/unknown을 구분해 기록한다. 식별/소유권 미확인 창을 강제 종료하거나 현재 감독·새 감독·실행 중 worker를 닫지 않는다. 사용자 추가 승인 없이 역할을 Astra나 다른 모델로 대체하지 않는다.

## 결과와 종료 분기

새100척의 고정 탐색 점수·후보A·자료 부족표를 만들 수 있으면 이전 legacy100척과 직접 성능 비교하지 않는다. 분포가 달라도 다른 집단이라는 점을 먼저 설명한다. B/C와 사고 성능은 보류 사유를 명시한다.

새 입력의 참조/코드계보가 불완전하면 그 범위를 고치고 다시 검산한다. 사후 임계값·정답을 만들어 통과시키지 않는다. 사고–RFID 신원, 확인 정상자료, 사고파일 개발사용 범위, 공식 시간오차 수식이라는 외부 근거는 여전히 필요하다. 유효한 로컬 검증을 마친 뒤에도 외부 근거 없이는 성능 평가를 진행할 수 없다면 blocked_external_evidence를 구체화한다. 같은 검색·같은 모델을 의미 없이 반복하지 않는다.

라운드마다 이전 대비 변화·현재 결과·다음 검증을 보고하고, 성공 기준 미충족이며 유효한 후속이 있으면 또 새 Sol high 감독에게 실제 인계한다. 사용자에게 반복 실행 허락을 다시 요청하지 않는다.
