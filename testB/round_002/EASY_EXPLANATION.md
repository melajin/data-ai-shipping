# 새100척 계산 준비에서 확인한 것

새 제출 대상100척의 항적을 골라46,705행을 확보했습니다. 다른 실행자가 원 캐시를 청크로 다시 읽어, 선별한 모든 행의 값과 원행 번호를 비교했습니다. 46,705행이 전부 일치했고, 선박별 요약100개도 일치했습니다.

유효한 행이 있다는 사실은 계산의 출발 조건입니다. 어떤 배는 행이1개뿐입니다. 그래서 형식이 맞는 행이 있다고 해서 사고를 판단할 정보가 충분하다고 말할 수는 없습니다. 원자료의 날짜와 시간을 보존했으며, 시간대와 좌표 기준의 정확한 의미는 아직 미확인입니다.

기존 점수 함수는2026 학습자료로 만든 공통 기준을2025 Test에 적용하는 구조입니다. 그러나 기존 명령을 그대로 실행하면 옛100척 명부와 기존 출력 경로를 사용합니다. 새 명부·원행 번호·독립 출력 경로를 보존하는 실행기를 따로 준비한 이유입니다. 별도 합성자료 검사로 점수식과 최고점 동점 규칙을 확인했지만, 실제 새100척 점수는 아직 계산하지 않았습니다.

독립검산은 기록 오류도 발견했습니다. 현재 해시와 옛 해시가 한 문서에 설명 없이 섞여 있어 첫 감사를 실패로 남겼습니다. 생산자가 옛값을 역사 기록으로 분리하고, 다른 실행자가 그 변경만 다시 확인했습니다. 처음 실패한 사실과 수정 과정을 모두 남겼습니다.

다음 문제는 공통 기준을 재구성할 때의 메모리입니다. 기존 코드는 큰 표를 여러 번 올리고 복사하므로, 2GiB면 충분하다는 초기 예상은 보장되지 않습니다. 다음 라운드에서는 작은 청크를 먼저 숫자형으로 바꾸면서 같은 값·순서·제외 규칙을 유지할 수 있는지 확인합니다. 큰 실행 직전에는 가용 RAM을 다시 확인합니다.

최고 탐색점수의 시각A도 실제 사고 정답은 아닙니다. 사고 선박의 신원·정상 정답·독립 평가 분할·임계값 근거가 없어 사고 성적표는 만들 수 없습니다. 이번에는 자료와 계산 준비를 검증했으며, 학습자의 이해나 실제 선박 안전을 검증한 것은 아닙니다.

스스로 확인할 질문:

1. 행이1개인 배와3,000개인 배를 같은 정보량으로 볼 수 있는가?
2. 원행 순서와 시간 순서를 따로 보존하는 이유는 무엇인가?
3. 코드 검사 통과와 사고 성능 검증에는 어떤 근거 차이가 있는가?
