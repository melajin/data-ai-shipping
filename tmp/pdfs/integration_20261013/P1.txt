3. 문제 배경 —  V-Pass와 이 과제가 나온 이유
3.1 공지가 설명하는 배경 공지
어선은 어업 종류와 조업 방식에 따라 서로 다른 항적 패턴을 보이며, 이 특성은 선박 위치정보를 통해 데이터로 수집되고
있습니다. 근거 법령으로 「어선법」 제5조의2(어선위치발신장치)와 「선박패스(V-Pass) 장치 등의 설치기준 및 운영 등에
관한 고시」 제9조가 제시되어 있습니다.
관할 해역이 경기도보다 넓어, 수많은 어선을 사람이 모니터링해서는 사고·불법조업을 빠르게 판별하기 어렵습니다.
조업방식별 항적 패턴을 학습하고 시간대별 항적과 비교하면, 평상시와 다른 이동 양상을 찾아 사고 관련 이상징후를 조기에
탐지할 수 있다는 것이 문제의 출발점입니다.
3.2 V-Pass(선박패스)란
V-Pass는 어선의 위치를 자동으로 발신하는 어선위치발신장치의 한 종류로, 어선에 설치되어 해양경찰 측 육상 수신국으로
위치를 보냅니다. 공개 연구(J ournal of M arine Science and Engineering, 2023)에 따르면 다음과 같은 특징이 있습니다.
단말의 SOS 버튼을 누르거나 안테나가 분리되면 해양경찰 상황실로 경보가 전송됩니다.
자동 출입항 신고 시스템과 연동되어, 파출소 방문 없이 출항·입항 신고가 가능합니다.
해당 연구의 실험에서는 단말이 30초 간격으로 위치를 저장했고, 발신은 규정상 최대 10분 이내 간격을 지켰습니다.
같은 연구에서 약 4시간 동안 기대 패킷 480개 중 269개만 수신되어 약 44%가 누락된 사례가 보고되었습니다.

추론  왜 1시간 경로가 여러 파트로 나뉘는가
공지는 파트 분리 기준을 설명하지 않습니다. 가능한 원인은 (a) 신호 수신이 끊겼다가 다시 이어진 경우, (b) 서로 다른
수신국·출처의 기록이 합쳐진 경우, (c) 원천 데이터를 시간대별로 가공하는 과정의 규칙 등입니다. 샘플 31703261 은
6개 파트에 점 126개가 있지만 고유 좌표는 7개뿐이며, 첫 파트와 나머지 파트의 좌표 정밀도가 다릅니다(4.5절). 이는 (b)
의 가능성을 시사하지만 확정할 수 없습니다. 파트 수, 파트 간 간격, 중복점 비율은 그 자체로 피처나 데이터 품질 지표가
될 수 있습니다.
4.4 좌표를 거리(미터)로 바꾸기
경도·위도는 각도이므로 그대로 빼면 거리가 되지 않습니다. 대략적인 환산은 다음과 같습니다.
위도 1° ≈ 111 km (어디서나 거의 일정)
경도 1° ≈ 111 km ×  cos(위도) → 한국 해역(위도 약 33~38°)에서는 약 88~93 km. 예: 위도 35°에서 약 91 km
예시: 소수점 넷째 자리 0.0001°는 위도 방향 약 11 m, 경도 방향(35°N) 약 9 m입니다.
정확한 계산은 하버사인(Haversine) 공식을 쓰거나, 좌표를 미터 단위 투영좌표계(예: 한국 통합좌표계 EPSG :5179, U TM  52N
등)로 변환한 뒤 유클리드 거리를 쓰는 방법이 일반적입니다 제안 .
데이터  좌표의 소수부에 60을 곱하면 깔끔한 “분(′)” 값이 나옵니다. 예: 34.71062166… ° → 34° 42.6373′. 즉 원천 데이터는
“도 분.분분분분” 형식으로 기록된 뒤 십진 도로 변환된 것으로 보입니다 추론 . 이는 좌표에 정밀도 단위(격자)가 있다는
뜻이고, 4.5절의 계단형 움직임을 설명합니다.
4.5 좌표 정밀도와 시간 정보의 한계
(1) 좌표 정밀도가 레코드마다 다르다 데이터
대부분의 레코드는 0.0001′(약 0.2 m) 단위까지 기록되어 있지만, 31007894  전체와 31703261 의 일부 파트는 0.01′(위도
방향 약 18.5 m) 단위로만 기록되어 있습니다. 그래서 실제로는 정지해 있어도 좌표가 18 m씩 “계단처럼” 튀며, 누적
이동거리를 단순 합산하면 과대평가됩니다(5장의 31007894: 누적 109 m, 시작-끝 직선거리 24 m). 추론  단말 종류나 수신
경로의 차이일 수 있습니다.
(2) 점마다 시각이 없다 데이터
각 점이 몇 분 몇 초에 찍혔는지 알 수 없으므로 속도 = 거리 ÷  시간을 정확히 계산할 수 없습니다. 샘플 10행 중 6행이 1시간에
점 17~18개를 가지고 있어, 약 3~4분 간격으로 고르게 기록된다고 가정하는 것은 가능합니다 추론 . 그러나 점이 2개뿐인 행,
4개뿐인 행, 126개(중복 다수)인 행도 있어 이 가정이 항상 맞지는 않습니다.
제안  시간 한계를 다루는 실용적 방법
1. 시간 불변 피처 우선: 직선성, 선회각 분포, 이동 범위, 경로 모양처럼 속도를 몰라도 계산되는 피처를 중심에 둡니다.
2. 1시간 단위 지표: “이 시간대에 얼마나 이동했는가(m/h)”처럼 시간대 단위로만 정의된 값은 가정 없이 계산됩니다.
3. 균등 간격 가정은 보조로만: 점 간격을 60분 ÷  (점 수 − 1)로 두는 “추정 속도”는 피처 하나로 쓰되, 점 수가 적거나

4. 연속 시간대 이어붙이기: 같은 선박의 같은 날 연속 시간대 행을 이어 하루 궤적을 복원하면 출항~입항 같은 긴 패턴을
볼 수 있습니다.

7. 과제 2 상세 —  이상항적 탐지
7.1 문제 정의 공지
정상 및 사고 구간이 포함된 전체 항적을 활용해 선박별 또는 동일 조업형태별 평상시 항적패턴을 분석하고, 신규 항적이
기존 패턴과 얼마나 다른지 분석합니다.
일부 사고 선박에 대해 사고선박 ID, 사고 발생시각 등 항적과 연계 가능한 사고정보가 제공됩니다.
평가는 Test A와 분리된 Test B로 합니다. 참가자는 Test B의 시간대별 이상점수(Anomaly Score)를 산출하고, 주최측은
별도로 보유한 실제 사고 발생시각을 기준으로 사고 전·후 이상징후를 얼마나 정확하고 조기에 탐지하는지 평가합니다.
이상징후 예시: 급격한 이동양상 변화, 급선회, 기존 조업구역 이탈, 동일 선박의 평상시 항적과 현저히 다른 패턴.
7.2 왜 어려운가
1. 사고 사례가 매우 적습니다. 사고 정보가 “일부” 선박에만 있으므로 “사고 vs 정상” 분류기를 학습하기 어렵습니다. 사고
정보는 학습보다는 검증에 쓰는 편이 현실적입니다 추론 .
2. “정상 데이터”가 깨끗하지 않습니다. 공지에 따르면 전체 항적에 사고 선박의 사고 전·후 항적도 섞여 있습니다. 정상 패턴을
학습할 때 사고시각 전후 구간을 빼지 않으면, 모델이 이상 패턴까지 “정상”으로 배울 수 있습니다.
3. 이상 ≠ 사고. 통발 어선의 잦은 방향 전환은 평소 행동이고, 기상 악화로 일찍 귀항하는 것도 “이상”이지만 사고는 아닙니다.
조업형태·선박별 기준선이 없으면 오탐이 많아집니다.
4. 조기 탐지와 오탐의 균형. 모든 시간대에 높은 점수를 주면 사고는 놓치지 않지만 의미가 없습니다. 평가가 오탐을 어떻게
벌하는지, “조기”를 몇 시간 전까지 인정하는지는 공지에 없습니다 → 확인 필요.
5. 신호가 끊긴 시간대를 어떻게 다루나. 사고로 단말이 꺼지거나 침수되면 해당 시간대의 행 자체가 없을 수 있습니다 추론 .
Test B에 점수를 매길 행이 없는 시간대를 어떻게 처리하는지도 확인 대상입니다.
7.3 이상 지표 후보

7.4 접근 단계 제안
단계 1. 규칙 기반 점수 (해석이 쉬움, 가장 먼저)
7.3의 지표를 시간대마다 계산 → 각 지표를 학습 데이터 분포에서의 백분위(0~1)로 바꿈 → 가중 평균하거나 최댓값을 취해
이상점수로 사용. 0~1 범위 요구를 자연스럽게 만족합니다.
단계 2. 기준선(Baseline) 비교
선박별 기준선: Test B 선박의 과거 항적이 Train에 있다면, 그 선박의 평소 분포와 비교합니다(“동일 선박의 평상시 항적”).
조업형태별 기준선: 선박 이력이 없으면 과제 1 모델로 조업형태를 추정한 뒤, 같은 형태의 평상시 분포와 비교합니다.
Test B 선박이 Train에 포함되는지는 공지에 없으므로 확인 필요합니다(어떤 기준선을 쓸 수 있는지가 이것으로 결정됨).
단계 3. 학습형 이상탐지
Isolation Forest / One-Class 모델: 정상 시간대 피처로 학습 → 고립되기 쉬운 시간대일수록 높은 점수.
오토인코더 재구성 오차: 정상 항적 패턴을 압축·복원하도록 학습 → 복원이 잘 안 되는 시간대가 이상.
다음 시간대 예측 오차: 과거 몇 시간의 항적으로 다음 시간대를 예측 → 예측과 실제의 차이가 크면 이상.
단계 4. 후처리와 검증
시간 평활: 한 시간대의 튀는 값보다 연속된 이상이 의미 있으므로 이동평균·지수평활을 적용합니다. 단, 과하면 탐지가
늦어집니다(조기 탐지 평가와 상충).
사고 선박으로 검증: 제공된 사고시각 기준으로 “사고 몇 시간 전부터 점수가 올라가는가”, “같은 선박의 평상시 날에는
점수가 낮은가”를 그려 보며 지표 가중치를 조정합니다.

    lon1, lat1, lon2, lat2 = map(np.radians, (lon1, lat1, lon2, lat2))
    a = np.sin((lat2-lat1)/2)**2 + np.cos(lat1)*np.cos(lat2)*np.sin((lon2-lon1)/2)**2
    return 2 * R * np.arcsin(np.sqrt(a))
def record_features(geom_text, stop_m=10.0):
    g = wkt.loads(geom_text)
    parts = [np.asarray(line.coords) for line in g.geoms]
    pts = np.vstack(parts)                     # (N, 2) = [ 경도 , 위도 ]
    lon, lat = pts[:, 0], pts[:, 1]
    step = haversine(lon[:-1], lat[:-1], lon[1:], lat[1:])   # 인접  점  간  거리 (m)
    moving = step[step >= stop_m]              # 정지  잡음  제거 ( 임계값은  실험으로  결정 )
    total = moving.sum()
    disp = haversine(lon[0], lat[0], lon[-1], lat[-1])
    return {
        "n_parts": len(parts),
        "n_pts": len(pts),
        "uniq_ratio": len(np.unique(pts, axis=0)) / len(pts),
        "total_m": total,
        "disp_m": disp,
        "straightness": min(disp / total, 1.0) if total > 0 else 0.0,
        "stop_ratio": (step < stop_m).mean() if len(step) else 1.0,
        "max_step_m": step.max() if len(step) else 0.0,
        "lon_mean": lon.mean(), "lat_mean": lat.mean(),
    }
feat = pd.DataFrame([record_features(s) for s in df["geom"]])
