### 오래된 조건을 어긴 것인지 구분해야 하는 부분

- **“단일 분류기부터 확인하고 필요하면 투트랙”**은 이전의 권장 순서였다. 최신 사용자가 6~10차의 투트랙 적용을 명시했으므로 이를 적용한 것 자체는 지침 위반이 아니다.
- **“모든 FIT 선박의 참여를 보장하지 말자”**는 모든 경우에 금지한다는 규칙이 아니라 여러 FIT 가설을 비교하자는 정리였다. 이번에 REF 선박 전체 요약을 전역 문맥에 넣는 것은 허용 가능한 가설이다. 다만 해당 선택이 최선임을 검증했다는 뜻은 아니다.
- **이전 Macro-F1 중심의 두 seed·신뢰구간 채택 기준**과 이번 Micro-F1+업종별 F1 우선 목표는 구별해야 한다. 새 목표는 적용할 수 있지만, 이전의 엄격한 채택 기준까지 통과했다고 주장하면 안 된다.
- 실제 선택 함수는 6~10차 공통으로 **Micro-F1 + 0.20×Macro-F1 + 0.10×가장 낮은 업종 F1**이다. Micro-F1의 비중이 가장 크지만, Micro-F1만을 엄격히 최대화하는 선택과는 다르다. 이는 업종별 성능도 중시한 실험자의 절충이며 사용자에게 정확히 설명해야 한다.

## 3. 높은 F1의 의미: 무엇이 좋아졌고, 무엇은 아직 아닌가

### 3.1 평가 질문이 바뀌었다

예전 주된 실험은 **FIT에 없던 선박을 업종 공통 특징으로 맞히는가**를 물었다. 이번에는 **이미 과거 기록이 있는 배가 많이 섞인 미래 기간에서 항적 기억을 활용하면 얼마나 맞히는가**를 묻는다. 최상위 문서 Part 1의 5절이 두 평가를 별도로 제안했으므로 시간 분리 자체는 타당하다.

OUTER 6,526척 중 REF와 같은 ID가 5,835척(89.41%), 없는 ID가 691척(10.59%)이다. 따라서 예전 신규 선박 분리 성적과 이번 전체 성적의 차이를 곧바로 ‘알고리즘 변형만으로 얻은 개선폭’이라고 할 수 없다. 평가 대상뿐 아니라 입력, 학습 문맥 수, 변환, 검색, 판정 방식도 바뀌었다.

10차 결합이 TabICL 혼합 단독보다 더 맞힌 순증가 1,336척은 이 평가에서 모두 REF 기존 집단의 순증가다. 신규 집단은 72척을 고치고 72척을 새로 틀려 순증가가 0이었다. 반면 검색 단독 대비 결합은 신규 18척을 순증가시켰다. 즉 **두 경로의 보완 효과는 일부 있지만, 신규 선박 문제의 근본 해결이라고 볼 수준은 아니다.**

7차와 10차의 검색 순위 학습은 새로 훈련된 작은 모델의 효과를 포함한다. 그러나 TabICL의 사전학습 가중치 자체를 계속 갱신해서 얻은 성과는 아니다. 6~10차에 유지된 마지막 FFN 기여 0.5는 내부 계산의 실제 변경이지만, 이번 기간에서 1.0과 0.5를 모두 동일 조건으로 대조하지 않았으므로 그 변경의 단독 기여는 아직 모른다.

창의성으로 설명할 수 있는 것은 **여러 공간 크기의 항적 기억, 시간 분리된 동일 선박 쌍을 이용한 순위 학습, 관측 증거에 따라 결합 비중을 바꾸는 설계**다. 이를 세계 최초 알고리즘, TabICLv2 자체의 입증된 개선, 또는 창의성 점수 확보라고 확대하지 않는다.

### 3.3 신규 선박을 정확히 걸러내는 단계는 완성되지 않았다

10차에서 검색 혼합을 허용한 선박은 5,996척(91.88%)이다. REF에 없는 691척 중 464척(67.15%)도 그 경로에 들어갔다. 승인된 1등 후보의 ID 일치율은 71.51%다. 따라서 승인 여부를 ‘기존 선박임을 알아냈다’로 읽으면 안 된다.

다만 다른 선박을 찾아도 같은 업종이면 조업분류는 맞을 수 있다. 현재 구조를 가장 정확하게 부르는 표현은 **항적 이웃의 업종 정보와 TabICL을 증거량에 따라 결합하는 분류 시스템**이다. 재식별 품질은 별도 보조 지표다. 상위 문서가 경고한 ‘1차에서 어려우면 신규’라는 가정은 채택하지 않았지만, 기존/신규를 정밀하게 구분했다는 목표도 아직 달성하지 못했다.

## 4. 과적합과 누수는 따로 판단해야 한다

|질문|현재 근거|판정|
|---|---|---|
|평가 ID를 정답 조회 키로 썼는가?|추론은 항적 특징을 사용하며 ID는 결과 연결·평가·학습 쌍 구성에 사용. 검색의 ID/질의 라벨 교체 불변성 검사 기록 존재|직접 ID 조회로 점수를 만들었다는 근거는 찾지 못함. 위치·반복 경로를 통한 간접 재식별은 의도적으로 사용|
|미래 항적을 과거 REF 문맥에 섞었는가?|1~3월 고정 REF, 기간별 원천 재집계, REF 전용 변환, 월별 순위 학습의 기준 월 공간 지원량 처리|검토한 코드·감사 범위에서 부합. 원본 전수 독립 검증의 대체물은 아님|
|같은 ID가 REF와 OUTER에 있으면 곧 누수인가?|서로 다른 기간의 관측, 과거 기록을 가진 배를 대상으로 한 문제 정의|그 사실만으로 누수는 아님. 대신 처음 보는 배의 일반화 검증으로 부를 수 없음|
|INNER에서 좋은 설정이 OUTER에도 좋았는가?|10차 업종 배율 보정 전 Micro 0.840178 → 보정 후 0.838339. 정답 33척 훼손, 오답 21척 수정|INNER 선택의 이전 실패가 실제로 관찰됨. 작은 보정도 과적합/분포 이동 위험이 있음. 어느 원인인지 단독 확정은 불가|
|OUTER는 최종 맹검인가?|6~10차 결과를 확인하며 후속 설계. 같은 5~6월을 반복 사용|아님. 다음 실험 설계까지 포함하면 반복 개발 평가이며 선택 편향이 남음|
|재현 검사 통과가 과적합 부재를 증명하는가?|저장된 예측의 CPU 재계산, 일부 표본의 원본 모델 재로딩·FFN 재적용 검사|아님. 계산 재현과 다른 기간·새 배에서의 일반화는 별개의 검사|

**‘과적합이 아니다’도 ‘점수가 높으니 전부 과적합이다’도 현재 근거를 넘어선 단정이다.** 가장 정직한 표현은 ‘기존 선박 특화라는 의도된 조건에서 개발 성능은 개선됐으며, 신규 선박 격차·반복 OUTER 선택·기간 차이에 대한 위험은 남아 있다’다.

원본 모델 재로딩 검사는 전역 512개와 각 지역 문맥의 일부 OUTER 표본을 대상으로 했다. 저장 예측과 일치했다는 것은 해당 표본의 실행 재현 근거이며, 전 OUTER를 모델 재로딩부터 다시 추론했다는 뜻은 아니다.

## 5. 공식 공지와 실제 적용 범위

사용자가 제공한 공지-문제 과제는 Test A를 **원칙적으로 Train에 없는 신규 선박**으로 설명한다. 반면 기존 분석에서 확인한 2026 학습/2025 테스트 ID 문자열 겹침은 88.08%다. 이는 반드시 같은 실제 선박이라는 증거도, 최종 평가의 기존 선박 비율이 약 90%라는 확정 규칙도 아니다.

이번 실험은 **2026년 과거→미래**의 시간 분리다. 제공된 공식 학습 2026년→테스트 2025년 적용과 연도 방향도 다르다. 따라서 다음 세 가지를 구분해야 한다.

1. **정당한 개발 목적:** 이미 관리 중인 배의 과거 항적을 이용해 나중의 관측 기간을 분류한다.
2. **현재 실험이 입증하지 못한 목적:** 처음 등장하는 배 위주인 공식 Test A에서도 전체 Micro 0.838 정도가 유지된다.
3. **확인이 필요한 적용 조건:** 실제 제출 데이터의 ID 의미·기존 선박 구성·항적 재식별 활용 조건. 이 검토만으로 공식 허용 또는 금지를 새로 확정하지 않는다.

또한 이번 OUTER 입력은 5~6월 관측을 모은 **기간 전체 일괄 분류**다. 5월 첫날 실시간 모니터가 6월 자료 없이 같은 성능을 낸다는 뜻은 아니다. 분류 자체가 허용한 관측 기간 전체를 쓰는 것과, 시점별 사고 탐지에 미래를 쓰는 것을 혼동하면 안 된다.

## 6. 빠졌거나 아직 증명되지 않은 항목

아래는 6~10차를 실행하지 않았다는 뜻이 아니라, 상위 문서의 권장 항목 중 **이번 결과만으로 완료라고 표시할 수 없는 부분**이다.

|남은 항목|필요한 이유|
|---|---|
|같은 시간 분할에서 자기 과거 이력을 허용/제외한 전체 시스템 대조|검색이 같은 배의 기억을 이용한 이득과 다른 배에도 통하는 업종 단서의 이득을 더 직접적으로 구분|
|완전 신규 ID 중심 평가 또는 새로 잠근 기간/해역 평가|현재 89.41% 기존 선박 구성과 반복 OUTER 활용의 영향을 줄여 일반화 확인|
|같은 입력·기간·문맥의 FFN 1.0/0.5 대조|‘TabICLv2 내부 변형의 효과’라는 인과적 설명에 필요|
|품질/관측량 특징을 검색 점수에 넣는 경우와 신뢰도에만 넣는 경우의 대조|7·10차 순위 모델은 품질·관측량도 입력한다. 수신 조건의 유사성을 업종/동일 선박 증거로 잘못 사용하는지 효과 분리 필요|
|지역 문맥·월별 추가 예시를 따로 빼는 대조|8차는 지역 문맥 변경과 월별 대표 요약을 함께 사용. 사후 지역 단독 성적은 낮아 각각의 기여를 확정할 수 없음|

|전처리와 문맥 구축을 포함한 실제 배포 시간·메모리 측정|지역 문맥 12개와 검색 자료를 포함한 시스템 비용은 단일 신경망 파라미터 수만으로 설명되지 않음|

추가로 공간 빈도는 **원본 시간대 도형의 호 길이 가중 중심점**을 격자에 넣어 계산했다. 선 전체가 지나간 칸, 체류시간, 실제 순간 속도, 실제 정박 항구의 정답이 아니다. 0.0002도 같은 세밀한 격자도 이 요약점의 반복성을 더 잘 구분한 결과이지, 원본 항적의 모든 세부 행동을 복원한 결과로 설명하면 안 된다. 이 정의는 `inputs/feature_definition.json`에 명시되어 있다.

## 7. 종합 보고서에 사용할 결론

**채택해도 되는 판단:** 사용자의 기존 선박 특화 아이디어는 실제로 시험할 가치가 있었고, 6~10차 시간 분리 개발 평가에서는 이전의 거친 검색보다 세밀한 항적 검색·순위 학습·결합 판독이 더 높은 전체 성적을 보였다. 새 선박을 자동으로 아는 정답 정보 없이 두 경로를 계산했으며, 공식 테스트 라벨을 추정해 F1을 만든 실험은 아니다.

**보류해야 하는 판단:** 알고리즘 자체의 한계를 해결했다, 모든 업종과 신규 선박까지 충분히 좋아졌다, 지역 문맥 특화가 주된 성공 원인이다, 과적합이 없다, 공식 제출에서도 같은 점수가 나온다. 이 주장들은 현재 자료가 뒷받침하지 못한다.

**다음 판단의 초점:** 점수 상승을 인정하되 실제 성과를 만든 검색 부분을 중심으로 설명하고, 신규 선박·채낚기연승낚시의 손해와 INNER 선택의 이전 실패를 함께 기록해야 한다. 새 OUTER를 보고 보정 없는 값이나 다른 혼합을 골라 기존 10차 결과를 소급 교체하지 않는다. 추가 모델 선택이 필요하면 그것을 새 개발 결정으로 표시하고 별도의 검증 근거를 마련해야 한다.
