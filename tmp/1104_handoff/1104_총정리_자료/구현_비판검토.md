# 6~10차 구현에 대한 독립 비판 검토

검토일: 2026-11-05(KST). 대상 실행 폴더는 `TabICLv2_투트랙_6_10차_20261104`이며, 이 문서는 기존 구현·결과·검증 기록을 읽고 해석한 자료이다. 새 학습, GPU 추론, 새로운 모델 실험은 실행하지 않았다. 기존 실험 파일도 수정하지 않았다.

**핵심 판단:** 10차의 Micro-F1 **0.838339**는 저장된 예측과 정답으로 재계산되는 성적이다. 그러나 이 수치는 **과거에 관측한 선박이 89.41% 포함된, 2026년 내부 시간 분리 개발평가**의 결과다. 새로운 선박에 대한 일반화 성적이나 공식 Test 성적, 과적합이 없다는 증명으로 해석하면 안 된다. 직접적인 OUTER 정답 입력이나 미래 특징으로 전처리를 학습한 경로는 검토한 계산 코드에서 발견하지 못했지만, 반복적인 검증 결과 확인에 따른 선택 편향은 남아 있다.

## 1. 무엇을 검토했고, 무엇까지 확인했는가

검토 범위는 다음과 같다.

- 입력 생성: `temporal_data.py`, `fine_grids.py`, 입력 NPZ와 원천·특징 정의 기록.
- TabICL 분류기: `model_core.py`, `local_context.py`, 기존 `readout_variants.py`의 `final_ffn_scale`.
- 재식별: `retrieval.py`, `fine_retrieval.py`, `fine_ranker10.py`.
- 정책 선택·최종 예측: `selection.py`, `finalize_attempt.py`, `choose_fine9.py`, `confidence_decoder10.py`.
- 지표·재현: `validation.py`, `audit_completed.py`, `native_replay.py`, 6~10차 `result.json`, 정책 후보 기록, CPU 감사 및 native 재현 기록.
- 기반 라이브러리 확인: 설치된 TabICL의 캐시 추론 경로와 마지막 FFN 변경 지점. 라이브러리 전체의 모든 기능을 검증했다는 뜻은 아니다.

| 확인된 것 | 이것만으로 확인되지 않는 것 |
|---|---|
| 저장된 예측에서 지표가 일관되게 계산됨 | 실제 제출 Test에서도 같은 성능이 나옴 |
| REF 입력·특징 변환·문맥 구성·확률 결합을 재현함 | 해당 특징이 본질적인 어업 동작을 학습함 |
| 체크포인트와 문맥으로 native 추론 표본을 다시 재현함 | 새로운 선박·해역·계절에서 과적합이 없음 |
| 현재 코드에서 모델 선택용 수치 계산은 INNER를 사용함 | 개발자가 이전 OUTER 결과를 보지 않은 완전한 독립 평가임 |
| 선박 ID 문자열을 분류 입력이나 추론 정답 조회에 넣지 않음 | ID와 상관이 높은 위치·반복 항로를 기억하지 않음 |

따라서 결과에는 **계산 재현성 검증 통과**라고 쓸 수 있다. **일반화 검증 완결**, **누수·과적합 가능성 완전 배제**라고 쓰기에는 근거가 부족하다.

## 2. 평가 단위부터 정확히 이해해야 한다

### 2.1 같은 선박의 과거와 미래를 나누는 평가다

| 역할 | 자료 기간 | 선박 수 | REF에 같은 ID가 있음 | REF에 같은 ID가 없음 |
|---|---|---:|---:|---:|
| REF: 과거 기억과 학습 자료 | 1~3월 | 6,585 | 해당 없음 | 해당 없음 |
| INNER: 설정 선택 | 4월 | 5,981 | 5,577 | 404 |
| OUTER: 개발 성적 확인 | 5~6월 | 6,526 | 5,835 | 691 |

최종 점수는 **선박당 한 번씩** 산출한다. 시간대별 항적 행을 각각 맞힌 정확도가 아니다. OUTER의 업종별 선박 수는 연안복합 3,183, 자망 2,245, 통발 957, 채낚기연승낚시 141이다.

같은 선박의 1~3월 자료를 기억하고 5~6월 자료를 맞히는 방식은, 관리 대상 선박을 반복 관찰한다는 목적에 적합한 검증 축이다. 같은 ID가 양쪽에 존재한다는 사실 자체를 누수라고 판단하면 안 된다. 다만 다음을 구분해야 한다.

1. **기존 선박의 새 관측을 분류하는 능력**과 **처음 보는 선박의 업종을 분류하는 능력**은 서로 다른 질문이다.
2. ID가 같다는 기준으로 나눈 그룹이지, 장비 교체·ID 재부여까지 조사해 물리적으로 같은 배임을 검증한 그룹은 아니다.
3. 1~5차 등의 선박 ID 완전 분리 OOF와 6~10차의 성적 차이는 알고리즘 변경 효과만으로 설명할 수 없다. 평가 문제가 바뀌었다.
4. 5~6월 전체 자료로 선박 한 척을 요약했다. 5월 첫날에 6월 항적까지 알고 실시간 판단할 수 있다는 뜻은 아니다. 기간 종료 후의 일괄 조업분류 성적이다.
5. 2026년 안에서의 시간 분리는 다른 연도·다른 수집 조건의 공식 Test 적용을 직접 검증하지 않는다.

### 2.2 라벨은 기간별 원자료에서 만들었지만, 변경 대응은 아직 제한적이다

각 기간의 정답 `y`는 그 기간 시간대 행에 있는 유효 라벨을 집계해 만든다. 6월 선박 `31703533`의 라벨 누락 행 1개는 라벨 집계에서 제외하되 항적 자료는 유지했다. 같은 선박의 다른 유효 관측 767행은 자망이다. 현재 자료에서 유효 라벨 변경은 확인되지 않았다.

그러나 코드의 실제 동작은 문서에 적힌 미래 대응 방침보다 좁다.

- `temporal_data.py`는 모든 유효 라벨이 전체 기간 선박표의 라벨과 같은지 확인하고, 다르면 중단한다.
- 한 기간에 두 종류 이상의 유효 업종 라벨이 있으면 역시 중단한다.
- 따라서 실제로 업종 라벨이 변하는 자료가 들어왔을 때, 기간별 최빈값을 계속 사용하면서 변경을 기록하는 일반적인 처리까지 구현한 것은 아니다.
- `validation.py`의 감사 함수는 기간 간 변경을 집계할 수 있지만, 입력 생성기의 앞선 중단 조건 때문에 실제 변경 자료가 거기까지 도달하지 못한다.

**현재 성적을 잘못 계산했다는 발견은 아니다.** 현재 유효 라벨이 일치하므로 수치 영향은 없다. 다만 향후 라벨 변경을 처리할 수 있다고 단정하는 설명은 수정해야 한다. 전체 기간 선박표는 현재 ID 인덱싱과 일관성 검사에 사용됐으며, 그 표의 전체 기간 특징을 REF 입력으로 넣은 것은 아니다.

또한 같은 업종 라벨이 지속된다는 사실은 매 시간대가 실제 조업 중이었다는 증거가 아니다. 이동·정박·대기 항적도 선박의 업종 라벨과 함께 들어올 수 있다.

## 3. 전처리에서 지켜진 점과 남은 정보 손실

### 3.1 학습 범위 분리는 코드에 반영되어 있다

`PastFeatureMap.fit(ref)`는 다음을 모두 REF로만 학습한다.

- 결측값을 채우는 중앙값.
- ExtraTrees를 이용한 수치 특징 112개 선택. 사용한 정답은 REF의 업종 라벨이다.
- 0.02도·0.005도 공간 격자를 압축하는 SVD 각 최대 32차원.
- REF에서 관측한 결측 특징의 표시 규칙.

8차의 중앙값·IQR 정규화, PCA 24차원, KMeans 12개 군집도 REF로만 학습한다. 공간 격자의 좌표 사전 역시 REF 관측 셀로 고정한다. INNER·OUTER에서 처음 등장한 셀의 질량을 단순히 버리고 남은 셀을 다시 100%로 만드는 처리는 하지 않는다.

원래 기간별 특징은 161개이며, 선택된 수치 특징·결측 표시·공간 압축 결과 등을 결합한 전역 TabICL 입력은 222개다. CPU 재검산에서 REF/INNER/OUTER의 저장된 입력과 재생성 입력 차이는 0이었다.

이 설계는 미래 자료까지 모아서 평균이나 차원 축소를 학습한 것과 다르다. **공간 특징을 쓴다는 이유만으로 transductive 학습이라고 부르면 부정확하다.** 여기서는 과거에서 정한 표현에 새 항적을 넣는다. 현재 요청 선박의 항적을 사용해 문맥을 선택하는 것 역시 그 자체로 다른 평가 선박의 정답을 사용하는 행위가 아니다.

### 3.2 아직 남아 있는 손실과 편향

| 처리 | 장점 | 제한 또는 반론 |
|---|---|---|
| 시간대→날짜→기간 요약 | 행 수가 많은 날 하나에 지나치게 끌려가지 않음 | 시간 순서와 짧은 사건의 연결이 사라질 수 있음 |
| 날짜마다 같은 비중 부여 | 많이 관측된 날의 독점을 줄임 | 1행만 있는 날과 풍부한 날을 같은 정도로 믿을 수 있음 |
| 중앙값·IQR·분위수 | 극단적인 한 행의 영향을 줄이고 분포를 남김 | 드문 유용한 조업 구간이 여전히 약해질 수 있음 |
| 결측 표시와 REF 중앙값 대체 | 부족한 자료를 무조건 삭제하지 않음 | 결측 방식 자체가 수집 환경이나 해역의 대리 신호일 수 있음 |
| 공간 SVD | 큰 격자를 작은 입력으로 압축 | 저빈도 위치가 압축 과정에서 약해질 수 있음 |
| 여러 해상도 공간 격자 | 같은 해역 안의 세부 반복 위치를 구분 | 위치·항구·장비 정밀도를 어업 단서로 오인할 수 있음 |

공간 히스토그램은 **각 시간대 WKT 선의 길이를 고려한 중심점**을 집계한다. 선의 모든 좌표가 어느 셀을 지나갔는지 그린 완전한 점유 지도가 아니다. 시간대 분포도 관측 행의 시간대 분포이며, 정확한 체류시간·순간 속도·어구를 놓은 시간을 의미하지 않는다.

짧은 이력은 `observed_days <= 7`, 즉 기록이 하나라도 있는 날짜가 7일 이하라는 뜻이다. 첫 관측과 마지막 관측 사이 달력 기간이 7일 이하라는 이전 지표와 혼용하면 안 된다. 유효 도형이 없는 날도 `observed_days`에는 포함될 수 있다.

## 4. 알고리즘을 실제로 어디까지 바꿨는가

| 요소 | 실제 구현 | 정확한 평가 |
|---|---|---|
| TabICL 내부 계산 변경 | 마지막 ICL 블록 FFN 출력에 γ=0.5를 곱해 잔차 기여를 줄임 | 내부 추론 계산을 실제로 변경함. 6~10차 공통 적용 |
| TabICL 가중치 학습 | 기존 체크포인트를 고정하고 `.fit`으로 문맥·캐시 구성 | 새 신경망 가중치를 미세조정한 실험은 아님 |
| 8차 지역별 문맥 | 특징이 비슷한 REF 선박과 서로 다른 월 대표를 문맥에 배치 | ICL이 참고하는 예시 선택을 바꾼 것 |
| 7·10차 쌍별 랭커 | HistGradientBoosting으로 같은 선박인지 구별하는 점수 학습 | TabICL 바깥의 학습 가능한 검색 모듈 |
| 9차 세밀한 위치 기억 | 작은 격자를 더하고 후보 합집합을 재순위화 | 검색 표현과 검색 절차 변경 |
| 10차 신뢰도별 결합 | 검색 점수·점수 차이에 따라 검색/분류 확률 혼합, 업종별 배율 적용 | 시스템 최종 판독 규칙 변경. TabICL 내부 디코더 가중치 학습과 다름 |

γ=0.5는 FFN을 절반 크기로 줄이거나 파라미터를 절반 삭제한 것이 아니다. 계산한 FFN 출력의 기여를 줄인다. γ=0일 때 계산을 건너뛰는 별도 코드가 있지만, 이번 6~10차 선택은 0.5다. 파라미터 저장량 절감이나 전체 추론 비용 절반 감소를 주장할 수 없다.

따라서 가장 정확한 명칭은 **“TabICLv2의 마지막 FFN 기여 조절과, 과거 항적 기억·문맥 선택·신뢰도 결합을 적용한 조업분류 시스템”**이다. “TabICLv2 자체를 새로 학습해 0.8383을 달성했다”는 설명은 맞지 않는다. γ 자체의 기여도 동일 시간분할에서 γ=1과 나란히 대조하지 않았으므로 별도로 입증하지 못했다.

### 4.1 투트랙과 편향 학습은 적용됐지만, 사용자의 첫 그림과 완전히 같지는 않다

기존 선박을 기억하는 방향은 다음 세 부분에 반영됐다.

1. REF 선박 6,585척 모두의 기간 요약을 검색 메모리에 보관한다.
2. 전역 TabICL 문맥에 REF 선박 전체를 넣는다.
3. 지역 문맥에서는 선택된 선박의 기간 요약과 다른 월 대표를 함께 넣어 관리 대상의 반복·변형 패턴을 참고한다.

이는 같은 선박을 여러 epoch 반복 학습해 신경망 가중치에 외우게 하는 방식이 아니다. **과거 사례를 풍부하게 보관하고, 관련 사례를 더 가까이 참고하도록 구성하는 특화**다.

현재 투트랙은 “1차에서 기존/신규를 완벽하게 구분한 후 신규만 2차로 보냄”이 아니다. 검색 결과와 TabICL 업종 확률을 함께 구하고 증거에 따라 섞는다. 기존 선박도 분류기 영향을 받으며, 신규 선박도 유사한 과거 항적의 업종 정보를 참고할 수 있다.

이 혼합 방식 자체는 합리적이지만 **신규 선박 검출을 잘 해결했다는 뜻은 아니다.** `accepted_reid`는 실제 선박 신원 확정이 아니라 검색 결과의 혼합이 켜졌다는 진단 변수로 읽는 편이 정확하다.

## 5. 각 변경에 대한 독립적인 반론

### 5.1 7·10차 재식별 랭커: 유용하지만 신규 거부는 충분히 학습하지 않았다

학습은 REF 안에서 1월→2월, 1월→3월의 같은 ID를 정답 쌍으로 만든다. 한 정답 쌍당 항적이 비슷한 다른 선박 12개를 오답 쌍으로 선택한다. 정답 쌍의 가중치는 12, 각 오답 쌍의 가중치는 1이다. ID는 **학습 정답을 만드는 데 사용**하지만, ID 숫자·문자열 자체나 질의 ID의 정답 업종을 추론 입력으로 조회하지 않는다.

여기에는 세 가지 한계가 있다.

- 양성 선박이 초기 후보에 없어도 학습 쌍에는 강제로 추가한다. 랭커는 정답 후보를 만날 수 있지만, 실제 추론에서 후보 목록에 정답이 없으면 재순위화만으로 복구할 수 없다.
- 학습 질의는 과거에도 있는 선박이다. 과거에 전혀 없는 신규 선박을 통째로 거부하는 능력을 직접 학습한 것은 아니다. 비슷한 오답 선박 쌍을 구별하는 일과 “이 배는 기억에 없다”를 판정하는 일은 다르다.
- 116,363쌍은 116,363척의 독립 선박이 아니다. 8,951개의 월별 질의에 각 13쌍을 만든 것이고, 같은 선박이 다른 월에 다시 나올 수 있다.

랭커 출력은 선택된 양성·어려운 음성 쌍과 인위적 가중치 아래 학습한 점수다. 이를 그대로 “동일 선박일 확률 90%”라고 표현하면 안 된다. 10차가 이 점수를 혼합 비중에 사용하므로 순위가 개선되어도 확률 보정의 정확성은 별도 확인이 필요하다.

### 5.2 8차 지역 문맥: 다양한 월을 고른다는 말의 의미가 제한적이다

REF 특징을 PCA로 압축하고 KMeans 12개 군집을 만든다. 군집 중심에 가까운 약 1,100척에 업종별 보충 선박을 더하며, 선택한 각 선박에서 전체 REF 요약과 가장 먼 월 하나를 추가한다.

“가장 먼 월”은 새로운 행동의 후보를 얻는 간단한 규칙이다. 하지만 실제로 구별에 중요한 조업 구간인지 검증한 선택은 아니다. 관측량이 매우 적거나 잡음 때문에 멀어진 월을 고를 가능성이 있다. 무작위 월, 관측량이 충분한 월, 품질을 제한한 먼 월과의 독립 대조가 없어 이 규칙 자체의 우월성을 말할 수 없다.

또한 12개 지역 문맥에 포함되는 고유 REF 선박의 합집합은 4,809척, 전체의 73.03%다. 나머지도 전역 분류기와 검색 메모리에는 들어 있지만, 모든 선박이 지역 문맥에도 최소 한 번 참여했다고 설명하면 틀린다. 같은 선박의 기간 요약과 월 요약은 일부 관측이 겹치는 의도적 강조이며, 서로 독립인 두 표본으로 볼 수 없다.

### 5.3 9차 세밀한 격자: 성능 개선 신호와 정밀 좌표 기억 위험이 함께 있다

추가 격자는 0.001도와 0.0002도다. 남북 길이로 대략 111m·22m이며 동서 길이는 위도에 따라 더 짧다. “정확히 100m 정사각형·20m 정사각형”이라고 쓰지 않아야 한다.

굵은 격자 후보와 세밀한 격자 후보의 합집합을 만들기 때문에, 굵은 격자에서 놓친 가까운 후보를 회복할 수 있다. 이는 기존 선박의 반복 위치를 구분하려는 목적에 맞는다. 다만 중심점을 20m 안팎으로 나눈 것은 원자료의 실제 위치 정확도가 그만큼 보장된다는 뜻이 아니다.

세밀한 셀이 기억하는 것이 어업 방식인지, 익숙한 부두·정박 지점·좌표 반올림·수신 장치의 특성인지 현재 대조만으로 분리할 수 없다. 격자 시작점을 조금 옮기거나, 현실적인 위치 오차를 주거나, 새 해역·새 계절에서 같은 효과가 나는지 확인하지 않았다. 9차 상승을 **“어업 동작을 더 정확히 이해했다”**로 단정하지 말고 **“현재 과거-미래 선박 집합의 공간 대응이 더 유용해졌다”**로 해석해야 한다.

### 5.4 10차 신뢰도 결합: 전체 성능과 모든 업종 성능이 동시에 오른 것은 아니다

최종 선택은 학습된 세밀한 랭커, 후보 1개, `score_margin`, α=0.75, 업종 배율 `[1.0, 0.9, 1.1, 0.9]`이다. 첫 점수와 1·2위 차이에 따라 검색 비중을 조절한다. 후보가 1개이므로 저장된 temperature=0.08은 최종 1개 후보의 투표 비율에는 영향을 주지 않는다. 1개 가중치가 정규화되어 항상 1이 되기 때문이다.

업종 배율은 INNER에서 선택한 결과이며 OUTER에 적용했다. 그러나 9차→10차에서 채낚기연승낚시 F1은 **0.7860→0.7261**로 내려갔다. 전체 Micro 향상만으로 모든 업종이 개선됐다고 말할 수 없다. 통발 배율 증가, 세밀한 랭커 학습, 신뢰도 결합이 동시에 바뀌므로 각 요소의 개별 기여를 분리한 대조도 아니다.

## 6. 검증을 반복한 만큼 선택 편향을 고려해야 한다

### 6.1 실제 비교한 후보는 회차당 하나가 아니다

저장된 정책 후보 파일과 실행 루프를 대조한 수치다.

| 회차 | INNER에서 비교한 설정 수 | 세부 내용 |
|---|---:|---|
| 6차 | 216 | 후보 수·온도 6조합 × 문턱·혼합 비중 36조합 |
| 7차 | 216 | 위와 같은 선택, 학습된 검색 점수 사용 |
| 8차 | 432 | 분류 기반 확률 2종 × 216 |
| 9차 | 864 | 세밀한 격자 조합 4종 × 216 |
| 10차 | 207 | 검색 3종 × 후보 수·온도 5종 × 신뢰도 규칙 4종 × 혼합 비중 3종 =180, 이후 업종 배율 27 |

9차 선택안은 최종화 함수에서 216개 설정을 한 번 더 평가한다. 이미 앞선 864개에 포함된 설정의 재평가이므로 새로운 독립 후보 216개가 추가됐다고 세지 않았다. 여러 설정이 같은 예측을 낼 수 있고, 이 숫자는 독립적인 학습 모델 개수가 아니라 **기록된 설정 평가 횟수**다.

같은 4월 정답에 여러 설정을 맞추면 우연히 그달에 잘 맞는 규칙을 고를 여지가 커진다. 이 문제는 코드 오류가 아니라 검증 자료에 대한 선택 편향이다. 몇 회차만 실행했다는 이유로 탐색 규모가 작다고 생각해서는 안 된다.

### 6.2 선택 목적은 순수 Micro 최대가 아니다

실제 선택 점수는 다음과 같다.

`utility = Micro-F1 + 0.20 × Macro-F1 + 0.10 × 가장 낮은 업종 F1`

이는 전체 성능과 업종별 성능을 함께 고려하려는 설계다. 사용자의 공동 목표와 연결할 수 있지만, Micro가 최댓값인 설정을 항상 고르는 규칙은 아니다. 10차 INNER의 선택 Micro는 0.868584, 탐색 내 최고 Micro는 0.869587로 약 0.001003 낮다. 따라서 “Micro 최고 모델 선택”보다 **“Micro와 업종 균형을 함께 고려한 설정 선택”**이라고 표현해야 한다.

### 6.3 OUTER는 완전히 새 독립 시험지가 아니다

각 회차의 설정 선택 함수는 INNER 지표만 사용하며, 선택 기록을 저장한 뒤 최종 OUTER 성적을 계산한다. 그러나 두 층위를 구분해야 한다.

- **코드상의 직접 누수:** 현재 구현에서 OUTER 정답을 손실·특징 선택·정책 점수 계산에 넣은 경로는 발견하지 못했다.
- **실험 전체의 적응적 선택:** 이전 회차의 OUTER 성적을 확인하면서 8·9·10차 후속 아이디어를 결정했다. 더 오래된 전체 기간 분석과 1~5차 실험도 이미 존재한다. 그러므로 이번 OUTER는 개발 과정에 영향을 주지 않은 새 holdout이 아니다.

또한 6~9차 `finalize_attempt.py`는 선택 시작 때 OUTER 자료와 정답을 메모리에 읽고, `audit_split_protocol`에서 라벨 일관성도 점검한다. 실제 선택 목적식에 OUTER 정답을 사용한 것은 아니지만, **“선택 전에는 OUTER 정답 파일을 전혀 열지 않았다”**는 엄격한 설명은 코드와 맞지 않는다. 10차 함수 안에서는 선택 기록을 저장한 뒤 OUTER를 읽지만, 전체 개발 이력이 초기화되는 것은 아니다.

이런 이유로 **개발평가 성능**이라는 표현이 적절하다. 다른 팀이 공개한 F1 0.65~0.70과도 평가 자료·평가 단위·F1 종류가 같은지 확인하기 전에는 직접적인 우열을 확정할 수 없다. 앞으로 독립 확인을 한다면 설계와 설정을 먼저 고정하고, 이전 선택에 쓰지 않은 기간·해역 또는 별도 보유 평가 자료를 사용해야 한다. 이미 확인한 5~6월을 이름만 새 holdout으로 바꾸는 방식은 독립성을 회복하지 못한다.

### 7.1 10차는 기존 선박과 신규 선박 사이에 큰 차이가 남는다

관측일이 짧은 채낚기연승낚시 집단은 정답 선박이 6척, 신규이면서 짧은 집단은 1척뿐이다. 이처럼 작은 하위집단 F1은 몇 척의 변화에도 크게 흔들린다. 낮거나 높은 값을 모두 확정적인 모델 성질로 일반화하면 안 된다.

### 7.2 재식별의 의미를 과장하지 않아야 한다

10차에서 검색 혼합이 켜진 선박은 5,996척(91.88%)이다. 이 중 1위 후보 ID까지 일치한 선박은 4,288척으로 71.51%다. 신규 선박 691척 가운데 464척에도 검색 혼합이 켜진다.

이것은 새 선박의 67.15%를 신원까지 잘못 확정했다는 운영 결과와 동일하지 않다. 현재 출력은 검색과 업종 분류의 혼합이며, 비슷한 다른 선박이 같은 업종이면 업종 분류에는 도움을 줄 수 있다. 반대로 이 값을 근거로 신규 선박 거부가 잘 된다고 말할 수도 없다. **재식별 정답률과 업종 분류 성적을 분리해서 보아야 한다.**

현재 동일 ID는 신원 평가의 대리 정답일 뿐, 물리적인 선박 동일성 확인 자료는 아니다. 특히 연도가 바뀌는 실제 적용에서 ID와 배의 대응이 바뀌는 문제는 이번 2026년 내부 평가로 해결되지 않았다.

## 8. 재현 감사의 의미와 범위

저장된 CPU 감사는 입력 ID·라벨·행 정렬, 확률 합과 최종 예측, CSV/NPY/JSON 지표 일치, REF 전용 변환과 지역 문맥 구성, 저장 확률의 결합 결과를 확인했다. 당시 감사에는 233개 원천·산출물 파일의 지문이 포함됐다.

별도 native 재현 기록은 원래 체크포인트와 저장 문맥에서 모델을 새로 구성하고 γ=0.5를 다시 적용했다.

- 전역 분류기 표본 512개: 저장 확률과 최대 절대 차이 0.
- 지역 문맥 12개: 문맥별 최대 512개 이하 표본을 확인, 가장 큰 절대 차이 약 `4.67×10^-7`.
- 체크포인트 가중치 변경 없음.
- 덩치 큰 일시 캐시 파일 없이 체크포인트·설정·문맥으로 복원 가능함을 확인.

하지만 native 재현은 **13개 분기의 표본 추론**이다. OUTER 전체를 모든 분기에서 다시 GPU 추론한 시험이나 다른 하드웨어·라이브러리 버전의 재현성 시험은 아니다. 전체 행에 대한 확률 결합 검산과 native 분기 표본 재현은 서로 다른 검사다.

입력 생성은 이전의 시간대 특징·공간 캐시를 재사용했다. 새 기간 입력과 산출물의 지문은 확인했지만, 이 검토에서 거대한 원본 CSV 전체를 다시 도형 파싱하고 모든 원천 캐시 바이트를 재생성한 것은 아니다. 사후 지문 추가는 현재 파일 상태를 고정할 뿐, 과거 실행 시점의 상태까지 소급 증명하지 않는다.

현재 재현 증거는 제출 프로그램의 안정성을 위해 유용하다. 그러나 모델이 익숙한 항구나 반복 경로에 과도하게 의존하는지는 별도 일반화 시험의 문제다. 두 종류의 검증을 섞지 않아야 한다.
