## 2. 치명적 결함 1 — INNER 보호게이트를 통과한 후보가 0개인데 "보호 완전 성공"으로 공표됨

`grand_fusion_inner_search.py`는 INNER 제약을 `TP0 >= 958, TP3 >= 38`로 선언한다. 11개 혼합 × (pooled/local) = 22개 후보를 재계산한 결과:

```
INNER 보호게이트(TP0>=958, TP3>=38) 통과 후보 수: 0 / 22
INNER TP3 실측 범위: 33 ~ 36   (게이트 38 미달)
```

즉 **INNER에서는 모든 후보가 보호조건 실패**다. 보고서가 말하는 "보호 완전 성공(TP0=2541, TP3=92)"은 전부 **OUTER에서 측정한 값**이다. 선택 가능한 후보 집합을 OUTER의 `TP3 >= 92` 통과 여부로 걸러낸 것이므로, 이는 테스트 라벨을 사용한 후보 선별이다.

**원인(코드 레벨)**: `a3` 탐색 격자가 `np.linspace(1.20, 1.65, 19)`로 묶여 있었고, INNER OOF에서 `TP3 >= 38`에 도달하려면 `a3 ≈ 1.8`이 필요하다(§6 스윕 참조). 게이트가 **격자 밖에 있어 구조적으로 도달 불가능**했고, 그 사실이 보고되지 않은 채 OUTER 게이트로 대체되었다.

## 3. 치명적 결함 2 — 채택된 후보는 INNER에서 하위권이며, 그 열위는 통계적으로 유의하다

| 선택 규칙 | 선택 결과 | INNER | OUTER |
|---|---|---|---|
| 공표 채택 | `BothTab_T1_w10 \| pooled` | 1,396 (11개 중 8~9위) | **3,552 (0.602340)** |
| INNER 최고(정직) | `BothTab_T1_T2 \| pooled` | **1,412** | 3,537 (0.599797) |
| OUTER 최고(완전 누수) | `T1_w10 \| pooled` | 1,401 | 3,554 (0.602679) |
| OUTER 최고 + OUTER 게이트 | `BothTab_T1_w10 \| pooled` | 1,396 | 3,552 |

마지막 두 줄이 핵심이다. **"OUTER 정확도 최대 + OUTER 보호게이트 통과"로 고르면 정확히 공표 모델이 나온다.** 선택 규칙이 OUTER였다는 뜻이다.

INNER 기준 열위는 노이즈가 아니다(INNER OOF 쌍대 McNemar):

```
INNER 최고 vs 공표 채택 :  +27 / -11, net +16, p = 0.014
INNER 최고 vs Trio_Base :  +33 / -15, net +18, p = 0.013
```

**INNER↔OUTER 순위 상관은 음수(Pearson -0.229)**다. 이 후보군 안에서 INNER은 OUTER 성능을 예측하지 못하며, 오히려 INNER에서 유의하게 나쁜 후보가 OUTER 최고가 되었다. 이는 "INNER에서만 튜닝했다"는 절대 규칙이 **혼합비·운영점 선택 단계에서 깨졌다**는 직접 증거다.

## 5. 결함 4 — 통계 서술 과장 및 표 오류

**(a) "p < 0.001"은 성립하지 않는다.** 코드는 paired bootstrap CI만 계산하고 p값은 산출하지 않는다. 쌍대 McNemar 정확검정:

```
GrandFusion vs LGB 5-seed : +246 / -191 → net +55,  p = 0.0097
GrandFusion vs LGB seed42 : +269 / -193 → net +76,  p = 0.00047   (이쪽은 p<0.001 성립)
```

주 비교대상(종전 채택 5-seed)에 대한 p는 **0.0097**이다. 유의하긴 하나 `p < 0.001`은 약 10배 과장이며, 22개 후보 중 최대값을 고른 뒤의 p이므로 다중비교 보정 없이는 그대로 읽을 수 없다.

**(b) 이득이 fold에 집중되어 있다.**

```
fold 0 : base 1166 → cand 1162  (delta -4)
fold 1 : base 1167 → cand 1193  (delta +26)
fold 2 : base 1164 → cand 1197  (delta +33)
```

fold 0에서는 **오히려 손실**이다. "구조적 개선"이라면 3개 fold에서 같은 방향이어야 한다.

**(c) ROUND_REPORT §4.2 혼동행렬이 실제와 다르다.** 대각(정답)은 맞지만 비대각이 최대 11척 틀렸다.

```
실제        보고서      차이(보고서-실제)
[2541 332 37 10]   [2541 329 40 10]   [ 0 -3  3  0]
[1125 814 54 23]   [1114 814 60 28]   [-11 0  6  5]
[ 568 144 105 18]  [ 563 148 105 19]  [-5  4  0  1]
[  18  13  3 92]   [  18  12  4 92]   [ 0 -1  1  0]
```

**(d) Track2 혼합 후보는 검증 모델과 적용 모델이 다르다.** `grand_fusion_inner_search.py`는 INNER에서 t2 확률이 없어 그냥 건너뛰고(가중 0.03이 0 행렬에 곱해짐), OUTER에서는 실제 t2 확률을 더한다. 따라서 `*_T1_T2` 두 후보의 INNER 점수는 OUTER에서 평가된 모델의 점수가 아니다. 이 두 후보는 후보군에서 빠져야 한다.

**(e) 보호 하한 자체가 OUTER 통계로 정의되어 있다(이전 회차 상속 문제).**

```
seed42 OUTER TP = [2389, 889, 108, 90]   → 보호 하한 TP0 = 2389 (동일)
5-seed OUTER TP = [2381, 908, 116,  92]  → 보호 하한 TP3 = 92   (동일)
```

제약의 숫자가 테스트셋에서 측정된 기준선 TP다. 이 틀 안에서는 "보호 충족" 판정이 원리적으로 OUTER 참조를 요구한다.

**(f) §2의 "타 팀 선박중복 88~89%" 진단은 근거 산출물이 없다.** `11_04_final` 전체에서 이 수치는 round_026 서술 문서 2곳에만 존재하고, 중복률을 측정한 코드·CSV·JSON이 없다. 0.838과의 격차를 전부 누수로 귀속시키는 §2는 현재 **측정되지 않은 가설**이다.

## 6. 결함 수정 후 재실험 (정직한 프로토콜)

수정 3건을 적용해 다시 돌렸다(`reexp_honest_fusion.py`):

1. `a3` 격자를 `1.20~1.65` → **`1.00~3.00`(41점)**으로 확장 → INNER 게이트가 실현 가능해짐
2. INNER 확률이 없는 Track2 혼합 **후보 제외**
3. 혼합비·승수·운영점(pooled/local) 선택을 **전부 INNER OOF에서만** 수행, OUTER는 선택된 1개 후보에 **단 1회** 평가

INNER 게이트 통과: **13 / 18** (격자 확장만으로 0개 → 13개). INNER 최고 후보:

```
선택: Trio_BothTab | pooled   (0.40 LGB5 + 0.25 Tab42 + 0.25 Tab2026 + 0.10 Cat,  Track1 미포함)
INNER: 1,415 / 2,361 (0.599322), TP = [1021, 318, 38, 38]  게이트 통과
```

**OUTER 단 1회 평가 결과:**

```
3,538 / 5,897 = micro-F1 0.599966,  macro-F1 0.516198
TP = [2544, 791, 109, 94]   보호: TP0 2544 >= 2389 (PASS), TP3 94 >= 92 (PASS)
vs 5-seed(3,497): +41척  (+260 / -219),  McNemar p = 0.0675
fold별: fold0 -13, fold1 +20, fold2 +34
```

세 가지 함의:

- **정직한 선택은 0.599966에서 멈춘다.** 0.600136(3,539척)까지 **단 1척** 부족하다. 0.60은 돌파된 것이 아니라 **구분 불가능한 경계**에 있다.
- **정직한 프로토콜은 Track1을 뽑지 않는다.** INNER은 일관되게 T1 미포함 혼합을 선호한다. 즉 Round 026의 "공간 kNN이 0.60 돌파를 견인" 서사는 지지되지 않는다. 반면 **사전분포 승수 보정(prior-shift)과 TabICL 듀얼시드 결합은 정직한 조건에서도 살아남았다**(+41척, 보호 PASS).
- 다만 그 +41척의 **McNemar p = 0.0675로 0.05를 넘지 못한다.** 보호조건까지 만족하는 실질 개선은 있으나, 단일 회차 근거로 "유의"를 주장할 수 없다.

### 보조 측정 1 — 22개 후보 분포 (선택 편향 크기)

```
22개 후보 OUTER 정답수: 평균 3,543.6, sd 5.5, 범위 [3,537 , 3,554]
→ 평균 micro-F1 0.600922 / 공표 0.602340 / 정직 선택 0.599966
```

후보 전체가 0.5998~0.6027 구간에 뭉쳐 있다. **어느 후보를 집어도 0.600 전후**이고, 공표값은 그 분포의 상단이다. OUTER 반분 시뮬레이션(400회: A에서 고르고 B에서 평가)도 같은 결론이다.

```
A에서 선택한 후보의 B 성능 : 0.600597
INNER로 고른 후보의 B 성능 : 0.599919
B에서의 사후 최적(oracle)  : 0.603510
선택면 A - 검증면 B 낙폭   : +0.001029  (≈ +6.1척)
```

22-way 선택만으로 약 **+6척(+0.001)**이 거품이다. Track1 상류의 12-way + 42점 승수 OUTER 탐색을 합치면 공표 0.6023과 정직 0.5999의 차이(14척)는 대부분 설명된다.


1. **EXPERIMENT_LEDGER.csv의 round_026 행(`0.6023401729693064`, `completed_verified_grand_fusion_success`)을 그대로 상속하지 말 것.** 정직 재현값 `0.599966`을 병기해야 다음 회차의 기준선이 오염되지 않는다.
2. **Track1 산출물(`probabilities_track1.npz`)은 현재 상태로 재사용 금지.** 혼합비(`w_knn`)와 승수를 INNER에서 다시 고르고, 그 설정의 INNER 확률을 함께 저장해야 한다. 현재 npz는 `w=0.40` 설정의 INNER 확률만 들어 있어 다른 설정을 정직하게 비교할 수도 없다.
3. **보호 제약을 테스트 통계로 정의하는 관행을 끊을 것.** `TP0 >= 2389`, `TP3 >= 92`는 OUTER에서 측정한 기준선 TP다. INNER 비율 기반 제약(재현율 하한)으로 재정의하고, 격자가 그 제약을 포함하는지 **실행 전에** 확인해야 한다(`a3` 상한 1.65 사건의 재발 방지).
4. **후보 수 대비 검정력.** 22개 후보가 0.5998~0.6027(폭 17척, sd 5.5척)에 뭉쳐 있다. 5,897척 단일 평가로는 이 폭을 구분할 수 없다. 앞으로 "최고값"을 보고하려면 다중비교 보정 p 또는 선택-평가 분리(nested) 중 하나는 반드시 붙여야 한다.
5. **다음 단계 권고는 유효.** 전체 7,372척 학습 확장(소수 클래스 2.3배)은 현재 0.60 정체의 유일한 구조적 해법이다. 단, 확장 효과를 측정할 수 있도록 **선택에 쓰지 않은 평가면을 먼저 떼어 둘 것.** 현재 OUTER 5,897척은 26회차에 걸쳐 반복 노출되어 이미 선택면으로 오염되어 있다.
