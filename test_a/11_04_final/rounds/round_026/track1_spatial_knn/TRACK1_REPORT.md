## 3. 실험 1A: S1 스무딩 버그 원인 규명 및 수정 전후 비교

### 3.1 버그 원인 분석
- `round_025/code/s1_features.py` 450행:
  ```python
  total = float(adjusted.sum())
  if total > 1e-15:
      return (adjusted + ALPHA) / (total + ALPHA * N_CLASSES)
  ```
  - `ALPHA = 5.0`, `N_CLASSES = 4`.
  - 이 수식은 사실상 균등분포 `[0.25, 0.25, 0.25, 0.25]`를 향해 가중치 20.0을 부여하는 스무딩입니다.
  - 단 1척의 선박만 관측된 희소 셀(`total = 1.0`, class 0 관측)에서:
    $$\text{post}_0 = \frac{1 + 5}{1 + 20} = \frac{6}{21} \approx 0.2857$$
    $$\text{post}_3 = \frac{0 + 5}{1 + 20} = \frac{5}{21} \approx 0.2381$$
  - 실제 전체 데이터셋의 Class 0 비율은 ~76%, Class 3 비율은 ~3%입니다. 따라서 희소 셀을 한 번이라도 지나간 선박은 Class 0 사후확률이 76%에서 28.6%로 추락하고, Class 3 사후확률이 3%에서 23.8%로 8배 폭증하여 트리가 치명적인 오분류를 유발했습니다 (`1,811 -> 1,781`, -30척).

### 3.2 수정 알고리즘 (Prior-Smoothing & Min-Vessels Threshold)
1. **Fold 학습셋 사전확률(`prior`)로 스무딩**:
   $$\text{post} = \frac{\text{adjusted} + \alpha \cdot \text{prior}}{\text{total} + \alpha}$$
   - 데이터셋의 자연스러운 불균형(Class 0: 76%, Class 3: 3%)을 보존하므로, 희소 셀이라 하더라도 사전확률 주변에 안정적으로 수렴합니다.
2. **최소 선박 수 조건 (`min_vessels >= 3`)**:
   - `total < min_vessels`인 셀은 신뢰할 수 없으므로 다음 상위 해상도로 폴백(0.01° $\to$ 0.05° $\to$ 0.10°).
   - 최상위 해상도에서도 미만일 경우 `prior`를 직접 반환.
