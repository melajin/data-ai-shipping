# Round 007 학습 메모

이번 자료는 본인 학습자용이다. 선수지식·학습시간·연산자원 학습목표 수준은 아직 확인되지 않았으며 시스템 계산의 완료를 학습자의 이해 달성으로 간주하지 않는다. 하드웨어를 연결하거나 검증하는 활동은 없다.

## 흐름과 단계

합성 숫자/클래스 → 같은 전처리와 fitted estimator → feature grouping → 컬럼별 문맥 임베딩 → row/ICL 처리 → 클래스순서 복원 → 확률 비교의 흐름을 관찰한다. 컬럼 분할은 이 중 독립 컬럼 계산 부분에만 들어간다. 실제 선박 입력·전처리 계보와 모델 성능 평가는 다음 단계다.

| 단계 | 기술 목표·구현물 | 관찰·검증 | 설명할 질문 |
|---|---|---|---|
| 소스 | 컬럼 배치축 계약과 원관리자 복원 | source hash·shape·정규화/attention 적용축 검토 | (B,columns,T,group_size)에서 왜 T를 나누면 같은 모델이 아닐 수 있는가? |
| mock | 순서·불완전chunk·공유인수·shape오류·configure/복원 확인 | 모델 없이 tensor 대역의 기대값 비교 | mock 성공이 실제 모델 확률 일치를 보장하지 않는 이유는? |
| 합성 | 같은 fitted estimator 원경로1+분할1 | 2×4 확률·행합·최대차≤1e-5·argmax일치 | exact equality와 tolerance 통과는 어떻게 다른가? |
| 후속 실제재현 | 고정 FIT3144·두질의·원확률 비교 | 별도 회차의 입력해시/원확률1e-4 관문 | 합성32행이 실제3144행과 메모리·수치에서 다른 이유는? |
| 후속 성능 | 동결된 선박단위 개발평가 | 별도 학습/평가·paired비교·관측량 subgroup | 두 질의 재현이 micro-F1 개선의 증거가 아닌 이유는? |

예상은 독립축 분할이 이 합성 입력에서 허용오차 안의 확률을 유지한다는 것이다. 실제 계산값·통과/실패는 ROUND_REPORT와 artifacts에 기록한다. 실패 시 원자료·계약·전처리·모델/어댑터·실행자원·결과기록 계층을 나눠 좁힌다. 이번 소스검토에서 발견된 configure 전달 누락은 어댑터 인터페이스 문제이며 모델 성능 문제로 해석하지 않는다.

가용 RAM은 시스템 전체 값이고 소유 프로세스 working set은 해당 계산의 관측값이다. sampled peak는 샘플 사이 순간 peak를 놓칠 수 있다. 시작 여유량이 같다는 사실만으로 이전에 중단된 큰 입력이 안전해지지는 않는다. 작은 합성 입력의 통과·peak 역시 큰 입력 메모리 절감 보장이 아니다.

학습자가 직접 답할 과제: output_repeat가 어디서 쓰이는지 소스에서 찾고, FIT target을 컬럼축으로 확장하는 이유를 그림이나 작은 shape 예제로 설명한다. 월별 T5 평균과 월별 변화량 특징이 담는 정보 차이를 설명하고, 동일선박의 월을 서로 다른 split에 놓을 때 평가 질문이 어떻게 달라지는지 적는다. 이 답변은 이번 회차에서 자동 완성하거나 평가하지 않았다.
