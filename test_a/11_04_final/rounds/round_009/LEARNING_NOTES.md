# Round009 학습 기록

기술 검증과 학습자 이해를 구분한다. 이번 단계는 사전학습 모델의 계산 경로를 제한된 메모리에서 보존하는 실험이며 새 분류 성능을 평가하는 단계가 아니다. 학습자 수준·시간·연산 자원에 관한 개인 선호는 미확인이며 실제 장치를 다루지 않는다.

## 시스템 흐름과 관찰

고정 난수 합성표 → TabICL fit의 문맥 준비 → column embedding → ROW feature/register token attention → 전체 FIT/query 문맥 ICL → 두 질의의 4클래스 확률이다. fit 호출은 사전학습 체크포인트를 이용한 문맥 준비이며 이번에 계수를 새로 학습했다는 의미가 아니다.

컬럼 어댑터는 기존 검증본 chunk16을 유지한다. 이번 변경은 ROW의 독립 행 배치축 chunk8뿐이다. 같은 이름의 T축도 계산 계층에 따라 역할이 다르다. ROW에서는 각 행의 모든 feature/register token을 함께 attention하고, ICL에서는 전체 FIT가 질의의 문맥이 된다. 후자의 T를 임의로 잘라 붙이면 다른 모델 계산이 된다.

관찰할 값은 입력/출력 shape, 청크 수와 마지막 폭, 두 확률의 최대절대차, argmax, 입력·shuffle 불변, 원관리자 복원, 실행 시간과 sampled RAM이다. 계산값은 artifacts와 ROUND_REPORT에 기록한다. source/mock만 통과했다면 실제 모델 통과로 부르지 않는다.

## 설명·검산 활동

1. 합성 T=34에서 chunk8의 구간과 마지막 폭을 먼저 계산하고 실행 로그와 대조한다.
2. ROW의 feature/register token 전체를 보존하는 이유와 ICL 문맥을 자르면 생기는 의미 변화를 설명한다.
3. 확률 exact equality와 1e-5 tolerance 통과, argmax 일치가 각각 말해 주는 것을 구분한다.
4. 작은 합성 통과가 실제 FIT3144 문맥의 peak RAM·확률 재현·F1을 보장하지 않는 이유를 설명한다.
5. finally 복원 확인과 외부 RAM 감시자의 프로세스 종료 확인이 다른 증거임을 설명한다.

실패가 나면 원자료 문제가 아닌 합성 생성/계약·설정/어댑터 shape·계산/자원·프로세스/표시·기록 계층으로 좁힌다. 로그가 실패했다는 사실과 모델이 틀렸다는 사실을 혼동하지 않는다. 학습자의 답변·이해 달성 및 하드웨어 동작은 이번 회차에서 측정하지 않았다.
