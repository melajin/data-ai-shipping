# 이번 관문의 의미

기술적 성공은 고정 FIT3144 문맥과 두 INNER 질의의 확률 재현이다. 학습적 성공은 결과만 보는 것이 아니라 어떤 축이 독립이고 무엇을 고정했는지 설명할 수 있는 것이다. 학습자의 설명은 아직 평가하지 않았다.

합성32행에서 같았던 계산도 실제3144행에서는 메모리와 연산 시간 조건이 달라진다. ROW 입력의 T는 독립 행배치이므로 청크를 나누되 각 행의 feature/register sequence는 유지한다. 반면 ICL은 FIT 문맥을 참조하므로 전체 T를 임의로 나누면 계산의 의미가 달라진다.

확률의 exact equality와 최대절대차 허용오차는 별도 판정이다. 이번 실제 재현은 과거 CUDA 출력과 현재 CPU 출력을 비교하므로 미리 정한1e-4를 사용한다. 합성 비교의1e-5를 바꾸어 적용하거나 결과를 본 뒤 오차를 완화하지 않는다.

확인할 질문:

- 왜 ROW 행 청크8은 가능하지만 ICL 문맥을 같은 방식으로 잘라서는 안 되는가?
- 고정 두 질의가 일치해도5897척의 F1 향상을 뜻하지 않는 이유는 무엇인가?
- sampled peak와 실제 최대 메모리 요구량은 어떻게 다른가?
- 실행 전 RAM 부족과 실행 중 RAM 중단은 다음 실험 설계에 어떻게 다른 근거를 주는가?
- 월별 무관측을 비조업으로 바꾸면 어떤 오류가 생기는가?

## 독립 문서 검토

round007 SEASONAL_FEATURE_INVENTORY와 round008 SEASONAL_FOLLOWUP_DESIGN을 읽었다. 현재312열은 F156값+결측표시이며 F304와 다르다. 기존 월평균 참조/관측량은 월별 형태·지역 변화 자체와 다르다. 이번 재현에는 시간 특징을 추가하지 않는다. 후속 계절 가설은 월관측량 효과와 월별 변화효과를 분리한 유한 비교로 좁히고 timezone/분모/결측mask부터 확인해야 한다. 새 배열·원자료를 읽거나 계절 성능을 측정하지 않았다.

이 문서는 코드·자료 흐름 학습 지원이며 실제 장치 연결·하드웨어 검증은 없다. 조건·계산값·해석은 최종 ROUND_REPORT와 실행영수증으로 연결한다.
