# 학습·검증 기록

이번 기술목표는 고정된 실제 두 질의에 대해 컬럼 분할 경로가 저장 원확률을 허용오차 내 재현하는지 확인하는 것이다. 코드 검산, pure mock, 실제 선박 입력 재현과 F1 평가는 서로 다르다. 장치 실험은 없다.

관찰할 현상: 설정 적용 뒤 컬럼 분할 호출별 shape·chunk 순서, 최대 메모리와 마지막 완료 단계, 확률과 argmax, 종료 후 소유 프로세스, 원컬럼관리자 복원. 정상 Python finally와 외부 강제종료를 구분한다. 강제종료 시 finally가 실행됐다고 주장하지 않으며, 프로세스 종료와 전역/환경 미변경을 별도로 확인한다.

설명할 질문:
1. 문맥 T축을 나누는 것과 독립 컬럼 배치축을 나누는 것은 왜 다른가?
2. fit직후 원관리자.configure를 예측 없이 호출할 수 있는 근거는 무엇인가?
3. 두질의 확률 일치가 5,897척 F1이나 독립 일반화 성능을 말해주지 못하는 이유는?
4. RAM이 임계값 아래로 내려가 감시자가 종료한 것과 OS OOM, 수치불일치는 어떤 기록으로 구분하는가?
5. 합성 입력의 peak와 전체문맥의 peak가 다를 수 있는 중간배열은 무엇인가?

학습자의 답변·구현역량·이해달성은 아직 측정하지 않았다. 실험 결과와 자원 수치는 ROUND_REPORT에 실제 관측값만 기입한다.
