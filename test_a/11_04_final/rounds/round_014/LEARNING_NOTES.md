# M4 head 검증을 설명하기 위한 노트

이 문서는 합성 코드 검증의 해석을 돕는다. 실제 선박 성능이나 학습자의 이해를 측정한 결과는 아니다. 실행 성공 여부는 ROUND_REPORT와 원본 영수증을 따른다.

1. **클래스 변환과 복원.** 원래 클래스가 y이고 view의 치환이 p라면 그 view는 p[y]를 정답으로 배운다. 원래 클래스 k에 대한 logit은 view의 p[k] 위치에 있으므로 복원은 out[..., p]다. shift가 우연히 자기 역함수인 경우만 보면 잘못된 argsort 구현도 통과할 수 있으므로 비자기역 치환을 포함한 검사가 필요하다.
2. **B=0의 첫 A gradient.** W_eff=W0+B A일 때 dL/dA에는 B가 곱해진다. 따라서 초기 B=0이면 A gradient0은 정상이다. B는 초기 A를 통해 gradient를 받을 수 있다. 첫 B 갱신 뒤 두 번째 step에서 A gradient가 생기는지를 확인한다. 이것은 gradient 경로의 증거이며 실제 분류 정확도 상승의 증거가 아니다.
3. **context와 target의 경계.** 모델은 context의 정답을 표현에 주입한다. decoder hook의 전체20행에서 context16행까지 loss에 쓰면 답을 이미 본 행으로 학습하게 된다. target4행만 분리한 캐시와 별도 target label이 필요하다. 분류 라벨을 hook 또는 predict 인수로 흘려보내면 안 된다.
4. **고정 표현의 한계.** 같은 H에 대한 head 저장·재로드가 맞아도 전체 모델에서 다시 표현을 계산하는 경로, 전처리 상태, ensemble 순서까지 검증된 것은 아니다. full integration은 별도 입력·호출예산을 동결해 확인한다. 실제 선박 F1은 별도 평가 설계와 자료가 필요하다.
5. **오차와 출처.** 부동소수점의 exact equality와 허용오차 통과는 다르다. 실행 종료0, 저장된 수치의 일치, 실행 소스의 불변성도 서로 다른 조건이다. 한 조건이 참이어도 다른 실패를 지울 수 없다. round010의 역사 source-freeze 실패는 후속 검증으로 소급 취소하지 않는다.

자기 설명 과제: 4클래스의 p=[1,2,3,0]을 직접 써서 y=2의 학습 정답과 원래 클래스2의 출력 위치를 구하라. B=0에서 첫 A gradient0과 학습 전체 실패를 어떻게 구별하는가? 합성 CE가 내려가도 실제 F1 개선이라고 말할 수 없는 이유를 설명하라. 답변 평가는 아직 수행하지 않았다.
