# 실행 소스 동결 절차

1. 작성 담당자 한 명이 candidate 파일 목록·SHA256을 전달하면 쓰기를 중지한다. 검토자는 소스와 입출력·실행 예산을 독립 확인한 뒤 승인 map을 생성한다. 관리자는 작성자의 쓰기 중지와 승인을 모두 확인한다.
2. 관리자는 승인 map과 live hash를 대조하고 실행 디렉터리에 사본을 만든다. 실행사본도 승인 hash와 일치해야 한다. mock과 본 실행은 같은 승인 map을 사용한다. 사본에서 실행해도 live 원본의 불변 의무가 사라지지 않는다.
3. 승인 후 결함 발견 시 실행 전에는 승인 취소를 기록하고 새 버전 작성·검토·승인·mock을 거친다. 실행 시작 후에는 코드 수정·사후 승인map 갱신·원본 복원으로 clean을 만들지 않는다. 긴급 수정은 다음 버전/회차로 이관한다.
4. 종료 시 approved / 실행사본 / 현재 live 세 hash와 원래 receipt 판정을 각각 보존한다. 불일치이면 변경본과 diff·시각·분기 진입 증거를 새 회차 경로에 저장하고 전체 출처 관문을 실패로 남긴다. 수치 검증과 출처 실패를 분리한다.
5. 검토자는 결과를 읽기 전용으로 검산한다. 작성자는 승인 후 최종 결과 검토에도 원본 코드를 수정하지 않는다. 공유 STATUS/LEDGER/NEXT_SESSION은 관리자만 갱신한다.

round010은 과거 source-freeze 실패를 영구 보존한다. round011 검산 성공은 그 실패를 정확히 재구성했다는 뜻이며 round010 전체 성공으로 소급되지 않는다. 입력 NPZ/checkpoint를 이번 범위에서 읽지 않는 항목은 `not_reverified`로 표시한다.
