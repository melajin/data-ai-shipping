# Round029 독립 최종 검토

검토 대상: `ROUND_PLAN.md`, `run_fit_gate.py`, `fit_results.json`, `fit_predictions_frozen.npz`, `saved_prediction_verification.json` 및 관련된 Round025 설정·FIT/T5 증거 캐시. 해당 산출물과 코드만 읽어 확인했으며, 원시자료 재읽기나 모델 재학습은 하지 않았다.

## 판정

자료형 오류를 고친 뒤 기준선이 Round025의 저장 예측과 일치했고, 계획한 8개 fit이 모두 완료됐다. 따라서 Round028의 재현 실패 원인을 dtype 처리로 한정하고 같은 절차에서 다시 판정한 것은 타당하다. 다만 후보가 사전 고정된 관문을 통과하지 못했으므로 이 특징 후보는 채택할 수 없다.

## 재현과 자료형

- Round029 실행 코드는 FIT 행렬을 `fold_0_features.npz`에서 가져와 `float64` 3144×304인지 확인한다. Round025 각 fold의 `t5_matrix`를 156:166열에 그대로 대입하고 두 신규 특징을 `float64`로 만들어 붙인다. 확인한 원본 FIT 행렬 및 네 T5 행렬도 모두 `float64`다. 후보 입력은 따라서 3144×306 `float64`로 구성된다.
- 신규 특징 CSV는 `rfid_id`를 키로 조인하며 중복 ID와 FIT ID 누락을 오류 처리한다. 이 방식은 로스터 순서를 CSV의 행 순서에 의존하지 않는다.
- 각 fold의 후보 fit 전에 같은 fold 기준선의 `predict_proba` 결과를 `float32`로 바꾼 뒤 `argmax`하고 Round025 저장 예측과 완전 일치하는지 검사한다. 최종 저장 예측도 전체 3144개 기준선 행에서 Round025와 일치한다. `saved_prediction_verification.json`의 `original_baseline_exact`와 `reported_metrics_match`가 모두 참이며, 저장 배열을 읽어 확인한 값도 일치한다.
- 이 증거는 Round028에서 `float32`로 변환한 입력을 Round025와 동일한 dtype 경로로 되돌리는 교정이 실제 기준선 재현을 복구했다는 근거다. 이는 데이터·알고리즘의 일반적 동등성을 증명하는 주장이 아니라, 이 고정 실행 조건에서의 정확 일치 확인이다.

## 실행 수와 관문 결과

Round025 설정의 seed 42, 단일 스레드, 300 trees 및 저장된 fold 분할을 사용했다. `fit_progress.json`에는 fold별 기준선·후보가 모두 `completed`로 기록되어 총 8 fit이다. 실행 상태에는 OUTER 평가 0회, Test/holdout 평가 0회로 기록되어 있다.

| 지표 | 기준선 | 후보 | 변화 |
|---|---:|---:|---:|
| 정답 수 | 1811/3144 | 1822/3144 | +11 |
| micro | 0.576018 | 0.579517 | +0.003499 |
| macro | 0.491289 | 0.495259 | +0.003970 |
| TP, 클래스 0–3 | [1248, 473, 54, 36] | [1246, 483, 56, 37] | [−2, +10, +2, +1] |

저장 예측의 paired 비교는 새 정답 113건, 정답 손실 102건, 순증 11건으로 산술적으로 맞는다. 클래스 1·2는 TP와 F1이 모두 상승했지만 클래스 0 TP가 2 감소했다.

`ROUND_PLAN.md`와 코드의 고정 관문은 후보 정답 ≥1833, matched 기준선 대비 순증 ≥16, 자망 또는 통발의 TP·F1 동시 개선, 클래스 0 및 3 TP 비감소를 모두 요구한다. 실제 결과는 후보 정답 1822, 순증 11, 클래스 0 TP 감소로 실패하며, 나머지 두 조건만 통과한다. `fit_results.json`의 개별 판정과 `pass=false`는 이 조건과 일치한다. 실패 후 확장·채택하지 않은 상태도 `EXECUTION_STATUS.json`에 일관되게 기록됐다.

## 자원 및 검토 한계

기록상 진입 가용 RAM 3.03 GiB, 실행 중 최저 2.34 GiB, 자체 RSS 최고 약 0.17 GiB로 설정한 가용 RAM·RSS 문턱을 넘었다. 다만 `fit_resource_checks.json`에는 `cv2_candidate_fit`부터 종료까지 다른 Python PID 19072가 기록돼 있다. 그 프로세스의 명령줄·RSS·작업은 남지 않아 동시 계산이 무엇이었는지, 단일 계산 프로세스 조건이 지켜졌는지는 이 증거만으로 확인할 수 없다. 이 기록은 수치 재계산을 무효화하지 않지만 실행 거버넌스의 감사 가능성을 낮춘다.

이번 수치는 개발 FIT 3144의 내부 4-fold 결과다. OUTER, Test, holdout 또는 독립 일반화 성능을 나타내지 않는다. 요청된 모델 설정은 GPT-6 Luna max이며, 앞선 요청의 ultra는 호스트가 지원하지 않아 max로 수행하는 설정이다. 실제 백엔드 모델 식별은 독립적으로 인증할 수 없다.
