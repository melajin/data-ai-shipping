# Round 004 학습 기록

기술 목표: 재현에 필요한 고정 환경·체크포인트·개발 입력의 출처를 분리하여 검증한다. 학습 목표: 설치, 합성 실행, 원모델 재현, 실제자료 성능 평가가 서로 다른 증거라는 점을 설명한다. 이번 회차는 선박 장치나 센서를 연결하지 않는다.

흐름은 저장 특징(156개) → FIT 중앙값 결측 대치 → 원결측 표시156개 추가 → 모델 입력312개 → FIT 문맥과 질의 → 네 업종 확률 → 최종 라벨이다. 좌표별 시각 없이 속력·가속도를 생성하지 않으며 부분선을 연결하지 않는다.

직접 설명해 볼 질문:

1. `pip check`가 통과해도 왜 checkpoint 로드와 예측 성공을 단정할 수 없는가?
2. 304열 NPZ의 첫156개 이름이 같다는 사실만으로 원모델 입력과 같다고 할 수 있는가? 생성 코드·fold vocabulary·행순서·정밀도 중 어떤 증거가 더 필요한가?
3. 결측 대치된 값이 같아도 결측 표시가 다르면 모델 입력은 어떻게 달라지는가?
4. 모든 FIT 중앙값이 일치해도 개별행의 정확 일치가 보장되지 않는 이유는 무엇인가?
5. 합성20행 실행의 시간에서 전체5897척 실행 시간을 단순 비례로 추정하면 어떤 문맥 길이·메모리 비용을 놓치는가?
6. 재현에 쓰는 INNER 소수 질의를 정답이나 오류 여부를 보고 고르면 어떤 선택 편향이 생기는가?

검증 기록을 읽을 때 설치 로그/의존성 검사, 합성 smoke, 실제 개발 F1, 독립/공식 점수의 칸을 따로 본다. 미실행 검사는 실패한 분류 성능도 성공한 분류 성능도 아니다. 자원 관문 실패는 데이터나 모델 품질의 실패가 아니라 실행 환경 계층의 제한이다.

설명 능력·고장 진단·조건 변경 대응은 아직 평가하지 않았다. 문서 산출 완료를 학습자의 이해 달성으로 기록하지 않는다.
