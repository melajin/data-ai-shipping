# 제출 코드 최적화 점검

검토 범위는63회차의 고정 가중치로 과제1을 실행하는 경로입니다. 모델 설계와 추가 학습은 진행하지 않았습니다.

| 항목 | 반영 내용 |
|---|---|
| 공통 함수 | 행 형상,98열 요약,52열 배치,187열 상태 함수를 분리해 재사용 |
| CSV 처리 | 월별 파일을 청크로 읽고 공식 대상 ID를 먼저 필터링 |
| 중복 계산 | 한 번 읽은 대상 행에서 요약·상태·배치 자료를 함께 생성 |
| 미사용 분기 | relation 비중0에 맞춰 제출 추론20과제를14과제로 정리 |
| 모델 로딩 | 본체를 한 번 읽어 과제별 문맥 전처리와 공유 |
| 순서 결정성 | 모든 과제에서 요청된 none·power 순서를 보존하도록 vendor 한 곳 수정 |
| 실행 의존성 | 제출 추론에서 연구 상태 파일·공지 해시·옛 쿼리 캐시·복구 스크립트 제거 |
| 저장 계약 | 선택 가중치의 config와 state dictionary만 저장,추론 객체 pickle 제거 |
| 클래스·확률 | 최종 점수와 확률 계산을 단일 결합 함수로 통일 |
| 과제2 결합 | ID·시각·점수 검증과 정렬을 공통 함수로 처리,과제1 불변 확인 |

회귀 확인은 두 가지로 수행했습니다. 원자료에서 재계산한 네 선박의337개 특징이 기존 값과 일치했습니다. 정리한14과제 추론으로 기존2,949척을 예측했을 때 최종 클래스 변경은0개였고 REPORT Micro-F1도0.6122033898로 같았습니다.

학습 재현용 기존58개 모듈은 `src/research`에 분리해 보관했습니다. 제출 추론은 이 경로를 import하지 않습니다. 두 단계 역전파와 원래20과제 학습 손실은 학습 절차 보존을 위해 유지했습니다.

데이터 전체를 읽는 비용과 GPU 문맥 추론이 주된 실행 비용입니다. 학습 데이터 확대·새 네트워크·새 특징 탐색은 이번 최적화에 포함하지 않았습니다.
