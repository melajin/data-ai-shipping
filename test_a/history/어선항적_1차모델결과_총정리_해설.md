# 어선 항적 1차 모델 결과 총정리 해설

작성일: 2026-10-29

대상 문서: `어선항적_전체진행과_실제모델성능_통합정리_20261029.md`

이 문서는 새 실험 결과가 아니라 **지금까지의 대화 기록, 1차 모델 보고서, 공식데이터 설명서를 한 곳에 합친 총정리**다. 아래에서는 이 문서에서 새로 정리되거나 바로잡힌 부분 위주로 해설한다.

---

## 1. 프로젝트가 어떻게 흘러왔나

크게 **연습 단계(합성 데이터)**와 **실전 단계(실제 데이터)**로 나뉜다.

| 시기 | 한 일 | 비유 |
|---|---|---|
| 10/9~10/19 | 검사기 준비, 샘플 10행 확인 | 시험장 답사 |
| 10/12~10/27 | 가짜 항적(직진·굴곡·회전)을 만들어 모델 연습 | 모의고사 |
| 10/28~29 | 실제 데이터로 4개 조업형태 분류 학습·평가 | 실제 시험 |
| 10/29 | 사고 후보 조사, 성능 진단 통합 | 시험 후 오답 분석 |

### 이 문서가 가장 먼저 바로잡는 오해

"합성 데이터로 만든 모델을 실제 데이터에 그대로 썼더니 실패했다"가 **아니다.**

- 합성 단계의 정답: **직진 / 굴곡 / 회전** (경로 모양 3종)
- 실제 단계의 정답: **연안복합 / 자망 / 통발 / 채낚기연승낚시** (조업형태 4종)

정답 종류 자체가 달라서 옮길 수가 없다. 합성 단계에서 가져온 것은 **shape9라는 특징 계산법**뿐이고, 모델은 실제 정답으로 처음부터 새로 학습했다.

합성 단계 성적(정확도 79~81%, Macro F1 0.66~0.71)이 실제(Macro F1 0.30)보다 훨씬 좋아 보이지만, **문제 난이도가 전혀 달라서 비교하면 안 된다.** 합성 데이터는 "직진 vs 회전"처럼 모양으로 구분되도록 일부러 만든 것이다.

## 2. Macro F1은 크게 올랐는데 정답은 왜 3척만 늘었나

### R0(기준 모델)는 거의 전부 "연안복합"으로 찍었다

1,453척 중 1,451척을 연안복합, 2척을 자망으로 예측했다.

| 클래스 | R0 정답 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 연안복합 | 721/722 | 721/1,451 = 0.497 | 0.999 | **0.664** |
| 자망 | 1/498 | 1/2 = 0.5 | 0.002 | **0.004** |
| 통발 | 0 | - | 0 | **0** |
| 채낚기 | 0 | - | 0 | **0** |

**Macro F1** = 4개 F1의 단순 평균 = (0.664 + 0.004 + 0 + 0) ÷ 4 ≈ **0.167**

정확도는 722/1,453 ≈ 49.7%로 멀쩡해 보이지만 Macro F1은 바닥이다. 클래스 4개 중 3개를 사실상 포기했기 때문이다.

### ExtraTrees는 다른 클래스에도 답을 나눠 줬다

| 클래스 | ET F1 | R0 대비 정답 변화 |
|---|---|---|
| 연안복합 | 0.642 | **−122척** |
| 자망 | 0.306 | **+120척** |
| 채낚기 | 0.250 | +5척 |
| 통발 | 0 | 0척 |

Macro F1 = (0.642 + 0.306 + 0.250 + 0) ÷ 4 ≈ **0.300**

자망·채낚기의 F1이 0에서 올라가면서 평균이 크게 뛰었다. 하지만 그 대가로 **연안복합 122척을 자망으로 잘못 보냈다.** +120 + 5 − 122 = **+3척**. 그래서 전체 정답 수는 거의 그대로다.

> 비유: 모든 학생을 "문과"라고만 찍던 선생이 "이과도 좀 있겠지" 하고 120명을 이과로 맞혔는데, 동시에 원래 문과인 122명을 이과로 잘못 분류한 것. 균형은 좋아졌지만 실력이 늘었다고 보기는 어렵다.

## 3. 성능이 낮은 이유: 세 칸으로 나눠 봐야 한다

핵심 태도는 **"확인된 것", "의심되는 것", "원인이 아닌 것"을 섞지 않는 것**이다.

### ① 확인된 사실 (데이터에서 직접 보임)

- **정확도가 찍기 수준.** 연안복합만 찍어도 49.69%, 모델은 49.90%.
- **통발 0/204.** 한 척도 못 맞혔고, 통발이라고 찍은 6척도 전부 오답.
- **채낚기 5/29.** 학습 데이터 전체에 158척뿐인 희소 클래스.
- **클래스 가중치 없이 학습.** 모든 모델이 "다 같은 무게"로 학습했다. Macro F1을 직접 높이도록 훈련한 것이 아니다.

추가 디테일: **개발 단계 validation에서는 ExtraTrees가 통발을 조금 맞혔다** (분할별 2/125, 2/125, 3/124). 따라서 "통발은 항상 0"이 아니라 **"통발 구분 능력이 극히 낮다"**가 정확한 표현이다.

### ② 검증해야 할 가설 (그럴듯하지만 증명 안 됨)

| 가설 | 왜 의심되나 | 왜 아직 확정 못하나 |
|---|---|---|
| 클래스 불균형 | 연안복합 2,016척 vs 채낚기 86척 (약 23배) | 가중치만 바꿔서 다시 돌려본 실험이 없음 |
| 형상 특징의 한계 | 속도·시간·위치 없이 모양만 봄 | 클래스별로 특징이 얼마나 겹치는지 측정 안 함 |
| 표본이 너무 적음 | 389만 행 중 12.9만 행(3.3%)만 사용 | 월 8행, 16행으로 늘려본 실험 없음 |
| 라벨과 행동 불일치 | 라벨은 "배의 업종", 항적은 "그 시간의 행동" | 이동·정박이 얼마나 섞였는지 확인 안 함 |
| 희소 클래스 표본 부족 | 채낚기 평가 대상 29척 | 더 큰 독립 데이터가 없음 |

> 라벨-행동 불일치 비유: "이 학생 전공은 미술"이라는 정답이 있는데, 모델에게 보여준 일기 4페이지가 하필 "버스 타고 학교 감", "집에서 잠"이면 미술 전공인지 알 수 없다. 통발 어선도 6개월 중 상당 시간은 그냥 이동하거나 항구에 있다.

### ③ 원인이라고 하면 틀린 것

| 흔한 오해 | 왜 아닌가 |
|---|---|
| 합성 모델을 그대로 써서 | 실제 라벨로 새로 학습했음 |
| 월 버그·오염 행 때문 | 학습 전에 고쳤음 |
| 계산 실수 | 독립 검산 결과 일치 |
| 온도 보정 문제 | 보정 전후 예측이 바뀐 배 0척 |
| 400 epoch가 부족해서 | 과적합·발산 징후 없음. 400 이후는 안 해봐서 단정 불가 |
| Test 6월 파싱 오류 | 공식 Test는 이번 평가에 안 썼음. 내부 평가와 무관 |
| 2025/2026 연도 차이 | 내부 평가는 2026년 안에서만 했음. 연도 차이는 나중에 공식 Test에 갈 때의 별도 위험 |

마지막 줄이 중요하다. 연도 차이는 "지금 성능이 낮은 이유"가 아니라 "앞으로 성능이 더 떨어질 수도 있는 위험"이다. 시점이 다르다.

## 4. 두 자료가 서로 다른 숫자를 보고하는 부분

통합 문서는 "파일 크기가 다르니 같은 파일이라고 단정하지 않는다"고만 적고 넘어갔지만, 두 문서의 숫자를 직접 맞춰보면 차이의 위치를 좁힐 수 있다.

| 항목 | 1차 모델 보고서 | 공식데이터 설명서 |
|---|---|---|
| Train 6개 파일 크기 | 5,863,777,667 bytes | 월별 합산 5,863,777,667 bytes |
| Test 6개 파일 크기 | 5,970,852,731 bytes | 월별 합산 7,485,480,481 bytes |
| Test 파싱 행 수 | 3,365,197 (6월 61,586행에서 중단) | 4,212,389 (전부 정상) |

**Train은 크기가 바이트 단위까지 같다.** 차이는 전부 Test에 있다.

설명서의 Test 1~5월 행 수 합계는 592,013 + 442,715 + 624,514 + 755,491 + 888,878 = **3,303,611**. 여기에 1차 보고서의 6월 61,586행을 더하면 **3,365,197**로 1차 보고서 숫자와 정확히 같다.

즉 **1~5월 Test는 두 자료가 같고, 6월 Test 파일만 다른 버전**일 가능성이 높다. 같은 가정으로 크기를 역산하면 모델 실험에 쓴 6월 Test 파일은 약 107MB, 설명서가 검사한 6월 Test 파일은 약 1.62GB다. 모델 실험 쪽 6월 파일이 중간에 잘리거나 깨진 사본이었을 수 있다.

> 주의: 이는 행 수와 크기 산술에서 나온 **추정**이다. 확정하려면 두 6월 Test 파일의 SHA-256을 직접 비교해야 한다. 설명서 25절에 6월 Test 해시(`009ac034a7acb8552fac6fe1d28b307d6df2339ea5a1845ec4314c306f97b88d`)가 있으므로, 모델 실험에 쓴 `F:/문제 데이터_수정_1027`의 6월 Test 파일 해시만 구하면 바로 확인된다.

## 5. 문서 끝 학습 질문 4개에 대한 답

### Q1. Macro F1은 올랐는데 정답은 왜 3척만 늘었나?

2절 그대로다. R0가 3개 클래스를 포기해서 Macro F1이 바닥이었고, ExtraTrees가 자망·채낚기에 답을 나눠주며 평균이 올랐지만, 연안복합에서 122척을 잃어 정답 수는 +3에 그쳤다.

### Q2. "WKT 판독 가능", "shape9 계산 가능", "예측 가능", "정상 운항"은 어떻게 다른가?

| 단계 | 의미 | 예시 실패 |
|---|---|---|
| WKT 판독 가능 | 괄호·숫자 형식이 맞음 | 빈 칸, 잘린 문자열 |
| shape9 계산 가능 | 길이가 0이 아니고 좌표가 상식 범위 | 같은 점만 반복 (판독은 되지만 계산 불가) |
| 선박 예측 가능 | 그 배의 표본 중 하나라도 계산 가능 | 24행이 전부 길이 0 (→ 20척 유보) |
| 정상 운항 | 실제로 사고 없이 움직임 | 이 데이터로는 판단 불가 |

13,842행이 "길이 0"이라고 해서 CSV가 깨진 것이 아니다. 형식은 멀쩡한데 배가 움직이지 않아 모양 계산이 안 되는 것뿐이다.

### Q3. 내부 저성능 원인과 연도 간 위험을 구분할 수 있나?

지금 성능은 2026년 데이터 안에서 학습·평가해서 나온 것이라 연도 차이와 무관하다. 연도 차이는 나중에 2025년 Test에 적용할 때 추가로 생길 수 있는 위험이다.

### Q4. 한 요소만 바꾼 실험은 어떻게 설계하나?

예: "클래스 불균형이 원인인가?"를 확인하는 실험

- **고정:** 같은 분할(seed 3201~3203), 같은 특징(distribution36), 같은 ExtraTrees 설정
- **변경:** `class_weight=None` → `class_weight="balanced"` **이것 하나만**
- **기록:** Macro F1, 정확도, 클래스별 재현율(특히 통발), 유보 수, coverage
- **금지:** 최종 홀드아웃 1,473척을 보면서 튜닝하는 것 (이미 한 번 열어봤으므로)

이렇게 해야 "가중치를 줬더니 통발 재현율이 0%에서 X%로 올랐다"는 인과 주장이 가능하다. 여러 요소를 한꺼번에 바꾸면 무엇이 효과였는지 알 수 없다.

## 6. 한 줄 요약과 다음 단계

**"계산은 맞았고 상대 비교 기준도 통과했지만, 실제로는 찍기 수준이고 통발은 전혀 못 맞힌다. 원인 후보는 여러 개지만 아직 하나도 실험으로 증명하지 않았다."**

다음 단계: 최종 홀드아웃은 다시 건드리지 않고, 개발 분할 안에서 클래스 가중치부터 한 요소씩 바꿔보는 통제 실험을 진행한다. 이와 별도로 6월 Test 파일의 SHA-256을 대조해 두 자료의 버전 차이를 확정한다.
