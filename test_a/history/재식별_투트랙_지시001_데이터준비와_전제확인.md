# 지시 001 — 재식별 투트랙: 데이터 준비(S0~S7)와 1단계 전제 확인(V0)

설계 문서: `재식별_투트랙_시스템_설계.md` (먼저 읽을 것. 이 지시는 그 문서의 4장과 5.1절만 실행한다)

## 0. 목적과 범위

투트랙 시스템의 핵심 전제인 **"해가 바뀌어도 어선은 같은 동선을 다니고, 닮은 이웃의 업종이 그 배의 업종을 알려 준다"**가 맞는지 라벨 없이 확인한다.

| 범위 안 | 범위 밖 (하지 말 것) |
|---|---|
| S0~S7 데이터 준비, 선박 지문 생성, 선박 카드 | 업종 분류 모델 학습·재학습 |
| V0 검사 (아래 3절의 a~f) | V1 이후 단계(기간 분할 성능 평가, 소프트 결합, 최종 비교) |
| 결과 보고서 작성 | 지문 가중치·임계값을 V0 결과로 조정해 다시 돌리기 |

범위 밖 작업이 필요해 보이면 하지 말고 보고서 7항(질문)에 적는다. **V0 결과로 계속 진행할지는 검토자가 판단한다.** 실행자는 수치만 보고하고 판정 문구를 쓰지 않는다.

## 2. 데이터 준비 (S0~S7)

### S0 원본 확인
12개 CSV의 SHA-256을 기존 목록과 대조한다. 하나라도 다르면 **정지**한다.

### S1 시간 행 해석
기존 기하 캐시를 재사용한다. 새로 파싱하지 않는다. 학습 3,887,068행·7,372척, 테스트 4,212,389행·7,768척인지 확인한다.

### S2 위치 점 표
원본 WKT에서 점을 풀어 `id, year, date, hour, part, seq, lon, lat`로 저장한다(연도·월별 parquet).
- 선 조각(part) 사이를 잇지 않는다. 점에 시각을 만들지 않는다.
- 해석할 수 없는 도형은 버리지 말고 사유와 함께 별도 목록에 기록한다.

### S3 시간 행 요약
시간 행마다 다음을 만든다: 대표점(유효 점들의 중심), 정지형 표시(내부 길이 0·범위 양수), 직전 관측과의 간격(시간), 점 수, 조각 수.
- 기존 캐시에 같은 값이 있으면 일치를 확인하고, 다르면 정지하지 말고 차이를 보고한다.

### S4 격자화
대표점을 0.01°와 0.05° 격자 번호로 변환한다. **첫 버전은 시간 행마다 대표점 1개**로 한다(점 단위 길이 가중은 하지 않는다).

### S5 기간 블록 정의
V0는 연도 전체(각 1-6월)를 쓴다. V1을 위해 블록 정의만 미리 만들어 둔다(지문 계산은 연도 전체만 필수).
- `full`: 각 연도 1-6월 전체
- `half`: 1-3월 / 4-6월
- `biweekly`: 연초부터 14일 단위 교차(홀/짝), 블록 경계마다 앞뒤 3일을 완충으로 제외
- 블록 정의는 `s5_blocks.json`에 날짜 목록으로 저장한다.

### S6 선박 지문
배 × 연도(`full`)마다 계산한다.

| 요소 | 정의 |
|---|---|
| 공간 분포 (2종) | 0.01°/0.05° 격자별 체류 비중. **날짜마다 같은 비중**(하루 안에서 시간 행 균등, 날짜끼리 균등). 합 1 |
| 모항 | 정지형 시간 행이 가장 많은 0.01° 격자의 중심. 정지형이 없으면 결측 |
| 활동 반경 | 모항으로부터 대표점 거리(km)의 10/50/90 백분위. 모항 결측이면 결측 |
| 활동 시간대 | 0~23시 24칸 비중, 날짜 균등 |
| 지원량 | 시간 행 수, 관측 날짜 수, 첫·마지막 날짜 |

- **넣지 않는 것:** 관측 간격 분포, 품질 bit (수신 환경에 좌우되므로 닮음 판단에서 제외, 지원량 기록만).
- **이번에는 행동 사전 34칸을 넣지 않는다.** 기존 사전은 일부 개발 선박으로 만든 것이라 V0에서는 순수 위치·시간 지문만 본다.
- 업종 라벨과 ID 일치 정보는 지문에 넣지 않는다.
- 저장: `s6_fingerprint_grid.parquet` (`id, year, block, res, cell, weight`), `s6_fingerprint_summary.parquet` (`id, year, block` 행).

### S7 점검
- S1 시간 행 수 = S3 행 수 (연도별)
- 격자 비중 합 = 1 (허용 오차 1e-9), 음수 없음
- 블록 경계를 넘는 행 0개 (`half`, `biweekly` 정의 기준)
- 모항·반경 결측 선박 수와 사유
- 지문에 라벨·ID 일치 정보 열이 없음 (assert)
- 결과: `audit_s7.json`

### 선박 카드
- 대상: 공통 ID 중 2026 업종별 5척(난수 42로 고정 선정) + 신규 ID 5척(난수 42)
- 카드 1장: 0.01° 체류 히트맵, 모항 표시, 관측일수·행 수, 2026 업종(신규는 "미제공")
- 공통 ID는 2026 / 2025 카드를 나란히 놓는다. 같은 지도 범위를 쓴다.
- 저장: `cards/*.png`, 선정 목록 `cards/selection.json`

## 3. V0 — 1단계 전제 확인

### 공통 설정 (사전 고정, 결과를 보고 바꾸지 않음)
- **쿼리:** 2025 선박. **갤러리:** 2026 전체 7,372척.
- **거리:**
  - 공간: Hellinger 거리 `sqrt(1 − Σ sqrt(p·q))`. 희소 행렬 곱(√p · √qᵀ)으로 전체 쌍을 계산한다. 0.01°와 0.05°를 각각 계산한다.
  - 모항: 두 모항 사이 거리(km). 어느 한쪽 결측이면 결측.
  - 시간대: 24칸 분포의 Hellinger 거리.
- **결합 점수(고정):** `d = 0.35·H(0.01°) + 0.35·H(0.05°) + 0.15·H(시간대) + 0.15·min(모항거리/50km, 1)`. 모항 결측이면 그 항을 빼고 나머지 가중치를 비례 재조정한다.
- 각 요소 단독 결과도 함께 보고한다(요소별 기여 확인용, 가중치 재선택에는 쓰지 않음).
- 유사도 `s1 = 1 − d(1등)`, 격차 `margin = d(2등) − d(1등)`.

### 검사 a — 자기 자신 찾기
공통 ID 6,842척을 쿼리로 넣어, 같은 ID의 2026 선박이 몇 등인지 본다.
- 보고: 1등·5등 이내·10등 이내 비율, 순위 중앙값
- 나눠서 보고: 2026 업종별, 2025 관측일수 구간별(1-7 / 8-30 / 31-90 / >90일)
- 대조: 갤러리 ID를 무작위로 섞었을 때의 같은 지표(난수 42)

### 검사 b — 서로 1등인 비율
2025→2026, 2026→2025 양방향 검색에서 서로를 1등으로 찾는 공통 ID 쌍의 비율.

### 검사 c — 이웃의 업종 일치율 (핵심)
공통 ID 6,842척의 상위 K 이웃(2026 선박) 업종 투표가 **그 ID의 2026 업종**과 같은 비율.
- K = 1, 5, 10. 투표는 거리 역수 가중(`1/(d+1e-6)`)과 단순 다수 둘 다.
- **두 조건을 반드시 분리:**
  - (가) 자기 포함: 갤러리에 같은 ID가 있는 그대로(실제 상황)
  - (나) 자기 제외: 같은 ID를 갤러리에서 빼고 검색(순수 이웃 효과)
- 업종별 일치율과 4×4 혼동행렬(행 = 2026 본인 업종, 열 = 이웃 투표 결과). 특히 자망·통발→연안복합 칸을 표시한다.
- 참고 기준선(판정 아님): 다수 업종 비율 0.495, TabICLv2 A 개발 OOF 정확도 약 0.593 (평가 집단이 달라 직접 비교가 아님을 명시)

### 검사 d — 신규 선박 오인율
신규 ID 926척을 쿼리로 넣는다.
- 신규와 공통 ID의 `s1`, `margin` 분포를 같은 그림에 그린다.
- 공통 ID의 **자기 자신 1등 매칭**에서 `s1`의 50/80/90% 지점을 임계값으로 잡고, 각 임계값에서 신규 ID가 통과하는 비율을 보고한다(`margin`도 같은 방식으로 따로).
- 신규 ID 중 관측 10행 미만 / 이상을 나눠 보고한다.

### 검사 e — 모항 이동 분포
공통 ID의 2025·2026 모항 거리 분포(히스토그램, 로그 축 포함).
- 0~2 / 2~10 / 10~50 / >50km 구간 비율
- 구간별 검사 a의 1등 비율과 검사 c(자기 포함, K=5 가중)의 일치율

### 검사 f — 관측량 영향
검사 a·c의 결과를 2025 관측일수 구간별로 다시 정리하고, 관측 10행 미만 쿼리를 따로 표시한다.

## 5. 지킬 것

- 기존 캐시·완료 폴더·모델 파일은 읽기만 한다. 수정·덮어쓰기 금지.
- ID 일치 여부는 V0의 **채점용**으로만 쓴다. 지문·거리 계산에 넣지 않는다.
- 테스트(2025) 선박의 업종을 추정하거나 2026 라벨을 2025 선박에 붙인 파일을 만들지 않는다. 검사 c는 "같은 ID의 2026 라벨과 이웃 라벨의 일치"만 계산한다.
- 없는 데이터를 만들지 않는다: 공백 연결, 누락 시간의 정지 처리, 결측을 0으로 채우기 금지. 결측은 결측으로 두고 개수를 보고한다.
- 전경 단일 프로세스로 실행한다. 10분을 넘는 단계는 체크포인트를 남기고, 재개 시 해시로 기존 산출물을 확인한다.
- 오류로 진행할 수 없으면 추측으로 우회하지 않는다. 그 시점까지로 보고서를 쓰고 멈춘다.
- 보고서와 출력은 한국어로 쓴다.

## 6. 정지 조건

- S0 해시 불일치
- S1 행 수·선박 수가 공식 값과 다름
- S7에서 블록 경계 침범 또는 지문에 라벨 열 발견
- 거리 행렬 계산이 메모리를 넘을 경우: 정지하지 말고 쿼리를 1,000척 단위로 나눠 계산한다. 그래도 안 되면 정지하고 보고한다.
