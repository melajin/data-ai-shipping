# 분석 종합과 Test B 실행 계획

## 1. 먼저 읽을 결론

**Test B는 동일 선박의 제공된 전체 항적을 보고, 사고가 있었다면 발생시각 하나를 추정하는 과제다.** 이후 항적을 참고할 수 있지만 테스트 자료로 모델을 학습하면 안 된다. 미사고로 판단한 선박은 예측 결과 칸을 모두 비운다.

현재는 처음부터 시스템을 만들 필요가 없다. **100척의 시간대별 이상점수 캐시와 제출 형식 파일이 이미 존재한다.** 이를 재사용해 사고시각 선택 방법을 비교한다. 다만 기존 이상점수의 의미·참조자료·결측 처리와 새 공식 규칙의 정합성부터 확인해야 한다.

오늘의 우선 목표는 다음과 같다.

1. 기존 캐시와 점수 계산 조건을 확인한다.
2. 동일한 점수·대상 자료로 **최고점 시각 / 이상 구간 시작 시각 / 시작점에 지속 조건을 추가한 구성**을 비교한다. 마지막 구성은 별도 시각 계산법이 아니라 시작점 후보의 근거 확인이다.
3. 선박별 결과를 한 표에 모아, 시각이 크게 갈리는 선박과 자료가 부족한 선박을 먼저 살펴본다.

**사고와 선박을 확정적으로 연결한 정답은 아직 없다.** 2026 기간의 연결 후보표는 실제로 생성하고 검산했다(§14). 기존 조건에서 단일 후보인 30건 중 9조건 모두 같은 단일 후보가 남은 것은 1건이다. 후보 연결과 사고 탐지 정확도·공식 F1의 입증은 구분한다.

### 1.1 재현 검증으로 바뀐 전제 (2026-11-05)

§13의 재계산과 자료 기간 확인으로 이 문서의 두 전제가 바뀌었다.

1. **기준선(A. Peak)은 재현됐다.** `scored_rows.pkl`에서 최대점수 시각과 보조시각을 다시 계산해 기존 제출 CSV와 대조한 결과 **8개 열 전부 불일치 0, 100/100척**이다. §10.1의 1·2단계는 완료다.
2. **사고 정답 연결은 "확보 불가"가 아니라 "기간을 잘못 맞춘 것"이었다.** 사고 목록 167건은 전부 **2026년**이고 Test B 항적은 **2025-01-01~06-30**이다. 두 기간은 겹치지 않으므로 기존 0건 매칭은 탐지 실패가 아니라 **산술적 필연**이다. 같은 매칭을 **2026년 학습 항적**에 돌리면 **167건 중 118건이 매칭되고, 그중 30건은 후보 선박이 1척**이다.

따라서 2026 기간에서 사고–항적 후보를 조사할 경로가 열렸다. 다만 임계값 학습과 시간오차 평가에는 연결 신뢰도, 사고자료의 개발용 사용 범위, 정상 사례 근거, 개발/평가 사건·선박 분리가 추가로 필요하다. 항적의 연도가 같다는 사실만으로 사고파일의 학습 사용이 자동 허용되는 것은 아니다.

이 문서는 대화에서 확인한 내용과 기존 검토 기록을 통합한 것이다. 이번 과정에서 새 모델 학습이나 공식 제출은 하지 않았다. 수행한 것은 읽기 전용 재현·대조 계산이다(§13).

## 3. 공식 질의응답으로 확인된 규칙

근거는 사용자가 이 대화에 전달한 두 차례 주최 측 답변이다. 별도의 공식 웹페이지 원본을 이번에 확인한 것은 아니다.

### 3.1 확정된 내용

| 항목 | 주최 측 답변의 내용 | 시스템에 반영할 사항 |
|---|---|---|
| 항적 사용 범위 | 제공된 동일 선박의 전체 항적 활용 가능. 해당 시각 이후의 항적 참고 허용 | 사고 전후를 모두 보는 사후 분석 가능 |
| 테스트 학습 | 테스트 데이터는 예측 용도로만 사용. 모델 학습에는 사용 불가 | 의사라벨 자기학습 금지. 테스트로 학습 기준을 다시 맞추지 않음 |
| 정량 평가 | 사고시각은 시간오차를 고려한 F1으로 평가 | 사고 여부와 시각 오차를 함께 관리 |
| 시간오차 안내 | 사고시각은 가까울수록 고득점. “6시간 넘어가면서부터는 0점 처리” | 6시간 이내가 모두 동일한 정답이라는 뜻으로 해석하지 않음 |
| 정성 평가 | 시각1~3과 이상항적 점수는 정성평가에 반영 | 관련 시각과 근거를 설명할 수 있도록 보존 |
| 미사고 제출 | 미사고로 판단한 선박은 모두 빈칸 | 식별자·템플릿 구조는 유지하고 예측 결과 칸 전체를 공란 처리 |
| 시각 형식 | 제출샘플 상단 예시와 같은 형식 | 실제 셀의 값·표시 형식을 확인해 따름 |

### 3.2 아직 확정되지 않은 내용

- 시간오차를 TP·FP·FN 또는 최종 F1에 반영하는 정확한 수식.
- 사고시각을 일찍 추정한 경우와 늦게 추정한 경우에 동일하게 감점하는지.
- 정확히 6시간 차이일 때의 처리.
- 시각1~3 및 점수의 구체적인 정성평가 기준.
- 제출샘플의 빈 H1을 `시각3`으로 바꾸어도 되는지. 답변은 형식을 따르라는 것이며 헤더 변경을 명시 승인하지 않았다.
- 테스트 자료를 이용한 선박별 KDE 적합 등 경계 사례의 허용 여부.

따라서 `±6시간이면 정답`, 선형 감점, 조기경보 가점 등의 규칙을 임의로 만들지 않는다. 6시간이라는 안내를 이상 구간 병합 간격으로 자동 사용하지 않는다.

### 3.3 전체 항적 참고와 테스트 학습의 구분

고정된 계산 규칙으로 동일 선박의 앞뒤 항적을 비교하는 것은 전체 항적을 활용한 추론으로 설계할 수 있다. 반면 테스트 자료에서 모델 가중치, 스케일러, 군집, KDE, 임계값 등을 새로 적합하는 것은 별도 문제다.

“전체 항적을 볼 수 있다”는 답변이 모든 테스트 기반 통계 적합을 명시 허용한 것은 아니다. 오늘의 비교는 **출처를 확인한 기존 기준을 고정해 적용**하는 범위로 한정한다. 임계값이 없으면 테스트 점수의 분위수로 임의 생성하지 않는다.

## 4. Round 001과 Gemini 설명에 대한 정리

다음 수치는 [Gemini 대화 검토·반박](20261105_Gemini대화_검토반박.md)과 기존 실행 기록에 근거한다. 이 문서 작성 중 다시 학습하거나 OOF 전체를 재계산한 값은 아니다.

### 4.1 확인된 기준선과 실험 범위

| 항목 | 기록된 결과 | 해석 범위 |
|---|---|---|
| 개발 선박 | 5,897척 | 공식 Test B 사고 평가 집단이 아님 |
| 정답 예측 수(correct) | 평가 5,897척 중 3,497척 | 조업형태를 맞힌 수. 라벨을 보유한 선박 수와 구분 |
| Micro-F1 | 0.5930133966 | 모든 클래스를 포함하는 단일 라벨 분류에서 정확도와 같음 |
| Macro-F1 | 0.5252719739 | 클래스별 F1의 단순 평균 |
| CSV 기본 reader와 NPZ | T5 10열의 finite 값 bitwise 동일, ID·열·NaN mask 일치 | X304 전체 304열을 이번에 대조했다는 뜻이 아님 |
| reader 간 값 차이 | 최대 약 8.88e-16 | 원 동적 배열의 완전 재현 증거는 아님 |
| 예측 영향 | 일부 확률 변화, 최종 argmax·정답 수 변화 없음 | 확률까지 모두 동일한 것은 아님 |
| 새 학습 | 0회 | 옛 .59183과 현재 .593013 차이의 원인을 확정하지 못함 |

작은 입력 차이가 트리의 분기 경계를 넘으면 큰 출력 차이로 이어질 수 있다는 설명은 가능한 메커니즘이다. 그러나 이번 실험에서 개별 split이나 재학습 경로를 추적해 원인으로 확정한 것은 아니다.

개별 모델의 개발 전체 최대 확률 변화 0.004175와 OUTER 앙상블 최대 변화 0.001202를 그대로 비교해 상쇄를 설명하면 범위가 다르다. 같은 fold·같은 OUTER 행으로 맞춘 비교에서 감소를 설명해야 한다.

### 4.2 실제 클래스별 병목

| 업종 | 개발 척수 | Precision | Recall | F1 |
|---|---:|---:|---:|---:|
| 연안복합 | 2,920 | 0.6066 | 0.8154 | 0.6957 |
| 자망 | 2,016 | 0.5747 | 0.4504 | 0.5050 |
| 통발 | 835 | 0.4640 | 0.1389 | 0.2138 |
| 채낚기연승복합 | 126 | 0.6479 | 0.7302 | 0.6866 |

- 가장 적은 채낚기연승복합의 F1은 약 0.687이다. “희귀 업종이 Macro를 끌어내렸다”는 설명은 이 결과에 맞지 않는다.
- 주요 병목은 **통발 분리 실패와 연안복합 과예측**이다.
- 통발 835척 중 516척은 연안복합, 191척은 자망으로 예측됐다. 자망 1,010척도 연안복합으로 예측됐다.
- 실제 코드값의 명칭을 사용한다. `안강망`을 이 데이터의 클래스로 설명하지 않는다.
- 다른 팀 자료에 다른 클래스 명칭이 나오면 대응표를 확인한다. 이름이 비슷하다는 이유로 자동 통합하지 않는다.

### 4.3 라벨 사용·분할에 관한 정확한 설명

T5에는 FIT 선박의 라벨로 만든 격자별 클래스 비율이 포함된다. 따라서 “라벨을 전혀 참조하지 않는 순수 항적 특징”이라는 설명은 틀리다. 검토된 경로에서는 FIT 라벨만 사용하고 자기 기여를 제외하는 장치가 있다.

이 사실만으로 모든 버전의 T5·참조지도·추론 경로에 누수가 없다고 포괄 인증하지 않는다. **사용할 실제 artifact의 명부·참조 자료·전처리 범위를 확인**해야 한다. 라벨 경계와 무라벨 Test 항적의 학습 기여 여부도 별도 점검한다.

분할은 단순한 두 그룹 학습이 아니라 FIT / INNER / OUTER 구조다. fold 0·1의 기록은 3,144 / 787 / 1,966, fold 2는 3,145 / 787 / 1,965다. INNER를 early stopping에 사용한 이력을 무시하고 같은 자료를 독립 선택 자료로 재명명하지 않는다.

### 4.4 다른 성적과 섞지 않을 것

[팀원자료 검토보고서](20261105_팀원자료_검토보고서.md)의 0.8383 등은 별도의 조업 분류 실험이다. 그 문서는 기존 선박이 많은 평가 집단과 신규 선박 집단의 성능을 구분한다. 이를 본 문서의 .5930 기준선 또는 Test B 사고 성능과 직접 비교하지 않는다.

팀원 문서의 신규 집단 0.5789도 특정 내부 실험의 값이다. 공식 Test A의 예상 점수가 반드시 약 0.58이라고 확정할 수는 없다. 이번 정리에서는 해당 ZIP 원본·모델을 재검증하지 않았다.

## 5. Test B의 문제를 어떻게 이해할 것인가

### 5.1 관측·이상·사고는 서로 다르다

| 관측 | 정상 또는 다른 원인으로 가능한 설명 | 사고 관련 가능성 |
|---|---|---|
| 좁은 곳에 항적이 모임 | 조업 대기, 정박, 관측 표본 변화 | 비의도적인 이동 제한 등 |
| 경로 모양이 달라짐 | 조업 방식 전환, 회피 행동, 위치 오류 | 사고와 관련된 움직임 변화 |
| 평소 구역을 벗어남 | 어장 변경, 피항, 이동 항해 | 비의도적 표류 등 |
| 기록이 끊김 | 수신 문제, 누락, 제공 기간 종료 | 장비 손상 가능성 등 |

이상점수는 기준에서 벗어난 정도다. **0.9라는 점수를 사고 확률 90%로 읽지 않는다.** 여러 방법이 같은 시각을 골라도 그것만으로 사고 정답이 되지 않는다.

### 5.2 업종 분류는 보조 정보

업종을 알아야만 이상 탐지가 성립하는 것은 아니다. 고정된 방법으로 동일 선박의 앞뒤 항적을 비교할 수 있다. 예측 업종을 보조로 사용할 때는 오분류가 사고 판단까지 전파될 수 있다.

특히 현재 조업 모델의 통발 recall은 낮다. 출력 확률이 높다는 사실만으로 업종을 확정하지 않는다. 업종 조건부 기준을 쓸지는 별도 검증하며, 오늘의 시각 비교에 필수 단계로 추가하지 않는다.

### 5.3 확인 시각과 추정 발생시각

예시: 10시에 움직임 변화 → 13시까지 지속 확인 → 15시에 이상점수 최고.

- 최고점 방식은 15시를 후보로 잡을 수 있다.
- 시작점 방식은 10시를 후보로 잡을 수 있다.
- 지속 확인 방식도 13시에 확인한 뒤 10시를 후보로 보고할 수 있다.

이는 방법을 설명하는 가상 예시다. 10시가 실제 사고시각이라는 뜻은 아니다. 전조·사고·후속 행동이 서로 다른 시각에 나타날 수 있으므로 시작점이 더 정확하다는 것은 검증할 가설이다.

EMA나 지속성 확인은 확인 시점을 늦출 수 있지만, 사후에 시작점을 선택한다면 반드시 제출 시각까지 늦어지는 것은 아니다. “EMA는 무조건 정량 점수를 깎는다”라고 단정하지 않는다.

### 6.3 기존 방식의 한계

[11월 4일 추가 검토](../docs/review_20261104/astra_repo_addendum.md)에 따르면 기존 점수는 구역·변화·공백 점수의 계산 가능한 부분을 평균한 탐색적 이상점수다.

코드를 직접 읽어 확인한 결과는 다음과 같다. 이전에 “별도 확인 필요”로 남겨 둔 항목 대부분이 확정됐다.

- **점수 합성:** `np.nanmean([s_zone, s_change, s_gap])` — 계산 가능한 성분만 평균한다는 서술이 맞다. 세 성분이 전부 결측인 행만 NaN으로 남긴다.
- **보조 시각의 근거:** **확인 완료.** 코드는 피크에서 각각 3·2·1시간을 뺀 시각을 쓰되, **그 시각에 비결측 점수가 실제로 있을 때만** 기입한다. 즉 단순 산술 생성이 아니지만 후보 시각 자체는 피크 종속이다.
- **보조 시각의 공란 규모:** 시각1 공란 66척, 시각2 57척, 시각3 39척이고 **셋 다 채워진 선박은 30/100뿐**이다. 시각1~3은 정성평가 대상이므로 이 공란율은 실질적 감점 위험이다. 현 로직에서는 피크 직전 3시간 관측이 없으면 구조적으로 비워진다.
- **동점 처리:** `idxmax`는 최초 등장 시각을 고른다. 다만 현 캐시에서 **피크 동점 선박은 0척**이라 이 규칙은 아직 쟁점이 아니다.
- **관측 이력 부족:** `MIN_HIST_FOR_CHANGE = 24`가 S_변화의 최소 과거 행 수다. 24행 미만 8척, 1행 2척이며, **S_변화가 전 구간 결측인 선박도 정확히 8척**으로 일치한다. 이는 연속 24시간 관측이라는 뜻이 아니다.
- **점수 바닥값:** 전체 82,626행 중 바닥값(1e-6) 99행, 이를 포함한 선박 99척이다. 코드 주석도 바닥값이 “정상 확신”이 아님을 명시한다. 더 중요한 것은 **피크 점수 자체가 바닥값인 선박 2척(`36003490`, `36000725`)** 이다. 이 2척은 제출 CSV에 사고시각이 적혀 있으나 근거가 사실상 없으므로 §9의 “자료 부족·계산 불가”로 재분류할 1순위 후보다.
- **대상 선박의 참조지도 제외 장치가 없고, 라벨 집합과 Test B 대상의 ID 교집합은 95척이다.** 실제 밀도 기여에는 조업 마스크·고유격자 조건이 추가된다. 95척의 집합 포함만으로 각 조회 격자의 자기 기여나 점수 희석을 입증하지 않는다. fine/coarse 선택과 밀도 clip을 포함한 선박 제외 재계산으로 영향 여부·크기를 확인해야 한다.
- **성분별 결측률:** s_zone 0.0%, s_change 2.7%, s_gap 0.1%. 점수는 사실상 s_zone이 항상 들어간 평균이다.
- 기존 프로그램은 출력 경로가 고정돼 있다. 여러 조건으로 그대로 병렬 실행하면 기존 캐시·제출 파일을 덮어쓸 수 있다.
- **미사고 공란은 아직 없다.** 코드의 공란 분기는 “행이 없거나 점수가 전부 결측”일 때만 발동하고, 실제 `n_blank_vessel = 0`이다. 즉 기존 파일의 공란 경로는 **자료 부족 → 공란**이며, 새 공식 규칙에서 공란이 뜻하는 **미사고 판정 → 공란**과 의미가 겹친다. §9가 경고한 혼동이 이미 코드에 들어 있다.

따라서 비교 실행은 별도 작업 폴더를 사용하고 기존 산출물은 보존한다. 새 공식 답변을 반영한 사고 기각·공란 처리가 기존 파일에 구현돼 있다고 가정하지 않는다.

### 6.4 사고–항적 후보 연결의 상태 — 기간을 바로잡아 후보표 생성 완료

기존 사고 연계 검사 기록은 사고 167건과 항적의 ±1시간·5km 근접 후보 매칭이 **0건**이었다고 보고한다. **두 입력의 기간이 겹치지 않음을 확인했다. 이 조건에서 0건은 탐지 실패가 아니라 기간 불일치의 결과다.**

| 자료 | 기간 | 라벨 | 용도 |
|---|---|---|---|
| 테스트셋 `vpass_1~6월` | **2025-01-01 ~ 2025-06-30** | `fishing_code` 열 없음 | Test A·B 예측 대상 |
| `vpass_26년(1월_6월)` | **2026-01-01 ~ 2026-06-30** | `fishing_code` 있음 | 학습 (3,887,065행) |
| `26년 1~6월 어선 사고현황` | **2026년 167건 전부** | 좌표·발생일시 보유 | 파일명은 “테스트 데이터”지만 기간은 **학습 쪽**과 일치 |

기존 검사는 **2026년 사고**를 **2025년 테스트 항적**에 맞췄다. 두 집합의 시각이 1년 떨어져 있으므로 ±1시간 창에서 0건은 산술적 필연이며, 이상 탐지 성능과 무관하다.

**같은 매칭 규칙(±1시간·5km)을 2026년 학습 항적에 적용하면 결과가 달라진다.**

| 지표 | 결과 |
|---|---|
| 좌표 보유 사고 | 167 / 167 |
| 후보 선박이 1척 이상인 사고 | **118 / 167** |
| 매칭 사고당 평균 후보 선박 | 4.28척 |
| **후보 선박이 정확히 1척인 사고** | **30건** |

이 30건은 해당 시공간 조건에서 고유 RFID 후보가 하나인 사건이다. **확정 정답표가 아니다.** 단일 후보가 실제 사고 당사자라는 보장은 없고, 사고 선박이 vpass 추적 대상이 아닐 수도 있다. 사고 파일에는 여전히 **선박 ID·선명 열이 없다.** `사고선박수`, `선 종`, `톤수`는 검토 근거지만 대응 선박 제원표가 없으면 이를 이용해 특정 후보를 제거할 수 없다. §14 감사에서 30건 중 다선박 사고 3건, 9조건 안정 단일 1건을 확인했다.

이 경로의 의의는 세 가지다.

1. **개발용 사고 근거를 확보할 가능성이 생긴다.** 연결 신뢰도와 사고자료 사용 범위를 확인한 뒤 개발/평가를 분리해야 한다. 현재 후보표를 즉시 확정 학습 라벨로 사용하지 않는다.
2. **시각 비교를 위한 원 사건시각을 보존할 수 있다.** 사고시각 근처에서 선택한 항적행과의 차이는 연결 잔차이며 탐지 오차가 아니다. 후속 평가는 전체 기간에서 예측을 먼저 고정한 뒤 사건과 대조한다.
3. **정당한 평가 집단이 확보되면 시각오차 분포를 조사할 수 있다.** 그때 6시간 초과 비율 등을 내부 지표로 산출할 수 있으나, 공식 F1 수식과 같다고 하지 않는다.

주의: 2026 학습 기간에서 얻은 기준이 2025 테스트에 그대로 유효하다는 보장은 없다. 두 기간은 다른 해이고 선박 구성도 다르다. 이는 가정으로 명시하고, 기준을 사후에 바꾸지 않는 것으로 통제한다. 검토 문서의 `Train(2024)` 표기는 실제 자료와 맞지 않으므로 입력 계약으로 사용하지 않는다.

## 7. 오늘 비교의 설계

### 7.1 사고 판정과 시각 선택을 분리한다

두 질문을 동시에 바꾸면 무엇 때문에 결과가 달라졌는지 알기 어렵다.

1. **사고 여부:** 이 선박을 사고 후보로 보고할 근거가 충분한가?
2. **시각 선택:** 같은 후보 구간에서 어느 시각을 보고할 것인가?

오늘은 공통 점수·후보·사고 판정 기준을 고정하고 시각 선택과 후보의 지속성 근거를 비교한다. C의 지속 조건 미충족은 후보 근거 부족이며, 공통 사고 판정을 미사고로 바꾸는 규칙이 아니다. 사고 여부 임계값의 출처가 없으면 이진 사고 판정을 만들지 않고 후보 시각 비교로 범위를 제한한다.

### 7.2 공통 조건

- 같은 캐시 버전, 선박 목록, 기간, 점수 방향, 결측 규칙을 사용한다.
- 기준선의 최대점수 시각을 먼저 재현하고 기존 CSV와 대조한다.
- 임계값·이상 구간 정의·지속 조건·동점 처리·시간 간격 기준을 실행 전에 기록한다.
- 테스트 결과를 보고 이 기준들을 뒤늦게 바꾸어 유리한 조건을 고르지 않는다.
- 누락 구간을 넘어 연속된 이상으로 합치지 않는다. 단순히 연속 행이라는 이유로 연속 시간이라고 처리하지 않는다.
- 같은 사건 후보를 대상으로 시각 선택 방법만 비교한다. 여러 사건 중 선택 자체가 달라지면 별도 변화로 표시한다.
- 공통 기준이 성립하지 않으면 해당 조건을 계산 불가로 남긴다. 억지로 시각을 채우지 않는다.

### 7.3 두 가지 시각 선택법과 지속성 확인 조건

| 조건 | 계산 목적 | 정의 | 현재 상태 |
|---|---|---|---|
| A. Peak | 기존 결과 재현 | 기존 최대점수 시각. 동점은 최초 등장 시각(`idxmax`) | **재현 완료 — 100척, 8개 열 전부 불일치 0** |
| B. Onset | 같은 후보의 시작점 비교 | A가 속한 이상 구간의 첫 임계값 초과 시각 | 임계값 출처 확보 후 구현 (§6.4 경로) |
| C. Persistent onset | 단발성 변화를 구별하면서 시작점 비교 | 같은 후보 구간이 사전 고정한 지속 조건을 만족하면 그 시작 시각 선택 | 지속 조건 고정 후 구현 |

**B와 C가 같은 구간을 사용하고 C의 지속 조건이 충족되면 C시각은 B시각과 같다.** 따라서 A와 B는 시각 선택 차이를, B와 C는 지속 조건을 만족하는 후보의 비율과 근거 부족 여부를 비교한다. 이를 서로 독립된 세 알고리즘의 합의로 설명하지 않는다.

C가 조건을 만족하지 못하면 다른 시각을 몰래 대신 고르지 않고 조건 미충족으로 기록한다. 다른 사건으로 바꾸는 실험이 필요하면 별도 후보 선택 실험으로 분리한다.

임계값 근거가 없으면 B·C를 임의 임계값으로 실행하지 않는다. **확인 결과 `scores_meta.json`에는 임계값이 없다.** 정규화 기준(분위수 변환, 20km 고정 스케일)만 있고 "이 점수 이상이면 이상"이라는 경계는 어디에도 기록돼 있지 않다. 따라서 **기존 산출물만으로는 B·C를 오늘 실행할 수 없다.** 이 문서가 예견한 실패 분기가 실제로 발동했다.

후속 경로는 다음과 같다. §14의 후보표 감사만으로 임계값이 정해지는 것은 아니다.

1. 연결 신뢰도와 사고자료의 개발용 사용 범위·정상 근거·개발/평가 분리를 먼저 확인한다. 이 조건을 만족한 개발 자료에서만 임계값을 정하고 고정한다. 단일 후보 30건을 곧바로 사고 정답으로 취급하지 않는다.
2. 그 조건이 성립하기 전에는 A 재현, 데이터 품질표, 연결 후보의 민감도·원 항적 근거를 산출물로 삼는다. A 재현과 후보 연결 감사는 이미 완료했다.

테스트 점수의 분위수로 임계값을 만들지 않는다. 별도의 고정된 변화점 계산법을 추가하려면 새 가정과 조건을 먼저 기록한다.

### 7.4 병렬 작업 분담

| 담당 | 책임 | 파일·출력 경계 |
|---|---|---|
| 공통 담당 1명 | 입력 계약·캐시 검증·공통 점수·조건 고정 | 공통 manifest와 특징표 단독 관리 |
| A 담당 | 기존 최고점 시각 재현 | A 전용 결과 폴더 |
| B·C 담당 또는 분리 담당 | 시작점·지속 시작점 계산 | 조건별 전용 결과 폴더 |
| 검토 담당 | 선박·시각 정렬, 결측, 입력 무변경, 결과 병합 검산 | 검토 결과만 작성 |

원자료를 작업자마다 다시 읽지 않는다. 공통 준비가 끝난 뒤 독립 계산만 병렬화한다. 동시 실행 수는 실제 메모리와 CPU 상태를 보고 정하며 병렬화 자체가 빨라짐을 보장한다고 하지 않는다.

## 8. 비교 결과의 형식과 해석

### 8.1 선박별 비교표

최소한 다음 열을 남긴다.

`rfid_id, 관측범위, 유효행수, 누락상태, 공통판정상태, A시각, B시각, C시각, B-A시간차, C-A시간차, 후보변경여부, 계산불가사유, 근거경로`

추가로 점수 구성요소, 지속 조건 통과 여부, 원 후보 구간, 조건 버전을 보존한다. 시간 차이는 후보 간 차이이며 실제 사고시각 오차가 아니다.

### 8.2 우선 확인 순서

1. 원자료·결측·시간 처리 때문에 판단할 수 없는 선박.
2. 조건별 시각이 크게 다르거나 사건 후보 자체가 달라진 선박.
3. 근거가 한 종류의 점수 또는 단일 관측에 치우친 선박.
4. 조건이 비슷한 시각을 고른 선박의 표본 확인.

합의 결과는 규칙 변화에 대한 안정성 참고자료다. 합의율을 정확도로 표현하지 않는다. 같은 점수를 쓰는 세 방식은 독립적인 세 증인이 아니다.

### 8.3 오늘 계산 가능한 것과 아닌 것

| 구분 | 항목 |
|---|---|
| **완료** | 기준선 재현(불일치 0), 자료 부족·바닥값 비율, 보조시각 공란율, 성분별 결측률, 참조지도 자기기여 여부 |
| 계산 가능 | 후보 시각 이동량, 지속 조건 충족 후보 비율, 조건 일치·불일치, 실행시간 |
| 조건부 가능 | 근거가 있는 공통 사고 판정 규칙에 따른 후보 선박 수·공란 처리 |
| **이번에 완료된 추가 계산** | 2026 사고–항적 후보 118건·단일 후보 30건 재현, 9조건 민감도와 전체 사건 검토표 (§14) |
| 후속 조건부 평가 | 연결 신뢰도·자료 사용 범위·개발/평가 분리 후 추정시각 오차와 6시간 초과 비율 비교 |
| 여전히 미검증 | 2025 테스트 기간의 사고 탐지 정확도, 공식 시간오차 F1 수식, 최종적으로 가장 좋은 조건 |

현재 계산한 시간차는 연결 잔차다. 후속 2026 탐지 평가를 수행하더라도 그 기간과 검증 집단에 한정한 내부 지표이며, 2025 테스트 성능의 검증된 추정치로 제시하지 않는다. 공식 수식이 없으면 공식 점수라고 부르지 않는다.

## 9. 제출 단계의 규칙

내부 상태는 최소한 다음 세 가지로 나눈다.

| 내부 상태 | 의미 | 제출 처리 |
|---|---|---|
| 사고 예측 | 고정된 판단 기준을 통과 | 사고시각과 관련 점수·보조 시각 작성 |
| 미사고 예측 | 고정된 판단 기준상 사고로 판단하지 않음 | 예측 결과 칸 전체 공란 |
| 자료 부족·계산 불가 | 판단에 필요한 정보 부족 또는 처리 실패 | 내부 검토 대상으로 유지. 자동으로 미사고로 바꾸지 않음 |

자료 부족 상태의 최종 제출 처리 정책은 별도 확정이 필요하다. 임의의 0점·가짜 시각으로 채우지 않는다.

제출 파일 생성 시 다음을 확인한다.

- 공식 대상 ID와 순서, 중복·누락.
- 사고시각·시각1~3의 실제 관측 근거와 시간 순서.
- 시각1~3을 단순히 사고시각에서 1·2·3시간 뺀 값으로 만드는지 여부. 실제 관측이 없으면 근거를 만들어내지 않는다.
- 점수의 의미·범위와 날짜·시간 셀 형식.
- 빈 헤더를 포함한 템플릿 구조 보존.
- 미사고 예측 행의 결과 칸 전체 공란.
- Test A 시트를 갱신할 때 Test B 결과가 샘플값으로 덮이지 않는지, 반대 경우도 같은지.

공식 제출 파일은 탐색용 비교표와 분리한다. 형식 검사 통과와 사고 성능 검증은 별개다.

### 10.1 오늘의 우선 작업

| 순서 | 작업 | 산출물 | 완료 기준 | 상태 |

1·2단계에 이어 3단계 후보표 생성·감사도 완료됐다. 다음에는 연결 신뢰도와 자료 사용 범위, 정상 근거, 개발/평가 분리를 확인한다. 후보표 생성만으로 4·5단계가 자동으로 성립하지 않는다.

기한이 오늘이라는 것은 성능을 검증했다고 간주하는 이유가 되지 않는다. 구체적 소요시간은 보장하지 않는다. 다만 3단계의 매칭 자체는 학습 배열 388만 행에 대해 이미 수 초 규모로 돌려 봤다(§13).

## 11. 검증 기록과 학습 확인

각 실행에는 조건·예상 결과·계산 결과·해석을 남긴다. 시작/종료 시각, 실제 종료코드, 코드·입력 식별정보, 오류 로그를 보존한다. 종료코드를 확보하지 못했으면 성공 코드로 추정하지 않는다.

이번 단계에서 확인할 설명 질문은 다음과 같다.

1. 이상을 확인한 시각과 사고 발생 추정시각은 왜 다를 수 있는가?
2. 세 조건이 같은 시각을 골라도 사고 정답이라고 할 수 없는 이유는 무엇인가?
3. 미사고 예측과 자료 부족을 같은 빈칸으로 내부 처리하면 어떤 문제가 생기는가?
4. 사고 매칭이 0건이었을 때, "탐지 실패"가 아니라 "기간 불일치"를 먼저 의심해야 했던 이유는 무엇인가? 0건이라는 결과만 보고 모델을 고치러 갔다면 무엇을 잃었겠는가?
5. 참조 집합에 자기 ID가 있다는 사실과 실제 조회 격자·점수에 기여했다는 사실을 구분하려면 무엇을 확인해야 하는가?

비교 프로그램이 동작하는 것과 사용자가 이 질문에 답할 수 있는 것은 별도 완료 항목이다. 실제 하드웨어 실험이나 실선 안전성을 검증했다고 표현하지 않는다.
