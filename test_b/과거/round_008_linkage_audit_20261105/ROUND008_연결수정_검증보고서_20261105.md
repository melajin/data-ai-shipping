# Round 008 — 후보 연결 순서 수정과 기존 점수 재평가

2026-11-05. 사용자 지적을 코드 반례와 2026 Train 실제 자료로 확인하고 수정했다. **오류는 개발셋의 선박 신원을 실제로 바꿨다.** 수정 후에도 최고점 시각 규칙의 무작위 대비 우월성은 확인되지 않았다. 다만 신원 후보는 잠정 연결이며, 이 결과가 모든 사고 신호의 부재를 증명하지는 않는다.

## 1. 오류와 수정

기존 S1은 가장 넓은 ±6h/20km 안에서 선박별 거리 최소 관측 한 행을 남긴 뒤 S2가 좁은 조건을 검사했다. A선박의 `(시간차 6h, 거리 0.1km)`가 `(0h, 1km)`를 가리면, B선박 `(0h, 1.5km)`와 함께 있어도 w0/r2에서 A가 누락돼 B가 단일 후보로 보인다.

수정본은 넓은 창 안의 관측 **25,600행**을 보존한다. 각 `(w,r)`를 먼저 적용하고 그 안에서 선박 ID를 unique로 센다. 대표 관측도 선택된 티어 안의 실제 행에서 가져오며 원본 월·행 번호를 남긴다. 가장 넓은 창의 사건×선박 **4,200쌍**은 전과 같다.

어구 매핑·원행 유효성·거리식·정수 시간 절삭·기존 조건 우선순위·충돌 유지·음성 표본 seed는 유지했다. 따라서 주 비교는 사전 축약 오류의 영향이다. 기존 CASCADE는 엄밀한 포함관계가 아니므로 **고정 우선순위 조건 목록**이라고 부른다. `w0`은 사고와 같은 시간 버킷이며 원시각의 정확한 정각 일치를 뜻하지 않는다.

구현: [linkage.py](linkage.py), [연결 감사 실행기](run_linkage_audit.py), [기존 점수 추가 계산·평가](rescore_evaluate.py). 실행 전 범위와 보조 측정 절차는 [PROTOCOL](PROTOCOL.md)에 고정했다.

## 3. 수정 연결로 기존 점수를 다시 측정한 결과

수정된 양성 후보 82척 중 48척만 기존 점수 캐시에 있었다. 나머지 **34척만 동일 scorer·참조·밀도 자기 기여 제외 방식으로 추가 채점**했다. 양성 82척과 음성 1,500척, 총 **1,582척·822,000행**을 모두 포함했다. 새 특징·모델 학습·임계값 개선은 수행하지 않았다.

| 지표 | Round 007 | 수정 후 |
|---|---:|---:|
| 사고 ±6h 내 관측 존재 | 85/85 | **82/82** |
| 무작위 관측행 1개 선택의 기대 적중률 | 약 2.6% | **2.269%** |
| A_peak ±6h 적중 | 4/85 (4.71%) | **3/82 (3.66%)** |
| A_peak의 무작위 대비 단측 p값 | 0.164 (저장 시뮬레이션) | **0.27554 (정확 Poisson-binomial)** |
| 14규칙 중 하나라도 적중 | 15/85 (17.65%) | **10/82 (12.20%)** |
| 선박 최고점 AUC | 0.7255 | **0.7558** |
| 관측행 수만의 AUC | 0.7239 | **0.7959** |
| 행 수 짝짓기 후 최고점 AUC | 0.5904 | **0.5802** |
| 짝짓기 후 행 수 AUC | 0.5012 | **0.5008** |

수정 후 p값은 선박별로 다른 무작위 적중확률을 쓰며, 다중사건 선박은 모든 사고 창의 합집합으로 센다. 비교 기준은 **선박마다 관측행을 균등하게 한 개 선택하는 null**이다. `p≥.05`는 이 기준 대비 우월성 근거가 부족하다는 뜻이다. 관측 시각을 활용하는 모든 합리적 기준선과 비교한 결과도, 효과가 0이라는 증명도 아니다. 상관된 실제 14규칙의 합집합을 독립 무작위 14회 합집합과 직접 검정하지 않았다.

행 수 매칭은 ID 순 양성에 대해 관측행 수가 가장 가까운 음성을 중복 없이 택하는 명시적 새 보조 절차다. 원 매칭 코드가 없어 동일 알고리즘의 전후 재현으로 주장하지 않는다. 그래도 현재 최고점 AUC를 사고 탐지력으로 단독 해석하기 어렵다는 교란 징후는 다시 관찰됐다. 짝짓기만으로 교란을 완전히 제거했다고 주장하지 않는다.

원 S5 수치 계산을 그대로 재실행한 결과에서도 임계값 **0.64 이상에서 시간 적중 TP는 전부 0건**이다. 검사한 그리드의 dev 혼합비 F1 최댓값은 **0.0068**(임계값 0.58)이다. 이는 그 혼합비·잠정 라벨·그리드의 진단이며 실제 Test B 성능이나 최적 임계값의 확정이 아니다.

## 4. 민감도와 성분 신호 진단

| 평가 집합 | 사건/선박 | A_peak 적중 | 무작위 기대율 | 정확 단측 p값 |

충돌 사건 제외는 해당 사건만 제거한다. 같은 선박의 다른 비충돌 사건이 있으면 그 선박은 남는다. 다중사건 선박 제외는 11척 전체를 뺀 별도 민감도다.

원 M6의 난수 생성 코드가 없어, 새로 명시한 절차로 사건 ±6h 창 최대값의 자기 분포 백분위를 측정했다. 같은 선박의 관측 시작~끝 사이 균등 정수 시각 10개를 seed=20261105로 뽑는다. 빈/결측 창은 제외하고 **유효 창 전체 평균**을 낸다. 사건별 유효 무작위 창 수가 달라 동일 사건 가중치 평균과 다르다.

유효 무작위 창이 절반 정도이며 사건 연결 자체도 사고 인근 관측을 요구하므로 선택 영향을 주의해야 한다. 이 차이는 탐색적 진단이고 독립 정답의 검증이나 조합 성능의 상한이 아니다. 창별 원값과 빈/결측은 [window_percentiles.csv](window_percentiles.csv), 예정·유효·빈 수는 [accident_hour_percentile.json](accident_hour_percentile.json)에 있다.

## 5. 기존 네 결론과 다음 결정

1. **평가 단위 확보:** ‘확정 정답 98건’ 대신 **잠정 연결 100건/82척**으로 정정한다. 실제 신원 근거는 아직 필요하다.
2. **시각 선택:** A_peak의 정확 검정에서 무작위 대비 우월성 근거를 확인하지 못했다. 나머지 규칙도 적중률은 낮았지만 규칙별 정확 검정과 다중비교 보정을 수행한 것은 아니다. 모든 시각 규칙의 가능성을 기각한 것은 아니다. 82/82 관측 존재는 이 연결 설계의 영향을 받으므로 자료의 충분한 품질·빈도·관측 내용까지 보증하지 않는다.
3. **임계값:** 현재 최고점·검사 그리드에서는 유용한 시간 적중/오탐 절충을 확인하지 못했다. 행 수 교란 징후도 강하다. ‘임계값으로는 절대 불가능’이라는 보편 결론으로 확대하지 않는다.
4. **자료 부족·가중치:** 이번 단계에서 후순위는 유지한다. 다만 작은 주변 백분위 차로 ‘어떤 가중치/결측 수정도 성능을 올릴 수 없음’을 증명할 수는 없다.

후속 R008-1은 **이 수정 개발셋과 잠정 라벨의 한계**부터 승계해야 한다. 신원/충돌 처리와 시간 약라벨 정책(다중사건 union, ±3h 가정, 경계·guard band, 사고 목록 밖 구간의 미확인 처리)을 먼저 고정한다. 과거 인계서의 `+0.05` 관문과 ‘약 6건이면 유의’는 자동 확정 기준으로 쓰지 않고 표본·귀무모형·다중비교를 반영해 재설계해야 한다. 시간별 좌표가 없는 부분선 연결로 실제 속력·가속도를 만들지 않으며 `len_m` 기반 값은 항적 요약 지표로 구분한다.

이번 완료 범위는 연결 오류 수정과 기존 점수 재평가다. 신규 특징·모델 학습·2025 제출물 수정·공식 제출로 확장하지 않았다. 다음 진입 문서는 [새 인계서](NEXT_ROUND_인계_20261105.md)다.

## 6. 검증과 RAM 기록

- 합성 회귀 **9개 통과**: 유효 행 가림, 가짜 단일, 중복, 조건 안 증거행, 충돌, 어구, 경계, 빈 후보, 동률/입력 순서.
- 독립 집합 집계 40조건 통과. 보존한 원행으로 기존 잘못된 축약을 재현했을 때 **4,200쌍의 ID·거리·시간차·어구 일치**를 확인했다. 수정 증거행 100건 모두 선택 티어와 원행을 만족했다.
- Round 007의 23개 파일 SHA-256이 감사 중 유지됐다. 원자료와 선행 산출물을 덮어쓰지 않았다. [verification.json](verification.json), [독립 검토 기록](INDEPENDENT_REVIEW.md).
- 연결 최초 실행은 2026-11-05 11:05:52 KST 가용 **3,378.5MiB**, 예상 추가 최대 768MiB·여유 1,024MiB에서 시작했고 실제 peak RSS **251.8MiB**였다. 기록은 후속 보완 재실행 시 최신 preflight/receipt로 갱신됐다.
- 34척 추가 채점은 11:10:19 KST 가용 **3,333.4MiB**, 예상 추가 최대 1,024MiB·여유 1,024MiB에서 시작했다. 34척 추가 채점부터 전체 평가까지 **65.38초**, 실제 peak RSS **760.2MiB**였다. [최초 채점 영수증](score_evaluation_initial_receipt.json). 출력 설명과 빈 집합 처리를 보완한 후 추가 점수 캐시를 재사용해 재평가했고 [최종 영수증](score_evaluation_receipt.json)을 남겼다.
- 각 채점·합치기·평가 단계마다 RAM을 새로 확인했다. 메모리 polling, 사용자 프로세스 종료, 대형 병렬 데이터 로드는 하지 않았다. 독립 에이전트는 작은 소스와 문서만 검토했다.
