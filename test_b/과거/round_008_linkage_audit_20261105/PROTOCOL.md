# Round 008 연결 수정 감사 — 실행 전 계약

2026-11-05. 범위는 사용자가 지적한 사전 축약 오류의 수정과 개발셋 영향 검증이다. 신규 특징·모델 학습·2025 예측·공식 제출은 포함하지 않는다. Round 007과 원자료는 읽기 전용으로 유지한다.

- 기술 목표: ±6h/20km 내 모든 적격 관측을 보존하고, 각 시간·거리 조건을 먼저 적용한 뒤 선박 수를 센다. 대표 행은 선택한 조건 안에서만 결정한다.
- 학습 목표: 행을 고르는 연산과 조건을 거는 연산의 순서가 후보 수·라벨·평가를 어떻게 바꾸는지 반례와 실제 변경 목록으로 설명한다.
- 동일 비교: 어구 매핑, 시간의 정수 시간 절삭, 거리식, 원자료 유효성 조건, 기존 CASCADE의 순서·충돌 표시·음성 샘플 seed를 유지한다. CASCADE는 엄밀한 중첩이 아닌 우선순위 목록이다. 신원은 휴리스틱 후보이며 확정 정답이 아니다.
- 주 검증: 좁은 창의 유효 행 복원, 가짜 단일 후보 해소, 중복 행의 unique 집계, 경계 포함, 조건 안 대표 행, 빈 후보와 비포함 조건의 충돌을 합성 회귀로 검사한다. 실제 40조건의 후보 집합은 옛 집합의 상위집합이어야 하고 ±6h/20km 후보 선박·음성 풀은 같아야 한다.
- 영향 산출: 사건별 추가·제거·신원변경·티어변경·충돌변경, 전체 개발셋 규모, 기존 점수 캐시의 새 양성 선박 포괄률을 기록한다. 미포괄 선박을 누락한 평가를 전체 성능으로 보고하지 않는다.
- 결론 규칙: 기존 98건/85척과 이에 의존한 M2~M9는 당시 잠정 후보 기준 결과다. 수정 라벨로 재평가하기 전 유지된다고 단정하지 않는다. 독립 밀도 검산 M10은 연결 수정과 별개다. 작은 주변 백분위 평균차는 조합 특징 성능의 수학적 상한이 아니다. 유의하지 않음은 효과 부재의 증명이 아니다.
- 메모리: 관측은 65,536행 배치로 순차 읽는다. 실행 직전 가용 RAM·예상 최대 증가량·동시 작업·시각을 JSON에 기록한다. 예상 768MiB(배치 DataFrame/시간·거리 배열 및 작은 후보표, 전체 월별 누적 로드 없음)에 1GiB 여유를 요구한다. 부족하면 실행을 보류한다. 재시작 때 새로 확인하며 polling과 사용자 프로세스 종료는 하지 않는다.
- 담당: 부모가 구현·통합, sol_review(GPT-6.1 Sol high)가 독립 계약 검토, astra_decision(GPT-6 Astra high)가 정책 판단을 담당한다. 역할명·요청 설정은 도구의 agent 생성 요청에 남겼다. 부모 세션의 모델을 변경했다는 주장은 하지 않는다.

설명할 질문: 같은 배의 가장 가까운 행이 4시간 뒤에 있을 때, 사고 정각의 유효 행을 지우면 왜 좁은 창에서 경쟁 선박이 사라지는가? 수정 후에도 시공간·어구 단일 후보를 실제 신원 확인과 구분해야 하는 이유는 무엇인가?

## 연결 재계산 후, 점수 재평가 전 고정한 절차

수정 개발셋은 100건/82척이며 기존 점수 캐시에 34척이 없다. 해당 34척만 Round 007과 같은 scorer·참조·leave-self-out으로 추가 채점한다. 학습·점수 규칙 변경은 하지 않는다. 나머지는 원본 점수를 재사용하고 전체 82척을 포함한 뒤 S5를 재실행한다. 해당 추가 로딩/점수 합치기/평가는 각각 직전 가용 RAM을 확인하며 예상 추가 최대 1024MiB 및 여유 1024MiB를 요구한다.

보조 재평가 절차도 결과를 보기 전에 고정한다. 선박별 사고 창은 모든 연결 사건의 ±6h 합집합이다. 무작위 행 선택 null은 선박별 적중확률을 이용한 정확한 Poisson-binomial 꼬리확률로 계산한다. 충돌 사건 제외·다중사건 선박 제외를 각각 민감도로 평가한다. 관측행 수 교란은 동일 표본의 행 수 AUC와 최고점 AUC를 비교하고, 양성 선박별 가장 가까운 행 수의 음성 한 척(중복 없이, ID 동률 정렬)을 매칭한다. 백분위는 사건별 ±6h 창 최대값의 자기 분포 위치(right CDF)와 같은 선박 관측 시작~끝 사이 균등 정수 시각 10개(seed=20261105)의 ±6h 창을 비교한다. 빈 창·결측은 별도 count로 남긴다. 기존 M6의 난수 생성 코드가 없으므로 이 절차는 명시적 재정의이며 원래 수치의 비트 단위 재현으로 부르지 않는다. 어느 보조 결과도 수학적 성능 상한이나 확정 신원 검증으로 사용하지 않는다.

독립 검토 후 명확화: 백분위 평균은 빈 창을 제외한 유효 창 전체 평균이다. 사건마다 유효 무작위 창 수가 달라 사건별 동일 가중치 평균과 다르다. 사건 창·무작위 창의 전체 예정 수와 빈/결측 수를 함께 저장한다. 이 명칭 정정은 수치 계산법 변경이 아니다.
