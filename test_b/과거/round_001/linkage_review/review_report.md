## 판정

**권고: 아직 시각 비교 준비만 가능.** 검토한 연결 후보 30건 모두 `identity_confirmed=false`로 유지한다. 시공간 후보표는 사고 지점 주변의 항적을 찾았다는 근거이며 사고 당사자 신원 확인이 아니다. 사고목록 파일의 개발용 사용 근거가 원문으로 보존되어 있지 않고, 확인된 정상 라벨도 없다. 따라서 현재 자료로 사고 분류 학습·정상 오탐률·사고시각 정확도를 확정 평가할 수 없다.

## 조건

- 기존 감사에서 고정한 아홉 조건(시간 버킷 반경 h=0/1/2 × 중심점 구면거리 반경 1/3/5km)을 재사용했다. 새 후보 조건이나 정답을 사후 추가하지 않았다.
- 기존 단일후보 기준은 `h=1`, `≤5km`다. 여기서 h는 사고시각을 내린 정시 버킷 주변의 시간대 수다. 실제 사고 분·초 기준 ±60분이 아니다.
- 우선 합집합은 E0023, E0042/E0108/E0123, 시간 확장 시 다후보가 되는 7건이며 중복 E0123을 한 번 검토해 총 10건이다. 나머지 기존 단일후보 20건도 같은 표에 포함해 총 30건을 검토했다.
- 기존 `event_audit.csv`, `candidate_vessels.csv`, `baseline_single_review.csv`, `review_queue.csv`와 6개 월별 parquet 캐시를 읽기 전용으로 사용했다. 기존 연결 계산은 재실행하지 않았다. 캐시에서 기존 최소거리 후보의 요약 행 30개만 선택해 RFID/행 시각과 중심점·좌표 수·길이·경계상자 요약을 확인했다. 원 WKT, 부분선 경계는 이 캐시에 없으므로 새로 복원하지 않았다.
- 사고 XLSX에서는 머리글과 기존 단일후보 30건의 대응 원행만 읽었다. 제공 원본 CSV들은 이름 목록만 확인했고 내용을 재파싱하지 않았다.

## 예상

- 후보가 유일하거나 9조건에서 유지되더라도 그것은 신원확인이 아니다.
- 사고선박 수가 2척으로 기록된 사건에서 후보가 한 척이면 한 척만 포착했거나 근처의 다른 선박일 수 있다.
- 시간 범위를 넓히면 일부 단일 후보가 다후보로 바뀔 수 있다.
- 선박 ID·선명·등록번호 대응표가 없으면 선종·톤수만으로 후보를 제거하지 않는다.
- 사고목록에 없는 구간을 정상으로 처리하지 않는다. 좌표별 시각이 없어 속력·가속도를 계산하지 않는다.

## 계산·관찰

- 기존 단일후보 30건 모두 사고 원행(엑셀 행 번호), 후보 RFID, 조건별 후보 관계, 최소거리/시간 행의 캐시 파일·저장 원행 인덱스와 거리·시간 구간을 근거표에 보존했다.
- 우선 10건 가운데 E0023만 아홉 조건 모두 같은 단일 후보 `31005928`을 유지한다. 해당 기준 중심점 거리는 435.9m이며, 원행의 시간대는 사고시각보다 5분 앞서 시작한다. 캐시 요약은 좌표 91개, 궤적 길이 약 3,068.6m, bbox 약 2,353.6m다. 이는 원 항적 형태 요약과 시공간 유사성이지 신원 확인 근거가 아니다.
- 다선박 사고목록과 단일 후보가 만나는 E0042/E0108/E0123의 사고선박수는 각각 2척이고, 기본 후보는 각각 `36011749`, `31704782`, `36006776` 한 척이다. 시간 확장 h=2·5km에서 E0123은 `36010835`가 추가되어 두 후보가 된다. 세 사건 어느 것도 신원 확인 상태로 승격하지 않았다.
- 시간 확장 시 다후보로 바뀌는 7건은 E0046, E0052, E0096, E0109, E0123, E0134, E0136이다. h=2·5km 후보 RFID는 각각 `31001758;36013954`, `31011889;31705247;36001950;36001952`, `36012030;36315137`, `36010190;36012288`, `36006776;36010835`, `32400281;36313865`, `31007124;36015515`다. 일부 후보는 기준 후보의 사고 당사자임을 뜻하지 않는다.
- 30건 중 조건을 바꿔도 같은 단일 후보인 사건은 1건(E0023), h=2에서 다후보가 되는 것은 7건, 사고목록상 사고선박수가 2척인데 기본 후보가 한 척인 것은 3건이다. 이는 이미 저장된 민감도 결과를 선택 우선 사건과 함께 검토한 수치이며 성능 지표가 아니다.
- 캐시 요약 원행 30개를 확인했고 모든 행에서 후보 RFID가 일치했다. 시각 잔차는 `[시간대 시작, 다음 시간대 시작)`과 사고 발생시각 사이의 연결 근거다. 탐지 오차·실제 위치 오차로 쓰지 않았다.

## 해석과 후속 권고

- **신원 확인 근거 수준:** 0/30 확정. 모든 행은 시간·위치 기반 후보 연관이다. 안정적인 E0023도 사고 정답으로 쓰지 않는다.
- **모호성:** 우선 집합에서 다선박 사고 3건, 시간 확장 다후보 7건(중복 E0123), 나머지 단일후보도 조건 민감도와 반복 후보 관계를 보존했다. 단일 후보 개수는 정답 개수가 아니다.
- **결측:** 제공 사고 목록 외의 정상 상태·완전한 RFID 목록·항적 수신 범위에 대한 검증 라벨이 없다. 정상 오탐률, 사고 재현율, 사건별 시간 정확도를 계산하지 않았다.
- **대응 제원:** 조사 범위에서 RFID/선명/등록번호/제원 대응표를 찾지 못했다. 선종·톤수로 후보를 소거하지 않았다.
- **개발/평가 활용:** 실제자료 적합·학습·임계값 조정은 보류. 독립 신원 근거, 사고 파일의 사용 허용 원문, 확인 정상 라벨과 사건/선박 분할이 마련되기 전에는 확정 평가 불가. 현 단계는 A/B/C 입력·계산 절차 준비만 가능하다.

## 재현·실행 기록

- 코드: `run_linkage_review.py`; Python 3.13.3, Windows 11, PyArrow 및 OpenPyXL 버전은 `manifest.json` 참조.
- 최종 실행: 2026-11-05 02:46:06.021 +09:00 시작, 02:46:09.510 +09:00 종료, **실제 종료코드 0**. 최종 stdout/stderr 및 PowerShell 프로세스 기록은 별도 파일에 보존했다.
- 앞선 시도도 숨기지 않았다. 첫 시도는 UTF-8 BOM 포함 Orca 영수증 해석에서 exit 1, 세 번째는 메타데이터 문법 오류로 exit 1, 일곱 번째는 모델 영수증 인덱스가 parquet 입력을 가리켜 exit 1이었다. 각 실패의 stdout/stderr와 종료 기록을 보존하고 원인을 수정했다. 그 외 중간 완료 시도는 exit 0이었으며, 캐시·근거문서의 전후 해시와 원행 값을 포함한 최종 실행도 exit 0이다. 각 stdout/stderr/process 기록은 attempt 번호로 보존했다.
- 최종 실행에서 기록한 모든 입력 파일과 코드의 전후 SHA-256은 동일하다. parquet 6개, 원 사고 XLSX, 기존 감사표·계약·규정근거 문서의 경로·크기·해시는 `manifest.json`에 있다. 디스크 전체를 해시한 것은 아니다.
- Orca receipt의 요청 설정은 **gpt-6-luna / xhigh**다. 현재 세션의 서버 내부 실제 모델 설정은 별도 런타임 계측을 받지 않아 `unknown`으로 기록했다. 부모 실행 모델로 확대 주장하지 않는다.
- 감사·시뮬레이션이 아닌 기존 실제자료 후보표 및 선택 캐시 행을 검토했다. 물리 장치 실험, 사고 탐지 성능 평가, Test 자료 학습은 수행하지 않았다.
