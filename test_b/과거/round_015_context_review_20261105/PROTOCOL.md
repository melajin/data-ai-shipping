# Round015 — 선박 행동·위치 맥락 사례 점검 계약

작성: 2026-11-05  
상태: 정적 출처·범위와 사례 선택 규칙 고정. **원시행 추출은 별도 실행 티켓 및 G0–G3 확인 전에는 시작하지 않는다.**  
선행 기록: `testB/round_014_20261105/SUPERVISED_REVIEW/ROUND014_CASE_REPORT_REVIEW.md`는 Round014 사례 보고서의 근거 한계를 기록한다. Round014 산출물은 본 라운드의 증거로 승계하지 않는다.

## 목적과 학습 목표

**기술 목표:** 사고 연결의 불확실성, 저장 시간의 의미, 좌표·경로 요약의 한계를 드러낸 채 최대 6개 사례의 기준 시간 구간과 같은 후보 RFID의 비교 구간을 정한다. 이후 허용된 경우에만 선택한 개발자료 행의 원시 부분선을 별도로 추출하여 시간 순서·위치 요약을 대조한다.

**학습 목표:** 같은 후보 RFID의 기록에서 관측된 작은 경로량, 시간 버킷의 부재, 위치 패턴을 구별하고, 실제 정지·사고 원인·선박 신원·정상 행동이 자료만으로 확정되는지 설명한다.

## 확인값·가정·미확인 의미

- 출처 설명은 한 행이 선박·일자·`rfid_time` 0–23 시간 버킷의 WKT `MultiLineString`이며 X/Y 축은 경도/위도로 적혀 있다고 한다. 이 설명은 점별 시각을 제공하지 않는다.
- 실제 UTC/KST, 날짜 경계 정의, 정확한 EPSG/datum, 위치오차, 좌표 단순화와 시간 버킷의 물리적 순간 의미는 미확인이다. 저장된 벽시계 기반 시간 인덱스를 보존하고 임의 시간대 보정은 하지 않는다.
- 부분선 내부 경로 길이·상자 범위·좌표 평균은 요약치다. 부분선을 서로 연결하지 않고, 시간행 중심점을 실제 연속 항적처럼 연결하지 않는다. `len_m` 또는 중심점 이동으로 실제 속력·가속도·표류·예인을 계산하지 않는다.
- 관측 시간 키의 차이는 관측 공백이다. 공백을 실제 정지·통신 장애·입항으로 부르지 않는다. 파생 `state`는 사용하지 않는다.
- “같은 RFID”는 데이터 그룹키의 동일성을 뜻한다. 실제 동일 선체·사고 귀속·모항·조업 활동·어구 위치는 미확인이다.

## 사전 고정 사례 선택 규칙

아래 규칙은 기존 메타데이터에서 사례 목록을 만드는 데만 쓰며, raw WKT를 열기 전에 `case_register.csv`와 그 해시를 저장한다.

1. 두 입력은 파서의 선택 열 수준에서만 읽는다. `g2v2_voyages.csv`는 여러 분석 구간 행을 포함하므로 먼저 RFID별 `n_voyages`의 단일 일관성을 확인한 1행 메타 테이블을 만들고, 사고 연결표에 many-to-one으로 붙인다. 중복 구간 행을 사건 행에 직접 조인해 사건 수를 늘리지 않는다. 누락/모순 `n_voyages`를 0 또는 3으로 대체하지 않고 invalid/unavailable로 기록한다.
2. 슬롯마다 각 슬롯의 조건을 먼저 적용한 뒤 `acc_id` 숫자 오름차순으로 스캔한다. 전역 `rfid_id`별 최소 사건을 먼저 뽑아 축약하지 않는다. 선택되지 않은 사건은 다음 슬롯 조건을 만족할 수 있다. 이미 선택된 RFID는 건너뛰며, 슬롯 조건을 만족하는 적격 RFID가 부족하면 빈 슬롯을 그대로 둔다.
3. 고정 슬롯 순서는 다음과 같고, 전체 한도는 6 사건/6개 RFID다.
   - **A, 최대 3:** `conflict=False`, `tier<=1`, 유효한 단일 `n_voyages>=3`인 서로 다른 RFID의 첫 적격 사건.
   - **B, 최대 1:** A에서 미선택 RFID 중 `conflict=True`인 첫 적격 사건.
   - **C, 최대 1:** 앞 슬롯 미선택 RFID 중 `conflict=False`, `tier>=2`인 첫 적격 사건.
   - **D, 최대 1:** 앞 슬롯 미선택 RFID 중 유효한 단일 `n_voyages<3`인 첫 적격 사건.
4. `row_ts`는 Round008이 고른 증거 관측행의 기준 키 H다. 사고 시각을 중심으로 관측을 재선택하지 않는다. 표시 대상은 `[H-12,H+12]`의 저장 시간 키 25개이며, accident timestamp는 평가자 오버레이에만 표시한다.
5. 비교창은 같은 후보 RFID의 Round012 분석 구간 중 `t_end<=H-37`을 만족하는 것만 고려한다. `t_end` 내림차순, `t_start` 오름차순, `voy` 오름차순으로 정렬하고, 목록을 순서대로 보며 겹치지 않는 `[t_end-24,t_end]` 25 키 창을 최대 두 개 고른다. 두 개를 채울 때까지 겹치는 후보를 건너뛴다. 부재 버킷은 결측으로 남기며, 빈약하거나 겹치는 창을 이유로 범위를 늘리지 않는다.
6. 선택된 RFID의 나머지 사건 ID는 오버레이/한계 목록에 보존한다. 비교창에 다른 사고기록이 있어도 창을 바꾸지 않고 오버레이 표시에만 기록한다. 비교 구간은 미라벨이며 확정 정상 구간이 아니다.

최대 표시 규모는 18 패널, 450개 RFID×시간 키다. 사례는 결정 규칙으로 뽑힌 설명용 편의 표본이며 모집단 대표성이나 성능 추정을 제공하지 않는다.

## G0–G3 실행 관문

- **G0 티켓/소유권:** 이 계약 아래 원시행 추출을 시작할 별도 실행 티켓, 실행 Luna worker, 독립 Luna 검산자, Sol 감독자를 기록한다. 티켓은 정확한 원본 경로·case register 해시·ID·기준 키·비교창·허용 열을 명시한다.
- **G1 고정 목록:** 작은 `devset_positives.csv`와 `g2v2_voyages.csv`에서 허용 열만 이용해 슬롯·anchor·비교창 목록을 생성한다. 각 원본/캐시의 경로·파일 크기·수정시각·기존 SHA 출처를 기록한다. 현재 메타가 기존 증거와 다르면 호환성 미확인으로 중단한다. 표본 목록 및 시간/좌표 모드는 raw input 개봉 전에 고정한다. 이 프로토콜은 원본 해시 재계산이 완료됐다고 말하지 않는다.
- **G2 행 추적:** `source_month`와 `source_row_index`의 생성 규칙을 기존 parser에 대조한다. 기존 규약은 UTF-8-SIG, newline 보존, 헤더 제외 CSV 논리 레코드를 0부터 세며 물리 텍스트 줄번호가 아니다. 월별 누계 `source_ordinal`은 기존 파싱 메타의 월별 행수와 대조하며 이 확인을 위해 큰 parquet을 자동 개봉하지 않는다. 기존 대형 실행기를 import하지 않는다. anchor 키/원행 불일치 또는 중복 원행 충돌이 있으면 사례를 보류하고 감독 검토로 보낸다. 중복 시간 키의 모든 원본 레코드를 보존하고 충돌을 숨기지 않는다.
- **G3 자원:** 원시행을 읽기 직전에 KST 오프셋 포함 측정시각, 가용/전체 RAM, 데이터 작업 프로세스 RSS, 동시 계산, 디스크 여유, 추정 최대 추가 RAM을 기록한다. 작업은 한 프로세스·월 순차·CSV streaming으로 제한한다. 직전 기록값으로 메모리 여유를 추정하지 않는다.

### 원시 추출 상한 및 중단 조건

후속 티켓의 `<=1024`는 저장할 선택 원행 누계 상한이며 월 파일 전체에서 훑을 수 있는 논리 레코드 수 상한이 아니다. 전체 순차 스캔 중 만들어지는 모든 단일 논리 레코드는 `<=2 MiB`, 저장되는 WKT 누계는 `<=64 MiB`, 총 좌표는 `<=250,000`, 선택 원행 누계는 `<=1024`를 초깃값 상한으로 삼는다. 어느 상한이든 넘으면 자의적으로 자르거나 표본을 대체하지 말고 중단 후 불가/초과를 기록한다. 표준 `csv.reader`는 전체 레코드를 만든 뒤 길이를 확인하면 단일 거대 레코드의 메모리 상한을 보장하지 못한다. 상한을 보장하는 streaming parser를 검토하고 작은 synthetic fixture로 인용부호·내장 줄바꿈·6월 변형 헤더/행을 사전에 확인한다. 안전한 파서가 없으면 raw extraction을 시작하지 않는다.

보수적 최초 메모리 관문은 `expected_peak + 1024 MiB` 이상 가용 RAM, 그리고 최소 `1536 MiB`다(예상 peak 512 MiB 가정에 시스템 여유 1024 MiB를 더한 설계값). 구현/fixture에서 예상 peak가 512 MiB보다 크면 상향한다. 이는 실측 peak가 아니다. 예상 최대 RAM과 디스크 상한을 만족하지 않으면 작업을 보류하고 chunk/순차 방식 또는 더 작은 표본을 감독 검토에 보낸다. 사용자 프로세스를 종료하지 않고 polling 루프를 만들지 않는다.

## 추출 후 검증 및 해석 한계

독립 검산은 원행키·월·저장 시간 변환·중복/누락·계약된 시간창·부분선 개수와 좌표 수·부분선 불연결·오버레이 분리를 확인한다. `row_ts` anchor 원행이 Round008의 `source_month/source_row_index`와 일치하지 않으면 중단한다. 대상 사고 시각은 raw selection/비교창 선택에 사용하지 않았는지 재확인한다.

결과 보고서는 조건·예상 관찰·실제 관찰·자료 미확인·대안 설명을 기록한다. 저장 경로량이 작게 반복된 경우에도 “정지/표류/사고”라고 자동 명명하지 않는다. 사고 정보가 없는 창을 정상 정답으로 부르지 않는다. 결과의 성능·인과성·실제 운용 가능성을 주장하지 않으며 다음 모델/2025/제출 라운드로 자동 진행하지 않는다. 학습자 설명과 진단 능력은 별도 확인할 때까지 미평가다.
