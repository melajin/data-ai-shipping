## 결과 확인 전 감독 해석 고정

1. §3의 규범 문장인 '대상 항차 제외 나머지 >=10'을 우선한다. 총 항차 >=11이 원시 이력 기준이다. 표의 '<10'은 재현하여 별도 열로 보고하되 실제 적격과 혼동하지 않는다. 창별 유효 항차 기준 나머지 >=10도 별도 집계한다. 교란 분기 시 같은 버킷 유효 참조 >=10을 후속 단계에 적용할 수 있게 자료를 남긴다.
2. 항차 분할은 같은 선박 내 인접 ts 차이 >=6h, 중복키는 Round012와 같은 입력 순서 첫 행 보존. 중복 충돌 수, 비유한/음수 입력 수와 시간 정수 여부를 감사한다. §4의 유한값/len>=1 정의를 임의 변경하지 않는다. 음수 bbox가 실제 존재하면 실행을 멈추고 감독에게 보고한다.
3. §4 h는 항차 시작+w-1부터 끝까지 정수 epoch-hour 전체이다. 관측이 없는 h도 창의 끝이 될 수 있지만 원 관측을 보간하거나 결측 값을 채우지 않는다. 창은 시간 범위 [h-w+1,h]이며 최근 w개 관측행으로 대체하지 않는다. 동률 최소값은 가장 이른 h, 항차 선택 동률은 가장 이른 항차 시작/번호로 고정한다. 관측 시각만 쓰는 별도 민감도 탐색은 하지 않는다.
4. 시각대는 저장 epoch-hour modulo24이며 실제 현지시각이라고 주장하지 않는다. 주간 [06,18), 야간 나머지다. 모든 dev 82척의 유효 항차에서 w별 Spearman(min lin, collapse hour)과 24시간 분포를 산출한다. Tier0-1 선박 부분집합도 기술 통계로 함께 보고한다.
5. §5 사고 관련 항차는 같은 선박의 하나 이상의 정답 acc_ts가 [t_start-6,t_end+6]에 포함되는 항차, 대조 항차는 나머지로 고정한다. 이는 확정 정상 정답이 아니다. 각 항차를 한 번만 세어 ALL 선박 모집단의 두 표본 KS 검정 w별 1회, 가족 크기2 Bonferroni를 적용한다. |rho|>=0.2 또는 KS 보정 p<0.05이면 해당 w는 교란 존재. Tier0-1은 같은 통계를 기술 보고하고 추가 검정 가족을 만들지 않는다. 감독이 결과와 구현을 확인한 뒤 해당 w별 분기를 승인한다.
6. 이 해석은 결과를 보고 변경하지 않는다. 구현 중 모순이 발견되면 프로토콜을 덮어쓰거나 마음대로 바꾸지 말고 ask로 감독에게 질의한다.

## 자원과 검증

- 실행 직전 및 단계 전환 직전에 실제 가용 RAM, 확인시각, 예상 추가 peak, 근거, 동시 실행 프로세스를 기록한다. 이전 값은 승계하지 않는다. 현재 감독 측 19:36 KST 실측은 1311MiB였으나 실행 허가값으로 재사용하지 않는다.
- 가용 <768MiB이거나 작업 예상 peak를 감당하지 못하면 그 메모리 작업은 보류한다. 먼저 정적 점검·문서화 등 독립 작업을 한다. 재개 직전 다시 확인한다. 반복 polling/watch 및 사용자 프로세스 종료 금지.
- 필요한 열만 parquet iter_batches로 읽어 대상82척만 남기고 선박별 순차 처리한다. 동시 데이터 계산 금지. 예상 추가 peak는 512MiB 이하를 목표로 하되 실제 배열/모듈 근거로 산정한다. 전체 parquet 무차별 로딩 금지.
- Python 환경과 의존성은 기존 프로젝트 실행 기록을 우선 사용한다. 원자료·과거 라운드·PROTOCOL 해시를 전후 확인한다.
- 의미 있는 합성 검증: 시간 공백/시간창 대 행창, 6h 분할 경계, 항차 경계 역참조 차단, 품질 조건 각 경계, NaN/len<1, 동률, 10 대 11 항차, 주야간 경계. 실제 계산은 저장된 창/항차와 독립 직접 합산 표본을 비교한다. 코드/합성 검증과 실제 dev 계산을 구분한다.
- §3 dev·2025 항차 수 coverage CSV, §4 항차별 CSV, §5 결과 JSON/CSV, 코드/검증/실행로그, 계약해시, 모델 요청과 실제 확인 가능한 실행 증거를 남긴다. 2025는 기존 파생 항차 수가 있으면 재사용 근거 확인 후 사용하고 없으면 first_results/hourly_scores.parquet의 id와 ts만 청크 집계한다.
- Task 종료 보고: 파일 목록, 행/선박/사건 수, 검증 결과, w별 rho/KS raw·보정p/교란분기, coverage와 부적격 사유, RAM 기록, 미해결 사항을 worker_done으로 보낸다. 비영(0이 아닌) 실행 종료는 성공 처리하지 않는다. 자원 보류는 그 상태로 보고한다.
