# Test B 반복 실험 운영 기준

## 2026-11-06 인계 후 적용할 설계

현재 다음 회차는 [Round013 PROTOCOL](round_013_20261106/PROTOCOL.md)이다. 전체 학습 가능 선박에서 어업별 행동 기준을 만들고, 잠정82척/100사건은 적합과 분리한 탐색 평가에 사용한다. 두 데이터 버전의 계보와 중복을 구분하며, 공식 Test를 학습에 섞지 않는다. 새로운 지표·급변 가설을 다음 회차에 적용하되 이전 결과와 승인된 U/C 비교를 변경하지 않는다.

사용자가 밝힌 최신 정량 채점은 RFID·사고시각만 사용하는 6시간까지 시간오차를 고려한 F1이다. 보조 시각1~3을 추가 적중 기회나 그 자체의 FP로 취급하지 않는다. 미사고 선박에 사고시각을 쓰면 FP다. 연속 오차는 진단에 사용하며 최종 적중/FP 개선을 대체하지 않는다. 아래 초기 코어와 정보 미응답 문구는 이 최신 설계·사용자 설명보다 우선하지 않는다.

## 2026-11-06 회차12까지의 현재 상태

목표인 제출 가능한 성능 개선안은 아직 확보하지 못했다. 현재 결과·코어 구현/미확인·전체 회차 보고서와 기존 기준선 검토 패킷은 [CURRENT_STATUS.md](CURRENT_STATUS.md)에 연결했다. 고정한 내부 주관문을 통과하지 않은 결과를 성공으로 바꾸지 않는다.

두 경쟁 책임자의 최종 반박 검토에서 사후 적중 합집합만으로 임의 통합의 분기 우선순위를 정당화할 근거를 찾지 못했다. 이미 중단한 조건 재탐색과 근거 없는 새 성능 실험을 선정하지 않았으며,공식 규격·확정 사고-RFID 대조 또는 독립적인 분기 선택 근거의 확인이 다음 설계에 필요하다. 사용자에게 원문/대조표 경로를 비동기로 요청했고 아직 답이 없다. 목표 완료나 사용자의 일시정지로 기록하지 않는다. 새 정보가 오면 이전 원본·분모·실패를 보존하는 새 계약으로 이어간다.

기존 Test B 기준선은 새 추론 없이 바이트 사본과 원 점수 대조를 마친 검토 패킷으로 준비했다. 이는 공식 적합성·실제 사고 성능·개선 제출본을 확정한 결과가 아니다. 원본 양식과 CSV를 수정하거나 외부 제출하지 않았다.

## 최신 코어 보충 — 사용자 2026-11-05 지시 우선

어업 유형별 전체 항적 이해 → 항목별 행동 관찰 → 대기와 이상 대안 구분 → 공통/어업별 규칙 → 순차 적용에 따른 후보 변화와 적중률을 함께 다룬다. 아래 초기 시각선택 중심 정의는 이 전체 코어의 보조 성능 측정으로 읽는다. 상세 대조와 관문은 CORE_ALIGNMENT_REVIEW_20261105.md를 따른다.

사용자가 ‘특징을 지운다’를 규칙의 단계적 적용으로 확정했다. 입력 변수 제거 실험으로 임의 전환하지 않는다. 발상 전환 후 성과가 없으면 코어 단계로 복귀하고, 근거가 생긴 개선은 원래 코어와 보충 이유를 함께 기록한다. 적중률은 계속 중요하며, 코어 설명 가능성과 고정 정량 관문을 동시에 평가한다.

사용자는 이 점검 후 실험을 지속하도록 재지시했다. 새 모델·외부수집·전체자동화로 확대하기 전에 관찰 가능한 작은 흐름과 승인된 데이터 범위를 유지한다.

사용자 승인: 2026-11-05. 총괄 판단과 재설계를 반복해 제출 가능한 후보까지 진행한다. 이전 인계문서의 첫 사례 점검 범위는 출발점이며, 현재 사용자는 후속 분석·실험·Test B 추론·제출 파일 준비까지 계속 진행하도록 승인했다. 외부 제출은 별도 요청이 없으므로 로컬 제출 패키지를 만든다.

## 코어

동일 후보 RFID의 과거 위치·반복 행동을 기준으로 평소와 다른 시간 구간을 찾고, 사고 시각과 가까운 후보를 기존 방법보다 잘 선택하는지 확인한다. RFID 신원은 잠정 연결이다. 위치 반복을 어구/모항으로 단정하지 않고 경로량을 실제 속력으로 부르지 않는다.

뼈대: 자료 계약 → 같은 배의 과거·위치 맥락 → 행동 변화 → 후보 시각 → 동일 조건 평가 → 실패 원인 하나를 다음 round에서 개선.

## 성과 기준

- 같은 사건·관측기간·후보 수를 사용한다. 1개 후보와 4개 후보 결과를 섞지 않는다. 공식 제출의 허용 후보 수와 점수 정의를 기존 제공 문서에서 확인한다.
- 내부 핵심 지표는 사건별 ±6h 적중률. 전체 100사건과 Tier0–1, 이력 적격 집합의 분모를 모두 제시한다. 불가 사례를 제외해 전체 성능을 높여 보이지 않는다.
- 비교 기준은 재현 가능한 기존 방법과 동일 후보 수의 사건별 무작위 시각 선택이다. 새 방법의 실용 목표는 기존 방법 대비 절대 +5%p. 이 값은 프로젝트 운영 목표이며 통계 법칙이 아니다.
- 선박 단위 paired bootstrap으로 개선의 불확실성을 제시한다. 무작위 기준은 사건별 확률을 사용하고 동일 RFID의 사건 의존성을 고려한다. 반복 탐색을 숨기지 않는다.
- 이미 여러 번 사용한 dev에서의 개선은 탐색 성과다. 독립 평가자료가 없으면 검증된 일반화 성능으로 주장하지 않는다. 이 조건에서도 탐색 근거·한계·재현 명령을 갖춘 제출 후보는 준비한다.
- 숫자를 높이기 위해 정답 주변에서 후보를 생성하거나, 미래 사고시각·사고좌표를 평소 기준에 넣지 않는다. 사후 시각 국소화와 온라인 조기 탐지는 구분한다. 이번 목적은 제공된 전체 항적에서의 사후 후보 선택이며, 과거 기준 특징은 해당 시각 이전 기록으로 계산한다.

## 방향·실패·운영

- 각 작업은 어떤 후보 선택을 개선하고 무엇으로 확인하는지 설명해야 한다. 직접 연결되지 않는 작업은 축소한다. 감사는 실험에 필요한 최소한으로 끝낸다.
- 매 round에는 기준 방법, 변경 가설, 고정 입력·분모·후보 예산, 실제 결과, 실패 유형, 총괄 결정, 다음 개선 한 가지와 상세 보고서를 저장한다.
- Claude/Gemini의 한도 또는 실행 실패는 같은 명세와 중간 산출물을 GPT에 인계한다. 중간 책임자는 1명 체제도 허용한다. 총괄 역할은 유지한다. 무신호 결과도 기록하며 기준을 사후 낮추지 않는다.
- RAM은 실행 직전에 확인한다. 부족한 작업은 보류하고 작은 분석·청크·순차 작업을 진행한다. 사용자 프로세스 종료와 반복 감시 루프는 사용하지 않는다.
- round1부터 번호를 다시 시작한다. 기존 `과거`는 읽기 전용이며, 새 파일은 모두 `testB/final`에 저장한다.
