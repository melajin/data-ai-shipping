# ROUND021 — 전체 선단 사고시각 선택과 오차 진단

**개발 선박에서 기존 방식보다 더 맞힌 대안이 없어 기존 최고점 방식을 유지했다. 동점·공백 규칙에 의한 시각 적중 개선은 확인하지 못했다.**

전체 **7,372척·3,887,065행**을 같은 고정 함수로 다시 점수화하고, 세 시각 규칙을 라벨 없이 산출했다. 시각 평가가 가능한 것은 제공된 **잠정 연결 82척/100사건**이다. 선박별 시각 진단과 전체 선단 선별 결과를 아래에서 구분한다.

핵심 진단은 **79척에서 사고창 안에 점수가 있었지만 전 기간 최고점이 다른 시각에 있었다**는 것이다. 동점 선택으로 놓친 사례는 0척이다. 이 분류는 잠정 연결을 기준으로 한 결과이며, 사고 관련 점수와 연결 정답의 신뢰도를 별도로 검토할 필요가 있다. 시각 후보 범위를 넓히는 것만으로 개선됐다고 주장하지 않는다.

## 무엇을 확인했나

이번 질문은 기존 최고점 시각이 사고를 놓친 이유가 후보 부재·점수 순위·동점 선택 중 무엇인지, 그리고 소수의 시각 선택 변경으로 ±6시간 적중이 늘어나는지다. 앞선 Round020은 Round018의 저장 학습 모델과 ±6h 구간 합산을 사용했으므로 이번과 모델·선택기가 다르다. Round021은 Round019의 frozen_baseline을 그대로 사용하며 새 학습·새 점수 임계값 선택은 없다.

시각 규칙은 B 기존 최고점, T 정확한 최고점의 가장 긴 연속 관측 구간 중앙, G 최고점 원행의 직전 원행과 1시간 초과 공백이 있으면 그 중앙이다. G의 미관측 시각은 추정 시각이며 실측 위치나 새 관측점수가 아니다. 기존 s_gap과 같은 직전 원행을 사용하므로 동시간 중복 행의 간격 0은 이동하지 않는다.

## 개발에서 선택하고 검증에서 비교

전체 RFID를 고정 SHA256 순으로 나누어 개발·검증 각각 3,686척으로 분리했다. 개발 연결 선박은 50척, 검증 연결 선박은 32척이다. 예측과 분할을 봉인한 뒤 개발 사고시각만 해석했다. 개발에서 B보다 더 맞히는 대안이 있을 때만 하나를 선택하고, 없으면 B를 유지하도록 결정·봉인했다. 검증에서는 B와 선택 규칙만 평가했으며 미선택 대안의 검증 적중은 계산하지 않았다. 선택 규칙: **기존 최고점**.

| 구간 | 규칙 | 적중/연결 선박 | 적중률 [Wilson 95% CI] | 새 적중 / 잃은 적중 | 절대오차 중앙값(h) |
| --- | --- | --- | --- | --- | --- |
| 개발 | 기존 최고점 | 2/50 | 4.00% [1.10%, 13.46%] | 0 / 0 | 760.0 |
| 개발 | 최고점 동점 구간 중앙 | 2/50 | 4.00% [1.10%, 13.46%] | 0 / 0 | 760.0 |
| 개발 | 최고점 직전 공백 중앙 | 2/50 | 4.00% [1.10%, 13.46%] | 0 / 0 | 764.0 |
| 검증 | 기존 최고점 | 1/32 | 3.12% [0.55%, 15.74%] | 0 / 0 | 1165.0 |
| 전체 연결군 | 기존 최고점 | 3/82 | 3.66% [1.25%, 10.21%] | 0 / 0 | 912.5 |

검증의 선택 규칙은 새 적중 0척, 잃은 적중 0척이다. 정확 McNemar 양측 p=1.0000는 참고 수치이며 통과 조건으로 쓰지 않았다. 검증 적중 수 증가를 완화한 내부 개선 후보 기준으로 삼았다. 전체 연결군 합산은 기술적 집계이고 규칙 선택 후 독립 성능 추정으로 사용하지 않는다.

대안이 개발에서 선택되지 않았으므로 T/G의 검증 성능을 계산하거나 기각 판정한 것은 아니다. 아래 검증은 유지한 기준선의 성능 확인이다.

이번에 재측정한 B의 전체 시각 적중률은 **3/82=3.6585%**다. 과거 시나리오의 h=3.66%를 강제하지 않았다. 서로 다른 모델·선택기의 3/82 결과를 이번 계산의 기대 정답으로 고정하지 않는다. 시간 오차는 제공된 정수시간 acc_ts를 기준으로 계산했으며 분 단위 원문 시각을 사용한 실제 채점 구현 재현은 아니다. 중앙 오차는 탐지 해상도가 아니다.

## 왜 놓쳤나 — 잠정 사고창에 대한 진단

| 기존 방식의 분류 | 전체 | 개발 | 검증 |
| --- | --- | --- | --- |
| 유한 점수 없음 | 0 | 0 | 0 |
| 사고창이 관측 범위 밖 | 0 | 0 | 0 |
| 사고창 안 관측 없음 | 0 | 0 | 0 |
| 사고창 안 관측은 있으나 유한 점수 없음 | 0 | 0 | 0 |
| 사고창에 점수는 있지만 최고점이 다른 시각에 있음 | 79 | 48 | 31 |
| 사고창에도 최고점이 있지만 동점 선택으로 놓침 | 0 | 0 | 0 |
| 기존 최고점 시각 적중 | 3 | 2 | 1 |

분류는 선박별 모든 잠정 사고시각의 ±6h 창 합집합에 대해 사전 순서대로 배타적으로 계산했다. ‘점수 순위 실패’는 사고창에 점수 후보가 있어도 전 기간 최고점이 다른 곳에 있다는 뜻이다. ‘동점 선택 실패’는 사고창에도 정확한 최고점이 있었으나 기존 동점 규칙이 다른 시각을 골랐다는 뜻이다. 후보 공백·순위·동점은 알고리즘 진단이며 실제 사고 원인이나 연결 정답의 정확성을 확인한 것이 아니다.

[선박별 오차표](evaluation_001/time_errors_vessel.csv)에는 예측의 최소 시간 오차·진단 분류·선택 규칙 비교가 있다. [사건별 표](evaluation_001/event_errors.csv)는 100사건을 보존하고 관측/최고점까지 최소 오차, 관측 공백 포함 여부와 행별 시간 적중을 기록한다. 한 선박의 예측 하나로 여러 사건을 TP로 세지 않는다. 기준선의 최대 한 사건 배정 TP는 3건, 선택 규칙은 3건이다.

## 전체 선단 선별과 시각을 같은 예측에서 집계

| 구간 | 시각 규칙 | 선박 선별 기준 | 전체 선박 | 제출 C | 연결 선정 A | 선정+시각 적중 H | 미연결 선정 U |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 전체 | 기존 최고점 | 전부 제출 | 7372 | 7372 | 82 | 3 | 7290 |
| 전체 | 기존 최고점 | 최고점≥0.75 | 7372 | 183 | 7 | 0 | 176 |
| 전체 | 기존 최고점 | 반경≥전체 선단 95분위 | 7372 | 369 | 12 | 0 | 357 |
| 검증 | 기존 최고점 | 전부 제출 | 3686 | 3686 | 32 | 1 | 3654 |
| 검증 | 기존 최고점 | 최고점≥0.75 | 3686 | 94 | 4 | 0 | 90 |
| 검증 | 기존 최고점 | 반경≥전체 선단 95분위 | 3686 | 188 | 4 | 0 | 184 |

C는 제출 수, A는 선정된 잠정 연결 선박 수, H는 선정되고 시각까지 맞은 잠정 연결 선박 수다. U는 미연결 선정 수이며 확정 오경보가 아니다. 전체 선단을 읽기만 하고 82척만 예측한 결과가 아니다. 7,372척 모두 시각 예측과 선별 여부를 [전체 예측표](evaluation_001/predictions_with_selection.csv)에 남겼다.

반경 임계값은 전체 선단의 라벨을 보지 않은 선형 95분위 **81.99355308km**다. 세 선별 규칙은 결과를 보기 전에 정했으며 전체/검증 결과 중 가장 좋아 보이는 임계값을 새로 채택하지 않았다.

## 재측정한 시간 적중을 사용한 F1 시나리오

아래는 **검증 선박만**의 A·H·U로 계산했다. a=A/검증 연결수, b=U/검증 미연결수, r=H/검증 연결수일 때 `F1=2pr/[p(1+a)+(1−p)b]`다. 전체 h와 선정 재현율을 곱하지 않고 실제 선정된 선박의 시각 적중 H를 직접 사용했다.

| p 가정 | 기존 전부 제출 | 선택 규칙+전부 제출 | 선택 규칙+최고점 선별 | 선택 규칙+반경 선별 |
| --- | --- | --- | --- | --- |
| 2.27% | 0.001387 | 0.001387 | 0.000000 | 0.000000 |
| 10% | 0.005682 | 0.005682 | 0.000000 | 0.000000 |
| 20% | 0.010417 | 0.010417 | 0.000000 | 0.000000 |
| 50% | 0.020833 | 0.020833 | 0.000000 | 0.000000 |
| 100% | 0.031250 | 0.031250 | 0.000000 | 0.000000 |

이 표는 잠정 연결/미연결 집단의 조건부 분포가 가정한 p로 이식된다는 가정에 따른 기대 개수의 비율이다. 공식 F1이나 2025 Test B 성능이 아니다. 검증 연결 선박 수와 적중 수가 작으므로 시나리오 점추정값만으로 배포를 결정할 수 없다. 전체/개발/검증 및 선정 후 h=H/A는 [집계 CSV](evaluation_001/fleet_selection_counts.csv), 모든 p 시나리오는 [F1 CSV](evaluation_001/f1_scenarios.csv)에 있다.

## 검증과 범위

- [사전 계획](PROTOCOL.md)·[동결](freeze.json)과 점수화 코드·입력 해시를 보존한다. 기존 Round019 최고점·시각·상태·행 수를 7,372척 전수 비교한다. 기존 CSV에는 source_ordinal이 없어 원행번호 자체를 과거 출력과 대조했다고 주장하지 않는다.
- [점수화 요약](execution_001/labelblind_score_summary.json): 유한 점수 3,887,065행, 선박 오류 0건. 동점 중앙으로 시각이 변한 선박 1척, 공백 중앙으로 변한 선박 3072척이다. 변화가 곧 적중 개선은 아니다.
- 점수화 합성 검사 14개와 평가 합성 검사 17개를 통과했다. 합성 검사·코드 검토와 실제 자료 평가를 구분하며, 전체 저장 점수·예측·오차 분류·집계·해시의 독립 검산은 [AUDIT.md](AUDIT.md)에 기록한다. 재계산·정답 평가를 중단 후 임의 반복하거나 결과 후 대안을 추가하지 않는다.
- [선택 봉인](evaluation_001/selection_sealed.json), [평가 무결성](evaluation_001/evaluation_integrity.json)과 메모리 로그를 남긴다. RAM 부족 시 작업을 보류하고 다음 실행 직전에 다시 확인한다. 사용자 프로세스를 종료하지 않는다.
- 전체 2026 참조와 과거 라벨을 재사용했다. 이번 분할은 규칙 선택에서 검증 라벨 유입을 제한하지만 최초 독립 검증은 아니다. 잠정 연결 오류와 미연결 집단의 숨은 사고는 이 평가로 해결되지 않는다.
- 2025/Test A 자료, 새 선박 재식별·ID 연결, 외부 수집, 실시간 운용·공식 제출·실제 장치 실험은 수행하지 않았다. 미관측 시각에 실측 좌표·속력을 생성하지 않았다.

학습 확인: 사고창에 후보가 있는데도 최고점이 다른 곳에 있으면 동점 처리만 바꿔 해결할 수 있는가? 한 선박에 사고가 여러 개이면 예측 하나의 TP를 어떻게 세는가? 전체 h 대신 실제 선정된 선박의 H를 직접 세어야 하는 이유는 무엇인가?
