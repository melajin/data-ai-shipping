# Round021 — 전체 선단 예측과 사고시각 오차 진단

2026-11-06 사용자 승인 ‘해봐’에 따른 후속 실험. 이번 규칙의 결과 확인 전에 고정한다. Round019와 별도 진행된 Round018·020의 과거 결과는 이미 알려져 있다. 재사용 자료의 내부 비교이며 최초 독립 검증이 아니다.

## 범위와 입력

2026년 1–6월 3,887,065행/7,372척을 모두 예측한다. 기존 Round019의 검증된 128개 파티션은 여섯 Round017 원 요약과 해시·건수 대응을 확인해 재사용한다. frozen_baseline.py와 저장 참조를 그대로 호출하고 학습하지 않는다. 최고점·시각·상태·행 수를 기존 Round019 선박별 CSV와 전수 대조한다. 그 CSV에는 원행번호가 없으므로 source_ordinal까지 과거 출력과 대조했다고 주장하지 않는다.

잠정 사고 연결은 기존 devset_positives.csv의 100사건/82척만 사용한다. 제공된 2026 RFID 묶음 및 기존 산출물과의 같은 키 정렬만 허용하며 새로운 신원 연결·재식별·2025/Test A 자료 접근은 하지 않는다. 나머지 7,290척은 미연결 비교군이며 확정 정상으로 바꾸지 않는다. 새로운 파일은 본 Round021 폴더에만 기록한다.

주최 측 회신(사용자가 제공한 텍스트)은 관측 없는 시각의 점수·사고시각 제출, 참가자 판단에 따른 최고점 동점 선택, ±6시간 F1 평가를 허용/설명한다. 2026 사고표는 2025 Test B 정답이 아니다. 별도 메일 원본·채점 구현을 조회했다고 주장하지 않는다.

## 고정 시각 규칙 — 세 가지

- B `baseline`: 유한 점수 최댓값의 원행을 선택한다. 정확한 동점은 source_ordinal 최소, 나머지는 기존 안정 정렬 순서다. 점수 입력은 ts, rfid_time=ts%24, source_ordinal 순으로 정렬한다.
- T `tie_center`: 정확한 최고점의 고유 관측시간을 1시간 간격의 연속 구간으로 나눈다. 고유 시간 수가 가장 많은 구간, 동률이면 시작이 가장 이른 구간을 선택한다. 그 구간의 아래쪽 중앙 관측시간을 제출한다. 근사 동점 허용오차를 추가하지 않는다.
- G `gap_midpoint`: B가 선택한 원행의 **점수 계산 순서상 직전 원행** 시각을 a, B 시각을 b로 둔다. 직전 행이 있고 b-a>1이면 floor((a+b)/2)를 제출하고, 아니면 B로 돌아간다. 직전 고유 시각을 대신 사용하지 않는다. 동일시간 중복 행은 간격 0이므로 이동하지 않는다.

G는 기존 s_gap이 직전 행의 간격을 현재 관측에 귀속하는 점을 이용한 시각 귀속 가설이다. 긴 공백 자체를 사고로 판정하거나 선박별 최장 공백을 새로 찾지 않는다. G 후보 시각과 B 근거 시각을 구분하며 미관측 시각의 실측 좌표·속력·보정 사고확률·새 관측점수를 만들지 않는다. 범위 앞뒤 외삽은 하지 않는다. 전체 기간을 참조하는 사후 분석이다.

## 분할과 개발 선택

전체 RFID마다 SHA256('round021-v1|'+RFID UTF-8)을 계산해 (해시, RFID) 오름차순으로 정렬한다. 0부터 짝수 위치는 개발, 홀수는 검증으로 배정해 각각 3,686척이다. 사건별 분할이나 연결 라벨 층화는 하지 않는다. 예측·분할 및 해시를 봉인한 뒤 사고시각을 평가한다.

개발에서는 B/T/G를 비교한다. 선박당 한 예측이 해당 선박의 잠정 사고시각 중 하나와 ±6시간 이내면 1척 적중이다. 개발 적중 수가 B보다 엄격히 큰 T/G만 후보가 된다. 후보 중 적중 수 최대, 동수면 개발 전체 3,686척에서 B 대비 변경 시각 수 최소, 다시 같으면 T를 선택한다. 후보가 없으면 B를 유지한다. 선택 기록과 해시를 저장한 뒤 검증 사고시각을 해석한다. 구현상 라벨 CSV의 원 문자열을 읽더라도 검증 acc_ts를 선택 이전에 숫자로 해석하거나 집계하지 않는다.

검증은 B와 고정된 선택 규칙만 한 번 평가한다. 선택되지 않은 대안의 검증 사고시각 적중 결과는 계산·보고하지 않는다. 검증 적중 증가면 내부 개선 후보, 동률이면 개선 미확인, 감소면 기각한다. p값은 통과 조건이 아니다. 개발에서 후보가 없으면 ‘개발 단계에서 대안 미선택’으로 결론내며 검증 B 복제 결과를 새 방식 성공으로 표현하지 않는다. 검증 선박 적중률 Wilson 95% CI, 짝지은 얻은 적중·잃은 적중, 정확 McNemar 참고 p를 공개한다.

전체 2026 고정 참조와 과거 라벨 재사용이 있으므로 분할은 이번 규칙 선택의 검증 라벨 유입을 제한할 뿐, 독립적인 원자료·참조 적합·새로운 사고 정답 검증을 보장하지 않는다.

## 오차 진단

선박별 모든 사고창의 합집합을 기준으로 다음 순서로 배타 분류한다: 유한 점수 없음 → 모든 사고창이 관측 범위 밖 → 범위와 겹치나 사고창 안 관측 없음 → 관측은 있으나 유한 점수 없음 → 사고창 안 유한 점수는 있으나 전체 최고점 없음(순위 선택 실패) → 최고점이 사고창 안에도 있으나 B는 놓침(동점 선택 실패) → B 적중. 사건별 오차·관측 공백 포함 여부와 관측/최고점까지 최소 오차도 별도 저장한다. 공백 구간과 사고창의 교차는 기회 진단이며 사고 원인이나 공백 규칙 성공이 아니다.

기준선 전체 82척 오차표는 규칙 선택 봉인 후 작성한다. 개발 대안은 개발 표에서만 다루고, 검증에서 선택하지 않은 규칙의 사고창 비교는 하지 않는다. 100사건의 보조 표에서 행별 ±6h 여부와 최대 한 사건만 연결한 예측 적중을 구분한다. 한 선박의 예측 하나가 여러 사건 창에 들어도 적중 사건은 최소 절대오차, 동률이면 acc_id 순으로 하나만 배정한다.

## 선박 선별과 시각의 통합 집계

고정 선별 규칙은 전부 제출, Round019 최고점≥0.75, Round019 활동 반경≥전체 7,372척의 라벨을 보지 않은 95분위(선형 보간)다. 지표나 임계값을 이번 결과에 맞춰 바꾸거나 새로 조합하지 않는다. 기준선·개발에서 고른 시각 규칙 각각에 대해 전체/개발/검증의 제출 수 C, 연결 선박 선정 수 A, 선정되고 시각도 적중한 선박 수 H, 미연결 선정 수 U=C-A를 직접 센다. A/연결수, H/연결수, H/A를 따로 표시한다. U는 확정 FP가 아니다.

p=0.0227/0.10/0.20/0.50/1.00 시나리오는 a=A/연결수, b=U/미연결수, r=H/연결수로 2pr/[p(1+a)+(1-p)b]를 계산한다. 기존 h=.0366을 곱하지 않는다. 분모가 없으면 미정의로 둔다. 연결/미연결을 실제 사고/정상으로 간주하고 조건부 분포가 이식된다는 미검증 가정의 시나리오일 뿐 공식 F1이 아니다. 실제 선택된 연결 선박의 시각 적중률 H/A를 별도로 공개한다. 선택 효과 평가는 검증 표가 우선이며 개발+검증 합산은 기술적 전체 집계다.

## 실행·검증·산출물

전체 선단 점수화를 숨김 백그라운드에서 실행하고 파티션별 중단 복구를 지원한다. 각 파일 수정 담당자는 한 명이다. 입력/참조/코드의 전후 해시, 2026 기간, 전체 건수, 오류 수, Round019 최고점 재현을 확인한다. 입력·기존 산출물은 수정하지 않는다. RAM은 단계 전환과 큰 작업 직전에 시각·가용량·예상 최대·다른 프로세스와 함께 기록한다. 예상 parent256MiB+worker당512MiB+여유640MiB로 동시 수를 정하고 부족하면 보류/축소한다. RAM 확보 polling이나 사용자 프로세스 종료는 하지 않는다.

예측·시각별 점수·분할·선택 봉인·선박 및 사건 오차표·개발/검증 비교·전체 선별 집계·F1 시나리오·요약 JSON·보고서를 남긴다. 합성 검증과 실제 계산을 구분한다. 실패하면 먼저 후보 시간의 존재, 순위, 동점, 공백 귀속을 구분하며 결과 후 새 규칙을 추가 실행하지 않는다.

학습 목표는 관측 공백의 존재와 사고 근거를 구별하고, 선박 선별 재현율과 선택된 선박의 시각 적중률을 같은 예측에서 계산하는 것이다. 실제 장치 실험·실시간 성능·공식 제출은 이번 범위가 아니다.
