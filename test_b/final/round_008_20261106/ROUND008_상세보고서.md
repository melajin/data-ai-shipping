# Round8 상세보고서 — 부분선 내부 형상 비교는 적중률을 개선하지 못했다

## 결론

가장 긴 적격 부분선의 D/L을 자기 과거와 같은 어업의 과거에 비교하는 가설을 실제 자료로 평가했다. 주평가 Tier0–1 top1은 기존 B0 **2/60**, 자기 기준 S **0/60**, 어업 추가 G **0/60**이다. G 대 B0는 **−3.33%p**, 선박 단위 paired bootstrap 95% 구간은 **[−8.62%p, 0%p]**다. 전체 top1도3/100에서1/100으로 낮아졌다. 사전 고정 네 관문을 모두 통과하지 못했다. 이 방법을 개선 제출안으로 채택하지 않는다.

이번 결과는 ‘관측 형상의 이례성’이 ‘사고 시간 선택에 유용함’과 다르다는 반례다. 코드 검증과 형상 추출의 성공을 사고 탐지의 성과로 세지 않는다. 부분선의 물리적 분리 원인이나 사고 원인을 확정하지 않으며, 이 개발자료에서 검토한 이 가설의 실패로 범위를 한정한다.

## 시작 전 코어와 범위

기술 목표는 어업별 큰 항적 특성을 유지하면서 non-small 관측의 부분선 형상을 순차 판정하는 것이다. 학습 목표는 행 전체 bbox/총경로길이와 개별 부분선 내부 직선성, 관측과 가정, 과거 이력과 사고 정답을 구분해 설명하는 것이다. 구현물은 원행 계보가 있는 geometry_ledger, 단계 상태 장부, 같은 예산의 B0/S/G 예측과 풀, 사건 지표, 자원·해시 기록이다.

관찰할 현상은 유효 형상과 자기·어업 이력이 후보를 얼마나 줄이는지, 어업 조건이 실제 순위를 얼마나 바꾸는지, 그 변화가 적중률에 기여하는지다. 검증은 원키·캐시 대조, 부분선 경계 보존, 고유 좌표, 엄격한 과거, 같은 후보 수, 사고 정답을 읽기 전 예측 저장, 독립 검토다. 설명 질문은 ‘왜 거의 곧은 부분선 여러 개의 행 요약이 굽은 항적처럼 보일 수 있으며, 형상 이례성이 왜 사고 정답은 아닌가?’다.

이번 회차는 코어의 어업별 항적 특성과 항목별 순차 판정을 다룬다. 선로 추종, 항만 식별, 실제 대기·조업 상태, 재개 행동의 별도 판정은 구현 범위 밖이다. 어업은 R3의 제공 Train 코드를 사용했고, 동적 행동 정답을 새로 확보한 것이 아니다. 정상/위양성 정답, 확정 사고 신원, 점별 시각, 실제 시간대와 정확한 CRS는 미확인이다. 본인 학습자용 문서이며 학습자의 설명 능력 성취는 별도로 측정하지 않았다.

## 근거와 고정 설계

R7의 22시간행·101부분선 관찰에서 행 bbox/len과 개별 부분선 직선성이 다름을 확인했다. 그러나 사고 인근 B 사례는 결과를 보고 고른 진단 사례이므로 성능 후보 생성에 쓰지 않았다. 실제 추출은 **82척의 전체 관측 99,677행**을 원자료 ordinal로 선택했다.

각 부분선은 연결하지 않고 원래 좌표 순서로 길이 L과 시작·끝 변위 D를 계산했다. 유한 좌표, 고유 좌표3개 이상, L>0, D/L 범위 조건을 통과한 부분선 중 가장 긴 것을 선택했다. 동률은 원 part index가 작은 것을 썼다. 정보가 부족한 행은 이유와 함께 보존했다. 반경6,371,000m의 기존 haversine 계산 가정을 재사용했으며 점별 속력·가속도를 계산하지 않았다.

판정 규칙은 s0 유효 수치·기존 점수 → s1 non-small(len>100 또는 bbox>100) → s2 적격 부분선 형상 → s3 자기 과거 이력 → s4 같은 어업의 다른 선박 이력이다. 100m는 기존 관측 분기 가정이며 실제 정지 정답이 아니다. 기준 이력은 [t−720,t)에서 유효 s2 24행 이상·3일 이상이다. 현재와 미래는 제외했다. 자기 CDF의 midrank p로 희귀도1−2min(p,1−p)를 계산했다. 다른 같은 단일 어업 선박5척 이상이면 각 선박의 같은 시각 t 이전 분포에서 계산한 희귀도를 선박 균등 평균했다.

S는 자기 희귀도, 기존 점수 내림차순, 시각·ordinal 오름차순이다. G는 자기 희귀도 다음에 어업 희귀도를 동률 해소에 사용한다. 기존 점수는 모든 경로에서 내림차순이다. 자기 후보가 없으면 S는 B0로, 어업 후보가 없으면 G는 S의 실제 풀로 복귀한다. 세 방법은 RFID당 같은 min(4,G 실제 풀 크기) 예산을 썼으며, 실제로 모든82척에서4개씩 선택해 총984예측행이다. 같은 RFID의 여러 사건에 같은 예측 목록을 적용했다. top1은 동일 top4의 rank1이다.

## 실제 자료·자원·계보

제공 CSV1~6월을 순차 스트리밍하고 원 RFID·날짜·시각·ordinal·선정 캐시의 좌표수/길이/bbox/중심값을 대조했다.99,677행을 보존했으며 불일치0, 오류0이었다. 1·5·6월 전체 hash는 R7 기존 값과 일치했다. 2·3·4월 hash는 이번 신규 관측값이다. 원자료 전체의 물리적 정확성이나 정상 상태를 입증한 검사는 아니다.

추출은123.408초, 최대 working set293.72MiB였다. 실제 평가 실행은26.839초, 최대424.60MiB였다. 평가 직전 root 가용 RAM4281.6MiB를 확인했고 보수적 예상 추가1280+여유640MiB를 적용했다. 실행기도 직전에 RAM과 실행 작업을 재확인했다. raw WKT 전체를 메모리에 올리지 않았고 월별 투영·SQLite spool·배치 출력을 사용했다. 사용자 프로세스를 종료하지 않았다.

추출 parquet의 hash는2af19410a858dbc36f7b816c00b93adc19b8b33d5042cfa5a7c81fc82f756c9f, 실제 추출기 hash는a7a6ffed1319b8c75155df2935e11e3ab1c9f1de73f384563d5c6e99f1d1ffdb다. FINAL_CHECK_BINDING은 최종 합성 검사 전후 소스 일치를 기록한다. 실행 소스는 execution_sources_001에 보존했다. 사고 정답을 파싱하기 전 예측·풀을 저장했고, 평가 후 두 파일의 hash가 바뀌지 않았음을 실행 기록에서 확인했다.

## 순차 판정과 어업 추가에서 배운 것

단계별 유지 행 수는 **99,677 → 57,435 → 55,013 → 52,486 → 50,712**, 후보가 있는 선박은82→82→82→80→79척이다. s1에서 작은 경로량42,242행은 이번 분기 밖으로 제외됐다. s2에서 정보 부족2,422행, s3에서 자기 이력 부족2,527행, s4에서 동료 이력 부족1,774행은 유보했다. 이 상태들은 정상·사고 판정이 아니다. 사건창의 단계별 잔존은 ROOT_STAGE_COVERAGE_SUMMARY.json에 따로 집계했다.

G의 실제 s4 풀이 있는79척에서 자기 희귀도 동률 그룹3,264개·동률 후보7,755개였고, 그중3,261그룹은 peer 값이 달랐다. 같은 s4 풀 안에서 peer를 추가했을 때 top1이 바뀐 선박은63/79, top4 집합이 바뀐 선박은61/79다. 전체 S 대 G top1은63/82, top4 선택 목록은73/82에서 달랐다. 어업 정보가 계산에 거의 작동하지 않았다는 설명으로 이번 실패를 돌릴 수 없다. 실제로 순위는 많이 바뀌었지만 적중률 이득이 없었다. 풀 제한과 동률 해소 효과는 구분해 진단했다.

## 구현 검증과 두 경쟁 검토의 조정

검증 중 발견한 writer 첫 행 중복·null schema·기존 점수 역방향, 추출 receipt/API 병합 충돌, 시간키 선절삭·NaN 비교 누락·정확히5%p 경계 오판을 실제 평가 전에 수정했다. 원 실험 가설과 기준은 바꾸지 않았다. 추출·규칙의 작은 합성 검사와 평가14검사는 실제 사건 평가와 분리했다.

Sonnet은 부분선 적격성·최장 선택·엄격한 과거·fallback·공유 예산을 독립 확인했고 최종 검사와 소스 hash 연결을 요구했다. Terra는 실행기·평가기 경계의3개 결함을 구체적으로 찾아 수정하도록 했다. Sonnet의 부분적 실행기 긍정 의견으로 Terra의 반례를 덮지 않았다. 총책임자가 수정 증거를 확인한 후 실제 평가를1회 실행했다. 이 결과도 두 중간관리자에게 독립 검토와 다음 코어 분기 제안을 요청한다.

## 다음 결정

현재 가설은 채택하지 않으며, 같은 결과를 보고 기간·임계값·부분선 통계·score 우선순위를 바꿔 재탐색하지 않는다. 사용자 코어로 돌아가 ‘오래 작은 경로량 뒤 움직임이 다시 나타나는 과정’ 등 아직 다루지 않은 순차 행동이 무엇인지, 해당 질문에 현재 자료가 답할 수 있는지를 먼저 검토한다. 다음 라운드는 두 중간관리자 의견을 비교한 뒤 한 가지 작은 가설과 통과 조건으로 고정한다. 실제 행동 정답이나 항만 정보가 없다는 제약은 유지한다.

제출 가능한 개선 방법은 아직 도출되지 않았다. 새 Test B 추론·제출 파일 변경·외부 업로드·신규 모델 학습은 수행하지 않았다. 원본과 실패 결과를 보존하고 반복 dev에서 얻은 탐색적 근거로 해석한다.
