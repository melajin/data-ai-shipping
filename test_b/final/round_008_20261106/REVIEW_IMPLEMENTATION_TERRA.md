# Round8 구현 경쟁 검토 — 채점 실행 전 수정 필요

**판정: 실제 점수·평가 실행 보류.** 실행기 입력 검증이 검증 전에 소수 시간키를 정수로 절삭하고, 수치 결측 불일치를 놓칠 수 있다. 또한 정확히 +5%p인 결과가 부동소수점 오차로 주관문을 통과하지 못할 수 있다. 진행 중인 원자료 추출을 중단하라는 판정은 아니며, 완성된 추출 산출물 자체의 적합성도 이 정적 검토에서 판정하지 않았다.

## 수정해야 할 사항

1. **시간키 검증 순서 — `run_shape.py:476–485`.** `validate_and_merge_geometry`의 220–231행은 소수 시각을 거부하지만 실제 경로는 그 전에 두 `ts`를 `astype('int64')`로 바꾸므로 `123.5`가 `123`으로 절삭된다. `source_ordinal`도 같은 순서로 캐스팅된다. 원본 열에 대해 유한·정수·범위 및 source-clock 단위를 검사하고 성공한 뒤 변환해야 하며, 실제 runner 진입 경로에서 소수 시간과 소수 ordinal이 실패 영수증을 남기는 합성 반례가 필요하다. 두 입력의 값이 이미 정수인지 실제 산출물에서 확인하면 이번 실행에서 영향이 없다는 제한적 근거가 되지만 일반 검증 계약은 별도로 수정해야 한다.
2. **공유 숫자 대조 — `run_shape.py:243–255`.** `nanmax(abs(c-g))`만 비교하면 한쪽 결측과 다른 쪽 유한값의 차이가 NaN으로 무시되고, 전부 NaN인 경우도 `max_diff > tol`이 거짓이어서 불일치를 통과시킨다. 각 공유 필드에 대해 양쪽 결측 일치 여부와 유한/무한 상태를 명시적으로 비교하고, 양쪽 유한인 값만 허용 오차로 비교한다. 결측-유한 및 전체 결측-유한 합성 반례를 추가한다.
3. **+5%p 경계 — `evaluate_shape.py:644–658`.** hit rate를 나눈 부동소수점 차이를 그대로 `>= 0.05`로 비교한다. 예를 들어 Tier01 5/60 대 2/60은 정확히 +3/60=+5%p이나 이진 부동소수점 차이가 0.05보다 조금 작을 수 있다. 고정 분모에서는 `(G_hits-B0_hits)*20 >= 60`처럼 정수 비교로 판정하고, 정확 경계와 그 아래의 반례를 확인한다. CI·전체 비악화·random 관문은 기존 조건을 유지한다.

`evaluate_shape.py:357–360`은 runner가 라벨 파싱 전에 저장한 예측·풀을 라벨 파싱 후 같은 객체로 다시 쓴다. 코드상 재정렬은 없지만 증거를 더 명확히 하려면 재기록을 생략하거나 저장된 frozen 해시와 최종 예측 파일 해시가 일치함을 검사해 영수증에 남긴다. 이는 위 세 결함과 구별되는 계보 강화 사항이다.

## 확인한 연결과 남는 한계

- `validate_extractor_receipt`는 완료 상태, 명시적 불일치/오류 0, 99,677행, release flag와 parquet manifest 해시를 요구한다. 병합은 RFID/시간 및 ordinal의 각 유일성, 두 키 집합, 3중 키 1:1 병합, 행 수와 원래 순서를 확인한다. 상기 캐스팅·결측 문제를 해결해야 이 검사가 의도한 보증을 제공한다.
- `run_shape.py`는 규칙 결과의 예측·풀·장부와 예측 해시를 사고 CSV 파싱 전에 저장하며 고정 분모 100/82 및 Tier01 60/55를 확인한다. 결과를 먼저 읽어 후보를 정하는 경로는 검토한 실제 runner에 없다. 입력 숫자 시간은 시간대 변환 없는 기존 source-clock 시간키로 유지해야 한다.
- 평가기는 예측을 다시 순위화하지 않고 각 방법의 manifest 단계와 장부 마스크로 실제 풀 및 cap의 무작위 기대를 구분한다. 전체와 Tier01의 G를 섞지 않고 Tier01 G 기대를 주관문에 쓰며, RFID 단위 paired bootstrap을 사용한다. 이는 코드 정적 확인이며 실제 집계 재실행이나 결과 검증은 아니다.

## 코어 시작 점검

1. **대상 코어:** non-small 시간행의 부분선 내부 형상을 같은 선박 과거와 어업 peer 맥락으로 단계별 비교하고 후보와 사고시간 근접성을 함께 평가한다.
2. **범위 밖:** 선로 추종·항만·실제 속력·정상 대기·인과 및 확정 사고 신원은 이 코드로 판정하지 않는다.
3. **기술·학습:** 유효 좌표/부분선 선택, 순차 장부·동일 예산 hit과 peer 동률 영향 기록이 기술 산출물이다. 학습 질문은 행 전체 요약과 부분선 형상의 차이, 관측 결측과 실제 사고가 왜 다른가다.
4. **입력:** 전체 82척의 시간키·ordinal·과거 형상과 Train 어업등록을 쓰며, 정답 사고시각은 후보 고정 후 평가에만 쓴다. 점별 시각·정확 CRS·정상 행동 및 신원 정답은 미확인이다.
5. **관문:** 위 실행기/평가 경계 수정과 합성 반례, 추출 원행 계보·정상 receipt·same-cap·단계 포함을 먼저 확인한다. 이후 고정된 Tier01 G 대 B0 +5%p·선박 paired CI 하한 양수·전체 비악화·동일 Tier01 실제 풀 random 우위를 모두 평가하며 반복 dev 결과는 탐색적 근거로만 해석한다.

**경쟁 검토의 관점:** 추출기의 부분선 적격성과 원행 대조를 우선하는 접근은 실제 형상의 신뢰성 확보에 강점이 있다. 그 검사만으로 runner의 시간키 절삭, 결측 비교, 관문 경계 판정을 검증할 수 없으므로 두 모듈의 통합 경계를 함께 확인해야 한다.
