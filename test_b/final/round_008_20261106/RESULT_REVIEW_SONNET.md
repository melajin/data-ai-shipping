## 1. 독립 재검증 (실행 결과, 코드 재실행 없음)

event_results.csv를 직접 재집계해 전수 일치시켰다: B0=3/100·2/60·7/100·5/60, S=1/100·0/60·5/100·2/60, G=1/100·0/60·4/100·2/60. candidate_ledger.parquet에서 s0~s4 행수(99,677→57,435→55,013→52,486→50,712)와 RFID수(82→82→82→80→79)도 ROUND008_상세보고서 수치와 전수 일치한다. 4개 관문(Tier01 G-B0 top1 −3.33%p, bootstrap CI[−8.62%,0%], 전체100 −2%p, Tier01 random기대 2.2264%>관측0%) 모두 실패 확인.

3개 결정론적 RFID(31001758, 31007500, 31008085)와 보조로 36314076(채낚기, singleton gear) 총 4개×3방법=12건을 pool_manifest의 실제 pool_stage/fallback_reason에 따라 해당 단계 마스크로 직접 정렬해 대조했다 — **12/12 전부 predictions.csv의 선택과 일치**. 36314076의 G는 fallback_reason="s4_empty_use_s3"로 S의 해결 stage(s3)를 그대로 물려받았음도 확인(단일 어업 동료 부재의 올바른 처리).

diagnostics.json의 `peer_tie_activation_within_same_G_s4_pools`도 직접 열람해 확인: s4 pool 보유 79척 중 동률그룹 3,264개, peer값이 실제로 다른 그룹 3,261개, **peer 적용으로 rank1이 바뀐 척수 63/79, top4 집합이 바뀐 척수 61/79**. 이는 내가 1차 구현검토에서 우려했던 "peer가 거의 작동하지 않을 위험"이 기우였음을 실제로 반증한다 — 동료 맥락은 빈번히 작동했지만(80%의 s4-보유 선박에서 순위를 바꿈) 결과는 더 나빠졌다(G top1 0/60 < S top1 0/60=동률, G top4 2/60 < S top4 2/60=동률이나 전체100 top4는 4<5). 즉 이번 실패는 "동료 정보가 비활성"이 아니라 "동료 정보가 활성화됐는데도 사고시각과 무관"하다는 더 강한(그리고 더 정직한) 음성 결과다.

## 2. 커버리지 실패 대 랭킹 실패의 구분

S4단계 자체의 선박탈락(80→79)은 1척뿐으로 무시할 수준이다.

## 3. 5개 코어 점검

1. **코어 해당**: s0→s1→s2→s3→s4 순차 판정이 실제 99,677행 전체에 적용됐고, 자기 과거(own strictpast [t−720,t))·동료(≥5 동일단일어업)가 실제로 분리 계산됨을 위에서 확인.
2. **비코어 명시**: 선로추종·항만·실제정지/재개 라벨은 여전히 미구현, 결과 보고서도 이를 "관측 분기 가정"으로 반복 명시.
3. **학습/기술목표 대조**: 기술목표("같은 예산 B0/S/G 비교")는 달성됐고 수치로 답했다. 학습목표("왜 거의 곧은 부분선 여러 개가 굽은 항적처럼 보이는가")는 R7에서 이미 수치로 답했고 이번엔 "형상 이례성≠사고 정답"이라는 정확히 반대방향 반례를 추가로 확보했다.
4. **입력 가용성**: 1·5·6월 해시가 R7과 일치, 2·3·4월은 신규 관측치로만 기록(과거 일치 주장 없음) — 정직한 범위 qualification 유지.
5. **다음 관문**: PROTOCOL이 정의한 4관문 전부 실패로 기록되었고, 사후에 기간·임계값·집계통계를 바꾸지 않는다는 원칙이 실제로 지켜졌다(보고서 "다음 결정" 절).

## 4. 제안: ONE bounded 다음 질문 — "오래 작은 경로량 뒤 재개(resumption)" 자체를 후보 시각으로

지금까지 R4(개시: 큼→작음 전환), R6(지속: 작음 상태의 길이), R8(형상: 작음이 아닌 관측의 부분선 직선성)은 모두 **작은 경로량 run의 시작 또는 내부**만 후보로 다뤘다. run이 끝나고 **움직임이 다시 나타나는 그 시각 자체**는 지금까지 어떤 라운드도 후보로 채택한 적이 없다 — 이것이 과제가 지적한 "아직 다루지 않은 순차 행동"이다.

- **후보 정의(공통, 결과 비의존)**: Round6 `execution_001/run_registry.csv`(이미 디스크에 존재, 재추출 불필요)에서 `right_confirmed=True`인 모든 run의 `close_ts`(런 종료 직후 관측된 non-small 시각)를 후보 t로 삼는다. 이는 전체 82척·전체 관측기간에서 사고와 무관하게 정의된다.
- **자기 희귀도**: close_ts에서 끝난 run의 `observed_length`를, 그 선박의 **다른** 완결 run 길이 분포(Round6 self_cdf와 동일한 1−2min(p,1−p) 공식, 같은 [t−720,t) 과거 창)에 대조해 희귀도를 매긴다 — 새 공식이 아니라 기존에 이미 검증된 수식을 종료시점에 재적용하는 것뿐이다.
- **어업 추가**: 동일 단일어업 ≥5 동료가 있으면 Round8과 동일한 vessel-equal peer rarity를 2차 동률기준으로 추가한다(동일 수식 재사용, 신규 임계값 없음).
- **공정 비교**: B0는 기존 legacy score 내림차순 그대로, S/G는 해당 run-종료 후보 풀, cap=min(4,G 실제풀), RFID bootstrap(4000, seed20261105), 동일 Tier01=60/55·전체100/82 분모, 동일 4관문(+5%p/CI하한>0/비악화/random초과).
- **커버리지-랭킹 분리 보고를 사전 설계에 포함**: 사건별 "±6h 내 resumption 후보가 1개라도 있는가"(커버리지)와 "있다면 자기/동료 희귀도가 B0보다 나은가"(랭킹)를 처음부터 별도 분모로 보고한다 — 이번 라운드에서 배운 교훈을 다음 설계에 선반영.
- **윈도 누수 없음**: close_ts는 사고시각(acc_ts)과 무관하게 전수 정의되며, 과거 참조는 여전히 [t−720,t) 엄격 과거다. 새 임계값(24행/3일/5동료/100m)은 전혀 바꾸지 않는다.

### 내 제안의 한계 (자기비판)

- **커버리지가 작을 위험**: right_confirmed run만 대상이므로(관측 종료 전 끝나야 함) 사고 직전 run이 right-censored(데이터 끝까지 작음 유지)인 사건은 애초에 resumption 후보가 없다 — 이는 질문 자체의 한계이지 숨길 사안이 아니며, R4/R6/R8과 마찬가지로 "불가 사건"으로 분모에 남기고 B0 fallback으로 처리해야 한다.
- **R6과의 유사성 우려**: "run 길이 희귀도"라는 수식 자체는 R6과 동일하다. 다른 것은 **적용 시점**(run 내부 각 시간 vs run 종료 직후 1개 시각)과 **후보 집합**(매 작은 시간행 vs run당 1개 재개행)뿐이다. R6이 이미 실패했으므로 이 설계도 실패할 개연성이 낮지 않다는 점을 사전에 인정해야 하며, 이 가설도 실패하면 "run 길이/재개 계열 전체"를 코어 질문에서 접고 전혀 다른 관측축(예: 공백 직후 복귀, 반복영역 이탈)으로 넘어가야 한다는 중단조건을 미리 정해야 한다.

### 대안적 시각 하나 (가상의 경쟁안이 아니라, 증거에서 직접 구성한 대안) — 강점/위험

진단적 대안: 새 후보 가설을 추가하는 대신, 이미 저장된 execution_001의 self_rarity/peer_rarity와 event_results의 hit/abs_error를 재추출 없이 교차분석해 "self_rarity가 높을 때(희귀) 쪽과 낮을 때(흔함) 쪽 중 어느 쪽이 사고에 더 가까운 시각과 상관되는가"를 기술(記述)한다. **강점**: 이미 쓴 고비용 형상추출(123초, 99,677행)에서 추가 정보를 뽑아내며, 재추출이 전혀 없다. **위험**: 이는 결과를 본 뒤 상관방향을 찾는 사후 분석이라 "사후에 임계/집계 통계를 바꾸지 않는다"는 PROTOCOL 원칙과 충돌할 소지가 크다 — 실행한다면 반드시 "새 후보 생성 규칙 제안"이 아니라 "왜 실패했는지에 대한 기술적 설명"으로만 한정하고, 그 결과로 self_rarity의 부호를 뒤집어 재채점하지 않는다는 조건을 먼저 박아야 한다. 이 위험 때문에 나는 resumption 제안을 1순위로 유지한다.

## 결론

실제 결과는 재현 확인됐고 구현 결함은 없다. G 채택 불가, 임계값·기간 재탐색 금지 원칙에 동의한다. 다음 라운드는 위 resumption(재개) 후보 가설 1건을 중단조건과 함께 고정할 것을 제안한다.
