# Round8 실제 결과 독립 검토 — 형상 희귀성 미채택

## 판정과 확인한 근거

사건별 결과 CSV를 재집계한 전체 top1은 B0 3/100, S 1/100, G 1/100이고 Tier01 top1은 각각 2/60, 0/60, 0/60이다. 전체 top4는 7/100, 5/100, 4/100이고 Tier01 top4는 5/60, 2/60, 2/60이다. 주관문은 네 조건 모두 실패했다. Tier01 G−B0는 −2/60, paired RFID bootstrap 95% 구간은 약 −8.62%p~0%p이고 G의 Tier01 실제 풀 무작위 기대는 약 2.2264%다. 이 결과에서 G를 개선 후보로 선택하지 않는다.

사건창의 strict s0→s4 후보 존재는 전체 100→83→82→72→71/100, Tier01 60→50→50→41→41/60이다. s4 후보가 사고 시간 근처에 남은 사건이 적지 않은데도 G top1은 Tier01에서 0건이다. 이는 **후보가 존재해도 선택이 맞지 않은 사례가 있다**는 관찰이지, 후보 부족이 전혀 문제없거나 특정 물리 원인이 실패를 일으켰다는 증거는 아니다. G의 실제 풀에는 fallback도 포함되므로 strict 단계 coverage와 실제 방법 coverage는 구분한다.

검토자는 2026-11-06 02:53:00 KST에 가용 RAM 약 4,094MiB, 예상 추가 512MiB와 여유 640MiB를 확인하고 Python 프로세스 목록을 기록한 뒤, 저장 장부에서 필요한 열과 3척만 투영해 확인했다. `31001758`, `31007500`, `31008085` 각각의 B0/S/G 실제 풀 크기·공유 cap=4·계약상 내림차순 정렬과 저장 시각/방법 점수가 모두 일치했다. 이는 표본 검사이며 전 선박의 과거 이력 계산을 독립 재현한 것은 아니다.

82척 전부의 G cap은 4다. `predictions.csv`의 직접 계산 SHA-256 `fd19f3422f8ebcf9227c0515bd8087e4c83291365fb0621befc5355a473cb5ac`과 `pool_manifest.csv`의 `b49cd9758d21f8c966caa0b338c68ef46c01f4d5c2d7aa186d6fa8eeb52f8e8c`는 실행 영수증의 라벨 파싱 전 동결값 및 최종 출력값과 일치한다. 영수증은 규칙·실행기·평가기와 추출 manifest 해시를 기록하고 추출 receipt는 99,677행·불일치 0·오류 0을 보고한다. 수정된 평가기 합성 검사 영수증은 14/14 통과다. 이 검사는 실제 사고 선박의 신원이나 행동 정답을 확정하지 않는다.

실행 결과의 규칙 구현은 코어의 일부다. 어업 코드, 같은 배의 과거, 부분선별 형상, 순차 유보, 사건 단위 비교가 연결됐지만 항로 추종·항만·실제 대기·동적 행동의 진실값과 정상 정답은 없다. peer가 실제 순위를 바꾼 사실은 관측되더라도 사고 적중 개선을 뜻하지 않는다. 반복 사용한 개발셋과 잠정 RFID 연결에서 얻은 탐색 결과로만 읽는다.

## 다음 한 가지: 작은 관측 구간 뒤 조건 변화

이전 onset, 작은 구간 지속, 과거 완료 길이, 정적 부분선 형상의 각 가설은 고정 주관문에서 실패했다. 다음은 새 모델이나 임계값 탐색 없이 **관측된 작은 경로량이 두 시간키 이어진 직후 non-small 조건이 다시 나타나는 시간행**을 하나의 공통 순서로 시험한다. R5의 단계1→단계2 손실 13사건 중 `next_not_small`이 있는 8사건은 이 순서를 관찰할 동기이지만, 사고 창을 보고 고른 분석이므로 정상 기준이나 후보 생성 조건으로 사용하지 않는다. 작은 구간은 실제 정지·대기, 이어지는 큰 경로량은 실제 속력이나 출항이 아니다.

### 고정 후보와 과거 맥락

1. **공통 후보:** 같은 RFID에서 정수 시간키 t−2와 t−1이 각각 관측·유효하고 `len<=100` 및 `bbox<=100`, 현재 t가 관측·유효하고 `len>100` 또는 `bbox>100`이며 기존 score가 유한할 때 t를 후보로 둔다. 세 키가 정확히 연속이어야 하며 공백·무효 기하는 유보한다. 후보는 사건 정보 없이 전체 관측기간에서 만든다.
2. **공통 S:** 해당 후보를 기존 score 내림차순, t·ordinal 오름차순으로 선택한다. 후보가 없는 선박은 유효한 전체 B0 풀로 fallback한다.
3. **어업 맥락 G:** 각 후보 t에 대해 같은 배의 `[t−720,t)` 안에서 세 시간 모두 관측·기하 유효한 연속 삼중항을 분모로, 위의 작은-작은-non-small 전이인 삼중항을 분자로 계산한다. 참조 삼중항의 마지막 키는 반드시 t보다 작다. 자기 참조가 24개 이상·삼중항 끝 날짜가 3일 이상이고 같은 단일 어업의 **다른** 선박 5척 이상도 같은 t의 자기 과거로 이 기준을 충족하면, 자기 전이율을 동료 선박별 전이율에 대해 `p=(동료율<자기율 수 + 0.5×동률 수)/동료 수`로 비교한다. `1−p`가 높은, 즉 해당 어업 peer 대비 자기 이력이 상대적으로 드문 후보를 먼저 두고, 동률은 기존 score 내림차순·시간과 ordinal 오름차순으로 정한다. 이 빈도는 이상 확률이 아니다.
4. **유보와 예산:** G의 계산 가능 후보가 한 개도 없는 RFID는 S의 실제 풀·순위로, S 후보도 없으면 B0로 복귀한다. 1척뿐인 어업, 이력 부족, 관측 공백을 정상으로 처리하지 않는다. 세 방법은 RFID별 G 실제 풀의 크기와 4 중 작은 동일 cap을 적용하며 top1은 같은 top4 목록의 rank1이다. 여러 사건은 해당 RFID의 동일 목록을 공유한다.

전이 빈도에 적합한 참조가 충분한지 아직 알 수 없으므로 이를 성과라고 가정하지 않는다. 특히 후보가 드물거나 전이율이 같은 경우 기존 점수 동률 처리와 fallback이 대부분을 결정할 수 있다. 각 단계에서 입력·유지·제외·유보 수, 조건별 원행 계보, 자기 참조 수/날짜, peer 수, fallback, 사건창 후보 보존과 각 방법의 실제 풀을 남겨 **coverage 손실과 순위 손실을 따로** 확인한다. 인접 키의 관측 상태와 전이율만 설명하며 항만, 어구 위치 또는 대기 원인을 추정하지 않는다.

### 시작 점검과 관문

1. **코어:** 같은 배의 관측 순서와 어업별 과거 맥락을 공통 규칙 다음에 적용해 후보와 이유를 설명한다.
2. **범위 밖:** 선로 추종, 실제 이동 재개·대기, 속력·가속도, 검증된 항만 및 사고 원인은 판단하지 않는다. `non-small`은 단지 두 수치 조건의 부정이다.
3. **기술·학습:** 기존 숫자 장부에서 결과 독립 후보와 이력, 순차 사유 및 같은 예산 예측을 만든다. 관찰 질문은 “공백·조건 변화·실제 행동은 어떻게 다른가?”이며, 기술 검사는 정확한 시간키, 과거 종료 경계, 자기 제외 peer, 정보부족 fallback, 동점과 동일 RFID 예측 공유를 확인한다.
4. **입력:** 기존 시간별 len/bbox·score·ordinal, R3 개발용 어업 코드와 잠정 사건표를 사용한다. 정상 행동·점별 시각·정확 CRS·원 시간대·확정 사고 신원 및 제출 대상의 어업 코드 가용성은 미확인이다. 사고표는 예측 동결 후 평가에만 사용한다.
5. **다음 관문:** 전체 100건·Tier01 60건의 사건별 ±6시간 top1/top4와 각 실제 풀의 같은 예산 random 기대, RFID paired bootstrap을 보고한다. 주관문은 G−B0 Tier01 top1 **+5%p 이상**, CI 하한 >0, 전체 top1 비악화, Tier01 G가 해당 풀의 random 기대 초과를 모두 요구한다. 결과는 반복 dev 탐색으로 제한한다. 후보가 너무 적거나 이력이 부족하면 관측 부족과 순위 실패를 기록하고 다른 한계로 복귀하며 문턱을 사후 변경하지 않는다.

경쟁 가능한 방향으로 정적 형상 분기를 더 정교하게 만드는 접근은 이미 71/100 사건의 인근 후보가 남은 장점을 활용할 수 있다. 다만 현재 분석에서 형상 후보가 남아도 최상위 선택이 실패했고, 결과를 본 뒤 부분선 통계나 백분위 우선순위를 다시 조정하면 반복 dev 선택 편향이 커진다. 제안한 순서 역시 개선을 보장하지 않지만 기존 형상 장부의 숫자 입력으로 아직 직접 측정하지 않은 관측 흐름을 검증한다.
