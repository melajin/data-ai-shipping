# 코어 정합성 점검과 설계 제안

## 검토 근거와 현재 상태

사용자 최신 코어 지시 및 추가 결정, docs/fishing_execution_plan.md, round_001_20261105/ROUND001_상세보고서.md, round_002_20261105/PROTOCOL.md와 CONTRACT.md를 대조했다. 기존 문서와 구현은 보존한다. 본 문서는 코어 전체와 보조 시각선택 실험의 관계를 명확히 하는 추가 기록이다.

사용자 확정: ‘특징을 하나씩 지운다’는 입력 변수 제거가 아니라 **판정 규칙을 차례로 적용하며 후보가 좁혀지는 과정 관찰**이다. 기존 승인 U/C는 별도의 위치 조건 유무 비교로 유지한다.

Round2는 구현 완료 보고를 받았다. Luna는 입력·평가·runner 및 작은 합성 확인을, Gemini는 특징 모듈 및 합성11조건 통과를 보고했다. 이는 작업자 보고이며 총괄의 실제자료 통합 실행 또는 독립 검산 결과가 아니다. 실제 dev 실험·Test B 재추론·새 제출물 변경은 아직 하지 않았다.

## 1. 이번 작업과 코어의 관계

| 코어 | 현재 작업과 일치하는 부분 | 현재 부족하거나 다른 부분 |
|---|---|---|
| 어업 유형별 전체 항적 특성 | 기존 프로젝트에 조업 분류 자료와 실제자료 평가 이력이 있음 | 새 final round1/2에는 연안복합·통발·자망·채낚기별 항적 요약과 유형별 기준이 없음 |
| 항목별 행동 관찰 | Round2가 과거 경로량·공간 범위의 차이를 관찰 | 기존 선로 따르기·직진·작은 이동의 연속·재이동 순서가 구현되지 않음 |
| 대기와 이상 구분 | 반복 위치 조건에서 같은 작은 경로량의 의미가 달라질 가능성을 검토 | 항만 여부·어업별 정상 대기·대기 중 움직임을 구분하지 않음. 각도격자는 항만이 아님 |
| 공통 기준과 어업별 추가 기준 | 동일 RFID 과거 비교는 공통 관찰의 일부로 활용 가능 | 어업 유형을 입력하지 않고 유형별 조건도 분리하지 않음 |
| 규칙을 단계 적용해 후보 좁히기 | U/C의 조건 유무 비교는 보조 진단으로 남길 수 있음 | 단일 점수 최고시각 선택은 규칙별 후보 변화와 판정 이유를 보여주지 않음 |

**Round1 계보 감사는 준비 단계다. Round2의 위치 조건에 의한 시각 선택 개선만으로 행동 유형·단계적 이상 탐지 코어를 구현했다고 간주하지 않는다.** 이전 총괄이 시각 적중률 개선을 작업의 중심으로 좁힌 점을 수정한다. 승인된 수식·비교·+5%p 운영 목표는 변경하지 않고 적용 범위를 보조 실험으로 명시한다.

## 2. 관련이 적거나 다른 문제를 다루는 부분

상위1/4시각의 적중률·무작위 기대·bootstrap은 후보 시각의 품질을 평가한다. 행동 유형 구분, 대기 오인 방지, 어업별 설명 가능성의 증거를 대신하지 못한다. 로더·해시·계보 감사도 신뢰를 위한 수단이다. 이 작업들만 반복하는 것을 코어 진척으로 세지 않는다.

## 3. 다음 단계 제안 — 작은 관찰·판정 전체 흐름

다음 회차는 새로운 모델 없이 **어업 유형별 항적 요약 → 관찰 항목 → 공통 규칙 → 위치·대기 맥락 → 어업별 추가 규칙 → 남은 이상 후보와 설명**을 작은 사례에서 연결하는 설계를 먼저 만든다. 즉시 전체 시스템을 자동 완성하지 않는다.

- 기술 목표: 확인된 어업 그룹과 관측 가능한 행동 항목을 연결하고, 규칙 단계별 후보 변화표를 만들 수 있는 입력·출력 계약을 확정한다.
- 학습 목표: 같은 작은 이동이 어떤 경우에 대기·정보 부족·낯선 행동으로 다르게 해석되는지, 공통 규칙과 어업별 조건이 왜 다른지 설명한다.
- 구현물: 어업 라벨/신원/원행 연결 가용성 표, 유형별 작은 항적 관찰표, 관찰항목 정의표, 공통·어업별 규칙 목록, 단계별 후보 장부 설계. 장부에는 적용 전 후보, 추가 조건, 유지/제외/판단유보, 이유, 대안 설명과 근거를 남긴다.
- 관찰 현상: 반복 방문·기존 관측 경로와의 차이, 부분선 내부 형태, 연속 시간키의 작은 경로량, 이후 관측에서의 이동 재개, 관측 공백. 실제 연속 정지와 같은 말로 바꾸지 않는다.
- 검증: 관측값과 가정을 구분하고 원행을 추적한다. 같은 규칙을 차례로 적용할 때 후보가 왜 달라지는지 확인한다. 대기 가능성·항만 미확인·자료 공백으로 인해 유보된 사례를 기록한다. 사고 주변이라는 이유로 사례를 골라 정상 기준을 만들지 않는다.
- 설명할 질문: 왜 이 관측을 이상 후보로 남겼는가? 동일 행동을 다른 어업에서는 어떻게 해석할 수 있는가? 어느 규칙 때문에 후보가 줄었는가? 항만 자료가 없을 때 무엇을 유보해야 하는가?

위치 조건 U/C는 위 흐름의 ‘과거와 다른가’라는 항목에 들어갈 수 있는 보조 모듈이다. 완성된 코드의 존재만으로 그 역할이 검증된 것은 아니다. 순차 규칙 흐름과 연결한 다음, 기존 승인 프로토콜의 실제 실험을 수행할지 판단한다.

| 항목 | 확인 상태 | 설계에 미치는 영향 |
|---|---|---|
| 시간별 경로량·bbox·중심좌표·기존 점수 | 파생 Parquet footer와 schema 확인, 전체 행 내용은 새로 재계산하지 않음 | Round2 수식 입력 가능성과 실제 품질 검증을 구분 |
| 어업 라벨 | 실행 계획에 Train 조업 정답과 기존 분류 실험 이력 있음. 현재 Round2 정규 입력에는 어업 코드가 없음 | 원래 라벨과 현재 RFID/행을 연결할 수 있는지 확인 필요. 사고표의 어업면허를 Test B 선박 정답으로 대체 금지 |

| 정상/대기 정답 | 독립 근거 미확인 | 대기 오인률이나 확정 사고 F1을 임의 산출하지 않음 |

## 5. 다음 단계로 넘어가는 관문

관련 어업 그룹의 라벨·원행 연결이 확인되거나 미확인 사유가 명시돼야 한다. 작은 사례에서 관찰 항목을 실제 입력으로 계산할 수 있어야 하며, 계산 불가 항목은 유보해야 한다. 공통·어업별 규칙과 순서가 별도 표로 정리되고, 대기 가능성과 관측 공백을 사고로 자동 처리하지 않아야 한다. 단계별 후보 변화와 이유를 설명할 수 있을 때 실제자료 비교 범위를 확장한다.

## 발상 전환과 코어 보충의 운영 규칙

매 회차 시작에 ①코어 어느 부분 ②다른 문제를 다루는 부분 ③기술·학습 목표/구현물/관찰/검증/질문 ④확인된 입력과 미확인 ⑤다음 관문을 적는다.

발상을 바꾸는 경우에는 해결할 코어의 빈틈, 변경 한 가지, 평가 기준, 실패 시 복귀할 코어 단계부터 기록한다. 의미 있는 근거가 나오지 않으면 같은 방향의 복잡성만 늘리지 않고 결과를 보존한 뒤 해당 코어 단계로 돌아간다.

코어 보충은 가능하다. 새 항목이 기존 질문에 어떻게 답하는지, 실제 데이터로 관찰 가능한지, 대기 오인이나 설명의 어떤 빈틈을 줄이는지 근거를 남긴다. 기존 코어 문장을 지우지 않고 보충 전후와 이유를 기록한다. 근거가 약하면 제안/가정으로 유지한다. 목표·라벨 의미·승인 범위 자체를 바꾸는 결정은 사용자 지시와 구분한다.

계산 횟수나 시각 적중률만으로 성과를 선언하지 않는다. 기존 정량 운영 목표는 보조 성능 관문이며, 행동 유형·대기 대안·단계별 이유를 설명하는 코어 관문을 함께 충족해야 한다.
