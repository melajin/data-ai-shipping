# Round018 독립 사전 검토 기록

## 범위와 실행 설정 근거

- 검토 작업 식별자: `/root/contract_review`.
- 요청 역할·모델·effort: `sol_review`, GPT-6.1 Sol (`gpt-6.1-sol`), **high**. 생성 작업의 수신 메시지는 이 작업을 `/root/contract_review`로 지정했고, 부모가 요청한 Sol high 검토 범위를 전달했다. 모델 런타임 내부 설정을 별도로 계측한 것은 아니며, 저장된 설정으로 부모 세션 모델이 변경됐다고 주장하지 않는다.
- 검토 대상: `PROTOCOL.md`, `evaluate.py`, 기존 `frozen_baseline.py`와 입력 생성 코드의 계약, 지정된 Parquet footer/schema, 정답 CSV 헤더.
- 기존 파일 수정 없이 독립 코드 검토와 작은 합성 경계 검사만 수행했다. 이 문서는 검토자에게 별도 소유권이 지정된 새 파일이다. 다른 작업자의 수정은 보존했다.
- 실제 입력 데이터 행이나 실제 평가 결과를 계산·검토하지 않았다. 실행 중인 Round018 출력은 열지 않았다. 2025 테스트·F: 자료·외부 자료·추가 ID 매핑을 읽지 않았다.

## 사전 발견사항과 수정 확인

1. **기존 고정 기준선의 입력·참조 계약:** fleet Parquet에는 `rfid_time`이 없지만 기존 scorer는 이를 요구했다. 기존 집계 밀도는 contributor membership이나 leave-self-out 보정을 제공하지 않았다. Round018 최종 설계는 기존 scorer/참조를 실행·재사용하지 않고 세 가지 점별 기하값으로만 학습하므로 이 참조의 자가포함 문제를 새 모델에 가져오지 않는다. 제공된 기준선 3/82만 비교값으로 유지한다.
2. **빈 학습선박 제외:** `build_training`의 활성 그룹 조건이 딕셔너리 길이 대신 `len(group["ts"])`를 사용하도록 수정된 것을 확인했다. 빈 그룹을 넣은 합성 검사에서 후보가 있는 선박만 V와 가중치 계산에 포함됐다.
3. **정수 입력 계약:** 정수 시간·순번을 검증하지 않고 `int64`로 변환하면 잘못된 실수값을 조용히 절삭할 수 있음을 지적했다. 수정 후 각 Parquet의 필수 필드 스키마를 정확한 string/int64/double 타입과 대조하는 검사를 확인했다.
4. **경로와 동결 manifest:** 지정 경로의 resolve 결과가 프로젝트 내부 실제 파일인지 검증하고, 동결 manifest의 키 집합이 지정 파일 목록과 정확히 일치하는 검사를 확인했다. 추가 입력 경로를 인자로 받지 않는다. 직접 확인한 Round018 디렉터리, fleet execution 디렉터리, 정답 CSV에는 reparse-point 표시가 없었다.
5. **목적함수의 클래스 조건:** 전체 학습 라벨이 한 클래스인 경우 실행을 거부하는 검사를 확인했다. 선박별 한 클래스만 있는 경우의 가중치 규칙과 전체 학습의 두 클래스 요건은 구분된다.
6. **RAM 보류와 한 번 실행:** 실행 폴더 생성 뒤 RAM 부족을 `deferred`로 기록하지만 같은 폴더로 자동 재개할 수 없다는 동작을 프로토콜에 명시하도록 요청했다. 최종 프로토콜은 폴더 생성 전 보류는 같은 동결 코드로 재호출 가능하고, 생성 후 보류는 증거를 보존한 채 종료하며 자동 재개·덮어쓰기를 제공하지 않는다고 명시한다. 메모리 보류는 평가 완료로 세지 않는다. 이후 재개에는 새 RAM 확인과 평가 전 증거 보존이 필요하며, 규칙·하이퍼파라미터 변경 또는 결과가 나온 평가의 재시도는 허용하지 않는다.

## 코드 계약 검토 결과

- heldout 선박의 모든 관측과 모든 사건은 해당 fold의 학습·중앙값/IQR 정규화에서 제외된다. ID·좌표·시간·기존 점수·행 전이·선박별 이력 통계를 특징으로 사용하지 않는다.
- 세 log1p 입력, 학습 자료의 linear percentile, 0 IQR 대체, clipping, 9개 2차 특징, ridge logistic 목적함수와 analytic gradient가 프로토콜과 일치한다. 가중치 총합은 1이며 선박별 총량과 클래스별 배분 규칙을 따른다.
- top-1은 반올림 없는 로짓 최대값, 최소 `source_ordinal`, 최소 `ts` 순으로 정한다. 동일 시각의 여러 행은 후보로 보존한다.
- 정답 시각은 `row_ts` 대신 `acc_ts`를 사용한다. 선박별 오차는 모든 제공 사건에 대한 최소 절대 오차이며, ±6시간 경계는 포함한다. 후보 없음은 실패 예측으로 남고 82척 분모를 유지한다.
- 우연 모델은 관측된 고유 시간의 균등 선택이다. 다중사고 ±6시간 창은 합집합으로 처리하여 중복 계산하지 않는다. 행 균등 기대는 보조 기록으로 분리된다. Poisson-binomial 단측 꼬리와 가능한 기준선 겹침 전체의 최대 단측 p 계산을 확인했다.
- 예측 82개를 저장·해시한 뒤 적중 지표를 평가한다. 신규 execution 디렉터리와 배타적 파일 생성으로 덮어쓰기를 막고, 동결 파일 해시는 전후 확인한다.
- 개발셋 재사용, 중첩 LOOV 학습, 잠정 연결 정답의 한계가 프로토콜에 명시돼 있다. 명목 p값을 새 독립 평가의 유의성·공식 F1·실시간 탐지 성능으로 해석하지 않는다.

## 독립 합성 검산

`selftest()`는 파일을 쓰므로 호출하지 않았다. 모듈의 계산 함수를 작은 합성 배열에 직접 호출하고, optimizer 호출을 가로채 목적함수 기울기를 별도로 검산했다. 실제 자료를 로딩하지 않았고 합성 검사 결과 파일도 생성하지 않았다.

- 다중사고의 포함 경계와 창 합집합.
- 최고점 동점의 source ordinal 및 timestamp 순서.
- 최악 겹침 검정에서 H=9는 p>0.05, H=10은 p≤0.05인 경계.
- 확률 0과 1을 포함한 Poisson-binomial 경계.
- 빈 학습선박 제외와 선박·클래스 균형 가중치 총합.
- 빈 heldout 후보의 예측 처리.
- ridge logistic analytic gradient와 중앙 유한차분 비교: **최대 절대 차이 1.1396690535736553e-10**; 허용 오차 1e-8 이내.

위 검산은 통과했다. 이는 코드·계약 검증이며 실제 2026 성능 평가가 아니다.

## 사전 검토 결론

최종 수정 확인 시점에 동결을 막을 미해결 발견사항은 없었다. 이 결론은 사전 코드·계약 검토 범위에 한정되며, 실행 성공·실제 적중률·모델 채택을 확인한 진술이 아니다. 실제 실행 결과는 이 문서 작성 과정에서 열람하지 않았다.
