# Round021 — 전체 선단 내부 F1과 판단 절차

## 이번 목적

사용자는 공식 채점 세부식이 미확정이어도 가정을 밝힌 F1 수치를 제시하고, 보고서의 근거를 단순 수치 산출보다 **어떻게 판단하는가**에 두도록 요청했다. 이번에는 새 모델·임계값 탐색을 하지 않고 기존 전체 선단 산출물을 동일한 정의로 집계한다. 성능 합격/기각 실험이 아니라 재현 가능한 내부 진단과 판단 절차 문서화다.

F1 자체는 정해진 식 `2TP/(2TP+FP+FN)`이다. 미확정인 것은 공식 사고 매칭과 시간오차 반영 방식이다. 아래는 **2026 잠정 사고 연결을 기준으로, 미연결을 평가상 음성으로 두는 가정의 내부 F1**이며 공식 Test B 점수가 아니다. 알려진 Round019 비교 결과를 사용한 사후 기술통계이고 독립 검증이라고 주장하지 않는다.

## 입력과 고정 비교 규칙

입력은 Round019 `execution_001/vessel_peaks.csv`의 7,372척 요약과 Round008 `devset_positives.csv`의 제공된 100사건/82척이다. 이 둘의 제공된 RFID 묶음을 평가에 대조하며 새 연결·재식별은 하지 않는다. 설명 사례의 관측 근거만 Round017 `execution_001/hourly_01..06.parquet`에서 읽는다. 2025·F:·외부 자료는 읽지 않는다. 기존 실행 폴더와 자료를 수정하지 않는다.

세 규칙을 미리 정하고 새 결과에 따라 대표를 바꾸거나 최적 임계값을 고르지 않는다.

1. **주 비교:** 유한한 peak_score≥0.75이며 유효한 peak_ts가 있는 선박. .75는 Round019의 기존 대표 비교 기준으로, 검증된 운영 사고판정 임계값은 아니다.
2. **참고:** 유효한 점수·시각이 있는 전 선박 선정.
3. **검토 우선순위 참고:** 유한 활동 반경이 전체 유한 반경의 선형보간 95분위 이상이고 유효한 점수·시각이 있는 선박. 기존 Round019 대표 규칙이며 반경 자체는 사고 근거가 아니다.

모든 규칙에서 사고 후보시각은 동일한 저장 `peak_ts`다. 양성 82척에만 존재하는 Round020 시각을 섞지 않는다. 기존 참조를 사용하는 저장 점수의 감사·집계만 수행하며 지역 사전확률을 새로 만들거나 적합하지 않는다. 상속한 기준선에는 자기 선박의 밀도 기여를 제외하는 구현이 없고 원 참조 구성원도 확인되지 않았으므로, 올바른 LSO 또는 독립 표본 성능이라고 주장하지 않는다.

## 실제 정답 대조와 분모

전체는 7,372척, 잠정 연결은 82척, 미연결 비교군은 7,290척이다. 미연결 선박의 사고 부재는 확인되지 않았다. 계산상 음성 가정과 사실상 정상 판정을 분리한다. 누락·유보 선박을 분모에서 빼지 않는다.

- **선박 선정 F1:** 선정된 잠정 연결 선박 수가 TP, 선정된 미연결 선박 수가 FP, 미선정 연결 선박 수가 FN이다. 선정 수 K이면 `F1_vessel=2TP/(K+82)`.
- **주 시각 포함 사건 F1:** 선정한 선박의 저장 peak_ts와 같은 선박의 제공 사건 중 최소 절대 시간차가 6시간 이하면 사건 하나만 TP로 매칭한다. 같은 최소 오차는 acc_id 문자열 순으로 해소한다. 예측 하나가 복수 사고를 맞혔다고 중복 집계하지 않는다. TP=매칭 사건 수, FP=K−TP, FN=100−TP이며 **`F1_event_time=2TP/(K+100)`**다. 시각이 틀린 연결 선박의 예측도 FP이며 그 사건은 FN으로 남는다.
- **보조:** 선박당 제공 사건 하나만 맞히면 성공으로 보는 시간 포함 F1은 `2TP/(K+82)`로 별도 명명해 JSON에 남긴다. 사건 100건 기준 주 F1과 섞지 않는다. 기존 h=0.0366을 곱하는 시나리오로 실제 TP를 대체하지 않는다.
- 시각은 기존 정수시간 `acc_ts`와 `peak_ts`를 직접 비교한다. 이는 **시간 단위로 양자화된 내부 ±6h**다. 분 단위 발생일시나 미확인 시간대를 임의 보정하지 않는다. 공식 감점식·정확한 분 단위 경계와 같다고 주장하지 않는다.

규칙별 K, TP/FP/FN, precision, recall, 두 주 F1과 유보 수를 함께 저장한다. 성능 수치를 맞추기 위한 정답·분모·예측 수정은 없다.

## 자동 출력과 사람의 판단을 분리

주 규칙의 자동 출력은 **검토 후보 / 고정 기준상 미선정 / 입력 부족으로 판단 유보**다. 검사 결과를 확정 사고·정상 라벨로 바꾸지 않는다. peak_ts는 검토할 후보시각이다.

사람이 검토할 사항은 입력 신뢰성, 최고점·95분위·중앙값의 관계, 실제 관측 유무와 전후 기하 요약, 관측되지 않은 시간, 상태명의 의미, 가능한 대안 설명, 시각 근거의 범위다. 상태나 공백으로 새 자동 제외 규칙을 만들지 않는다. 실제 GPS·속력·사고 원인·동료나 날씨 영향은 근거 없이 단정하지 않는다. 사람의 최종 검토를 아직 수행하지 않은 단계는 완료했다고 표시하지 않고 F1에도 섞지 않는다.

주 규칙 기준으로 설명 사례는 다음 5종에서 RFID 문자열 오름차순 첫 사례를 뽑는다. 빈 분류는 없다고 기록한다: 선정·연결·시각 적중, 선정·연결·시각 불일치, 미선정·연결, 선정·미연결, 미선정·미연결. 이는 결과를 이해하는 사례 추출이며 예측 규칙을 바꾸지 않는다.

각 사례는 저장 peak_ts 전후 ±24시간의 **관측된 행만** 모아 시간별 관측 수·부분선 길이·bbox·중심점 범위 등을 설명한다. ±24h는 고정 설명 범위로, 탐지창 최적화나 사고 정답 창이 아니다. 전후 관측이 없으면 없다고 쓴다. peak 시각보다 엄격히 이른 시간의 실제 행 수도 기록하지만, 동일 시간에서 먼저 처리된 행은 빠진다. 저장 요약에 peak source_ordinal이 없으므로 이 수를 모델의 정확한 과거 이력 수로 표현하거나 24행 이력 조건 충족 여부의 완전한 검증으로 쓰지 않는다. 전체 n_rows도 peak 이전 이력으로 대체하지 않는다. 관측 공백을 선으로 연결하지 않는다.

## 실행·검증

새 Round021 폴더에만 산출물을 생성한다. 프로토콜과 코드·입력 해시를 먼저 고정하고 실행 후 해시를 다시 확인한다. 전체 7,372척에 세 규칙을 동일 적용하고 정책별 선정 목록을 저장한 뒤 사건을 대조한다. 원자료·기존 실행은 보존한다.

실행 전 가용 RAM, 예상 최대 512MiB, 여유 640MiB, 다른 Python 프로세스와 확인 시각을 기록한다. CSV는 작고 사례 항적은 32,768행 단위로 순차 읽는다. 부족하면 보류하고, 메모리 확보 polling이나 프로세스 종료는 하지 않는다. 학습·추가 대형 점수화는 없다.

합성 검증은 일대일 사건 매칭, 다중사고의 FN 보존, 틀린 시각의 FP+FN, 선정 없음, 6시간 경계, 미연결 예측, 선박/사건 분모 차이를 확인한다. 저장 결과는 독립 검산한다. 학습 목표는 F1의 숫자와 사고 판단 근거를 구분하고, 점수·관측·추정·미확인의 범위를 설명하는 것이다.
