## 1. 실측으로 확인한 것 (재현 가능)

### 1-1. ±6h top1은 무작위와 구분되지 않는다

출처 `round_011_20261106/execution_001/metrics.json` → `random_expectations` 블록.

| 지표 | 사건당 후보 n(중앙값) | 무작위 기대 | 관측 |
|---|---:|---:|---:|
| 전체 B0 top1 | 1,183 | **1.86 / 100** | 3 / 100 |
| 전체 B0 top4 | 1,183 | **6.05 / 100** | 7 / 100 |
| Tier01 B0 top1 | 916 | **1.50 / 60** | 2 / 60 |

- B0 3/100: λ=1.86 포아송에서 **P(X≥3) = 0.286**. 유의하지 않다.
- B0 top4 7건 vs 기대 6.05건: 사실상 정확히 무작위.
- R11이 기록한 관문 실패(1.667% < 2.337%)와 같은 사실의 다른 표현.

### 1-2. 검정력이 0에 가깝다

- Tier01 해상도 = **1사건 = 1.67%p**. 관문이 요구한 +5%p = **3사건 추가 적중**.
- 2/60의 Wilson 95% CI = **[0.9%, 11.4%]** — CI 폭이 요구 효과크기보다 넓다.
- 결론: 진짜로 2배 좋은 변경안이 나왔어도 "미달"로 찍혔을 설계다.

### 1-3. 적중이 겹치지 않는다 = 무작위 지문

출처 `round_012_20261106/diagnostic_001/retrospective_overlap.json`

### 1-4. 연속 지표로 재면 신호가 실제로 있다 ← **가장 중요**

`event_results.csv`의 `abs_error`는 **시간(hour) 단위**다 (`acc_ts`도 시간 단위 정수.
R5만 컬럼명이 `abs_error_hours`). 초로 착각하지 말 것.

예측값을 사건 간 2,000회 셔플한 순열 검정 (`null.py`):

| 회차 | 방법 | 오차 중앙값 | 순열 null | p | ±6h 적중 |
|---|---|---:|---:|---:|---:|
| R6 | G | **743h** | 1,128h | 0.000 | 1 |
| R8 | G | 812h | 1,074h | 0.011 | 1 |
| R11 | S | 823h | 1,165h | 0.004 | 2 |

| — | B0 | 1,054h | 1,377h | 0.006 | 3 |

→ 예측이 사건에 **특정하게** 붙어 있다(p<0.01). 단 해상도가 **30~44일**이다.
→ R6 G는 기준선보다 **311시간** 가까웠는데 장부에는 **"1/100 개선 미달"**로만 남았다.
   측정 가능한 진전을 지표가 버렸다.

### 1-5. 단, 변경안 고유 기여는 아직 유의하지 않다 (과대해석 금지)

같은 사건 짝 Wilcoxon (B0 대비, k=1, `remeasure.py`):

```
R8  G p=0.019   R11 S p=0.014   R11 G p=0.043   R4 S p=0.064
R6  G p=0.259   R6  S p=0.211   R9  G p=0.727   R9  S p=0.375
R4  G p=0.976   R5  G p=0.973   R5  S1 p=0.983
```
13개 비교 → Holm 보정 임계 0.0038. **하나도 생존하지 않는다.**
즉 1-4의 큰 개선폭은 **대부분 B0와 공유되는 몫**(후보 가용성·시간분포)이고,
변경안 고유 효과는 미확인이다. R6 G가 −311h인데 짝지은 비교에서 p=0.259인 게 그 증거다.

**이 절을 빼고 1-4만 인용하지 말 것.**

## 3. 피처가 보고 있는 것이 틀렸다

현재까지의 8개 가설은 전부 **"이 배가 요 며칠 평소와 다른가"** 를 재는 느린 지표다.

| 쓴 것 | 실제로 재는 것 | 성격 |
|---|---|---|
| small run (저속 구간) | 이 배가 평소보다 느리게 다니나 | 느림 |
| 부분선 형상 이력 | 항적 모양이 과거와 다른가 | 느림 |
| 과거 중심거리 CDF | 평소 조업터에서 벗어났나 | 느림 |

그래서 답이 "며칠~한 달"로 뭉개진다(1-4의 743~1,054h). 계절·선박 습관 변화까지 같이 잡힌다.

사고는 갑작스럽다. 시각을 콕 찍으려면 **빠른** 지표가 필요하다:

| 필요 | 상태 |
|---|---|
| 속도 급락 / 정지 | 미구현 |
| 해당 시각 항적 끊김 | 초기 라인에 `과거/first_results/gap_*` 존재, 현 계열엔 없음 |
| 급선회·진로 급변 (`jump_reference.npy`) | 초기 라인에만 |
| 조업 중 → 표류 패턴 전환 | 미구현 |

데이터 해상도는 **시간 단위**다 (`과거/first_results/gap_meta.json`: `gap_median_h: 1.0`,
`scored_rows: 46705` / 100척 ≈ 467시간). 시 단위 예측은 데이터상 가능하다.
`CURRENT_STATUS.md`의 "아직 확인/구현되지 않은 것" 칸에 위 항목들이 이미 적혀 있다.

**즉 느린 지표만 8번 바꿔 끼우고, 빠른 지표는 현 계열에서 한 번도 제대로 넣지 않았다.**

## 4. 권고 (판단은 수신자 권한)

순서가 중요하다. 2번 없이 1번만 하면 9번째 "미달"이 하나 더 생긴다.

1. **(선행) 내부 선택 지표 교체 — 재실행 불필요**
   주지표를 `±6h top1 적중 수` → `정답 시각의 pool 내 순위 백분위` 또는 `abs_error`로.
   검정은 B0 대비 paired Wilcoxon + 순열 null 둘 다, 다중비교 보정 명시.
   저장된 `event_results.csv`만으로 기존 8개 가설을 **재채점**할 수 있다(연산 거의 0).
2. **관용창 단계화** ±720h → ±72h → ±24h → ±6h.
   신호가 어디서 끊기는지가 다음 가설을 정한다. 1,000h→6h는 3건→6건과 다른 종류의 문제다.
3. **급변 피처 도입** 정지·항적 끊김·급선회·표류 전환. `과거/first_results`의 `gap`/`jump`
   계열을 현 평가 틀로 되살리는 것이 최단 경로로 보인다.
4. **캐스케이드를 hard 제외 → soft 감점으로.** 커버리지 100→28이면 어떤 가설도 평가 불가다.
5. **학습 범위를 82척에 묶지 말 것.** 사용자 원 지시 및 Codex 자체 반성과 일치.
   82척/100사건은 **평가** 분모일 뿐 학습·분석 범위가 아니다.

### 재탐색 금지 (측정으로 기각 완료)
- 스태커·임계값·공간압축·월별 drift
- 3성분 점수로 사고시각 신호 찾기 (규칙 교체·재가중·임계값)
- 위치 CDF 계열의 격자/꼬리/창/동료 우선순위 튜닝 (R11에서 STOP 선언)
- 동일 선박 과거 항적 프로필링·재식별·ID 조인 (전 경로 무효. 지역 사전확률은 leave-self-out만)
- 결과 보고 S/top4/일부 유형으로 주지표 바꾸기

### 철회된 과거 주장 (되살리지 말 것)
- Round026 "0.60" → OUTER 참조 선택값. 정직한 기준선은 0.599966

## 5. 미해결 블로커 (외부 의존, 여전히 미응답)

1. **공식 채점식** — 특히 제출 양식 **시각1~3의 역할.** 네 칸이 네 번의 기회라면 전략이
   완전히 달라진다(top4는 7~10/100). 현재 저장 제출본은 보조 칸이 33/38/58척만 채워져 있고
   샘플 XLSX의 H1은 빈 헤더다. 허용 결측·시간 형식·대상 기간 미확인.
2. **확정 사고↔RFID 대조표** — 있으면 우리가 추정해 붙인 82개 라벨을 검증할 수 있다.
   오면 원 devset을 덮어쓰지 말고 별도 버전 라벨·분모·사전 계약을 만들 것(R12 결정 유지).

참고: 후보 1,200개에서 ±6h를 찍는 과제이고 무작위가 1.9%다. **이 대회는 전원 저득점일
