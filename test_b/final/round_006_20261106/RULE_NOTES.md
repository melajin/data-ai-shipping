# Round6 duration rules ? Luna scope

`duration_rules.py` implements `build_duration_rules(frame, gear_registry) -> {ledger, predictions, pool_manifest, run_registry, diagnostics, stage_spec}`. It consumes only the canonical numeric frame and R3 gear registry; it does not read labels, incident fields, or source datasets.

The public API accepts integer `ts` only as epoch-hours (`unit="h"`) or datetime dtype values aligned to exact epoch hours. It rejects missing timestamps, strings, nanosecond-valued integers, out-of-range values, and unaligned datetimes instead of guessing a unit. Internal and returned `ts` values are hour-aligned datetimes; ledger `source_ts_hour` preserves the integer epoch-hour lineage. Prediction and run-registry timestamps use the normalized datetime representation.

Geometry validity depends only on finite, nonnegative `len_m` and `bbox_m`; longitude and latitude do not affect duration eligibility. Runs are consecutive valid small hourly observations. A completed reference requires valid non-small observations at both exact neighboring hours. Gaps and invalid geometry censor runs. `current_L` counts only observed small keys in the present run, and `current_L_is_lower_bound` records an unconfirmed left edge. Historical references require both boundaries, `start_ts >= t - 720h`, and `close_ts < t`; self history needs 10 runs across 3 start dates. Peer scores are per-vessel CDF values for other eligible single-code vessels of the same gear, averaged equally, with at least 5 peers.

A row that fails d0 has d1-d4 masks false and statuses `not_applicable`. Run construction remains geometry-based: a past completed run is not dropped because one of its observations had a missing or infinite legacy score. An invalid current score defers that candidate; it is not treated as a normal observation. G fallback reasons follow the actual selected pool stage: d3=`no_peer_history_candidates`, d2=`no_self_history_candidates`, d0=`no_continuation_candidates`, or an empty d0 pool=`no_observations`.

The exact source used by the completed `execution_001` run is preserved at `implementation_fixes/duration_rules_before_guard.py` and its SHA-256 matches the run receipt. `ACTUAL_MASK_CHECK.json` records 99,677/99,677 finite scores, all d0 rows true, and zero nesting violations; the guard therefore leaves that run's candidate masks and ranking usable.
