# Round 013 설계 — 전체 학습 자료의 행동 기준과 시간별 급변 진단

작성: 2026-11-06. 상태: 설계 완료용 계약; 본 실험 미실행. 총괄이 통합·판단하며 원본과 Round 001–012 결과를 보존한다.

## 1. 이번 회차가 답할 질문

**82척 밖의 학습 가능한 전체 항적에서 어업별 행동 기준을 만들면, 시간별 경로량의 급격한 감소를 정상적인 작은 움직임과 구별하여 사고 주변 후보의 순위를 높일 수 있는가?**

전체 자료 활용은 파일 수를 늘리는 작업이 아니다. 원본·수정본의 계보를 유지하고, 중복을 한 번만 반영하며, 학습 가능한 선박을 82척에 제한하지 않는다는 뜻이다. 공식 Test는 역할을 보존하여 적용·평가에 사용한다. Test 정답이나 평가 선박으로 기준을 적합하지 않는다.

이번 회차는 작은 전체 흐름인 자료 → 어업별 기준 적합 → 연속 변화 관찰 → 단계별 후보 설명 → 시간 국소화 평가를 구현 대상으로 삼는다. 사고 여부 판정과 실제 F1 검증은 정답 확보 상태에 맞춰 별도로 관리한다.

## 2. 시작 전 코어 점검 다섯 항목

1. **다루는 코어:** 연안복합·통발·자망·채낚기 등의 전체 항적 분포, 직진성·경로량·작은 움직임·회복의 순차 관찰, 공통 기준과 어업별 분포의 분리. 작은 움직임을 대기나 사고로 단정하지 않는다.
2. **코어와 다른 부분:** 버전/분할 확인과 기존 지표 재집계는 준비 작업이다. 이들만 완료하고 행동 분석이나 탐지 성능을 구현했다고 보고하지 않는다. 항만 식별·항로 추종·물리적 표류 판정은 이번 회차에 확보됐다고 주장하지 않는다.
3. **기술·학습 목표:** 전체 학습 가능 항적에서 기준을 적합하고, 사건 전후 관측과 점수 변화가 일치하는지 설명한다. 각 단계의 산출물과 관문은 아래에 고정한다.
4. **확인/미확인:** 두 F드라이브 폴더 실존, 과거 해시 감사, 시간별 항적 구조와 잠정 사고 연결은 확인했다. 현재 파일의 재해시, 전체 고유 선박 수·역할별 중복, 좌표별 시각, 확정 사고 RFID, 완결된 미사고 라벨, 공식 시간오차 가중식은 아직 확인하지 않았다.
5. **진입 조건:** 자료 역할·중복·분할이 명시되고, 실제 사고 주변 관측을 확인하며, 라벨 없이 생성 가능한 단일 급변 신호를 고정한다. 연속 오차만 개선되고 6시간 적중이 나빠지면 제출 개선안으로 승격하지 않는다.

## 5. 단계 B — 전체 행동 기준과 실제 사례를 먼저 연결

기술 목표: 전체 적합 선박에서 어업별 경로량·공간 범위·부분선 직진성·연속 시간 변화·관측 공백 분포를 만든다. 이는 어업 코드별 관측 기준이며 정상 행동 정답이나 새 어업 분류 모델의 성능은 아니다.
학습 목표: 항적 형상, 관측량 변화, 행동 해석, 사고 여부를 구분한다.

구현물: `fishery_profiles.parquet`, `profile_summary.csv`, `event_windows.parquet`, `case_review.md`, `figures/`.
관찰: 전체 100사건의 ±24시간에서 관측 유무, 경로량·bbox·기존 점수, 부분선 수/점 수, 사고 위치와 잠정 연결 거리; 사고 범주별 변화와 불변 사례를 함께 기록한다.
검증: 사건 시각은 그림·평가에만 결합한다. 특징 생성 입력에는 사고 시각·좌표·유형을 넣지 않는다. 시간 공백을 보간하지 않고 부분선을 잇지 않는다. 사건별 실제 사고 분 단위와 기존 정수 시각을 나란히 기록한다.

상세 원항적 사례는 결과를 보기 전에 12건을 선정한다. 이미 언급한 acc_id 2,22,79는 설명용 3건으로 고정하고, 나머지 9건은 나머지 acc_id의 SHA256(`round013:<acc_id>`) 순으로 고정한다. 전체100사건 수치 분석도 함께 수행하여 이 12건을 대표 성능으로 쓰지 않는다. 동일 선박의 사고 밖 비교창은 라벨 미확인 비교창으로 표시하며 정상 정답으로 쓰지 않는다.

사례별 관찰표: (a) 사고 주변 관측 부족, (b) 관측량 변화가 있으나 기존 점수가 놓침, (c) 뚜렷한 관측 변화 없음, (d) 다른 변화/대기 설명 가능, (e) 연결 자체 미확인. 범주는 중복 가능하며 관측·해석·미확인을 분리한다. 전부 급격한 사고라고 가정하지 않는다.

설명 질문: 6월 사고에 1월 후보를 고른 사례에서 6월에 실제로 무엇이 관측됐고, 기존 점수가 무엇을 놓쳤는가?
통과 조건: 그림과 원자료 좌표·시각이 맞고, 변화 신호를 계산할 수 있는 시간별 관측 수를 제시한다. 관측이 없으면 모델 튜닝 전에 데이터 가용성 문제로 분리한다. 한 두 사례의 인상으로 임계값을 정하지 않는다.

## 6. 단계 C — 한 가지 급변 가설만 적합·적용

실험 가설: **직전 관측 한 시간에 비해 경로량이 크게 줄어드는 전이가, 항상 작은 경로량 자체보다 사고 시각 국소화에 유용할 수 있다.** 정지/실제 속도 급락을 측정한다는 뜻은 아니다.

어업 코드는 출처가 확인된 제공 라벨만 사용한다. Test의 코드가 없거나 연결 근거가 없으면 미상으로 기록하고 공통 분포를 적용한다. 기존 어업 분류 모델의 예측을 쓰는 것은 이번 단일 가설과 별도 변경이므로 자동 추가하지 않는다.

주 입력은 유효한 시간대표행의 부분선 내부 경로량 L(m). t-1과 t가 실제로 연속한 경우에만

`D(t) = log1p(L(t-1)) - log1p(L(t))`

를 계산한다. 전체 적합 선박의 D 분포를 어업별로 학습한 midrank 경험누적분포 `F_g(D)`를 급감 순위 점수로 사용한다. 기준 분포가 없는 어업은 공통 분포를 사용하고 그 사실을 표시한다. 선박별 경험분포를 먼저 만든 뒤 선박을 동일 가중하여 기록이 긴 선박의 독점을 방지한다. 모두 사후 국소화 실험이며 전체 훈련 기간으로 기준을 적합했음을 명시한다. 온라인 조기탐지 성능으로 표현하지 않는다.

직전 한 시간 대비는 장기 동일 선박 위치 프로필/재식별 가설의 재탐색이 아니다. 이 회차는 위치 CDF·3성분 재가중·스태커·임계값 격자·gap/jump 결합을 수행하지 않는다. 기존 gap/jump는 정의와 누락 여부만 확인하고 별도 가설로 보관한다.

공통 규칙과 어업별 추가 기준을 분리한다:

1. R0 자료 유효성·시간 연속성 확인. 미관측은 작은 움직임이나 이상으로 대체하지 않는다.
2. R1 공통 D와 공통 분포 점수. 감소·증가·변화 없음의 연속 관찰을 표시한다.
3. R2 어업별 분포 점수로 상대적 이례성을 설명한다. R1/R2는 미리 정한 두 목록으로 함께 보고하고 새 가중 결합을 만들지 않는다.
4. R3 bbox 변화·부분선/점 수 변화·이후 1~3시간의 회복 여부를 대안 설명으로 기록한다. 이후 정보는 진단용이며 이번 후보 점수에는 넣지 않는다. 항만 미확인 상태를 항만 밖으로 바꾸지 않는다.

각 단계는 원래 후보 ID를 유지하고 적용 가능·보류·판정 사유·순위 변화를 기록한다. 행동 조건 미충족만으로 원 후보 행을 삭제하지 않는다. 사용자가 정한 순차 규칙 관찰은 유지하되, 대기라는 근거 없는 hard 제외나 감점을 도입하지 않는다. 결측·무효로 실제 계산 불가한 행은 별도 표시하고 사고창 커버리지 손실을 숨기지 않는다.

RFID별 전체 기간에서 최고 점수 1시각을 고른다. 동점은 ts, source_ordinal 오름차순. 계산 가능한 전이가 전혀 없는 선박은 무예측으로 남기고 실패 분모에 포함한다. 이번 단계는 국소화 진단이며, 모든 선박에 이 시각을 사고로 기입하는 제출 정책이 아니다. 실제 사고 출력/보류 기준은 확정 양성·음성 또는 주최 평가 근거와 별도 계약이 필요하다.

구현물: `transition_features.py`, `fit_profiles.py`, `stage_ledger.parquet`, `predictions.csv`, `fit_manifest.json`.
검증: 상수 경로량, 감소/증가, 결측 시간, 중복 시간, 부분선 경계, 선박 분리, 평가 RFID의 fit 배제, 동점 처리, 사고 라벨 입력 차단. 대형 신규 모델은 추가하지 않는다.
설명 질문: 길이가 줄어든 이유가 움직임 변화인지 관측 누락인지 어떻게 구별하는가? 대기 후 재출항이 사고 후보로 올라간 이유를 설명할 수 있는가?

## 7. 단계 D — 가까워진 정도와 실제 적중을 함께 평가

기존 최종 유효 실행을 명시한 manifest로 선택한다(R2/R5 수정 execution_002 포함). glob로 폐기·수정 전 실행을 섞지 않는다. 원100/60 결과·시간 단위·정수시각 계약을 보존한다. 새 단계가 원 사고 분 단위 평가를 추가하면 별도 열로 병기한다.

고정 보고 항목:

- 전체100사건과 Tier01 60사건의 6/24/72/720h 이내 적중 수 및 전체 시간오차 누적곡선. 무예측은 모든 유한 시간창에서 실패다.
- 예측 존재 사건의 중앙/평균 절대오차는 조건부 수치로 표기하고 무예측 수·분모를 바로 옆에 둔다. 오차 중앙값을 데이터의 시간 해상도라 부르지 않는다.
- 원후보 관측 커버리지와 각 규칙 단계의 계산 가능 커버리지. 시간창 안 후보가 없으면 순위 통계에서 조용히 빼지 않는다.
- 사고 ±6h 내 최고 점수 후보의 전체 후보 대비 midrank 백분위(작을수록 좋음), 동률 규모, 계산 불가/창 미관측 비율. 저장된 event_results만으로 이 순위는 복구할 수 없으므로 후보 점수 ledger가 필요하다.
- 같은 RFID의 모든 사고에 동일 예측을 공유한다. RFID 묶음 bootstrap 4,000회(seed 20261106)로 B0 대비 효과 구간을 계산한다. 사건 간 전역 timestamp 셔플은 사용하지 않는다.
- 무작위 비교는 각 선박의 실제 후보 시각에서 1개를 선택하고 해당 RFID의 모든 사고에 공유한다. 원풀/계산가능풀을 구분한다. Monte Carlo p가 필요하면 `(극단횟수+1)/(B+1)`이고 p=0으로 쓰지 않는다. 추가 다중검정은 비교군을 먼저 명시한다.
- 전체 적용 선박 수와 후보 시각 출력 수를 보고하되 미라벨 선박의 출력을 FP로 세지 않는다. 확정 미사고 라벨과 공식 시간 가중식을 확보했을 때만 공식 정의에 맞춘 F1을 산출한다.

진척은 세 수준으로 구분한다:

1. **구현 통과:** 전학습 코퍼스 사용 증거, 누수 방지, 실제 사례·전이 신호·전체 평가 연결 완료. 성능 향상이라는 뜻은 아니다.
2. **탐색 진척:** 시간오차 곡선/사고창 순위가 개선되고 그 이유를 사례로 설명할 수 있음. 6h 적중이 떨어지면 시간 국소화 한계로 기록하고 제출 승격 금지. 6h가 정체돼도 연속 개선은 다음 단일 가설의 근거로만 사용한다.
3. **제출 개선:** 국소화 외에 사고 여부/미사고 FP와 공식 점수 개선 근거가 필요하다. 현재 잠정 양성100건의 오차 감소만으로 달성했다고 보고하지 않는다.

R1/R2 모두 개선 근거가 없으면 창 길이·임계값을 훑지 않는다. 실패 사례를 관측 부족/연결 불확실/행동 변화 없음/대기 혼동/급변 점수 누락으로 나누고, 다음 가설 하나를 선택하거나 코어의 행동 구분 단계로 돌아간다. 공식 정보 미확인은 전체 내부 분석을 멈출 이유가 아니다.

## 8. 실행 순서·소유권·자원

이번 요청에 따른 산출물은 **설계와 검토**다. 이 문서를 작성하면서 학습·전수 스캔·새 예측·제출 파일 변경을 실행하지 않았다. 후속 실행은 A → B → C → D로 진행하며, A/B 완료를 이유로 회차를 끝내지 않고 가능하면 동일 회차에서 작은 전체 흐름까지 연결한다. 관문 미달이면 정확한 실패와 대체 작업을 기록한다.

- 총괄: 공통 계약/실험 가설/라벨과 점수 정의/최종 보고의 유일 수정 담당.
- 자료 작업자: manifest·코퍼스·분할·전체 분포 적합. 다른 담당 코드를 되돌리지 않는다.
- 연속 항적 작업자: 사례창·부분선 그림·전이 구현. 자료 계약을 임의 변경하지 않는다.
- 독립 검토자 둘: 통계/채점과 코어/자료 활용을 따로 검토한 뒤 의견 차이를 총괄에게 전달. 모델 쿼터 소진은 인계 사유이며 사용자 승인 재요청 사유가 아니다. 실제 실행 모델은 생성 응답으로만 기록한다.

설계 확인 시각 2026-11-06T05:55:45+09:00의 가용 RAM은 4,177MiB였다. 이번 검토는 작은 문서 읽기 2작업, 각 추가 128MiB 추정이며 대형 데이터 작업을 실행하지 않았다. 본 실행 직전 RAM과 다른 대형 프로세스를 다시 확인한다. 초기 숫자열 청크/선박 파티션 작업 예상 peak1,024MiB + reserve640MiB는 계획치이며 실측치가 아니다. WKT 추출은 별도 순차 작업으로 512MiB부터 예산을 잡고 표본 peak로 수정한다. 부족하면 청크를 줄이고 독립 문서/소규모 검증부터 수행한다. 사용자 프로세스 종료와 반복 RAM polling은 하지 않는다.

최종 회차 보고에는 기술 결과, 학습자가 설명할 질문, 모든 실제 분모, 실패·무예측·어업별 편차, 측정/가정/미확인, 다음 변경 하나를 기록한다. 실제 학습자 이해나 하드웨어 성능을 검증했다고 표현하지 않는다.
