# Round3 상세보고서 — 어업 유형별 관측 기준선

이 문서는 회차 보고서 이름을 통일하기 위해2026-11-06에 추가한 총책임자 정리다. 당시 원[report.md](report.md),수치 표와[해석 정정](REPORT_QUALIFICATIONS.md),[중간 검토/결정](MIDDLE_REVIEW_AND_DECISION.md)을 보존한다. 새 계산이나 성능 실험은 아니다.

## 목적과 코어

R2 위치 조건 비교의 실패 후, 어업 유형별 전체 항적 특성을 먼저 파악하는 코어로 돌아왔다. 기술 목표는 잠정 사고-RFID 개발집합82척의 어업 코드·관측 수·경로량·작은 경로량 연속 관측·반복 공간을 기록하는 것이다. 학습 목표는 어업 코드와 동적 조업상태,시간행 경로량과 실제 속력,반복 위치와 항만/정상 대기의 차이를 설명하는 것이다.

구현물은inventory.py,gear_registry.csv,per_vessel.csv,group_summary.csv,case_observations.csv,summary.json,실행 receipt다. 관찰은 어업 그룹별 경로량/경계상자 차이와 small 조건의 연속·공백이다. 검증은99,677개 canonical행/82RFID,단일 코드 연결과 결정론적 사례,분모/가중 방식,공백에서 run 분리다. 설명 질문은‘관측 숫자가 어업 그룹마다 다를 때 무엇을 정상 기준으로 부를 수 있는가?’다.

## 실제 입력과 결과

|---|---:|---:|---:|

| 자망 |31|47,447|311.0|
| 통발 |13|19,894|5,125.7|

82척 모두 Train fishing_code의 한 문자열로 연결됐고 혼합/결측 선박은0이었다. 이것은 잠정 사고 개발집합의 구성이지 전체 어업 모집단의 대표 표본이 아니다. 채낚기연승낚시1척으로 어업별 정상 지속 기준을 만들지 않았다.

small은len≤100,bbox≤100이라는 설계상 관측 조건이다. 전체 행 비율42.38%,선박별 비율 평균42.57%,중앙값40.39%는 서로 다른 통계다. run은 정확히 연속한 관측 시간키에서 조건을 만족한 개수이며 실제 정지·대기 시간은 아니다. 종료가 관측돼도 자력 출항·수리·조업 재개를 확정하지 않는다. 반복0.05도 셀도 항만·어장·어구 정답이 아니다.

당시 숫자 장부에는 원부분선 점열이 없어 선로 추종·부분선 내부 직선성을 유보했다. 이후R7/R8에서 제공 원 CSV의 부분선을 제한 관찰/추출한 것은 이 입력을 보충한 별도 단계다. 공식 항만 경계·정상/대기 행동 정답·점별 시각은 이 회차에서 확인하지 못했다. 수치를 실제 시간당 속력으로 바꾸지 않았다.

## 자원과 해석 제한

실행은12.2초였다. 직전 가용 RAM3578.7MiB에서 추가512+여유640MiB와 다른 Python 작업을 확인했다. tracemalloc46.33MiB는 Python 추적 메모리이며 프로세스 실제 최대 메모리가 아니다. RSS는 시작85.8MiB·종료366.14MiB,증가280.34MiB로 기록됐다. 종료 RSS를 전 과정 최대라고 주장하지 않는다. 실제 하드웨어 동작은 시험하지 않았다.

원 report의 어업별72시간 규칙·정상 집어/표류·대기 오탐 배제 해석은 검증되지 않았으므로 다음 실험에 자동 채택하지 않았다. 원본을 보존하고 REPORT_QUALIFICATIONS에서 구분했다. 이 회차는 행동 기초 관측이며 사고 적중률이나 precision/F1을 평가하지 않았다. 학습자가 실제 설명할 수 있는지도 측정하지 않았다.
