# Round12 — 저장 결과의 관측·평가 의존성 진단

## 코어 시작 점검

1. 코어의 어업 행동·순차 이상 후보가 **평가 대상의 관측 가능한 현상과 연결되는지** 점검한다. 새 행동 탐지 구현이나 성능 개선 회차는 아니다. 앞선 고정 규칙 실패를 새로운 문턱 탐색으로 이어가지 않는다.
2. 새로운 매칭/확정 라벨·사건 제외·학습·추론·제출 파일 변경·외부 수집은 범위 밖이다. 공식 평가와 내부±6h 지표의 동일성, 실제 사고 선박 신원, 정상 대기는 미확인으로 유지한다.
3. 기술 목표는 저장된 결과와 기존 연결 metadata의 정확한 사건 단위 결합·층별 기술 집계·방법 간 적중 교집합이다. 학습 목표는 잠정 연결과 정답, 같은 적중 수와 같은 사건, 사후 합집합과 실행 가능한 예측기의 차이를 설명하는 것이다. 산출물은 실행 코드·출처 hash·사건/층별 표·교집합·현재 판단 근거다. 관찰은 기존 tier/conflict/발생유형/dt_h별 적중·관측 범위의 차이다. 검증은 기존100/82·60/55 분모,원사건 ID/metadata 불변,같은 source/method/k 사건 수와 직접 교집합이다. 설명 질문은 ‘더 엄격한 근접 연결을 확정 신원이라고 부를 수 있는가?’다.
4. 기존100건 devset과 R4/R5/R6/R8/R9/R11의 저장 event_results만 읽는다. 공식 채점 원문·확정 사고-RFID 대조표는 경로 요청 후 미응답이다. 원자료 전체 재감사나 새 수집은 하지 않는다.
5. 집계가 원 결과 수치·전체 분모와 일치하고 모든 원본이 불변이어야 통과한다. 집계 자체에 적중 개선 관문을 적용하지 않고 **개선 판정 없음**으로 기록한다. 어떤 층/사건만 남겨 재평가하거나 사후 합집합을 새 방법으로 제출하지 않는다. 공식 규격/확정 대조 자료가 확인되기 전 제출 성과를 확정하지 않는다.

## 고정 진단 범위

층은 이미 제공된 tier의 값별,conflict의 값별,원본 발생유형별,dt_h의 값별이다. 새 거리 절단값이나 사고 유형 재라벨을 만들지 않는다. 전체100과Tier01 60 기준 집계도 함께 보존한다. 여러 회차의 예산/후보 풀은 다를 수 있어 top4 단순 우열을 새 공정 비교로 주장하지 않는다. 사후 union은 이미 시도한 목록 중 적중한 사건의 기술 집합일 뿐 정답 없이 그 방법을 고르는 알고리즘이 아니다.
