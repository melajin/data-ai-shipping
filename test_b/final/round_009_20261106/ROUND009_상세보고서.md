# Round9 상세보고서 — 작은 경로량 뒤 조건 변화는 개선 기준 미달

## 결론

정확히 연속된 관측에서 **small → small → non-small** 순서를 후보로 삼았다. 공통 후보를 기존 점수로 고른 S와 과거 전이율의 어업 상대순위로 고른 G 모두 Tier0–1 top1은 **2/60**으로 기존 B0와 같았다. 전체 top1은 기존3/100에서2/100으로 낮아졌다. G의 네 사전 관문 중 무작위 기대 초과만 통과했고 나머지 세 개는 실패했다. 개선 제출안으로 채택하지 않는다.

후보 순서가 실제 자료에 존재한다는 점, 두 독립 구현이 같은 패턴을 집계한다는 점은 확인했다. 이것은 실제 대기·운항 재개 정답이나 사고 탐지의 성공을 뜻하지 않는다. 계획대로 작은 구간의 길이·개시·지속·종료/재개 계열을 같은 문턱 조정으로 더 반복하지 않고 보류한다.

## 이번 라운드의 코어와 학습 목표

코어의 ‘작은 경로량이 이어진 뒤 다시 움직임 조건이 나타나는 과정’을 관측 순서로 구현했다. 공통 순서 규칙과 어업별 추가 맥락을 분리하고, 규칙을 차례로 적용할 때 후보와 적중이 어떻게 달라지는지 기록했다. 실제 대기·정지·출항은 판정하지 않았다. 항로 추종, 항만, 실제 속력/가속도, 행동 정답, 확정 사고 신원은 범위 밖이거나 미확인이다.

기술 목표는 결과 독립적인 전체82척 순서 장부와 같은 예산 B0/S/G를 만드는 것이다. 학습 목표는 연속 관측과 공백, 관측 조건과 실제 행동, 사건창에 후보가 없음과 선박 전체 후보 풀이 없음의 차이를 설명하는 것이다. 구현물은 transition_rules.py, 독립 집계, 대표4사례의12원행, 후보 장부·예측·풀·사건 결과·자원 기록이다. 관찰은 패턴 빈도, 자기 과거 참조, 동료 상대순위, 단계별 후보 손실과 적중이다. 검증은 시간키·과거 경계·유효 참조 분모·독립 집계 일치·같은 cap·정답 전 예측 동결이다. 설명 질문은 ‘이 관측 순서를 실제 대기 재개로 확정하지 않으면서 무엇을 검증했는가?’다.

본인 학습자용 설명이며 선수지식과 실습시간은 미확인이다. 코드·실제 데이터 계산은 수행했지만 학습자가 설명할 수 있는지는 별도로 평가하지 않았다. 장치 연결이나 실제 하드웨어 검증은 없다.

## 사전 고정 설계와 입력

R4 숫자 장부99,677행·82척과 R3 어업등록을 재사용했다. 추가 원자료 추출, 외부 수집, 신규 모델 학습은 없었다. R5의 next_not_small 진단은 질문의 동기일 뿐 후보 생성에는 사고 시각을 사용하지 않았다. 정수 시각은 기존의 시간대 변환 없는 source-clock 시간키이며 실제 시간대·점별 시각·정확 CRS는 미확인이다.

small은 len≤100m 및 bbox≤100m라는 기존 관측 조건이다. s0는 현재 유효 기하·유한 기존 점수, s1은 정확한 t−2/t−1의 유효 기하 관측 존재, s2는 두 이전 관측이 small이고 현재가 non-small인 순서, s3는 자기 과거 참조, s4는 같은 단일 어업의 다른 선박5척 이상이라는 추가 기준이다. 이전 관측의 기존 점수가 결측이어도 유효 기하는 순서와 참조에 사용할 수 있다. 조건 밖 관측의 제외와 정보 부족 유보를 구분했다.

참조 분모는 사고나 패턴만 고른 행이 아니라 모든 유효 연속3키다. 세 키 모두 [t−720,t)에 들어와야 하므로 참조 종료 u는 [t−718,t)다. 현재 종료 t와 미래를 제외했다. 24삼중항·종료 날짜3일 이상이 자기 적격 조건이다. 패턴 수/참조 수가 과거 전이율이며 분자0은 유효한 빈도0이다. 실제 대기 빈도나 사고 확률이 아니다.

G는 자기 전이율이 같은 어업의 다른 적격 선박 전이율에 비해 드문 낮은 값인지 midrank로 비교해1−p를 순위 통계로 사용했다. 동료는 같은 t 기준의 각자 과거만 사용하며 현재 관측이 없어도 된다. 선박당 한 개의 빈도를 균등 비교했고, 분수 비교는 정수 교차곱으로 수행했다. S와 B0는 기존 점수 내림차순이다. G는 어업 상대순위 다음 기존 점수 내림차순, 동률은 시각·ordinal 오름차순이다. R6 run 길이나 R8 형상 CDF를 섞지 않았다.

S는 s2 후보가 없을 때 B0로, G는 s4 후보가 없을 때 S의 실제 풀·순위로 복귀했다. cap=min(4,G 실제 풀 크기)를 세 방법에 동일하게 적용했다. cap4인79척, cap1인2척, cap3인1척으로 방법당321개·합계963예측행이다. 동일 RFID의 여러 사건에는 같은 예측 목록을 썼다. top1은 같은 top4의 rank1이다.

## 구현과 독립 검증

Luna는 판정 모듈과517행 합성 검사를 구현했고11검사가 통과했다. 검사 전후 구현 hash80da231443a7c16b2e05d5b348bbfb30d9608594af92f971f37c0ffbfffd7360이 일치했다. 현재 종료 제외, full-triple 창 경계,24/23참조,3일,분자0,5동료,정확한 분수 동률,이전 점수 결측,공통 cap/fallback/미래 추가 불변성을 확인했다.

Gemini는 Luna 모듈을 가져오지 않고 전체 숫자 자료를 독립 집계했다. 유효 삼중항88,036개·패턴3,807개였다. 과장된 ‘이미 Luna와100% 일치’라는 초기 보고 제목은 실제 통합 전이라 채택하지 않았고, 수동 어업별 전체행 수 오류와 receipt 자기 자신 hash도 INVENTORY_REPORT_QUALIFICATIONS.md에 구분했다. 실제 root 실행에서 **사건 정답을 읽기 전에82척별 유효 삼중항 수와 패턴 수가 모두 일치**함을 확인했다. 이제 이 통합 일치는 실제 실행 근거가 있다.

어업별 패턴/유효 삼중항은 연안복합1470/25703, 자망1733/42921, 통발564/17677, 채낚기연승낚시40/1735다. 이는 관측 삼중항 가중 빈도이며 정상 분포나 실제 재개 비율이 아니다. 채낚기연승낚시는1척뿐이다. 대표 사례는 어업별 최초 패턴4개·각3원행으로 정답 시각과 무관하게 골랐다.

평가는 재검증을 거친 R8의 **일반 s0~s4 수치 평가기**를 읽기 전용으로 재사용했다. 함수명에 shape가 남아 있어도 R9가 형상 특징을 사용한 것은 아니다. 실제 입력은 이번 순서 모듈의 장부·stage_spec이다. 원 코드와 계약을 execution_sources_001에 보존했고 실행 전후 소스 hash가 일치했다.

## 후보 축소와 실패의 위치

단계별 행 수는99,677→88,036→3,807→3,702→3,634, 후보가 있는 선박 수는82→81→77→76→75다. s1에서11,641행은 정확한 이전 관측/기하 정보가 부족해 유보했고, 유효 삼중항84,229개는 이번 순서가 아니라 s2에서 제외됐다. 자기 참조 부족105패턴, 동료 조건 부족68패턴은 추가 유보했다.

사고±6h에 strict 단계 후보가 하나 이상 남은 사건은 전체100→94→30→28→28, Tier01 60→56→23→21→21이다. **Tier01 39건의 strict s4 창 부재와 선박 전체 G fallback은 다르다.** S 전체 fallback은5척, G는75척에서 s4 풀을 쓰고 나머지7척에서 fallback한다. 현재 사건창 밖의 후보가 있어 fallback하지 않는 선박도 있다.

이번에는 공통 패턴 적용 때 사건 인근 후보가 크게 줄어드는 가용성 문제와, 남은 후보 중 적중을 충분히 선택하지 못한 문제가 함께 있다. G는 S와 비교해 top1 선택이73/82척, top4 목록이74/82척에서 달랐지만 주지표 이득이 없었다. 같은 적중 수라고 반드시 같은 사건을 맞혔다는 뜻은 아니므로 사건별 교집합은 별도 검토 대상으로 남긴다.

## 실행·자원·해석의 한계

실제 root 실행은21.473초, 최대 working set356.16MiB였다. 직전 가용 RAM4521.5MiB를 확인했고 추가1280+여유640MiB를 보수적으로 잡았다. 실행기가 직전에 다시 확인했고 다른 실제 대량 작업은 없었다. 독립 집계는1.488초·154MiB였다. 사건 정답을 읽기 전에 예측·풀·장부를 저장했으며 평가 후 예측·풀 hash가 동일했고 실행 소스도 바뀌지 않았다.

이는 실제 자료의 계산 평가이며 하드웨어 실험이 아니다. 잠정 사고-RFID 연결과 반복 사용한 dev라는 제약이 남는다. 단일 관문 통과나 일부 top4 증가로 실제 사고 탐지 일반화·실선 운용·제출 성과를 확정하지 않는다.

## 다음 결정의 범위

사전 중단 조건대로 작은 구간의 길이·종료/재개 계열은 보류한다. 1시간/3시간 조건이나 거리·기간을 바꿔 같은 실패 가설을 다시 평가하지 않는다. 두 경쟁 중간관리자에게 실제 결과를 독립 검토하고 다음에 다룰 **다른 코어 관측축**을 한 가지씩 제안하도록 한다. 기존 선로/관측 공간범위 변화 같은 질문은 자료가 실제로 무엇을 표현하는지 먼저 명확히 해야 하며, 시간별 중심좌표를 실제 항로 정답처럼 표현해서는 안 된다. 공백은 실제 통신 장애나 사고로 단정하지 않는다.

제출 가능한 개선안은 아직 확보하지 못했다. 모든 원본·실패 결과를 보존하며 새 Test B 추론·제출 변경·외부 업로드·신규 모델 학습은 하지 않았다.
