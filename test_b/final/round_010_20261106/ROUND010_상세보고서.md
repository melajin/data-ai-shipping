# Round10 상세보고서 — 과거 중심위치 거리의 계산 가용성 확인

## 결론과 다음 단계

시간행의 평균 중심위치와 같은 선박의 엄격한 과거 중심위치 사이 최단 거리를 계산했다. 두 독립 구현의 **82척별 가용성 집계가 모두 일치**했고 **12개 거리·최근접 원행·참조 수/날짜도 일치**했다. 이 검증을 마친 뒤 사건 정보를 읽어 확인한 Tier0–1의 적격 관측 창은 **53/60**, 동료 조건을 충족하는 관측을 하나 이상 가진 선박은 **79/82**다. 사전 가용성 기준인50/60 이상·6척 이상을 통과했다.

이것은 다음 점수 설계를 시도할 입력이 있다는 결과다. **사고 적중률 개선을 입증한 결과가 아니며 예측 목록을 만들지 않았다.** 실제 항로 추종·이탈, 항만, 정상 대기, 통신 상태나 사고 원인도 판정하지 않았다. 다음 회차는 두 경쟁 검토자가 이 제한을 유지하면서 한 가지 고정 순위 규칙을 제안하고 총책임자가 선택해야 한다.

## 이번 단계의 코어와 학습 목표

사용자 코어의 기존 선로·반복 공간과 현재 관측의 관계를 다룰 수 있는지 작은 전체 흐름으로 확인했다. 다만 현재 입력은 원부분선이 아니라 **시간행 좌표들의 평균 중심**이다. 평균이 실제 부분선 위에 있지 않을 수도 있으므로 이것을 항로나 항만 정답처럼 사용하지 않는다. 이번 준비 단계를 행동 유형·단계적 사고 탐지의 완성으로 표현하지 않는다.

기술 목표는 결과 독립 과거 위치 대리값과 단계별 유보 장부, 독립 계산의 일치 확인이다. 학습 목표는 중심 대리값과 원항적, 반복 위치와 정상 상태, 과거 참조와 정답 누수의 차이를 설명하는 것이다. 구현물은99,677행 위치 장부·82척/어업 요약·12개 독립 거리 질의·사건별 가용성·자원/hash 기록이다. 관찰은 좌표 유효성, 과거 수와 날짜, 최단 거리와 원행, 동료 이력의 가용성이다. 검증은 좌표 범위·현재/미래 제외·창 경계·거리 동률·독립 집계/표본 거리·정답 전 장부 동결이다. 설명 질문은 ‘반복해서 나타난 위치를 왜 정상 대기나 항만이라고 확정할 수 없는가?’다.

범위 밖은 중단된 small-run 조건 변경, 실제 항로/항만/대기/통신/속력, 모델 학습, Test B 새 추론과 제출 변경이다. 본인 학습자용 설명이며 학습자의 실제 설명 능력 성취는 별도로 평가하지 않았다. 실제 장치 실험은 없다.

## 채택한 접근과 보존한 대안

Round9 결과를 독립 검토한 Terra는 자기 과거 중심까지의 최근접 구면거리와 이력 가용성을 먼저 점검하자고 제안했다. Sonnet은0.05도 셀의 자기 방문 빈도로 공간 낯섦을 즉시 평가하자고 제안했다. 총책임자는 현재 자료가 무엇을 나타내는지 먼저 확인하고 임의 셀 경계 효과를 추가하지 않기 위해 연속 거리 대리값 가용성 점검을 선택했다. 두 제안과 채택 이유는 이전 회차 FINAL_RESULT_RECONCILIATION.md에 보존했다.

‘흔한 위치의 정상 대기 오탐이 자동 억제된다’는 해석은 검증되지 않아 채택하지 않았다. 현재 정상/대기/위양성 라벨이 없다. 먼 위치가 정상 새 조업지일 수도 있고 가까운 위치에서 사고가 날 수도 있으므로 거리와 사고를 동치로 보지 않는다.

## 입력·가정·고정 계산

R4 숫자 장부의 rfid_id,ts,source_ordinal,cen_lon,cen_lat99,677행/82척과 R3 단일 어업 코드를 사용했다. 원 CSV/캐시 재추출이나 외부 수집은 하지 않았다. 유효 좌표는 유한 경도[−180,180],위도[−90,90]다. len/bbox/기존 점수로 위치 가용성을 필터링하지 않았다. 실제 시간대·정확 CRS·점별 시각·정상 행동·항만·확정 사고 신원은 미확인이다.

시각 t의 과거는 같은 RFID의 유효 중심 중[t−720,t)다. 현재·미래를 제외하며 정확한 t−720은 포함한다.24개 이상·source-clock 날짜3일 이상일 때 현재 유효 중심에서 과거 중심까지의 haversine 최소 거리를 계산했다. 기존 반경6,371,000m 가정이며 실제 측지 정확도의 실측이 아니다. 동일한 최소 거리이면 이른 시각·작은 ordinal을 선택했다. 다른 과거 시각에 같은 좌표가 반복되면0m가 허용된다. 부분선 사이를 연결하지 않았다.

어업 추가는 동일 시각 t에 같은 과거24/3 조건을 만족하는 다른 동일 단일 어업 선박이5척 이상인지 가용성만 센 것이다. 동료의 현재 관측은 필수 조건이 아니다. 자기 과거 부족과 동료 부족은 유보하며 정상으로 간주하지 않는다. singleton인 채낚기연승낚시는 자기 거리 계산이 가능해도 동료 단계가 유보된다.

Luna의12개 합성 검사에는 좌표 결측/범위,0거리,알려진 구면거리,현재·미래 제외,720/721시간 경계,24/23개·3일 조건,동률,현재 관측 없는 동료,미래 추가 불변성과 잘못된 키 거부가 포함됐다. 검사 전후 코드 hash가 일치했다. 실제 숫자 probe는1회 실행했고4.634초·최대175.94MiB였다.

Gemini는 Luna 모듈/장부를 읽지 않고 이력 적격과 동료 가용성을 독립 집계했다. 어업별로 적격 관측이 있는 최소 RFID를 골라 첫/중간/마지막 질의12개에서 scalar haversine 최근접 거리·원행·참조 수/날짜를 계산했다. 이는4선박×3질의이며 사고12사례가 아니다. 실제 독립 계산은4.153초·최대125.64MiB였다.

Root는 원 장부의 모든 키·순서·복사 중심좌표를 확인하고,82척별 다섯 수치 집계와12개 거리/이웃을 대조했다. 현재/미래가 최근접 이웃에 들어가지 않았는지 확인했다. 유효성→자기→동료의 단계 포함도 확인했다. ROOT_VALIDATION.json과distance_concordance.csv에 결과를 저장했고 **이 검증 이후에만** 기존 사고표를 파싱했다. 입력 장부 hash가 검증 중 바뀌지 않았음을 확인했다.

## 사건창 가용성과 사전 기준

| 범위 | 자기 적격 관측이 있는±6h 창 | 동료 추가 적격 관측이 있는±6h 창 |
|---|---:|---:|
| 전체 | 92/100 | 91/100 |
| Tier0–1 | 53/60 | 53/60 |

선박 전체 기간 중 동료 적격 관측이 하나 이상 있는 선박은79척이다. 사전 기준은 Tier01 자기 적격 사건창50/60 이상, 동료 적격 선박6척 이상이었다. 실제53과79로 둘 다 통과했다. 이 수치는 자료 가용성의 탐색 시작선이며 통계적 성능 증명이나 기존4개 적중 관문을 대체하지 않는다. 사건창에 적격 관측이 없음과 선박 전체의 이력 부재도 구분했다.

root 검증은root_validation_001에 저장했고 예측 파일이나 hit-rate/precision/F1은 생성하지 않았다. 각 사건에 자기·동료 적격이 있는지만 기록했다. 적격 사건만 남기는 새 성능 분모를 만들지 않았다. 다음 성능 평가를 한다면 기존 전체100/82 및 Tier01 60/55 분모를 유지해야 한다.

## 자원·계보와 해석의 한계

각 작업 전 RAM과 다른 Python 작업을 확인했다. 실제 probe는 가용4450.40MiB에서 Luna768+Gemini512+여유640MiB를 보수적으로 확보했다. root 검증 직전 가용4428.9MiB, 추가1280+여유640MiB를 확인했고 실행기에서도 다시 확인했다. 원자료 전체 좌표 쌍 행렬을 만들지 않고 선박별720시간 이내 과거 벡터를 사용했다. 사용자 프로세스 종료나 RAM polling은 하지 않았다.

실행 코드·입력·출력 hash와 전후 안정성은 각 EXECUTION/OUTPUT_HASHES 및root검증에 기록됐다. 실제 probe hash는efb6f3c1b9a8256dcd5c7773b43f3c7f740705e649f15a7e365579729b0a1ddb, 위치 parquet hash는c3943c953143a4f71335bfa8cceadac6c96b30287f40a935e41b375a429b63b8이다. 이전 회차나 원본은 수정하지 않았다.

위치 대리값은 관측 밀도·좌표 양자화·다중 부분선 평균·운항 해역에 영향을 받는다. 반복 위치가 정상/항만이라는 정답은 없고, 낯선 위치가 사고라는 근거도 이번에 평가하지 않았다. 이번은 계산 가용성·표본 수치 검증까지이며 실제 항로 추종 및 사고 탐지 코어를 완성한 결과가 아니다.

## 다음 결정

다음 점수 설계를 위한 자료 가용성은 확인됐다. 두 중간관리자는 이 결과와 한계를 대조해 **한 가지 고정된 자기 위치 변화 점수와 어업 추가 규칙**을 제안한다. 지금까지 실패한 크기·run 길이·재개·형상 문턱은 재탐색하지 않는다. 가용성 결과로 어느 사고만 적격했는지 골라 점수/임계값을 맞추지 않는다. 후속 성능은 기존 G−B0 Tier01 top1+5%p·paired CI하한>0·전체 비악화·같은 풀 random 초과 네 관문을 모두 만족해야 한다.

제출 가능한 개선 결과는 아직 없다. 이번 가용성 통과를 제출 성과로 표현하지 않으며 Test B 추론·제출 파일 변경·외부 업로드·신규 학습은 수행하지 않았다.
