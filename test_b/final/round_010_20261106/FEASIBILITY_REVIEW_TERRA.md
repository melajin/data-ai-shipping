# Round10 가용성 독립 검토와 단일 위치 점수 제안

## 확인한 결과와 해석 범위

두 `per_vessel.csv`의 82개 RFID와 관측·유효 좌표·자기 적격·peer 적격 행 수를 다시 대조해 모두 일치했다. 합계는 각각 99,677, 99,677, 96,976, 94,525행이고 peer 적격 관측이 한 번 이상인 선박은 79척이다. `distance_concordance.csv` 12질의의 최대 거리 차이는 약 `1.82e-12m`이며, 이는 4척×최대 3개 질의의 표본 검산이다. 독립 검증 결과는 이웃 원행과 참조 수/날짜도 일치했다고 기록한다. 전체 거리의 독립 재계산을 본 검토에서 수행한 것은 아니다.

저장된 위치 parquet SHA-256을 직접 계산해 `c3943c953143a4f71335bfa8cceadac6c96b30287f40a935e41b375a429b63b8`과 일치시켰다. `ROOT_VALIDATION.json`은 82척 집계와 12질의 대조가 사건 라벨을 읽기 전에 완료됐다고 기록한다. 사건별 가용성 파일은 100행이며 기존 availability gate는 전체 자기 92/100·peer 91/100, Tier01 자기 53/60·peer 53/60, peer 가능 RFID 79척으로 고정 시작 기준을 통과했다. **예측이나 적중률은 이 회차에 산출되지 않았고, 이 통과는 네 성능 관문을 대체하지 않는다.**

기존 probe 코드는 현재가 아닌 `[t−720,t)` 좌표, 현재 행/미래 제외, 자기 24개·3 source-clock 날짜, 다른 같은 단일 어업 선박 5척 조건을 사용한다. 반복 좌표의 0m는 허용하며 이웃이 같은 시각·미래가 아닌지 원행 계보가 저장된다. 이는 정확 CRS나 물리적 항로, 항만, 정상 대기를 입증하지 않는다. Sonnet의 이전 0.05도 격자 제안은 계산과 설명이 단순한 장점이 있으나 임의 격자 경계의 영향을 받으며 반복 셀을 정상 대기라고 볼 근거가 없다. 총괄이 선택한 연속 거리 대리값을 유지한다.

## 다음 한 가지 고정 실험: 과거 거리의 상위 경험순위

가설은 **현재 시간행의 중심이 같은 배의 과거 중심과 비교해 평소보다 멀리 떨어져 있는 정도가 사고 관련 시각 선택에 기여하는가**다. 거리 자체를 선박 간 직접 비교하기보다 각 선박이 기존에 보인 거리 분포로 정규화한다. 이는 관측 밀도와 해역 범위 차이를 일부 설명하려는 설계 가정이며 효과나 정상성을 보장하지 않는다. 위치가 낯선 정상 조업일 수도, 익숙한 위치의 사고일 수도 있으므로 한쪽 꼬리 점수는 사고 확률이 아니다.

### 입력과 시간 기준

- 기존 R10 `position_ledger.parquet`의 전체 82척·99,677시간행의 `nearest_distance_m`, `own_distance_eligible`, 원행 key와 기존 숫자 장부의 `len_m,bbox_m,score`를 `rfid_id,ts,source_ordinal` 1:1로 결합한다. 결합 전 키 유일성과 정수 source-clock 시간·동일 key 집합, 행 보존을 검사한다. R3 단일 어업등록을 RFID로 결합한다. 0m는 유효하다.
- R10의 거리 `d_v(s)`는 s 자신의 유효 과거 중심 `[s−720,s)`에 대한 최단 거리다. 현재 후보 t의 **거리 분포 참조**는 같은 배의 `d_v(s)`가 유효한 s 중 `[t−720,t)`에 있는 행으로 고정한다. 그 각 거리 계산의 기저 좌표는 s보다 엄격히 이전이므로 전체 기원은 t−1440까지 갈 수 있다. 현재 거리·미래·사고시간/좌표는 자기 또는 peer 참조에 넣지 않는다.
- 분포 참조는 거리값 24개 이상·그 source-clock 날짜 3일 이상일 때 적격이다. R10의 24개 과거 **좌표** 적격과 여기의 24개 과거 **거리값** 적격은 다르며 후자의 실제 coverage는 아직 미확인이다. 이중 이력 조건이 초기 관측과 희소 선박을 더 줄일 수 있다.

### 순차 규칙과 예측 API

기존 범용 평가기에 `build_position_rules(frame,gear_registry) -> {ledger,predictions,pool_manifest,diagnostics,stage_spec}`을 제공한다. 각 행의 s0~s4 마스크·keep/reject/defer/not_applicable·이유, 거리 이웃의 원행, 참조 수·날짜, self/peer 점수, pool·fallback·cap을 보존한다.

1. **s0/B0:** 유효 비음수 len/bbox와 유한 기존 score인 시간행. B0는 전체 s0를 기존 score 내림차순, 시간·ordinal 오름차순으로 순위화한다.
2. **s1:** s0이면서 현재 좌표 유효하고 R10 자기 이력 적격이며 `nearest_distance_m`이 유한·비음수인 행. 위치나 이력 부족은 `defer`, 상위 실패는 `not_applicable`이다. 사건 정답이나 small/non-small 구분으로 후보를 고르지 않는다.
3. **s2/S:** s1에서 자기 과거 거리값 24개·3일 조건을 만족한 경우 `p_self=(과거 거리 < 현재 d의 개수 + 0.5×동률 개수)/n`을 계산한다. S는 s2를 `p_self` 내림차순, 기존 score 내림차순, 시간·ordinal 오름차순으로 고른다. 큰 과거 상대 거리를 우선하는 단측 규칙은 결과를 보기 전에 고정한다. s2가 선박 전체에서 비면 S는 s0/B0 순위로 fallback한다.
4. **s3:** s2의 현재 거리 d에 대하여, 같은 단일 어업의 다른 RFID 각각이 동일 t의 과거 거리값 `[t−720,t)`에서 24개·3일을 충족하면 그 선박 분포에 대해 같은 `p_peer`를 계산한다. 다른 선박의 현재 관측은 요구하지 않는다. 적격 **다른 5척 이상**이면 선박별 `p_peer`를 한 번씩 균등 평균하고, singleton·혼합/미확인 어업·부족은 `defer`다. 이 peer 기준은 다른 배들의 자기-과거 최단 거리 분포이지 두 배 사이 거리나 실제 어구 동작이 아니다.
5. **s4/G:** s3 행을 G의 풀로 사용하고 `p_self` 내림차순을 첫째, 균등 평균 `p_peer` 내림차순을 둘째, 기존 score 내림차순, 시간·ordinal 오름차순으로 고른다. s4가 선박 전체에서 비면 G는 S의 실제 풀·순위로 fallback한다. 자기 경험순위가 동률일 때에만 어업 점수가 순서를 바꾸므로 동률 및 동일 풀 내 peer 적용 전후 top1/top4 변경을 별도로 집계한다. 효과가 작아도 결과를 보고 순위를 바꾸지 않는다.

세 방법은 RFID마다 `min(4, G 실제 풀 크기)`의 동일 cap을 쓴다. G/S/B0의 실제 풀은 각각 다를 수 있으므로 후보 수가 적은 경우에도 같은 cap을 적용하고, 예측이 없는 사건은 전체 분모의 miss로 둔다. top1은 같은 top4 목록의 첫 시각이고 동일 RFID의 모든 잠정 사건에는 같은 예측 목록을 쓴다. 예측·풀·장부와 해시를 사고표를 읽기 전에 고정한다. 사고창은 오직 사후 평가와 coverage 보고에 사용한다.

### 평가와 사전 중단

전체 100사건/82척, Tier01 60사건/55척, ±6시간 포함을 유지한다. B0/S/G 각각의 실제 풀에서 같은 후보 수의 사건별 무작위 기대를 별도로 계산하고 RFID paired bootstrap 4,000회, seed `20261105`를 쓴다. 주비교는 오직 Tier01 G−B0 top1이며 다음 네 조건을 모두 충족해야 탐색적 개선이다: **+5%p 이상**, paired 95% 구간 하한 양수, 전체 100건 top1 비악화, Tier01 G가 같은 Tier01 G 실제 풀의 무작위 기대 초과. +5%p 경계는 사건 수 정수 비교로 처리한다. S/top4 결과나 특정 사건군만 선택해 주관문을 바꾸지 않는다.

단계별 전체 행·선박·사건창 coverage, 사유, 유보/fallback, G와 S의 풀 차이 및 peer 동률 영향을 보고한다. 전체 창 coverage와 선박 전체 fallback을 구분한다. 이중 이력 부족이나 미관측을 분모에서 지우지 않는다. 불변/누수·key·시간/예산·peer 자기 제외·0거리/동률·미관측 선박·두 코호트 random 집계·정확 5%p 경계는 작은 합성 검사로 확인한다. 데이터 실행 직전에 RAM, 예상 최대 사용량 및 동시 실행을 다시 확인하고 부족하면 보류하거나 순차 처리한다.

네 관문 중 하나라도 실패하거나 실제 입력/예측 동결/풀 검증이 실패하면 이 방법을 개선 제출안으로 채택하지 않는다. 사건창 결과를 보고 이력 길이·거리 꼬리·순위 우선순위를 바꾸거나 격자/기간을 훑지 않는다. 독립 검증 자료가 없으므로 통과하더라도 반복 사용한 개발셋의 탐색 결과로만 기록한다. 정상/대기 정답이 없어 오경보 억제를 주장하거나 실제 false-positive rate를 계산하지 않는다.

## 다섯 가지 코어 시작 점검

1. **해당 코어:** 동일 선박의 과거 관측 공간과 현재 중심의 관계를 공통 규칙으로 살피고 같은 어업의 관측 분포를 추가한다. 실제 선로 추종의 증거와 구분한다.
2. **다른 문제/범위 밖:** 중단한 small-run/onset/duration/resumption이나 R8 형상 문턱 재탐색, 항만·실제 대기·속력·사고 원인 판정, 새 모델 학습·외부 수집·제출 변경은 하지 않는다.
3. **기술·학습 목표:** 기술 산출물은 원행 추적 가능한 순차 장부·동일 예산 예측·사건 비교다. 학습 질문은 “평균 중심이 왜 실제 항로가 아닐 수 있는가, 멀거나 반복된 위치가 왜 사고/정상을 확정하지 못하는가?”다. 과거 참조·관측 밀도·peer 유보와 적중 결과를 함께 설명한다.
4. **확인 입력과 미확인:** R10의 동결 위치 장부, R4 숫자 장부, R3 Train 어업 코드와 잠정 사건표가 사용 가능하다. 정확 CRS·원 시간대·점별 시간·항만·정상 대기/행동·확정 신원 및 제출 대상 어업코드는 미확인이다. 시간행 전체 자료의 사후 선택이며 온라인 조기경보가 아니다.
5. **다음 관문:** key·거리/분포의 엄격 과거·단계/풀·동결 예측과 같은 예산을 검증한 뒤 고정 네 성능 조건을 함께 판정한다. 수학적·소프트웨어 검사나 가용성 통과는 학습자 이해와 실제 사고 성능을 대신하지 않는다.
