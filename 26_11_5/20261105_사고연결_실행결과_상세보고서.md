# 2026 사고–항적 연결 실행 결과 상세 보고서

## 1. 결론

**2026년 사고 목록과 2026년 학습 항적을 연결한 후보표를 만들고 독립 검산까지 완료했다.** 전달받은 기존 결과인 **167건 중 후보 존재 118건, 단일 후보 30건**을 직접 읽은 캐시로 재현했다. 기존 2025 항적과 2026 사고를 비교한 0건 결과를 사고 탐지 실패로 해석해서는 안 된다.

다만 이번에는 단일 후보의 안정성까지 확인했다. 중요한 결과는 다음과 같다.

- 기존 조건의 단일 후보 30건 중 **9가지 조건 모두에서 같은 한 척이 남은 사건은 1건**이다.
- 시간 범위를 앞뒤 한 시간 더 넓히면 **7건은 다후보로 바뀐다.**
- 단일 후보 30건 중 **3건은 사고 목록에 사고선박수가 2척으로 기록돼 있다.**
- 따라서 30건을 곧바로 사고 학습 정답으로 사용하는 것은 근거가 부족하다.

현재 확보한 것은 **원본 사건–후보 선박–조건별 근거를 추적할 수 있는 연결 후보표**다. 사고선박 신원을 확정한 정답표나 사고 탐지 성능표가 아니다.

기술적 완료는 후보 생성·재현·민감도 분석·검산이며, 사고 탐지 성능은 아직 평가하지 않았다. 기존 테스트 점수·제출 파일은 변경하지 않았다.

## 3. 무엇을 ‘연결 후보’로 계산했는가

### 3.1 기존 조건의 정확한 의미

기존 재현 조건은 다음 두 조건을 모두 만족하는 항적행이다.

1. 항적 시간대와 `floor(사고 발생시각, 1시간)`의 차이가 앞뒤 1시간 버킷 이내.
2. 사고 좌표와 캐시의 항적 중심점 사이 구면거리가 5km 이하.

이것은 실제 분·초 기준의 ±60분 검사가 아니다. 예를 들어 사고가 17:58이면 16시·17시·18시 시간대의 행이 선택된다. 16시 시간대 시작과 사고시각은 118분 차이지만 조건에는 들어올 수 있다.

항적행의 시간은 `[시간대 시작, 다음 시간대 시작)` 구간으로 다뤘다. 실제 좌표별 시각이 없으므로 그 안의 어떤 순간에 사고 좌표 가까이에 있었는지는 알 수 없다. 원자료의 시간대가 같은 시간 기준이라는 가정으로 비교했고, 별도의 시간대 변환 근거는 확보하지 않았다.

거리에는 지구 반지름 6,371,000m인 구면 거리 계산을 사용했다. **캐시 중심 대리점까지의 거리**이며 실제 항적의 최근접 거리나 사고 순간 선박 위치 오차가 아니다. 비교 전 반올림하지 않고 `거리 ≤ 경계값`을 적용했다.

### 3.2 한 사건에서 후보 수를 세는 방법

같은 선박의 여러 항적행이 조건을 만족해도 고유 RFID는 한 번 센다. 후보 관계별로 다음 근거는 따로 보존했다.

- 조건을 만족한 항적행 수와 고유 시간대 수.
- 중심점 거리가 가장 작은 원본 행.
- 사고시각과 시간구간의 차이가 가장 작은 원본 행.
- 각 행의 캐시 파일명, 저장된 원본 행 인덱스, 캐시 내부 행 위치.
- 원 사고 분·초, 시간구간 시작·종료, 구간 시작과 사고시각의 부호 있는 분차.

거리 최소 행과 시간 최소 행은 서로 다를 수 있다. 두 행의 좋은 값만 섞어서 실제 존재하지 않는 한 관측처럼 만들지 않았다.

표본 검사는 모든 후보 관계를 원자료에서 독립 재계산했다는 뜻이 아니다. 집계·관계·메타데이터 검사는 저장된 전체 결과를 대상으로 했다.

### 7.2 파생 검토표: 31개 검사 통과

### 7.3 합성 코드 검사와 실제자료 검산의 구분

구현 담당의 내장 자체검사는 시간 버킷과 분차의 구분, 반개구간 끝점, 5km 포함 경계, 거리 단위, 다후보 보존, NaT·NaN 보존, 배치 유효성·원행 추적 등 13항목을 통과했다. 이는 합성 입력에 대한 코드 검사다.

본 167건과 388만 행 계산은 실제자료의 근접 후보 감사다. 코드 검사 통과나 실제자료 계산 완료를 실제 사고 탐지 성능 또는 선박 안전성 검증으로 표현하지 않는다.

### 7.4 실행 중 수정한 문제

본 후보 연결 감사는 첫 실행에서 종료코드 0으로 완료했다.

파생 단일 후보표의 첫 생성은 `one_to_one` 병합 검사에서 종료코드 1로 실패했다. 왼쪽에는 단일 후보 사건만 있었지만 오른쪽에는 다후보 사건도 포함돼 있어 전체 오른쪽 키 유일성 검사가 실패한 것이다. **오른쪽도 단일 후보 사건으로 제한한 뒤, 유일성 검사를 유지한 상태로 재실행해 종료코드 0을 확인했다.**

첫 실패는 파생 파일을 쓰기 전에 발생했고 본 연결 결과에는 영향을 주지 않았다. 실패 코드와 원인은 [실패 기록](accident_linkage_audit_20261105/execution_001/derived_attempt1_failure.json), 수정 전 코드는 [보존본](accident_linkage_audit_20261105/execution_001/build_review_queue_attempt1.py), 재실행 종료코드는 [파생 실행 기록](accident_linkage_audit_20261105/execution_001/derived_process_result.json)에 남겼다.

사전 환경 확인 중 PowerShell의 Python stdin 전달에서 한글 경로가 깨져 실패한 읽기 전용 점검 1회도 있었다. 경로를 명령행 인자로 전달해 환경을 다시 확인했다. 본 감사에는 저장된 UTF-8 스크립트와 인자를 사용했다.

## 9. 다음 단계와 진행 기준

### 9.1 먼저 할 일

1. **E0023부터 원 항적·사고 메타데이터를 확인한다.** 가장 안정적인 후보를 먼저 볼 수 있다는 의미이며 이 사건을 곧바로 정답으로 선택하는 것은 아니다.
2. **다선박 단일 후보 3건과 확대 시 다후보가 되는 7건을 검토한다.** 잘못된 일대일 연결을 방지하는 데 직접 도움이 된다.
3. **사고파일과 RFID를 직접 연결할 추가 근거를 확인한다.** 선박 제원 레지스트리가 없다면 사고 목록의 선종·톤수만으로 후보를 제거할 수 없다. 이번 후보표에도 제원 필터를 적용하지 않았다.
4. **사고자료의 개발용 사용 범위와 정상 사례 근거를 정리한다.** 사고 목록에 없다는 이유만으로 정상 라벨을 만들지 않는다.

### 9.2 임계값·A/B/C 비교로 넘어가는 조건

- 후보 연결의 신뢰도를 구분하고, 어떤 연결을 어떤 근거로 사용할지 정한다.
- 규칙을 정할 사건·선박과 결과를 확인할 사건·선박을 분리한다.
- 사고시각을 기준으로 평가 구간을 미리 좁혀 예측을 만들지 않는다. 전체 평가 기간에서 예측을 먼저 고정한 뒤 정답과 대조한다.
- 모델·전처리·임계값·지속 조건은 허용된 개발 자료에서만 정하고 고정한다.
- 시각오차 통계는 신원이 검증된 사건 또는 연결 불확실성을 명시한 탐색적 집단에 한정한다. 공식 시간오차 F1 식이 없으면 내부 지표로 표시한다.

그 후에 최고점(A), 시작점(B), 시작점의 지속 근거(C)를 비교할 수 있다. 같은 구간에서 C가 통과하면 C시각=B시각이므로, 독립적인 세 모델의 투표로 해석하지 않는다.

### 9.3 이번에 하지 않은 작업

확정 사고 라벨 생성, 정상 라벨 생성, 임계값 학습, 새 모델 학습, A/B/C 탐지 성능 계산, 참조지도 제외 재학습·재계산, Test B 제출 파일 변경, 공식 제출은 수행하지 않았다. 이들은 이번 후보 연결 감사의 완료와 구분한다.
