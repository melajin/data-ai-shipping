# Round63 경험을 다른 문제에 쓰기

[프로젝트 시스템·근거 정리](../project/test_a/07_Round63_전체시스템과_판단.md)에서 다른 작업에 가져갈 수 있는 판단을 추출한다. 상태는 **한 프로젝트에 근거한 경험 관찰 또는 재사용 후보**다. 다른 프로젝트에서의 교차 검증과 운용 성숙도는 확인되지 않았다.

## 1. 관측 단위에 맞춰 물리량을 정의한다

**앞선 문제와 근거.** 항적을 선으로 그릴 수 있어도 선 위의 각 좌표가 언제 관측됐는지는 알 수 없었다. Round63은 관측일·시간키와 MultiLineString을 사용하면서 떨어진 부분을 잇거나 좌표별 시각·속도를 만들지 않는다. 공간 배치 특징에는 EPSG:5179 투영을 명시한다. ([모델 설명](../../test_a/deliverables/round63_submission_20261106/docs/과제1_모델설명.md))

**도출 원리 — 재사용 후보.** 데이터가 직접 제공하는 단위, 파생값을 만드는 가정, 실제 확인한 값을 구분한다. 관측 구간의 시간값이 있어도 각 좌표의 시간값이 없으면 점별 실제 속력·가속도를 결정할 수 없다. 좌표계와 투영은 각 데이터의 명세와 코드에서 따로 확인한다.

**절차.** 한 행과 좌표의 뜻을 적고, 시각·좌표계·단위·분리 구간을 확인한다. 계산에 필요한 정보가 없으면 미확인으로 둔다. 가정을 도입했다면 실측값과 별도 표시한다.

**실패 조건과 응용 가설.** 생산 설비의 구간별 상태 로그에도 적용할 수 있다. 공통 구조는 연속 과정이 요약 구간으로만 보인다는 점이고 단위 계약 점검은 그대로 쓴다. 설비는 센서 수신 지연·집계 방식이 다르므로 구간 경계와 원 센서 기록을 대조해야 한다. 해당 분야 적용 결과는 없다.

## 2. 도메인 차이를 성능 개선으로 곧장 바꾸지 않는다

**앞선 문제와 근거.** Test B는 조업 유형별 정상 항적 차이를 바탕으로 어업별 기준 G를 시험했다. 2026년 잠정 연결 개발 100사건에서 G의 ±6시간 적중은 1건, 같은 조건 B0는 3건이었다. 이는 유형별 차이가 없다는 증명이 아니라 시험한 규칙이 기준선을 넘지 못했다는 결과다. ([실험과 기준](../project/test_b/03_final_round001_012_재구성.md))

**도출 원리 — 경험 관찰.** 집단별 분포 차이, 이를 이용한 규칙, 목적 지표 개선은 다른 주장이다. 새로운 집단이나 예측된 유형의 오류를 포함하면 성능이 달라질 수 있다.

**절차.** 유형별 관측 차이와 표본 수를 적고, 유형을 실제로 아는지 모델이 예측하는지 구분한다. 기본 규칙과 변경 규칙을 같은 사건·조건에서 사전 기준으로 비교하고 분류 오류·결측·소수 집단 성능을 확인한다.

**응용 가설.** 설비 종류별 고장 경보에도 집단별 분포 확인과 동일 조건 비교를 적용할 수 있다. 설비별 고장 정답·환경과 오경보 비용은 새로 확인해야 하며, 다른 분야에서 검증하지 않았다.

## 3. 평균 성능과 어려운 집단을 함께 본다

**앞선 문제와 근거.** Round63 개발 REPORT는 1,475척 중 903척 정답, micro-F1 0.612203이었지만 같은 표에서 통발 재현율은 0.177033이었다. ([클래스별 표](../../test_a/deliverables/round63_submission_20261106/docs/과제1_모델설명.md))

**도출 원리 — 재사용 후보.** 전체 점수 하나로는 작은 집단의 실패가 가려질 수 있다. 전체 성능과 클래스별 표본 수·precision·recall·F1을 같은 평가 모집단과 함께 기록한다. 소수 클래스 보호 기준과 미달 시 처리는 목적에 맞게 사전에 정한다.

**응용 가설과 한계.** 불량품 분류처럼 희귀 클래스를 다루는 문제에 점검표를 쓸 수 있다. 이 프로젝트의 가중치나 숫자 기준은 그대로 옮길 수 없고 희귀 사건의 표본 수·누락 비용·불확실성을 새로 평가해야 한다. 한 REPORT 결과로 새 집단의 성능을 장담하지 않는다.

## 4. 재현과 일반화를 구분한다

**앞선 문제와 근거.** Round63 기록에는 TUNE·REPORT 2,949척의 재구현 예측 변경 0, 선택한 네 척의 특징 1,348개 값 차이 0이 있다. REPORT는 개발 검토에 사용됐다. 이는 구현 재현 근거이지 처음 보는 표본의 성능은 아니다. ([추론 회귀](../../test_a/deliverables/round63_submission_20261106/validation/report_regression.json), [특징 회귀](../../test_a/deliverables/round63_submission_20261106/validation/feature_regression.json), [원본 설명](../../test_a/deliverables/round63_submission_20261106/README.md))

**도출 원리 — 재사용 후보.** 같은 입력·환경의 결과를 되살리는 검사와 새 자료에서 성능을 재는 검사는 목적이 다르다. 입력·표본·비교 대상·측정값·환경을 함께 보존한다. 선택에 사용한 데이터는 최종 독립 검증으로 이름을 바꿔 쓰지 않는다.

**절차.** 고정 입력의 특징·출력 비교 → 파일 해시와 환경 기록 → 선택 절차가 닿지 않은 자료의 목적 지표 평가 순으로 진행한다. 실패 시 원자료·계약·전처리·모델·전달 계층으로 좁힌다. 독립 자료가 없다면 미측정으로 둔다.

**응용 가설.** 센서 예지보전 모델에도 같은 구분을 적용할 수 있다. 출력 비교 절차는 옮길 수 있지만 정답 확정 시점, 시간 분할, 집단 이동과 손실 함수는 다시 정해야 한다.

## 5. 파일 통합과 모델 연동은 별도로 검증한다

**앞선 문제와 근거.** 제출 스크립트는 Test A 분류 CSV와 저장된 Test B 후보표를 같은 엑셀에 합친다. 읽은 코드에는 Test A 분류 결과를 Test B 점수 함수에 넣는 단계가 없다. ([통합 코드](../../test_a/deliverables/round63_submission_20261106/scripts/export_integrated.py), [Test B 설명](../../test_b/deliverables/testb_system_20261106/README.md))

**도출 원리 — 재사용 후보.** 파일이 한곳에 모였는지와 한 구성요소의 출력이 다른 구성요소의 입력을 바꾸는지는 각각 확인한다. 식별자·시각·단위·누락 상태와 데이터 가용 시점을 계약으로 명시하고 실제 전달 경로를 코드와 산출물로 대조한다.

**응용 가설.** 여러 병원 검사 결과를 하나의 보고서로 합치는 경우에도 유용할 수 있다. 검사 시점·환자 식별·임상 검증과 개인정보 조건은 새로 검토해야 한다. 이 통합 엑셀만으로 다른 분야의 운영 효과는 주장할 수 없다.

## 기존 개인 지식과의 관계

[기존 도메인 초안 A1~A4](2026-11-07%20A%20도메인%20지식%20어선%20AIS%20항적%20자료의%20특성.md)는 당시의 기록으로 남긴다. 다만 관측 공백을 정상 입항으로 단정한 문장, 사고가 항차 내부에서 100% 발생한다는 일반화, 모든 시간 정보·거리 계산이 없다는 문장은 원자료 조건을 다시 확인해야 한다. 관측 시간키와 좌표별 시각, 투영 계산과 실측을 구분한다.
