# 현재 상태와 패키징

## 1. 고정 기준선(B0) 및 재현 검증 상태

Test B의 최종 파이프라인은 고정 기준선(B0, `frozen_baseline.py`)으로 확정되었다(`deliverables/testb_system_20261106/README.md`, `제출결과물/README_TestB.md`). 새로운 가중치를 학습하거나 사고 탐지 성능을 사후적으로 억지 개선했다고 주장하지 않고, 데이터 경계와 검증된 기준선을 재현 가능한 독립 실행 패키지로 완성했다(`deliverables/testb_system_20261106/README.md`).

2025년 Test B 평가 대상 100척(46,705행)에 대해 저장된 기하 입력과 고정 참조자료로부터 점수를 처음부터 다시 계산하고 보관된 결과와 전수 대조한 결과는 다음과 같다(`deliverables/testb_system_20261106/README.md`, `제출결과물/README_TestB.md`).

| 검증 항목 | 대조 결과 | 의미 |
|---|---:|---|
| 비교 대상 행 수 | 46,705행 / 100척 | 2025년 시간대별 항적 기하 요약 |
| `s_zone`·`s_change`·`s_gap`·`score` 최대 절대차 | **0.0** | 보관된 원 저장 점수와 전수 일치 (Parity 0.0) |
| 결측 위치 불일치 | 0건 | 4개 점수 열 결측 위치 전수 일치 |
| 상태(`state`) 불일치 | 0행 | 규칙 기반 상태 분류 일치 (실제 조업 정답 아님) |
| 후보 시각·원행 번호 불일치 | **0 / 100척** | 원본 동점 규칙(`source_ordinal` 최솟값)까지 전수 일치 |
| 실행 시간 | 33.4 ~ 41.21초 | CPU 단독 실행 |
| 최대 프로세스 메모리 | 298.69 ~ 299.30 MiB | 계획 예산(512 MiB) 이내 충족 |
| 점수 경계 단위 테스트 | 4개 통과 | 점수 바닥값 및 성분 함수 검사 |
| 시간순 입력 계약 테스트 | 26개 통과 | 실시간 입력 계약 및 격리 검사 |

후보 100척의 종합 이상점수 중위수는 0.548824이며 전체 46,705행의 점수 중위수는 0.349603이다(`제출결과물/인계메모_TestB_20261106.md`). 후보 100척 중 39척은 과거 관측이 24행에 미치지 못해 `s_change` 점수를 산출할 수 없었고, 6척은 과거 관측이 0행으로 정보가 심각히 부족한 상태였다(`제출결과물/인계메모_TestB_20261106.md`). 이러한 정보 부족 상태는 숨기지 않고 점수와 함께 나란히 출력되도록 설계되었다(`제출결과물/README_TestB.md`).

## 2. 정량 평가 지표 총괄 요약

Test B에서 최종 측정된 핵심 정량 지표와 평가 조건은 다음과 같다(`제출결과물/인계메모_TestB_20261106.md`, `testB/final/round_015_official_f1_20261106/ROUND015_공식F1_보고서_20261106.md`, `testB/final/round_021_internal_f1_judgement_20261106/ROUND021_판단근거와_내부F1.md`).

| 지표 항목 | 실측값 | 평가 조건 및 기준 |
|---|---:|---|
| **공식 규칙 F1** | **0.0366** | $\pm 6$시간 허용창, 82척, TP 3 · FP 79 · FN 79 (`round_015`) |
| 시간오차 중앙값 | 912.5시간 | 고정 기준선 B0 (100건 사건 대상) |
| 내부 $\pm 6$시간 적중 수 | 3/100 (기준선 B0) | 최고치 4/100 (동료 동시성 필터, 조업시간대 가중) |
| 전 선단 최고점 ROC AUC | 0.5756 | 2026 Train 전체 7,372척 대상 (양성 82척 대 음성 7,290척) |
| 전 선단 중심점 반경 AUC | 0.6073 | 위와 동일 |
| 전 선단 선박 선정 내부 F1 | 0.05283 | 최고점 $\ge 0.75$ 기준 183척 선정, 잠정 연결 선박 7척 포함 |
| 전 선단 시각 포함 사건 내부 F1 | 0.00000 | 183척 중 $\pm 6$시간 내 적중 시각 0건 |

### 성능 정체의 근본 원인 규명

연구 전반에 걸쳐 공식 F1이 0.0366에 머무는 원인은 세 가지 층위에서 실측으로 규명되었다(`제출결과물/TestA_요청사항_20261106.md`, `deliverables/testb_system_20261106/reports/어선_이상항적_시스템_결과보고서.md`).

1. **사고 유형과 기하 요약의 불일치**: 개발 정답 167건 중 기관손상 58건, 부유물감김 20건 등 추진 상실로 해상에서 정지하는 사고가 대다수를 차지한다(`제출결과물/TestA_요청사항_20261106.md`). 그러나 해당 사고창($\pm 6$시간)에서 `해상정지` 상태가 나타난 비율은 15.0%인 반면, 같은 선박의 평상시 기대 비율은 26.0%였다(`testB/final/round_016_state_signal_20261106/ROUND016_상태신호_기각_20261106.md`). 어선은 평소에도 투망, 양망, 물닻 대기로 멈춰 서기 때문에 1시간 단위 기하 요약치로는 일상 조업 정지와 사고 정지를 분별할 수 없다(`제출결과물/TestA_요청사항_20261106.md`).
2. **관측 공백의 정상 생활주기성**: 점수가 높은 후보 상당수가 관측 공백 후 재등장 시점이었으나, 인접 관측의 91.2%가 1시간 간격이고 전체 기간 커버리지가 10.4%에 불과한 데이터 구조상, 공백의 실체는 사고 통신 두절이 아니라 정상적인 입항 및 휴식 주기였다(`testB/과거/round_012_20261105/ROUND012_근본분석_쉬운설명_20261105.md`).
3. **공란 필터링의 역효과**: 적중한 3척 선박의 이상점수가 전체 중위값(0.5488)보다 낮았기 때문에, 점수 임계값을 올려 이상점수가 높은 선박만 남기면 맞힌 배부터 버려져 임계값 0.65 이상에서는 F1이 0이 되었다(`testB/final/round_015_official_f1_20261106/ROUND015_공식F1_보고서_20261106.md`, `제출결과물/인계메모_TestB_20261106.md`).

## 3. 실행 패키지 구조 (`deliverables/testb_system_20261106/`)

독립 실행 패키지는 `deliverables/testb_system_20261106/`에 구축되었으며, 외부 종속성 없이 자체 완결된 상대경로로 구동된다(`deliverables/testb_system_20261106/README.md`, `deliverables/testb_system_20261106/MANIFEST.json`).

| 경로 | 역할 및 구성 |
|---|---|
| `README.md` | 패키지 설명, 실행 방법, 환경 구성 및 재현 대조표 |
| `MANIFEST.json` | 63개 파일의 SHA-256 해시, 크기, 역할 메타데이터 |
| `config.json` | 실행 옵션, 임계값 미설정, 프로세스 메모리 예산(512 MiB) |
| `requirements.txt` | 고정된 Python 라이브러리 의존성 |
| `data/` | `observations.parquet`(46,705행 입력), `stored_expected.parquet`, `stored_candidates.csv` |
| `model/` | 고정 참조분포: `harbors.json`(항구 77점), `density.pkl`(밀도지도), `gap_cdf.npy`, `jump_cdf.npy`, `provenance.json` |
| `src/` | `frozen_baseline.py`(점수 계산 원형 함수), `run_analysis.py`(입력 검증→재계산→전수 대조→후보 출력 진입점) |
| `scripts/` | `run.ps1` (Windows PowerShell 실행 래퍼) |
| `notebooks/` | `TestB_이상항적_분석.ipynb` (데이터 확인부터 후보 출력까지 6단계 실행 노트북) |
| `figures/` | 점수 분포 1장, 실제 후보 사례 3장 |
| `reports/` | 19쪽 최종 보고서 PDF, 편집 원문(`어선_이상항적_시스템_결과보고서.md`), 빌드 코드(`build_report.py`), 검증 JSON |
| `results/reproduction_001/` | 실제 실행 산출물: `scored_rows.parquet`(전체 점수), `candidates.csv`(100척 근거), `summary.json`(재현 대조 결과) |
| `support/` | 독립 시간순 입력 계약 검증 코드 및 샘플 데이터 |
| `tests/` | 단위 테스트 코드 (점수 경계 테스트 4개, 입력 계약 테스트 26개) |

실행 명령은 패키지 루트에서 다음과 같이 수행된다(`deliverables/testb_system_20261106/README.md`).

```powershell
python src/run_analysis.py --output results/reproduction_new
python -m unittest discover -s tests -v
```

실행 시 입력·참조·소스 해시와 가용 RAM을 확인하며, 계획 예산 512 MiB와 여유 640 MiB가 확보되지 않으면 계산을 보류한다(`deliverables/testb_system_20261106/README.md`).

3. `인계메모_TestB_20261106.md`: Test A 담당자에게 전달된 인계 문서로, Test B 패키지 폴더 구조 유지 요청, 공식 F1 0.0366 수치와 근거 보존, 한계 서술 시 방어적 어투 배제 및 평서문 유지, clean 가상환경 재현 검증 절차를 명시했다(`제출결과물/인계메모_TestB_20261106.md`).

5. `demo/`: 추론 과정 데모영상(2분 8초)과 `DEMO_NOTES.md`가 포함되어 있다(`제출결과물/인계메모_TestB_20261106.md`).
