# Test B 개요와 공식 규칙

## 1. 과업의 목적과 배경

Test B는 어선 항적 데이터를 바탕으로 선박의 사고 발생 여부를 판별하고, 사고가 발생한 선박에 대해 사고 발생시각 하나를 추정하는 과업이다(`deliverables/testb_system_20261106/README.md`, `제출결과물/README_TestB.md`). 본 과업이 속한 대회 저장소(`D:\obsidian\claude\obsidian_export\DATA AI SHIPPING`)에는 조업형태 4종(연안복합, 자망, 통발, 채낚기연승)을 항적으로 분류하는 Test A 트랙과 이상항적 및 사고시각을 추정하는 Test B 트랙이 공존한다(`제출결과물/README_TestB.md`). Test A가 선박의 평상시 조업 유형 기준선을 정의한다면, Test B는 그 기준선에서의 이탈을 측정하여 사고를 국소화하는 구조를 갖는다(`제출결과물/README_TestB.md`).

Test B의 최종 정량 평가는 제출된 선박별 사고시각에 대한 시간오차를 고려한 F1으로 산출되며, 현재 고정 기준선(B0)에 대해 공식 규칙을 적용해 실측된 공식 F1은 0.0366이다(`testB/final/round_015_official_f1_20261106/ROUND015_공식F1_보고서_20261106.md`).

## 2. 주최 측 질의응답 및 확정된 공식 규칙

주최 측의 공식 질의응답을 통해 확인된 규칙과 설계 기준은 다음과 같다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`, `testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`, `docs/fishing_execution_plan.md`).

### 확정된 규칙

1. **동일 선박의 전체 항적 열람 허용**: 사고시각 추정에 동일 선박의 제공된 전체 항적을 활용할 수 있으며, 추정 대상 시각 이후의 항적을 열람하는 사후 분석이 허용된다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 따라서 온라인이나 인과적(causal) 제약은 적용되지 않는다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`).
2. **테스트 데이터 학습 금지**: 테스트 데이터는 예측 용도로만 사용해야 하며 모델 학습에는 사용할 수 없다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 테스트 데이터를 바탕으로 의사라벨 자기학습을 수행하거나 테스트 점수의 분위수를 임계값으로 적합하는 행위는 금지된다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`).
3. **정량 평가 지표와 6시간 허용창**: 정량 평가는 오직 사고시각 하나에 대해서만 시간오차를 고려한 F1으로 평가된다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 사고시각은 실제 시각과 가까울수록 고득점이며, "6시간을 넘어가면서부터는 0점 처리"된다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`).
4. **미사고 선박 전 칸 공란 제출**: 미사고로 판단한 선박은 예측 결과 칸 전체를 빈칸으로 제출한다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 템플릿의 식별자 행 구조는 유지하되 예측 결과 셀 전체를 공란 처리해야 한다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 미사고 선박에 사고시각을 기재하면 위양성(FP)으로 집계된다(`testB/final/CURRENT_STATUS.md`).
5. **정성 평가 요소**: 시각 1~3과 이상항적 점수는 정성평가에 반영된다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 따라서 다중 시각 후보와 점수 산출 근거를 설명 가능하게 유지해야 한다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`).
6. **제출 형식**: 제공된 `제출샘플.xlsx`의 `테스트B` 시트 형식(100행 9열)을 따른다(`testB/과거/round_007_20261105/ROUND007_보고서_20261105.md`). 열 구성은 `rfid_id`, `사고시각`, `이상항적 점수`, `시각1`, `시각1 이상항적 점수`, `시각2`, `시각2 이상항적 점수`, `시각3`, `시각3 이상항적 점수` 순이며, 시각 표기는 `YYYYMMDD H` 정수 시간 형식이다(`testB/과거/round_012_20261105/ROUND012_근본분석_쉬운설명_20261105.md`). 예시행의 일자 `20251027`은 테스트 기간 밖의 값으로 형식 예시일 뿐 정답이 아니다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`).

### 공식 규칙의 수학적 함의

공란 규칙과 6시간 허용창 규칙이 결합하면, 선박별 사고 판정 임계값이 정밀도(Precision)의 절반을 결정한다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`). 100척의 예측 칸을 모두 채우면 정밀도는 `TP/100`으로 고정된다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`). 허용창을 초과한 예측은 정답을 맞히지 못했으므로 위양성(FP)이자 해당 실제 사고를 놓친 위음성(FN)으로 동시에 집계된다(`testB/final/round_015_official_f1_20261106/ROUND015_공식F1_보고서_20261106.md`).

칸을 하나 추가할 때 적중 확률을 $q$, 전체 F1을 정의할 때 $q > F1 / 2$ 조건을 만족해야 F1이 상승한다(`testB/과거/round_012_20261105/ROUND012_근본분석_쉬운설명_20261105.md`). 따라서 낮은 적중률 상태에서는 공란을 늘려도 F1이 상승하지 않으며, 고신뢰 예측 구간이 확보되었을 때만 공란 전략이 F1을 방어할 수 있다(`testB/과거/round_012_20261105/ROUND012_근본분석_쉬운설명_20261105.md`).

## 3. 데이터 구조와 기간 불일치

프로젝트 초기 가장 큰 장애 요인은 데이터 기간 불일치였다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`).

| 자료명 | 기간 | 규모 | 비고 |
|---|---|---|---|
| Train 항적 (`vpass_26년(1월_6월)`) | 2026-01-01 ~ 2026-06-30 | 3,887,068행 / 7,372척 | `fishing_code` 포함, 기준 분포 생성용 |
| Test B 평가 항적 | 2025-01-01 ~ 2025-06-30 | 46,705행 / 100척 | `fishing_code` 부재, 최종 제출 점수 대상 |
| 어선 사고현황 파일 | 2026-01-01 ~ 2026-06-30 | 167건 (전부 어선) | 선박 식별자(선명, RFID) 없음 |

사고현황 파일명에 "테스트 데이터"라는 수식어가 붙어 있었으나, 실제 기록된 사고 일시는 모두 2026년이었다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`). 반면 채점 대상인 Test B 항적은 2025년 1~6월 자료다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`). 따라서 2026년 사고기록은 2025년 Test B의 직접 정답이 될 수 없으며, 2025년 제출 대상 항적에 대한 공식 정답지는 프로젝트 내에 존재하지 않는다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`).

이 기간 차이를 인식하지 못하고 2026년 사고를 2025년 항적에 시간창으로 매칭했던 초기 시도는 0건 매칭을 산출했고, 이를 "정답 연결 불가"로 오판하는 원인이 되었다(`testB/과거/TestB_전과정_종합보고서_감독검토_20261105.md`). 반면 2026년 사고기록을 같은 연도인 2026년 학습 항적에 매칭하면 개발용 정답(dev)을 확보할 수 있다(`26_11_5/20261105_분석종합과_TestB_실행계획.md`). 이에 따라 모든 모델 규칙과 임계값은 2026년 개발셋에서 탐색·고정한 뒤 2025년 테스트 항적에 일방향으로 적용하는 체계로 고정되었다(`testB/과거/round_007_20261105/ROUND007_보고서_20261105.md`).

## 5. 보조 디렉터리 역할 정의

루트 디렉터리 내 보조 폴더 9종의 역할은 다음과 같다.

1. `fishing_demo/`: 어선 항적 및 조업·이상항적 시각화를 위한 웹 데모 UI 자산과 구동 스크립트를 보관하는 디렉터리이다.
2. `tools/`: 프로젝트 공통 데이터 파싱, 변환, 검증 및 좌표 진단 유틸리티 스크립트들을 보관하는 도구 디렉터리이다.
3. `configs/`: 실시간 시간순 입력 계약 검증(`testb_realtime.json`) 등 시스템 구동 설정을 보관하는 디렉터리이다.
4. `data/`: 학습 및 평가를 위한 원천·가공 항적 Parquet/CSV 데이터 파일을 보관하는 데이터 디렉터리이다.
5. `outputs/`: 모델 추론 결과, 중간 실행 로그 및 생성된 임시 데이터프레임을 저장하는 디렉터리이다.
6. `tests/`: 점수 함수, 입력 계약 및 회귀 검증을 위한 단위·통합 테스트 코드를 보관하는 디렉터리이다.
7. `examples/`: 시스템 호출 예제 및 데모 실행 샘플 스크립트를 보관하는 디렉터리이다.
8. `_handoff/`: 에이전트 간 인계 문서, 코치 지시서 및 리뷰 기록을 보관하는 인계 디렉터리이다.
9. `tmp/`: 실행 중 생성되는 임시 캐시 및 scratch 파일들을 임시 보관하는 디렉터리이다.
