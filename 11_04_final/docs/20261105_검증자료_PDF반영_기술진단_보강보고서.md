## 3. 사후 조정의 한계: 입증한 것과 입증하지 않은 것

양의 클래스 배수 `a_k`를 사용하는 판정은 다음과 같다.

`ŷ_i(a) = argmax_k a_k p_ik = argmax_k [log(p_ik) + log(a_k)]` (양의 확률에 대해).

이는 기존 점수에 클래스별 상수 편향을 더한다. 새 관측값이나 표현을 학습하지 않고 결정 경계를 이동시킨다. 고정 클래스 쌍의 log-odds에는 상수만 더해져 해당 쌍 점수의 표본 간 순서는 유지된다. 다만 다중 클래스 정규화 이후 모든 one-vs-rest 순위까지 불변이라고 일반화하지 않는다.

정답 집합의 변화는 정확히 `Δcorrect = Gain − Loss`이며 단일 라벨·모든 클래스 포함 micro-F1에서는 `Δmicro = (Gain − Loss)/N`이다. 이것이 이번 32−28의 상쇄를 설명하는 직접적인 수학이다.

확률 `p`가 참 조건부 확률이라면 argmax는 조건부 정답 확률을 최대화한다. 그러나 저장된 모델 추정 확률이 참 확률이라는 전제는 입증되지 않았다. 추정값의 편향을 교정하는 후처리가 정답률을 올리는 경우는 가능하다. 이번에 제한된 배수 후보와 선택 절차가 실패했다는 사실만으로 모든 가능한 후처리의 최적값이 0.7 미만임을 증명할 수 없다.

따라서 결론은 **“시험한 사후 조정은 실질 개선의 근거가 부족하므로 같은 탐색을 반복할 우선순위가 낮다. 다음 실험은 입력 표현·학습 또는 상보적 모델이라는 새 가설을 검증한다”**로 한정한다. ‘불가능의 수학적 증명’, ‘네 방법을 모두 결합해야만 달성 가능’이라는 PDF 표현은 채택하지 않는다.

## 4. 목표까지의 정답 수와 클래스별 제약

단일 라벨 분류에서 정답 수를 C, 표본 수를 N이라 하면 `ΣTP=C`, `ΣFP=ΣFN=N−C`이므로 `micro-F1=2C/[2C+2(N−C)]=C/N`이다.

`ceil(0.7 × 5897) = ceil(4127.9) = 4128`.

4,127척은 0.6998474로 미달하고 4,128척은 0.7000170으로 넘는다. LightGBM 정답 3,497척 기준 순증 +631척이 필요하다. 이는 현재 정답 수 대비 약 18.04%, 기존 오답 2,400척의 약 26.29%에 해당한다. TabICL raw는 seed 42 기준 +637척, seed 2026 기준 +625척이다. 두 시드 평균 정답 3,497에서 평균 목표 4,128까지의 +631은 평균에 대한 계산이며, 개별 시드의 개선량을 같다고 뜻하지 않는다.

## 6. 4대 개선 방향의 구체화와 실행 관문

### 6.1 동역학·공간 특징

120개는 후보 규모 제안이다. 개별 명세·가용 원천 필드·계산 비용·중복 제거가 없으므로 ‘120종 설계 완료’로 쓰지 않는다. 현재 승인된 재현 입력은 선박별 집계 F156이며 점별 시각이 있는 AIS 시퀀스를 확보·검증했다는 증거가 아니다.

| 후보 | 필요한 관측 계약 | 현재 판단 |
|---|---|---|
| 속도 구간별 체류 시간·가속도 | 점별 시각, 신뢰 가능한 SOG 또는 거리/시간, 단위·간격·결측 처리 | 점별 시각 없이는 실제 속력·가속도 계산 금지. 직접 SOG가 있어도 시간가중 체류율에는 시간 필요 |
| 선회율·방향 엔트로피·첨도 | 연속 구간, 각도 wrap, 정지 시 방향 신뢰도, 시간 간격 | ROT는 방향 변화율이며 타각 자체가 아니다. 엔트로피와 첨도는 별도 통계량 |
| 주야간 저속 활동 비율 | UTC/현지 시각, 좌표, 일출·일몰 기준, 관측 편향 | 시간 계약 확인 후 후보화. 선박 업종 정답을 행동 시점 정답으로 사용하지 않음 |
| 공간 집적·형상 | 좌표계·거리단위·세그먼트 경계 | 부분선을 임의 연결하지 않음. 시간 부재 시 공간 기하 특징으로 명명 |

PDF 속도 구간은 5~8kt가 비어 있다. 경계 포함 규칙과 모든 유효 속도를 포괄하는 구간을 먼저 정의해야 한다. 속도만으로 ‘투양망·탐색·조업’을 확정하지 않고 저속 활동의 대리 특징으로 해석한다. 특정 어업 행동을 ‘명확히 분리’한다는 주장은 클래스별 검증 전에는 가설이다. 원자료 접근은 기존 차단·이력 관문을 준수하는 별도 유한 계획으로 다룬다.

### 6.2 TabICL M4 적응과 문맥 선택

Round 004 합성 실행에서 관찰한 decoder는 512→1024→10이며 마지막 `Linear` weight는 PyTorch 저장형식으로 `[10,1024]`다. 현재 분류의 활성 클래스가 4개인 것과 체크포인트의 출력 용량 10개는 별개다. [PyTorch 2.6 Linear 소스](https://github.com/pytorch/pytorch/blob/v2.6.0/torch/nn/modules/linear.py)의 weight 규약은 `[out_features,in_features]`다. PDF의 1024×4를 기존 모듈의 실측 구조라고 쓰지 않는다.

M4-a는 ① 10출력 head 유지·활성 클래스 slice·shuffle 역변환 계약을 보존하는지, ② 4출력으로 교체하는 별도 구조 실험인지 먼저 정해야 한다. weight-only gradient, bias·backbone 동결, loss 계산 대상, optimizer 실제 변경 목록과 backward 가능 여부를 검증해야 한다. `requires_grad` 표시나 forward 성공은 학습 성공이 아니다. 가중치만 조절한다고 클래스 사전분포 편향을 ‘완벽히 흡수’하지 않는다.

M4-b LoRA는 정확한 대상 projection과 rank·동결 범위가 필요하다. 학습 파라미터 수 절감과 계산 비용 0은 다르며, CPU backward의 시간·메모리 절감은 측정 전이다. 먼저 기존 출력 재현 관문을 통과한 뒤 선택한다.

원래 fold 0 문맥은 FIT 3,144척이다. 합성 smoke의 16행을 역사적 원모델의 문맥 수와 혼동하지 않는다. FIT label을 사용하는 추론을 ‘라벨 없는 zero-shot’이라고 부르지 않는다. 16-shot 프로토타입은 문맥 축소라는 새 실험이며 원출력 재현이 아니다. 16개가 총수인지 클래스별 수인지, 거리·대표점·경계점 선정법을 고정하고 FIT 내부 정보만 사용한다. 성능·상보성 향상은 보장하지 않는다.

`run_settings`의 결측 표시 설명과 실제 코드·저장 전처리기의 156+156=312열 불일치는 재현 계약의 문서 문제다. 이것만으로 실제 입력이 왜곡되었거나 성능 저하의 원인이 되었다고 단정하지 않는다. Round 004는 이름·순서·FIT 중앙값·역할 대응을 확인했지만 보호된 전체 과거 원행의 일대일 값 동등성을 확인하지 않았다.

### 6.3 이종 스태킹과 확률 교정

LightGBM 5-seed를 먼저 평균한 4차원 벡터, CatBoost 4차원, TabICL 4차원을 결합하면 12차원이다. 5개 seed를 별도 입력하면 차원이 달라진다. 확률과 logit은 같은 값이 아니므로 입력 정의와 clipping·변환을 고정한다. 기존 프로젝트에는 LightGBM 기준과 다원 앙상블 탐색 이력이 있으므로 ‘지금까지 TabICL 단일 모델만 사용’이라는 PDF 진단은 맞지 않는다.

FIT 내부 교차적합 예측으로 메타 모델을 학습하고, 선택용 INNER와 평가 OUTER를 분리한다. 이미 반복 평가한 개발 OOF 전부에서 메타 모델을 적합한 뒤 같은 행 성능을 평가하면 누출된다. 보정기 역시 적합용 예측과 평가용 예측을 분리해야 한다. 이 원칙은 [StackingClassifier](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingClassifier.html)의 교차검증 기반 메타 입력과 [확률 교정 문서](https://scikit-learn.org/stable/modules/calibration.html)의 독립된 보정 데이터 원칙에 부합한다.

모델 오류의 상보성은 동일 선박별 정답·오답 겹침으로 확인한다. Isotonic은 적은 표본에서 과적합할 수 있고 클래스별 적용 후 정규화·동률 처리가 필요하다. ECE≤0.005, 최고 micro-F1 또는 통발/자망 F1 목표 달성은 보장값이 아니다. ECE bin 규칙과 logloss·Brier·분류 성능을 함께 기록한다.

### 6.4 관측 기간별 모델

‘1~7일·8~30일·31일 이상’은 경과일수인지 유효 관측일수인지 먼저 정의한다. 누락·0일 처리, 모델 분기 시 사용 가능한 필드와 fold별 표본 수를 확인한다. [v1 검증 JSON](../rounds/round_003/verification_20261105/v1_integrity.json)의 observed_days 기준 1~7일은 962척, 전체의 약16.31%로 PDF의 22%와 다르다. F1≤0.44는 지표 집계 정의가 없고 특정 혼동 74%도 이번 제시 근거만으로 검증되지 않았으므로 확정 통계에서 제외한다.

먼저 기간·결측률 조건부 오류를 점검하고, 전용 encoder보다 작은 그룹 특징 또는 단순 분기 모델의 이득을 검증하는 안을 우선한다. ‘depth-wise 분리 트리’는 구현 가능한 estimator·목적함수·결측 처리 규칙으로 명세해야 한다. 그룹별 모델은 표본 감소와 경계 불연속이 생길 수 있어 자동으로 과적합을 차단하지 않는다.

다음 새 가설을 실행할 때는 모델 적합 횟수·후보 수·최대 시간·RAM·중단 조건을 시작 전에 명시한다. 예를 들어 M4는 먼저 forward/backward·파라미터 변경 검증 한 건, 특징은 데이터 계약 충족 여부 한 건을 관문으로 삼고, 통과 후 성능 실험을 별도 동결한다. ‘할 수 있는 것 전부’는 한 회차 무제한 탐색으로 해석하지 않는다.

## 8. RAM·평가 거버넌스와 학습 확인

Round 004 실제 RAM 관문은 최초 2.196GiB 미달, 사용자 재확인 후 실행 직전 4.045GiB였다. 합성 실행 peak working set 약726.2MiB는 16행 smoke의 값이며 전체 FIT 추론·학습의 필요 RAM을 뜻하지 않는다. 본 보강의 [RAM snapshot](report_review_20261105/ram_snapshot.json)은 별도 시점의 WMI 측정값이다. 가용 ≥3GiB는 시작 조건, 실행 중 <1.5GiB는 소유 자식 중단 조건이며 3GiB로 모든 제안이 실행 가능하다는 보장이 아니다. 다른 작업의 프로세스를 임의 종료하지 않는다.

동일 선박 단위 5,000회 paired bootstrap은 시드별 행을 독립 11,794척으로 부풀리는 오류를 피한다. 그러나 반복된 개발 점수 선택의 낙관 편향을 제거하지 않는다. 차이의 CI와 절대 점수의 CI도 구분한다. PDF 4쪽의 ‘하한>0.7000’과 5쪽의 ‘하한>0.6900’은 서로 다른 조건이다. 다음 계획에서 어느 것을 채택할지 사전 명시해야 하며, 기존 회차 게이트를 소급 변경하지 않는다.

독립성 이력 확인 없이 holdout을 열지 않는다. 원 split metadata의 `known_holdout_reused=true` 기록은 특히 주의할 이력이다. 향후 개발 0.7이 관측되어도 독립 평가·공식 제출 성공과 분리한다. 외부 업로드·공식 제출·신규 유료 자원 사용은 이번 범위에 없다.

기술 목표는 근거의 일관성과 다음 가설의 실행 가능성을 높이는 것이다. 학습 목표는 ① 정답 수와 micro-F1 관계, ② discrimination·calibration·판정 규칙 차이, ③ 멤버십과 순서 해시, ④ 합성 실행·출력 재현·학습·일반화 평가 차이를 설명할 수 있게 하는 것이다. 이해 확인 질문: ‘왜 +4척이 평균 +2척이 되는가?’, ‘TP 목표만으로 F1을 정할 수 있는가?’, ‘정렬 해시가 같아도 문맥 순서는 달라질 수 있는가?’, ‘가용3GiB와 학습 성공은 왜 다른가?’ 학습자의 실제 이해나 하드웨어 동작을 평가했다고 주장하지 않는다.

작성·검토 근거는 [수학 검토](report_review_20261105/math_review.md), [기술 검토](report_review_20261105/technical_review.md)와 연결한다. 기존 회차의 실행 모델·effort 증거는 Round 004의 `MODEL_AND_OWNERSHIP.md`, `model_runtime_evidence.json`에 보존되며, 요청값과 호스트 관측값을 구별한다. 본 보강은 Round 005 소유자의 STATUS·ledger·NEXT_SESSION을 수정하지 않는다.
