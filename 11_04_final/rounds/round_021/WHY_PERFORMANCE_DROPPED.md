# Round021 — 왜 점수가 낮아졌는가

**직접 원인은 연안복합의 정답 손실이 다른 세 클래스의 정답 증가보다 컸기 때문이다. 설계상 핵심 한계는 보호 조건을 학습에 강제하지 않고 평가 후 채택 검사로만 적용했다는 점이다.** 다음 회차·추가 실험·새 세션 인계는 사용자 지시에 따라 중지했다.

점수는 저장된 29,485개 확률 행을 별도 검토자가 다시 계산했고 50개 일관성 검사를 모두 통과했다. 이는 계산 검산이며 독립 데이터 성능 검증은 아니다.

## 1. 어디에서 44척을 잃었나

같은 개발 OUTER 5,897척에서 12열 확률 결합은 3,407척 정답, 공간8열을 추가한 20열 후보는 3,363척 정답이다. micro-F1은 **0.577751 → 0.570290**으로 떨어졌다.

| 실제 클래스 | 12열 정답 | 공간20열 정답 | 변화 |
|---|---:|---:|---:|
| 연안복합 | 2,428 | 2,317 | **−111** |
| 자망 | 800 | 844 | +44 |
| 통발 | 104 | 116 | +12 |
| 채낚기연승 | 75 | 86 | +11 |
| 합계 | 3,407 | 3,363 | **−44** |

다른 클래스에서 얻은 정답은 합계67척인데 연안복합에서111척을 잃었다. 개별 선박을 짝지어 보면 새로 맞힌245척보다 새로 틀린289척이 많았다. 실제 연안복합을 자망으로 분류한 수는402→495, 통발로는80→97, 채낚기로는10→11이었다. 이는 혼동행렬의 순변화이며, 개별 선박의 모든 이동이 한 방향이었다는 뜻은 아니다.

macro-F1은 .481603→.497078로 올랐지만 micro-F1은 내려갔다. macro는 네 클래스를 같은 비중으로 평균하므로 소수 클래스의 F1 상승이 더 크게 반영된다. 이번 목표인 micro는 맞힌 선박의 총수를 따르므로111척 손실이 더 중요하다. macro 상승은 관찰 결과이며 모델이 macro를 직접 최적화했다는 뜻은 아니다.

## 2. 자망·통발을 더 많이 예측했지만 정밀도가 떨어졌다

| 항목 | 자망: 12열 → 20열 | 통발: 12열 → 20열 |
|---|---:|---:|
| 해당 클래스로 예측한 수 | 1,398 → 1,555 | 265 → 313 |
| 맞힌 수 TP | 800 → 844 | 104 → 116 |
| 잘못 해당 클래스로 예측한 수 FP | **598 → 711** | **161 → 197** |
| precision | .572246 → **.542765** | .392453 → **.370607** |
| recall | .396825 → .418651 | .124551 → .138922 |
| F1 | .468658 → .472697 | .189091 → .202091 |

자망 예측157척 증가 중 정답 증가는44척이고 FP 증가는113척이었다. 통발 예측48척 증가 중 정답12척, FP36척 증가였다. 따라서 recall 상승만으로 좋은 개선이라고 판단할 수 없다. 연안복합은 반대로 예측 수4,100→3,883, FP1,672→1,566으로 줄어 precision은 .592195→.596704로 조금 올랐지만 recall이 .831507→.793493으로 떨어졌다.

## 3. 공간 특징 이전에 확률 결합 기준선부터 약해졌다

| 모델 | 정답 | micro-F1 |
|---|---:|---:|
| 기존 채택5seed | 3,497 | .593013 |
| 같은 seed42 TabICL 원확률 | 3,491 | .591996 |
| 같은 seed42 LightGBM | 3,476 | .589452 |
| 같은 seed42 CatBoost | 3,424 | .580634 |
| 이번 12열 Logistic 결합 | 3,407 | .577751 |
| 이번 공간20열 Logistic 결합 | 3,363 | .570290 |

저장 원확률의 별도 집계에서도 세 원모델 모두12열 결합보다 높았다. 12열 결합만으로 같은 seed42 LightGBM보다69척, TabICL보다84척을 덜 맞혔다. 공간 특징 추가가 그 위에서44척을 더 잃었다. 따라서 전체 하락을 공간 특징 하나의 탓으로만 설명할 수 없다. 기존 채택5seed와 이번 seed42 차이도 있으므로, 결합 자체의 하락은 우선 같은 seed42 비교에서 판단했다.

공간 추가 후 세 fold의 정답 변화도 각각−20/−7/−17이며, 관측일수 네 구간도−13/−2/−21/−8이었다. 하락이 특정 fold나 관측일수 한 구간에만 국한되지는 않았다. 이것만으로 특정 원인을 입증하지는 않는다.

후보의 자망 TP844는 기존 채택 기준선908보다 낮다. 통발 TP116은 기존과 같지만 FP가134→197로 늘었다. 낮아진12열 비교군 대비 일부 recall 개선을 기존 모델 대비 성능 개선으로 해석하면 안 된다.

## 4. 사용자 요구와 실제 학습 설계의 차이

이번에 학습한 것은 SELECT394척/fold에 맞춘 일반적인 4클래스 LogisticRegression이었다. log-loss와 L2 규제를 사용했고 C=1, class_weight=None였다. 공간8열은 추가 입력이었다.

- **자망·통발 특화 학습은 구현하지 않았다.** 두 클래스 전용 전문가, 별도 목적함수나 특화 가중치는 없었다.
- **연안복합·채낚기 recall 보존은 학습 제약이 아니었다.** 학습 후 OUTER에서 정수 TP 하한을 검사하고 실패 후보를 기각하는 규칙이었다.
- log-loss를 줄이는 학습이 micro-F1이나 보호 클래스 recall을 반드시 올리는 것은 아니다. 기존 LightGBM의 결정을 보존하는 구조도 없었다.

따라서 “자망·통발을 개선하면서 다른 두 클래스를 유지하도록 학습했다”고 표현하면 부정확하다. 정확한 설명은 **일반 결합 모델을 학습한 뒤, 그 요구를 만족하는지 사후 검사했다**는 것이다. 검사는 제대로 작동해 나쁜 후보의 채택을 막았지만, 원하는 제약을 만족시키는 학습 설계까지 완성한 것은 아니다.

보호 하한은 연안복합 TP≥2,389, 채낚기 TP≥92다. 공간 후보는2,317/86으로 각각72척/6척 부족하다. 12열 기준선도 채낚기75척으로 보호에 실패했다. 두 모델 모두 기각하며 기존 채택 기준선을 유지한다.

## 5. 무엇이 확인됐고 무엇은 아직 추정인가

**확인된 사실:** 입력 ID/라벨/fold/역할 정렬, 원확률 행합, 공간 FIT/query 분리, 모델 저장·재로드, 저장 예측 재계산 검사를 통과했다. 6개 모델의 재로드 오차는 모두0이었다. 공간 프로필과 SELECT/OUTER 특징의 누락은0이었다. 실패를 단순한 현재 행 정렬 오류, 모델 저장 오류, 누락된 공간 행으로 설명할 증거는 없다. 이전 코드의 로더 결함은 실제 적합 전에 수정했다.

**입증되지 않은 원인 후보:** fold당394척의 작은 SELECT 표본에12/20열을 적합한 데 따른 표본 민감성이나 과적합, 절대적인 공간 겹침이 클래스 간 구분보다 넓은 지역 공유를 반영한 영향, 현재 정규화·규제·결합 방식의 부적합이다. 이번에는 고정된 한 조건만 비교했으므로 이 중 어느 것이 주원인인지 확정할 수 없다. 특히 “과적합이 원인이다”, “공간 정보가 쓸모없다” 또는 “성능 상한이다”라고 결론짓지 않는다.

후보와12열 기준선의 micro 차이95% paired bootstrap 구간은[-.015266, .000170]으로0을 포함한다. 평균 개선의 증거가 없고 관찰 점수 및 보호조건도 실패했다. 데이터는 반복 노출된 개발 자료이므로 독립 검증·공식 점수로 해석하지 않는다.

추가 실험은 하지 않는다. 결과·원인 정리만 저장했고, 다시 실행하려면 사용자의 새로운 명시적 지시가 필요하다.
