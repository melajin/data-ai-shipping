# Round019 학습 기록

기술 목표는 deadline·종료 관찰·정리 증거를 서로 구분해 모델 없는 실행 관문을 검증하는 것이다. 학습 목표는 기록된 사실이 어떤 주장을 뒷받침하고 어떤 주장은 뒷받침하지 않는지 설명하는 것이다. 학습자 수준·시간·연산환경에 대한 일반 교육 조건은 미확인이며, 이번 문서는 본인 학습자용 실행 기록이다.

1. WaitForExit(false)가 뜻하는 것은 요청한 짧은 대기구간의 만료다. 전체 실행 deadline까지 반드시 도달했다는 뜻은 아니다. 단조시계의 시작·끝·요청길이를 함께 읽는다.
2. deadline 뒤 프로세스가 살아 있었다는 관찰과 kill 뒤 종료 관찰은 별개의 사건이다. 뒤 사건을 앞 사건의 증거로 소급 사용하지 않는다.
3. 종료 signal 대기, OS 정수코드 조회, ExitTime 조회·유효성은 별도 계약이다. 1601년 같은 무효시각은 unknown으로 남긴다. 코드 -1을 실패를 숨기기 위해0으로 고치지 않는다.
4. Python 결과, PowerShell wrapper, 바깥 OS 종료와 전체 시간은 모두 성공해야 다음 단계로 진행한다. 한 계층의 성공이 다른 계층 실패를 지우지 않는다.
5. 저장JSON 수치·해시 감사는 저장 증거의 일관성 검사다. tensor 재계산·실제자료 F1·독립 성능 검증은 별도다.

실험 조건·예상은 ROUND_PLAN.md, 실제 관찰과 해석은 ROUND_REPORT.md 및 logs/manager에 남긴다. 학습자가 설명할 질문: 늦게 발견한 자연종료를 timeout이라 할 수 없는 이유는 무엇인가? 종료코드와 종료시각이 충돌하면 어느 주장을 보류해야 하는가? 왜 새로운 seed나 재분할만으로 반복노출 OUTER가 독립 평가가 되지 않는가?

이 문서 작성은 학습자의 이해 달성을 검증한 것이 아니다. 하드웨어 연결·장치 실측도 없다.
