## 조건과 선택 과정

기술 목표는 같은 X304·FIT에서 다른 모델의 확률이 오류를 줄이는지 확인하는 것이었다. 학습 목표는 조기 종료·결합 선택 자료 분리와 추가정답/새오답의 순손익을 설명하는 것이다. 예상 성능은 미정으로 고정했다.

- 기존 NPZ3개·304열, FIT3,144/3,144/3,145척, INNER787척, OUTER1,966/1,966/1,965척을 유지했다.
- INNER를 층화 분할(seed20261105, test_size=.5)하여 fold마다 ES393/SELECT394척으로 나눴다. 명부·정답·열 순서·해시를 저장했다.
- 기준선은 기존 sqrt_macro 설정(seed42, FIT inverse-sqrt 가중치, ES macro-F1 조기 종료)으로 재학습했다.
- CatBoost는 CPU/seed42/최대3,000회/depth6/lr.03/l2=3/가중치없음/NaN Min/ES Accuracy 조기 종료200이다.
- 결합은 각 SELECT에서 alpha0/.25/.5/.75/1 중 micro최고, 동점은 작은 alpha를 골랐다. 선택을 저장·해시 고정한 뒤 OUTER를 추론했다. OUTER로 다시 고르지 않았다.

fold0에서 SELECT는 후보를 골랐지만 OUTER에서는 낮아졌다. 선택 자료의 개선이 다른 선박에서도 그대로 이어진다고 보장하지 않는다. 결과를 보고 alpha를 바꾸지 않았다.

## 실행·실패 복구·검증

전용 환경은 Python3.13.3, NumPy2.2.5, LightGBM4.7.0, sklearn1.6.1, CatBoost1.2.10이다. 설치 파일 SHA256·버전·라이선스·freeze를 저장했다. 관리자/보조 호스트 turn_context는 각각 gpt-6-astra/high, gpt-6-luna/xhigh로 확인해 model_runtime_evidence.json에 보존했다. 모델 내부를 별도로 검증했다는 뜻은 아니다.

학습 전 검토에서 SELECT 참조 오류를 수정했다. 실행1은 기준선 fold0 완료 후 CatBoost 생성자의 feature_names 인자 미지원으로 실패했다. CatBoost.fit은 호출되지 않았고 OS 종료코드는 unknown이다. 실행2는 Pool로 특징 이름을 전달했으나 가중치 없는 자료의 use_weights 옵션이 설치본에서 거부됐다. CatBoost.fit이 iteration 전에 실패했고 실제 종료코드는1이다.

실행3은 가중치 없는 Accuracy로 API 표기만 수정했다. 후보·용량·seed·분할·선택 규칙은 유지했고 기존 기준선을 입력/모델/명부/확률/설정 동등성 검증 뒤 재사용했다. **총 성공모델6개 = 실행1의 기준선1개 + 실행3의 신규5개**다. fit 함수 호출은 성공6회와 실패1회이며 생성자 실패는 별도다. 완료 모델을 재학습하지 않았다.

실행3은 **15:18:42–15:23:12 UTC**, 실제 종료코드0이다. runner PID2716, wrapper PID6152다. 내부 집계270.17초와 이전 시도24.41초를 합한 약294.58초는 설치·관리시간을 제외한 계산값이다. 초기45분 관리 예산은 API 복구와 사용자의 2차 완료 지시로 연장됐으며 45분 내 완료라고 주장하지 않는다. 계산30분·동시학습1·threads<=3·fit 전 가용RAM>=1.5GiB 제한은 유지했다.

기준선 iteration은108/154/199, CatBoost tree 수는323/115/39다. 모든 모델의 live 대 reload ES/SELECT 확률 최대 차이는0이며 OUTER 재로드 추론도 최대 차이0이다. 검사 대상 입력·소스의 전후 해시는 같았다. 이를 원자료 전체 재감사나 디렉터리 전체 무변경 증명으로 확대하지 않는다.

실패 원인은 라이브러리/API 연결 계층이었다. 원자료·정답·분할을 바꿔 복구하지 않았다. 원래 동적 T5와 CSV의 완전 일치, 옛 S6 .59183의 원인, holdout 독립성은 미해결이다. 기존 T5/local_rel의 population 통계 조건을 FIT-only라고 부르지 않는다.

독립 최종 검토는 절차 PASS, 종합 CONDITIONAL, 채택 REJECT다. 검토자는 저장 확률로5,897척의 혼동행렬·micro/macro·recall과 alpha1/0/.5를 다시 계산해 일치함을 확인했다. 결합 확률 차이도0이었다. bootstrap 구간은 실행 결과를 인용했으며 검토자가 별도 재표집한 것은 아니다.

## 후속 계획과 일시정지

사용자가 지정한 알고리즘 변형 아이디어 문서를 전부 읽고 사본·SHA256을 보존했다. 후속은 **TabICL A의 원확률/기존 통발 배수/INNER micro 선택 배수의 R0 비교 → 최종 Linear 직접 조정과 rank2 수정의 실행 근거 확인** 순서다. A의 실제 저장 예측 위치도 찾았고, 입력 정의·FIT 문맥·체크포인트 미확인 부분은 별도 관문으로 남겼다. 자세한 판단은 IDEA_REVIEW_AND_ROUND003.md에 있다.

**현재는 사용자 요청에 따른 일시정지다.** 3차 실행·새 관리자 세션 생성은 하지 않는다. NEXT_SESSION은 재개용 보존 계획이며 USER_PAUSE.md와 STATUS.handoff.ready=false를 따른다. 명시적 재개 전에는 후속 실험을 수행하지 않는다.
