# 학습 목표와 확인 질문

이번 구현은 기본 모델 세 개를 다시 학습하는 작업이 아니라, 서로 다른 모델의 저장 원확률을 같은 fold의 SELECT에서만 결합하는 실험이다. 코드 테스트·저장 확률 검산·반복노출 개발 평가를 구분하며 하드웨어 실측은 수행하지 않는다.

학습자가 설명할 질문:
1. 한 선박의 global OOF 예측을 다른 fold의 INNER 예측 대신 사용할 수 없는 이유는 무엇인가?
2. 기존 모델의 조기 종료 ES와 결합 SELECT를 분리하면 어떤 자료 재사용 문제를 줄이는가?
3. 세 모델 중 하나가 정답인 선박의 비율은 왜 Logistic 결합 모델의 이론적 성능 상한이 아닌가?
4. 전체 정답 수가 증가해도 통발 recall이나 짧은 관측일 집단 성능이 감소하면 채택을 유보하는 이유는 무엇인가?
5. 확률 파일의 행에는 연도가 없는데 출처가 Train2026이라고 할 때, 확인 사실과 설계 가정을 어떻게 구별해야 하는가?
6. 021의 공간 prototype에 query 자신의 정답을 사용하면 어떤 누출이 발생하는가?

시스템 구현·계산 완료는 결과 보고서에 기록한다. 학습자의 설명·설계 역량은 아직 평가하지 않았다.
